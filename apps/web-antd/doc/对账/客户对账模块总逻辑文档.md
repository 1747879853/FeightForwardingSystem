# 1. 业务背景说明 (Background)

**白话解释：**  
客户对账（SOA）把同一结算对象下的多笔业务费用归集到一张对账单，便于向客户确认应收/应付。对账单本身不存「结算状态」「开票状态」「收付类型汇总」，这些列由关联费用实时汇总。

表：`App_Statements`；明细子表：`App_StatementFees`（`StatementId` + `OrderFeeId`）。

**允许多次对账：** 一条费用可同时被多张对账单包含，同一条费用在同一张对账单里只能出现一次。`OrderFee` 上已无 `StatementId` 字段，判断费用是否已对账一律查子表。

# 2. 功能与操作说明 (Features & Operations)

- **列表查询：** `GET StatementAdmin/GetPagedListAsync`，支持客户、对账单号、时间、收付类型、开票状态、结算状态、我司银行等筛选；`keyword` 模糊匹配对账单号/客户名称/客户代码/备注，`keys` 对同一批字段精确匹配（任意一条命中即可）；返回币别金额汇总（含**两套已占用额度合计**，收付各一列）、主提单号、收付/开票/结算汇总列。
- **详情：** `GET StatementAdmin/DetailAsync`，按业务（TransportOrder）分组展示费用明细、附件；业务组 `transportOrder` 按 `bizType` 返回 `seaExport`/`seaImport`/`airExport`（SimpleDto），并带**应收整票结算状态** `recSettlementStatus`；每条费用返回**组合费用状态** `combinedFeeStatus` 与**两套已占用额度**；业务组的 `statementCurrencyGroup` 带 4 列占用合计；对账单头返回收付类型、结算状态汇总；`IsPrint=true` 时每个业务组返回 `statementCurrencyFeeCodeGroup`（币别+费用代码汇总）。
- **新增/编辑/删费用：** `AddAsync` / `EditAsync` / `AddFeesAsync` / `RemoveFeesAsync`；费用结算对象须等于对账单客户。加费用写子表，删费用删子表行（只解除本对账单关联）；删除对账单前必须显式清子表，ABP 软删除不会级联。
- **选可对账费用：** `GetOrderFeeGroupAsync`，**结算对象 `settlementId` 非必填**（不传则跨结算对象浏览，但一张对账单只能对一个结算对象，混选的在新建/加费用时被拦）；可按费用级 `SettlementStatus` 筛选；默认只返回从未对账过的费用，`includeStatemented=true` 时带出已对账费用，传 `statementId` 时排除本对账单已有费用；**申请修改/申请删除审核中的费用一律不返回**；`keyword` 模糊匹配委托编号/主提单号/订舱编号，`keys` 对同一批字段精确匹配（任意一条命中即可）；业务按 `bizType` 返回 `seaExport`/`seaImport`/`airExport`（SimpleDto）。销售/操作/客服筛选为**多选**（`saleIds`/`operatorIds`/`customerServiceIds`），字段内多个id取或、字段之间取且。每条费用返回 `isStatemented` 与已对账列表 `statements[]`（对账单号/对账时间/对账人）、**组合费用状态** `combinedFeeStatus`；业务行返回**应收整票结算状态** `recSettlementStatus`，以及全部**往来单位对象**（`client`/`clientContact`/`team`/`custBroker`/`warehouse`/`insurance`/`consignee`/`shipper`/`notifier`）。

# 3. 状态流转说明 (Status Transitions)

| 当前状态 | 触发人/动作 | 目标状态 | 状态说明 |
| :-- | :-- | :-- | :-- |
| 费用未结算 | 收费/付费结算审核通过或部分核销 | 费用部分结算 / 结算完毕 | 回写 `OrderFee.SettlementStatus`、`SettledAmount` |
| 对账单头结算状态 | 费用结算状态变化后重新打开列表/详情 | 未结算 / 部分结算 / 结算完毕 | **只读计算**，不入库 |
| 对账单头收付类型 | 增减费用后打开列表/详情 | 全收 / 全付 / 收付都有 | **只读计算**，不入库 |

对账单头结算状态汇总：

| 汇总结果 | 条件                    |
| :------- | :---------------------- |
| 未结算   | 全部费用 `UnSettled`    |
| 结算完毕 | 全部费用 `Settlemented` |
| 部分结算 | 其他                    |

对账单头收付类型汇总：

| 汇总结果   | 条件         |
| :--------- | :----------- |
| 0 全部为收 | 有收、无付   |
| 1 全部为付 | 有付、无收   |
| 2 收付都有 | 收与付均存在 |

业务行的应收整票结算状态（`recSettlementStatus`，`GetOrderFeeGroupAsync` 与 `DetailAsync` 均返回）：

| 汇总结果   | 条件                            |
| :--------- | :------------------------------ |
| null       | 该业务下没有应收费用            |
| 0 未结算   | 整票应收费用全部 `UnSettled`    |
| 2 结算完毕 | 整票应收费用全部 `Settlemented` |
| 1 部分结算 | 其他                            |

**「整票」按该业务下的全部应收费用算，与接口的结算对象、是否已对账、费用状态等筛选条件完全无关**；同样地，详情里也不限于本对账单收录的那几条费用。

# 5. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **[卡点 1：结算状态只读]** 对账单头 `settlementStatus` 不可编辑，随费用结算回写后在列表/详情自动变化。

> [!IMPORTANT] **[卡点 2：筛选过滤空费用单]** 按 `settlementStatus`/`invoiceStatus`/`paySide` 筛选时，无关联费用的对账单不会命中。

> [!IMPORTANT] **[卡点 3：已对账费用禁止改动]** 只要费用存在于任意一张对账单，业务费用侧的**删除、编辑、申请修改、申请删除、驳回**全部拦截。其中「编辑」自 2026-08-11 起由静默跳过改为直接报错。需要改动时先从所有对账单里移除该费用。

> [!IMPORTANT] **[卡点 4：同一对账单内费用不可重复]** 一条费用可以进多张对账单，但同一张对账单里只能出现一次，重复添加报「费用输入错误 本对账单已包含该费用」。

> [!IMPORTANT] **[卡点 5：审核中的费用不可对账]** 存在审核中（`TaskStatus=Auditing`）的申请修改或申请删除任务的费用，不会出现在 `GetOrderFeeGroupAsync` 的选费用列表里。原因是审核通过后金额会变、或费用直接被删，此时若已挂进对账单会导致对账金额失真，或留下指向已删费用的明细行。等审核有结论后该费用会自动重新出现。

> [!IMPORTANT] **[卡点 6：删除对账单必须先清子表]** ABP 软删除会取消 EF 级联，删 `Statement` 前必须显式 `DeleteAsync(x => x.StatementId == ...)` 清 `App_StatementFees`，否则残留明细会被按子表直查的逻辑读到。

> [!IMPORTANT] **[卡点 7：整票结算状态与列表筛选无关]** `recSettlementStatus` 是另查一次「该业务全部应收费用」算出来的，不跟着接口的筛选条件走。因此会出现「按未结算筛选，业务行却显示部分结算」的情况，这是预期行为——若跟着筛选走，选费用列表默认只给没对过账的费用，这一列会永远是「未结算」，毫无意义。

> [!IMPORTANT] **[卡点 8：一张对账单只能对一个结算对象]** 选费用的 `settlementId` 自 2026-08-29 起非必填，列表里可以同时出现多个结算对象的费用，但对账单结构没变——`AddAsync` / `AddFeesAsync` 会校验所选费用的结算对象**必须彼此相同、且等于对账单客户 `clientId`**，否则分别报「所选费用的结算对象不一致 不可对账」「费用的结算对象与对账单客户不一致」；结算对象为空的费用（录入状态可空）一律报「存在未设置结算对象的费用 不可对账」。

> [!IMPORTANT] **[卡点 9：两套已占用额度口径不同，不可混用]** 费用行与币别分组上的「发票已占用额度」（`orderInvoiceAmount`）和「结算已占用额度」（`settlementOccupiedAmount`）参与项不同：前者=开票申请+付费申请，**不含收费结算**；后者=付费申请+收费结算+开票申请。两列不能互相加减或比大小得结论，各自的唯一出口是 `IOrderFeeInvoicedProvider` 与 `IOrderFeeOccupiedProvider`，禁止在本模块自己写聚合。另外 `settlementOccupiedAmount` **不等于** `settledAmount`——前者含被申请占住但尚未结算的钱。币别分组的收/付拆分按**费用自己的 `paySide`**，不是按占用来源：付费申请与结算单都允许收付混选（应收费用进付费申请做冲抵），所以应收费用的占用里也可能有付费申请的份额；只有开票申请强制只能选应收费用。
