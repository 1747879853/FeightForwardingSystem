# 付费结算接口文档

**控制器**：`PaymentSettlementAdmin`

**所有接口均需要登录认证**

---

## 零、汇率规则（2026-08-10 变更）

付费结算**不再录入汇率**，所有写接口都已删除 `paymentSettlementRates` 入参，`App_PaymentSettlementRates` 表已废弃。汇率一律由后端从付费申请取，并快照到 `PaymentSettlementItem.Rate` 上：

| 付费申请类型 | 判定 | 结算币别约束 | 汇率来源 |
|------|------|------|------|
| 固定币别申请 | `PaymentApplication.CurrencyId` 有值 | 申请币别必须**等于**结算单的 `currencyId`，否则报错 | 逐条取 `PaymentApplicationItem.Rate` |
| 原币申请 | `PaymentApplication.CurrencyId` 为空 | 只能结算原币**等于**结算单 `currencyId` 的费用，其他币别的费用不能选进来 | 恒为 `1` |

两类申请可以挂在同一张结算单上。所有金额口径仍是 `SUM(SettledAmount × Rate)`，只是 `Rate` 改为逐条明细的快照。

前端选择付费申请时，请给 `PaymentApplicationAdmin/GetPagedListForSettlementAsync` 和 `GetPagedListByCurrencyForSettlementAsync` 传 `settlementCurrencyId`，接口会直接过滤掉不能选的申请和行。

## 一、新增付费结算

### `POST /api/services/app/PaymentSettlementAdmin/AddAsync`

**权限**：`Admin.PaymentSettlement.Add`

**入参** `PaymentSettlementAddDto`：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `settlementTime` | `DateTime` | 是 | 结算时间，默认当前时间可自定义 |
| `payType` | `int?` | 否 | 付款方式 |
| `settlementId` | `Guid` | 是 | 结算对象ID（客户） |
| `currencyId` | `long` | 是 | 结算币别ID。固定币别申请的申请币别必须与之相同；原币申请只能结算该币别的费用 |
| `orgBankAccountId` | `Guid?` | 否 | 我司银行ID |
| `clientInvoiceBankId` | `Guid?` | 否 | 结算对象银行（对方银行）ID |
| `transactionFee` | `decimal?` | 否 | 手续费 |
| `remark` | `string` | 否 | 备注 |
| `paymentApplicationGroups` | `List<PaymentSettlementAddItemGroupDto>` | 是 | 付费申请结算列表 |
| `attachments` | `List<AttachmentItemForItemInputDto>` | 否 | 附件列表 |

**`PaymentSettlementAddItemGroupDto`**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `paymentApplicationId` | `Guid` | 付费申请ID |
| `settledPrice` | `decimal?` | 结算总金额（结算币别）。固定币别的付费申请使用此字段，后端自动分配到各原币币别；原币申请不需要此字段 |
| `currencyItems` | `List<PaymentSettlementAddItemCurrencyDto>` | 币别结算列表。原币申请必填，且只能是结算币别那一条；固定币别申请如果传了 `settledPrice` 则由后端自动计算，不需要传此字段 |

**`PaymentSettlementAddItemCurrencyDto`**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `originalCurrencyId` | `long` | 原币币别ID |
| `settledAmount` | `decimal` | 本币别申请结算的净额（原币），必须在 [settleableLowerLimit, settleableUpperLimit] 范围内 |

**入参示例（原币申请 - 只能结算等于结算币别的那个原币）**：

结算币别 `currencyId = 1`（假设是 USD），那么原币申请里只有 USD 的费用能选进来，`currencyItems` 只能有 `originalCurrencyId = 1` 这一条。

```json
{
  "settlementTime": "2026-05-12T00:00:00",
  "payType": 1,
  "settlementId": "client-guid",
  "currencyId": 1,
  "orgBankAccountId": "bank-guid",
  "clientInvoiceBankId": "client-bank-guid",
  "transactionFee": 50.00,
  "remark": "5月结算",
  "paymentApplicationGroups": [
    {
      "paymentApplicationId": "pa-guid-1",
      "currencyItems": [
        { "originalCurrencyId": 1, "settledAmount": 1000.00 }
      ]
    },
    {
      "paymentApplicationId": "pa-guid-2",
      "currencyItems": [
        { "originalCurrencyId": 1, "settledAmount": 2000.00 }
      ]
    }
  ],
  "attachments": [
    { "attachmentId": 123, "displayOrder": 0 }
  ]
}
```

**入参示例（固定币别申请 - 只传结算总金额，后端自动分配）**：

要求两张申请的申请币别都等于 `currencyId`，各原币的汇率由后端从申请明细上取。

```json
{
  "settlementTime": "2026-05-12T00:00:00",
  "payType": 1,
  "settlementId": "client-guid",
  "currencyId": 1,
  "orgBankAccountId": "bank-guid",
  "clientInvoiceBankId": "client-bank-guid",
  "transactionFee": 50.00,
  "remark": "5月结算",
  "paymentApplicationGroups": [
    {
      "paymentApplicationId": "pa-guid-1",
      "settledPrice": 11100.00
    },
    {
      "paymentApplicationId": "pa-guid-2",
      "settledPrice": 14400.00
    }
  ],
  "attachments": [
    { "attachmentId": 123, "displayOrder": 0 }
  ]
}
```

**出参**：`Guid`（新建的付费结算ID）

**业务规则**：
- 校验所有外键（结算对象、结算币别、我司银行、对方银行）
- **固定币别的付费申请（CurrencyId 有值）**：申请币别必须等于结算单 `currencyId`，否则报「付费申请【单号】的申请币别【x】与结算币别【y】不一致,不能结算」。客户传 `settledPrice`（结算币别总金额），后端自动分配到各原币币别：
  1. 校验 `settledPrice` 在总可结算范围 [totalPriceLower, totalPriceUpper] 内（各币别的上下限 × 汇率后求和，汇率取该原币下第一条申请明细的 `Rate`）
  2. 按比例分配：`fraction = (settledPrice - totalPriceLower) / (totalPriceUpper - totalPriceLower)`，每个币别 `settledAmount = lowerLimit + fraction × range`
  3. 最后一个币别用剩余金额倒算（`remainingPrice / rate`），吸收前面各币别的舍入差
  4. 每个币别的分配结果 clamp 到 [lowerLimit, upperLimit] 范围内
  5. 明细落库时的 `Rate` 快照逐条取自对应 `PaymentApplicationItem.Rate`
- **原币申请（CurrencyId 为空）**：只能结算原币等于结算单 `currencyId` 的费用，否则报「付费申请【单号】是原币申请,只能结算币别为【x】的费用,不能结算【y】的费用」。客户手动传 `currencyItems`，汇率恒为 1
- 每个付费申请的每种币别的结算量必须在可结算范围内：`settleableLowerLimit ≤ settledAmount ≤ settleableUpperLimit`
  - 有效金额：收的费用取 UnSettledAmount，付的费用取 -UnSettledAmount（注意费用可以录负数）
  - 上限（settleableUpperLimit）= 正数有效金额之和
  - 下限（settleableLowerLimit）= 负数有效金额之和
- 结算量按顺序分配到付费申请的每条明细（按费用录入顺序）：
  1. 计算 diff = settledAmount - total（total = 所有有效金额之和）
  2. diff = 0：结算所有费用明细
  3. diff > 0：取所有正数有效金额的费用全量结算，再按录入顺序对负数项挨个取直至差值满足
  4. diff < 0：取所有负数有效金额的费用全量结算，再按录入顺序对正数项挨个取直至差值满足
- 新增后自动更新：OrderFee.SettledAmount / SettlementStatus、PaymentApplicationItem.UnSettledAmount、PaymentApplication.Status

## 二、修改主表和汇率

### `PUT /api/services/app/PaymentSettlementAdmin/EditAsync`

**权限**：`Admin.PaymentSettlement.Edit`

**入参** `PaymentSettlementEditDto`：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | `Guid` | 是 | 付费结算ID |
| `settlementTime` | `DateTime` | 是 | 结算时间 |
| `payType` | `int?` | 否 | 付款方式 |

- 附件全量替换

## 三、添加结算明细

### `POST /api/services/app/PaymentSettlementAdmin/AddItemsAsync`

**权限**：`Admin.PaymentSettlement.Edit`

**入参** `PaymentSettlementAddItemsDto`：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | `Guid` | 是 | 付费结算ID |
| `paymentApplicationGroups` | `List<PaymentSettlementAddItemGroupDto>` | 是 | 新增的付费申请结算列表 |

**出参**：`bool`

**业务规则**：
- 已锁定的不能编辑
- 新增的付费申请不能包含已添加过的PaymentApplication
- 付费申请必须是审核通过或部分结算状态
- 币别约束同新增接口：固定币别申请的申请币别必须等于结算单币别，原币申请只能结算等于结算单币别的费用
- 固定币别的付费申请传 `settledPrice` 自动分配（规则同新增接口）；原币申请手动传 `currencyItems`
- 每种币别的结算量必须在可结算范围 [settleableLowerLimit, settleableUpperLimit] 内（规则同新增接口）
- 结算量按顺序分配（规则同新增接口）
- 新增后自动更新关联数据（同新增接口）

| 字段 | 类型 | 必填 | 说明 |

**权限**：`Admin.PaymentSettlement.Unlock`

**入参** `PaymentSettlementLockDto`：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | `Guid` | 是 | 付费结算ID |

**出参**：`bool`

**业务规则**：
- 未锁定的不能解锁（`locked == false` 时拒绝）
- 解锁后 `locked` 置为 `false`，`lockeTime` 置为 `null`

## 十二、错误提示汇总

| 错误信息 | 触发条件 |
|---------|---------|
| `输入不能为空` | 入参为null |
| `结算对象不存在` | settlementId 无效 |
| `结算币别不存在` | currencyId 无效 |
| `我司银行不存在` | orgBankAccountId 无效 |
| `结算对象银行不存在` | clientInvoiceBankId 无效 |
| `部分付费申请不存在` | paymentApplicationId 无效 |
| `付费申请【xx】状态不是审核通过或部分结算,不能结算` | 付费申请状态不对 |
| `付费申请【xx】的申请币别【xx】与结算币别【xx】不一致,不能结算` | 固定币别申请的申请币别不等于结算单币别 |
| `付费申请【xx】是原币申请,只能结算币别为【xx】的费用,不能结算【xx】的费用` | 原币申请选了原币不等于结算币别的费用 |
| `付费申请【xx】存在明细未录入有效汇率,不能结算` | 固定币别申请的明细 Rate 为空或 ≤ 0 |
| `付费申请【xx】的结算总金额xx不在可结算范围[xx, xx]内` | 固定币别申请的 settledPrice 超出总可结算上下限 |
| `付费申请【xx】币别ID【xx】的结算量xx不在可结算范围[xx, xx]内` | 结算量超出可结算上下限 |
| `付费结算已锁定,不能编辑` | 对已锁定的结算进行编辑 |
| `付费结算已锁定,不能删除` | 对已锁定的结算进行删除 |
| `以下付费申请已在该结算单中,不能重复添加` | AddItemsAsync时重复添加 |
| `要删除的付费申请ID列表不能为空` | DeleteItemsAsync时paymentApplicationIds为空 |
| `未找到对应付费申请的结算明细` | 传入的付费申请ID在该结算单中无对应明细 |
| `付费结算已锁定,不能重复锁定` | 重复锁定 |
| `付费结算未锁定,不能解锁` | 对未锁定的结算解锁 |
