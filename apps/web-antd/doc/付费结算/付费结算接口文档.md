## 一、新增付费结算

### `POST /api/services/app/PaymentSettlementAdmin/AddAsync`

**权限**：`Admin.PaymentSettlement.Add`

**入参** `PaymentSettlementAddDto`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `settlementTime` | `DateTime` | 是 | 结算时间，默认当前时间可自定义 |
| `payType` | `int?` | 否 | 付款方式 |
| `settlementId` | `Guid` | 是 | 结算对象ID（客户） |
| `currencyId` | `long` | 是 | 结算币别ID |
| `orgBankAccountId` | `Guid?` | 否 | 我司银行ID |
| `clientInvoiceBankId` | `Guid?` | 否 | 结算对象银行（对方银行）ID |
| `transactionFee` | `decimal?` | 否 | 手续费 |
| `remark` | `string` | 否 | 备注 |
| `paymentSettlementRates` | `List<PaymentSettlementRateAddDto>` | 是 | 汇率列表 |
| `paymentApplicationGroups` | `List<PaymentSettlementAddItemGroupDto>` | 是 | 付费申请结算列表 |
| `attachments` | `List<AttachmentItemForItemInputDto>` | 否 | 附件列表 |

**`PaymentSettlementRateAddDto`**：

| 字段                 | 类型      | 说明                   |
| -------------------- | --------- | ---------------------- |
| `originalCurrencyId` | `long`    | 原币币别ID             |
| `rate`               | `decimal` | 汇率（原币对结算币别） |

**`PaymentSettlementAddItemGroupDto`**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `paymentApplicationId` | `Guid` | 付费申请ID |
| `settledPrice` | `decimal?` | 结算总金额（结算币别）。固定币别的付费申请使用此字段，后端自动分配到各原币币别；原币申请不需要此字段 |
| `currencyItems` | `List<PaymentSettlementAddItemCurrencyDto>` | 币别结算列表。原币申请必填；固定币别申请如果传了 `settledPrice` 则由后端自动计算，不需要传此字段 |

**`PaymentSettlementAddItemCurrencyDto`**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `originalCurrencyId` | `long` | 原币币别ID |
| `settledAmount` | `decimal` | 本币别申请结算的净额（原币），必须在 [settleableLowerLimit, settleableUpperLimit] 范围内 |

**入参示例（原币申请 - 手动指定各币别结算量）**：

```json
{
  "settlementTime": "2026-05-12T00:00:00",
  "payType": 1,
  "settlementId": "client-guid",
  "currencyId": 1,
  "orgBankAccountId": "bank-guid",
  "clientInvoiceBankId": "client-bank-guid",
  "transactionFee": 50.0,
  "remark": "5月结算",
  "paymentSettlementRates": [
    { "originalCurrencyId": 2, "rate": 7.2 },
    { "originalCurrencyId": 3, "rate": 7.8 }
  ],
  "paymentApplicationGroups": [
    {
      "paymentApplicationId": "pa-guid-1",
      "currencyItems": [
        { "originalCurrencyId": 2, "settledAmount": 1000.0 },
        { "originalCurrencyId": 3, "settledAmount": 500.0 }
      ]
    },
    {
      "paymentApplicationId": "pa-guid-2",
      "currencyItems": [{ "originalCurrencyId": 2, "settledAmount": 2000.0 }]
    }
  ],
  "attachments": [{ "attachmentId": 123, "displayOrder": 0 }]
}
```

**入参示例（固定币别申请 - 只传结算总金额，后端自动分配）**：

```json
{
  "settlementTime": "2026-05-12T00:00:00",
  "payType": 1,
  "settlementId": "client-guid",
  "currencyId": 1,
  "orgBankAccountId": "bank-guid",
  "clientInvoiceBankId": "client-bank-guid",
  "transactionFee": 50.0,
  "remark": "5月结算",
  "paymentSettlementRates": [
    { "originalCurrencyId": 2, "rate": 7.2 },
    { "originalCurrencyId": 3, "rate": 7.8 }
  ],
  "paymentApplicationGroups": [
    {
      "paymentApplicationId": "pa-guid-1",
      "settledPrice": 11100.0
    },
    {
      "paymentApplicationId": "pa-guid-2",
      "settledPrice": 14400.0
    }
  ],
  "attachments": [{ "attachmentId": 123, "displayOrder": 0 }]
}
```

**出参**：`Guid`（新建的付费结算ID）

**业务规则**：

- 校验所有外键（结算对象、结算币别、我司银行、对方银行、汇率币别）
- 汇率列表的币别种类必须跟结算明细涉及的币别完全一致
- **固定币别的付费申请（CurrencyId 有值）**：客户传 `settledPrice`（结算币别总金额），后端自动分配到各原币币别：
  1. 校验 `settledPrice` 在总可结算范围 [totalPriceLower, totalPriceUpper] 内（各币别的上下限 × 汇率后求和）
  2. 按比例分配：`fraction = (settledPrice - totalPriceLower) / (totalPriceUpper - totalPriceLower)`，每个币别 `settledAmount = lowerLimit + fraction × range`
  3. 最后一个币别用剩余金额倒算（`remainingPrice / rate`），吸收前面各币别的舍入差
  4. 每个币别的分配结果 clamp 到 [lowerLimit, upperLimit] 范围内
- **原币申请（CurrencyId 为空）**：客户手动传 `currencyItems` 指定各币别结算量
- 每个付费申请的每种币别的结算量必须在可结算范围内：`settleableLowerLimit ≤ settledAmount ≤ settleableUpperLimit`
  - 有效金额：收的费用取 UnSettledAmount，付的费用取 -UnSettledAmount（注意费用可以录负数）
  - 上限（settleableUpperLimit）= 正数有效金额之和
  - 下限（settleableLowerLimit）= 负数有效金额之和
- 结算量按顺序分配到付费申请的每条明细（按费用录入顺序）：
  1. 计算 diff = settledAmount - total（total = 所有有效金额之和）
  2. diff = 0：结算所有费用明细
  3. diff > 0：取所有正数有效金额的费用全量结算，再按录入顺序对负数项挨个取直至差值满足
  4. diff < 0：取所有负数有效金额的费用全量结算，再按录入顺序对正数项挨个取直至差值满足
- 新增后自动更新：OrderFee.SettledAmount / SettlementStatus、PaymentApplicationItem.UnSettledAmount、PaymentApplication.Status

## 二、修改主表和汇率

### `PUT /api/services/app/PaymentSettlementAdmin/EditAsync`

**权限**：`Admin.PaymentSettlement.Edit`

**入参** `PaymentSettlementEditDto`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `Guid` | 是 | 付费结算ID |
| `settlementTime` | `DateTime` | 是 | 结算时间 |
| `payType` | `int?` | 否 | 付款方式 |
| `orgBankAccountId` | `Guid?` | 否 | 我司银行ID |
| `clientInvoiceBankId` | `Guid?` | 否 | 结算对象银行ID |
| `transactionFee` | `decimal?` | 否 | 手续费 |
| `remark` | `string` | 否 | 备注 |
| `paymentSettlementRates` | `List<PaymentSettlementRateAddDto>` | 是 | 汇率列表（全量替换） |
| `attachments` | `List<AttachmentItemForItemInputDto>` | 否 | 附件列表（全量替换） |

**出参**：`bool`

**业务规则**：

- 已锁定的付费结算不能编辑
- 汇率列表的币别种类必须跟已有结算明细（PaymentSettlementItem）的币别完全一致
- 不能修改结算对象和结算币别
- 汇率全量替换后会同步更新明细上的汇率快照
- 附件全量替换

## 三、添加结算明细

### `POST /api/services/app/PaymentSettlementAdmin/AddItemsAsync`

**权限**：`Admin.PaymentSettlement.Edit`

**入参** `PaymentSettlementAddItemsDto`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `Guid` | 是 | 付费结算ID |
| `paymentApplicationGroups` | `List<PaymentSettlementAddItemGroupDto>` | 是 | 新增的付费申请结算列表 |
| `paymentSettlementRates` | `List<PaymentSettlementRateAddDto>` | 是 | 汇率列表（全量替换，需包含新增后所有币别） |

**出参**：`bool`

**业务规则**：

- 已锁定的不能编辑
- 新增的付费申请不能包含已添加过的PaymentApplication
- 付费申请必须是审核通过或部分结算状态
- 固定币别的付费申请传 `settledPrice` 自动分配（规则同新增接口）；原币申请手动传 `currencyItems`
- 每种币别的结算量必须在可结算范围 [settleableLowerLimit, settleableUpperLimit] 内（规则同新增接口）
- 结算量按顺序分配（规则同新增接口）
- 汇率币别必须覆盖已有明细 + 新增明细的所有币别
- 新增后自动更新关联数据（同新增接口）

---

## 四、删除结算明细

### `POST /api/services/app/PaymentSettlementAdmin/DeleteItemsAsync`

**权限**：`Admin.PaymentSettlement.Edit`

**入参** `PaymentSettlementDeleteItemsDto`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `Guid` | 是 | 付费结算ID |
| `paymentApplicationIds` | `List<Guid>` | 是 | 要删除的付费申请ID列表（删除该结算单中属于这些付费申请的所有结算明细） |
| `paymentSettlementRates` | `List<PaymentSettlementRateAddDto>` | 是 | 汇率列表（全量替换，需包含删除后剩余的所有币别） |

**入参示例**：

```json
{
  "id": "settlement-guid",
  "paymentApplicationIds": ["pa-guid-1", "pa-guid-2"],
  "paymentSettlementRates": [{ "originalCurrencyId": 2, "rate": 7.2 }]
}
```

**出参**：`bool`

**业务规则**：

- 已锁定的不能编辑
- 按付费申请维度删除：传入付费申请ID列表，删除该结算单中属于这些付费申请的所有结算明细（与 AddItemsAsync 按付费申请添加的逻辑对称）
- 汇率币别必须跟删除后剩余明细的币别完全一致
- 删除后自动回滚：OrderFee.SettledAmount / SettlementStatus、PaymentApplicationItem.UnSettledAmount、PaymentApplication.Status

## 八、锁定

### `PUT /api/services/app/PaymentSettlementAdmin/LockAsync`

**权限**：`Admin.PaymentSettlement.Lock`

**入参** `PaymentSettlementLockDto`：

| 字段 | 类型   | 必填 | 说明       |
| ---- | ------ | ---- | ---------- |
| `id` | `Guid` | 是   | 付费结算ID |

**出参**：`bool`

**业务规则**：

- 已锁定的不能重复锁定（`locked == true` 时拒绝）
- 锁定后 `locked` 置为 `true`，`lockeTime` 赋值为当前时间
- 锁定后不能进行任何编辑/删除操作，除非解锁

---

## 九、解锁

### `PUT /api/services/app/PaymentSettlementAdmin/UnLockAsync`

**权限**：`Admin.PaymentSettlement.Unlock`

**入参** `PaymentSettlementLockDto`：

| 字段 | 类型   | 必填 | 说明       |
| ---- | ------ | ---- | ---------- |
| `id` | `Guid` | 是   | 付费结算ID |

**出参**：`bool`

**业务规则**：

- 未锁定的不能解锁（`locked == false` 时拒绝）
- 解锁后 `locked` 置为 `false`，`lockeTime` 置为 `null`

## 十一、附件说明

所有涉及附件的接口使用 `AttachmentItemForItemInputDto`：

## 十二、错误提示汇总

| 错误信息 | 触发条件 |
| --- | --- |
| `输入不能为空` | 入参为null |
| `结算对象不存在` | settlementId 无效 |
| `结算币别不存在` | currencyId 无效 |
| `我司银行不存在` | orgBankAccountId 无效 |
| `结算对象银行不存在` | clientInvoiceBankId 无效 |
| `汇率列表中存在重复的币别` | 传了重复的originalCurrencyId |
| `汇率列表中存在不存在的币别` | originalCurrencyId 在币别表不存在 |
| `部分付费申请不存在` | paymentApplicationId 无效 |
| `付费申请【xx】状态不是审核通过或部分结算,不能结算` | 付费申请状态不对 |
| `付费申请【xx】的结算总金额xx不在可结算范围[xx, xx]内` | 固定币别申请的 settledPrice 超出总可结算上下限 |
| `付费申请【xx】币别ID【xx】的结算量xx不在可结算范围[xx, xx]内` | 结算量超出可结算上下限 |
| `汇率的币别种类必须跟结算明细的币别完全一致` | 汇率和明细币别不匹配 |
| `付费结算已锁定,不能编辑` | 对已锁定的结算进行编辑 |
| `付费结算已锁定,不能删除` | 对已锁定的结算进行删除 |
| `以下付费申请已在该结算单中,不能重复添加` | AddItemsAsync时重复添加 |
| `要删除的付费申请ID列表不能为空` | DeleteItemsAsync时paymentApplicationIds为空 |
| `未找到对应付费申请的结算明细` | 传入的付费申请ID在该结算单中无对应明细 |
| `付费结算已锁定,不能重复锁定` | 重复锁定 |
| `付费结算未锁定,不能解锁` | 对未锁定的结算解锁 |
