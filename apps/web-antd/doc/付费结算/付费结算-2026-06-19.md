# 1. 背景意图 (Background)

付费结算业务围绕“付费申请”进行：本质是企业对外付款，因此在计算可结算的“有效金额(effectiveAmounts)”时，方向应为 **付 - 收**（付为正、收为负）。

此前代码错误地使用了 **收 - 付**（收为正、付为负）的方向，导致：

- `PaymentApplicationAdminAppService.GetPagedListForSettlementAsync` 返回的可结算上下限（`SettleableUpperLimit` / `SettleableLowerLimit` 及对应价格）符号方向相反；
- 用户在结算选择列表看到的上下限，与 `PaymentSettlementAdminAppService` 实际结算时的范围校验口径一致性存在风险。

本次修复统一为 **付 - 收** 方向。

# 2. 核心逻辑变更 (Core Changes)

## 2.1 PaymentApplicationAdminAppService.GetPagedListForSettlementAsync

`src/CsprojBuilder.Application/App/PaymentApplication/PaymentApplicationAdminAppService.cs`

- 固定币别申请分组（CurrencyGroup）与原币申请分组两处 `effectiveAmounts` 计算：
  - 修改前：`i.OrderFee.PaySide == PaySide.收 ? i.UnSettledAmount : -i.UnSettledAmount`（收-付，错误）
  - 修改后：`i.OrderFee.PaySide == PaySide.付 ? i.UnSettledAmount : -i.UnSettledAmount`（付-收，正确）
- 影响字段：`TotalUnSettledAmount`、`SettleableUpperLimit`、`SettleableLowerLimit`、`SettleablePriceUpperLimit`、`SettleablePriceLowerLimit`（符号方向随之修正）。

## 2.2 PaymentSettlementAdminAppService（一致性同步修正）

`src/CsprojBuilder.Application/App/PaymentSettlement/PaymentSettlementAdminAppService.cs`

- `BuildSettlementItemsForCurrency`：有效金额 `Effective` 计算由 收-付 改为 付-收；注释由“收取原值 付取相反数”更正为“付取原值 收取相反数”。
- `DistributeSettledPriceAcrossCurrencies`：`effectiveAmounts` 计算由 收-付 改为 付-收。
- 上述两处的 `upperLimit` / `lowerLimit` / `Range` 及后续按序分配逻辑均由有效金额派生，方向修正后整体保持自洽，无需额外改动。

# 3. 避坑指南 (Pitfalls)

- **方向口径必须全链路统一**：结算选择列表（GetPagedListForSettlementAsync）展示的上下限，与结算保存时的范围校验（BuildSettlementItemsForCurrency / DistributeSettledPriceAcrossCurrencies）必须使用相同的“付-收”符号约定，否则用户输入的结算量会落在错误的可结算区间。
- **正负含义**：付-收约定下，正数有效金额代表净付出（上限方向），负数代表净收回（下限方向）。
- 存库的 `SettledAmount` 仍使用明细原始 `UnSettledAmount`，符号约定仅用于上下限判定与正负项分配，不改变落库金额本身。
