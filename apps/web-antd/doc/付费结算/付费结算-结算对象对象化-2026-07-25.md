# 1. 背景意图 (Background)

付费结算、银行流水的详情/列表此前返回字符串 `settlementName`。业务单据（海运出口、付费申请等）已统一为 `ClientSimpleDtoForOrder settlement` 对象（含简称/全称/默认地址）。本次对齐这两个模块，**删除 `settlementName`**，改为返回 `settlement` 对象。

# 2. 核心逻辑变更 (Core Logic)

## 2.1 涉及接口

| 模块 | 接口 | 变更 |
| :-- | :-- | :-- |
| 付费结算 Admin | `GET .../PaymentSettlementAdmin/DetailAsync` | 删除 `settlementName`，新增 `settlement`；分组内 `paymentApplications[]` 同步带 `settlement` |
| 付费结算 Admin | `GET .../PaymentSettlementAdmin/GetPagedListAsync` | 同上 |
| 银行流水 Admin | `GET .../BankStatementAdmin/DetailAsync` | 删除 `settlementName`，新增 `settlement` |
| 银行流水 Admin | `GET .../BankStatementAdmin/GetPagedListAsync` | 同上 |
| 银行流水 非Admin | `GET .../BankStatement/DetailAsync`、`GetPagedListAsync` | 共用同一 DTO，同步变更 |

## 2.2 `settlement` 字段结构（`ClientSimpleDtoForOrder`）

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | `Guid` | 客户ID |
| `name` | `string` | 客户简称 |
| `fullName` | `string` | 客户全称 |
| `address` | `string` | 默认地址（`ClientAddresses.IsDefault=true` 的 `Address`） |

地址口径与海运出口 `MapClient`、付费申请详情一致。

# 3. 避坑指南 (Pitfalls)

- **破坏性变更**：前端必须改读 `settlement?.name`，不能再读 `settlementName`（字段已删除，不是并存）。
- **费用上的 `orderFee.settlementName` 未改**：那是费用维度的结算对象名称字符串，与单据主表 `settlement` 对象无关。
- **无默认地址时 `address` 为 null**：打印/展示需空值兜底。
