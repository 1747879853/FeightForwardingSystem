# 付费结算 - 选择付费申请列表接口文档

## 一、接口概述

**接口名称**：`GET PaymentApplicationAdmin/GetPagedListForSettlementAsync`

**用途**：付费结算模块选择可结算的付费申请列表。只返回**已审核通过**且**有未结算余额**的付费申请。

**权限**：`Admin_PaymentApplication_Get`

> 另有一整套同数据源、以「付费申请 + 原币币别」为一条数据的并存接口（选择列表 / 新建 / 加明细 / 删明细 / 详情），详见 [付费结算-按原币和付费申请-接口文档.md](./付费结算-按原币和付费申请-接口文档.md)。

---

## 二、入参

`PaymentApplicationQueryDto`（Query 参数）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `paymentSettlementId` | `Guid?` | 否 | 付费结算ID，传入后会**排除**该结算单已关联的付费申请 |
| `keyword` | `string` | 否 | 关键字，模糊匹配费用关联的业务 CommissionNum / MblNum / BookingNum |
| `applicationNo` | `string` | 否 | 申请单号（模糊匹配） |
| `settlementId` | `Guid?` | 否 | 结算对象ID（客户） |
| `currencyId` | `long?` | 否 | 币别ID。不传=搜全部；传 `0`=搜原币申请；传具体值=搜指定币别 |
| `settlementCurrencyId` | `long?` | 否 | 结算单的结算币别。传了之后固定币别申请只返回申请币别等于它的，原币申请只返回 `currencyGroup` 中该原币那一组。**建单/加明细场景必传**，否则前端会列出选了也提交不了的申请 |
| `submitTimeStart` | `DateTime?` | 否 | 提交时间起 |
| `submitTimeEnd` | `DateTime?` | 否 | 提交时间止 |
| `endTimeStart` | `DateTime?` | 否 | 最晚付款时间起 |
| `endTimeEnd` | `DateTime?` | 否 | 最晚付款时间止 |
| `creatorUserId` | `long?` | 否 | 申请人ID |
| `orgId` | `long?` | 否 | 组织ID（数据权限过滤） |
| `pageIndex` | `int` | 是 | 当前页码（从1开始） |
| `pageSize` | `int` | 是 | 每页条数 |
| `sorting` | `string` | 否 | 排序字段 |

**硬性过滤条件（不需要前端传参）**：

| 条件 | 说明 |
|------|------|
| `Status == Passed \|\| Status == Partial` | 只返回审核通过（3）或部分结算（4）的付费申请 |
| `PaymentApplicationItems.Any(x => x.UnSettledAmount > 0)` | 至少有一条明细的未结算金额 > 0 |
| 排除 `paymentSettlementId` 已关联的 | 如果传了 `paymentSettlementId`，排除该结算单已选过的付费申请 |

> **结算币别约束（2026-08-10）**：付费结算不再录汇率，汇率一律取自付费申请。因此固定币别申请的申请币别必须等于结算币别，原币申请只能结算原币等于结算币别的费用。传 `settlementCurrencyId` 让接口把不满足的申请和币别分组直接过滤掉。

## 五、Status 状态说明

| 枚举值 | 名称 | 含义 |
|--------|------|------|
| 0 | Entering | 录入/未提交 |
| 1 | Auditing | 已提交/审核中 |
| 2 | Rejected | 审核驳回 |
| **3** | **Passed** | **审核通过（未进行过付费结算）** |
| **4** | **Partial** | **部分结算（已结算但还有未结算完的）** |
| 5 | Settlemented | 结算完毕 |

> 本接口只会返回 `status = 3` 或 `status = 4` 的数据。

## 六、PaymentSettlementId 排除逻辑

当编辑付费结算时，传入当前结算单的 `paymentSettlementId`，接口会查询 `PaymentSettlementItem` 表中该结算单已关联的所有付费申请ID，并从结果中排除，避免重复选择。

| 场景 | paymentSettlementId | 行为 |
|------|---------------------|------|
| 新建付费结算 | 不传 | 返回所有可结算的付费申请 |
| 编辑付费结算 | 传当前结算单ID | 排除该结算单已选过的付费申请 |

## 七、固定币别 vs 原币申请 字段差异

| 字段 | 固定币别申请（CurrencyId 有值） | 原币申请（CurrencyId 为 null） |
|------|------|------|
| `currencyCode` | 有值 | null |
| `totalPayPrice` | 有值（各币别 PayPrice 之和） | null |
| `totalReceivePrice` | 有值（各币别 ReceivePrice 之和） | null |
| `totalSettleablePriceUpperLimit` | 有值（各币别 SettleablePriceUpperLimit 之和） | null |
| `totalSettleablePriceLowerLimit` | 有值（各币别 SettleablePriceLowerLimit 之和） | null |
| `currencyGroup[].receivePrice` | 有值 | null |
| `currencyGroup[].payPrice` | 有值 | null |
| `currencyGroup[].settleablePriceUpperLimit` | 有值（settleableUpperLimit × 汇率） | null |
| `currencyGroup[].settleablePriceLowerLimit` | 有值（settleableLowerLimit × 汇率） | null |
