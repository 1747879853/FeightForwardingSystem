# 1. 背景意图 (Background)

ByCurrency 流程落地后有两处需要补齐：

1. **选择列表缺结算币别口径的「整行未结满」金额**。前端结满一行时只能自己用原币量乘汇率心算，同一原币多汇率时算不准，且和后端校验区间对不上。
2. **结算侧分配路径绕了两圈**。`BuildSettlementItemsByCurrencyRows` 先调 `ResolveSettledAmountFromPrice` 在结算币别口径上倒算原币总额，再调 `BuildSettlementItemsForCurrency` 用原币总额再分一次，同一套「按费用录入顺序逐条吃额度」写了两遍，还有两轮舍入。

# 2. 核心逻辑变更 (Core Changes)

## 2.1 选择列表新增 `TotalUnSettledPrice`

`src/CsprojBuilder.Application/App/PaymentApplication/Dto/PaymentApplicationDto.cs`

- `PaymentApplicationCurrencyForSettlementDto` 新增 `decimal TotalUnSettledPrice`（非空）。
- 含义：该「付费申请 + 原币」行在**结算币别**下的未结算净额，等于可结算上下限各自取整后再相加。
- 固定币别申请：逐条 `有效金额 × PaymentApplicationItem.Rate` 累加；原币申请：汇率恒为 1，数值等于 `TotalUnSettledAmount`。
- 字段做成非空 `decimal`：原币申请行原币等于结算币别，返 null 会导致前端合计不出总额。

`GetPagedListByCurrencyForSettlementAsync` 组装金额时同步修正：

- `SettleablePriceUpperLimit` / `SettleablePriceLowerLimit` 不再用组内首条明细的代表汇率乘整组上下限，改为与 `TotalUnSettledPrice` 同源的逐条汇率累加结果。
- 可空性不变：仍只有固定币别申请给值；原币申请这两个字段为 null，前端用 `settleableUpperLimit` / `settleableLowerLimit`（或直接用 `totalUnSettledPrice`）即可。

取整口径刻意与结算侧对齐：上下限各自 `ToFinancialRound` 后再相加，而不是先求和再取整。结算侧判定「整行全额结算」用的是 `settledPrice == priceUpper + priceLower`；前端把 `totalUnSettledPrice` 原样当 `settledPrice` 传过去必须逐位一致，否则会走偏部分结算分支。

## 2.2 结算分配合并进 `BuildSettlementItemsByCurrencyRows`

`src/CsprojBuilder.Application/App/PaymentSettlement/PaymentSettlementAdminAppService.cs`

- **删除**私有方法 `ResolveSettledAmountFromPrice`、`BuildSettlementItemsForCurrency`。
- `BuildSettlementItemsByCurrencyRows` 一次走完：币别校验 → 按 `OrderFee.CreationTime` 排序 → 结算币别口径上下限校验 → 按 `diffPrice` 全额/正吃负/负吃正分配 → 落 `PaymentSettlementItem`。
- 吃满的明细直接取自身 `UnSettledAmount`，只有被截断的那一条才做 `takePrice / Rate`，避免两轮舍入累计误差。
- 超范围只剩一条提示：`付费申请【xx】币别ID【xx】的结算金额xx不在可结算范围[xx, xx]内`。原「结算量」口径的报错不再出现。

注释掉的 `AddAsync` / `AddItemsAsync` 里仍残留对已删方法的调用文本，整段在 `/* */` 中不影响编译。

# 3. 避坑指南 (Pitfalls)

- **结满一行请直接传 `totalUnSettledPrice`**，不要自己用 `totalUnSettledAmount × 某个汇率` 心算。同一原币多汇率时心算必错。
- **原币申请行也有 `totalUnSettledPrice`**，值等于 `totalUnSettledAmount`，不要因为 `settleablePrice*` 为 null 就以为结算币别金额没有。
- **`settleablePriceUpperLimit` / `settleablePriceLowerLimit` 的计算口径变了**。以前是组内首条汇率 × 原币上下限，现在是逐条汇率累加。联调时若旧前端还按代表汇率心算区间，会和接口返回值差几分。
- **不要再期望「结算量不在可结算范围」这条错误**。超范围统一报「结算金额」。
