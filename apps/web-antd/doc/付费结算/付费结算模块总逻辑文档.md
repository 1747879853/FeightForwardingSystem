# 1. 业务背景说明 (Background)

**白话解释：**

付费申请审核通过后，财务按结算对象、结算币别做一笔付费结算：把多张付费申请里尚未结完的费用，折到同一种结算币别上付款。一张结算单只对应一个结算对象、一种结算币别，明细按「付费申请 + 原币币别」落库。

主表另有可选的**手续费**和**手续费币别**。手续费币别允许不填；不填时接口回显按结算币别展示，避免历史单和未选币别的单在前端没有币别对象。

当前写接口以 ByCurrency 套为准：`AddByCurrencyAsync` / `AddItemsByCurrencyAsync` / `DeleteItemsByCurrencyAsync` / `DetailByCurrencyAsync`。旧的 `AddAsync` / `AddItemsAsync` / `DetailAsync` 已在服务端注释停用。修改主表仍走 `EditAsync`。接口字段以 [付费结算-按原币和付费申请-接口文档.md](./付费结算-按原币和付费申请-接口文档.md) 与 [付费结算接口文档.md](./付费结算接口文档.md) 为准。

# 2. 功能与操作说明 (Features & Operations)

- **新建结算：** 选定结算对象、结算币别、可选手续费及手续费币别，按行提交「付费申请 + 原币」的结算金额，生成结算单号并回写费用已结量、申请未结量与申请状态。
- **修改主表：** 改结算时间、付款方式、银行、手续费、手续费币别、备注、附件。不能改结算对象和结算币别。已锁定不可改。改结算时间时，本单结算过的费用的最终结算时间会重算。
- **追加 / 删除明细：** 按「付费申请 + 原币币别」增删行，同步回滚或累加已结量，并维护费用的结算状态、最终结算时间与客户超期历史。
- **列表：** `GET PaymentSettlementAdmin/GetPagedListAsync`，出参 `PaymentSettlementListDto`。主表列全部返回。结算对象只留简称，结算币别和手续费币别只留代码，业务分组只留主提单号和委托编号。不返回币别汇总、付费申请简要、费用简要、申请人昵称。组织串每级只有名称，并带本位币代码。
- **详情：** 返回结算币别 `currency`、手续费币别 `transactionFeeCurrency`（空则回落到结算币别），以及币别组、按申请组的嵌套费用清单。费用清单按费用 `sortId` 升序、相同再按创建时间升序。
- **锁定 / 解锁：** 锁定后禁止编辑和删除。

# 5. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **[卡点 1：手续费币别回显回落]** 库里的 `TransactionFeeCurrencyId` 可以为空（历史单、前端未选）。列表 `GetPagedListAsync`、详情 `DetailByCurrencyAsync` 返回的 `transactionFeeCurrency` **不会因为库空而为 null**：空则按结算币别 `CurrencyId` 组装 `CurrencySimpleDto`。前端展示手续费币别请读 `transactionFeeCurrency`，不要只看 `transactionFeeCurrencyId`。
>
> 写入仍按实传：不传就存 null，不会在新增时把结算币别写进手续费币别列。

> [!IMPORTANT] **[卡点 2：已锁定禁止改删]** `Locked == true` 时编辑主表、增删明细、删除整单都会失败。

> [!IMPORTANT] **[卡点 3：结算时间参与费用最终结算时间的取值，但取的是「最大」不是「最后一次」]** 费用表 `App_OrderFees` 的冗余字段 `FinalSettlementTime`（最终结算时间）只有费用结算完毕时才有值，取的是该费用**全部**关联结算里业务时间最大的那条：付费结算侧参与比较的是本结算单的 `SettlementTime`，收费结算侧参与比较的是其所挂银行流水的 `StatementTime`（不是收费结算自己的结算时间）。
>
> 一条费用可以同时挂多张付费结算单和多条银行流水，后补的那次结算业务时间未必更晚，所以**每次都按来源重算**，不在某一次结算里直接写。`EditAsync` 改结算时间时会调 `SyncFinalSettlementTimeAsync` 把本单结算过的费用整批重算（不做筛选，时间改大可能让本单占上最大值，改小则可能让位给别的结算）。删明细、删整单导致费用退出结算完毕时，最终结算时间立即置空。
>
> 完整口径见 [收费结算.md](../收费结算/收费结算.md) 第十三之二节。

> [!IMPORTANT] **[卡点 4：应收费用结清晚于应结日期会留一条客户超期记录]** 最终结算时间一变，就会连带重算**客户超期历史** `App_ClientOverdueHistories`：应收费用结算完毕、且最终结算日期（舍掉小时）晚于业务的应结日期 `TransportOrder.SettlementDate` 时留一条记录，记客户id（费用的结算对象）、业务id、应结日期、最终结算日期、超期天数。
>
> 付费结算里的**应付**费用不入表；付费申请允许混入应收费用，那部分与收费结算同等处理。费用退出结算完毕、或改时间后不再超期时记录会被删掉，不留历史。完整口径见 [收费结算.md](../收费结算/收费结算.md) 第十三之三节。
