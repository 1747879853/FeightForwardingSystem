# 付费结算 - 按原币和付费申请 接口文档

## 一、总览

这是一整套与原有接口**并存**的接口，把付费结算全流程的粒度从「一条付费申请」下沉到「一条付费申请 + 一个原币币别」。选择列表、新建、加明细、删明细、详情五个环节的行结构完全一致，前端选完可直接提交，回显结构也一样，不需要在一维和两层之间来回转换。

| 环节 | 原接口 | 本套接口 | 权限 |
| --- | --- | --- | --- |
| 选择付费申请 | `GET PaymentApplicationAdmin/GetPagedListForSettlementAsync` | `GET PaymentApplicationAdmin/GetPagedListByCurrencyForSettlementAsync` | `Admin_PaymentApplication_Get` |
| 新建结算 | `POST PaymentSettlementAdmin/AddAsync` | `POST PaymentSettlementAdmin/AddByCurrencyAsync` | `Admin_PaymentSettlement_Add` |
| 追加明细 | `POST PaymentSettlementAdmin/AddItemsAsync` | `POST PaymentSettlementAdmin/AddItemsByCurrencyAsync` | `Admin_PaymentSettlement_Edit` |
| 删除明细 | `POST PaymentSettlementAdmin/DeleteItemsAsync` | `POST PaymentSettlementAdmin/DeleteItemsByCurrencyAsync` | `Admin_PaymentSettlement_Edit` |
| 结算详情 | `GET PaymentSettlementAdmin/DetailAsync` | `GET PaymentSettlementAdmin/DetailByCurrencyAsync` | `Admin_PaymentSettlement_Get` |

### 三个币别概念（全文最容易混的地方）

| 概念 | 字段 | 含义 |
| --- | --- | --- |
| **原币币别** | `originalCurrencyId` | 费用自身的币别（`OrderFee.CurrencyId`），也是本套接口的分组键、汇率表的键、结算明细的键 |
| **申请币别** | 付费申请行上的 `currencyId` | 付费申请头上的币别，为 null 代表原币申请 |
| **结算币别** | 结算单头上的 `currencyId` | 整张结算单最终的结算币别，各原币通过汇率折算过来 |

### 与原接口的行为差异

| 差异点 | 原接口 | 本套接口 |
| --- | --- | --- |
| 选择列表一行 | 一个付费申请，币别在 `currencyGroup[]` 里 | 一个「付费申请+原币币别」组合 |
| 选择列表 `totalCount` | 付费申请条数 | 展开后的组合行数 |
| 写接口结算行 | `paymentApplicationGroups[].currencyItems[]` 两层 | `paymentApplicationCurrencyItems[]` 一层 |
| 按总额自动分摊 | 固定币别申请可只传 `settledPrice` 由后端分摊 | **不支持**，每行必须直接给 `settledAmount` |
| 追加/删除判重粒度 | 按付费申请 | 按「付费申请+原币币别」组合 |
| 详情结算内容 | `paymentApplications[]` 按申请分组、内嵌 `currencyGroup[]` | `paymentApplicationCurrencies[]` 一维行 |

### 前端串联流程

1. 选择付费申请：调 `GetPagedListByCurrencyForSettlementAsync`，拿到一维行，每行带 `originalCurrencyId` 和可结算上下限。
2. 用户按行填结算量，字段名一一对应地组装成 `paymentApplicationCurrencyItems`。
3. 新建走 `AddByCurrencyAsync`；编辑时追加走 `AddItemsByCurrencyAsync`，去掉某行走 `DeleteItemsByCurrencyAsync`。
4. 回显走 `DetailByCurrencyAsync`，`paymentApplicationCurrencies` 的行结构与第 1 步一致。

> **汇率是全量替换**：三个写接口的 `paymentSettlementRates` 币别集合都必须与操作后结算单中所有明细的原币币别集合**完全相等**，多一个少一个都会报错。

## 二、接口一：选择付费申请列表

**`GET PaymentApplicationAdmin/GetPagedListByCurrencyForSettlementAsync`**

**权限**：`Admin_PaymentApplication_Get`

过滤口径与 `GetPagedListForSettlementAsync` 完全一致，只是把原来行内的 `currencyGroup[]` 拍平，每个币别单独成行，分页也按展开后的行数算。

### 入参 PaymentApplicationQueryDto（Query，与原接口共用同一个类）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `paymentSettlementId` | `Guid?` | 否 | 付费结算ID，传入后**排除**该结算单已关联的付费申请 |
| `keyword` | `string` | 否 | 关键字，模糊匹配费用关联业务的 CommissionNum / MblNum / BookingNum |
| `applicationNo` | `string` | 否 | 申请单号（模糊匹配） |
| `settlementId` | `Guid?` | 否 | 结算对象ID（客户） |
| `currencyId` | `long?` | 否 | **本接口语义已调整，见下表** |
| `submitTimeStart` | `DateTime?` | 否 | 提交时间起 |
| `submitTimeEnd` | `DateTime?` | 否 | 提交时间止 |
| `endTimeStart` | `DateTime?` | 否 | 最晚付款时间起 |
| `endTimeEnd` | `DateTime?` | 否 | 最晚付款时间止 |
| `creatorUserId` | `long?` | 否 | 申请人ID |
| `orgId` | `long?` | 否 | 组织ID（含下级组织，数据权限过滤） |
| `pageIndex` | `int` | 是 | 当前页码（从1开始） |
| `pageSize` | `int` | 是 | 每页条数，**控制返回多少个「申请+币别」组合行** |
| `sorting` | `string` | 否 | 排序字段，作用于付费申请层 |

`status`、`invoiceProcess`、`invoiceNo`、`invoiceDateStart`、`invoiceDateEnd` 本接口不参与过滤。

#### currencyId 语义对比

| 传值 | 原接口 | 本接口 |
| --- | --- | --- |
| 不传 | 搜全部 | 搜全部 |
| `0` | 只搜原币申请（申请币别为空） | 同左，**语义未变** |
| `>0` | 搜「申请币别=该值」或「原币申请中含该币别费用」的申请，返回整条申请 | **直接按行过滤**，只返回原币币别=该值的行 |

#### 硬性过滤条件（不需要前端传参）

| 条件 | 说明 |
| --- | --- |
| `Status == Passed \|\| Status == Partial` | 只返回审核通过（3）或部分结算（4）的付费申请 |
| `PaymentApplicationItems.Any(x => x.UnSettledAmount > 0)` | 该付费申请至少有一条明细的未结算金额 > 0 |
| 排除 `paymentSettlementId` 已关联的 | 传了 `paymentSettlementId` 时排除该结算单已选过的付费申请 |

### 出参 `PagedList<PaymentApplicationCurrencyForSettlementDto>`

```json
{ "totalCount": 5, "items": [ PaymentApplicationCurrencyForSettlementDto, ... ] }
```

#### PaymentApplicationCurrencyForSettlementDto

继承 `DataPermissionFullAuditedEntityDto<Guid>`（基类字段见 [第七节](#七公共-dto)）。

**行标识**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `Guid` | 付费申请ID。**同一申请多币别时多行重复**，表格行 key 请用 `rowKey` |
| `rowKey` | `string` | 行唯一键，格式 `付费申请id_原币币别id` |
| `paymentApplicationId` | `Guid` | 付费申请ID，与 `id` 相同，便于语义化取值 |

**付费申请维度（同一申请的多行内容相同）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `applicationNo` | `string` | 申请单号 |
| `status` | `int` | 申请状态：`3`=审核通过，`4`=部分结算 |
| `submitTime` | `DateTime?` | 提交时间 |
| `endTime` | `DateTime?` | 最晚付款时间 |
| `settlementId` | `Guid` | 结算对象ID |
| `currencyId` | `long?` | **申请币别**ID（null=原币申请） |
| `require` | `string` | 支付要求 |
| `remark` | `string` | 备注 |
| `invoiceProcess` | `int?` | 发票流程 0先票后付 1先付后票 2不开票 |
| `invoiceNo` | `string` | 发票号 |
| `invoiceDate` | `DateTime?` | 开票日期 |
| `tenantId` | `int` | 租户ID |
| `settlement` | `ClientSimpleDtoForOrder` | 结算对象（含默认地址） |
| `currency` | `CurrencySimpleDto` | 申请币别对象，原币申请为 null |
| `creatorUserName` | `string` | 创建人昵称 |
| `lastModifierUserName` | `string` | 最后修改人昵称 |

> 本接口**不返回** `paymentSettlements`（已关联的付费结算简要列表）。需要的话走原接口 `GetPagedListForSettlementAsync` 或付费申请详情。

**原币币别维度（本行的分组键与金额）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `originalCurrencyId` | `long` | **原币币别**ID，取自 `OrderFee.CurrencyId` |
| `originalCurrencyCode` | `string` | 原币币别代码，如 USD、CNY |
| `rate` | `decimal?` | 本行原币除以申请币别的汇率，原币申请为 null |
| `payAmount` | `decimal` | 申请量（付），原币 |
| `payPrice` | `decimal?` | 申请金额（付），转成申请币别，原币申请为 null |
| `receiveAmount` | `decimal` | 申请量（收），原币 |
| `receivePrice` | `decimal?` | 申请金额（收），转成申请币别，原币申请为 null |
| `totalUnSettledAmount` | `decimal` | 该原币币别未结算量（不乘汇率）= 收的有效金额 + 付的有效金额 |
| `settleableUpperLimit` | `decimal` | **可结算上限**（原币）= 正数有效金额之和 |
| `settleablePriceUpperLimit` | `decimal?` | 可结算上限（申请币别）= `settleableUpperLimit` × 汇率，原币申请为 null |
| `settleableLowerLimit` | `decimal` | **可结算下限**（原币）= 负数有效金额之和 |
| `settleablePriceLowerLimit` | `decimal?` | 可结算下限（申请币别）= `settleableLowerLimit` × 汇率，原币申请为 null |
| `orderFees` | `OrderFeeDto[]` | 该原币币别下的费用列表 |

> **有效金额定义**：付的费用取 `UnSettledAmount`，收的费用取 `-UnSettledAmount`。结果为正的累加得可结算上限，为负的累加得可结算下限。所有金额按财务规则保留2位。提交结算时该行的 `settledAmount` 必须落在 `[settleableLowerLimit, settleableUpperLimit]` 内。

**任务相关**

| 字段                | 类型        | 说明       |
| ------------------- | ----------- | ---------- |
| `auditUserId`       | `long?`     | 审核人ID   |
| `auditUserNickName` | `string`    | 审核人昵称 |
| `auditTime`         | `DateTime?` | 审核时间   |

### 排序与分页规则

1. `sorting` 作用在**付费申请**层，先排出付费申请的顺序；
2. 同一付费申请内部的多个原币币别按 `originalCurrencyId` **升序**；
3. 按上述顺序展开成一维行后再按 `pageIndex` / `pageSize` 切片；
4. `totalCount` 是展开后的**总行数**。

因此同一付费申请的多行可能被切到**两页**，做「按申请合并单元格」展示时需处理跨页。

### 固定币别申请 vs 原币申请

| 字段 | 固定币别申请（`currencyId` 有值） | 原币申请（`currencyId` 为 null） |
| --- | --- | --- |
| `currency` / `rate` / `payPrice` / `receivePrice` / `settleablePriceUpperLimit` / `settleablePriceLowerLimit` | 有值 | null |
| `payAmount` / `receiveAmount` / `totalUnSettledAmount` / `settleableUpperLimit` / `settleableLowerLimit` | 有值 | 有值 |

## 三、写接口的公共结构

### PaymentSettlementItemByCurrencyInputDto（结算行输入）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `paymentApplicationId` | `Guid` | 是 | 付费申请ID |
| `originalCurrencyId` | `long` | 是 | 原币币别ID（费用的币别） |
| `settledAmount` | `decimal` | 是 | 本行结算的净额（原币），需落在该行的 `[settleableLowerLimit, settleableUpperLimit]` 内 |

### PaymentSettlementPayAppCurrencyKeyDto（结算行定位键）

| 字段                   | 类型   | 必填 | 说明       |
| ---------------------- | ------ | ---- | ---------- |
| `paymentApplicationId` | `Guid` | 是   | 付费申请ID |
| `originalCurrencyId`   | `long` | 是   | 原币币别ID |

### PaymentSettlementRateAddDto（汇率）

| 字段                 | 类型      | 必填 | 说明                            |
| -------------------- | --------- | ---- | ------------------------------- |
| `originalCurrencyId` | `long`    | 是   | 原币币别ID                      |
| `rate`               | `decimal` | 是   | 原币对结算币别的汇率（6位小数） |

## 四、接口二：新增付费结算

**`POST PaymentSettlementAdmin/AddByCurrencyAsync`**

**权限**：`Admin_PaymentSettlement_Add`

### 入参 PaymentSettlementAddByCurrencyDto（Body）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `settlementTime` | `DateTime` | 是 | 结算时间 |
| `payType` | `int?` | 否 | 付款方式 |
| `settlementId` | `Guid` | 是 | 结算对象ID（客户） |
| `orgId` | `long?` | 是 | 所属公司ID，必须是当前用户的直属组织 |
| `currencyId` | `long` | 是 | **结算币别**ID |
| `orgBankAccountId` | `Guid?` | 否 | 我司银行ID |
| `clientInvoiceBankId` | `Guid?` | 否 | 结算对象银行ID |
| `transactionFee` | `decimal?` | 否 | 手续费（2位） |
| `remark` | `string` | 否 | 备注 |
| `paymentSettlementRates` | `PaymentSettlementRateAddDto[]` | 是 | 汇率列表，币别种类必须与结算行的原币币别**完全一致** |
| `paymentApplicationCurrencyItems` | `PaymentSettlementItemByCurrencyInputDto[]` | 是 | 结算行列表，组合不能重复 |
| `attachments` | `AttachmentItemForItemInputDto[]` | 否 | 附件 |

### 出参

`Guid` —— 新建的付费结算ID。

### 校验规则

| 校验 | 报错文案 |
| --- | --- |
| 结算行为空 | 结算行列表不能为空 |
| 汇率为空 | 汇率列表不能为空 |
| 结算对象不存在 | 结算对象不存在 |
| 结算币别不存在 | 结算币别不存在 |
| 组织不是本人直属 | （由 `EnsureUserOwnsOrgAsync` 抛出） |
| 我司银行/对方银行不存在 | 我司银行不存在 / 结算对象银行不存在 |
| 汇率币别重复 | 汇率列表中存在重复的币别 |
| 汇率币别不存在 | 汇率列表中存在不存在的币别 |
| 结算行组合重复 | 结算行列表中存在重复的付费申请+原币币别组合 |
| 付费申请不存在 | 部分付费申请不存在 |
| 付费申请状态不是3/4 | 付费申请【单号】状态不是审核通过或部分结算,不能结算 |
| 费用结算对象与结算单不一致 | 存在费用的结算对象与付费结算的结算对象不一致 |
| 某行原币币别不在汇率表中 | 付费申请【单号】的币别ID【x】在汇率列表中不存在 |
| 某行原币币别在该申请下没有费用 | 付费申请【单号】下没有币别ID【x】的费用 |
| 汇率币别 ≠ 明细币别 | 汇率的币别种类必须跟结算明细的币别完全一致 |

## 五、接口三：添加结算明细

**`POST PaymentSettlementAdmin/AddItemsByCurrencyAsync`**

**权限**：`Admin_PaymentSettlement_Edit`

### 入参 PaymentSettlementAddItemsByCurrencyDto（Body）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `Guid` | 是 | 付费结算ID |
| `paymentApplicationCurrencyItems` | `PaymentSettlementItemByCurrencyInputDto[]` | 是 | 新增的结算行列表 |
| `paymentSettlementRates` | `PaymentSettlementRateAddDto[]` | 是 | 汇率列表（全量替换），需包含新增后**所有**原币币别 |

### 出参

`bool` —— 固定返回 `true`。

### 判重规则（与原接口的核心差异）

按「付费申请+原币币别」组合判重：**同一付费申请的另一个原币币别可以追加进来**，只有完全相同的组合才报错。

报错文案：`以下付费申请+原币币别已在该结算单中,不能重复添加: 【PA202607090001-USD】、【PA202607090002-CNY】`

其余校验（结算单存在、未锁定、付费申请存在且状态合法、费用结算对象一致、汇率币别不重复不缺失、行组合不重复）与新增接口一致。汇率全量替换后，已有明细的 `Rate` 会同步刷新。

## 六、接口四：删除结算明细

**`POST PaymentSettlementAdmin/DeleteItemsByCurrencyAsync`**

**权限**：`Admin_PaymentSettlement_Edit`

### 入参 PaymentSettlementDeleteItemsByCurrencyDto（Body）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `Guid` | 是 | 付费结算ID |
| `paymentApplicationCurrencyKeys` | `PaymentSettlementPayAppCurrencyKeyDto[]` | 是 | 要删除的「付费申请+原币币别」组合列表 |
| `paymentSettlementRates` | `PaymentSettlementRateAddDto[]` | 是 | 汇率列表（全量替换），需包含删除后剩余的所有原币币别 |

### 出参

`bool` —— 固定返回 `true`。

### 行为说明

可以只删掉某个付费申请的某一个原币币别，该申请的其余币别保留在结算单里。删除时同步回滚：`PaymentApplicationItem.UnSettledAmount` 加回、`OrderFee.SettledAmount` 减回并重算 `SettlementStatus`、受影响付费申请的 `Status` 重算。

### 校验规则

| 校验                    | 报错文案                                         |
| ----------------------- | ------------------------------------------------ |
| 组合列表为空            | 要删除的付费申请+原币币别列表不能为空            |
| 汇率为 null             | 汇率列表不能为空                                 |
| 结算单不存在            | 付费结算不存在                                   |
| 结算单已锁定            | 付费结算已锁定,不能编辑                          |
| 组合都没匹配到明细      | 未找到对应付费申请+原币币别的结算明细            |
| 汇率币别 ≠ 剩余明细币别 | 汇率的币别种类必须跟删除后剩余明细的币别完全一致 |

> 全部删完时（剩余明细为空）不校验汇率币别，`paymentSettlementRates` 可以传空数组。

## 九、付费申请 Status 状态说明

| 枚举值 | 名称         | 含义                                   |
| ------ | ------------ | -------------------------------------- |
| 0      | Entering     | 录入/未提交                            |
| 1      | Auditing     | 已提交/审核中                          |
| 2      | Rejected     | 审核驳回                               |
| **3**  | **Passed**   | **审核通过（未进行过付费结算）**       |
| **4**  | **Partial**  | **部分结算（已结算但还有未结算完的）** |
| 5      | Settlemented | 结算完毕                               |

> 选择付费申请列表只会返回 `status = 3` 或 `status = 4` 的数据。
