# 海运进口模块接口文档

本文档只讲**怎么调用**：地址、鉴权、参数结构、返回结构、报文样例、报错文案。

业务含义、字段口径、计算规则、权限设计等**业务逻辑**统一见同目录下的《海运进口模块总逻辑文档》，本文不重复解释业务，只在需要时标注「规则见逻辑文档 X.Y」。

本文档面向**前端开发与测试**（含前端 AI 与测试 AI），内容覆盖到可以脱离后端独立完成开发与验证的程度。

# 1. 对接总纲

本章是纯技术约定，与业务无关，但**每一个请求都会受它影响**。第 4 章描述各接口时不再重复。

## 1.1 服务地址与鉴权

| 项 | 值 |
| :-- | :-- |
| 接口基址 | `{host}/api/services/app/SeaImportAdmin/` |
| 完整路径 | 基址 + 方法名，**方法名保留 `Async` 后缀** |
| 登录接口 | `POST {host}/api/TokenAuth/Authenticate`，请求体 `{ "userNameOrEmailAddress": "...", "password": "...", "rememberClient": true }` |
| 鉴权头 | `Authorization: Bearer {accessToken}`，token 取自登录接口返回的 `result.accessToken` |
| 租户头 | `Abp.TenantId: {租户id}`。宿主（Host）账号登录后不带该头；租户账号登录时带上自己的租户 id |
| 请求体类型 | `Content-Type: application/json`（POST / PUT / DELETE 都是） |

本模块 11 个接口**全部要求已登录**，且各自要求对应的功能权限点（见 1.9）。

## 1.3 统一响应包装

**所有**接口（包括报错）都返回同一层信封，业务数据在 `result` 里：

```json
{
  "result": { "……业务数据……" },
  "targetUrl": null,
  "success": true,
  "error": null,
  "unAuthorizedRequest": false,
  "__abp": true
}
```

失败时：

```json
{
  "result": null,
  "targetUrl": null,
  "success": false,
  "error": {
    "code": 0,
    "message": "销售有且只能有一个",
    "details": null,
    "validationErrors": null
  },
  "unAuthorizedRequest": false,
  "__abp": true
}
```

前端判定成功与否**只看 `success`**，失败时直接把 `error.message` 弹给用户——本文档各接口「报错文案」小节列出的引号内文字，就是 `error.message` 的原文。

## 1.4 HTTP 状态码

| 状态码 | 场景 | `success` |
| :-- | :-- | :-- |
| 200 | 调用成功 | `true` |
| **500** | **业务校验失败**（本文档列出的所有业务报错都走这里） | `false` |
| 401 | 未登录 / token 过期 / token 无效 | `false`，且 `unAuthorizedRequest = true` |
| 403 | 已登录但缺少对应功能权限点 | `false`，且 `unAuthorizedRequest = true` |
| 400 | 参数格式非法，模型绑定或 `[Range]`、`[StringLength]` 特性校验不通过；`error.validationErrors` 里是具体字段 | `false` |

> [!IMPORTANT] 业务错误返回的是 **HTTP 500**，不是 400。前端不能用「状态码 2xx」判成功、「4xx」判业务错误，必须按 `success` 字段判。测试断言业务报错时，期望值写「HTTP 500 且 `error.message` 等于 XXX」。

各接口的实现把整个方法体包在异常捕获里，任何非预期的系统异常（数据库超时、空引用等）也会被转成同样的信封返回，`error.message` 是原始异常消息。因此**看到不在本文档清单里的报错文案，就是系统异常，应当提缺陷**，而不是当成业务规则。

## 1.5 JSON 字段命名规则

响应体统一使用 **camelCase**（PascalCase 首字母连续大写的部分整体小写）。请求体的 JSON 反序列化不区分大小写，QueryString 的模型绑定也不区分大小写，因此**入参写 camelCase 或 PascalCase 都能被正确接收**；但**出参永远是 camelCase**。

本文档参数表里写的是 C# 属性名（PascalCase），报文样例里写的是实际 key（camelCase）。特殊换算：

| 属性名 | 响应中的 key | 说明 |
| :-- | :-- | :-- |
| `Vessel` | `vessel` | 常规首字母小写 |
| `POLId` / `PODId` | `polId` / `podId` | 连续大写整体转小写 |
| `POL` / `POD` / `POLRemark` | `pol` / `pod` / `polRemark` | 同上 |
| `POLIdEmpty` / `PODIdEmpty` | `polIdEmpty` / `podIdEmpty` | 同上 |
| `ETD` / `ETA` / `ATD` | `etd` / `eta` / `atd` | 同上 |
| `ETDStart` / `ETDEnd` | `etdStart` / `etdEnd` | 同上 |
| `PKGS` | `pkgs` | 同上 |
| `TEU` | `teu` | 同上 |
| `UpperPKGS` | `upperPKGS` | 第二个字符是小写，只转首字母 |
| `CodeGoodsHSCode` | `codeGoodsHSCode` | 第二个字符是小写，只转首字母 |
| `HSCode` | `hsCode` | 开头连续大写整体转小写，后面保持不变 |
| `Kgs` / `Cbm` | `kgs` / `cbm` | 常规 |
| `SeaImport` / `TransportOrder` | `seaImport` / `transportOrder` | 常规 |

## 1.6 数据类型在 JSON 中的表示

| 类型 | 请求写法 | 响应形态 | 说明 |
| :-- | :-- | :-- | :-- |
| `Guid` | `"3f2504e0-4f89-11d3-9a0c-0305e82c3301"` | 同左，小写带连字符 | 空 Guid 是 `"00000000-0000-0000-0000-000000000000"`，等价于「没传」 |
| `long` / `int` | `123` | `123` | 不要传字符串 |
| `decimal` | `1234.56` | `1234.56` | 标注了 2 位精度的字段，**入参会自动四舍五入到 2 位**再进入业务逻辑 |
| `bool` | `true` / `false` | 同左 |  |
| `DateTime` | `"2026-08-01"` 或 `"2026-08-01T13:20:00"` | `"2026-08-01T00:00:00"` | ISO 8601，**不带时区后缀**，服务端按本地时间原样存取，不做时区换算 |
| `enum` | 数字，如 `1` | 数字，如 `1` | **不接受也不返回枚举名字符串**，取值见第 2 章 |
| `null` | `null` | `null` | 可空字段不传等同于传 `null` |
| 数组 | `[...]` | `[...]` | 传 `null` 与传 `[]` 在部分接口语义不同，见各接口说明 |

## 1.7 入参字符串会被自动 Trim

请求进入业务逻辑之前，框架会**递归遍历整个入参对象树**（含嵌套对象、数组元素、字典值），把所有字符串属性的首尾空白去掉。因此：

- 传 `"  ABC  "` 等价于传 `"ABC"`；
- 传 `"   "`（全空白）等价于传 `""`（空字符串），**但不等于 `null`**；
- 长度校验是在 Trim **之后**执行的，首尾空格不占长度配额。

## 1.8 字段级权限会让 key 直接消失

字段级权限不是把值置为 `null`，而是在 JSON 序列化阶段**整个跳过该属性**——响应里根本不会出现这个 key。

前端读取时必须用「key 不存在」和「值为 null」都能兜住的写法（如可选链 + 默认值），不能假设 key 一定存在。测试断言「无权限时字段不可见」时，应断言 **key 不存在**，而不是断言值为 `null`。

被屏蔽的字段分两层，独立配置，可能出现「进口层能看船名、业务层看不到主提单号」这种组合：

| 层级             | 模块标识             | 作用范围                        |
| :--------------- | :------------------- | :------------------------------ |
| 海运进口自身字段 | `SeaImport = 4`      | 响应里海运进口这一层的字段      |
| 业务主表字段     | `TransportOrder = 2` | `transportOrder` 对象内部的字段 |

编辑接口有配套保护：入参中当前用户无权查看的字段，后端会用数据库原值回填，避免前端因看不到该字段而没传、导致保存时被覆盖成空。规则见逻辑文档 4.3。

## 1.10 分页与排序

列表接口（`GetPagedListAsync`）的分页排序参数：

| 参数 | 类型 | 默认值 | 取值范围 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| PageIndex | int | 1 | 1 ~ 2147483647 | 当前页码，从 1 开始。传 0 或负数返回 HTTP 400 |
| PageSize | int | 10 | 1 ~ 100000 | 每页条数。超出范围返回 HTTP 400 |
| Sorting | string | `CreationTime DESC` | - | 排序表达式，见下 |

**`Sorting` 表达式规则**

- 支持**逗号分隔的多字段**，按书写顺序依次作为第一、第二……排序键；
- 每个字段后可跟 `ASC` 或 `DESC`（不区分大小写），省略时按 `ASC`；
- 支持**多级导航属性路径**，用 `.` 逐级下钻访问关联表字段；
- 排序根对象是**海运进口这一层**，业务主表字段要写成 `TransportOrder.XXX`；
- 字段名用 C# 属性名（PascalCase），不是 camelCase。

可用示例：

```
CreationTime DESC
TransportOrder.ETD DESC, CreationTime DESC
Vessel ASC, InnerVoyno ASC
TransportOrder.Client.Name ASC, TransportOrder.CommissionNum DESC
TotalNetWeight DESC
TransportOrder.AccountDate DESC, TransportOrder.SettlementDate ASC
```

传入不存在的字段名会抛异常，表现为 HTTP 500 且 `error.message` 是解析异常原文。前端应固定使用列头绑定的白名单字段，不要把用户输入直接拼进去。

**分页返回结构**

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| Items | 数组 | 当前页数据；无数据时是 `[]`，不是 `null` |
| TotalCount | int | 满足条件的总记录数（**已叠加数据权限过滤**，不同账号查同样条件可能不同） |
| SkipCount | int | 已跳过的条数 = (PageIndex − 1) × PageSize |
| MaxResultCount | int | 本次最多返回条数 = PageSize |
| CurrentPage | int | 当前页码 = SkipCount ÷ MaxResultCount + 1 |
| TotalPages | int | 总页数 = ⌈TotalCount ÷ MaxResultCount⌉ |

## 1.11 筛选参数的匹配语义

| 匹配方式 | 实现 | 注意 |
| :-- | :-- | :-- |
| 模糊 | SQL `LIKE '%关键字%'` | 数据库排序规则默认**不区分大小写**；该字段为 `NULL` 的行**不会**被匹配到 |
| 精确 | `=` |  |
| 区间 | `>= 起` 且 `<= 止`，**闭区间** | 两端可以只传一端 |
| 空白入参 | 传 `null`、`""`、全空白字符串 | 一律视为**不筛选**（数值和日期传 `null` 同理） |
| 多个筛选条件 | 一律 `AND` | 没有任何 `OR` 组合，只有 `Keyword` 内部的多字段之间是 `OR` |

**「未填写」开关**：四个可空下拉字段和船名同时提供「指定值」与「未填写」两个参数，二者**同时传有效值时直接报错**。

| 指定值参数 | 未填写参数 | 冲突时的报错文案 |
| :-- | :-- | :-- |
| CarrierId | CarrierIdEmpty | 船公司筛选：未填写与指定id不可同时传入 |
| POLId | POLIdEmpty | 起运港筛选：未填写与指定id不可同时传入 |
| PODId | PODIdEmpty | 目的港筛选：未填写与指定id不可同时传入 |
| OriginCountryId | OriginCountryIdEmpty | 原产国筛选：未填写与指定id不可同时传入 |
| TerminalId | TerminalIdEmpty | 码头筛选：未填写与指定id不可同时传入 |
| Vessel | VesselEmpty | 船名筛选：未填写与指定船名不可同时传入 |

「未填写」传 `false` 等同于不传，**不会**筛出「已填写」的票。该校验在查询构建的最前面执行，优先于其它一切筛选逻辑。

## 1.12 日期参数的注意点

- 请求可以只传日期 `"2026-08-01"`，也可以带时分秒。
- 业务主表的 `ETD`、`ATD`、`ETA` 保存时**只保留日期部分**，回读永远是 `T00:00:00`。
- 海运进口层的换单、提货、报关、转站、箱使日期**原样保存**，传了时分秒会原样回读。
- 区间筛选是闭区间，因此筛选上述「原样保存」的日期时，「止」端建议传当天的 `23:59:59`，否则当天带时分秒的数据会被漏掉。

## 1.13 典型页面的调用顺序

| 场景 | 调用序列 |
| :-- | :-- |
| 打开列表页 | `GetPagedListAsync`（首屏）→ 需要统计卡片时并行 `GetGroupedListAsync` |
| 新建一票 | 表单提交 `AddAsync` → 拿到 Guid → 用该 Guid 调 `DetailAsync` 回显 |
| 打开编辑页 | `DetailAsync` 取全量 → 用户改 → `EditAsync`（**子表必须整体回传**） |
| 复制一票 | `CopyAsync` → 拿到新 Guid → `DetailAsync` 打开新票 |
| 单独管理附件 | `GetAttachmentsAsync` / `AddAttachmentsAsync` / `DeleteAttachmentsAsync`；也可以在 `AddAsync` / `EditAsync` 里用 `AttachmentGroup` 一起提交 |
| 删除一票 | 先确认该票没有费用 → `DeleteAsync` |

# 3. 公共数据结构

各接口反复用到的对象，集中定义一次，第 4 章直接引用。

> [!IMPORTANT] **关联表返回规则**：海运进口层（顶层）与集装箱层的关联表**一律以对象返回**，不平铺成 `XxxName`：起运港 `pol`、目的港 `pod`（航线 `lane`、国家 `country` 作为下一层挂在港口对象里）、原产国 `originCountry`、船公司 `carrier`、箱型 `ctnCode`、包装 `codePackage`、商品 `codeGoods`。例外：业务主表层 `transportOrder` 内的业务来源、运输条款、包装、商品子表、关联人员，为与海运出口保持同一套结构，仍是 `codeSourceName`、`codeServiceName`、`codePackageName`、`orderCodeGoodss[].codeGoodsName`、`orderUsers[].userNickName` 这类平铺字段；往来单位（委托单位、车队等）本来就是对象。以本章各表为准。

## 3.1 GuidIdDto（只带主键的入参）

用于详情、删除、重新生成委托编号、查询附件。

| 字段    | 类型   | 说明                                          |
| :------ | :----- | :-------------------------------------------- |
| Id      | Guid   | 海运进口主键（与业务主表 Id 相同）            |
| Ids     | Guid[] | **本模块不使用**，传了被忽略，不支持批量      |
| IsPrint | bool?  | 仅详情接口使用，`true` 时额外返回公司打印信息 |

# 4. 接口详解

每个接口按「地址与权限 → 输入参数 → 输出参数 → 报错文案 → 报文样例」的固定顺序描述。

参数表中「必填」列的含义：**是** = 不传或传空会报错；**否** = 可以不传；**忽略** = 结构上存在但后端不采信，传了也没用。

### 4.2.1 地址与权限

| :------- | :------------------------------------------- |
| 方法     | `PUT`                                        |
| 地址     | `/api/services/app/SeaImportAdmin/EditAsync` |
| 参数位置 | 请求体（JSON）                               |
| 权限点   | `Admin.SeaImport.Edit`                       |
| 返回     | `result` 为 `true`                           |

### 4.2.2 输入参数

与新增（4.1.2 / 4.1.3）**逐字段相同**，仅有两处增加：

| 参数 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| Id | Guid | **是** | 海运进口主键 |
| TransportOrder.Id | Guid | 否 | 业务主表主键，与顶层 `Id` 相同 |
| OrderCtns[].Id | long? | 否 | 传已有 id = 更新该行；不传 / `0` / `null` = 新增行 |
| TransportOrder.OrderCodeGoodss[].Id | long? | 否 | 同上 |
| TransportOrder.OrderUsers[].Id | long? | 否 | 同上 |

> [!IMPORTANT] **三张子表按全量比对处理：库里存在但本次入参中没有出现的行会被删除。** 前端必须提交完整的子表列表，不能只提交发生变化的行。

> [!IMPORTANT] **`ServiceTypes` 也要每次整份提交（2026-10-02 起）。** 后端拿它和库里本票的服务项比集合（不比顺序）：目的港或服务项**有变化**就删掉本票全部服务项与任务（含已完成的）按新的重建；**没变**只按新的关联人员同步待处理任务的处理人。漏传 `ServiceTypes` 等于把服务项清空，会把任务全删掉。本票已完成任务「完成后不允许修改」的字段，入参会被后端换回库里原值，不报错。

## 4.3 详情 DetailAsync

### 4.3.1 地址与权限

| 项       | 值                                             |
| :------- | :--------------------------------------------- |
| 方法     | `GET`                                          |
| 地址     | `/api/services/app/SeaImportAdmin/DetailAsync` |
| 参数位置 | QueryString                                    |
| 权限点   | `Admin.SeaImport.Get`                          |
| 返回     | `result` 为海运进口完整对象                    |

**本接口会做行级数据权限 + 表级权限过滤**（2026-08-19 起，此前不过滤、拿到 Id 就能查）。查不到时按三种情况分别报错：记录不存在 →「输入海运进口错误」；没有行级数据权限 →「没有这条数据的数据权限,不能查看」；被表级权限挡掉 →「没有这条数据的表级权限,不能查看」。

返回里新增 `isEditable`（是否可编辑），以及 `previousId` / `nextId`（上一票/下一票），见 4.3.3。

### 4.3.2 输入参数

入参 = **当前票 `Id`** + **与列表 `GetPagedListAsync` 完全相同的搜索条件与排序**（`SeaImportDetailQueryDto`）。从列表点进详情、以及详情里点上一票/下一票时，把当时列表的 Query 原样带上，只换当前票 `Id`。上一票/下一票按这份条件筛完、再按 `Sorting` 排完之后的全量顺序定位，**与当前在第几页无关**（`PageIndex` / `PageSize` 可带但不参与定位）。

| 参数 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| Id | Guid | **是** | 当前海运进口主键 |
| IsPrint | bool? | 否 | 传 `true` 时额外返回 `CompanyPrintInfo`，且不计算上一票/下一票；不传等同 `false` |
| Sorting | string | 否 | 与列表相同，默认 `CreationTime DESC`。决定上一票/下一票的前后方向 |
| 其余筛选字段 | 同列表 | 否 | 与 4.4 列表入参完全一致 |
| PageIndex / PageSize | int | 否 | 可随列表 Query 一起带上，**不影响**上一票/下一票 |

只传 `Id`、不传筛选时：上一票/下一票按「当前用户可见的全部海运进口 + 默认创建时间倒序」计算。

示例：`?Id=4e9a5b21-0c7d-4f88-9a15-2b3c6d8e0011&Keyword=COSCO&Sorting=CreationTime DESC`

# 6. 常见对接坑位

| # | 坑 | 正确做法 |
| :-- | :-- | :-- |
| 1 | 业务错误返回 HTTP **500** | 用 `success` 字段判成败，不要用状态码 |
| 2 | 两个 DELETE 接口参数在 **body** | `axios.delete(url, { data })` |
| 3 | 集装箱在**最外层** `orderCtns` | `transportOrder.orderCtns` 提交被忽略、返回恒为 `null` |
| 4 | 编辑是**全量比对** | 子表必须整体回传，漏传的行会被删 |
| 5 | 无权限字段 **key 直接消失** | 用可选链读取，断言时断言 key 不存在 |
| 6 | 「到港日期」字段名是 `etd` | 不要去找 `arrivalDate`，也不要用 `eta` |
| 7 | 净重、净重合计、转站日期、箱使日期**后端不重算** | 改了基准值必须前端重新计算并提交 |
| 8 | 会计期间、应结日期**后端强制覆盖** | 前端传了也没用，只做只读展示 |
| 9 | 删除附件传的是 `attachmentId` 不是关联记录 `id` | 传错不报错但删不掉 |
| 10 | 委托编号规则未配置时**复制和重新生成必定失败** | 上线前先配 `SeaImport.CommissionNum` |
| 11 | 「未填写」与「指定值」筛选**同时传会报错** | 二选一 |
| 12 | 模糊筛选**匹配不到 NULL 行** | 想查空值请用 `XxxEmpty` 开关 |
| 13 | 所属组织 `orgId` 类型可空但**实际必填** | 表单加必填校验 |
| 14 | 销售**必须恰好 1 个** | 0 个和 2 个都报同一句错 |
| 15 | 列表每行都带完整费用与子表 | `PageSize` 不要开太大 |
| 16 | `orderFees[].combinedFeeStatus` 恒为 `0` | 读票级的 `payFeeStatus` / `receiveFeeStatus` |
| 17 | 详情、编辑、删除、重新生成委托编号都做行级数据权限 | 2026-08-19 起生效，此前拿到 Id 就能查改。列表和详情新增 `isEditable`，前端据此禁用编辑/删除按钮 |
| 18 | 枚举是**数字**不是字符串 | `cargoId: 0` 而不是 `"普通货"` |
| 19 | 关联表**一律是对象，没有 `xxxName` 平铺字段** | 起运港名读 `pol.portName`，原产国读 `originCountry.countryName`，箱型读 `orderCtns[].ctnCode.ctnName`；找不到 `polName` 这类 key 是正常的 |
| 20 | 航线、国家**只挂在起运港对象下**，深两层 | 读 `pol.lane.laneName`、`pol.country.countryName`，且要逐层判空（`pol` 为 `null` 时整棵子树都取不到） |
| 21 | 码头**从自由文本改成了往来单位下拉** | 提交 `terminalId`（Guid），读取 `terminal.name`。老代码里那个字符串 `terminal` 字段**已经不存在了**，继续按字符串传会被忽略 |
| 22 | 码头是**唯一在最外层的往来单位对象** | 其余八个（委托单位、车队、报关行、仓库、保险、收发通）都在 `transportOrder` 下，别去 `transportOrder.terminal` 里找 |
| 23 | 贸易方式 `tradeMode` 的**枚举后端完全不认识** | 取值范围、中文文案、默认值全部由前端维护；后端不校验、不参与任何计算，也不会因为传了没定义的数字而报错 |
| 24 | 主提单号当前租户业务表内不可重复 | 和海运出口、空运出口撞号也会报「主提单号【{号码}】已存在」。空不校验；编辑排除自身 |
