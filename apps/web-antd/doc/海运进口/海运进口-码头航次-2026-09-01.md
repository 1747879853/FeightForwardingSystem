# 1. 背景意图 (Background)

海运进口原来只有一个航次字段 `InnerVoyno`，界面标签就叫「航次」，存的是**船公司给的航次**。

但港区（码头）自己另有一套航次编号，和船公司航次经常不一样。外部「码头船舶计划」接口认的是**港区航次**，之前一直拿船公司航次去查，本质上查不准——表现就是「明明有这条船，却查不到计划」。

因此新增一个 `TerminalVoyno`「码头航次」字段，与船公司航次并存，两者都由用户维护。改动与海运出口同步进行。

# 2. 核心逻辑变更

## 2.1 新增字段

| 项 | 值 |
| :-- | :-- |
| 实体 | `SeaImport.TerminalVoyno` |
| 类型 / 长度 | `string`，`[StringLength(32)]`（与 `InnerVoyno` 对齐，比海运出口短） |
| 界面标签 | 码头航次 |
| 是否必填 | 否 |

`InnerVoyno` 的注释同步改为「航次(船公司航次)」，值和长度都没动。

## 2.2 接入范围

| 场景 | 处理 |
| :-- | :-- |
| 新增 `AddAsync` | `SeaImportAddDto.TerminalVoyno`，走 `ObjectMapper.Map` 自动映射 |
| 编辑 `EditAsync` | `SeaImportEditDto.TerminalVoyno`，手写赋值 `seaImport.TerminalVoyno = input.TerminalVoyno` |
| 长度校验 | `ValidateSeaImportInputAsync` 新增一个 `terminalVoyno` 参数，超 32 报「码头航次长度不能超过32个字符」 |
| 列表 / 详情 | `SeaImportDto.TerminalVoyno`，走 `ObjectMapper.Map` 自动映射 |
| 简易输出 | `SeaImportSimpleDto.TerminalVoyno` |
| 列表查询 | `SeaImportQueryDto.TerminalVoyno`，模糊匹配 |
| 复制 `CopyAsync` | 自动带过去（走 `ObjectMapper.Map`，未列入「一票一号不复制」名单） |

海运进口**没有**批量修改字段枚举（那是海运出口独有的 `SeaExportPropEnum`），所以这块无需处理。

**关键字 `keyword` 的模糊范围没有加码头航次**，仍是船名、船公司航次、发票号、批次号、备注、主提单号、订舱编号、合同号、委托编号。想按码头航次搜，用 `terminalVoyno` 这个专用筛选条件。

## 2.3 码头船舶计划改用码头航次

`FeituoAdmin/QueryTerminalScheduleAsync`（按业务单查码头船舶计划）的航次取值改为：

1. 业务单的**码头航次**有值 → 直接用它。
2. 码头航次为空、**船公司航次**有值 → 先调外部「船司航次转码头航次」换算一次，用换算结果查。
3. 两者都为空 → 不带航次，按船名 + 起运港查全部挂靠计划。

返回结构里 `innerVoyno` / `terminalVoyno` 两个航次都会带上，另有 `terminalVoynoConverted` 标识本次的码头航次是否为换算所得。**换算结果不落库**，需要固化得由用户自己补录到单据上。

外部接口返回条目里的 `ivoyage` 也是**码头航次**，前端填表时要填到「码头航次」而不是「航次」。

# 3. 避坑指南 (Blockers)

> [!IMPORTANT] **1. 两个航次不能混用。** `innerVoyno` 是船公司航次，`terminalVoyno` 是港区航次。查码头船舶计划、以及外部返回的 `ivoyage` 都属于码头航次这一侧。界面上两个字段要分开摆、标签写清楚，不要共用一个输入框。

> [!IMPORTANT] **2. 迁移要自己生成。** `App_SeaImports` 新增 `TerminalVoyno` 列（`nvarchar(32)`，可空），需自行生成 EF Core 迁移。存量数据该列为 `NULL`，此时查码头船舶计划会走「拿船公司航次换算」的分支，不影响可用性。

> [!IMPORTANT] **3. 海运进口查码头船舶计划经常查不到，与本次改动无关。** 该接口按**起运港**查询，而海运进口的起运港多是国外港口，外部平台的码头船舶计划以国内港区为主。返回空是正常现象。加了码头航次只是让「能查到的那部分」查得准，不会让国外港变得可查。

> [!NOTE] **4. 长度比海运出口短。** 进口是 32 位、出口是 64 位，跟各自的 `InnerVoyno` 保持一致，没有统一。前端两个模块的输入框 `maxlength` 要分别设。
