# 1. 背景意图 (Background)

提成单模块要把多币种费用折算成本位币算利润。原先沿用的是应收汇率 `DRValue`，但这是个将就的方案：

汇率表原有五列（应收 `DRValue`、应付 `CRValue`、海关 `CustomValue`、核算 `CalculateValue`、发票 `InvoiceValue`）都是**按业务口径**分的，应收应付还各占一列。而提成算的是「利润 = 应收 − 应付」这个**跨收付**的口径，取应收那一列就等于让应付也按应收汇率折算，语义上说不通，财务口径上也解释不清。

所以给汇率表**单开一列「提成汇率」`CommissionValue`，应收应付共用它**。好处是提成折算率变成可以独立维护的业务参数，调整它不会牵动开票、结算、模板生成任何一条现有链路。

# 2. 核心逻辑变更 (Core Logic)

涉及文件：

- `src/CsprojBuilder.Core/Entites/ExchangeRate.cs`
- `src/CsprojBuilder.Application/App/ExchangeRate/Dto/ExchangeRateDto.cs`
- `src/CsprojBuilder.Application/App/ExchangeRate/ExchangeRateAdminAppService.cs`

## 2.1 实体变更

`ExchangeRate`（`App_ExchangeRates`）新增一列：

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `CommissionValue` | `decimal?` | 提成汇率。提成单折算专用，**收付共用这一个值**，不像应收应付那样分两列 |

与同表其余汇率列一致，不加 `[Column(TypeName)]`，精度在 DTO 侧用 `[DecimalPrecision(6)]` 约束。

## 2.2 DTO 变更

四个 DTO 全部放开该字段，前端在汇率维护页正常录入即可：

| DTO | 变更 |
| :-- | :-- |
| `ExchangeRateAddDto` | 新增 `CommissionValue`（`decimal?`，`[DecimalPrecision(6)]`） |
| `ExchangeRateEditDto` | 同上 |
| `ExchangeRateDto`（列表与详情输出） | 新增 `CommissionValue` |
| `ExchangeRateSimpleDto`（简易输出） | 新增 `CommissionValue` |

## 2.3 接口变更

`ExchangeRateAdminAppService`：

- 新增走 `ObjectMapper.Map`，DTO 加了字段即自动落库，无需改代码。
- **编辑**需显式赋值，已补 `exchangeRate.CommissionValue = input.CommissionValue;`。
- 列表 `GetPagedListAsync`、详情 `DetailAsync` 走 `ExchangeRateDto` 映射，加了字段即自动返回。

接口地址与入出参结构均未变，只是各多了一个字段。

## 2.4 谁在消费它

目前只有提成单模块：`CommissionOrderAdminAppService.BuildRateMapAsync` 按「币别 + 该票会计期间月1号」取本列。

```
筛选条件 = CurrencyId 匹配
         且 LocalCurrency = 'RMB'
         且 Enable = true
         且 CommissionValue 有值
         且 StartDate ≤ 会计期间月1号 ≤ EndDate（两端为空视为不限）
区间重叠命中多条时取 StartDate 最晚的一条
```

人民币（`Currency.Code == "RMB"`）不查表，折算率恒为 1。详见 `文档\提成单\提成单模块总逻辑文档.md` 第 5.3 节。

# 3. 避坑指南 (Pitfalls)

> [!IMPORTANT] **存量汇率记录的 `CommissionValue` 全是空的。** 新列上线后不会自动从 `DRValue` 复制，也没有默认值。
>
> **不补录就建不出销售提成单**——提成模块查不到该币别该月的提成汇率时会直接拦住新建，并在确认接口的「不能提交的原因」里返回 `币别【X】缺少yyyy-MM的提成汇率 请先在汇率表配置`。上线前须按币别、按月把历史区间补齐。

- **不要拿它当通用汇率用。** 这一列的语义就是「提成折算专用」，收付共用是刻意的。开票、结算、对账、模板自动生成费用各有各的取值列（`InvoiceValue` / `DRValue` / `CRValue`），别混。
- **提成模块不复用基类的 `ResolveExchangeRateAsync`。** 那个方法按 `PaySide` 分取 `DRValue`/`CRValue`、不筛 `Enable`、匹配不到返回 `0`；提成要求收付同率、只认启用记录、且匹配不到必须**报错**而不是按 0 算，所以另写了一套解析。改动本列的取值口径时，两处不会互相影响。
- **改了汇率不会重算已有提成单。** 提成单的金额是新建那一刻算死的快照，事后调整汇率只影响之后新建的单子。
