# 编号生成模块 (GenerateNumAdmin) 前端对接文档

## GenerateEnum 枚举值

| 值  | 名称      | 说明                                   |
| --- | --------- | -------------------------------------- |
| 0   | AutoNum   | 自动生成的数字                         |
| 1   | Text      | 固定字符串                             |
| 2   | UserName  | 用户名                                 |
| 3   | yyyyMMdd  | 四位年两位月两位日（系统当前日期）     |
| 4   | yyMMdd    | 两位年两位月两位日（系统当前日期）     |
| 5   | yyyyMM    | 四位年两位月（系统当前日期）           |
| 6   | yyMM      | 两位年两位月（系统当前日期）           |
| 7   | ETDyyyyMM | 业务日期四位年两位月(若为空取当前时间) |
| 8   | ETDyyMM   | 业务日期两位年两位月(若为空取当前时间) |

## 校验规则

| 校验规则                                  | 错误信息                     |
| ----------------------------------------- | ---------------------------- |
| `orgId` 有值 且 `generateNumUsers` 有数据 | "组织和适用用户不能同时设置" |
| `orgId` 指向不存在的组织                  | "组织不存在"                 |
| `generateNumUsers` 中包含不存在的用户id   | "适用用户中存在无效的用户"   |
| 同一 `tableName` + `orgId` 组合重复       | "规则已存在,不可重复设置"    |
| 子表规则为空                              | "子表规则不能为空"           |
| AutoNum 类型规则超过1条                   | "自增编号数量不可超过1"      |

**互斥逻辑：** 一条规则只能选以下三种之一：

- 指定组织（设 `orgId`，不传 `generateNumUsers`） 组织可以选择公司和部门
- 指定用户（传 `generateNumUsers`，不设 `orgId`）
- 不限制（`orgId` 为 null，`generateNumUsers` 为 null 或空）

## 1. 新增

**POST** `/api/services/app/GenerateNumAdmin/Add`

### Request Body

```json
{
  "name": "string",
  "tableName": "string",
  "orgId": null,
  "generateNumRules": [
    {
      "generateEnum": 0,
      "text": "string",
      "length": 4,
      "reset": true,
      "sortId": 0
    }
  ],
  "generateNumUsers": [{ "userId": 10 }]
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| name | string | 是 | 规则名称 |
| tableName | string | 是 | 表名或表名+字段名 |
| orgId | long? | 否 | 组织id，与 generateNumUsers 互斥 |
| generateNumRules | array | 是 | 至少1条，AutoNum最多1条 |
| generateNumRules[].generateEnum | int | 是 | 枚举值见上方 |
| generateNumRules[].text | string | 否 | generateEnum=1时使用 |
| generateNumRules[].length | int | 是 | 本规则生成长度 |
| generateNumRules[].reset | bool | 是 | 此条变化后是否重置序号 |
| generateNumRules[].sortId | int | 是 | 排序，小的在前 |
| generateNumUsers | array | 否 | 适用用户，与 orgId 互斥 |
| generateNumUsers[].userId | long | 是 | 用户id |

### Response

`long` — 新增记录 Id

## 2. 编辑

**PUT** `/api/services/app/GenerateNumAdmin/Edit`

### Request Body

```json
{
  "id": 1,
  "name": "string",
  "tableName": "string",
  "orgId": null,
  "generateNumRules": [
    {
      "id": 5,
      "generateNumId": 1,
      "generateEnum": 0,
      "text": "string",
      "length": 4,
      "reset": true,
      "sortId": 0
    }
  ],
  "generateNumUsers": [{ "id": 3, "generateNumId": 1, "userId": 10 }]
}
```

### 子表增删改逻辑（generateNumRules 和 generateNumUsers 相同）

- `id > 0` → 更新
- `id <= 0` → 新增
- 数据库中存在但未传入的 → 删除

### Response

`bool`

## 编号生成匹配优先级（后端逻辑，供前端理解）

1. **用户精确匹配** — 当前用户在 `GenerateNumUsers` 中
2. **组织从近到远匹配** — 按**业务单据自身的所属组织**（不是当前登录用户的组织）沿组织串向上找：先匹配本组织（如青岛分公司-业务部），再匹配上级（青岛分公司 → 山东分公司 → …），最先命中的生效
3. **无限制默认规则** — orgId 为空且无适用用户 这种代表全部

> 一个用户可能同时属于多个组织（如「青岛分公司-业务部」和「天津分公司-销售部」），所以组织匹配只认单据的 `orgId`。同一个人在天津建的单子不会套用青岛分公司配的规则；若单据所属组织及其上级都没配规则，则落到无限制默认规则，仍没有才报「未配置生成规则」。

## 业务日期规则说明

- `ETDyyyyMM` / `ETDyyMM` 优先取调用方传入的业务日期 `ETD`（开船日期）；若为空则取当前时间。
- 海运出口（`SeaExport.CommissionNum`）、海运进口（`SeaImport.CommissionNum`）在新增/复制/更新委托编号时会传入业务单的 `ETD`。

## reset 字段说明

当非 AutoNum 类型的规则设置 `reset=true` 时，该规则生成的文本发生变化会导致自增序号重置为0。例如日期规则 `reset=true` 则每天重置序号；`reset=false` 则日期变化后序号继续递增。业务日期规则同理：不同 `ETD` 年月且 `reset=true` 时序号按年月分段重置。
