# 附件类型（AttachmentDtlType）API 前端对接文档

> 本文档位于 `aspnet-core\文档\附件` 目录  
> 变更记录见同目录 `附件-2026-06-21.md`

---

## 一、概述

附件相关能力分为三部分：

| 能力 | 说明 |
| :-- | :-- |
| **附件类型管理（后台）** | `AttachmentDtlTypeAdminAppService`，增删改查 + 权限控制 |
| **附件类型查询（通用）** | `AttachmentDtlTypeAppService`，需登录，无需具体权限 |
| **业务附件字段扩展** | 各业务模块保存/返回附件时，新增 `attachmentDtlTypeId`、`clientVisible` 及类型信息 |

### 概念说明

- **ModuleTypeId**：附件所属**模块大类**（如海运出口、费用等），6 位字符串，由后端 `ModuleTypeIds` 定义。
- **AttachmentDtlType（附件详细类型）**：同一模块内的**业务类型**（如托书、提单、发票），与模块大类不同。
- **AttachmentDefaultModule（子表）**：配置某附件类型默认在哪些 `ModuleType`（`int`，前端定义）下展示上传入口。

## 三、附件类型管理（后台）

> 基础路径：`/api/services/app/AttachmentDtlTypeAdmin`  
> 所有接口需要登录，并按方法标注的权限校验

---

### 3.1 新增附件类型

```
POST /api/services/app/AttachmentDtlTypeAdmin/AddAsync
Content-Type: application/json
```

**权限**：`Admin.AttachmentDtlType.Add`

**请求体示例**

```json
{
  "name": "提单",
  "sortId": 1,
  "attachmentDefaultModules": [{ "moduleType": 1 }, { "moduleType": 2 }]
}
```

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| name | string | 是 | 类型名，例如托书、提单、发票等 |
| sortId | number | 否 | 排序字段，数值越小越靠前，默认 0 |
| attachmentDefaultModules | array | 否 | 默认展示模块子表 |
| attachmentDefaultModules[].moduleType | number | 是 | 模块类型（前端定义，例如 1=海运出口） |

**响应**

```json
{
  "result": 1,
  "success": true
}
```

> `result` 为新增的附件类型 Id。

---

### 3.2 编辑附件类型

```
PUT /api/services/app/AttachmentDtlTypeAdmin/EditAsync
Content-Type: application/json
```

**权限**：`Admin.AttachmentDtlType.Edit`

**请求体示例**

```json
{
  "id": 1,
  "name": "提单",
  "sortId": 2,
  "attachmentDefaultModules": [{ "moduleType": 1 }]
}
```

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| id | number | 是 | 附件类型 Id |
| name | string | 是 | 类型名 |
| sortId | number | 否 | 排序字段 |
| attachmentDefaultModules | array | 否 | 子表**全量替换**（先删后插） |
| attachmentDefaultModules[].moduleType | number | 是 | 模块类型 |

**响应**

```json
{
  "result": true,
  "success": true
}
```

---

### 3.3 删除附件类型

```
DELETE /api/services/app/AttachmentDtlTypeAdmin/DeleteAsync
Content-Type: application/json
```

**权限**：`Admin.AttachmentDtlType.Delete`

**请求体**

```json
{
  "id": 1
}
```

| 字段 | 类型   | 必填 | 说明        |
| :--- | :----- | :--- | :---------- |
| id   | number | 是   | 附件类型 Id |

**响应**

```json
{
  "result": true,
  "success": true
}
```

**删除限制**：若该类型已被任意 `AttachmentItem` 引用，禁止删除，返回提示：

> 该附件类型已被【附件】模块引用,禁止删除

## 四、附件类型查询（通用）

> 基础路径：`/api/services/app/AttachmentDtlType`  
> **需登录，无需具体权限**

---

### 4.1 获取全部附件类型列表（不带子表）

```
GET /api/services/app/AttachmentDtlType/GetListAsync
```

**请求参数**：无

**响应示例**

```json
{
  "result": [
    {
      "id": 1,
      "name": "提单",
      "sortId": 1
    },
    {
      "id": 2,
      "name": "托书",
      "sortId": 2
    }
  ],
  "success": true
}
```

| 字段   | 类型   | 说明        |
| :----- | :----- | :---------- |
| id     | number | 附件类型 Id |
| name   | string | 类型名      |
| sortId | number | 排序字段    |

> 按 `sortId` 升序返回，不含子表 `attachmentDefaultModules`。适用于下拉选择等场景。

---

### 4.2 按模块类型查询默认展示的附件类型

```
POST /api/services/app/AttachmentDtlType/GetListByModuleTypesAsync
Content-Type: application/json
```

**请求体示例**

```json
{
  "moduleTypes": [1, 2]
}
```

| 字段        | 类型     | 必填 | 说明                                     |
| :---------- | :------- | :--- | :--------------------------------------- |
| moduleTypes | number[] | 否   | 模块类型集合；不传则返回所有已配置的模块 |

**响应示例**

```json
{
  "result": [
    {
      "moduleType": 1,
      "attachmentDtlTypes": [
        { "id": 1, "name": "提单", "sortId": 1 },
        { "id": 2, "name": "托书", "sortId": 2 }
      ]
    },
    {
      "moduleType": 2,
      "attachmentDtlTypes": []
    }
  ],
  "success": true
}
```

| 字段                        | 类型   | 说明                           |
| :-------------------------- | :----- | :----------------------------- |
| moduleType                  | number | 模块类型                       |
| attachmentDtlTypes          | array  | 该模块下默认展示的附件类型集合 |
| attachmentDtlTypes[].id     | number | 附件类型 Id                    |
| attachmentDtlTypes[].name   | string | 类型名                         |
| attachmentDtlTypes[].sortId | number | 排序字段                       |

**行为说明**

- 传了 `moduleTypes`：对传入的**每个值都返回一项**，没有配置的类型返回空数组。
- 未传 `moduleTypes`：返回所有已在子表中配置过的模块。
- 每个模块下的 `attachmentDtlTypes` 按 `sortId` 升序排列。

**使用场景**：某模块（如海运出口 `moduleType=1`）新建时，前端根据返回结果默认渲染对应类型的附件上传入口。

## 五、业务附件字段扩展

各业务模块（合约、付费申请、海运出口等）在保存/返回附件时，统一使用 `AttachmentItemForItemInputDto`（入参）和 `AttachmentItemDto`（出参）。

### 5.1 附件入参（AttachmentItemForItemInputDto）

业务模块新增/编辑时，附件对象需携带以下字段：

```json
{
  "attachmentId": 12345,
  "attachmentDtlTypeId": 1,
  "clientVisible": true,
  "displayOrder": 0
}
```

| 字段                | 类型        | 必填 | 说明                          |
| :------------------ | :---------- | :--- | :---------------------------- |
| attachmentId        | number      | 是   | 附件 Id（先通过上传接口获取） |
| attachmentDtlTypeId | number/null | 否   | 附件详细类型 Id               |
| clientVisible       | boolean     | 否   | 客户是否可见                  |
| displayOrder        | number      | 否   | 显示顺序                      |
| itemId              | string      | 否   | 关联对象 Id（一般由后端赋值） |
| url                 | string      | 否   | 文件下载 Url                  |

### 5.2 附件出参（AttachmentItemDto）

业务模块列表/详情返回附件时，新增字段：

```json
{
  "id": 100,
  "attachmentId": 12345,
  "itemId": "guid-xxx",
  "moduleTypeId": "160010",
  "attachmentDtlTypeId": 1,
  "attachmentDtlType": {
    "id": 1,
    "name": "提单",
    "sortId": 1
  },
  "clientVisible": true,
  "isFirstShow": true,
  "displayOrder": 0,
  "url": "https://xxx.com/file.pdf",
  "mediaType": 2,
  "friendlyFileName": "提单.pdf",
  "fileLength": 102400,
  "creationTime": "2026-06-21T10:00:00",
  "creatorUserId": 1,
  "creatorUserName": "张三"
}
```

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| attachmentDtlTypeId | number/null | 附件详细类型 Id |
| attachmentDtlType | object/null | 附件详细类型信息（根据 attachmentDtlTypeId 计算） |
| attachmentDtlType.id | number | 类型 Id |
| attachmentDtlType.name | string | 类型名 |
| attachmentDtlType.sortId | number | 排序字段 |
| clientVisible | boolean | 客户是否可见 |

> 当 `attachmentDtlTypeId` 为空时，`attachmentDtlType` 为 `null`。

### 5.3 已支持的业务模块

以下模块保存附件时已透传 `attachmentDtlTypeId`、`clientVisible`：

- 合约（Agreement）
- 付费申请（PaymentApplication）
- 付费结算（PaymentSettlement）
- 对账单（Statement）
- 客户（Client）
- 业务问题（TransportOrderQuestion）
- 出库（OuterWarehouse）
- 入库（EnterWarehouse）
- 库存（Inventory）
- 公告（Announcement）
- 栏目/分类标题图（Category）
- 船公司 Logo（Carrier）
- 组织机构 Logo（OrganizationUnit）
- 站点 Logo（TenantSettings / HostSettings）
- 海运出口（SeaExport）
- 业务联系单（PreOrder）

### 5.4 批量修改附件关联客户是否可见

批量修改多条 `AttachmentItem`（附件与业务的关联关系）的 `clientVisible`。每条独立指定目标值。

```
POST /api/services/app/Attachment/UpdateAttachmentItemsClientVisibleAsync
```

**鉴权**：需登录（`[AbpAuthorize]`）。

**入参**：`UpdateAttachmentItemClientVisibleDto[]`

```json
[
  { "id": 1001, "clientVisible": true },
  { "id": 1002, "clientVisible": false }
]
```

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| id | long | 是 | 附件关联(AttachmentItem)Id（`<=0` 忽略；同一 id 多次传入取最后一条） |
| clientVisible | boolean | 否 | 目标客户是否可见 |

**出参**：无（`200 OK`）。空集合或全部 id 无效时直接返回，不报错。

## 七、前端对接建议

### 7.1 附件类型管理页

1. 列表调用 `GetPagedListAsync`，默认按 `sortId` 排序。
2. 新增/编辑时维护 `attachmentDefaultModules`，勾选该类型默认展示的模块。
3. 删除前无需前端判断引用，后端会自动校验。

### 7.2 业务模块新建页

1. 进入新建页时，根据当前模块的 `moduleType` 调用 `GetListByModuleTypesAsync`。
2. 对返回的每个 `attachmentDtlType`，默认渲染一个附件上传区域。
3. 用户上传后，保存时传入 `attachmentId`、`attachmentDtlTypeId`、`clientVisible`。

### 7.3 附件类型下拉

调用 `GetListAsync` 获取全部类型（不带子表），用于编辑已有附件时选择类型。

## 八、错误提示汇总

| 场景                       | 提示文案                                |
| :------------------------- | :-------------------------------------- |
| 新增/编辑时名称为空        | 附件类型名称不能为空                    |
| 编辑/删除/详情时 Id 不存在 | 附件类型不存在                          |
| 删除时被附件引用           | 该附件类型已被【附件】模块引用,禁止删除 |
