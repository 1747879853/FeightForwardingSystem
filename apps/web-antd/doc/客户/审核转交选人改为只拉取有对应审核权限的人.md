## 背景

审核转交选人现在调 `User/GetUserSimplePagedListAsync` 时没有传权限，拉的是全部已激活用户。这是不对的：没有对应审核权限的人转交时，后端会拒绝，提示「被转交人无xxx审核权限 无法转交」。

选人列表要在请求时带上**当前这条审核任务**对应的权限，只列出有这个权限的人。

## 改哪里

客户、费用、提单、提成单、付费申请、业务联系单的转交选人共用这一处。客户审核转交当前拉的是全员，改成传 `permissions=Admin.Client.Audit`。

其它模块如果也有转交选人，按下面的对照传对应权限，不要继续拉全员，也不要写死成客户权限。

不是转交的选人（下拉搜同事、单据关联用户等）不要加这个参数，否则会把人筛没。

## 接口

```
GET /api/services/app/User/GetUserSimplePagedListAsync
```

新增入参 `permissions`（字符串数组）。传多个时是**并且**：人必须同时拥有每一项。不传或空 = 不按权限筛。

传参必须重复 query，不要传 JSON 字符串。传成 `permissions=["Admin.Client.Audit"]` 会绑定失败，接口不报错，结果仍是全员。

```
GET /api/services/app/User/GetUserSimplePagedListAsync?permissions=Admin.Client.Audit&pageIndex=1&pageSize=10
```

多个权限：

```
permissions=Admin.OrderFee.Audit&permissions=Admin.Client.Audit
```

关键字、分页仍然一起传。

## 任务类型 → 权限名

| 当前审核任务 | permissions |
| :-- | :-- |
| 费用提交 / 费用修改 / 费用删除 | `Admin.OrderFee.Audit` |
| 付费申请 | `Admin.PaymentApplication.Audit` |
| 业务联系单 | `Admin.PreOrder.Audit` |
| 新建客户审核 / 申请修改客户 / 申请删除客户 | `Admin.Client.Audit` |
| 提成单 | `Admin.CommissionOrder.Audit` |
| 提单签出 | `Admin.BillOfLading.Audit` |

## 验收标准

- [ ] 客户审核转交选人只出现有「合作客户基本信息-审核」的人，没有该权限的人不在列表里
- [ ] 关键字、分页仍可用，和 `permissions` 一起传
- [ ] 其它不是转交的选人仍拉全部已激活用户
- [ ] 其它业务的转交选人如已上线，按上表传对应权限，不要统一写死成客户权限
