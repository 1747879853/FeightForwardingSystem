# 1. 背景意图 (Background)

**业务需求：** 客户附件此前仅提供整体覆盖式编辑（`EditAttachmentAsync`：先删后建全量覆盖），不便于按附件类型分组展示与增量维护。本次参照「海运出口」（`SeaExportAdminAppService`）的附件分组模式，为客户模块新增三个附件接口：

- 获取某个客户的附件**分组列表**（按 `AttachmentDtlTypeId` 分组）。
- 给某个客户**添加多个附件**（不分组输入）。
- **删除某个客户的多个附件关联**（不分组，仅删除当前客户下的关联，不删附件本体）。
- 获取某个客户关联的**所有账期（ClientBillingPeriod）的附件列表**（不分组，扁平）。

**涉及改动：**

- 新增两个输入 DTO。
- `ClientAdminAppService` 注入 `IRepository<AttachmentItem, long>`，新增三个公开接口及配套私有方法。

# 2. 核心逻辑变更 (Core Logic Changes)

## 2.1 DTO

文件：`src/CsprojBuilder.Application/App/Client/Dto/ClientDto.cs`

新增两个类（复用附件公共 DTO `AttachmentItemForItemInputDto`）：

- `ClientAttachmentsAddDto`：`Guid Id`（客户Id）+ `List<AttachmentItemForItemInputDto> Attachments`（不分组附件集合）。
- `ClientAttachmentsDeleteDto`：`Guid Id`（客户Id）+ `List<long> AttachmentIds`（附件本体 `Attachment.Id` 集合）。

分组输出复用附件公共 DTO `AttachmentGroupDto`（`App.Attachments.Dto`）。

## 2.2 客户接口 (ClientAdminAppService)

文件：`src/CsprojBuilder.Application/App/Client/ClientAdminAppService.cs`

- 构造函数新增注入 `IRepository<AttachmentItem, long> _attachmentItemRepository`（用于删除关联）。
- 新增「附件分组」区域，三个公开接口：
  - `GetAttachmentsAsync(GuidIdDto)`：校验客户存在后返回分组附件。
  - `AddAttachmentsAsync(ClientAttachmentsAddDto)`：校验客户存在后调用 `SaveAttachmentsAsync` 批量创建附件关联。
  - `DeleteAttachmentsAsync(ClientAttachmentsDeleteDto)`：校验客户存在、校验 `AttachmentIds` 非空后，仅删除「当前客户 + 客户模块 + 指定附件Id」的关联记录。
  - `GetBillingPeriodAttachmentsAsync(GuidIdDto)`：校验客户存在后，查出该客户所有账期(`ClientBillingPeriod`)Id，再按 `ModuleTypeIds.Bussiness.ClientBillingPeriod` + 账期Id集合查询附件关联，回填创建人昵称，返回扁平列表(按 `DisplayOrder` 排序)。
- 构造函数另新增注入 `IRepository<ClientBillingPeriod, long> _clientBillingPeriodRepository`（用于查账期Id）。
- 配套私有方法：
  - `SaveAttachmentsAsync`：过滤 `AttachmentId<=0`，统一以 `ModuleTypeIds.Bussiness.Client` 创建关联。
  - `GetAttachmentGroupsAsync`：查询关联并回填创建人 `CreatorUserName`（NickName），再按类型分组。
  - `EnsureClientExistsAsync`：`AnyAsync` 校验客户是否存在，不存在抛「输入合作客户id错误」。
  - `BuildAttachmentGroups`：按 `AttachmentDtlTypeId` 分组，组间按 `AttachmentDtlType.SortId` 再按类型Id排序，组内按 `DisplayOrder` 排序。

# 3. 接口参数说明 (API)

模块类型：`ModuleTypeIds.Bussiness.Client`；均需权限。

## 3.1 获取客户附件分组列表

**GET** `/api/services/app/ClientAdmin/GetAttachmentsAsync`（权限 `Admin_Client_Get`）

**输入：**

| 参数 | 类型 | 必填 | 说明   |
| ---- | ---- | ---- | ------ |
| id   | Guid | 是   | 客户Id |

**输出：** `List<AttachmentGroupDto>`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| attachmentDtlTypeId | long? | 附件详细类型Id（分组依据），无类型为 null |
| attachmentDtlType | AttachmentDtlTypeSimpleDto | 附件详细类型信息 |
| items | AttachmentItemDto[] | 该类型下的附件集合（含 `CreatorUserName` 创建人昵称），按 `displayOrder` 排序 |

## 3.2 客户添加多个附件（不分组）

**POST** `/api/services/app/ClientAdmin/AddAttachmentsAsync`（权限 `Admin_Client_Edit`）

**输入：** `ClientAttachmentsAddDto`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | Guid | 是 | 客户Id |
| attachments | AttachmentItemForItemInputDto[] | 是 | 不分组附件集合 |
| attachments[].attachmentId | long | 是 | 附件本体Id（`<=0` 会被忽略） |
| attachments[].attachmentDtlTypeId | long? | 否 | 附件详细类型Id |
| attachments[].clientVisible | bool | 否 | 客户是否可见 |
| attachments[].displayOrder | int | 否 | 显示顺序 |

**输出：** `bool`（成功返回 true）

## 3.3 客户删除多个附件关联（不分组）

**DELETE** `/api/services/app/ClientAdmin/DeleteAttachmentsAsync`（权限 `Admin_Client_Edit`）

**输入：** `ClientAttachmentsDeleteDto`

| 参数          | 类型   | 必填 | 说明                                    |
| ------------- | ------ | ---- | --------------------------------------- |
| id            | Guid   | 是   | 客户Id                                  |
| attachmentIds | long[] | 是   | 附件本体 `Attachment.Id` 集合，不能为空 |

**输出：** `bool`（成功返回 true）

## 3.4 获取客户所有账期的附件列表（不分组）

**GET** `/api/services/app/ClientAdmin/GetBillingPeriodAttachmentsAsync`（权限 `Admin_Client_Get`）

汇总该客户下所有 `ClientBillingPeriod`（账期）关联的附件，扁平返回（不分组、不区分属于哪条账期）。

**输入：**

| 参数 | 类型 | 必填 | 说明   |
| ---- | ---- | ---- | ------ |
| id   | Guid | 是   | 客户Id |

**输出：** `List<AttachmentItemDto>`（含 `CreatorUserName` 创建人昵称，按 `displayOrder` 排序；客户无账期时返回空数组）

# 4. 避坑指南 (Pitfalls)

- **只删关联不删附件本体**：`DeleteAttachmentsAsync` 删除的是 `AttachmentItem` 关联记录，且限定 `ItemId=客户Id` 且 `ModuleTypeId=Client`，不会影响其它模块引用同一附件。
- **账期附件模块类型不同**：`GetBillingPeriodAttachmentsAsync` 查询的是 `ModuleTypeId=ClientBillingPeriod`、`ItemId=账期Id`（非客户Id）的附件，与客户自身附件（`ModuleTypeId=Client`）互不影响；返回结果为多条账期附件的合并扁平列表。
- **删除入参不可为空**：`AttachmentIds` 为空时抛「附件Id集合不能为空」，避免误删全部。
- **添加为增量、编辑为覆盖**：`AddAttachmentsAsync` 为追加式；原 `EditAttachmentAsync` 仍是「先删后建」的全量覆盖，两者语义不同，前端按场景选用。
- **`AttachmentId<=0` 会被忽略**：新增时无效附件Id不会创建关联。
- **分组排序规则**：组间先按 `AttachmentDtlType.SortId`（空排最后）再按类型Id，组内按 `DisplayOrder`。
