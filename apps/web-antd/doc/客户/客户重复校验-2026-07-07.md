# 客户重复校验-2026-07-07

## 背景意图

- 现有 `ClientAdminAppService` 在新增和编辑时仅校验了合作客户全称(`FullName`)唯一性，未覆盖合作客户简称(`Name`)唯一性。
- 前端需要一个可复用的重复检查接口，用于输入 `id(可空)`、`FullName`、`Name` 后，判断除当前 `id` 外是否存在重复数据。

## 核心逻辑变更

- 在 `AddAsync` 中新增简称重复校验：当存在相同 `Name` 的客户时，抛出“合作客户简称不能重复”。
- 在 `EditAsync` 中新增简称重复校验：排除当前 `Id` 后，若存在相同 `Name` 的客户，抛出“合作客户简称不能重复”。
- 扩展 `ClientNameCheckDto`：新增 `Name` 字段，支持同时校验全称和简称。
- 新增接口 `CheckDuplicateAsync(ClientNameCheckDto input)`：
  - 入参支持 `Id` 为空；
  - 同时校验 `FullName` 与 `Name`；
  - 查询条件排除输入 `Id`；
  - 返回 `bool`：有重复为 `true`，无重复为 `false`。
- 保留并增强原有 `ClientNameChecksync`：增加 `Name` 非空与重复校验，保持原调用兼容。

## 避坑指南

- `CheckDuplicateAsync` 的返回语义为“是否有重复”，调用方不要反向理解。
- 当 `FullName` 和 `Name` 都为空时，接口返回 `false`（不判重），前端如需必填约束应在提交前校验。
- 新增和编辑接口仍保留服务端强校验，避免仅依赖前端预校验导致并发脏写。
