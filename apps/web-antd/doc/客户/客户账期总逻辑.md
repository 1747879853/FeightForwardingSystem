# 1. 业务背景说明 (Background)

**白话解释：**  
客户账期约定「这家客户按什么方式结款、适用哪些业务范围、授信多少」。一条账期挂在某个合作客户下，可限定部门、销售、业务来源与业务类型，并附带合同号、日期起算类型与授信信息。账期没有独立后台服务，跟客户一起增删改查。

# 2. 功能与操作说明 (Features & Operations)

- **新增账期：** 新增客户时在 `billingPeriods` 里一起提交；权限 `Admin.Client.Add`。
- **编辑账期：** 编辑客户时提交完整 `billingPeriods`。有 `id` 的改、没 `id` 的增、库里多出来的删；部门/销售/业务来源子表按差量增删，**不能全删再插**。每条账期附件仍是全量覆盖。权限 `Admin.Client.Edit`。
- **删除账期：** 编辑客户时不提交该条即删；删客户时清掉该客户全部账期、子表、附件。权限 `Admin.Client.Delete` / `Edit`。
- **同步账期：** 按这条账期规则回刷该客户**票结**历史业务的应结日期与结算方式；权限 `Admin.Client.Edit`。业务保存时落的是当时的账期快照，改完规则要让老单子跟上就点这个。
- **查询：** 客户列表、详情都返回 `billingPeriods`（含子表名称和附件）；权限 `Admin.Client.Get`。

# 5. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **[卡点 1：非永久必须有生效时间]** `permanent=false` 且未传 `effectiveTime` → 报错「非永久账期必须提供生效时间」。

> [!IMPORTANT] **[卡点 2：结算方式子字段]** 月结缺 months/settlementDay 或日期不在 1–31；约定天数缺 days 或 days 小于 1；票结的 addDays 填了但小于 0 → 对应友好异常。票结不填 addDays 合法，应结日期不加天。

> [!IMPORTANT] **[卡点 3：授信币别外键]** `creditCurrencyId` 有值但币别不存在 → 「授信币别不存在」。

> [!IMPORTANT] **[卡点 4：编辑附件全量覆盖]** 某条账期不传或传空 `attachments` 会清空该账期全部附件关联。

> [!IMPORTANT] **[卡点 5：编辑必须整包提交账期]** 客户编辑不传或传空 `billingPeriods` 会删掉该客户下全部账期。要保留的账期必须带着 `id` 交回来。

> [!IMPORTANT] **[卡点 6：编辑按 id 增量，不能全删再插]** 有 id 的改原行，没 id 的插入新行，库里多出来的才删。部门/销售/业务来源子表同样按差量，不会先清空再重建。

# 7. 应结日期怎么命中账期

海运出口 / 海运进口 / 空运出口保存时走 `GetSettlementDateAsync`，先筛「当前生效」的账期再按业务类型/销售/组织/业务来源匹配。

**当前生效**判定（按当前时间 `now`）：

| 情况             | 是否生效                  |
| :--------------- | :------------------------ |
| `permanent=true` | 是，不再看两个时间        |
| 生效时间为空     | 起始不限制                |
| 失效时间为空     | 截止不限制                |
| 生效时间有值     | 须 `effectiveTime <= now` |
| 失效时间有值     | 须 `now <= expiringTime`  |

两端都空（且不是长期有效）同样算生效。旧逻辑把失效时间写成了再生效时间，填了失效时间的规则实际上筛不掉，已改。

命中规则后按结算方式算应结日期：

| 结算方式 | 应结日期 |
| :-- | :-- |
| 没匹配到规则（默认票结） | 基准时间当天，不加天 |
| 票结 | 基准时间当天；填了 `addDays` 则 `time.AddDays(addDays)`，不填不加 |
| 月结 | 往后推 N 个月后取结算日 |
| 约定天数 | `time.AddDays(days)`，未填按 1 |

基准时间 `time` 取业务的开船日期 `ETD`，没填则取当前时间（与账期的 `dateType=开船日期` 一致）。

# 8. 同步账期怎么回刷

改账期规则**不会**自动回刷历史业务：业务表上的应结日期与结算方式是保存当时的账期快照。要让老单子跟上，用同步账期接口。

三层筛选，任一层不过就跳过：

| 层 | 条件 | 不过的结果 |
| :-- | :-- | :-- |
| 账期本身 | 按第 7 节的口径当前生效 | 直接返回 0，一条业务都不动 |
| 业务范围 | 该账期客户下结算方式为**票结**的业务 | 月结/约定天数的业务不动 |
| 账期限定 | 业务类型、销售、组织机构、业务来源四个维度全部命中（账期子表为空表示该维度不限定） | 跳过该票 |

命中后按第 7 节重算，与业务新增/编辑走的是同一个算法，口径不会分叉。算出来与库里一致的跳过，不一致的才写回。返回值是实际改动的票数。

几个容易问到的点：

- **只挑票结**：票结既是「配了票结规则」也是「没匹配上任何规则」的兜底值，所以只有它才可能是「本该月结、当时没规则」的漏网单；其余结算方式属于当时确实匹配到了规则，不再翻动。
- **重算后仍可能是票结**：例如账期规则本身就是票结、只是多了 `addDays`，此时结算方式不变、应结日期变。
- **未生效的账期同步无效**：返回 0，不是失败。
- **没有开船日期的业务**：基准时间取当前时间，因此这类业务每次同步都可能算出新的应结日期。
