# 背景意图

同一合作客户下不允许出现重复的开票抬头（`Header`）或纳税人识别号（`TaxNum`），避免开票信息混淆与重复维护。

# 核心逻辑变更

- `AddAsync` / `EditAsync`：保存前校验同一 `clientId` 下 `header`、`taxNum` 唯一；编辑排除自身 `id`。
- `BatchEditAsync`：先校验本次入参列表内部抬头/税号不自相重复，再走逐条新增/编辑（仍会走库内唯一校验）。
- 入参 `header`、`taxNum` 会先 `Trim`。
- `taxNum` 为空或空白时**不参与**税号唯一校验（允许多条无税号记录）。
- 提示文案：
  - `同一客户下抬头不能重复`
  - `同一客户下纳税人识别号不能重复`

# 避坑指南

- 唯一范围是**单个客户内**，不同客户允许相同抬头/税号。
- 批量保存时，即使库内暂无冲突，入参列表自身重复也会直接报错。
- 软删除记录不参与判重（走 ABP 默认 `IsDeleted` 过滤）。
- `BatchEditAsync` 删除后会先 `SaveChanges`，避免删后同抬头/税号重建被旧行挡住。
