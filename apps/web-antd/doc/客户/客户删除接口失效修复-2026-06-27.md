# 1. 背景意图 (Background)

**问题现象：** 在客户管理列表中，选择一条客户（如简称为“测试”）后点击删除，前端提示“删除成功”，但刷新列表后被删除的数据仍然存在。

**根因定位：** 前后端删除接口的入参字段不一致，导致后端实际未删除任何数据，却仍返回 `true`（删除成功）。

- 前端 `deleteClient` 调用 `DELETE /services/app/ClientAdmin/DeleteAsync`，请求体为数组形式：`{ "ids": ["<guid>", ...] }`（列表为多选工具栏删除）。
- 后端 `ClientAdminAppService.DeleteAsync([FromBody] GuidIdDto input)` 仅读取单数字段 `input.Id`，从未读取 `input.Ids`。
- 因此 `input.Id` 恒为 `Guid.Empty`，ABP 的 `_clientRepository.DeleteAsync(Guid.Empty)` 找不到实体便**静默跳过**（不抛异常），方法仍 `return true`。
- 前端收到“成功”后刷新列表（`gridApi.query()`），但数据库未发生软删除，记录依旧显示。

> 注：`Client` 继承 `FullAuditedEntity<Guid>`，删除为软删除（`IsDeleted=true`）；列表查询走 ABP 全局软删除过滤器，逻辑本身正确。问题完全出在删除接口的入参解析。

# 2. 核心逻辑变更 (Core Logic Changes)

文件：`src/CsprojBuilder.Application/App/Client/ClientAdminAppService.cs` → `DeleteAsync`

- 同时兼容**单个删除**（`input.Id`）与**批量删除**（`input.Ids`）两种入参，合并去重并过滤掉空 Guid。
- 当未传入任何有效 Id 时，抛出友好提示“请选择需要删除的合作客户”，避免再次出现“假成功”。
- 引用校验改为按 Id 集合批量判断（保留原有“入库单关联 / 贸易商合同关联 不可删除”规则）。
- 循环执行软删除。

关键代码：

```csharp
var ids = new List<Guid>();
if (input.Ids != null) ids.AddRange(input.Ids);
if (input.Id != Guid.Empty) ids.Add(input.Id);
ids = ids.Where(x => x != Guid.Empty).Distinct().ToList();
if (!ids.Any()) throw new UserFriendlyException("请选择需要删除的合作客户");

if (_enterWarehouseRepository.GetAll().Any(x => x.SupplierId.HasValue && ids.Contains(x.SupplierId.Value)))
    throw new UserFriendlyException("合作客户已被入库单关联 不可删除");
if (_agreementRepository.GetAll().Any(x => x.AgreementType == 2 && ids.Contains(x.SettlementId)))
    throw new UserFriendlyException("合作客户已被贸易商合同关联 不可删除");

foreach (var id in ids)
{
    await _clientRepository.DeleteAsync(id);
}
return true;
```

# 3. 避坑指南 (Pitfalls)

- **入参字段类型差异：** `EnterWarehouse.SupplierId` 为 `Guid?`（可空），引用校验需 `HasValue` 后再 `Contains`；`Agreement.SettlementId` 为 `Guid`（非空），直接 `Contains`。
- **删除“假成功”陷阱：** ABP `DeleteAsync(id)` 在找不到实体时不抛异常、静默返回。任何删除接口都不应在未校验入参的情况下直接 `return true`，否则会出现“提示成功但数据仍在”。
- **前后端契约对齐：** 列表删除是多选场景，前端传 `ids` 数组；新增/编辑等单条场景部分接口传 `id`。后端建议统一兼容 `Id` + `Ids`，避免再次出现字段错位。
- 无需生成 migration（仅逻辑变更，未改实体结构）。
