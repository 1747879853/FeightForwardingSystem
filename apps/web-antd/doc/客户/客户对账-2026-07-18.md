# 1. 背景意图 (Background)

本次对客户对账（`StatementAdminAppService`）做了两类改动，前端需按本文档同步：

1. **列表新增两个汇总列并支持筛选**：`PaySide`（收付类型）与 `InvoiceStatus`（开票状态）。这两列不是对账单自身字段，而是根据该对账单下**所有关联费用**汇总计算得出，且列表支持用这两个字段搜索。
2. **增删改查支持"我司银行"（`OrgBankAccountId`）**：新增/编辑做外键校验（非必填，传值才校验），列表/详情额外返回关联的 `OrgBankAccountSimpleDto`（我司银行简易对象）。

> 参照对象为开票申请（`InvoiceApplication`）的 `OrgBankAccountId`，区别在于：开票申请的 `OrgBankAccountId` 为**必填**（`Guid`），客户对账的为**非必填**（`Guid?`）。

# 3. 字段变更明细 (Field Changes)

## 3.1 收付类型 `PaySide`（列表新增，int）

- **类型**：`int`（注意：不是枚举，直接返回整数）
- **取值规则**（按对账单下所有费用的收付类型汇总）：

| 值  | 含义     | 判定条件         |
| :-- | :------- | :--------------- |
| `0` | 全部为收 | 所有费用均为"收" |
| `1` | 全部为付 | 所有费用均为"付" |
| `2` | 收付都有 | 既有"收"又有"付" |

## 3.2 开票状态 `InvoiceStatus`（列表新增，枚举）

- **类型**：枚举 `InvoiceStatus`
- **取值规则**（按对账单下所有费用的开票状态汇总）：

| 值  | 枚举名            | 含义     | 判定条件                       |
| :-- | :---------------- | :------- | :----------------------------- |
| `0` | `NotIssued`       | 未开票   | 所有费用均为未开票             |
| `1` | `PartiallyIssued` | 部分开票 | 既非全部未开票、也非全部已开票 |
| `2` | `Issued`          | 已开票   | 所有费用均为已开票             |

## 3.3 我司银行 `OrgBankAccountId` / `OrgBankAccount`

- **输入（新增/编辑）**：`OrgBankAccountId`，类型 `Guid?`，**非必填**；传值时后端校验是否存在，不存在返回「我司银行不存在」。
- **输出（列表/详情）**：同时返回 `OrgBankAccountId`（`Guid?`）与关联对象 `OrgBankAccount`（`OrgBankAccountSimpleDto`，无值时为 `null`）。

`OrgBankAccountSimpleDto` 字段：

| 字段                 | 类型     | 说明                                     |

| `Id`                 | `Guid`   | 我司银行主键ID                           |
| `OrganizationUnitId` | `long`   | 组织（公司）id                           |
| `CurrencyId`         | `long`   | 账户币种id                               |
| `CurrencyCode`       | `string` | 币种代码（当前由实体直接映射，可能为空） |
| `AccountName`        | `string` | 账户名称                                 |
| `BankShortName`      | `string` | 开户银行简称                             |
| `BankName`           | `string` | 开户银行全称                             |
| `BankAccount`        | `string` | 银行账号                                 |
| `SwiftCode`          | `string` | SwiftCode                                |

# 5. 避坑指南 (Pitfalls)

- **`PaySide` 是 int 不是枚举**：返回值直接是 `0/1/2`，其中 `2` 代表"收付都有"，前端需自行映射展示文案，不要按收付枚举（收=0/付=1）解析 `2`。
- **汇总字段仅列表有**：`PaySide`、`InvoiceStatus` 仅在 `GetPagedListAsync` 计算；`DetailAsync` 返回默认值，勿在详情页使用。
- **筛选会过滤空费用单**：用 `PaySide`/`InvoiceStatus` 搜索时，没有任何关联费用的对账单不会被命中（正常流程中移除完费用会自动删单，属极端情况）。
- **我司银行非必填**：新增/编辑均可不传 `OrgBankAccountId`；仅在传值时校验，与开票申请（必填）不同。
- **编辑为手动赋值**：`EditAsync` 采用逐字段赋值，`OrgBankAccountId` 已显式赋值（支持置空）。
- **`OrgBankAccount.CurrencyCode` 可能为空**：当前 `OrgBankAccountSimpleDto` 由实体直接映射（实体仅有 `CurrencyId`），`CurrencyCode` 未额外回填，与发票开出的返回方式一致；若前端需要币种代码，可用 `CurrencyId` 自行匹配或后续联系后端补充。
- **无需 migration**：实体字段（`Statement.OrgBankAccountId`）已由后端新增，本次仅接口层改动。
