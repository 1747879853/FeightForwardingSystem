# 委托单位排除服务项目 修改记录 2026-06-09

**修改时间：** 2026-06-09

**修改人：** 后端

**关联需求：** `ClientExceptService.POLId` 支持可空（支持针对默认港口配置的排除）

---

## 一、需求背景

由于 `SeServiceConfig.POLId` 已改为可空（为空代表默认港口配置），`ClientExceptService` 表需要同步支持可空 `POLId`，以便客户可以针对默认港口配置设置排除服务项。

---

## 二、修改文件清单

| 文件 | 路径 | 修改类型 |
| --- | --- | --- |
| 实体 | `Core/Entites/Client.cs` → `ClientExceptService` | `POLId` 类型 `long` → `long?` |
| 输出DTO | `Application/App/ClientExceptService/Dto/ClientExceptServiceDto.cs` → `ClientExceptServiceConfigDto` | `POLId` 已为 `long?`（上轮已改） |
| 编辑DTO | `Application/App/ClientExceptService/Dto/ClientExceptServiceDto.cs` → `ClientExceptServicePOLEditDto` | `POLId` 类型 `long` → `long?` |

| 对接文档 | `文档/客户/委托单位排除服务项目对接.md` | 全面更新 |

## 三、详细修改内容

### 3.1 实体修改（Client.cs → ClientExceptService）

```csharp
// 变更前
public long POLId { get; set; }

// 变更后
public long? POLId { get; set; }
```

**说明：** 为空时代表针对默认港口配置（`SeServiceConfig.POLId == null`）的排除。

### 3.2 DTO修改（ClientExceptServiceDto.cs）

#### ClientExceptServicePOLEditDto

```csharp
// 变更前
public long POLId { get; set; }

// 变更后
public long? POLId { get; set; }
```

**说明：** 编辑时 `polId` 传 `null` 代表针对默认港口配置设置排除。

### 3.3 GetClientExceptServicesAsync 方法修改

#### 变更前

- 过滤掉默认配置（`Where(x => x.POLId != null)`），只返回有具体港口的配置
- `IsChecked` 比较使用 `config.POLId.Value`

#### 变更后

- 返回所有配置，包含默认港口配置（`POLId`为`null`）
- `IsChecked` 比较使用 `config.POLId`（`long?` 对 `long?` 比较），正确处理 `null == null` 的匹配

```csharp
// 变更前
var configs = await _seServiceConfigRepository.GetAll()
    ...
    .Where(x => x.POLId != null)
    .ToListAsync();
IsChecked = !clientExceptServices.Any(ces =>
    ces.POLId == config.POLId.Value && ...)

// 变更后
var configs = await _seServiceConfigRepository.GetAll()
    ...
    .ToListAsync();
IsChecked = !clientExceptServices.Any(ces =>
    ces.POLId == config.POLId && ...)
```

### 3.4 EditClientExceptServicesAsync 方法修改

#### 变更前

- 对所有 `polId` 校验港口存在性

#### 变更后

- `polId` 有值时校验港口存在
- `polId` 为空时校验默认港口配置存在（`SeServiceConfig` 中存在 `POLId == null` 的记录）

```csharp
// 变更前
foreach (var pol in input.POLs)
{
    var portExists = await _portCodeRepository.GetAll().AnyAsync(x => x.Id == pol.POLId);
    if (!portExists) throw new UserFriendlyException($"起运港Id {pol.POLId} 不存在");
}

// 变更后
foreach (var pol in input.POLs)
{
    if (pol.POLId.HasValue)
    {
        var portExists = await _portCodeRepository.GetAll().AnyAsync(x => x.Id == pol.POLId.Value);
        if (!portExists) throw new UserFriendlyException($"起运港Id {pol.POLId.Value} 不存在");
    }
    else
    {
        var defaultConfigExists = await _seServiceConfigRepository.GetAll().AnyAsync(x => x.POLId == null);
        if (!defaultConfigExists) throw new UserFriendlyException("默认港口配置不存在，无法设置默认港口排除服务项");
    }
}
```

## 四、API 变更对前端的影响

### 获取接口（GetClientExceptServicesAsync）

| 项               | 变更前                 | 变更后                        |
| ---------------- | ---------------------- | ----------------------------- |
| 返回数据         | 仅包含有具体港口的配置 | 包含所有配置，含默认港口配置  |
| `polId` 字段类型 | `long`                 | `long?`（默认配置时为`null`） |
| `pol` 字段       | 始终有值               | 默认配置时为`null`            |

### 编辑接口（EditClientExceptServicesAsync）

| 项                 | 变更前         | 变更后                     |
| ------------------ | -------------- | -------------------------- |
| `polId` 字段类型   | `long`（必填） | `long?`（可为`null`）      |
| `polId` 为空的含义 | 不支持         | 代表针对默认港口配置的排除 |
| `polId` 为空时校验 | 不适用         | 校验默认港口配置是否存在   |

### 新增错误信息

| 错误信息 | 触发场景 |
| --- | --- |
| 默认港口配置不存在，无法设置默认港口排除服务项 | 编辑时`polId`为`null`但`SeServiceConfig`中无默认配置 |

## 五、数据库变更

`App_ClientExceptServices` 表的 `POLId` 列需要从 `NOT NULL` 改为 `NULL`。需要新增 EF Core Migration。

## 六、验收标准

| 序号 | 验收项 | 期望结果 |
| --- | --- | --- |
| 1 | 获取排除服务项配置 | 返回所有港口配置（含默认港口，`polId`为`null`） |
| 2 | 默认港口配置的IsChecked | 根据 `ClientExceptService` 中 `POLId == null` 的记录正确计算 |
| 3 | 编辑：排除默认港口的服务项 | `polId`传`null`，成功插入 `POLId` 为空的排除记录 |
| 4 | 编辑：默认港口配置不存在时 | 报错 "默认港口配置不存在，无法设置默认港口排除服务项" |
| 5 | 编辑：具体港口不存在 | 报错 "起运港Id {polId} 不存在" |
| 6 | 清空所有排除 | `poLs` 传空数组，清空所有排除记录（含默认港口的排除） |
