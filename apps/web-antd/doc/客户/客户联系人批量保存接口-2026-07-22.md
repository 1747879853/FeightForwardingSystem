# 1. 背景意图 (Background)

**业务需求：** 客户联系人此前只能逐条 `Add` / `Edit`。前端在「客户详情-联系人」表格里往往一次维护多行（新增几行、改几行），需要一次性提交整份联系人列表。本次为 `ClientContactAdminAppService` 新增**批量保存**接口 `BatchSaveAsync`：

- 列表项 `Id` 大于 0 且在库中存在 → **编辑**。
- 列表项 `Id` 为空/0，或库中不存在该 Id → **新增**。
- **不处理删除**（未出现在入参里的既有联系人保持不变）。

**涉及改动：**

- 新增两个输入 DTO。
- `ClientContactAdminAppService` 新增 `BatchSaveAsync`，接口 `IClientContactAdminAppService` 同步声明。

# 3. 核心逻辑变更 (Core Logic Changes)

## 3.1 DTO

`ClientContactBatchSaveDto`

- `Guid ClientId`：合作客户id。
- `List<ClientContactBatchItemDto> Contacts`：联系人列表。

`ClientContactBatchItemDto`（明细项，字段与单条新增/编辑一致）

- `long Id`：为空/0/库中不存在时视为新增；大于 0 且存在时视为编辑。
- `Name`（名字）、`Mobile`（手机）、`Email`（邮箱）、`Tel`（办公电话）、`Landline`（座机）、`Position`（职位）、`WeChat`（微信号）、`IsDefault`（是否默认）、`Remark`（备注）、`QQ`、`InvoiceEnable`（发票可用）、`StatementEnable`（对账可用）、`IsDisabled`（是否禁用）。

## 3.2 服务逻辑（BatchSaveAsync）

1. 校验 `ClientId` 客户存在，不存在抛「输入合作客户id错误」。
2. `Contacts` 为空直接返回空集合。
3. 逐项校验 `Name` 非空（「合作客户联系人名称不能为空」）。
4. 取出入参中 `Id>0` 的 Id 集合，一次性查出**本客户下**这些联系人（EF 跟踪）。
5. 遍历入参：
   - 命中既有联系人 → **编辑**：仅赋值改动字段，依赖工作单元(UoW)自动保存，**不调用 `UpdateAsync`**，生成的 UPDATE 只含改动列（局部更新）。
   - 未命中（`Id<=0` 或库中不存在）→ **新增**：`Id` 归零、`ClientId` 归属当前客户后插入。
6. 按输入顺序返回每项保存后的联系人 Id。

> 说明：编辑仅针对「ClientId 属于当前客户」的联系人，避免跨客户误改；不在入参内的既有联系人不做删除。

# 4. 接口参数说明 (API)

## 4.1 批量保存联系人

**POST** `/api/services/app/ClientContactAdmin/BatchSaveAsync`

**输入：** `ClientContactBatchSaveDto`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| clientId | Guid | 是 | 合作客户id |
| contacts | ClientContactBatchItemDto[] | 是 | 联系人列表 |
| contacts[].id | long | 否 | 联系人id；为空/0/库中不存在=新增，大于0且存在=编辑 |
| contacts[].name | string | 是 | 名字 |
| contacts[].mobile | string | 否 | 手机 |
| contacts[].email | string | 否 | 邮箱 |
| contacts[].tel | string | 否 | 办公电话 |
| contacts[].landline | string | 否 | 座机 |
| contacts[].position | string | 否 | 职位 |
| contacts[].weChat | string | 否 | 微信号 |
| contacts[].isDefault | bool | 否 | 是否默认 |
| contacts[].remark | string | 否 | 备注 |
| contacts[].qq | string | 否 | QQ |
| contacts[].invoiceEnable | bool | 否 | 发票可用 |
| contacts[].statementEnable | bool | 否 | 对账可用 |
| contacts[].isDisabled | bool | 否 | 是否禁用 |

**输出：** `List<long>` — 按输入顺序返回保存后的联系人 Id（新增项为新生成的 Id，编辑项为原 Id）。

**请求示例：**

```json
{
  "clientId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "contacts": [
    {
      "id": 12,
      "name": "张三",
      "mobile": "13800138000",
      "isDefault": true,
      "invoiceEnable": true
    },
    { "id": 0, "name": "李四", "mobile": "13900139000", "isDisabled": false }
  ]
}
```

**响应示例：**

```json
[12, 35]
```

（`id=12` 为编辑，`id=0` 新增后返回新 Id `35`）

# 5. 避坑指南 (Pitfalls)

- **不处理删除**：未出现在 `contacts` 里的既有联系人不会被删除，如需删除请另调 `DeleteAsync`。
- **Id 不存在即新增**：传了 `Id>0` 但库中查不到（或不属于该客户），也按新增处理，不会报错。
- **跨客户隔离**：编辑仅匹配 `ClientId=入参客户` 下的联系人，防止改到别的客户数据。
- **局部更新**：编辑走 EF 跟踪 + UoW 自动保存，仅更新改动列，不做全列覆盖。
- **名称必填**：任一项 `name` 为空整批失败（同单条新增/编辑校验）。
- **默认联系人**：本接口不强制唯一默认，`isDefault` 按传入原样保存（与既有单条接口一致）。
