# 客户通用 API 文档

> **服务名**：`ClientAppService`
>
> **接口基础路径**：`/api/services/app/Client/`
>
> **说明**：本文档面向前端对接，覆盖 `ClientAppService` 下所有通用客户接口。与后台管理接口（`ClientAdmin`）不同，本服务主要供业务页面在**已登录**场景下使用，权限要求较低，返回精简的 `ClientSimpleDto`。

# 第一部分：前端接口文档

## 通用说明

| 项目 | 说明 |
| :-- | :-- |
| 认证方式 | 需在请求头携带有效 Token |
| 响应包装 | ABP 标准格式：`{ "result": ..., "success": true, "error": null }`，以下示例仅展示 `result` 部分 |

### 分页入参（所有分页接口通用）

| CurrentPage | `currentPage` | `int` | 当前页码，对应本次请求的 `pageIndex` |
| TotalPages  | `totalPages`  | `int` | 总页数                               |

## 1. 获取合作客户简易分页列表

**Summary：** 获取合作客户简易分页列表，返回 `ClientSimpleDto`，仅需登录，无需 `Admin.Client.Get` 后台权限。筛选条件与 `ClientAdmin/GetPagedListAsync` 完全一致，适用于下拉选择委托单位、结算对象、订舱代理等外键关联场景。

**GET** `/api/services/app/Client/GetPagedListAsync`

**权限**：`[AbpAuthorize]`（登录即可）

### 入参 Query Parameters（`ClientQueryDto`）

| 字段 | JSON Key | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| Keyword | `keyword` | `string` | 否 | 关键字，模糊匹配客户简称、代码、全称、英文名、备注 |
| IndustryCategory | `industryCategory` | `string` | 否 | 行业类别；传 `p` 时额外启用干系人数据权限过滤 |
| CodeSourceId | `codeSourceId` | `long?` | 否 | 业务来源 id，为空不筛选 |
| ClientCoopStatus | `clientCoopStatus` | `CoopStatus[]` | 否 | 客户合作状态多选，为空不筛选 |
| SupplierCoopStatus | `supplierCoopStatus` | `CoopStatus[]` | 否 | 供应商合作状态多选，为空不筛选 |
| PageIndex | `pageIndex` | `int` | 否 | 当前页码，从 `1` 开始，默认 `1` |
| PageSize | `pageSize` | `int` | 否 | 每页条数，默认 `10`，范围 `1~1000` |
| Sorting | `sorting` | `string` | 否 | 排序字段，默认 `CreationTime DESC` |

> 分页入参**仅** `pageIndex`、`pageSize`，详见上文「分页入参（所有分页接口通用）」。

**CoopStatus 枚举：** `0=潜在, 1=正式, 2=暂停合作, 3=黑名单`

### 请求示例

```
GET /api/services/app/Client/GetPagedListAsync?keyword=上海&industryCategory=p&clientCoopStatus=1&clientCoopStatus=2&pageIndex=1&pageSize=10&sorting=CreationTime%20DESC
```

### 出参 `PagedList<ClientSimpleDto>`

```json
{
  "totalCount": 2,
  "currentPage": 1,
  "totalPages": 1,
  "items": [
    {
      "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "name": "上海XX",
      "code": "SH001",
      "fullName": "上海XX物流有限公司",
      "enName": "Shanghai XX Logistics Co., Ltd."
    }
  ]
}
```

### 出参分页字段说明（`PagedList<ClientSimpleDto>`）

| 字段 | JSON Key | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| TotalCount | `totalCount` | `int` | 总记录数 |
| CurrentPage | `currentPage` | `int` | 当前页码，对应入参 `pageIndex` |
| TotalPages | `totalPages` | `int` | 总页数 |
| Items | `items` | `ClientSimpleDto[]` | 当前页数据 |

### 出参列表项字段说明（`ClientSimpleDto`）

| 字段     | JSON Key   | 类型     | 说明        |
| :------- | :--------- | :------- | :---------- |
| Id       | `id`       | `Guid`   | 客户主键 id |
| Name     | `name`     | `string` | 客户简称    |
| Code     | `code`     | `string` | 客户代码    |
| FullName | `fullName` | `string` | 客户全称    |
| EnName   | `enName`   | `string` | 客户英文名  |

> **注意**：`ClientSimpleDto` 为外键关联用简易输出，**不返回** `creatorUserName`、`lastModifierUserName`、`creationTime`、币别、业务来源、对账人、附件等管理字段。

### 业务规则

1. 仅需登录，不校验 `Admin.Client.Get` 等后台权限。
2. 筛选条件与 `ClientAdmin/GetPagedListAsync` 完全一致：
   - `keyword` 为空时不按关键字过滤；有值时匹配 `Name`、`Code`、`FullName`、`EnName`、`Remark`。
   - `industryCategory` 非空时按行业类别包含关系过滤。
   - `codeSourceId` 有值时精确匹配业务来源。
   - `clientCoopStatus`、`supplierCoopStatus` 非空时分别按多选 `Contains` 过滤；两个维度之间为「与」关系，各自内部为「或」关系。
3. 当 `industryCategory == "p"` 时，启用干系人数据权限过滤：当前用户（及其数据权限可见用户）须命中 `ClientStakeholder` 中任意干系人，否则该客户不可见。
4. 列表查询使用 `ProjectTo<ClientSimpleDto>` 投影，SQL 仅查询简易字段，不加载客户表全部字段及关联子表。
5. 相比 `ClientAdmin/GetPagedListAsync`，本接口**不返回** `ClientDto` 完整字段（币别、业务来源、对账人、附件、创建人等）。

## 1. 业务背景说明 (Background)

**白话解释：**

`ClientAppService` 是面向业务系统的**通用客户服务**，与后台管理的 `ClientAdminAppService` 分工不同：

- **ClientAdmin**：面向系统管理员，负责合作客户的增删改查、附件、对账人、干系人等完整管理，需要 `Admin.Client.*` 权限。
- **Client（本服务）**：面向已登录的业务用户，提供合作客户简易分页查询，适合业务单据中选择委托单位、结算对象、订舱代理等外键场景。

典型使用场景包括：业务联系单选择委托单位、费用录入选择结算对象、各类表单下拉搜索客户等。业务页面若用户没有客户管理查看权限，仍可通过本接口完成客户选择。

## 2. 功能与操作说明 (Features & Operations)

| 功能 | 接口 | 说明 |
| :-- | :-- | :-- |
| 合作客户简易分页列表 | `GetPagedListAsync` | 登录即可调用，返回 `ClientSimpleDto`，筛选条件与 Admin 列表一致 |

### 与 ClientAdmin 分页接口的对比

| 对比项 | `Client/GetPagedListAsync` | `ClientAdmin/GetPagedListAsync` |
| :-- | :-- | :-- |
| 权限 | 仅需登录 | 需要 `Admin.Client.Get` |
| 返回类型 | `ClientSimpleDto` | `ClientDto` |
| 筛选条件 | 与 Admin 相同 | 完整列表筛选 |
| 数据权限 | `industryCategory=p` 时启用干系人过滤 | 同上 |
| 关联子表 | 不加载 | 加载币别、业务来源、对账人、创建人等 |
| 适用场景 | 业务页面选人/选客户 | 后台客户管理列表 |

## 5. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **卡点 1：权限差异**
>
> 业务页面若只需选择/展示客户，应调用 `Client/GetPagedListAsync`，**不要**调用 `ClientAdmin/GetPagedListAsync`，否则普通业务用户会因缺少 `Admin.Client.Get` 权限而 403。

> [!IMPORTANT] **卡点 2：行业类别与数据权限**
>
> 当 `industryCategory` 传 `p` 时，列表会按干系人数据权限过滤，仅返回当前用户可见的客户。其他行业类别不做此过滤。

> [!IMPORTANT] **卡点 3：分页参数**
>
> 分页请求**仅**传 `pageIndex` 和 `pageSize`，**禁止**传 `skipCount`、`maxResultCount`。响应中使用 `currentPage`、`totalPages`、`totalCount` 驱动分页控件。

> [!IMPORTANT] **卡点 4：返回字段精简**
>
> 本接口仅返回 `ClientSimpleDto` 五个字段，不包含创建人、修改人、币别、对账人等。若页面需要完整客户信息，应调用 `ClientAdmin/DetailAsync`（需 `Admin.Client.Get` 权限）。
