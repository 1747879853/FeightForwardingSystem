# 1. 背景意图 (Background)

**业务需求：** 每个合作客户（`Client`）可以配置多个「对账人」，对账人从系统用户（`User`）表中选取。对账人用于在收费对账场景下确定数据可见范围：当某个结算对象（客户）的对账人包含当前登录人时，该登录人查询该客户的未对账费用时应能看到「全部费用」，而不再受数据权限（`DataPermissionFilterAsync`）限制。

**涉及改动：**

- 客户增删改查接口需要携带对账人列表，返回时带出对账人的 `NickName`。
- 收费对账的 `GetOrderFeeGroupAsync` 按登录人是否为对账人决定是否放行全部费用。

# 2. 核心逻辑变更 (Core Logic Changes)

## 2.1 实体与数据结构

文件：`src/CsprojBuilder.Core/Entites/Client.cs`

- 新增子表实体 `ClientReconciler`（表名 `App_ClientReconcilers`，继承 `FullAuditedEntity<long>, IMustHaveTenant`）。
  - `ClientId`(Guid)：所属客户。
  - `UserId`(long)：对账人用户 Id，外键关联 `User`。
- `Client` 新增导航属性 `List<ClientReconciler> ClientReconcilers`。
- `CsprojBuilderDbContext` 注册 `DbSet<ClientReconciler> ClientReconcilers`。

> 注：按要求未生成 migration，由维护人自行生成。

## 2.2 客户接口 (ClientAdminAppService)

文件：`src/CsprojBuilder.Application/App/Client/ClientAdminAppService.cs`

- **新增 `AddAsync`**：读取入参 `ReconcilerUserIds`（`List<long>`），去重校验、校验用户存在后，随主表一起插入 `ClientReconcilers`。
- **编辑 `EditAsync`**：采用「按原数据匹配」增量维护，**不删了重建**。
  - 删除：库中已存在但输入中不含的对账人。
  - 新增：输入中存在但库中原本没有的对账人。
  - 已存在且仍在输入中的对账人保持不动。
- **详情 `DetailAsync`**：返回 `Reconcilers` 列表，每项带 `UserId` 与 `UserNickName`（取自用户缓存 `GetUserInfoMapAsync`）。
- **列表 `GetPagedListAsync`**：批量查询当前页客户的对账人并按 `ClientId` 分组返回，同样带出 `UserNickName`。

DTO（`src/CsprojBuilder.Application/App/Client/Dto/ClientDto.cs`）：

- `ClientAddDto` / `ClientEditDto` 新增输入 `List<long> ReconcilerUserIds`。
- `ClientDto` 新增输出 `List<ClientReconcilerDto> Reconcilers`。
- 新增 `ClientReconcilerDto`：`Id`、`UserId`、`UserNickName`。

## 2.3 收费对账接口 (StatementAdminAppService)

文件：`src/CsprojBuilder.Application/App/Statement/StatementAdminAppService.cs` → `GetOrderFeeGroupAsync`

- 注入 `IRepository<ClientReconciler, long>`。
- 在应用数据权限前判断：当前登录人是否为 `input.SettlementId` 对应客户的对账人。
  - 是对账人：**跳过** `DataPermissionFilterAsync`，返回全部费用。
  - 非对账人：照常执行 `DataPermissionFilterAsync` 做数据权限过滤。

关键代码：

```csharp
var isReconciler = AbpSession.UserId.HasValue
    && await _clientReconcilerRepository.GetAll()
        .AnyAsync(x => x.ClientId == input.SettlementId && x.UserId == AbpSession.UserId.Value);
if (!isReconciler)
{
    query = await DataPermissionFilterAsync(query);
}
query = await TablePermissionsAsync(query, FrightModule.TransportOrder);
```

# 3. 避坑指南 (Pitfalls)

- **编辑增量匹配**：对账人编辑基于 `UserId` 做差集匹配（删除/新增），避免全删重建导致的审计字段与主键跳变。
- **对账人查询以 `input.SettlementId` 为准**：`SettlementId` 为 `Guid`，即结算对象的客户 Id，与 `ClientReconciler.ClientId` 对应。
- **`TablePermissionsAsync` 依旧执行**：对账人只放行「数据权限」，表级权限过滤不受影响。
- **返回 NickName**：所有关联 `User` 的展示统一返回 `NickName`，不返回 `Name`。
- **无 migration**：实体结构有变更（新增表），需自行生成并执行 migration 后接口方可正常读写。
