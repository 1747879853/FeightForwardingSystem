# 一、背景意图

票结原先应结日期永远等于基准当天。现在票结也可以像约定天数那样 `time.AddDays`，但天数可选：不填就不加。

完整口径见《客户账期总逻辑》第 4.1 节、第 7 节。接口字段见《客户账期接口文档》。

# 二、核心逻辑变更

新增字段 `addDays`（`int?`）：

| 接口                                           | 是否带这个字段 |
| :--------------------------------------------- | :------------: |
| AddAsync / EditAsync                           |     ✓ 可选     |
| DetailAsync / GetListAsync / GetPagedListAsync |       ✓        |

命中**票结**规则时：`SettlementDate = time.AddDays(addDays ?? 0).Date`。没匹配到任何账期、走默认票结时，仍然是基准当天，不会去加某条规则上的天数。

`addDays` 与约定天数的 `days` 不是同一个字段。约定天数不填按 1；票结不填按 0。

# 三、避坑指南

> [!IMPORTANT] **不要把 `addDays` 和 `days` 填反。** 票结看 `addDays`，约定天数看 `days`。票结填了 `days` 不算数。

> 填了负数会报「票结加的天数不能小于0」。不填、填 0 都合法。
