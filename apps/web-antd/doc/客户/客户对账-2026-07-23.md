# 1. 背景意图 (Background)

客户对账列表与详情需要展示「结算状态」汇总列。结算状态不落在对账单表上，而是按该对账单下**全部关联费用**的 `OrderFee.SettlementStatus` 聚合计算，规则与现有开票状态汇总一致。

# 2. 核心逻辑变更 (Core Changes)

## 2.1 汇总规则

| 汇总结果 | 枚举值                  | 判定条件                               |
| :------- | :---------------------- | :------------------------------------- |
| 未结算   | `UnSettled` = 0         | 所有费用均为未结算                     |
| 结算完毕 | `Settlemented` = 2      | 所有费用均为结算完毕                   |
| 部分结算 | `PartialSettlement` = 1 | 其余情况（含混合、或存在单条部分结算） |

## 2.2 代码改动点

| 位置                | 改动                                                 |
| :------------------ | :--------------------------------------------------- |
| `StatementDto`      | 新增输出字段 `SettlementStatus`                      |
| `StatementQueryDto` | 新增筛选字段 `SettlementStatus?`                     |
| `GetPagedListAsync` | DB 层按汇总规则筛选；分页后按费用集合聚合写入返回值  |
| `DetailAsync`       | 有关联费用时按同样规则写入 `result.SettlementStatus` |

**无需 migration**：对账单实体不加字段，仅接口层汇总。

# 4. 避坑指南 (Pitfalls)

- **与费用行状态区分**：详情里每条费用仍有自身 `OrderFeeDto.SettlementStatus`；对账单头上的 `SettlementStatus` 是整单汇总。
- **与 `SettlementId` 区分**：`SettlementId`/`SettlementName` 是结算对象（客户），不是结算状态。
- **空费用单**：无关联费用时不改写，返回枚举默认值 `UnSettled(0)`；用该字段筛选时也不会命中无费用对账单。
- **筛选在 DB 层**：与 `InvoiceStatus` 相同，基于 `Statement.OrderFees` 导航做 `Any`/`All` 子查询。
