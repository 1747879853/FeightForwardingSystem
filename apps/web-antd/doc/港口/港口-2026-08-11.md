# 背景意图

TAPD #0655：港口管理列表需支持按港口查询、航线、EDI、国家筛选，并展示「创建人」列。前端已对接查询参数与 `creatorUserName` 展示，后端 `PortCodeAdmin/GetPagedListAsync` 对齐。

# 核心逻辑变更

1. `PortCodeQueryDto` 新增：
   - `LaneId`（`long?`）：精确匹配航线
   - `EdiCode`（`string`）：模糊匹配 EDI 代码
   - `CountryId`（`long?`）：精确匹配国家
2. `Keyword` 语义收窄为「港口查询」：仅模糊匹配 `PortName`、`CnName`（不再匹配 `Explain`/`EdiCode`）。
3. `GetPagedListAsync`：`AsNoTracking` + `Include(Country/Lane)`；上述条件与 `Status` 均可组合；填充 `CreatorUserName` / `LastModifierUserName`（`GetUserInfoMapAsync().GetNickName`）。
4. `DetailAsync`：同样 `AsNoTracking`，并返回创建人/修改人昵称。
5. `PortCodeDto` 新增 `CreatorUserName`、`LastModifierUserName`。

# 避坑指南

- **搜 EDI 请用 `EdiCode`，不要指望 `Keyword`。** 本次把 Keyword 从「广义关键字」改成只搜港口中英文名，旧前端若仍用 Keyword 搜 EDI 会查不到。
- **无创建人时昵称为 null。** `CreatorUserId` 为空或用户缓存未命中时，`creatorUserName` 为 null/空，前端列需兼容。
- **国家/航线仍是嵌套对象。** 列表出参不要再依赖已废弃的平铺字段 `countryName`/`laneName`。
