# 1. 业务背景说明 (Background)

**白话解释：**  
港口是订舱/运价等业务的主数据（英文名、中文名、所属国家、航线等）。  
`PortCodeAppService` 面向前端下拉/选港场景：登录即可拉取**全量**港口列表（不分页，港口列与国家英文名走缓存），也可走**分页检索**（同一份港口缓存，国家/航线从缓存贴对象，不带用户名）。

与 `PortCodeAdminAppService` 区别：Admin 负责增删改查（带权限、返回国家/航线对象和用户昵称）；本服务只读、无权限点。

# 2. 功能与操作说明 (Features & Operations)

- **全量港口列表：** 调用 `GET PortCode/GetListAsync`，返回精简字段 `i`/`p`/`c`/`e`/`s`（对应 id/portName/cnName/countryEnName/sortId）。港口列与国家英文名都走缓存，禁用港也返回。排序固定为 `SortId` 降序，同值再按英文名、`Id` 升序。
- **业务端分页检索：** 调用 `GET PortCode/GetPagedListAsync`。筛选与管理端列表相同（`Keyword`/`LaneId`/`EdiCode`/`CountryId`/`Status`），港口列走内存缓存，本页的国家/航线从缓存按 id 贴对象，不带用户昵称。
- **管理端维护：** 仍走 `PortCodeAdmin`（见 `港口api.md`）。新增、编辑、列表、详情都带 `sortId`（降序，值大的排前面）。
- **管理端分页检索：** `PortCodeAdmin/GetPagedListAsync` 支持港口查询（`Keyword` 模糊匹配英文名/中文名/EDI）、航线（`LaneId`）、EDI（`EdiCode`）、国家（`CountryId`）、状态（`Status`），可组合；列表/详情返回创建人、修改人昵称和国家/航线对象。港口主查询仍打库，国家/航线从缓存贴对象。未传 `sorting` 时按 `SortId` 降序 + `Id` 降序。`CountryCodeAdmin` / `LaneCodeAdmin` 的列表和详情不走这份缓存，继续查库。
- **管理端删除：** `DELETE PortCodeAdmin/DeleteAsync`，入参 `{ id }`，一次删一条。港口不存在报 `输入港口信息错误`；被业务数据引用时拒绝删除，报 `该港口信息已被【xx、yy】模块引用,禁止删除`，校验范围见卡点 9。校验通过后软删除。

## 4.1 港口简易对象（外键关联用）

其它模块的单据/费用/报价等接口，凡是返回港口外键的，一律返回下表结构的对象，**不平铺**成 `polName`/`podEdiCode`/`countryName`/`laneName` 之类的字段。

涉及两个类名：`PortCodeSimpleDto` 与 `PortCodeSimpleDtoForOrder`，**字段完全一致**，前端按同一套逻辑取值即可。后端由 `PortCodeSimpleDtoMapper` 统一投影，所有接口口径一致。

| 字段       | 类型             | 说明                         |
| :--------- | :--------------- | :--------------------------- |
| `id`       | `long`           | 港口主键                     |
| `portName` | `string`         | 港口代码 / 英文名            |
| `cnName`   | `string`         | 港口中文名                   |
| `ediCode`  | `string`         | 港口 EDI 代码                |
| `lane`     | `object \| null` | 航线对象（挂在港口上），见下 |
| `country`  | `object \| null` | 国家对象（挂在港口上），见下 |

`lane`（`LaneCodeSimpleDto`）：

| 字段         | 类型     | 说明          |
| :----------- | :------- | :------------ |
| `id`         | `long`   | 航线主键      |
| `code`       | `string` | 航线代码      |
| `laneName`   | `string` | 航线中文名    |
| `laneEnName` | `string` | 航线英文名    |
| `ediCode`    | `string` | 航线 EDI 代码 |

`country`（`CountryCodeSimpleDto`）：

| 字段            | 类型     | 说明         |
| :-------------- | :------- | :----------- |
| `id`            | `long`   | 国家主键     |
| `code`          | `string` | 国家唯一代码 |
| `countryName`   | `string` | 国家中文名   |
| `countryEnName` | `string` | 国家英文名   |

**取值示例**

```json
{
  "id": 123,
  "portName": "SHANGHAI",
  "cnName": "上海",
  "ediCode": "CNSHA",
  "lane": {
    "id": 5,
    "code": "FE",
    "laneName": "远东航线",
    "laneEnName": "FAR EAST",
    "ediCode": "FE"
  },
  "country": {
    "id": 9,
    "code": "CN",
    "countryName": "中国",
    "countryEnName": "CHINA"
  }
}
```

**业务口径**：界面上的航线/国家取自哪个港口按业务模块定 —— 海运出口取**目的港**（`pod.lane` / `pod.country`），海运进口取**起运港**（`pol.lane` / `pol.country`）。

# 5. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **[卡点 1：国家英文名为空]** 港口 `CountryId` 无效或国家未维护 `CountryEnName` 时，字段 `e` 可能为 `null`/空串。

> [!IMPORTANT] **[卡点 2：含禁用港口]** 本接口按「全部」返回，**不按** `Status` 过滤；若下拉只要启用港，需前端自行过滤或另提需求。

> [!IMPORTANT] **[卡点 3：港口英文名称 + 国家唯一]** 管理端 `PortCodeAdmin/AddAsync`、`PortCodeAdmin/EditAsync` 校验 `PortName` + `CountryId` 组合唯一（大小写不敏感、`PortName` 去首尾空格、编辑排除自身、软删除数据不参与）。重复时报 `港口英文名称和国家已存在`。同名港口允许分属不同国家；数据库未建唯一索引，存量重复数据不会自动清理，编辑历史重复行时会被直接拦住，需先人工合并或删除。

> [!IMPORTANT] **[卡点 4：Keyword 不再搜 EDI/说明]** 管理端列表 `Keyword` 仅匹配港口英文名、中文名；搜 EDI 请传独立参数 `EdiCode`。

> [!IMPORTANT] **[卡点 5：港口简易对象的 lane / country 可能为 null]** 港口未维护航线或国家、或关联的航线/国家已被软删除时，`lane` / `country` 为 `null`。前端务必判空取值（如 `pod?.lane?.laneName`），不要直接点下去。

> [!IMPORTANT] **[卡点 6：存量港口 SortId 为 0]** 新列迁移后历史数据全是 `0`。管理端默认按 `SortId` 降序时，这些行会挤在一起，再按 `Id` 降序；业务端全量列表同值时按英文名。要排出先后必须在编辑里补数字。`PortCodeSimpleDto` 不带 `sortId`，单据上的港口对象不受影响。

> [!IMPORTANT] **[卡点 7：港口查询贴国家/航线走缓存，国家/航线 Admin 查库]** 港口业务端分页、管理端列表/详情按 `CountryId`/`LaneId` 从 `BasicDataCache` 拷贝 `CountryCodeSimpleDto` / `LaneCodeSimpleDto` 贴对象，不把缓存里的实例直接返回。未维护或已被软删除时 `country` / `lane` 为 `null`。`CountryCodeAdmin` / `LaneCodeAdmin` 的列表和详情不走这份缓存，继续查库。管理端改国家/航线仍会清缓存，避免港口列表拿到旧对象。

> [!IMPORTANT] **[卡点 8：业务端分页走 PortCodePagedDto 列缓存]** 只缓存分页 DTO 的港口表列（不含 `CreationTime`、租户、审计字段，也不含国家/航线对象）。首次或失效后把当前租户未软删港口一次性载入 ABP 内存缓存。`GetPagedListAsync` 的 `Keyword` 等筛选在内存里 `Contains`（忽略大小写，对齐 SQL Server CI）。`GetListAsync` 读同一份港口缓存，国家英文名按 `CountryId` 从国家缓存取，返回字段与排序键不变，禁用港也返回。管理端增删改走仓储事件清缓存；另有 60 分钟绝对过期兜底。未传 `sorting` 或仍是基类默认 `CreationTime DESC` 时按 `SortId` 降序 + `Id` 降序。`PortCodeAdmin` 的港口主查询仍打库，不走港口整表缓存。

> [!IMPORTANT] **[卡点 9：被业务数据引用的港口禁止删除（含件杂货与件杂货分单）]** `PortCodeAdmin/DeleteAsync` 删除前按下表逐个模块检查，全部查完后把命中的模块名按表中顺序用顿号拼进报错，例如 `该港口信息已被【海运出口、件杂货】模块引用,禁止删除`。任一字段等于待删港口 id 即算引用。

| 报错里的模块名 | 检查的实体 | 检查的港口字段 |
| :-- | :-- | :-- |
| 海运出口 | `SeaExport` | 起运港 `POLId`、目的港 `PODId`、签单地点 `SigningPortId`、收货地 `ReceivePortId`、交货地 `DeliverPortId` |
| 海运进口 | `SeaImport` | 起运港 `POLId`、目的港 `PODId` |
| 海运出口分单 | `SeaExportSeparate` | 签单地点 `SigningPortId` |
| 件杂货 | `BreakBulk` | 起运港 `POLId`、目的港 `PODId`、中转港1 `POT1Id`、中转港2 `POT2Id`、收货地 `ReceivePortId`、交货地 `DeliverPortId`、签单地点 `SigningPortId`、付费地点 `PrepareAtId` |
| 件杂货分单 | `BreakBulkSeparate` | 签单地点 `SigningPortId`、付费地点 `PrepareAtId` |
| 海运出口运价 | `SeFreiPrice` | 起运港 `POLId`、目的港 `PODId` |
| 报价单 | `QuotationItem`（报价明细） | 起运港 `POLId`、目的港 `PODId` |
| 合作客户 | `ClientExceptService`（委托单位排除海运出口服务项目）/ `ClientSiExceptService`（委托单位排除海运进口服务项目，2026-10-02） | 起运港 `POLId` / 目的港 `PODId` |
| 业务港口服务项目配置 | `SeServiceConfig`（海运出口港口服务项配置）/ `SiServiceConfig`（海运进口港口服务项配置，2026-10-02） | 起运港 `POLId` / 目的港 `PODId` |

> **测试注意**：只校验上表列出的字段。海运出口的中转港1/2 与付费地点、海运出口分单的付费地点、运价与报价明细的中转港，以及业务联系单上的港口都不在校验范围内，只被这些字段引用的港口可以删掉。
