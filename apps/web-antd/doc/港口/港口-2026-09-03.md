# 背景意图

港口管理列表需要按业务指定的顺序展示，不能只按英文名或主键排。`App_PortCodes` 新增 `SortId`，口径对齐空运港口：值越大越靠前，增删改查一并带上。

# 核心逻辑变更

1. 实体 `PortCode` 新增 `int SortId`（降序，大的在前）。未传时默认 `0`。存量数据迁移后也是 `0`。
2. 新增 / 编辑入参、列表 / 详情出参均增加 `sortId`。新增走 `ObjectMapper.Map` 自动映上；编辑在跟踪实体上局部赋值 `portCode.SortId = input.SortId`，不调 `UpdateAsync`。
3. 管理端分页 `GetPagedListAsync`：未传 `sorting` 时固定 `SortId` 降序 + `Id` 降序；传了 `sorting` 仍走 `ApplySorting`，前端可覆盖。
4. 业务端全量列表 `GetListAsync`：改为 `SortId` 降序，同值再按 `PortName`、`Id` 升序；精简 JSON 新增字段 `s`（对应 `sortId`）。
5. `DbContext` 为 `App_PortCodes` 增加 `(TenantId, SortId)` 普通索引，支撑按租户列表排序。未生成 Migration。

删除接口不需要这个字段：删的是整行，引用校验逻辑不变。

# 避坑指南

- **存量全是 0。** 迁移后旧港口 `SortId` 都是 0，彼此之间会退回到次级排序（管理端按 `Id` 降序，业务端按英文名）。要排出先后必须在编辑里补数字。
- **允许重复。** 多条港口可以填同一个 `SortId`，没有唯一约束，也不做范围校验。
- **外键简易对象不带 `sortId`。** `PortCodeSimpleDto` / `PortCodeSimpleDtoForOrder` 仍是选港展示用，不加排序字段。海空合并列表 `GetSeaAirPortPagedListAsync` 排序也没改。
- **传了 `sorting` 就不再按 `SortId`。** 管理端列表只有 `sorting` 为空时才用默认的 `SortId` 降序。
