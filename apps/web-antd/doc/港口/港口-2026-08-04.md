# 背景意图

港口主数据此前允许无限重复录入：同一个国家下可以建出多条同名的 `PortName`，导致订舱、运价、报价单等下游模块选港时出现多个一模一样的选项，业务无法判断该选哪一条，且统计口径被拆散。

业务口径是「港口英文名称在同一个国家内唯一」——同名港口允许存在于不同国家（例如多个国家都有 `VICTORIA`），但同一国家内不允许重复。因此唯一键取 `PortName + CountryId` 组合，而不是单独的 `PortName`。

# 核心逻辑变更

1. `PortCodeAdminAppService` 新增私有方法 `ValidateDuplicateAsync(string portName, long countryId, long? excludeId)`：
   - 命中条件：`CountryId` 相同 **且** `PortName` 大写后相同。
   - 命中后抛 `UserFriendlyException("港口英文名称和国家已存在")`。
   - 查询使用 `AsNoTracking()`；编辑场景通过 `excludeId` 排除自身。
2. `AddAsync`：在原有「名称非空 / 航线id / 国家id」校验之后，先 `Trim()` 掉 `PortName` 首尾空格得到 `portName`，再调用 `ValidateDuplicateAsync(portName, input.CountryId, null)`；映射实体后用 `data.PortName = portName` 落库规整后的值。
3. `EditAsync`：同样先 `Trim()` 得到 `portName`，调用 `ValidateDuplicateAsync(portName, input.CountryId, input.Id)`，通过后再赋值 `portCode.PortName = portName`。

# 避坑指南

- **校验必须在赋值之前。** `EditAsync` 里的 `portCode` 是被 EF 跟踪的实体，一旦先赋值再校验，抛异常时若外层已 `SaveChanges` 就可能把脏值写进库。当前顺序是「查实体 → 校验 → 赋值」，不要调换。
- **大小写不敏感。** 比较统一走 `ToUpper()`，`shanghai` 与 `SHANGHAI` 视为重复。虽然 SQL Server 默认排序规则本身大小写不敏感，但显式 `ToUpper()` 可以不依赖数据库排序规则配置。
- **只 `Trim()`，不做内部空格压缩。** `SHANG HAI` 与 `SHANGHAI` 仍是两条不同数据，如需更严格的归一化要另提需求。
- **软删除数据不参与校验。** `PortCode` 继承 `FullAuditedEntity<long>`，仓储 `GetAll()` 自带 `IsDeleted = false` 过滤，所以删掉的同名港口不会阻塞新增；这也意味着「删了再建同名」是允许的。
- **数据库层没有加唯一索引。** 校验仅在应用层，历史脏数据（存量重复行）不会被自动清理，编辑这类历史行时会直接被拦住，需要先人工合并/删除重复数据。
- **国家变更同样受约束。** 编辑时只改 `CountryId` 不改 `PortName`，若目标国家下已存在同名港口，也会被拦下。
