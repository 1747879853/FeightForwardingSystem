# 空运出口模块接口文档

本文档只讲**怎么调用**：地址、鉴权、参数结构、返回结构、报文样例、报错文案。

业务含义、字段口径、计算规则、权限设计等**业务逻辑**统一见同目录下的《空运出口模块总逻辑文档》，本文不重复解释业务，只在需要时标注「规则见逻辑文档 X.Y」。

本文档面向**前端开发与测试**（含前端 AI 与测试 AI），内容覆盖到可以脱离后端独立完成开发与验证的程度。

# 1. 对接总纲

本章是纯技术约定，与业务无关，但**每一个请求都会受它影响**。第 4 章描述各接口时不再重复。

## 1.1 服务地址与鉴权

| 项 | 值 |
| :-- | :-- |
| 接口基址 | `{host}/api/services/app/AirExportAdmin/` |
| 完整路径 | 基址 + 方法名，**方法名保留 `Async` 后缀** |
| 登录接口 | `POST {host}/api/TokenAuth/Authenticate`，请求体 `{ "userNameOrEmailAddress": "...", "password": "...", "rememberClient": true }` |
| 鉴权头 | `Authorization: Bearer {accessToken}`，token 取自登录接口返回的 `result.accessToken` |
| 租户头 | `Abp.TenantId: {租户id}`。宿主（Host）账号登录后不带该头；租户账号登录时带上自己的租户 id |
| 请求体类型 | `Content-Type: application/json`（POST / PUT / DELETE 都是） |

本模块 11 个接口**全部要求已登录**，且各自要求对应的功能权限点（见 1.9）。

## 1.2 接口一览

| # | 业务动作 | HTTP | 完整路径 | 参数位置 | `result` 的类型 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | 新增 | POST | `/api/services/app/AirExportAdmin/AddAsync` | 请求体 | `string`（新票 Guid） |
| 2 | 编辑 | PUT | `/api/services/app/AirExportAdmin/EditAsync` | 请求体 | `bool` |
| 3 | 详情 | GET | `/api/services/app/AirExportAdmin/DetailAsync` | QueryString | 对象 |
| 4 | 列表 | GET | `/api/services/app/AirExportAdmin/GetPagedListAsync` | QueryString | 分页对象 |
| 5 | 复制 | POST | `/api/services/app/AirExportAdmin/CopyAsync` | 请求体 | `string`（新票 Guid） |
| 6 | 删除 | DELETE | `/api/services/app/AirExportAdmin/DeleteAsync` | **请求体** | `bool` |
| 7 | 分组统计 | GET | `/api/services/app/AirExportAdmin/GetGroupedListAsync` | QueryString | 数组 |
| 8 | 重新生成委托编号 | PUT | `/api/services/app/AirExportAdmin/UpdateCommissionNumAsync` | 请求体 | `string`（新编号） |
| 9 | 查询附件 | GET | `/api/services/app/AirExportAdmin/GetAttachmentsAsync` | QueryString | 数组 |
| 10 | 新增附件 | POST | `/api/services/app/AirExportAdmin/AddAttachmentsAsync` | 请求体 | `bool` |
| 11 | 删除附件 | DELETE | `/api/services/app/AirExportAdmin/DeleteAttachmentsAsync` | **请求体** | `bool` |

> [!WARNING] **两个 DELETE 接口的参数在请求体里，不在 URL 上。** 浏览器 `fetch` 支持 DELETE 带 body；`axios` 必须写成 `axios.delete(url, { data: payload })`，写成 `axios.delete(url, payload)` 会把 payload 当成配置对象丢掉，后端收到空入参。

## 1.3 统一响应包装

**所有**接口（包括报错）都返回同一层信封，业务数据在 `result` 里：

```json
{
  "result": { "……业务数据……" },
  "targetUrl": null,
  "success": true,
  "error": null,
  "unAuthorizedRequest": false,
  "__abp": true
}
```

失败时：

```json
{
  "result": null,
  "targetUrl": null,
  "success": false,
  "error": {
    "code": 0,
    "message": "销售有且只能有一个",
    "details": null,
    "validationErrors": null
  },
  "unAuthorizedRequest": false,
  "__abp": true
}
```

前端判定成功与否**只看 `success`**，失败时直接把 `error.message` 弹给用户——本文档各接口「报错文案」小节列出的引号内文字，就是 `error.message` 的原文。

## 1.4 HTTP 状态码

| 状态码 | 场景 | `success` |
| :-- | :-- | :-- |
| 200 | 调用成功 | `true` |
| **500** | **业务校验失败**（本文档列出的所有业务报错都走这里） | `false` |
| 401 | 未登录 / token 过期 / token 无效 | `false`，且 `unAuthorizedRequest = true` |
| 403 | 已登录但缺少对应功能权限点 | `false`，且 `unAuthorizedRequest = true` |
| 400 | 参数格式非法，模型绑定或 `[Range]`、`[StringLength]` 特性校验不通过；`error.validationErrors` 里是具体字段 | `false` |

> [!IMPORTANT] 业务错误返回的是 **HTTP 500**，不是 400。前端不能用「状态码 2xx」判成功、「4xx」判业务错误，必须按 `success` 字段判。测试断言业务报错时，期望值写「HTTP 500 且 `error.message` 等于 XXX」。

各接口的实现把整个方法体包在异常捕获里，任何非预期的系统异常（数据库超时、空引用等）也会被转成同样的信封返回，`error.message` 是原始异常消息。因此**看到不在本文档清单里的报错文案，就是系统异常，应当提缺陷**，而不是当成业务规则。

## 1.5 JSON 字段命名规则

响应体统一使用 **camelCase**（PascalCase 首字母连续大写的部分整体小写）。请求体的 JSON 反序列化不区分大小写，QueryString 的模型绑定也不区分大小写，因此**入参写 camelCase 或 PascalCase 都能被正确接收**；但**出参永远是 camelCase**。

本文档参数表里写的是 C# 属性名（PascalCase），报文样例里写的是实际 key（camelCase）。特殊换算：

| 属性名 | 响应中的 key | 说明 |
| :-- | :-- | :-- |
| `FlightNo` | `flightNo` | 常规首字母小写 |
| `POLId` / `POTId` / `PODId` | `polId` / `potId` / `podId` | 连续大写整体转小写 |
| `POL` / `POT` / `POD` | `pol` / `pot` / `pod` | 同上 |
| `POLRemark` / `POTRemark` / `PODRemark` | `polRemark` / `potRemark` / `podRemark` | 同上 |
| `POLIdEmpty` / `POTIdEmpty` / `PODIdEmpty` | `polIdEmpty` / `potIdEmpty` / `podIdEmpty` | 同上 |
| `ETD` / `ETA` / `ATD` | `etd` / `eta` / `atd` | 同上 |
| `ETDStart` / `ETDEnd` | `etdStart` / `etdEnd` | 同上 |
| `PKGS` | `pkgs` | 同上 |
| `KGS` | `kgs` | 同上 |
| `CBM` | `cbm` | 同上 |
| `TEU` | `teu` | 同上 |
| `UpperPKGS` | `upperPKGS` | 第二个字符是小写，只转首字母 |
| `CodeGoodsHSCode` | `codeGoodsHSCode` | 第二个字符是小写，只转首字母 |
| `HSCode` | `hsCode` | 开头连续大写整体转小写，后面保持不变 |
| `IataCode` | `iataCode` | 常规 |
| `Kgs` / `Cbm`（业务主表的毛重体积） | `kgs` / `cbm` | 常规 |
| `AirExport` / `AirExportOrderCtns` / `TransportOrder` | `airExport` / `airExportOrderCtns` / `transportOrder` | 常规 |

> [!IMPORTANT] 货物明细行里的件数、重量、体积用的是**全大写属性名** `PKGS` / `KGS` / `CBM`，序列化后是 `pkgs` / `kgs` / `cbm`；而业务主表那一层的毛重、体积属性名是 `Kgs` / `Cbm`（只有首字母大写），序列化后**也是** `kgs` / `cbm`。两者 key 长得一样但**分属不同层级、含义完全不同**（一个是单件值，一个是整票申报值），不要串层取值。

## 1.6 数据类型在 JSON 中的表示

| 类型 | 请求写法 | 响应形态 | 说明 |
| :-- | :-- | :-- | :-- |
| `Guid` | `"3f2504e0-4f89-11d3-9a0c-0305e82c3301"` | 同左，小写带连字符 | 空 Guid 是 `"00000000-0000-0000-0000-000000000000"`，等价于「没传」 |
| `long` / `int` | `123` | `123` | 不要传字符串 |
| `decimal` | `1234.567890` | `1234.567890` | 空运出口新增的小数字段标注的是 **6 位精度**，**入参会自动四舍五入到 6 位**再进入业务逻辑；业务主表的毛重体积仍是 2 位 |
| `bool` | `true` / `false` | 同左 |  |
| `DateTime` | `"2026-08-01"` 或 `"2026-08-01T13:20:00"` | `"2026-08-01T00:00:00"` | ISO 8601，**不带时区后缀**，服务端按本地时间原样存取，不做时区换算 |
| `enum` | 数字，如 `1` | 数字，如 `1` | **不接受也不返回枚举名字符串**，取值见第 2 章 |
| `null` | `null` | `null` | 可空字段不传等同于传 `null` |
| 数组 | `[...]` | `[...]` | 传 `null` 与传 `[]` 在部分接口语义不同，见各接口说明 |

## 1.7 入参字符串会被自动 Trim

请求进入业务逻辑之前，框架会**递归遍历整个入参对象树**（含嵌套对象、数组元素、字典值），把所有字符串属性的首尾空白去掉。因此：

- 传 `"  ABC  "` 等价于传 `"ABC"`；
- 传 `"   "`（全空白）等价于传 `""`（空字符串），**但不等于 `null`**；
- 长度校验是在 Trim **之后**执行的，首尾空格不占长度配额；
- 航班（`FlightNo`）还额外做了一步规范化：Trim 之后为空字符串的，**入库时存 `null`**，以保证「未填写」筛选能命中。

## 1.8 字段级权限会让 key 直接消失

字段级权限不是把值置为 `null`，而是在 JSON 序列化阶段**整个跳过该属性**——响应里根本不会出现这个 key。

前端读取时必须用「key 不存在」和「值为 null」都能兜住的写法（如可选链 + 默认值），不能假设 key 一定存在。测试断言「无权限时字段不可见」时，应断言 **key 不存在**，而不是断言值为 `null`。

被屏蔽的字段分两层，独立配置，可能出现「空运层能看航班、业务层看不到主提单号」这种组合：

| 层级             | 模块标识             | 作用范围                        |
| :--------------- | :------------------- | :------------------------------ |
| 空运出口自身字段 | `AirExport = 5`      | 响应里空运出口这一层的字段      |
| 业务主表字段     | `TransportOrder = 2` | `transportOrder` 对象内部的字段 |

编辑接口有配套保护：入参中当前用户无权查看的字段，后端会用数据库原值回填，避免前端因看不到该字段而没传、导致保存时被覆盖成空。规则见逻辑文档 4.3。

## 1.10 分页与排序

列表接口（`GetPagedListAsync`）的分页排序参数：

| 参数 | 类型 | 默认值 | 取值范围 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| PageIndex | int | 1 | 1 ~ 2147483647 | 当前页码，从 1 开始。传 0 或负数返回 HTTP 400 |
| PageSize | int | 10 | 1 ~ 100000 | 每页条数。超出范围返回 HTTP 400 |
| Sorting | string | `CreationTime DESC` | - | 排序表达式，见下 |

**`Sorting` 表达式规则**

- 支持**逗号分隔的多字段**，按书写顺序依次作为第一、第二……排序键；
- 每个字段后可跟 `ASC` 或 `DESC`（不区分大小写），省略时按 `ASC`；
- 支持**多级导航属性路径**，用 `.` 逐级下钻访问关联表字段；
- 排序根对象是**空运出口这一层**，业务主表字段要写成 `TransportOrder.XXX`；
- 字段名用 C# 属性名（PascalCase），不是 camelCase。

可用示例：

```
CreationTime DESC
TransportOrder.ETD DESC, CreationTime DESC
FlightNo ASC
TransportOrder.Client.Name ASC, TransportOrder.CommissionNum DESC
BubbleRatio DESC
TransportOrder.AccountDate DESC, TransportOrder.SettlementDate ASC
```

> **不能按货物明细的字段排序**（如计费重）。明细是一对多集合，排序表达式无法下钻集合。需要按计费重排序时只能前端在当前页内自行排。

传入不存在的字段名会抛异常，表现为 HTTP 500 且 `error.message` 是解析异常原文。前端应固定使用列头绑定的白名单字段，不要把用户输入直接拼进去。

**分页返回结构**

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| Items | 数组 | 当前页数据；无数据时是 `[]`，不是 `null` |
| TotalCount | int | 满足条件的总记录数（**已叠加数据权限过滤**，不同账号查同样条件可能不同） |
| SkipCount | int | 已跳过的条数 = (PageIndex − 1) × PageSize |
| MaxResultCount | int | 本次最多返回条数 = PageSize |
| CurrentPage | int | 当前页码 = SkipCount ÷ MaxResultCount + 1 |
| TotalPages | int | 总页数 = ⌈TotalCount ÷ MaxResultCount⌉ |

## 1.11 筛选参数的匹配语义

| 匹配方式 | 实现 | 注意 |
| :-- | :-- | :-- |
| 模糊 | SQL `LIKE '%关键字%'` | 数据库排序规则默认**不区分大小写**；该字段为 `NULL` 的行**不会**被匹配到 |
| 精确 | `=` |  |
| 区间 | `>= 起` 且 `<= 止`，**闭区间** | 两端可以只传一端 |
| 空白入参 | 传 `null`、`""`、全空白字符串 | 一律视为**不筛选**（数值和日期传 `null` 同理） |
| 多个筛选条件 | 一律 `AND` | 没有任何 `OR` 组合，只有 `Keyword` 内部的多字段之间是 `OR` |
| 货物明细区间 | `存在满足条件的明细行` | 见下方警告 |

> [!WARNING] **货物明细的区间筛选是「存在」语义，起止两端各自独立判断。** 例如同时传 `CtnChargeWeightStart = 100` 和 `CtnChargeWeightEnd = 200`，命中条件是「该票**存在**计费重 ≥ 100 的行」**并且**「该票**存在**计费重 ≤ 200 的行」，这两行**可以是不同的行**。一张有 50kg 和 500kg 两行的票会被这个条件命中，尽管没有任何一行落在 100~200 之间。界面上要把这个语义说清楚，或者干脆只提供单端筛选。

**「未填写」开关**：五个字段同时提供「指定值」与「未填写」两个参数，二者**同时传有效值时直接报错**。

| 指定值参数 | 未填写参数 | 冲突时的报错文案 |
| :-- | :-- | :-- |
| POLId | POLIdEmpty | 起运地筛选：未填写与指定id不可同时传入 |
| POTId | POTIdEmpty | 中转地筛选：未填写与指定id不可同时传入 |
| PODId | PODIdEmpty | 目的地筛选：未填写与指定id不可同时传入 |
| BookingAgentId | BookingAgentIdEmpty | 订舱代理筛选：未填写与指定id不可同时传入 |
| FlightNo | FlightNoEmpty | 航班筛选：未填写与指定航班不可同时传入 |

该校验在所有筛选之前执行，一旦冲突其它条件都不生效。「未填写」传 `false` 或不传，等同于不筛，**不会**反向筛出「已填写」的票。

## 1.12 日期参数的注意点

- 请求可以只传日期 `"2026-08-01"`，也可以带时分秒。
- 业务主表的 `ETD`（起飞日期）、`ATD`（实际起飞日期）、`ETA`（预抵日期）、`GoodsCompleteTime`（货好时间）保存时**只保留日期部分**，回读永远是 `T00:00:00`。
- 空运出口层的 `CustomsDeclareDate`（报关日期）、`DeliveryWarehouseDate`（送仓日期）**原样保存**，传了时分秒会原样回读。
- 区间筛选是闭区间，因此筛选上述「原样保存」的两个日期时，「止」端建议传当天的 `23:59:59`，否则当天带时分秒的数据会被漏掉。

## 1.13 典型页面的调用顺序

| 场景 | 调用序列 |
| :-- | :-- |
| 打开列表页 | `GetPagedListAsync`（首屏）→ 需要统计卡片时并行 `GetGroupedListAsync` |
| 新建一票 | 表单提交 `AddAsync` → 拿到 Guid → 用该 Guid 调 `DetailAsync` 回显 |
| 打开编辑页 | `DetailAsync` 取全量 → 用户改 → `EditAsync`（**子表必须整体回传**） |
| 复制一票 | `CopyAsync` → 拿到新 Guid → `DetailAsync` 打开新票 |
| 单独管理附件 | `GetAttachmentsAsync` / `AddAttachmentsAsync` / `DeleteAttachmentsAsync`；也可以在 `AddAsync` / `EditAsync` 里用 `AttachmentGroup` 一起提交 |
| 删除一票 | 先确认该票没有费用 → `DeleteAsync` |

# 2. 枚举取值速查

枚举在 JSON 中一律是**数字**。业务含义见逻辑文档第 3 章。

| 枚举 | 取值 |
| :-- | :-- |
| BizType 业务类型 | `0` 海运出口、`1` 海运进口、**`2` 空运出口** |
| OrderInputType 录入方式 | `0` 手动录入、`1` 业务联系单导入、`2` 复制 |
| CargoType 货物类型 | `0` 普通货、`1` 冻柜、`2` 危险品、`3` 超限箱（空运没有对应录入位） |
| TradeTermsType 贸易条款 | `0` CIF、`1` FOB、`2` EXW、`3` FCA、`4` DDP、`5` DDU、`6` DAP、`7` C&F（空运出口不展示） |
| UserAttribute 用户属性 | `0` 无、`1` 操作、`2` 客服、`4` 单证、`8` 商务、`16` **销售**、`32` 财务、`64` 海外客服、`128` 人事（一条记录只放一个值） |
| AirExportGroupField 分组字段 | `3` 委托单位、`5` 起运地、`6` 目的地、`12` 仓库、`13` 车队、`15` 订舱代理、`16` 中转地、`17` 保险公司、`18` 报关行 |
| PaySide 收付类型 | `0` 收、`1` 付 |
| FeeStatus 费用状态 | `0` 录入、`1` 提交审核、`2` 审核通过、`3` 驳回 |
| SettlementStatus 结算状态 | `0` 未结算、`1` 部分结算、`2` 结算完毕 |
| InvoiceStatus 开票状态 | `0` 未开票、`1` 部分开票、`2` 已开票 |
| DataEntryMethod 费用录入方式 | `0` 手动、`1` 历史费用引入、`2` 收转付、`3` 付转收、`4` 费用模板、`5` 业务复制、`6` 业务联系单导入 |
| 组合费用状态（`payFeeStatus` / `receiveFeeStatus`） | `0` 录入、`1` 提交审核、`2` 审核通过、`3` 部分结算、`4` 结算完毕、`5` 驳回、`6` 申请修改、`7` 申请删除；无该方向费用时为 `null` |

## 3.2 货物明细（空运出口专属）

**位置：请求和响应中都在最外层 `airExportOrderCtns`**，不在 `transportOrder` 里面。这张表是空运出口用来替代海运集装箱的，外键挂的是**空运出口 Id**。

| 字段 | 类型 | 新增入参 | 编辑入参 | 出参 | 精度 | 说明 |

| Id | Guid? | — | 有 | 有 | - | **Guid，不是自增整数**。编辑时区分新增行（不传或传 `null`）与更新行（传已有 id）。出参恒有值 |

| PKGS | int? | 有 | 有 | 有 | - | **件数**，本行有多少件 |

> **票级没有计费重合计**，需要整票计费重时由界面把各行相加。
>
> **主键是 Guid，排不出录入先后。** `SortId` 相同的行之间兜底的主键排序是随机顺序，界面必须给每行分配唯一且连续的 `SortId` 才能保证行序稳定。另外前端渲染表格时不能拿主键当「新行未保存」的判据（新行不带 `id` 或带 `null`，不是 `0`），建议自己维护一个临时行号做 key。

| 分组 | 字段 |
| :-- | :-- |
| 订阅状态 | `IsSubscribed`、`IsSubscribeSuccess`、`BusinessNumber`（11 位航司单号）、`FeituoSubscriptionId`、`ErrorMessage`、`LastQueryTime`、`LastPushTime` |
| 整票状态 | `Status`（`COMPLETE` 完成 / `PROCESS` 进行中）、`UpdateTime`、`Direct`（`true` 直达 / `false` 中转） |

| 当前节点 | `CurrentEventCategory`、`CurrentEventCode`、`CurrentEventClassifier`（`ACT` 实际 / `EST` 预计）、`CurrentEventTime`、`CurrentDescription`、`CurrentFlight`、`CurrentLocationCode`、`CurrentLocationName`、`CurrentLocationCity`、`CurrentLat`、`CurrentLon` |
| 起降 | `OriginCode`/`OriginName`/`OriginCity`、`DestinationCode`/`DestinationName`/`DestinationCity`、`FirstFlight`、`LastFlight`、`DestinationEta`、`DestinationAta` |

**三条使用口径**：

1. **订阅成功不代表马上有轨迹。** 刚订阅时飞驼往往还没抓到数据，此时 `feituoTracking` 不为 `null` 但当前节点全空，界面提示「数据获取中」即可。
2. **当前节点是后端算的。** 飞驼空运不返回"当前状态"，后端取所有事件里时间最新的**实际**事件；没有实际事件才退回预计事件。`CurrentEventClassifier = EST` 时说明这是预计节点，展示上建议区分。
3. **所有时间都是字符串**（飞驼原样返回 `yyyy-MM-dd HH:mm:ss`），直接展示，不要解析成日期再格式化，否则会因时区偏移显示错时间。

> 订阅与重新订阅不在本模块，见《飞驼对接-航空货运跟踪-前端对接.md》。云当空运运踪的 `IsYundangSubscribed` / `IsYundangSubscribeSuccess` / `YundangAirShipmentNode` 与飞驼互相独立，可同时订阅。

## 4.3 详情 DetailAsync

### 4.3.1 地址与权限

| 项       | 值                                             |
| :------- | :--------------------------------------------- |
| 方法     | `GET`                                          |
| 地址     | `/api/services/app/AirExportAdmin/DetailAsync` |
| 参数位置 | QueryString                                    |
| 权限点   | `Admin.AirExport.Get`                          |
| 返回     | `result` 为空运出口对象                        |

> **本接口会做行级数据权限 + 表级权限过滤**（2026-08-19 起，此前不过滤、拿到 Id 就能查）。查不到时按三种情况分别报错：记录不存在 →「输入空运出口错误」；没有行级数据权限 →「没有这条数据的数据权限,不能查看」；被表级权限挡掉 →「没有这条数据的表级权限,不能查看」。
>
> 返回里新增 `isEditable`（是否可编辑），以及 `previousId` / `nextId`（上一票/下一票）。

### 4.3.2 输入参数

入参 = **当前票 `Id`** + **与列表 `GetPagedListAsync` 完全相同的搜索条件与排序**（`AirExportDetailQueryDto`）。从列表点进详情、以及详情里点上一票/下一票时，把当时列表的 Query 原样带上，只换当前票 `Id`。上一票/下一票按这份条件筛完、再按 `Sorting` 排完之后的全量顺序定位，**与当前在第几页无关**（`PageIndex` / `PageSize` 可带但不参与定位）。

| 参数 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| Id | Guid | **是** | 当前空运出口主键 |

## 4.6 复制 CopyAsync

### 4.6.1 地址与权限

| 项       | 值                                           |
| :------- | :------------------------------------------- |
| 方法     | `POST`                                       |
| 地址     | `/api/services/app/AirExportAdmin/CopyAsync` |
| 参数位置 | 请求体（JSON）                               |
| 权限点   | `Admin.AirExport.Add`                        |
| 返回     | `result` 为新票的 Guid 字符串                |

### 4.6.2 输入参数

| 参数          | 类型 | 必填   | 说明                               |
| :------------ | :--- | :----- | :--------------------------------- |
| Id            | Guid | **是** | 要复制的空运出口 id                |
| CopyOrderFees | bool | 否     | 是否连费用一起复制，不传按 `false` |

**复制的处理规则**：

| 项 | 处理 |
| :-- | :-- |
| 委托编号 | **一律重新生成**，不沿用原票 |
| 主提单号 / 订舱编号 / 合同号 / 发票号 | **清空** |
| 录入方式 | 写 `2` 复制 |
| 业务锁定 / 未完结 / 费用锁定及其四个人员时间字段 | **重置**（锁定为 `false`，人员时间为 `null`） |
| 会计期间 / 应结日期 | 按新票重新计算（基准仍是源票的起飞日期） |
| 所属组织 / 所属人 | 组织沿用源票；所属人改为当前登录用户。**复制不执行组织归属校验** |
| 货物明细 / 商品子表 / 关联人员 | **全部复制**，主键重新生成 |
| 空运出口层其它字段（订舱代理、航班、三个空港及备注、泡比、报关日期、送仓日期、排序号） | **原样复制** |
| 附件 | **不复制** |
| 改单 | **不复制** |
| 费用 | `CopyOrderFees = true` 时复制**非改单**费用，且每条重置为：费用状态 `0` 录入、结算状态 `0` 未结算、开票状态 `0` 未开票、录入方式 `5` 业务复制、已结算金额 `0`、对账单 `null`、改单 `null`、费用模板项 `null`，会计期间取新票的 |

### 4.6.3 输出参数

| 字段   | 类型   | 说明      |
| :----- | :----- | :-------- |
| result | string | 新票 Guid |

### 4.6.4 报错文案

| 报错文案                            | 触发条件                               |
| :---------------------------------- | :------------------------------------- |
| 输入信息不能为空                    | 请求体为 `null`                        |
| 空运出口id不能为空                  | `Id` 为空 Guid                         |
| 空运出口不存在                      | `Id` 查不到（含已软删除）              |
| 业务信息不存在                      | 空运出口存在但业务主表不存在（脏数据） |
| 业务关联人员不能为空                | **源票**没有关联人员                   |

| 未配置生成规则 / 未配置自增编号规则 | 编号规则问题，同 4.1.5                 |

> 后两条说明：源票是通过接口正常创建的话不会出现，但历史数据或直接改库可能造成。

# 6. 常见对接坑位

1. **货物明细在顶层，不在 `transportOrder` 里。** `transportOrder.orderCtns` 恒为 `null`，那是海运的集装箱。
2. **明细行里单件值和合计值混着。** 件数、重量、长宽高、体积是单件；体积重、计费重是整行合计。填错量级会差几十倍。
3. **四个派生值后端不算也不校验。** 改了长宽高或整票毛重体积后，必须前端重新计算再提交，否则存下去的是旧值，后端不会纠正也不会报错。
4. **泡比算不出来要传 `null`，不要传 `0`。** 体积为 0 或为空时，`0` 会被当成真实泡比存下去。
5. **计费重的进位是 0.5kg 向上。** 12.1 → 12.5，12.5 → 12.5，12.6 → 13.0。不是四舍五入，也不是整数进位。
6. **`etd`/`atd` 界面叫起飞日期，不是开船日期。** 别去找 `flightDate`。
7. **`eta` 界面就叫「预抵日期」**，与海运一致，不要改成「到达日期」。
8. **航班不是航次。** `flightNo` 在空运出口扩展表上，`innerVoyno` 是海运的字段，空运出口表里根本没有。
9. **三张子表全量比对，漏传即删除。** 编辑时必须整表回传。
10. **明细排序靠 `sortId`。** 拖动排序、往中间插行时要把整表 `sortId` 重排后一起提交，只改被拖那一行会导致序号重复，重复时按主键升序兜底——而主键是 Guid，兜底出来的是随机顺序，不是录入先后。
11. **明细主键是 Guid 且可空，不是自增整数。** 判断「这是不是未保存的新行」不能写 `id === 0` 或 `id > 0`，要判 `null` / `undefined`；新增行**不要传全零 Guid**，那会被当成「传了主键」去库里找对应行，找不到就既不更新也不插入，这一行会**静默丢失**。表格 key 建议用前端自己维护的临时行号，不要用主键。
12. **两个 DELETE 接口参数在请求体。** `axios.delete(url, { data })`。
13. **删除附件传的是 `attachmentId`，不是关联记录的 `id`。**
14. **有费用的票删不掉。** 含改单费用。
15. **销售必须恰好 1 个，且所属组织必须是这个销售的直属组织。** 换销售时要重新加载组织下拉并清掉旧选择。
16. **编号规则 `AirExport.CommissionNum` 没配置，新增（不填编号时）、复制、重新生成编号三个功能全部不可用。** 上线前必须先配。
17. **业务错误是 HTTP 500，按 `success` 判断，不要按状态码判断。**
18. **字段级权限会让 key 整个消失**，不是置 `null`，读取要能兜住 key 不存在。
19. **列表每行带完整费用清单和三张子表**，`PageSize` 不要开太大。
20. **明细的区间筛选是「存在」语义**，起止两端可命中不同行。
21. **模糊搜索搜不到空值。** 想找「未填写」要用 `XxxEmpty` 开关，且不能和值同时传。
22. **报关日期、送仓日期不截断时分秒**，区间筛选的「止」端要传 `23:59:59`。
23. **`transportOrder.teu` 恒为 0、`totalCtn` 恒为 `null`、商品的 `teu` 恒为 0**，界面不要展示这三个。
24. **空港对象不带国家。** 需要国家请查空运港口基础资料。
25. **可能存在有业务主表、没有空运出口扩展记录的脏票**（直接改库或历史迁移造成）。这类票在空运出口列表里查不到，走业务主表详情时 `airExport` 为 `null`，界面要兜住。
26. **飞驼订阅成功不等于有轨迹。** `feituoTracking` 不为 `null` 但当前节点全空，是「已订阅、飞驼还没抓到数据」，提示「数据获取中」而不是报错。
27. **飞驼的当前节点可能是预计值。** `currentEventClassifier = EST` 说明这是预计节点（后端在一条实际事件都没有时才会取它），展示上要和实际节点区分。
28. **飞驼运踪里的时间全是字符串**（`yyyy-MM-dd HH:mm:ss`），直接展示，别解析成 Date 再格式化，否则会因时区偏移显示错时间。
29. **列表不返回 `feituoTrackingDetail` 和 `feituoTrackingWarnings`**，只有摘要。要看完整轨迹和预警明细请进详情。
30. **主提单号当前租户业务表内不可重复。** 和海运出口、海运进口撞号也会报「主提单号【{号码}】已存在」。空不校验；编辑排除自身。
