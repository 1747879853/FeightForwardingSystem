# 1. 背景意图 (Background)

`InvoiceApplicationAdminAppService` 的列表 `GetPagedListAsync` 与详情 `DetailAsync` 此前只返回 `ClientInvoiceBankId`（客户银行ID），前端拿不到该银行所属的**客户开票信息**（抬头、税号、地址、电话等）。本次让两个接口**额外返回 `ClientInvoiceBankId` 对应的 `ClientInvoiceInfo` 的 DTO**，无对应数据时为 `null`。

# 2. 核心逻辑变更 (Core Logic)

涉及文件：

- `src/CsprojBuilder.Application/App/InvoiceApplication/InvoiceApplicationAdminAppService.cs`
- `src/CsprojBuilder.Application/App/InvoiceApplication/Dto/InvoiceApplicationDto.cs`

## 2.1 DTO 变更

`InvoiceApplicationListDto`、`InvoiceApplicationDetailDto` 各新增：

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `ClientInvoiceInfo` | `ClientInvoiceInfoDto` | 客户银行(`ClientInvoiceBankId`)对应的客户开票信息，无则 `null`，含其下银行列表 `ClientInvoiceBanks`（带 `CurrencyCode`） |

新增 `using CsprojBuilder.App.ClientInvoiceInfo.Dto;`。

## 2.2 解析逻辑（私有方法）

新增私有方法 `GetClientInvoiceInfoMapByBankIdsAsync(List<Guid> clientInvoiceBankIds)`，返回 `银行id -> ClientInvoiceInfoDto` 字典：

1. 过滤掉空 `Guid` 并去重；为空直接返回空字典。
2. 经 `_clientInvoiceBankRepository` + `.Include(b => b.ClientInvoiceInfo).ThenInclude(i => i.ClientInvoiceBanks)` 一次性加载银行→开票信息→该信息下全部银行。
3. 批量取币别回填 `ClientInvoiceBankDto.CurrencyCode`，银行列表按 `IsDefault`、`SortId` 倒序。
4. 列表方法批量调用、详情方法单 id 调用，均用 `GetValueOrDefault` 取值（无则 `null`）。

关系链：`InvoiceApplication.ClientInvoiceBankId → ClientInvoiceBank.ClientInvoiceInfoId → ClientInvoiceInfo`。

# 3. 避坑指南 (Pitfalls)

- **`Currency` 命名冲突**：`CsprojBuilder.App.Currency` 命名空间会与实体 `Currency` 撞名，新建空列表须写 `new List<Entites.Currency>()`，否则编译报 CS0118/CS0173。
- **无数据返回 `null`**：`ClientInvoiceBankId` 为空或银行/开票信息查不到时，`ClientInvoiceInfo` 为 `null`。
- **`ClientInvoiceInfoDto.ClientInvoiceBanks` 是“该开票信息下全部银行”**，不是仅当前选中的那一条；当前选中的银行仍可由 `ClientInvoiceBankId` 定位。
- **复用既有映射约定**：银行 DTO 的 `CurrencyCode` 与组织/客户模块一致，需按 `CurrencyId` 关联回填，AutoMapper 不自动赋值。
