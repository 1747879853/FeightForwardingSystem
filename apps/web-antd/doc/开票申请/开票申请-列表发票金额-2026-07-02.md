# 1. 背景意图 (Background)

开票申请列表接口 `GetPagedListAsync` 此前仅返回 `TotalAppliedAmount`（费用明细申请金额合计，为**原币金额**，可能是外币）。业务需要在列表中直接看到**发票金额**，即开票金额合计，且该金额必须是**人民币金额**而非原币金额，便于统一口径核对开票总额。

# 2. 核心逻辑变更 (Core Logic)

涉及文件：

- `src/CsprojBuilder.Application/App/InvoiceApplication/Dto/InvoiceApplicationDto.cs`
- `src/CsprojBuilder.Application/App/InvoiceApplication/InvoiceApplicationAdminAppService.cs`

## 2.1 DTO 变更

`InvoiceApplicationListDto` 新增字段：

| 字段 | 类型 | 含义 |
| :-- | :-- | :-- |
| `InvoiceAmount` | `decimal?` | 发票金额（开票金额合计，**人民币金额**），= 原币申请金额合计 × 发票汇率；无有效发票汇率时为 `null` |

## 2.2 接口变更

| 接口 | 变更 |
| :-- | :-- |
| `GetPagedListAsync` | 在原有 `InvoiceExchangeRate`（发票汇率）基础上，计算并返回 `InvoiceAmount = Round(TotalAppliedAmount × InvoiceExchangeRate, 2, AwayFromZero)`；发票汇率不存在时返回 `null` |

# 3. 避坑指南 (Pitfalls)

- **原币 vs 人民币**：`TotalAppliedAmount` 是**原币金额**（费用明细 `AppliedAmount` 之和，可能外币）；`InvoiceAmount` 是**人民币金额**，务必区分，前端展示"发票金额"应取 `InvoiceAmount`。
- **发票汇率来源**：沿用列表已有的 `InvoiceExchangeRate`（`ExchangeRate` 表 `InvoiceValue`，本位币 RMB 且当前时间在有效期内）。若对应币别未维护发票汇率，`InvoiceExchangeRate` 与 `InvoiceAmount` 均为 `null`，前端需做空值兜底。
- **口径一致**：折算逻辑与新增/修改时的商品明细金额校验（`itemsAppliedRmb = 原币合计 × 发票汇率`，四舍五入 2 位 `AwayFromZero`）保持一致，避免出现列表与保存校验金额不符。
- **汇率时点**：列表取的是**当前有效**发票汇率，非开票申请创建时点的历史汇率（实体未存储历史汇率），与详情/列表既有 `InvoiceExchangeRate` 行为一致。
