# 1. 背景意图 (Background)

开票申请费用明细 `appliedAmount` 支持传负数，用于冲红。但原实现只校验“不能大于剩余可开票额度”，没有校验负数下界。

这会导致一种超额场景：若负数绝对值超过当前已占用额度，就可能把某条费用的开票申请占用额冲成负数，进而放大后续的可开票额度，连带影响依赖 `InvoiceApplicationItem.AppliedAmount` 的其他模块校验。

# 2. 核心逻辑变更 (Core Logic)

## 2.1 影响接口

| 接口 | 地址 | 说明 |
| :-- | :-- | :-- |
| 新增开票申请 | `POST /api/services/app/InvoiceApplicationAdmin/AddAsync` | 校验单条费用申请额上下界 |
| 编辑开票申请 | `PUT /api/services/app/InvoiceApplicationAdmin/EditAsync` | 校验单条费用申请额上下界 |
| 追加费用明细 | `POST /api/services/app/InvoiceApplicationAdmin/AddItemsAsync` | 校验单条费用申请额上下界 |

## 2.2 新的金额区间

对每条费用，`appliedAmount` 必须满足：

`-其他申请已占用额 <= appliedAmount <= 费用金额 - 其他申请已占用额`

其中：

- `其他申请已占用额 = Sum(其他 InvoiceApplicationItem.AppliedAmount)`
- 上界表示本次不能超过剩余可开票额度。
- 下界表示冲红后总占用额不能小于 0。

## 2.3 错误提示

| 场景     | 提示                                           |
| :------- | :--------------------------------------------- |
| 超过上界 | `费用剩余可开票额度不足,可用额度:{maxAllowed}` |
| 低于下界 | `费用冲红额度不足,最小可用额度:{minAllowed}`   |

# 3. 避坑指南 (Pitfalls)

- **负数不是无限冲红**：允许负数只代表支持冲红，不代表可以把某条费用的累计申请额冲成负值。
- **编辑与追加费用也要走同一口径**：否则新增能拦住、编辑/追加仍可绕过。
- **该修复只处理超额风险**：`UnInvoicedAmount` 等展示字段是否调整，不在本次修复范围内。
