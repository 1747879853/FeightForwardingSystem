# 开票申请银行可空-2026-07-23

## 背景意图

- 业务要求 `InvoiceApplication.OrgBankAccountId`、`ClientInvoiceBankId` 在新增/编辑时可空保存；未传不校验、不自动填充默认银行。
- 提交审核时强制校验两字段不可为空，保证进入待审核后发票开出仍可依赖银行信息。

## 核心逻辑变更

- 实体可空化：
  - `InvoiceApplication.OrgBankAccountId`：`Guid` → `Guid?`
  - `InvoiceApplication.ClientInvoiceBankId`：`Guid` → `Guid?`
- DTO 可空化：
  - 新增币别分组、编辑入参、列表/详情/简易输出、发票开出侧 `InvoiceIssueApplicationDto` 同步为 `Guid?`
- 服务层：
  - `AddAsync`：取消“未传则取默认银行”；仅传值时校验我司银行归属公司、客户银行归属结算对象
  - `EditAsync`：同上，未传不校验，支持置空
  - `SubmitAsync`：校验 `OrgBankAccountId`、`ClientInvoiceBankId` 均有值，否则分别报「我司银行不能为空」「客户银行不能为空」
  - 列表/详情解析 `ClientInvoiceInfo` 时对空银行做容错
- 发票开出：
  - 合并校验增加银行非空检查；从开票申请取值时使用 `.Value`

## 避坑指南

- 本次未生成 migration，请自行将 `App_InvoiceApplications` 两列改为可空。
- 历史数据若已有银行值不受影响；草稿态可空后，提交前前端需补齐银行。
- 客户对账文档中“开票申请 OrgBankAccountId 为必填”的表述已过时，以本文为准。
