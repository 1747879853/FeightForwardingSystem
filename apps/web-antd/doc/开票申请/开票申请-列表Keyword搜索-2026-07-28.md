# 1. 背景意图 (Background)

开票申请列表原先只能按申请单号、发票号等主表字段筛选，无法直接按开票申请中费用所对应业务的**主提单号**或**委托编号**检索。业务希望在列表中增加一个通用 `Keyword`，用于模糊搜索 `InvoiceApplicationItems` 关联费用所属业务。

# 2. 核心逻辑变更

| 项 | 说明 |
| :-- | :-- |
| 查询入参 | `InvoiceApplicationQueryDto` 新增 `Keyword` |
| 搜索范围 | `InvoiceApplicationItems -> OrderFee -> TransportOrder` |
| 匹配字段 | `TransportOrder.MblNum`、`TransportOrder.CommissionNum` |
| 匹配方式 | `Contains` 模糊匹配 |
| 列表/详情返回 | `mblNums`、`commissionNums`，分别对主提单号/委托编号去重后按空格拼接 |
| 影响接口 | `InvoiceApplicationAdminAppService.GetPagedListAsync` |

# 3. 避坑指南

- `keyword` 查的是**费用对应业务**，不是 `InvoiceApplication` 主表自身字段。
- 一个开票申请下只要**任意一条**费用明细对应业务命中主提单号或委托编号，该开票申请就会被查询出来。
- 该条件与原有 `ApplicationNo`、`InvoiceNo`、`SettlementId` 等条件取交集，同时受数据权限过滤约束。
