# 1. 背景意图 (Background)

对账单（Statement）下可能挂有同一客户的多条应收费用。业务需要一键按对账单生成开票申请，前端只传 `statementId`，后端按费用币别自动拆分成 1~N 张开票申请，每条费用按当前最大剩余可开票额度申请。

# 2. 核心逻辑变更 (Core Logic)

## 2.1 接口

`POST /api/services/app/InvoiceApplicationAdmin/AddByStatementAsync`

**权限**：同时需要 `Admin.InvoiceApplication.Add` 与 `Admin.Statement.Edit`

**入参**：`InvoiceApplicationAddByStatementDto`

| 字段          | 类型   | 说明               |
| :------------ | :----- | :----------------- |
| `statementId` | `Guid` | 对账单Id，唯一入参 |

## 2.2 后端固定生成规则

| 项       | 规则                                                           |
| :------- | :------------------------------------------------------------- |
| 结算对象 | `statement.ClientId`                                           |
| 所属组织 | 对账单 `OrgId`                                                 |
| 状态     | `Entering`                                                     |
| 银行     | `OrgBankAccountId` / `ClientInvoiceBankId` 均不填              |
| 发票类型 | 固定 `p`（普通发票电票）                                       |
| 商品明细 | 空列表                                                         |
| 费用明细 | 按币别自动分组；每条费用 `AppliedAmount = Amount - 已申请额度` |

## 2.3 校验规则

1. 对账单、结算对象存在。
2. 当前用户必须配置 `DefaultOrgId`，且通过 `EnsureUserOwnsOrgAsync`。
3. 对账单下必须有费用。
4. 只允许**应收**费用：若任一费用 `PaySide=付`，报错：`存在应付费用 不可提交开票申请`。
5. 费用不可禁开票：`InvoiceBlocked=true` 报错 `费用不允许开票`。
6. 费用结算对象必须等于对账单客户。
7. 锁内按 `remaining = Amount - Sum(InvoiceApplicationItems.AppliedAmount)` 计算最大可申请额度；若任一费用 `remaining <= 0`，报错 `费用剩余可开票额度不足,可用额度:0`（或对应剩余额度）。

# 3. 避坑指南 (Pitfalls)

- 本接口会**按币别拆单**，所以返回 `List<Guid>`，不是单个 Id。
- 若对账单混入应付费用，会整单失败，不会自动跳过。
- 本接口不自动生成商品明细；后续如需提交审核，前端应进入详情继续补商品明细/银行等信息。
