# TAPD #0314 角色删除占用校验 — 后端修改说明

> **TAPD**：https://www.tapd.cn/61580498/bugtrace/bugs/view/1161580498001000314  
> **处理人**：李飞（后端）  
> **前端结论**：删除请求已正确调用接口，需在服务端拦截「仍被用户引用的角色」删除。

---

## 1. 问题描述

角色已被用户使用时，在 **系统管理 → 角色管理** 仍可删除成功；之后在 **用户管理** 修改该用户角色并保存时报错，无法保存。

## 2. 涉及接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `DELETE` | `/api/services/app/Role/DeleteRoleAsync?Id={id}` | 删除角色（需加占用校验） |
| `PUT` | `/api/services/app/UserAdmin/CreateOrUpdateUser`（或项目内等价用户保存接口） | 用户保存角色时因脏 `roleId` 失败 |

**页面**：`/system/role`、`/system/user`

## 3. 复现路径

1. 在角色管理中创建角色 A，并分配给至少一名用户。
2. 回到角色管理，删除角色 A（当前可删除成功）。
3. 打开已分配该角色的用户，修改角色后保存 → 报错。

## 4. 前端现状（无需改即可验证）

- 删除：`apps/web-antd/src/views/system/role/list.vue` → `deleteRole(row.id)`
- API：`DELETE /services/app/Role/DeleteRoleAsync`，参数 `Id`

前端**无**「角色是否被用户引用」查询接口，无法在删除前可靠拦截。

## 5. 后端修改要求

在 `RoleAppService.DeleteRoleAsync`（或等价实现）中：

1. 删除前查询该角色是否仍关联用户（`UserRole` / 项目内用户-角色关系表）。
2. 若 `count > 0`：**不删除**，抛出用户可读业务异常，建议文案：  
   `该角色已被 {count} 个用户使用，无法删除`
3. 若 `count == 0`：按现有逻辑删除。

可选（非必须）：同步检查角色是否被其他业务实体硬引用。

## 6. 验收标准

| 场景                     | 期望                       |
| ------------------------ | -------------------------- |
| 角色无用户引用           | 删除成功                   |
| 角色仍有用户引用         | 删除失败，返回明确错误信息 |
| 删除失败后               | 用户管理改角色仍可正常保存 |
| 先解除所有用户该角色再删 | 删除成功                   |

## 7. 前端后续（后端完成后）

若错误信息通过 ABP 标准 `error.message` 返回，前端 `deleteRole` 的 `.catch` 会由全局请求拦截展示，一般**无需额外改动**。若需定制文案再单独提需求。
