# 港口前端接口文档（PortCode）

**控制器**：`PortCode`（`PortCodeAppService`，非 Admin）

**说明**：登录即可访问，**无需业务权限**；查询全量港口，不分页。

与 `PortCodeAdmin` 区别：Admin 负责增删改查（带权限、分页）；本服务只读、无权限点、不分页。

---

## 一、获取全部港口列表

### `GET /api/services/app/PortCode/GetListAsync`

**权限**：仅需登录（`[AbpAuthorize]`，无具体权限点）

**入参**：无

**出参**：`List<PortCodeListItemDto>`（JSON 字段为单字母，减小体积）

### `PortCodeListItemDto` 字段

| 字段 | 类型 | 含义 |
|------|------|------|
| `i` | `long` | 主键ID |
| `p` | `string` | 港口英文名称/港口代码（原 portName） |
| `c` | `string` | 港口中文名称（原 cnName） |
| `e` | `string` | 关联国家英文名称（原 countryEnName）；无则为 `null` |

**响应示例：**

```json
[
  { "i": 1, "p": "SHANGHAI", "c": "上海", "e": "China" },
  { "i": 2, "p": "LOS ANGELES", "c": "洛杉矶", "e": "United States" }
]
```

### 业务规则

1. **全量返回**：不分页；ABP 软删除过滤后的全部港口（含启用/禁用）。
2. **关联国家**：通过 `PortCode.CountryId` → `CountryCode`，投影 `CountryEnName` → 字段 `e`。
3. **排序**：`PortName` 升序，再按 `Id` 升序。
4. 查询使用 `AsNoTracking()`。
5. **传输压缩**：Host 已启用 `ResponseCompression`（gzip/brotli）。浏览器请求带 `Accept-Encoding` 时，响应头会出现 `Content-Encoding`；Chrome 里请看 **Transferred**（传输体积），不要只看 Size（解压后体积）。

### 4. 批量数据缓存（Map 方式）

```typescript
import { getPortCodeList } from '#/api/system/base-data/port-code-admin';

// 创建 Map 缓存，便于快速查找
const portMap = new Map<number, {
  id: number;
  portName: string;
  cnName: string;
  country: string | null;
}>();

async function loadPorts() {
  const ports = await getPortCodeList();
  
  ports.forEach(port => {
    portMap.set(port.i, {
      id: port.i,
      portName: port.p,
      cnName: port.c,
      country: port.e,
    });
  });
  
  console.log(`已加载 ${portMap.size} 个港口`);
}

// 根据 ID 获取港口名称
function getPortName(portId: number): string {
  const port = portMap.get(portId);
  return port ? `${port.cnName}(${port.portName})` : '-';
}
```

### 5. 与 PortCodeAdmin 接口的对比

| 特性 | PortCode（本文档） | PortCodeAdmin |
|------|-------------------|---------------|
| **接口路径** | `/services/app/PortCode/GetListAsync` | `/services/app/PortCodeAdmin/GetPagedListAsync` |
| **权限要求** | 仅需登录 | 需要业务权限 |
| **分页** | ❌ 不分页，全量返回 | ✅ 支持分页 |
| **字段命名** | 单字母（i, p, c, e） | 完整字段名（id, portName, cnName...） |
| **适用场景** | 下拉框选项、数据字典 | 管理后台 CRUD |
| **性能优化** | 传输压缩 + 精简字段 | 分页查询 |

### 6. 注意事项

⚠️ **重要提示**：

1. **字段映射**：新接口使用单字母字段，注意映射关系：
   - `i` → `id`（港口ID）
   - `p` → `portName`（港口英文名）
   - `c` → `cnName`（港口中文名）
   - `e` → `countryEnName`（国家英文名）

2. **数据类型**：
   - `i` 是 `number` 类型（后端是 `long`）
   - `e` 可能为 `null`（当港口没有关联国家时）

3. **性能考虑**：
   - 虽然接口返回全量数据，但已启用 gzip/brotli 压缩
   - 建议在页面初始化时一次性加载并缓存
   - 对于超大数量级的港口数据，考虑使用 `PortCodeAdmin` 的分页接口

4. **搜索过滤**：
   - 接口本身不支持关键字搜索
   - 如需搜索，建议在前端对返回结果进行过滤
   ```typescript
   const filteredPorts = ports.filter(port => 
     port.p.toLowerCase().includes(keyword.toLowerCase()) ||
     port.c.includes(keyword)
   );
   ```

## 三、常见问题

### Q1: 为什么不直接使用 PortCodeAdmin 的分页接口？

**A**: `PortCode` 接口专为以下场景优化：
- 下拉框选项加载（需要全量数据）
- 数据字典缓存（避免多次请求）
- 无需权限控制的只读场景

如果需要管理功能（增删改查），请使用 `PortCodeAdmin` 接口。

### Q2: 单字母字段会不会影响可读性？

**A**: 单字母字段仅用于网络传输，前端接收到数据后可以立即转换为易读的格式：
```typescript
const readablePorts = ports.map(p => ({
  id: p.i,
  name: p.p,
  chineseName: p.c,
  country: p.e,
}));
```

### Q3: 如何处理端口没有关联国家的情况？

**A**: 字段 `e` 可能为 `null`，使用时需要做空值判断：
```typescript
const displayText = port.e ? `${port.c}(${port.p}) - ${port.e}` : `${port.c}(${port.p})`;
```
