# 海运出口运价模块（SeFreiPrice）逻辑全景文档

> 本文档面向前端、后端、测试和AI Agent，旨在描述运价模块的核心数据结构、业务规则、易踩坑点和注意事项。AI Agent 在修改本模块代码前应先通读此文档，减少重复阅读代码的频率。 **最后更新**：2026-09-30

---

## 一、模块概述

运价模块管理海运出口的运价数据。一条运价记录描述了 "某船公司 + 起运港 → 目的港" 的一套运费价格方案，包含多种箱型的成本价和指导价、多种附加费用、有效期、开船日/截单日等信息。

**核心业务场景**：运营人员维护运价 → 业务员/客户查询运价 → 用于订舱报价。

## 二、数据结构与表关系

### 2.1 表关系图（文本版）

```
SeFreiPrice（运价主表）
├── BookingAgent → Client（订舱代理，可空，Guid FK）
├── Carrier（船公司，long FK）
├── POL → PortCode（起运港）
├── POD → PortCode（目的港）→ Lane（航线）+ Country（国家）
├── POT1 → PortCode?（中转港1，可空）
├── POT2 → PortCode?（中转港2，可空）
├── Currency（币别）
├── SeFreiPriceCtn[]（运价箱型，1:N）
│   └── CtnCode（箱型代码）
├── SeFreiPriceFee[]（运价费用，1:N）
│   ├── FeeCode（费用代码）
│   ├── Currency（费用币别）
│   └── SeFreiPriceCtnFee[]（箱型费用交叉表，仅 PriceFeeType==Ctn 时有值）
├── SeFreiPriceDay[]（关联日，1:N，0到多条）
└── SeFreiPriceWeekDay[]（关联周几，1:N，0到多条）
```

## 四、核心业务规则

### 4.1 费用计费方式（PriceFeeType）—— 最复杂的逻辑

每条费用（SeFreiPriceFee）有两种计费模式：

| PriceFeeType | Price | SeFreiPriceCtnFees | 业务含义 |
| --- | --- | --- | --- |
| Ctn (0) | **必须为空** | 按需填写各箱型价格 | 按集装箱计费：不同箱型不同价格 |
| Order (1) | **必须有值** | **禁止有值** | 按票计费：固定一个价格 |

**坑点清单**：

- 前端切换 PriceFeeType 时必须同步清除/禁用对应字段
- 后端有严格校验：Ctn 模式下传了 Price 会报错，Order 模式下传了 CtnFees 也会报错
- 新建用 `ValidatePriceFeeType`，编辑用 `ValidatePriceFeeTypeEdit`（参数类型不同：AddDto vs EditDto 的 CtnFees 列表类型不同）

### 4.2 箱型费用交叉表（SeFreiPriceCtnFee）—— 映射逻辑

**关键机制**：前端通过 `CtnCodeId`（long）关联箱型，后端在保存后将其映射为 `SeFreiPriceCtnId`（Guid）。

```
前端传入：{ ctnCodeId: 1, price: 500 }
后端映射：ctnCodeIdToCtnIdMap[1] → SeFreiPriceCtnId = "guid-xxx"
数据库存：{ SeFreiPriceCtnId: "guid-xxx", SeFreiPriceFeeId: "guid-yyy", Price: 500 }
```

**坑点**：

- 新建时：先 InsertAndGetId 主表 → SaveChanges → 再用 entity.SeFreiPriceCtns 获取映射
- 编辑时：先处理箱型增删改 → SaveChanges → 再从数据库查询最新映射
- 如果 CtnCodeId 在箱型列表中找不到，抛异常 "箱型费用中的箱型CtnCodeId={id}在箱型列表中不存在"

### 4.3 子表编辑策略

| 子表 | 新增时 | 编辑时 | 删除主表时 |
| --- | --- | --- | --- |
| SeFreiPriceCtn（箱型） | 随主表创建 | 增删改（id 有值=改，null=增，不在列表=删） | 级联删除 |
| SeFreiPriceFee（费用） | 随主表创建 | 增删改（同上） | 级联删除 |
| SeFreiPriceCtnFee（箱型费用） | SaveChanges 后创建 | 增删改（同上） | 级联删除 |
| SeFreiPriceDay（关联日） | 随主表创建 | **删除重建** | 级联删除 |
| SeFreiPriceWeekDay（关联周几） | 随主表创建 | **删除重建** | 级联删除 |

**坑点**：

- 关联日和关联周几是删除重建，不是增删改。编辑时不需要传 id
- 删除箱型时必须先删除关联的箱型费用（SeFreiPriceCtnFee），否则外键约束失败
- 删除费用时也必须先删除关联的箱型费用
- 处理顺序很关键：箱型和费用 → SaveChanges → 再处理箱型费用交叉表

### 4.4 订舱代理（BookingAgentId）

- 关联 Client 表，类型 Guid?，可空
- 校验规则：有值时检查客户是否存在 + 行业类别（IndustryCategories）必须包含 `"o"`（订舱代理）
- 新建/编辑（AddAsync、EditAsync、BatchAddSimpleAsync、BatchEditSimpleAsync）：用户传什么就存什么（包括 null 表示清空）
- 批量编辑（BatchEditAsync）：null 不修改，有值时校验后赋值
- 列表/详情返回 `BookingAgent`（`ClientSimpleDto`，含客户简称等简要信息）

### 4.5 批量编辑（BatchEditAsync）的特殊逻辑

与单条编辑不同，批量编辑的字段更新是**选择性的**：

- 值类型字段（long?、bool?、int? 等）：为 null 不修改，有值才更新
- 字符串字段：空字符串不修改，有内容才更新
- BookingAgentId：通过 `UpdateBookingAgent` 标志控制
- 子表（箱型/费用/关联日/关联周几）：为 null 不修改，不为 null 时执行各自的更新逻辑
- 批量编辑的费用处理逻辑：按 FeeCodeId 匹配已有费用，存在则复用，不存在则新建

### 4.6 有效期与重复运价失效

生效状态按自然日比较，忽略时分秒。和列表筛选 `IsValid` 同一套口径：

| 值  | 状态   | 条件                                                     |
| --- | ------ | -------------------------------------------------------- |
| 0   | 已生效 | 有效期起的日期 ≤ 今天 ≤ 有效期止的日期（止日当天仍有效） |
| 1   | 未生效 | 今天 < 有效期起的日期                                    |
| 2   | 已过期 | 其余情况（今天已过有效期止，且今天不早于有效期起）       |

详情和列表行上的布尔 `IsValid` 只表示「已生效」。它不是数据库字段，在 `MapToOutDto` 里计算。

**新增时冲掉同航线的未失效运价**（`AddAsync`、`BatchAddSimpleAsync`）：

库里已经有**未生效或已生效**的运价，并且下面六列与本次新增完全相同，就把那些旧记录改成失效。已过期的不动。编辑不走这条规则。

比对列：船公司、起运港、目的港、是否直达、中转港1、中转港2。中转港为空和为空算相同，空和有值不算相同。订舱代理、约号、币别、航程、船名航次不参与比对。

对每一条命中的旧记录：

1. 有效期起、有效期止都写成 `2000-01-01`（当天 0 点）。之后按上面的口径就是已过期。
2. 把改之前的有效期换行追加到备注末尾。原备注为空时不另起一个空行，直接写这一句：

```
运价重复 已设置为失效状态 设置前有效期起yyyy年MM月dd日 有效期止yyyy年MM月dd日
```

月、日补零，例如 `2026年09月01日`。只改有效期起、止和备注，不调用整行更新。

同一批简单新增里，每插入一条就落库（仍在同一事务里）。后一条会把本批中已经写入、并且仍是未生效或已生效的前一条，按同样规则置失效。本批中途失败则整批回滚，旧运价的有效期和备注都不会被改掉。

### 4.7 列表箱型涨跌

只在 `GetPagedListAsync` 上计算，写在每条 `SeFreiPriceCtns` 的 `costDelta`、`sugDelta` 上。详情这两个字段为 null。没有上一条、箱型对不上、或差额为 0 时，对应字段为 null。

**上一条**按全库找，不套当前列表的筛选和分页。软删和租户范围与列表查询相同（走仓储 `GetAll`）。

同一航线必须下面五列全部相等。中转港 1 空和空算相等，空和有值不算。中转港 2、币别、订舱代理不参与。这和 4.6 冲掉重复运价的六列不是同一套键（4.6 含中转港 2）。

| 列        | 说明     |
| --------- | -------- |
| CarrierId | 船公司   |
| POLId     | 起运港   |
| PODId     | 目的港   |
| IsDirect  | 是否直达 |
| POT1Id    | 中转港 1 |

在同航线、且不是当前行自己的记录里，只保留**有效截止日的日期**严格早于当前行截止日日期的。时分秒不参与比较：3 月 31 日 08:00 和 3 月 31 日 18:00 算同一天，互不为上一条；3 月 30 日 23:59 早于 3 月 31 日 00:01。取截止日期最大的一条。同一天有多条时，取创建时间较晚的，创建时间再相同取 Id 较大的。当前行截止日是默认值，或没有更早的截止日时，没有上一条。

箱型对齐：先按 `CtnCodeId`，对不上再用箱型名称 `CtnName`。差额 = 现价 − 上一条。涨为正，跌为负。

| 字段      | 何时为 null                                          |
| --------- | ---------------------------------------------------- |
| costDelta | 没有上一条、箱型对不上，或差额为 0                   |
| sugDelta  | 没有上一条、箱型对不上、差额为 0，或任一侧没填指导价 |

本页只多两次查询：一次查出这些航线里截止日早于本页最大截止日的运价头，一次查出命中的上一条的箱型。不按行再查列表。

## 五、坑点汇总

### 5.1 后端坑点

| # | 坑点 | 影响范围 | 说明 |
| --- | --- | --- | --- |
| B1 | 箱型费用需要 SaveChanges 后才能获取映射 | AddAsync, EditAsync | 新建时先 InsertAndGetId → SaveChanges → 才能拿到 ctnCodeIdToCtnIdMap |
| B2 | 编辑子表处理顺序 | EditAsync | 必须先处理箱型和费用 → SaveChanges → 再处理交叉表 |
| B3 | 删除顺序有外键依赖 | DeleteAsync, EditAsync | 必须先删 CtnFee → 再删 Ctn 和 Fee → 最后删主表 |
| B4 | ValidateForeignKeysAsync 是可选参数 | 所有新建/编辑 | bookingAgentId 是默认参数 null，旧调用不受影响 |
| B5 | BookingAgentId 在不同接口语义不同 | Add/Edit vs BatchEdit | 新建/编辑直接赋值（含null），批量编辑 null=不修改、有值=赋值 |
| B6 | PriceFeeType 校验方法有两套 | AddAsync vs EditAsync | ValidatePriceFeeType 和 ValidatePriceFeeTypeEdit 参数类型不同（AddDto vs EditDto 的 CtnFees 类型） |
| B7 | 批量编辑费用的 CtnFee 跳过逻辑 | BatchEditAsync | 该箱型若找不到匹配的运价箱型会 continue 跳过（不报错），单条编辑则抛异常 |
| B8 | 关联日/关联周几是删除重建 | EditAsync, BatchEditAsync, BatchEditSimpleAsync | 不要用增删改逻辑处理，编辑时前端不需要传 id |
| B9 | Include 链式加载导航属性 | GetPagedListAsync, DetailAsync | 新增外键时需同步添加 .Include()，否则导航属性为 null |

### 5.2 前端坑点

| # | 坑点 | 影响范围 | 说明 |
| --- | --- | --- | --- |
| F1 | PriceFeeType 切换时清除数据 | 费用表单 | Ctn→Order：清空 seFreiPriceCtnFees，显示 price。Order→Ctn：清空 price，显示箱型费用区域 |
| F2 | CtnFee 使用 CtnCodeId 不是 CtnId | 新建/编辑费用表单 | 箱型费用通过 CtnCodeId（long）关联，不是 SeFreiPriceCtnId（Guid） |
| F3 | 编辑时子表 id 判断 | 编辑表单 | id 有值=修改已有，id 为 null=新增，前端删除某项时不要传该项（后端按差集删除） |
| F4 | 批量编辑 null 语义 | 批量编辑表单 | null=不修改，有值=统一修改 |
| F5 | 关联日/关联周几编辑不传 id | 编辑表单 | 这两个子表是删除重建，传 id 无意义 |
| F6 | 箱型重复校验 | 新建/编辑表单 | 同一运价下不可添加重复的 CtnCodeId，后端会校验 |
| F7 | BookingAgentId 是 Guid 类型 | 订舱代理选择器 | 与 CarrierId (long) 不同，注意类型一致性 |
| F8 | 有效期影响 IsValid | 列表展示 | IsValid 是后端计算的，不要前端自己算（时区差异） |
| F9 | 列表涨跌读箱型上的 `costDelta`、`sugDelta` | 运价列表 | 不要再按航线补拉 `GetPagedListAsync`。字段为 null 时不展示角标。详情这两个字段为 null |
