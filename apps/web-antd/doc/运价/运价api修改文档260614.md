# 运价API修改文档

**修改时间**：2026-06-14

---

## 修改概述

1. `SeFreiPriceAdminAppService.GetPagedListAsync`（运价列表）的查询参数 `IsValid` 由 `bool?` 调整为 `List<int>`，以支持按**三种生效状态多选**进行筛选：已生效、未生效、已过期。原有的“是否有效”二值（true/false）已无法表达“未生效”和“已过期”的区别，本次改造将其改为支持多选的状态集合（满足任一即命中）。
2. 新增特殊排序：当 `Sorting` 入参为 `id desc` 时，按**生效状态**排序（已生效在前、未生效居中、已过期在后），再依次按**起运港id**、**目的港id** 升序排列。
3. 列表接口请求方式由 `HttpGet`（参数 `[FromQuery]`）改为 `HttpPost`（参数 `[FromBody]`，JSON 请求体），因查询字段过多，置于 Body 更便于前端组织参数与传递数组型字段。

> 取值约定：不传/空=不按生效状态筛选；`0`=已生效；`1`=未生效；`2`=已过期；可同时传多个（满足任一即命中）。判断依据为当前服务器时间与主表 `ValidTimeStart`（有效时间起）/ `ValidTimeEnd`（有效时间止）的比较。

无。本次仅调整查询入参类型、筛选逻辑与排序逻辑，未改动任何实体/表结构。

## 二、DTO变更

### 查询DTO（SeFreiPriceQueryDto）字段变更

| 字段 | 原类型 | 新类型 | 说明 |
| --- | --- | --- | --- |
| IsValid | bool? | List&lt;int&gt; | 生效状态，**支持多选**，满足任一即命中。不传/空=不筛选；`0`=已生效；`1`=未生效；`2`=已过期 |

生效状态取值含义：

| 取值        | 含义             | 时间判断条件                               |
| ----------- | ---------------- | ------------------------------------------ |
| 不传/空集合 | 不按生效状态筛选 | —                                          |
| 0           | 已生效           | ValidTimeStart <= 当前时间 <= ValidTimeEnd |
| 1           | 未生效           | 当前时间 < ValidTimeStart                  |
| 2           | 已过期           | 当前时间 > ValidTimeEnd                    |

> 输出DTO（SeFreiPriceOutDto）中的 `IsValid`（bool，表示当前是否已生效）保持不变，本次不涉及。

## 三、AppService 接口变更

### GetPagedListAsync（运价列表）

#### 0. 请求方式变更

由 `HttpGet` + `[FromQuery]` 改为 `HttpPost` + `[FromBody]`：

变更前：

```
[HttpGet]
public async Task<PagedList<SeFreiPriceOutDto>> GetPagedListAsync([FromQuery] SeFreiPriceQueryDto input)
```

变更后：

```
[HttpPost]
public async Task<PagedList<SeFreiPriceOutDto>> GetPagedListAsync([FromBody] SeFreiPriceQueryDto input)
```

#### 1. 生效状态筛选

将原有的两条 `WhereIf` 二值筛选条件替换为三态筛选条件：

变更前：

```
.WhereIf(input.IsValid == true, m => m.ValidTimeStart <= now && now <= m.ValidTimeEnd)
.WhereIf(input.IsValid == false, m => m.ValidTimeStart > now || now > m.ValidTimeEnd)
```

变更后（多选，按计算出的状态值判断是否在所选集合内）：

```
.WhereIf(input.IsValid != null && input.IsValid.Any(),
    m => input.IsValid.Contains(m.ValidTimeStart <= now && now <= m.ValidTimeEnd ? 0
        : (now < m.ValidTimeStart ? 1 : 2)))
```

#### 2. 特殊排序（id desc）

当 `Sorting` 入参为 `id desc`（不区分大小写）时，使用自定义排序：生效状态（已生效=0、未生效=1、已过期=2）升序 → 起运港id 升序 → 目的港id 升序；其余排序值仍走原动态排序逻辑。

变更前：

```
query = query.OrderBy(input.Sorting);
```

变更后：

```
if (!string.IsNullOrWhiteSpace(input.Sorting)
    && input.Sorting.Trim().Equals("id desc", StringComparison.OrdinalIgnoreCase))
{
    query = query
        .OrderBy(m => m.ValidTimeStart <= now && now <= m.ValidTimeEnd ? 0
            : (now < m.ValidTimeStart ? 1 : 2))
        .ThenBy(m => m.POLId)
        .ThenBy(m => m.PODId);
}
else
{
    query = query.OrderBy(input.Sorting);
}
```

其余逻辑（分页、导航属性批量加载、船公司Logo、输出映射）均无变化。

## 五、前端对接注意事项

1. **接口请求方式已由 GET 改为 POST**，参数改为 JSON 请求体（`Content-Type: application/json`），原 query string 调用方式不再适用，前端需改为在 body 中提交参数对象。
2. 列表“生效状态”筛选项使用**多选**下拉/复选：已生效=`0`、未生效=`1`、已过期=`2`，可同时选中多个（满足任一即命中）。Body 中形如 `"IsValid": [0, 1]`，无需再处理 query 数组序列化。
3. `IsValid` 仍为可选参数，不传/空集合即不按生效状态筛选，但**原先传 `true`/`false` 的调用方式不再兼容**，需改为传整数数组。
4. 若需要“已生效在前、未生效居中、已过期在后”的默认排序，将 `Sorting` 传 `id desc` 即可（后端会自动套用三段排序：生效状态 → 起运港id → 目的港id）。
5. 生效状态以服务器当前时间为准实时计算，不持久化存储。
