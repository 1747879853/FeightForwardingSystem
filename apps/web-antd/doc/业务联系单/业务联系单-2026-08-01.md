# 1. 背景意图 (Background)

业务联系单列表/分组此前使用基类通用 `DataPermissionFilterAsync`，仅按所属人 `UserId`、所属组织 `OrgId` 过滤，干系人无法看到自己参与的单据。需与海运出口 `SeaExportListDataPermissionFilterAsync` 对齐：独立方法 + 干系人可见。

# 2. 核心逻辑变更 (Core Logic)

涉及文件：

- `src/CsprojBuilder.Application/App/PreOrder/PreOrderAdminAppService.cs`

## 2.1 新增独立方法 `PreOrderListDataPermissionFilterAsync`

与 `SeaExportListDataPermissionFilterAsync` 同构：

1. 调用 `GetDataPermissionUserIdsAsync`；若 `AllowAll` 则不过滤。
2. 独立子查询 `PreOrderUser`（避免主查询 JOIN），角色范围与海运出口一致：销售/商务/操作/客服/单证/海外客服/航线。
3. 可见条件（任一命中）：
   - 所属人 `UserId` 在数据权限用户内
   - 创建人 `CreatorUserId` 在数据权限用户内
   - 所属组织 `OrgId` 在组织权限内
   - 干系人 `PreOrderUser.UserId` 在数据权限用户内
4. 仅解析出一个用户 id 时用 `==` 替代 `Contains`，避免 SQL `IN` 子查询性能问题。

## 2.2 调用点替换

- `GetPagedListAsync`、`GetGroupedListAsync`：`DataPermissionFilterAsync` → `PreOrderListDataPermissionFilterAsync`。
- `SetDataPermissionPropsAsync` 仍只负责填充展示用 `Orgs`，逻辑不变。

# 3. 避坑指南 (Pitfalls)

- **干系人角色白名单**：仅上述 7 种 `UserAttribute` 参与列表可见性；其他属性即使挂在 `PreOrderUser` 也不放开数据权限。
- **详情未套该过滤**：`DetailAsync` 仍按 id 直查；若需详情也做同口径校验，需另加。
- **与基类通用过滤差异**：通用 `DataPermissionFilterAsync` 不含创建人、不含干系人；本模块勿再回退到基类方法。
