# 背景意图

`ExtractSeaExportToAddDtoAsync` 原先只回填起运港/目的港 Id（`pOLId`/`pODId`），前端新建海运出口时还需要港口备注字段。备注应取自港口主数据，而不是 OCR 原始文本。

# 核心逻辑变更

1. 新增 `ResolvePortAsync`：在原有港口匹配逻辑上，命中后一并查出 `PortCode.PortName` 与关联 `Country.CountryEnName`。
2. 新增 `BuildPortRemark`：按 `PortName, CountryEnName` 组装备注（如 `QINGDAO, CHINA`）。
3. `ExtractSeaExportToAddDtoAsync` 对起运港、目的港赋值：
   - `POLId` / `POLRemark`
   - `PODId` / `PODRemark`
4. 签单地点、交货地仍只回填 Id，不回填备注。

# 避坑指南

- 港口匹配失败时，`pOLRemark`/`pODRemark` 同步为空，不要用抽取原文硬填。
- 备注来源是**库内港口主数据**，与抽取文本大小写/空格差异无关。
- 海运出口新建校验备注长度 ≤ 128，超长主数据理论上极少见，前端仍应按新建接口规则校验。
