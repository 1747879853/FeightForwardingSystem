# 1. 说明

码头船舶计划只需对接 **一个接口**，调 **一次**：传业务单Id，拿回该船在起运港的作业计划列表。

船名、航次、起运港代码、进出口标识**全部由后端从业务单自己取**，前端一个都不用传。token、中转站等前端也无需关心。

> [!IMPORTANT] **这是纯查询接口，不会改任何数据。** 后端不回填业务单。用户从返回的列表里选中一条后，由**前端把值填到表单上**，再走海运出口/海运进口原有的编辑保存接口落库。

> [!IMPORTANT] **航次有两个字段，别搞混。** 海运出口/进口上：
>
> - `innerVoyno`「航次」= **船公司航次**
> - `terminalVoyno`「码头航次」= **港区航次**（新增字段）
>
> 本接口查的是**码头航次**。业务单只填了船公司航次时，后端会自动调飞驼换算一次；返回条目里的 `evoyage`/`ivoyage` 也都是码头航次，填表时要填到「码头航次」而不是「航次」。

# 2. 接口

| 项目     | 内容                                                             |
| :------- | :--------------------------------------------------------------- |
| 方法     | `POST`                                                           |
| 地址     | `/api/services/app/FeituoAdmin/QueryTerminalScheduleAsync`       |
| 请求体   | JSON，见第 3 节                                                  |
| 返回     | JSON，见第 4 节（ABP 统一包一层 `result`）                       |
| 权限     | 需登录且具备「第三方接口 > 查询」权限（`Admin.ExternalApi.Get`） |
| 适用业务 | 仅 **海运出口** 与 **海运进口**；空运出口会报错                  |

# 3. 请求参数

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| transportOrderId | Guid | 是 | 业务单Id（海运出口/海运进口的Id，与业务表Id同值） |

```json
{
  "transportOrderId": "3fa85f64-5717-4562-b3fc-2c963f66afa6"
}
```

# 4. 返回结构

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| transportOrderId | Guid | 业务单Id |
| bizType | int | 业务类型：`0` 海运出口、`1` 海运进口 |
| vessel | string | 本次查询用的船名（后端从业务单取的，可回显给用户确认） |
| portCode | string | 本次查询用的港口代码（业务单起运港的EDI代码，已转大写） |
| portName | string | 本次查询用的起运港名称 |
| innerVoyno | string | 业务单上的**船公司航次**（字段名与业务单一致） |
| terminalVoyno | string | 本次**尝试**用来过滤的**码头航次**（字段名与业务单一致）。优先取业务单的码头航次；为空且船公司航次有值时是换算结果；两者都为空时为 `null`。**注意它只是"尝试用的"**，是否真的按它过滤看 `filteredByTerminalVoyno` |
| terminalVoynoConverted | bool | `true` = 上面的 `terminalVoyno` 是由船公司航次**换算**出来的（业务单码头航次原本为空）。可以提示用户把它补录到业务单的「码头航次」上 |
| filteredByTerminalVoyno | bool | `items` 是否按码头航次过滤过。`false` = 返回的是该船在该港的**全部挂靠计划**（可能含多个航次），必须让用户自行核对、**别默认取第一条** |
| isExport | string | **最终那次请求**实际带的进出口标识：`E` 出口、`I` 进口。跟着航次走，退化成"不带航次查全部"时为 `null`。判业务类型请用 `bizType`，不要用这个字段 |
| items | 数组 | 飞驼返回的**全部**条目，见 4.1。无数据时为空数组（不是 `null`） |
| message | string | 提示信息，可直接弹给用户。两种情况有值：完全没查到、以及"未匹配到码头航次已返回全部挂靠计划"；按码头航次正常查到时为 `null` |

## 4.1 items[] 一条码头船舶计划

全部是飞驼原样字段。**所有时间都是字符串**（`yyyy-MM-dd HH:mm:ss`），飞驼没数据时为 `null`。

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| status | string | 船期状态，**仅上海港提供**：预报 / 确报 / 在港 / 离港 / 取消 |
| vesselNameEn | string | 船舶英文名 |
| vesselNameCn | string | 船舶中文名 |
| shipCode | string | 船公司代码 |
| shipName | string | 船公司中文名 |
| agentCode | string | 船代代码 |
| agentName | string | 船代名称 |
| lineCode | string | 航线代码 |
| terminal | string | 码头 |
| portsEn | string | 挂靠港英文，**以 `+` 分隔的长字符串** |
| portsCn | string | 挂靠港中文，同上 |
| eta | string | 计划抵达(抵锚)——**抵达起运港**，不是预抵目的港 |
| ata | string | 实际抵达(抵锚)——同样是抵达起运港 |
| etb | string | 计划靠泊 |
| atb | string | 实际靠泊 |
| etd | string | 计划离港 |
| atd | string | 实际离港 |

| cyClosing | string | 截港时间 |

# 5. 建议的交互流程

1. 用户在海运出口/海运进口单据上点「查码头船舶计划」，调本接口，只传 `transportOrderId`。
2. `items.length === 0` → 弹 `message` 提示，结束。
3. `items` 有数据 → 弹窗展示列表让用户选一条。建议展示列：船名、出口/进口航次、码头、船期状态、计划离港、开港、截港、截单、截关。可以把 `vessel` / `terminalVoyno` / `portName` 回显在弹窗标题上，让用户知道是按什么条件查的。
4. **`filteredByTerminalVoyno === false` 时要显著提示。** 说明这批数据**没有按航次过滤**，是该船在该港的全部挂靠计划、可能含多个航次；把 `message` 显示出来，让用户自己认哪一条是自己那票。**绝对不要在这种情况下默认选中或自动填第一条。**
5. 用户选中一条 → **前端把对应值填到表单字段上**，用户确认后走原有的编辑保存接口落库。

## 5.0 后端的两趟查询（前端只调一次）

前端只调一次接口，后端内部可能查两趟：

| 情况 | 后端行为 | 返回 |
| :-- | :-- | :-- |
| 有码头航次且按它查到了 | 只查一趟 | `filteredByTerminalVoyno=true`，`message=null` |
| 有码头航次但按它查不到 | 自动去掉航次+进出口标识**重查一次**，以重查结果为准 | `filteredByTerminalVoyno=false`，`message` 说明「未匹配到码头航次…」 |
| 本来就没有码头航次 | 直接不带航次查 | `filteredByTerminalVoyno=false`，`message=null`（有数据时） |

也就是说 **`items` 有数据但 `filteredByTerminalVoyno=false` 是常见情况**，不是异常，务必按第 4 步处理。

## 5.1 字段填表对应关系

选中某条后，建议按下表往表单里填。**这些都由前端决定填不填、填哪些**，后端不做任何写入。

| 飞驼字段 | 海运出口表单字段 | 海运进口表单字段 |
| :-- | :-- | :-- |
| atd 实际离港 | 实际开船日期 | 实际开船日期 |
| evoyage / ivoyage | **码头航次** `terminalVoyno`（用 `evoyage`） | **码头航次** `terminalVoyno`（用 `ivoyage`） |
| cyClosing 截港时间 | 截港日期 | — |
| portCloseDate 截单时间 | 截单日期 | — |
| customsCloseDate 截关时间 | 截关日期 | — |

海运进口没有截港/截单/截关字段，能对上的只有实际开船日期与航次。

> [!WARNING] **`etd`（计划离港）不建议自动填开船日期，`eta`/`ata` 更不能填预抵日期。** 开船日期由操作自行维护；`eta`/`ata` 是"船抵达**起运港**(抵锚)"，比开船还早，和"预抵目的港"完全不是一回事，拿它去算箱使、转站等日期会全错。

# 6. 前端注意事项

- **这个接口不写库。** 调完不需要刷新单据；真正落库发生在用户确认、走编辑保存之后。
- **`items` 可能有多条。** 同一船名+港口会有多个航次或多次挂靠，后端不做取舍，必须让用户选，别默认取第一条。`filteredByTerminalVoyno=false` 时更要注意，那批数据连航次都没过滤。
- **`eta`/`ata` 不是预抵目的港。** 展示文案要写清"抵达起运港"，别标成"预抵"。
- **别拿 `isExport` 判进出口。** 它只反映"本次请求实际带了什么"，没航次时是 `null`。要判业务类型用 `bizType`（`0` 海运出口、`1` 海运进口）。
- **返回 0 条说明这条船在这个港真的查不到。** 因为按码头航次查不到时后端已经自动去掉航次重查过一遍了，所以 `items` 为空时不是航次的问题，而是船名或港口对不上（船名拼写、或该港区不在覆盖范围内）。
- **`terminalVoynoConverted=true` 时建议提示用户补录。** 说明这次的码头航次是后端从船公司航次换算出来的、业务单上还没存。可以提示"已自动识别码头航次 xxx，是否补录到单据"，避免每次查询都要重新换算。
- **所有时间都是字符串**，要排序或做日期计算得自己转。
- **`portsEn`/`portsCn` 是以 `+` 分隔的长串**，需要的话自己 split 成标签展示。
- **`status` 只有上海港有值**，其它港口是 `null`，别做成必显示列。
- **常见报错**（HTTP 500，按 `success` 判断，原文在 `error.message`）：
  - `请提供业务单Id`
  - `未找到指定的业务单`
  - `码头船舶计划仅支持海运出口与海运进口`
  - `该业务单未填写船名，无法查询码头船舶计划`
  - `该业务单未选择起运港，无法查询码头船舶计划`
  - `起运港[xxx]未维护EDI代码，无法查询码头船舶计划` —— 需去基础资料补 EDI 代码
- **海运进口经常查不到。** 进口按起运港查，而起运港多是国外港口，飞驼的码头船舶计划以国内港区为主，返回空是正常现象，不是 bug。
