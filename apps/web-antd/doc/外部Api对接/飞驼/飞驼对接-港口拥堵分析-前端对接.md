# 1. 说明

港口拥堵分析只需对接 **一个接口**。token 获取、中转站等均由后端处理，前端无需关心。

数据是**实时查飞驼**的，后端不落库，因此不存在"要先订阅"这类前置动作，传港口CODE 直接查即可。

# 2. 接口

| 项目   | 内容                                                             |
| :----- | :--------------------------------------------------------------- |
| 方法   | `POST`                                                           |
| 地址   | `/api/services/app/FeituoAdmin/QueryPortCongestionAsync`         |
| 请求体 | JSON，见第 3 节                                                  |
| 返回   | JSON，见第 4 节（ABP 统一包一层 `result`）                       |
| 权限   | 需登录且具备「第三方接口 > 查询」权限（`Admin.ExternalApi.Get`） |

# 3. 请求参数

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| portCode | string | 是 | 港口CODE（五字码），后端自动 Trim 并转大写，如 `CNNGB`、`USLAX` |
| includeMmsi | bool | 否 | 是否返回船舶明细（MMSI 列表），默认 `false` |

**请求示例：**

```json
{
  "portCode": "CNNGB",
  "includeMmsi": false
}
```

> [!WARNING] **`includeMmsi` 不要随便开。** 一个大港一天的在港船就上百条 MMSI，三个数组加起来响应体会膨胀好几倍。只在确实要展示船舶明细的页面才传 `true`。

# 4. 返回结构

`result` 的顶层是港口信息，`rows` 是**按天**的拥堵情况，最近 15 天、每天一条。

| 字段      | 类型   | 说明                 |
| :-------- | :----- | :------------------- |
| portCode  | string | 港口CODE             |
| lon / lat | string | 港口经纬度（字符串） |
| rows      | 数组   | 每天一条，见 4.1     |

## 4.1 rows[] 每天的拥堵情况

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| key | string | 汇总日期 `yyyy-MM-dd` |
| ataVesselCount | int? | 在港总船数 |
| atbVesselCount | int? | 靠泊总船数 |
| atdVesselCount | int? | 离港总船数 |
| avgAtbA | decimal? | 平均候泊时长，**单位小时** |
| avgAtbD | decimal? | 平均作业时长，**单位小时** |
| avgAtd | decimal? | 平均在港时长，**单位小时** |
| portStatus | string | 拥堵状态：`A` 正常、`B` 轻微拥堵、`C` 中度拥堵、`D` 严重拥堵 |
| portStatusDetails | string | 拥堵原因分析（中文，整段自然语言） |
| portStatusDetailsEn | string | 拥堵原因分析（英文） |
| portWeather | string | 天气影响：`A` 正常、`B` 轻微影响、`C` 中度影响、`D` 严重影响 |
| portWeatherDetails | 对象 | 天气详情，见 4.2 |
| ataVessels | string[] | 在港船舶 MMSI，**仅 `includeMmsi=true` 时返回** |
| atbVessels | string[] | 在泊船舶 MMSI，同上 |
| atdVessels | string[] | 离港船舶 MMSI，同上 |

## 4.2 portWeatherDetails 天气详情

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| weatherType | string | 天气类型：`SUNNY_DAY` 晴(白天)、`SUNNY_NIGHT` 晴(夜间)、`CLOUDY_DAY` 多云(白天)、`CLOUDY_NIGHT` 多云(夜间)、`OVERCAST` 阴、`WINDY` 大风、`HAZE` 雾霾、`RAINY` 雨、`SNOWY` 雪 |
| weatherLevel | string | 天气级别（飞驼内部使用）：`NORM` / `MILD` / `MODERATE` / `SEVERE` |
| portWeatherDetails | string | 天气现象原因（中文），如「能见度为456.0米」 |
| portWeatherDetailsEn | string | 天气现象原因（英文） |
| visibility | string | 能见度，单位米 |
| temperature | string | 实时气温，单位 ℃ |
| humidity | string | 空气相对湿度，单位 % |
| atmosphericPressure | string | 大气压强，单位 Pa |
| rainfall | string | 小时降水量，单位 mm |
| wind | 对象 | `direction` 风向角度(度)、`speed` 风速(m/s)、`power` 风力等级 |
| date | string | 观测时间 |
| portCode / lat / lon | string | 与顶层重复，飞驼原样返回 |

# 5. 前端注意事项

- **拥堵和天气是两套独立等级。** `portStatus` 与 `portWeather` 都用 A/B/C/D，但一个是拥堵程度、一个是天气影响程度，**不要共用同一套图例文案**。
- **时长单位是小时**，`avgAtd` 常见值是几十上百（如 93.71 小时 ≈ 3.9 天），展示时按需换算成天更直观。
- **港口没数据时 `rows` 是空数组**，不是 `null`，直接判 `length === 0` 即可。
- **数值型字段都是可空的**，飞驼某天没统计到会返回 `null`，图表要能跳过空点。
- **天气里的数字都是字符串**（`visibility`、`temperature` 等），要参与计算得自己转数字。
- **报错走 ABP 标准信封**：业务错误是 HTTP 500，按 `success` 判断，报错原文在 `error.message`，常见的是「请填写港口CODE(PortCode)」和飞驼返回的原始错误。
