# 1. 背景意图 (Background)

原飞驼船期对接的原始反序列化模型 `FeituoScheduleRawItem` 仅映射了飞驼 `/vessel2/v2/schedule` 返回的约 27 个字段，接口实际返回的大量字段(共舱、船舶标识、港口原始名/UNCODE/时区、班期、内部路径ID等)被直接丢弃，导致前端拿不到完整船期数据。本次按飞驼 apifox 官方文档全量补齐所有字段，并为每个字段补注释。

# 2. 核心逻辑变更 (Changes)

涉及文件：

- `src/CsprojBuilder.Application/App/ExternalApi/Feituo/Dto/FeituoDto.cs`
- `src/CsprojBuilder.Application/App/ExternalApi/Feituo/FeituoScheduleAdminAppService.cs`

## 2.1 原始 DTO(内部反序列化)

- `FeituoScheduleRawResponse`：新增 `size`。
- `FeituoScheduleRawItem`：新增 `shareCabins`、`imoNumber`、`mmsi`、`callSign`、`shipManagerEn`、`pol`、`polCountry`、`polTerminal`(原始)、`polUnCode`、`polUnName`、`polTimeZone`，以及对应的 `pod`/`podCountry`/`podTerminal`/`podUnCode`/`podUnName`/`podTimeZone`、`routeEtd`、`routeEta`、`staticEtdWeekOfYear`、`atd`、`ata`、`manifestCutoff`、`cvCutoff`、`pathCode`、`pathDescription`、`solutionDescription`、`solutionCode`。字段顺序对齐 apifox 文档。
- 新增 `FeituoShareCabinRawItem`(scac/carrier/routeCode/displayName)。
- `FeituoTransitRawItem`：新增 `portEn`、`portTimeZone`、`terminal`(原始)、`imoNumber`、`mmsi`、`callSign`。

## 2.2 展示 DTO(返回前端)

- `FeituoScheduleResultDto`：新增 `status`、`size`。
- `FeituoScheduleItemDto`：新增与原始 DTO 对应的全部字段，并新增 `shareCabins`(`List<FeituoShareCabinDto>`)。
- 新增 `FeituoShareCabinDto`。
- `FeituoScheduleTransitDto`：新增 `portEn`、`portTimeZone`、`terminalCn`、`imoNumber`、`mmsi`、`callSign`(保留原 `terminal`)。

## 2.3 映射

`FeituoScheduleAdminAppService.Format` 全量映射上述字段，中转集合仍按 `sort` 升序。

# 3. 避坑指南 (Blockers & Notes)

> [!IMPORTANT] **契约变更：码头字段语义调整。** 旧版 `polTerminal`/`podTerminal`/`transits[].terminal` 返回的是**标准码头名**(来源 `polTerminalCn`/`podTerminalCn`/`terminalCn`)。现已改为返回**船公司原始码头名**(飞驼 `polTerminal`/`podTerminal`/`terminal`)，标准码头名请改用新增的 `polTerminalCn`/`podTerminalCn`/`terminalCn`。前端如依赖旧字段需同步调整。

> [!NOTE] `pathCode`/`pathDescription`/`solutionDescription` 为飞驼内部字段，业务侧一般可忽略；`atd`/`ata` 为预设字段，飞驼暂无数据。
