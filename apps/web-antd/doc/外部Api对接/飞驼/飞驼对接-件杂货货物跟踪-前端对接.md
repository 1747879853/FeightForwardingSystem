# 1. 说明

件杂货货物跟踪前端只需对接 **两个接口**：订阅、查询。token 获取、飞驼推送接收与自动落库都由后端处理，前端无需关心。

另外**件杂货的列表与详情、业务联系单列表已直接带上运踪字段**(见「6.」)，做列表跟单与详情轨迹不用额外调接口。

> 完整的架构/订阅规则/推送说明见：`飞驼对接-件杂货货物跟踪.md`
>
> 海运出口/海运进口的集装箱跟踪是另一套接口，见 `飞驼对接-集装箱跟踪-前端对接.md`，两者不要混用。

# 2. 接口清单

| 接口 | 方法 | 地址 | 权限 |
| :-- | :-- | :-- | :-- |
| 件杂货货物跟踪订阅 | `POST` | `/api/services/app/FeituoAdmin/SubscribeBreakBulkAsync` | `Admin.ExternalApi.Use` |
| 查询件杂货货物跟踪 | `POST` | `/api/services/app/FeituoAdmin/GetBreakBulkTrackingAsync` | `Admin.ExternalApi.Get` |

> 返回体 ABP 统一包一层 `result`。

# 3. 件杂货货物跟踪订阅 SubscribeBreakBulkAsync

## 3.1 请求参数 (FeituoBreakBulkSubscribeInputDto)

| 字段名           | 类型   | 含义         | 必填 | 说明                 |
| :--------------- | :----- | :----------- | :--- | :------------------- |
| **breakBulkIds** | Guid[] | 件杂货Id集合 | 是   | 可批量；内部自动去重 |

**请求示例：**

```json
{
  "breakBulkIds": ["3f2504e0-4f89-11d3-9a0c-0305e82c3301"]
}
```

## 3.2 返回结构 (FeituoBreakBulkSubscribeResultDto)

| 字段名       | 类型  | 含义                        |
| :----------- | :---- | :-------------------------- |
| total        | int   | 提交订阅的总条数            |
| successCount | int   | 订阅成功条数                |
| failedCount  | int   | 订阅失败条数                |
| items        | array | 各票订阅结果，元素见「3.3」 |

## 3.3 单条订阅结果 (items[] - FeituoBreakBulkSubscribeItemResultDto)

| 字段名 | 类型 | 含义 |
| :-- | :-- | :-- |
| breakBulkId | Guid | 件杂货Id |
| subscriptionId | Guid? | 本地订阅记录Id(订阅记录创建成功才有) |
| isSuccess | bool | 是否订阅成功 |
| billNo | string | 上传给飞驼的单号(主提单号) |
| carrierCode | string | 上传给飞驼的船公司代码(固定 `AUTO`) |
| polCode | string | 上传给飞驼的起运港代码(起运港 EDI 代码) |
| podCode | string | 上传给飞驼的目的港代码(目的港 EDI 代码) |
| statusCode | int | 飞驼返回的状态码(20000 有数据、20001 暂无数据，两者都算订阅成功) |
| message | string | 飞驼返回的提示信息 |
| alertMessage | string | 飞驼返回的异常提示信息 |
| errorMessage | string | 失败原因(本地校验失败或请求异常时有值) |
| data | object | 本次返回的跟踪数据，结构见「5. 跟踪数据结构」；未取到数据时为 null |

## 3.4 规则与报错

| 规则 | 报错 |
| :-- | :-- |
| 没传件杂货Id | 整批抛错：`请至少选择一条件杂货` |
| 件杂货不存在 | 该条 `errorMessage`：`未找到指定的件杂货` |
| 只用**主提单号**订阅 | 未填主提单号：`该件杂货未填写主提单号，无法订阅` |
| 船公司代码固定传 `AUTO`(件杂货没有船公司，由飞驼识别) | — |
| 请求外部接口失败 | `货物跟踪订阅失败(HTTP 状态码)` / `请求外部接口异常，请稍后重试` / `外部接口返回为空` |
| 飞驼返回失败状态码 | `errorMessage` 为飞驼返回的提示信息 |

> 单条失败不影响其它条：失败信息在该条的 `errorMessage` 上，不会整批抛错(没传件杂货Id除外)。

> [!IMPORTANT] **同一票再调一次就是重新订阅**，会再消耗一次飞驼调用次数，别做成自动重试或页面加载时调用。件杂货改了主提单号后需要重新订阅，否则后续推送认领不到。

# 4. 查询件杂货货物跟踪 GetBreakBulkTrackingAsync

读本地已落库的最新快照，不请求飞驼。

## 4.1 请求参数 (FeituoBreakBulkTrackingInputDto)

| 字段名          | 类型 | 含义     | 必填 | 说明                    |
| :-------------- | :--- | :------- | :--- | :---------------------- |
| **breakBulkId** | Guid | 件杂货Id | 是   | 不传报 `请提交件杂货Id` |

**请求示例：**

```json
{
  "breakBulkId": "3f2504e0-4f89-11d3-9a0c-0305e82c3301"
}
```

## 4.2 返回结构 (FeituoBreakBulkTrackingDto)

| 字段名 | 类型 | 含义 |
| :-- | :-- | :-- |
| breakBulkId | Guid | 件杂货Id |
| hasSubscription | bool | 是否已订阅(false 表示这票从未订阅过，除 `breakBulkId` 外其余字段为空或默认值) |
| subscriptionId | Guid? | 本地订阅记录Id |
| isSuccess | bool | 订阅是否成功 |
| billNo | string | 订阅用的单号(主提单号) |
| carrierCode | string | 订阅用的船公司代码(固定 `AUTO`) |
| polCode | string | 订阅用的起运港代码 |
| podCode | string | 订阅用的目的港代码 |
| subscribeTime | DateTime? | 最近一次订阅时间 |
| lastPushTime | DateTime? | 最近一次收到飞驼推送的时间 |
| lastQueryTime | DateTime? | 最近一次落库时间(订阅落库或推送合并落库) |
| message | string | 飞驼返回的提示信息 |
| alertMessage | string | 飞驼返回的异常提示信息 |
| errorMessage | string | 失败原因 |
| data | object | 跟踪数据，结构见「5」；未取到数据时为 null |
| placeFallbackApplied | bool | 是否用**计划地点**兜底补过 `data.result` 里的 `receipt`/`delivery`/`firstVessel`，见下方说明 |

> [!IMPORTANT] **`placeFallbackApplied=true` 时，船期来自计划而非实际跟踪。** 订阅刚受理、飞驼还在采集时，报文里可能只有 `places`(计划地点)，没有 `receipt`/`delivery`/`firstVessel`。本接口在这三个节点**整个为 null** 时用计划地点补齐：起运侧取 `type=2`(缺失退 `type=1`)、目的侧取 `type=4`(缺失退 `type=5`)，船名航次取起运侧那条；飞驼给了就一个字段都不动。前端拿到 `true` 时建议加一句「以下为计划船期」。 **`currentStatus`(当前节点)不兜底。**

# 5. 跟踪数据结构 (data - FeituoBreakBulkDataDto)

| 字段名 | 类型   | 含义                    |

# 7. 注意事项

- **订阅即查询**：订阅成功时 `data` 里就带回了当前全量数据，可直接展示，无需再调查询接口。
- **数据会自动更新**：飞驼有变化会推送增量，后端合并落库。前端**不需要轮询飞驼**，调 `GetBreakBulkTrackingAsync` 或看列表/详情里的运踪字段即可。自动更新依赖飞驼客服配置好散货/RORO 的回调地址；配好之前只有订阅时带回的那一份快照。
- **首次订阅可能无数据**：`statusCode=20001` 或 `data` 为空表示订阅成功但飞驼尚未抓到数据，属正常情况，等推送更新即可。
- **"数据获取中"阶段也可能已有船期**：此时报文只有计划地点，会用它兜底补出预计开船/预计到港/船名航次并置 `placeFallbackApplied=true`。 `GetBreakBulkTrackingAsync` 补的是 `data.result` 里的 `receipt`/`delivery`/`firstVessel`，列表与详情的 `feituoTracking` 补的是 `polEtd`/`polAtd`/`podSta`/`podEta`/`podAta`/`firstVesselName`/`firstVesselVoyage`。
- **未订阅过的件杂货**：`GetBreakBulkTrackingAsync` 返回 `hasSubscription=false`、`data` 为 null；列表与详情的 `feituoTracking` 为 null。
- **按 `status[]` 数组顺序画轨迹即可**：订阅返回按飞驼的业务节点顺序，推送合并后后端按发生时间重排(时间为空的排最后)。
