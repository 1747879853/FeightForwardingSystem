# 1. 业务背景说明 (Background)

**白话解释：** 飞驼「海运港拥堵分析」提供全球港口**最近 15 天**的拥堵情况：每天的在港/靠泊/离港船数、平均候泊与作业时长、拥堵等级与**中英文原因分析**，并附带该港当天的天气情况（能见度、气温、风力等）。业务上用来判断某个港口最近堵不堵、堵的原因是什么，辅助订舱与客户答复。

> [!IMPORTANT] **本功能不建任何表。** 数据只透传给前端，不落库、不写日志。每次查询都实时请求飞驼。

# 2. 功能与操作说明 (Features & Operations)

- **港口拥堵分析查询：** `FeituoAdminAppService.QueryPortCongestionAsync`，按港口CODE查，可选是否返回船舶明细（MMSI 列表）。

# 3. 架构与数据流

```
业务端 ──取token(头 X-Relay-Token)──▶ 中转站 /relay/feituo/token ──▶ access_token
业务端 ──查询(Bearer token)──▶ 飞驼 GET /vessel2/ports/status?portCode=xxx ──▶ 拥堵数据(直接返回前端)
```

**Token 与其它飞驼功能共用**：`FeituoTokenProvider` 是同一份进程内缓存，船期、集装箱跟踪、航空货运跟踪、港口拥堵四处共用，不会重复取号。

# 5. 返回字段口径

`data` 下 `portCode` / `lon` / `lat` 是港口本身的信息，`rows[]` 是**按天**的拥堵情况（最近 15 天，每天一条）。

**每天一条 `rows[]` 的内容：**

| 分组 | 字段 | 说明 |
| :-- | :-- | :-- |
| 日期 | `key` | 汇总日期 `yyyy-MM-dd` |
| 船数 | `ataVesselCount` / `atbVesselCount` / `atdVesselCount` | 在港 / 靠泊 / 离港总船数 |
| 时长 | `avgAtbA` / `avgAtbD` / `avgAtd` | 平均候泊 / 平均作业 / 平均在港时长，**单位小时** |
| 拥堵 | `portStatus` | `A` 正常、`B` 轻微拥堵、`C` 中度拥堵、`D` 严重拥堵 |
| 拥堵原因 | `portStatusDetails` / `portStatusDetailsEn` | 中英文分析描述，是整段自然语言 |
| 天气 | `portWeather` | `A` 正常、`B` 轻微影响、`C` 中度影响、`D` 严重影响 |
| 天气详情 | `portWeatherDetails` | 见下表 |
| 船舶明细 | `ataVessels` / `atbVessels` / `atdVessels` | MMSI 字符串数组，**仅 `includeMmsi=true` 时返回** |

**`portWeatherDetails`（天气详情）：**

| 字段 | 说明 |
| :-- | :-- |
| `weatherLevel` | 天气级别，飞驼内部使用：`NORM` / `MILD` / `MODERATE` / `SEVERE` |
| `weatherType` | 天气类型：`SUNNY_DAY` 晴(白天)、`SUNNY_NIGHT` 晴(夜间)、`CLOUDY_DAY` 多云(白天)、`CLOUDY_NIGHT` 多云(夜间)、`OVERCAST` 阴、`WINDY` 大风、`HAZE` 雾霾、`RAINY` 雨、`SNOWY` 雪 |
| `portWeatherDetails` / `portWeatherDetailsEn` | 天气现象原因中英文，如「能见度为456.0米」 |
| `visibility` / `temperature` / `humidity` / `atmosphericPressure` / `rainfall` | 能见度(米) / 气温(℃) / 相对湿度(%) / 气压(Pa) / 小时降水量(mm) |
| `wind` | `direction` 风向角度(度)、`speed` 风速(m/s)、`power` 风力等级 |
| `date` | 观测时间 |

> [!NOTE] **天气详情里也有 `portCode` / `lat` / `lon`**，与 `data` 顶层重复，飞驼原样返回，本系统未做去重。

# 6. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **1. 本功能不建表、不落库。** 每次查询实时请求飞驼。若将来要做趋势对比或减少外部调用，再考虑加缓存或落库。

> [!IMPORTANT] **2. `includeMmsi` 默认不传。** 一个大港一天的在港船就上百条 MMSI，三个数组加起来响应体会膨胀好几倍。只在前端确实要展示船舶明细时才传 `true`。

> [!NOTE] **3. 数值类字段的类型不统一，已做兼容。** 飞驼文档把 `wind.power` 标注为字符串，但示例里返回的是数字 `2`；本系统 DTO 用 `string` 接，Newtonsoft 会自动把数字转成字符串，不会反序列化失败。时长类 `avgAtbA` / `avgAtbD` / `avgAtd` 是小数，用 `decimal?` 接。

> [!NOTE] **4. 港口无数据时返回空壳而不是 null。** 飞驼对没有拥堵数据的港口会返回 `data = null`，本系统会补一个 `Rows` 为空数组的对象返回，前端不必判 `null`。

> [!NOTE] **5. 拥堵与天气是两套独立等级。** `portStatus`（拥堵）和 `portWeather`（天气）虽然都用 A/B/C/D，但含义不同：前者是拥堵程度，后者是天气影响程度。界面上不要共用同一套图例文案。
