# 1. 说明

前端船期查询只需对接 **一个接口** `QueryScheduleAsync`。token 获取、后台刷新、中转站等均由后端处理，前端无需关心。

> [!WARNING] **2026-08-09 接口地址已变更。** 飞驼的所有接口合并到了同一个服务 `FeituoAdmin`，船期查询的地址由 `/api/services/app/FeituoScheduleAdmin/QueryScheduleAsync` 改为 `/api/services/app/FeituoAdmin/QueryScheduleAsync`。方法名与入参出参**完全没变**，只需改地址前缀。

> 完整的架构/Token/后台刷新说明见：`飞驼对接-船期查询与Token中转.md`

# 2. 接口

| 项目   | 内容                                                  |
| :----- | :---------------------------------------------------- |
| 方法   | `POST`                                                |
| 地址   | `/api/services/app/FeituoAdmin/QueryScheduleAsync`    |
| 请求体 | JSON，见「3. 请求参数」                               |
| 返回   | JSON，见「4. 返回结构」(ABP 统一包一层 `result`)      |
| 权限   | 需登录且具备「船期 > 查询」权限(`Admin.Schedule.Get`) |

# 3. 请求参数 (FeituoScheduleQueryInputDto)

| 字段名 | 类型 | 含义 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| **polCode** | string | 起始港五字码 | 是 | 自动转大写，如 CNSHA |
| **podCode** | string | 目的港五字码 | 是 | 自动转大写，如 USLGB |
| **etd** | string | 预计离港日期 | 是 | 格式 yyyy-MM-dd |
| **weeksOut** | int | 范围(周) | 是 | 1=7天…8=56天；传 eta 时飞驼接口不生效，但仍需传入 |
| **eta** | string | 预计到港日期 | 否 | 与 etd 组合查询，传入后 weeksOut 不生效 |
| **carrierCd** | string | 船公司代码 | 否 | 仅支持单个 |
| **routeCode** | string | 头程航线代码 | 否 |  |
| **isTransit** | int? | 中转标识 | 否 | 0直达 1中转，不传返回全部 |
| **transitPortEn** | string | 第1次中转港口名 | 否 |  |
| **vessel** | string | 船名 | 否 |  |
| **pageNum** | int | 页码 | 否 | 默认 1 |
| **pageSize** | int | 每页条数 | 否 | 最大 1000，默认 100 |

**请求示例：**

```json
{
  "polCode": "CNSHA",
  "podCode": "USLGB",
  "etd": "2026-07-20",
  "weeksOut": 8
}
```

# 5. 注意事项

- `weeksOut` 为必填，取值 1~8，未传或越界后端会返回错误提示。
- `polCode`/`podCode` 后端会自动转大写，前端可不处理。
- `statusCode=20001` 表示查询成功但无数据，`items` 为空数组，属正常情况。
- 船期数据为实时查询，**不落库**，每次请求都会实时拉取。
