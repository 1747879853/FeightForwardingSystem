# 1. 业务背景说明 (Background)

**白话解释：** 飞驼「中国海关跟踪(提单号)」按提运单号查该票在中国海关的关务节点：报关单号、船代代码、结束时间，以及一串回执状态（申报、放行、查验等，各带发生时间与状态码）。

本系统的用法与码头船舶计划一致——**按业务单一键查询**：操作在海运出口/海运进口单据上点一下，后端拿这条单子的**主提单号**去查，按业务类型自动带进出口标识。前端只需要传业务单Id。

> [!IMPORTANT] **纯查询接口：不建表、不落库、不回填业务单。** 结果只透传给前端展示。

# 2. 功能与操作说明 (Features & Operations)

- **海关跟踪查询：** `FeituoAdminAppService.QueryCustomsTrackingAsync`，入参只有业务单Id。
  - 查到 → `data` 里是关务数据，`message` 为空。
  - 没查到 → `data` 为 `null`，`message` 带上"未查到主提单号[xxx]的海关跟踪信息"。

# 3. 架构与数据流

```
业务端 ──取token(头 X-Relay-Token)──▶ 中转站 /relay/feituo/token ──▶ access_token
业务端 ──查询(Bearer token)──▶ 飞驼 GET /terminal/cn/customs/getBlnoDeclare ──▶ 关务数据(原样返回前端)
```

请求统一走 `FeituoTokenProvider.SendAsync`，token 失效会自动换新重试一次，详见《飞驼对接-船期查询与Token中转.md》的卡点。

# 5. 返回字段口径

飞驼返回的字段**全部原样透传**，一个都不落库。时间类字段都是飞驼返回的原始字符串。

| 字段        | 说明                     |
| :---------- | :----------------------- |
| `ieid`      | 进出口标识，飞驼原样回显 |
| `blno`      | 单号，即查询用的提运单号 |
| `entryid`   | 报关单号                 |
| `entdeclno` | 船代代码                 |
| `endtime`   | 结束时间                 |
| `status[]`  | 关务状态节点数组，见下   |

**`status[]` 每一项：**

| 字段          | 说明                          |
| :------------ | :---------------------------- |
| `note`        | 回执状态描述                  |
| `noticedate`  | 发生时间                      |
| `statuscd`    | 回执状态码（**可能为 null**） |
| `channelname` | 回执状态描述（通道名）        |
| `entryid`     | 报关单号                      |

# 6. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **1. 报文是双层 `data`，业务数据在内层。** 飞驼返回 `{ statusCode, message, data: { success, status, message, data: {真正的数据} } }`。外层 `data` 里的 `success` / `status` / `message` 飞驼文档明确标注为"内部使用"，本系统**不解读、也不返回给前端**，只把内层 `data` 取出来透传（代码里就是 `response.Data?.Data`）。改这块时别把外层当成业务数据。

> [!IMPORTANT] **2. 主提单号是唯一查询依据，没填直接报错。** 业务单没填 `MblNum` 时报「该业务单未填写主提单号，无法查询海关跟踪」。不像集装箱跟踪那样有"退回箱号"的兜底——飞驼这个接口只收提运单号。

> [!NOTE] **3. 只支持海运出口与海运进口。** 飞驼把它归在「海运集装箱跟踪 / 中国港区+海关跟踪」下，入参是提运单号；空运出口的 `MblNum` 是航空主运单号，口径对不上，因此空运会直接报「海关跟踪仅支持海运出口与海运进口」。

> [!NOTE] **4. 状态码 20001 不是失败。** 飞驼的 `20001` 表示"请求成功但无数据"，判成功统一走 `FeituoStatusCode.IsSuccess`， **不要**写 `statusCode == 20000`，否则没有关务数据的单子会报"查询失败"而不是"未查到"。

> [!NOTE] **5. 对外报错不带服务商名。** 请求异常一律说「请求外部接口异常」，供应商名与原始报文只写进日志。这是仓库规则，见 `.cursor/rules/dotnet-api-dto.mdc`。
