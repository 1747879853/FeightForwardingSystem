# 0. 前端只需看这一份

空运航空货运跟踪有 **2 个接口**：订阅、重新订阅。token 获取、飞驼查询与推送接收全部由后端处理，前端无需关心。

**轨迹不需要单独调接口** —— 空运出口的列表与详情已经直接带上运踪，见第 3 节。

> [!IMPORTANT] **订阅成功不代表马上有轨迹。** 飞驼空运的订阅接口只返回订阅ID，后端会紧接着回查一次；但刚订阅时飞驼往往还没抓到数据，此时返回里 `trackingLoaded = false`，**这不算订阅失败**。等飞驼推送来了后端会自动落库，无需前端轮询。

# 1. 接口一览

| 功能 | 方法 | 地址 | 权限 |
| :-- | :-- | :-- | :-- |
| 航空货运跟踪订阅 | `POST` | `/api/services/app/FeituoAdmin/SubscribeAirWaybillAsync` | `Admin.ExternalApi.Use` |
| 航空货运跟踪重新订阅 | `POST` | `/api/services/app/FeituoAdmin/ResubscribeAirWaybillAsync` | `Admin.ExternalApi.Use` |

# 2. 航空货运跟踪订阅

**地址：** `POST /api/services/app/FeituoAdmin/SubscribeAirWaybillAsync`

## 2.1 入参

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| airExportIds | Guid[] | 是 | 空运出口Id集合，可批量。重复Id会自动去重 |
| forceResubscribe | bool | 否 | 是否强制重新订阅，默认 `false`。默认情况下"已订阅成功且航司单号未变"的单会直接复用已有订阅、不再请求飞驼；传 `true` 则强制重订 |

**请求示例：**

```json
{
  "airExportIds": ["3fa85f64-5717-4562-b3fc-2c963f66afa6"],
  "forceResubscribe": false
}
```

## 2.2 出参

| 字段         | 类型     | 说明                                     |
| :----------- | :------- | :--------------------------------------- |
| total        | int      | 提交订阅的总条数                         |
| successCount | int      | 订阅成功条数（含直接复用已有订阅的条数） |
| failedCount  | int      | 订阅失败条数                             |
| items        | object[] | 各空运出口的订阅结果明细，见下表         |

**items[] 明细：**

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| airExportId | Guid | 空运出口Id |
| subscriptionId | Guid? | 本地订阅记录Id（订阅记录创建成功才有；本地校验失败时为 null） |
| isSuccess | bool | 是否订阅成功 |
| alreadySubscribed | bool | 本次是否直接复用了已有订阅（未请求飞驼，不消耗订阅配额） |
| businessNumber | string | 上传给飞驼的航司单号（11位纯数字） |
| sourceMblNum | string | 订阅时业务单上的主运单号原文 |
| feituoSubscriptionId | string | 飞驼返回的订阅ID（后续查询轨迹要用它） |
| statusCode | int | 飞驼返回的状态码，20000 为成功 |
| message | string | 飞驼返回的提示信息 |
| errorMessage | string | 失败原因（本地校验失败或请求异常时有值） |
| trackingLoaded | bool | 订阅后立即回查是否拿到了轨迹并落库。**false 不代表订阅失败** |
| trackingMessage | string | 回查没拿到数据时的说明（`trackingLoaded=false` 时有值） |

**返回示例（成功）：**

```json
{
  "result": {
    "total": 1,
    "successCount": 1,
    "failedCount": 0,
    "items": [
      {
        "airExportId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
        "subscriptionId": "8c1b2f90-1a2b-4c3d-9e8f-7a6b5c4d3e2f",
        "isSuccess": true,
        "alreadySubscribed": false,
        "businessNumber": "11273690094",
        "sourceMblNum": "112-73690094",
        "feituoSubscriptionId": "4ef4ee1e9ecf5e4361cf234f325ebac7",
        "statusCode": 20000,
        "message": "成功",
        "errorMessage": null,
        "trackingLoaded": true,
        "trackingMessage": null
      }
    ]
  }
}
```

**返回示例（订阅成功但飞驼还没数据）：**

```json
{
  "result": {
    "total": 1,
    "successCount": 1,
    "failedCount": 0,
    "items": [
      {
        "airExportId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
        "subscriptionId": "8c1b2f90-1a2b-4c3d-9e8f-7a6b5c4d3e2f",
        "isSuccess": true,
        "alreadySubscribed": false,
        "businessNumber": "11273690094",
        "sourceMblNum": "112-73690094",

        "statusCode": 20000,
        "message": "成功",
        "errorMessage": null,
        "trackingLoaded": false,
        "trackingMessage": "飞驼暂无该运单的跟踪数据"
```

# 3. 前端注意事项

- **批量订阅是"单条互不影响"的**：某一条失败不会中断其它条，最终 `total = successCount + failedCount`，逐条看 `items[].isSuccess` 即可。
- **失败原因看 `errorMessage`**，成功提示看 `message`。两者不会同时有值。
- **`alreadySubscribed = true` 也算成功**，只是没有真的请求飞驼。可以给用户提示"该运单此前已订阅"。
- **主运单号格式**：后端会自动剥离连字符和空格，`112-73690094` 与 `11273690094` 都能订阅成功。但提取出的数字必须**恰好11位**，否则直接被拦截、不会发给飞驼。
- **整个请求级别的报错**（如"请至少选择一条空运出口"）走 ABP 的标准异常返回，不在 `items` 里。
- **`trackingLoaded=false` 要区别对待**：这条是订阅成功的，只是飞驼还没抓到轨迹。给用户的提示应该是"订阅成功，数据获取中"，而不是报错。
- **数据会自动更新**：订阅成功后飞驼有变化会推送全量数据，后端自动落库。前端**不需要轮询**。

# 3. 重新订阅

**地址：** `POST /api/services/app/FeituoAdmin/ResubscribeAirWaybillAsync`

无视已有订阅记录**强制再向飞驼订阅一次**，拿到新的订阅ID后重新登记推送路由并回查落库。用于运单号改过、或订阅数据异常需要重来的场景。

## 3.1 入参

| 字段        | 类型 | 必填 | 说明               |
| :---------- | :--- | :--- | :----------------- |
| airExportId | Guid | 是   | 空运出口Id（单条） |

## 3.2 出参

返回结构与订阅接口 `items[]` 的**单条明细完全一致**（见 2.2），直接是一个对象而不是数组。

> [!IMPORTANT] **重新订阅会消耗一次飞驼订阅配额。** 普通订阅接口对"已订阅成功且单号未变"的票会直接复用、不花钱（返回 `alreadySubscribed: true`），所以只在确实需要重来时才用这个接口。

# 4. 空运出口列表与详情里的运踪

轨迹**不需要单独调接口**，`AirExportAdmin` 的列表与详情已经带上了。

| 字段 | 出现位置 | 说明 |
| :-- | :-- | :-- |
| isFeituoSubscribed | 列表 + 详情 | 是否已订阅 |
| isFeituoSubscribeSuccess | 列表 + 详情 | 是否订阅成功 |
| feituoTracking | 列表 + 详情 | **运踪摘要**，未订阅时为 null |
| feituoTrackingDetail | **仅详情** | 完整数据（全部事件、运输路径、地点、预警），列表恒为 null |
| feituoTrackingWarnings | **仅详情** | 异常预警明细，列表恒为 null |

## 4.1 feituoTracking（摘要）字段

**订阅状态**：`isSubscribed` / `isSubscribeSuccess` / `businessNumber`(11位航司单号) / `feituoSubscriptionId` / `errorMessage` / `lastQueryTime` / `lastPushTime`

**整票状态**：`status`（`COMPLETE` 完成 / `PROCESS` 进行中）、`updateTime`、`direct`（true 直达 / false 中转）

**航空公司**：`carrierName` / `carrierNameEn` / `carrierCode` / `carrierUrl` / `carrierIsSupported`（1支持 0不支持）

**货物**：`cargoPieces` / `cargoWeight` / `cargoVolume`

**当前节点**（这票现在到哪了）：`currentEventCategory` / `currentEventCode` / `currentEventClassifier`（`ACT` 实际 / `EST` 预计）/ `currentEventTime` / `currentDescription` / `currentFlight` / `currentLocationCode` / `currentLocationName` / `currentLocationCity` / `currentLat` / `currentLon`

**起降**：`originCode|originName|originCity`（起飞机场）、`destinationCode|destinationName|destinationCity`（目的机场）、`firstFlight` / `lastFlight`、`destinationEta` / `destinationAta`

**异常预警**：`hasWarning` / `warningCount` / `latestWarningCategory` / `latestWarningCode` / `latestWarningTime` / `latestWarningDescription`

## 4.2 前端注意事项

- **`feituoTracking` 不为 null 但当前节点全空**，说明已订阅、飞驼还没抓到数据，提示"数据获取中"即可。
- **当前节点是后端算的**：飞驼空运不返回"当前状态"，后端取时间最新的**实际**事件（没有实际事件才退回预计事件）。`currentEventClassifier = EST` 时说明这是个预计节点，展示上建议区分。
- **时间字段都是字符串**（飞驼原样返回，格式 `yyyy-MM-dd HH:mm:ss`），直接展示即可，不要当 Date 解析后再格式化，避免时区偏移。
- **列表不返回 `feituoTrackingDetail`**，需要看完整轨迹请进详情。
