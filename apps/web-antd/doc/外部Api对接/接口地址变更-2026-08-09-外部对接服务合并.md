# 0. 一句话说明

飞驼与云当各自分散在多个 AppService 里的接口，分别合并到了 `FeituoAdminAppService` 和 `YundangAdminAppService`。**ABP 的接口地址是按 AppService 类名生成的，所以合并会改地址。**

**方法名、入参、出参全部没有变化，前端只需要改地址前缀。**

# 1. 需要改的接口清单

## 1.1 飞驼（6 个接口全部要改）

| 功能 | 旧地址 | 新地址 |
| :-- | :-- | :-- |
| 船期查询 | `/api/services/app/FeituoScheduleAdmin/QueryScheduleAsync` | `/api/services/app/FeituoAdmin/QueryScheduleAsync` |
| 集装箱跟踪订阅 | `/api/services/app/FeituoContainerAdmin/SubscribeContainerAsync` | `/api/services/app/FeituoAdmin/SubscribeContainerAsync` |
| 查询集装箱跟踪数据 | `/api/services/app/FeituoContainerAdmin/GetContainerTrackingAsync` | `/api/services/app/FeituoAdmin/GetContainerTrackingAsync` |
| 航空货运跟踪订阅 | `/api/services/app/FeituoAirAdmin/SubscribeAirWaybillAsync` | `/api/services/app/FeituoAdmin/SubscribeAirWaybillAsync` |
| 航空货运跟踪重新订阅 | `/api/services/app/FeituoAirAdmin/ResubscribeAirWaybillAsync` | `/api/services/app/FeituoAdmin/ResubscribeAirWaybillAsync` |
| 港口拥堵分析 | `/api/services/app/FeituoPortCongestionAdmin/QueryPortCongestionAsync` | `/api/services/app/FeituoAdmin/QueryPortCongestionAsync` |

> [!IMPORTANT] **船期查询是唯一已经上线在用的飞驼接口**，改地址前请确认前端已同步。其余 5 个（集装箱跟踪、空运、港口拥堵）尚未上线，改了没有影响。

## 1.2 云当（只有空运 3 个要改，海运不变）

| 功能 | 旧地址 | 新地址 |
| :-- | :-- | :-- |
| 空运运单批量订阅 | `/api/services/app/YundangAirAdmin/BatchSubscribeAirBillAsync` | `/api/services/app/YundangAdmin/BatchSubscribeAirBillAsync` |
| 空运运单重新订阅 | `/api/services/app/YundangAirAdmin/ResubscribeAirBillAsync` | `/api/services/app/YundangAdmin/ResubscribeAirBillAsync` |
| 查询空运推送信息 | `/api/services/app/YundangAirAdmin/GetAirPushInfoAsync` | `/api/services/app/YundangAdmin/GetAirPushInfoAsync` |

**云当海运的 3 个接口地址完全没变**，因为合并后的类名仍是 `YundangAdminAppService`：

| 功能 | 地址（未变） |
| :-- | :-- |
| 海运运单批量订阅 | `/api/services/app/YundangAdmin/BatchSubscribeOceanBillAsync` |
| 海运运单重新订阅 | `/api/services/app/YundangAdmin/ResubscribeOceanBillAsync` |
| 查询海运推送信息 | `/api/services/app/YundangAdmin/GetOceanPushInfoAsync` |

# 2. 不需要改的部分

## 2.1 推送入口（Controller 路由，全部不变）

推送走的是普通 MVC Controller，路由写死在 `[Route]` 上，与 AppService 合并无关：

| 入口                  | 地址（未变）                      |
| :-------------------- | :-------------------------------- |
| 飞驼海运增量+预警推送 | `POST /api/feituo/increment-push` |
| 飞驼空运全量推送      | `POST /api/feituo/air-push`       |
| 云当海运推送          | `POST /api/yundang/push`          |
| 云当空运推送          | `POST /api/yundang/air/push`      |

**中转站的对外地址也全部不变**（`/relay/feituo/increment-push`、`/relay/feituo/air-push`、`/relay/feituo/air-register`、`/relay/yundang/push`、`/relay/yundang/air/push`、`/relay/{provider}/token`）。已经提供给飞驼、云当客服配置的回调地址**不用重新提交**。

## 2.2 入参与出参

**一个字段都没改。** 合并只是把方法搬到同一个类里，方法签名与 DTO 完全保持原样。

## 2.3 权限点

全部沿用原有权限，没有变化：

| 接口                                 | 权限点                  |
| :----------------------------------- | :---------------------- |
| 飞驼船期查询                         | `Admin.Schedule.Get`    |
| 飞驼集装箱订阅 / 空运订阅 / 空运重订 | `Admin.ExternalApi.Use` |
| 飞驼跟踪查询 / 港口拥堵              | `Admin.ExternalApi.Get` |
| 云当海运/空运订阅、重订              | `Admin.ExternalApi.Use` |
| 云当海运/空运查询推送信息            | `Admin.ExternalApi.Get` |

# 3. 后端内部改动（前端不用关心，供后端排查用）

## 3.1 文件变化

| 平台 | 合并前 | 合并后 |
| :-- | :-- | :-- |
| 飞驼 | 6 个 AppService + 6 个接口 = 12 个文件 | `FeituoAdminAppService.cs` + `IFeituoAdminAppService.cs` |
| 云当 | 4 个 AppService + 4 个接口 = 8 个文件 | `YundangAdminAppService.cs` + `IYundangAdminAppService.cs` |

各平台的 Manager 类（落库映射、增量合并、只读查询、Token 提供者）保持独立，它们不是对外接口，且体量很大。

## 3.2 两个内部方法改了名

推送处理方法合并进主服务后出现同名，**ABP 的动态 WebApi 不支持同名方法重载**（会路由冲突），因此改名：

| 平台         | 原方法名           | 新方法名                |
| :----------- | :----------------- | :---------------------- |
| 云当海运推送 | `ProcessPushAsync` | `ProcessOceanPushAsync` |
| 云当空运推送 | `ProcessPushAsync` | `ProcessAirPushAsync`   |

调用方是 `YundangPushController` / `YundangAirPushController`，已同步改好。这两个方法不对前端开放，改名不影响任何外部调用。

## 3.3 云当合并时处理的命名冲突

海运与空运两套实现有 53 处成员重名。处理方式：

- **19 个仓储字段类型相同 → 直接共用一个**（如 `_seaExportRepository`、`_pushLogRepository`、各子表仓储）
- **2 个字段类型不同 → 按业务前缀区分**：`_subscriptionRepository` 拆成 `_oceanSubscriptionRepository` / `_airSubscriptionRepository`，`_shipmentRepository` 拆成 `_oceanShipmentRepository` / `_airShipmentRepository`
- **4 个工具方法两边实现完全相同 → 只保留一份**：`GetTokenAsync`、`BuildBusinessUrl`、`ParseDate`、`Truncate`，另加 `ParseLocalKeySeq`、`BuildLocalKey`、`Chunk`
- **返回类型不同但参数相同 → 重命名**：`BuildLocalFailure` 的空运版改为 `BuildAirLocalFailure`，嵌套类型 `ResubscribeApplyResult` 的空运版改为 `AirResubscribeApplyResult`
- **其余同名但参数类型不同的私有方法**（`BuildItem`、`MapShipment`、`MapSubscription` 等）靠 C# 重载共存，未改名

> [!NOTE] **token 缓存有一处实质改善。** 合并前云当海运与空运各有一份 `static` token 缓存，等于同一个云当账号被重复取号；合并后共用一份，取号次数减半。飞驼那边原本就已经通过 `FeituoTokenProvider` 共用。
