# Gemini对接-账单识别费用-2026-09-06

# 1. 背景意图

船公司/订舱代理会发来单票账单（Invoice / Debit Note）。操作员要对照账单把应付费用录进对应业务，以前只能人工看提单号、再逐条抄费用代码、币别、箱型、箱量、单价。

新增接口：上传这份账单，自动识别提单号和费用行；提单号能对上系统业务时，返回**费用添加 DTO 列表**给用户勾选确认后再落库。认不出提单号、或对不上业务，直接报错，不返回费用。

本接口**只识别、不落费用**。用户确认后仍走现有 `OrderFeeAdmin/BatchEditAsync`（`Id` 为空即新增）。

# 2. 核心逻辑变更

| 项 | 说明 |
| :-- | :-- |
| 新接口 | `POST /api/services/app/GeminiAdmin/ExtractBillFeesAsync` |
| 入参 | `multipart/form-data`，取第一个文件。可选 `transportOrderId`（当前业务id）。支持 pdf / 图片 / txt / xlsx / xls。上限 **20MB** |
| 识别字段 | 提单号；每条费用的费用项目、币别、Unit（箱型名）、Quantity（该箱型箱量）、单价、金额 |
| 业务匹配 | 未传业务id：提单号去空格后忽略大小写精确匹配 `TransportOrder.MblNum`。0 条报「未找到提单号对应的业务」；多于 1 条报「提单号对应多条业务，请人工核对」。传了业务id：先查该票是否存在，再与识别出的主提单号核对，对不上报「账单提单号与当前业务主提单号不一致」 |
| 费用匹配 | 费用代码按 Code/中文名/英文名/**备注别名**匹配，括号内缩写也会打备注里的别名；币别按代码/中英文名/符号/**别称 Alias**/**备注**匹配。别称、备注支持逗号分号斜杠分隔的多个别名。箱型 40HC 与 40HQ 互通。匹配不到的 Id 为 **-1** |
| 收付 | 账单默认按**应付**组装（`paySide=付`）。结算对象按费用代码默认付费客户类型从业务上带，`settlementId` 与完整 `settlement` 客户对象一并返回；带不到则为空 |
| 出参 | `GeminiBillFeeExtractDto`：识别提单号 + 匹配到的业务简要 + `orderFees`（即 `OrderFeeEditDto` 列表，`id` 恒为空） |
| 缓存 | 按文件内容缓存模型原始 JSON；费用代码/币别/箱型/业务匹配每次重跑 |

完整入参见《Gemini对接-前端对接》第 7 节。

# 3. 避坑指南

> [!IMPORTANT] **接口成功不等于可以原样提交费用。** `feeCodeId` / `currencyId` 为 `-1` 时表示名称认出来了但基础资料没对上。直接拿去调 `BatchEditAsync` 会被拦「费用名称不能为空 / 币别id不能为空」。前端必须标红让用户改完再提交。

> [!IMPORTANT] **认不出提单号是接口失败，不是空列表。** 文案：「未能识别到提单号」「未找到提单号对应的业务」「提单号对应多条业务，请人工核对」「账单提单号与当前业务主提单号不一致」。不要把发票号当成提单号去对业务。
>
> 费用页已打开某一票时应传 `transportOrderId`，用来拦住「认到了提单号但不是当前这票」。

> [!IMPORTANT] **本接口不写费用。** 返回列表只供预览。用户勾选后用现有费用批量编辑接口新增（`id` 不传）。
