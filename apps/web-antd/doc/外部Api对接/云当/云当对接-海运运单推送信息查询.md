# 1. 业务背景说明 (Background)

**白话解释：** 海运出口完成云当订阅后，云当会通过推送将运单跟踪动态回写到本系统。操作人员在海运出口详情页需要查看「订阅是否成功」以及「最新货物跟踪动态」（船名航次、箱轨迹、航段、海运节点等）。本功能提供按海运出口Id查询的只读接口，汇总订阅记录与解析后的运单动态，供前端展示跟踪面板。

与订阅接口的关系：

- **订阅**：`BatchSubscribeOceanBillAsync` — 向云当发起订阅并落库 `App_YundangOceanSubscriptions`
- **查询**：`GetOceanPushInfoAsync` — 读取订阅表 + 运单动态解析表，不调用云当实时接口

# 2. 功能与操作说明 (Features & Operations)

- **查看订阅状态：** 传入海运出口Id，返回该票的订阅记录（单号、船东、是否成功、云当Id、错误信息等）。
- **查看运单动态：** 若云当已推送且后端已解析入库，返回运单主信息及子表（集装箱、箱轨迹、航段、海运节点）。
- **未订阅/未推送：** `subscription` 或 `shipment` 为 `null`，前端按空态展示。

# 3. 状态流转说明 (Status Transitions)

| 当前状态 | 触发人/动作 | 目标状态 | 状态说明 |
| :-- | :-- | :-- | :-- |
| 未订阅 | 用户调用订阅接口 | 订阅中/成功/失败 | `subscription` 有记录，`isSuccess` 区分成败 |
| 订阅成功 | 云当推送运单数据 | 有运单动态 | `shipment` 非空，含箱/轨迹等子表 |
| 订阅成功 | 云当尚未推送 | 等待动态 | `subscription.isSuccess=true`，`shipment=null` |
| 订阅失败 | 用户修正后重试订阅 | 更新订阅记录 | 同一 `seaExportId` 更新原记录，见批量订阅文档 |

# 5. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **[卡点 1：订阅成功但无运单动态]** 订阅接口只负责发起订阅；运单动态依赖云当异步推送。`subscription.isSuccess=true` 且 `shipment=null` 时，应提示「已订阅，等待云当推送」，可定时刷新本查询接口。

> [!IMPORTANT] **[卡点 2：一条海运出口一条订阅]** 以 `SeaExportId` 为准，不可重复成功订阅。查询时同样只取该 Id 对应的一条订阅记录。

> [!IMPORTANT] **[卡点 3：不返回原始报文]** 排查问题需查库字段 `LatestPushJson` 或推送日志表；本接口面向业务展示，不含 `RawJson`/`YundangPushLog`。

# 7. 核心逻辑 (Core Logic)

## 7.1 接口 `GetOceanPushInfoAsync`

1. 校验 `seaExportId` 非空。
2. 查询 `App_YundangOceanSubscriptions`：`SeaExportId = seaExportId`，按 `SubscribeTime` 降序取一条 → 映射为 `subscription`。
3. 查询运单动态主表：`SeaExportId = seaExportId` 或 `LocalKey = seaExportId.ToString("N")`，按 `LastPushTime` 降序取一条。
4. 若存在运单动态，批量加载子表（集装箱、箱状态、航段、海运节点），箱轨迹按 `ContainerId` 归组后映射为 `shipment`。
5. 返回 `YundangOceanPushInfoDto`；无数据时对应字段为 `null`。
