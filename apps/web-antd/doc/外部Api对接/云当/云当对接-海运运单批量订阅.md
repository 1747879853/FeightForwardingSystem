# 1. 背景意图 (Background)

**白话解释：** 对接云当(Trackingeyes) 物流跟踪平台，实现海运/空运数据的对接。本次为第一步：**海运运单批量订阅**。操作人员在系统中勾选多票 **海运出口**，一次性把这些票的提单号/订舱号/箱号提交给云当发起货物跟踪订阅；订阅成功后云当会返回订阅Id，系统落库保存，供后续「推送/下载」接口把跟踪动态回写到对应海运出口。

对接接口文档：

- 获取Token：`POST https://api.trackingeyes.com/api/auth/authorization` （<https://trackingeyes-cn.apifox.cn/api-221743604>）
- 批量运单订阅：`POST https://api.trackingeyes.com/api/oceanbill/batchOceanBill` （<https://trackingeyes-cn.apifox.cn/api-221743610>）

# 3. 核心逻辑变更 (Core Logic)

## 3.1 鉴权流程

> [!NOTE] 鉴权方式已调整为经**中转站**统一下发，详见《云当对接-中转站与推送接收-2026-07-02.md》。以下为最新口径。

1. 云当密钥(`companyCode`/`secret`/`orgCode`)只配置在**中转站**，业务服务器 `appsettings.json` 仅配 `Relay:BaseUrl` + `Relay:Token`。
2. 业务服务器带 `X-Relay-Token` 向中转站 `GET /relay/yundang/token` 获取 `token` 及 `params:{companyCode,orgCode}`。
3. token/companyCode/orgCode 采用 **进程内静态缓存**（`SemaphoreSlim` 加锁，双检）；调用云当业务接口时把 `companyCode/token/orgCode` 拼到 **Query 参数**。

## 3.2 批量订阅接口 `BatchSubscribeOceanBillAsync`

- 入参：`SeaExportIds`(海运出口Id集合)。
- 订阅方式由海运出口数据自动判断（参照[云当批量运单订阅接口](https://trackingeyes-cn.apifox.cn/api-221743610)）：
  - `BLType=整箱(0)`：`referenceNo`=主提单号 `MblNum`，`carrierCd`=船公司代码，`blType`=""
  - 其他装运方式：`referenceNo`=第一个箱号，`carrierCd`=船公司代码，`blType`=""
- **服务类型(serviceType)与 polCd 自动判断（综合接口优先）**：
  - 起运港 `SeaExport.POL.EdiCode`(港口云当代码)命中综合支持清单 → **综合订阅**：`serviceType`="CT"、`polCd`=起运港 EDI 代码、场景 `Comprehensive`。
  - 起运港未维护 EDI 代码、或不在清单内 → 回退**普通订阅**：`serviceType`="C"、不传 `polCd`、场景 `Normal`。
  - 综合支持清单(10 个码头，硬编码常量 `ComprehensiveSupportedPolCds`)：厦门 `CNXMN`、上海 `CNSHA`、宁波 `CNNGB`、盐田 `CNYTN`、蛇口 `CNSHK`、大铲湾 `CNDCB`、南沙 `CNCAN`、青岛 `CNTAO`、天津新港 `CNTXG`、大连 `CNDLC`。
  - `polCd` **必须使用港口 EDI 代码字段** `PortCode.EdiCode`（不是港口五字码/主键）。
- 逐票组装订阅明细 → 本地校验失败的直接作为失败结果返回（不提交云当）→ 有效明细 **每 30 条一批** 提交云当 → 结果回写并落库。
- `carrierCd` 取 `Carrier.Code`(退化 EdiCode/OtherCode)；`localKey` = 海运出口Id 的无连字符字符串，便于推送回传定位。
- 重新订阅接口 `ResubscribeOceanBillAsync` 复用同一 `BuildItem`，服务类型判断规则一致。

## 3.3 装运方式与订阅参数

| BLType | 装运方式          | referenceNo 取值                  |
| :----- | :---------------- | :-------------------------------- |
| 0      | 整箱              | `TransportOrder.MblNum`(主提单号) |
| 1/2    | 拼箱主票/拼箱分票 | `OrderCtn.CtnNo`(第一个箱号)      |

## 3.4 落库

- 表 `App_YundangOceanSubscriptions` 保存每条订阅的入参、云当返回Id(`YundangId`)、跟踪状态、结果/错误信息。
- **原始报文留痕**（每次订阅/重新订阅覆盖为最新）：
  - `SubscribeRequestJson`：本次实际发给云当的**请求参数**原始JSON(单条订阅明细，含 `localKey`/`referenceNo`/`carrierCd`/`blType`/`ctnrNo`/`serviceType`/`polCd`/`extendNo`/`noticeEmail`/`customer`)。
  - `SubscribeResponseJson`：本次云当返回的**结果**原始JSON(单条 `result` 元素)；请求整体失败(无 `result`)时为空，失败原因见 `ErrorMessage`。
- 判重键：`SeaExportId + ReferenceNo + CarrierCd + CtnrNo`，重复订阅则更新（与云当「localKey+referenceNo+carrierCd 判重」一致）。
- `TenantId` 由 ABP 自动填充（`IMustHaveTenant`）。

# 4. 避坑指南 (Blockers)

> [!IMPORTANT]
>
> 1. **云当密钥配置在中转站**(`Relay:Providers:yundang`)，业务服务器仅需配 `Relay:BaseUrl`/`Relay:Token`；未配置中转站地址接口会直接报错。
> 2. **单次最多 30 条**：超出会自动分批，单批异常不影响其它批次。
> 3. **箱号来源**：一票多柜/历史箱/SINO 等场景依赖 `OrderCtn.CtnNo`，海运出口无箱号信息将被判为失败。
> 4. **`AUTO` / `CT` 需云当额外开通服务**，未开通会由云当返回失败。
> 5. **迁移文件未生成**：新增实体 `YundangOceanSubscription` 的 EF Core 迁移请自行生成后更新数据库。
> 6. token 为 **进程内静态缓存**，多实例部署时各实例各自持有，均在 2 小时内有效，无需共享。
> 7. **综合订阅(CT)仅支持 10 个码头**：判断依据是起运港 **EDI 代码** `PortCode.EdiCode`，不在清单内自动回退普通订阅(C)。若云当后续调整支持码头，改常量 `ComprehensiveSupportedPolCds` 即可（改动需发版）。起运港 EDI 代码务必与云当港口代码一致(如 `CNSHA`)。
