# 1. 说明

本文档面向前端，汇总云当(Trackingeyes)相关**前端需对接的接口**（均在 `YundangAdminAppService` 中）。token 获取、中转站、推送接收/回写等均由后端处理，前端无需关心。

> 完整的架构/Token 中转/推送接收说明见：`云当对接-中转站与推送接收.md`、`云当对接-海运运单批量订阅.md`、`云当对接-海运运单推送信息查询.md`

# 2. 接口清单

| 接口 | 用途 | 章节 |
| :-- | :-- | :-- |
| `BatchSubscribeOceanBillAsync` | 海运运单批量订阅 | 见「3. 海运运单批量订阅」 |
| `ResubscribeOceanBillAsync` | 海运运单重新订阅 | 见「5. 海运运单重新订阅」 |
| `GetOceanPushInfoAsync` | 查询某海运出口的云当订阅与运单动态 | 见「4. 查询云当推送信息」 |

> 后续云当其它接口(如空运等)接入后，在本文档继续追加章节。

# 3. 海运运单批量订阅 (BatchSubscribeOceanBillAsync)

## 3.1 接口

| 项目   | 内容                                                           |
| :----- | :------------------------------------------------------------- |
| 方法   | `POST`                                                         |
| 地址   | `/api/services/app/YundangAdmin/BatchSubscribeOceanBillAsync`  |
| 请求体 | JSON，见「3.2 请求参数」                                       |
| 返回   | JSON，见「3.3 返回结构」(ABP 统一包一层 `result`)              |
| 权限   | 需登录且具备「第三方接口 > 使用」权限(`Admin.ExternalApi.Use`) |

## 3.2 请求参数 (YundangOceanBatchSubscribeInputDto)

| 字段名 | 类型 | 含义 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| **seaExportIds** | Guid[] | 待订阅的海运出口Id集合 | 是 | 单次最多 30 条，超出后端会自动分批提交 |

> 订阅方式由后端根据海运出口数据自动判断，前端无需传场景/单号类型/服务类型等参数：
>
> - `BLType=0`(整箱)：按**船公司 + 主提单号**订阅
> - 其他装运方式：按**船公司 + 第一个箱号**订阅
> - **服务类型自动判断**：起运港的云当代码(港口 EDI 代码)命中综合支持清单时走**综合订阅**(`serviceType=CT`，并上传 `polCd`=起运港 EDI 代码)，否则回退**普通订阅**(`serviceType=C`)。
>   - 综合订阅当前仅支持 10 个码头：厦门(CNXMN)、上海(CNSHA)、宁波(CNNGB)、盐田(CNYTN)、蛇口(CNSHK)、大铲湾(CNDCB)、南沙(CNCAN)、青岛(CNTAO)、天津新港(CNTXG)、大连(CNDLC)。
>   - 起运港未维护 EDI 代码、或不在上述清单内，均自动回退普通订阅。

**请求示例：**

```json
{
  "seaExportIds": ["11111111-1111-1111-1111-111111111111"]
}
```

## 3.3 返回结构 (YundangOceanBatchSubscribeResultDto)

| 字段名       | 类型  | 含义                                     |
| :----------- | :---- | :--------------------------------------- |
| totalCount   | int   | 请求总条数(实际提交给云当的订阅明细数)   |
| successCount | int   | 订阅成功条数                             |
| failCount    | int   | 订阅失败条数                             |
| items        | array | 各明细订阅结果，元素见「3.3.1 明细结果」 |

### 3.3.1 明细结果 (items[] - YundangOceanSubscribeItemResultDto)

| 字段名 | 类型 | 含义 |
| :-- | :-- | :-- |
| seaExportId | Guid | 关联的海运出口Id |
| localKey | string | 本地业务键(海运出口Id无连字符+序号，如 `...859061`；序号从 localKey 后缀解析) |
| referenceNo | string | 订阅单号(referenceNo) |
| carrierCd | string | 船东代码(carrierCd) |
| ctnrNo | string | 指定箱号(ctnrNo) |
| isSuccess | bool | 是否订阅成功 |
| yundangId | string | 云当返回的订阅Id |
| resultType | string | 处理结果类型(如"订阅成功") |
| resultTypeCd | string | 处理结果类型代码(如 success) |
| trackStatus | string | 跟踪状态(如"跟踪中") |
| error | string | 错误代码(失败时) |
| errorMessage | string | 错误描述(失败时；本地校验未通过也会写入此处) |

## 3.4 注意事项

- **localKey 规则**：`localKey = 海运出口Id(无连字符) + 递增序号`，如 `2dd8823b62db4d6bb51985bd342859061`、`...062`。云当不接受重复 localKey，每次重新订阅序号+1。
- **业务关联以 YundangId 为准**：推送回写、运单动态查询均按云当返回的 `yundangId` 关联，**不使用 localKey**。
- **重复订阅**：同一海运出口、**同一订阅单号**且已成功 → 直接返回「当前单号已成功订阅」；**提单号/箱号变更**后可重新订阅（新 localKey + 新 YundangId）。
- 若此前订阅失败或未订阅，可再次调用；后端会更新 `App_YundangOceanSubscriptions` 表中对应记录。
- `seaExportIds` 单次最多 30 条，超出后端自动分批；建议前端也做批量大小提示。
- 一次请求中**部分成功部分失败**是正常的，需遍历 `items` 按 `isSuccess` 分别展示；失败原因看 `errorMessage`。
- 订阅成功后，运单动态由云当**推送**回写(后端自动处理)，前端订阅接口只负责发起订阅，不返回后续动态。
- 场景/单号类型的组合约束由后端根据海运出口 `BLType` 自动判断，传错数据会在对应明细返回失败提示。

## 4.4 注意事项

- 以 **`seaExportId`** 查订阅记录；运单动态按当前订阅的 **`yundangId`** 关联查询，**不使用 localKey**。
- `subscription` 为 `null` 表示尚未发起订阅；`subscription.isSuccess = false` 表示订阅失败，可结合 `errorMessage` 展示原因。
- `shipment` 为 `null` 表示云当尚未推送，或当前订阅尚无 `yundangId`；订阅成功后需等待云当推送。
- 本接口**不返回**原始 JSON 报文(`RawJson`/`LatestPushJson`)及 `YundangPushLog` 推送日志。
- 列表/详情接口 `SeaExportAdmin/GetPagedListAsync`、`DetailAsync` 已返回 `isYundangSubscribed`、`isYundangSubscribeSuccess`，可用于控制「订阅」按钮与「查看动态」入口的展示。

# 5. 海运运单重新订阅 (ResubscribeOceanBillAsync)

**仅支持单条**重新订阅。须已有订阅记录；每次使用新 `localKey` 提交云当。

## 5.1 接口

| 项目 | 内容 |
| :-- | :-- |
| 方法 | `POST` |
| 地址 | `/api/services/app/YundangAdmin/ResubscribeOceanBillAsync` |
| 请求体 | JSON，见「5.2 请求参数」 |
| 返回 | JSON，单条明细(`YundangOceanSubscribeItemResultDto`，ABP 包一层 `result`) |
| 权限 | 需登录且具备「第三方接口 > 使用」权限(`Admin.ExternalApi.Use`) |

**请求示例：**

```json
{
  "seaExportId": "11111111-1111-1111-1111-111111111111",
  "forceResubscribe": false
}
```

## 5.2 请求参数 (YundangOceanResubscribeInputDto)

| 字段名 | 类型 | 含义 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| **seaExportId** | Guid | 待重新订阅的海运出口Id | 是 | 须已有订阅记录 |
| **forceResubscribe** | bool | 是否强制重新订阅 | 否 | 见「5.4 业务规则」 |

## 5.3 返回结构

字段同「3.3.1 明细结果」，并额外包含：

| 字段名             | 类型  | 含义                                          |
| :----------------- | :---- | :-------------------------------------------- |
| yundangIdChanged   | bool? | 云当返回的 YundangId 相对上次是否变化         |
| oldPushDataCleared | bool  | 是否已清除原 YundangId 关联的运单动态推送数据 |

## 5.4 业务规则

按当前海运出口数据组装 `ReferenceNo`、`CarrierCd`，与已有订阅记录对比：

| 条件 | 行为 |
| :-- | :-- |
| 无订阅记录 | 返回「尚未订阅，请使用批量订阅接口」 |
| `ReferenceNo`、`CarrierCd` 均未变，且上次**已成功** | 返回 `errorMessage=已成功订阅禁止重新订阅`，不提交云当 |
| `ReferenceNo`、`CarrierCd` 均未变，且上次**失败**，且 `forceResubscribe=false` | 返回「订阅未成功，请勾选强制重新订阅后再试」 |
| `ReferenceNo`、`CarrierCd` 均未变，且上次**失败**，且 `forceResubscribe=true` | 允许重新订阅 |
| `ReferenceNo` 或 `CarrierCd` 有变化 | 允许重新订阅（视为订阅数据已更新） |

其他：

- 每次重新订阅 **localKey 序号 +1**。
- **YundangId 变化**：删除原 YundangId 关联的运单动态，清空 `LatestPushJson`/`LastPushTime`，再更新订阅字段。
- **YundangId 不变**：不删除推送数据，仅更新订阅字段(含 `localKey` 等)。
- **重新订阅失败**且此前已成功：保留原 `YundangId` 与推送数据。
