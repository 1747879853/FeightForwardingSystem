# 发票开出用-已提交开票申请列表（不分页）

## 1. 背景意图 (Background)

**白话解释：**

开票人在做"发票开出"（多个开票申请合并成一张发票）时，需要先看到一份"可选择的开票申请清单"。这份清单只应包含**已提交（待审核 `Auditing`）**的开票申请，且不分页（一次性全部返回，方便前端勾选合并）。

与"开票申请分页列表 `GetPagedListAsync`"不同，本接口面向"发票开出"这一场景，需要把每条开票申请的**费用明细**及其**费用 / 运输订单 / 海运出口**信息都带出来，方便开票人核对；同时由于**发票汇率会随时间变动**，需要给出一个"金额是否仍然匹配"的标记，提示金额是否需要重新调整。

## 2. 核心逻辑变更 (Core Logic)

### 新增接口

`InvoiceIssueAdminAppService.GetSubmittedApplicationListAsync(InvoiceIssueApplicationQueryDto input)`

- 路由：`GET /api/services/app/InvoiceIssueAdmin/GetSubmittedApplicationListAsync`
- 权限：`Admin.InvoiceIssue.Get`
- 返回：`List<InvoiceIssueApplicationDto>`（**不分页**）

### 数据来源与过滤

- 仅查询 `InvoiceApplication.Status == Auditing`（已提交/待审核）。
- 支持可选过滤：`applicationNo`（模糊）、`settlementId`、`currencyId`、`invoiceType`、`applyTimeStart`/`applyTimeEnd`（申请时间范围）、`applyUserId`（申请人）、`header`（抬头模糊）、`orgId`（按组织下用户过滤）。
- **抬头过滤**：抬头存在于 `ClientInvoiceInfo.Header`。通过 `ClientInvoiceBank` 子查询 `b.ClientInvoiceInfo.Header.Contains(header)` 得到匹配的 `bankId` 集合，再以 `InvoiceApplication.ClientInvoiceBankId ∈ 集合` 过滤（`ClientInvoiceBankId` 对应的 `ClientInvoiceBank.ClientInvoiceInfoId` 即目标 `ClientInvoiceInfo`）。
- 走 `DataPermissionFilterAsync` 数据权限过滤，按 `applyTime` 倒序。

### 输出结构（与开票申请详情相似，但差异如下）

- **不返回** 按运输订单分组的 `FeeGroups`。
- 返回扁平的费用明细 `invoiceApplicationItems`（`List<InvoiceApplicationItemDetailDto>`）：
  - 每条含 `orderFee`（`OrderFeeDto`）；
  - `orderFee` 返回对应的 `transportOrder`（`TransportOrderSimpleDto`）与 `seaExport`（`SeaExportSimpleDto`）。
- 返回商品明细 `invoiceApplicationGoodsDtls`（`List<InvoiceApplicationGoodsDtlDto>`）。

### 金额匹配判断（关键）

每条开票申请按**当前**发票汇率折算并判断是否匹配：

```
totalAppliedAmount = Σ invoiceApplicationItems.appliedAmount   // 原币
totalGoodsAmount   = Σ invoiceApplicationGoodsDtls.amount        // 人民币
appliedAmountRmb   = Math.Round(totalAppliedAmount × InvoiceValue, 2, AwayFromZero)
amountMatched      = 有有效发票汇率 && (totalGoodsAmount == appliedAmountRmb)
```

- 无有效发票汇率时 `appliedAmountRmb = null`、`amountMatched = false`。
- 该折算/四舍五入规则与开票申请"新增 / 编辑"时的校验完全一致（保证一处口径）。

### DTO 变更

- 新增 `InvoiceIssueApplicationQueryDto`（查询入参）、`InvoiceIssueApplicationDto`（输出）到 `InvoiceIssueDto.cs`。
- 为共享的 `OrderFeeDto` 新增 `SeaExport`（`SeaExportSimpleDto`）字段：**按需填充**，仅本接口会赋值，其他复用 `OrderFeeDto` 的场景保持 `null`，AutoMapper 无对应源成员不会报错。

## 3. 避坑指南 (Pitfalls)

- **"已提交"= `Auditing`**：本系统开票申请提交审核后进入 `Auditing`（待审核）即视为"已提交/可开票"，不要误判为其他状态。
- **`SeaExport.Id == TransportOrderId`**：海运出口与运输订单主键相同，按 `TransportOrderId` 反查 `SeaExport` 即可，无需额外外键。
- **`amountMatched` 依赖"当前"汇率**：创建开票申请时金额是匹配的，但发票汇率变动后再开票就可能不匹配，务必用当前有效汇率重新折算判断，不能沿用历史值。
- **性能**：费用的"已开票金额 / 发票申请金额"聚合采用**批量分组查询**（跨全部 `orderFeeId` 一次查询），避免逐条 N+1。
- **`OrderFeeDto` 污染最小化**：新增的 `SeaExport` 是可空扩展字段，不影响既有映射；请勿在其他场景强行赋值。
- **不分页**：本接口无 `pageIndex/pageSize`，直接返回 `List<...>`；若后续数据量增大需分页，请另建带 `PagedList` 的接口。
