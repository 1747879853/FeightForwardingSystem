# 发票开出-编辑拆分-前端对接文档-2026-07-24

路由前缀：`/api/services/app/InvoiceIssueAdmin`  
权限：`Admin.InvoiceIssue.Edit`（下列三个新接口）

> 原 `PUT EditAsync`（全量替换）**保留不变**，新页面建议改用下列拆分接口。

---

## 1. 仅编辑主表 — `PUT /api/services/app/InvoiceIssueAdmin/EditMainAsync`

### 入参 `InvoiceIssueEditMainDto`

| 字段 | JSON | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 主键 | `id` | Guid | 是 | 发票开出ID |
| 所属组织 | `orgId` | long? | 是 | 须为数据所属人直属组织 |
| 开出方式 | `invoiceIssueType` | InvoiceIssueType | 是 | 0诺诺 / 1手动 |
| 发票号 | `invoiceNo` | string | 否 | 变更时同步回填已关联开票申请 |
| 开票时间 | `invoiceIssueTime` | DateTime | 是 | — |
| 开票要求 | `require` | string | 否 | — |
| 备注 | `remark` | string | 否 | — |

### 出参
`bool`

### 说明
不改开票申请明细、不改商品明细。

---

## 2. 新增多条开票申请 — `POST /api/services/app/InvoiceIssueAdmin/AddApplicationsAsync`

### 入参 `InvoiceIssueAddApplicationsDto`

| 字段 | JSON | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 主键 | `id` | Guid | 是 | 发票开出ID |
| 新增明细 | `invoiceIssueItems` | List | 是 | 至少一条；不可与已关联重复 |
| 商品明细 | `invoiceIssueGoodsDtls` | List | 是 | **合并后全部申请**对应的完整商品明细 |

`invoiceIssueItems[]`：`invoiceApplicationId`(Guid)、`remark`(string?)  
`invoiceIssueGoodsDtls[]`：同新增接口商品字段（codeInvoiceId、quantity、unitPrice、amount、noTaxAmount、taxRate、taxAmount 等）

### 出参
`bool`

### 业务规则
- 新申请须为待审核(已提交)，且未被其他发票开出占用。
- 与已有申请四要素一致（结算对象/发票类型/币别/我司银行）。
- 商品三项合计须与**现有+新增**全部开票申请商品合计相等；不一致时分别提示金额 / 不含税金额 / 税额合计不一致。
- 成功后：插入关联、全量替换商品明细、新申请改已开票并回填本单发票号、回写费用开票状态。

---

## 3. 移除多条开票申请 — `PUT /api/services/app/InvoiceIssueAdmin/RemoveApplicationsAsync`

### 入参 `InvoiceIssueRemoveApplicationsDto`

| 字段 | JSON | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 主键 | `id` | Guid | 是 | 发票开出ID |
| 申请ID列表 | `invoiceApplicationIds` | Guid[] | 是 | 要移除的开票申请，至少一条 |
| 商品明细 | `invoiceIssueGoodsDtls` | List | 是 | **剩余申请**对应的完整商品明细 |

### 出参
`bool`

### 业务规则
- 须属于本发票开出；移除后至少保留 1 条申请。
- 商品合计与剩余申请一致。
- 若申请已被收费结算引用则禁止移除（反开票校验）。
- 成功后：删关联、全量替换商品、申请回退待审核并清空发票号、回写费用开票状态。
