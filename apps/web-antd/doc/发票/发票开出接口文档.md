# 发票开出接口文档

**控制器**：`InvoiceIssueAdmin`

**所有接口均需要登录认证**

---

# 1. 业务背景说明 (Background)

**白话解释：** 开票申请（`InvoiceApplication`）经提交审核后，可由开票人合并成一张实际开出的发票，即"发票开出"（`InvoiceIssue`）。

- 多个开票申请可以合并成一个发票开出，但这些开票申请的 `SettlementId`（结算对象）、`InvoiceType`（发票类型）、`CurrencyId`（币别）、`OrgBankAccountId`（我司银行）必须完全相同，否则不允许合并。
- 开票申请的商品明细与发票开出商品明细的 `Amount`（金额）、`NoTaxAmount`（不含税金额）、`TaxAmount`（税额）三个字段，其合计必须分别相等；不一致时分别提示「金额合计不一致」「不含税金额合计不一致」「税额合计不一致」（含双方合计数值）。
- 发票开出新建成功后，关联的开票申请状态会被改为"已开票"（`Invoiced`）。

# 2. 数据结构

- 主表：`InvoiceIssue`（发票开出）
- 子表1：`InvoiceIssueItem`（发票开出明细，关联开票申请）
- 子表2：`InvoiceIssueGoodsDtl`（发票开出商品明细）

## 一、新增发票开出

### `POST /api/services/app/InvoiceIssueAdmin/AddAsync`

**权限**：`Admin.InvoiceIssue.Add`

**入参** `InvoiceIssueAddDto`（Body JSON）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `invoiceIssueType` | `InvoiceIssueType` | 是 | 发票开出方式：0=接口开票，1=手动记录 |
| `invoiceNo` | `string` | 否 | 发票号 |
| `invoiceIssueTime` | `DateTime` | 是 | 开票时间 |
| `require` | `string` | 否 | 开票要求 |
| `remark` | `string` | 否 | 备注 |
| `invoiceIssueItems` | `List<InvoiceIssueItemInputDto>` | 是 | 合并的开票申请（至少一条） |
| `invoiceIssueGoodsDtls` | `List<InvoiceIssueGoodsDtlInputDto>` | 是 | 发票开出商品明细（至少一条） |

`InvoiceIssueItemInputDto`：

| 字段                   | 类型     | 必填 | 说明       |
| ---------------------- | -------- | ---- | ---------- |
| `invoiceApplicationId` | `Guid`   | 是   | 开票申请ID |
| `remark`               | `string` | 否   | 备注       |

`InvoiceIssueGoodsDtlInputDto`：

| 字段            | 类型      | 必填 | 说明           |
| --------------- | --------- | ---- | -------------- |
| `codeInvoiceId` | `long`    | 是   | 发票商品编码ID |
| `specification` | `string`  | 否   | 规格型号       |
| `unit`          | `string`  | 否   | 发票单位       |
| `quantity`      | `decimal` | 是   | 数量           |
| `unitPrice`     | `decimal` | 是   | 含税单价       |
| `amount`        | `decimal` | 是   | 金额           |
| `noTaxAmount`   | `decimal` | 是   | 不含税金额     |
| `taxRate`       | `decimal` | 是   | 税率(%)        |
| `taxAmount`     | `decimal` | 是   | 税额           |
| `remark`        | `string`  | 否   | 备注           |

**出参**：`Guid`（新建的发票开出ID）

**业务规则（校验）**：

- `invoiceIssueItems`、`invoiceIssueGoodsDtls` 均不能为空，开票申请不能重复。
- 所有开票申请必须存在，且未被其他发票开出关联。
- 开票申请状态必须为"待审核（已提交）"（`Auditing`）。
- 所有开票申请的 `SettlementId`、`InvoiceType`、`CurrencyId`、`OrgBankAccountId` 必须一致，否则报错。
- 开票申请商品明细与发票开出商品明细的 `Amount`、`NoTaxAmount`、`TaxAmount` 三项合计需分别相等；不一致时分别提示「金额合计不一致」「不含税金额合计不一致」「税额合计不一致」。
- 主表的 `SettlementId`、`InvoiceType`、`CurrencyId`、`OrgBankAccountId`、`ClientInvoiceBankId`、`OrgId`（归属组织id）取自开票申请（已校验一致）。
- 开出单号 `ApplicationNo` 由编号生成规则（`InvoiceIssue.ApplicationNo`）自动生成。
- 新建成功后，关联的开票申请状态改为"已开票"（`Invoiced`）。

## 二、修改发票开出

### `PUT /api/services/app/InvoiceIssueAdmin/EditAsync`

**权限**：`Admin.InvoiceIssue.Edit`

**入参** `InvoiceIssueEditDto`（Body JSON）：在 `InvoiceIssueAddDto` 基础上增加：

| 字段 | 类型   | 必填 | 说明       |
| ---- | ------ | ---- | ---------- |
| `id` | `Guid` | 是   | 发票开出ID |

**出参**：`bool`

**业务规则**：

- 子表（开票申请明细、商品明细）全量替换。
- 校验逻辑同新增（排除自身的关联校验）。
- 新关联的开票申请改为"已开票"；被移除的开票申请回退为"待审核"（`Auditing`）。
- **兼容保留**；局部改主表/加减申请请用下列拆分接口（见 `发票开出-编辑拆分-前端对接文档-2026-07-24.md`）。

### `PUT /api/services/app/InvoiceIssueAdmin/EditMainAsync`

**权限**：`Admin.InvoiceIssue.Edit`

**入参** `InvoiceIssueEditMainDto`：`id`、`orgId`、`invoiceIssueType`、`invoiceNo`、`invoiceIssueTime`、`require`、`remark`

**出参**：`bool`

**业务规则**：仅更新主表；不改开票申请/商品明细；`invoiceNo` 变更时同步回填已关联开票申请。

### `POST /api/services/app/InvoiceIssueAdmin/AddApplicationsAsync`

**权限**：`Admin.InvoiceIssue.Edit`

**入参** `InvoiceIssueAddApplicationsDto`：`id`、`invoiceIssueItems`（本次新增）、`invoiceIssueGoodsDtls`（合并后完整商品明细）

**出参**：`bool`

**业务规则**：与已有申请合并后做四要素与金额校验；全量替换商品明细；新申请改已开票。

### `PUT /api/services/app/InvoiceIssueAdmin/RemoveApplicationsAsync`

**权限**：`Admin.InvoiceIssue.Edit`

**入参** `InvoiceIssueRemoveApplicationsDto`：`id`、`invoiceApplicationIds`、`invoiceIssueGoodsDtls`（剩余完整商品明细）

**出参**：`bool`

**业务规则**：移除后至少保留一条；金额与剩余申请一致；反开票结算引用校验；申请回退待审核。

| `invoiceApplicationItems` | `List<InvoiceApplicationItemDetailDto>` | 费用明细（扁平，不分组） |
| `invoiceApplicationGoodsDtls` | `List<InvoiceApplicationGoodsDtlDto>` | 商品明细 |

`InvoiceApplicationItemDetailDto`：含 `id`、`invoiceApplicationId`、`orderFeeId`、`appliedAmount`、`remark`、`remainingInvoiceAmount`（剩余最大可开票金额，不含本条申请）及 `orderFee`（`OrderFeeDto`）。

`OrderFeeDto`（费用详情）：除费用自身字段（`amount`、`currencyId`、`taxRate`、`paySide`、`feeStatus` 等）及 `feeCodeName`、`currencyCode`、`settlementName`、`invoicedAmount`、`orderInvoiceAmount`、`unInvoicedAmount` 外，返回：

- `transportOrder`（`TransportOrderSimpleDto`）：含 `id`、`userId`、`commissionNum`、`mblNum`、`bookingNum`、`clientName`、`etd`，以及嵌套的 `seaExport`（`SeaExportSimpleDto`）。
  - `transportOrder.seaExport`：含 `id`、`vessel`、`innerVoyno`、`pol`（`PortCodeSimpleDto`）、`pod`（`PortCodeSimpleDto`）、`carrier`（`CarrierSimpleDto`）；无运输订单时为 `null`。
  - **注意**：海运出口在 `orderFee.transportOrder.seaExport`，**不在** `orderFee.seaExport`（`OrderFeeDto` 无该字段）。
  - `pol`/`pod` 含 `id`、`portName`、`cnName`；`carrier` 含 `id`、`cnName`、`cnShortName`、`enName`、`code`（英文简称）、`ediCode`（已无扁平 `polId`/`polName`/`carrierId`/`carrierName`）。

**核心业务卡点（汇率变动导致金额不匹配）**：

> [!IMPORTANT] 开票申请创建时，商品明细金额合计（人民币）= 费用明细申请金额合计（原币）× 当时的发票汇率。由于发票汇率会随时间变动，开出发票时若汇率已变，则 `totalGoodsAmount ≠ appliedAmountRmb`，此时 `amountMatched = false`，前端需提示用户金额已不匹配（一般需要退回重新调整商品明细或汇率）。

| `99` | 冲红完成 | 终态 | "已冲红"（红/灰）+ 展示红票号与红票附件 |

### `POST /api/services/app/InvoiceIssueAdmin/QueryRedResultAsync`

**权限**：`Admin.InvoiceIssue.Edit`

主动查一次冲红进度。这个接口不只是"查"——它会顺带把整条链路往前推：

1. 查红字确认单的最新状态
2. 确认单已生效且是**纸票**时，自动调冲红接口开红票
3. 红票已开出时，回填红票号码/发票代码/开票日期并**存红票附件**

所以调完这个接口再刷详情就能看到红票号和红票附件了。

**入参** `InvoiceIssueIdInputDto`（Body JSON）：

| 字段 | 类型   | 必填 | 说明       |
| ---- | ------ | ---- | ---------- |
| `id` | `Guid` | 是   | 发票开出ID |

**出参**：同 `InvoiceIssueRedStateDto`（见上）。
