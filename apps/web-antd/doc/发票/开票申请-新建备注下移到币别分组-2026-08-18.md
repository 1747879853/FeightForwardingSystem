# 1. 背景意图 (Background)

`AddAsync` 一次可传多个币别，后端按币别各生成一条 `InvoiceApplication`。原来备注 `Remark` 只在根层 `InvoiceApplicationBatchAddDto` 上，所有币别被强制写入同一段备注。实际业务里每个币别的开票申请备注是各自独立的，因此把 `Remark` 下移到 `InvoiceApplicationCurrencyGroupDto`。

# 2. 核心逻辑变更 (Core Logic)

## 2.1 影响接口

| 接口 | 地址 |
| :-- | :-- |
| 新建开票申请（批量-按币别分组） | `POST /api/services/app/InvoiceApplicationAdmin/AddAsync` |

## 2.2 入参结构变化

| DTO | 字段 | 变化 |
| :-- | :-- | :-- |
| `InvoiceApplicationBatchAddDto` | `Remark` | **移除** |
| `InvoiceApplicationCurrencyGroupDto` | `Remark` | **新增**（`string`，可空，每个币别各自独立） |

`Require`（开票要求）保持在根层不变，仍为所有分组共用。

## 2.3 写入逻辑

生成每个币别的 `InvoiceApplication` 时，`Remark` 取自当前分组：

```text
data.Remark = currencyGroup.Remark   // 原为 input.Remark
```

# 3. 避坑指南 (Pitfalls)

- **前端必须同步改造**：`remark` 从根节点移到 `currencyGroups[i]` 下，旧结构继续传根层 `remark` 会被忽略，生成的开票申请备注为空。
- `EditAsync` / `EditMainAsync` 的 `remark` 仍在根层（单条编辑，天然只对应一个币别），本次不动。
