# 1. 背景意图 (Background)

新建开票申请时经常是「先跟客户对完账，再按这张对账单开票」。原来拉取可开票费用只能按委托编号/主提单号/订舱编号等业务字段找，无法按对账单号一次性把这张对账单里的费用捞出来，只能人工比对，容易漏费用。

# 2. 核心逻辑变更 (Core Logic)

## 2.3 过滤实现

对账关系在子表 `App_StatementFees`（一条费用可被多张对账单包含），因此走 `OrderFee.StatementFees` 导航反查，命中任意一张对账单即保留：

```csharp
.WhereIf(!string.IsNullOrWhiteSpace(input.StatementNum),
    x => x.StatementFees.Any(sf => sf.Statement.StatementNum.Contains(input.StatementNum)))
```

条件挂在与其它业务字段同一条 `WhereIf` 链上，与剩余可开票额度、审核中费用排除、数据权限过滤等既有条件是**与**关系。

# 3. 避坑指南 (Pitfalls)

- **不要用 `StatementId` 单表等值查**：一条费用可进多张对账单，且需求是按单号模糊搜，必须走子表 `Any` + `Contains`。
- 软删除的对账单与对账明细由 ABP 全局查询筛选器自动排除，不需要也不应手写 `IsDeleted` 判断。
- 该条件只做**筛选**，不改变分组维度：分页仍以 `TransportOrder` 为单位，命中的费用按所属业务分组返回。
- 同一业务下未进该对账单的费用会被过滤掉，所以搜出来的分组里费用条数可能少于该业务的全部可开票费用，这是预期行为。
