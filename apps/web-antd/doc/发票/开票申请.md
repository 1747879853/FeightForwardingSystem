## 一、拉取剩余未开票金额>0的费用（按业务分组）

### `GET /api/services/app/InvoiceApplicationAdmin/GetOrderFeeGroupAsync`

**权限**：`Admin.InvoiceApplication.Get`

**入参** `InvoiceApplicationFeeQueryDto`（Query参数）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `invoiceApplicationId` | `Guid?` | 否 | 开票申请ID（编辑时传入，排除此申请已关联的费用） |
| `commissionNum` | `string` | 否 | 委托编号（模糊） |
| `mblNum` | `string` | 否 | 主提单号（模糊） |
| `bookingNum` | `string` | 否 | 订舱编号（模糊） |
| `settlementId` | `Guid?` | 否 | 结算单位ID（费用的） |
| `currencyId` | `long?` | 否 | 币别ID |
| `bizType` | `BizType?` | 否 | 业务类别 |
| `carrierId` | `long?` | 否 | 船公司ID |
| `clientId` | `Guid?` | 否 | 委托单位ID（TransportOrder的） |
| `etdStart` | `DateTime?` | 否 | 开船日期起 |
| `etdEnd` | `DateTime?` | 否 | 开船日期止 |
| `saleId` | `long?` | 否 | 销售ID |
| `accountDateStart` | `DateTime?` | 否 | 会计期间起 |
| `accountDateEnd` | `DateTime?` | 否 | 会计期间止 |
| `operationId` | `long?` | 否 | 操作ID |
| `feeCreatorUserId` | `long?` | 否 | 录入人ID（费用的CreatorUserId） |
| `polId` | `long?` | 否 | 起运港ID |
| `podId` | `long?` | 否 | 目的港ID |
| `vessel` | `string` | 否 | 船名（模糊） |
| `innerVoyno` | `string` | 否 | 航次（模糊） |
| `orgId` | `long?` | 否 | 组织ID（通过TransportOrder的UserId查询） |
| `pageIndex` | `int` | 是 | 当前页码（从1开始） |
| `pageSize` | `int` | 是 | 每页条数 |
| `sorting` | `string` | 否 | 排序字段 |

**出参** `PagedList<InvoiceApplicationFeeGroupOutputDto>`：

```json
{

      "transportOrder": {

        "polId": 1,

        "podName": "洛杉矶",
        "carrierId": 1,
        "carrierName": "COSCO"
      },
      "orderFees": [
        {
          "id": "fee-guid",
          "feeCodeName": "海运费",
          "currencyId": 1,
          "currencyCode": "CNY",

        }

```

**业务规则**：

- 不限制收付类型（收付均可，支持互抵，总额=收-付）
- 只返回审核通过（FeeStatus=Passed）且允许开票（CanInvoice=true）的费用
- 已开票金额(InvoicedAmount) = Sum(AppliedAmount) WHERE InvoiceApplication.Status=Invoiced（仅已开票状态）
- 发票申请金额(OrderInvoiceAmount) = Sum(AppliedAmount)（包含所有状态的开票申请）
- 剩余可开票金额 = 费用总金额 - 发票申请金额
- 如果传入 `invoiceApplicationId`，则排除该申请已关联的费用（编辑场景）
- 分页维度为 TransportOrder，`totalCount` 为符合条件的 TransportOrder 总数
- 通过 `orgId` 查询时，使用 `GetUserIdsByOrgIdCacheAsync` 获取组织下所有用户ID，通过 TransportOrder.UserId 进行过滤
- 通过 `saleId`/`operationId` 查询时，通过 OrderUser 表的 UserAttribute 枚举进行匹配

## 二、新增开票申请（批量-按币别分组）

### `POST /api/services/app/InvoiceApplicationAdmin/AddAsync`

**权限**：`Admin.InvoiceApplication.Add`

**入参** `InvoiceApplicationBatchAddDto`（Body JSON）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `settlementId` | `Guid` | 是 | 结算对象ID（Client表） |
| `companyId` | `long` | 是 | 所属公司（OrganizationUnit的Id，需验证IsCompany=true） |
| `require` | `string` | 否 | 开票要求 |
| `remark` | `string` | 否 | 备注 |
| `currencyGroups` | `List<InvoiceApplicationCurrencyGroupDto>` | 是 | 按币别分组的子表数据，每组生成一个InvoiceApplication |

**`InvoiceApplicationCurrencyGroupDto`**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `currencyId` | `long` | 是 | 币别ID |
| `invoiceType` | `string` | 否 | 发票类型（p=普通发票(电票)(默认)，c=普通发票(纸票)，s=专用发票），每个币别各自独立 |
| `invoiceApplicationItems` | `List<InvoiceApplicationItemAddDto>` | 是 | 本币别下的费用明细列表 |
| `invoiceApplicationGoodsDtls` | `List<InvoiceApplicationGoodsDtlAddDto>` | 否 | 本币别下的商品明细列表 |
| `orgBankAccountId` | `Guid?` | 否 | 我司银行ID，不传则取对应币别的默认银行 |
| `clientInvoiceBankId` | `Guid?` | 否 | 客户银行ID，不传则取对应币别的默认银行 |

**`InvoiceApplicationItemAddDto`**：

| 字段            | 类型      | 必填 | 说明                               |
| --------------- | --------- | ---- | ---------------------------------- |
| `orderFeeId`    | `Guid`    | 是   | 费用ID                             |
| `appliedAmount` | `decimal` | 是   | 本次申请金额（可为负数，用于冲红） |
| `remark`        | `string`  | 否   | 备注                               |

**`InvoiceApplicationGoodsDtlAddDto`**：

| 字段            | 类型      | 必填 | 说明           |
| --------------- | --------- | ---- | -------------- |
| `codeInvoiceId` | `long`    | 是   | 发票商品编码ID |
| `specification` | `string`  | 否   | 规格型号       |
| `unit`          | `string`  | 否   | 发票单位       |
| `quantity`      | `decimal` | 是   | 数量           |
| `unitPrice`     | `decimal` | 是   | 含税单价       |
| `amount`        | `decimal` | 是   | 金额           |
| `noTaxAmount`   | `decimal` | 是   | 不含税金额     |
| `taxRate`       | `decimal` | 是   | 税率(%)        |
| `taxAmount`     | `decimal` | 是   | 税额           |
| `remark`        | `string`  | 否   | 备注           |

**出参**：`List<Guid>` — 返回生成的所有 InvoiceApplication 的 ID 列表

```json
["guid-1", "guid-2"]
```

**业务规则**：

- 前端按币别预分组传入，每个 CurrencyGroup 生成一个 InvoiceApplication
- 验证每条费用的 CurrencyId 必须与其所在分组的 CurrencyId 一致
- 申请单号自动生成（GenerateNum，TableName="InvoiceApplication.ApplicationNo"）
- 验证 CompanyId 对应的 OrganizationUnit 的 IsCompany 必须为 true
- OrgBankAccountId 从传入映射或自动取 CompanyId 对应组织的该币别默认银行
- ClientInvoiceBankId 从传入映射或自动取 SettlementId 对应客户的该币别默认开票银行
- 每条费用的申请额不能大于该费用的剩余未开票额度（Amount - 所有其他申请的AppliedAmount之和）
- 商品明细的 Amount 合计必须等于同币别费用明细的 AppliedAmount 合计
- 使用 `UPDLOCK, ROWLOCK` 锁定 OrderFee 行防止并发验证问题（不再更新 OrderFee 的金额字段）
- **发票汇率验证**：验证每个币别在 ExchangeRate 表中存在当前时间有效的发票汇率（InvoiceValue），无则报错"未维护xxx币种的发票汇率，请先维护"

## 三、修改开票申请（单条）

### `PUT /api/services/app/InvoiceApplicationAdmin/EditAsync`

**权限**：`Admin.InvoiceApplication.Edit`

**入参** `InvoiceApplicationEditDto`（Body JSON）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `Guid` | 是 | 主键ID |
| `settlementId` | `Guid` | 是 | 结算对象ID |
| `companyId` | `long` | 是 | 所属公司 |
| `orgBankAccountId` | `Guid` | 是 | 我司银行ID |
| `clientInvoiceBankId` | `Guid` | 是 | 客户银行ID |
| `invoiceType` | `string` | 否 | 发票类型（p=普通发票(电票)，c=普通发票(纸票)，s=专用发票） |
| `require` | `string` | 否 | 开票要求 |
| `remark` | `string` | 否 | 备注 |
| `invoiceApplicationItems` | `List<InvoiceApplicationItemAddDto>` | 是 | 费用明细列表（全量替换） |
| `invoiceApplicationGoodsDtls` | `List<InvoiceApplicationGoodsDtlEditDto>` | 否 | 商品明细列表（全量替换） |

**出参**：`bool`

**业务规则**：

- 只有录入状态（Entering）或驳回状态（Rejected）才能修改
- 不可修改 ApplicationNo 和 InvoiceNo
- 不可修改 CurrencyId（币别在新建时确定）
- 费用明细和商品明细为全量替换（先删后插）
- 验证各外键有效性（同新增）
- 费用的 CurrencyId 必须与开票申请的 CurrencyId 一致
- 使用 `UPDLOCK, ROWLOCK` 锁定 OrderFee 行防止并发验证问题（不再更新 OrderFee 的金额字段）
- **发票汇率验证**：验证该币别在 ExchangeRate 表中存在当前时间有效的发票汇率（InvoiceValue），无则报错"未维护xxx币种的发票汇率，请先维护"

## 七、审核开票申请（仅驳回）

### `PUT /api/services/app/InvoiceApplicationAdmin/AuditAsync`

**权限**：`Admin.InvoiceApplication.Audit`

**入参** `InvoiceApplicationAuditDto`（Body JSON）：

| 字段           | 类型     | 必填 | 说明             |
| -------------- | -------- | ---- | ---------------- |
| `id`           | `Guid`   | 是   | 主键ID           |
| `rejectReason` | `string` | 是   | 驳回原因（必填） |

**出参**：`bool`

**业务规则**：

- 审核**只支持驳回**，不支持审核通过
- 设计理念：只要是已提交（Auditing）的开票申请即可开票；审核时只驳回有错误的，没问题的不处理
- 只有待审核状态（Auditing）才能驳回
- 驳回原因必填
- 驳回时：
  - 状态变为驳回（Rejected）
  - 记录驳回人（`RejectUserId` = 当前用户）、驳回时间（`RejectTime`）和原因（`RejectReason`）
  - 驳回后用户可以修改后重新提交

## 状态枚举

### InvoiceApplicationStatus

| 值  | 名称     | 说明                                                |
| --- | -------- | --------------------------------------------------- |
| 0   | Entering | 录入状态/未提交                                     |
| 1   | Auditing | 已提交/待审核（已提交即可开票，审核只驳回有问题的） |
| 2   | Rejected | 审核驳回                                            |
| 3   | Invoiced | 已开票（由后续开票操作设置，非审核设置）            |

### InvoiceType（发票类型，字符串）

| 值  | 说明                   |
| --- | ---------------------- |
| p   | 普通发票(电票)（默认） |
| c   | 普通发票(纸票)         |
| s   | 专用发票               |

> 新增时每个币别分组（CurrencyGroup）各自带一个 InvoiceType；修改时单条开票申请有一个 InvoiceType。
