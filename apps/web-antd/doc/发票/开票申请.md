**业务规则**：

- 不限制收付类型（收付均可，支持互抵，总额=收-付）
- 只返回审核通过（FeeStatus=Passed）且未禁开发票（InvoiceBlocked=false）的费用
- 已开票金额(InvoicedAmount) = Sum(AppliedAmount) WHERE InvoiceApplication.Status=Invoiced（仅已开票状态）
- 发票申请金额(OrderInvoiceAmount) = Sum(AppliedAmount)（包含所有状态的开票申请）
- 剩余可开票金额 = 费用总金额 - 发票申请金额
- 如果传入 `invoiceApplicationId`，则排除该申请已关联的费用（编辑场景）
- 传入 `statementNum` 时，按 `App_StatementFees` 反查：只保留**至少进过一张**对账单号命中该关键字的对账单的费用；一条费用可进多张对账单，命中任意一张即返回；已删除的对账单/对账明细不参与匹配
- `statements` 由 `IOrderFeeStatementFiller.GetStatementMapAsync` 统一产出，与业务费用、付费申请、客户对账等模块**同源同口径**；按对账单号升序；注意它**不受** `statementNum` 过滤影响，返回的是该费用进过的**全部**对账单
- 分页维度为 TransportOrder，`totalCount` 为符合条件的 TransportOrder 总数
- 通过 `orgId` 查询时，使用 `GetUserIdsByOrgIdCacheAsync` 获取组织下所有用户ID，通过 TransportOrder.UserId 进行过滤
- 通过 `saleId`/`operationId` 查询时，通过 OrderUser 表的 UserAttribute 枚举进行匹配
- `transportOrder.orgs` 通过 `SetDataPermissionPropsAsync` 按 `TransportOrder.UserId` 解析组织串（顶→底）
- **业务类型简要**按 `transportOrder.bizType` 挂在 `transportOrder` 下：海运出口=`seaExport`（`SeaExportSimpleDto`）、海运进口=`seaImport`（`SeaImportSimpleDto`）、空运出口=`airExport`（`AirExportSimpleDto`），三者互斥，非当前类型为 `null`；分组根上**无**独立 `seaExport` 字段
- **外键对象化**：除 User 表昵称平铺外，费用代码/币别/结算对象/委托单位/包装均返回 SimpleDto，不再返回 `feeCodeName`/`currencyCode`/`settlementName`/`clientName`/`codePackageName`

## 二、新增开票申请（批量-按币别分组）

### `POST /api/services/app/InvoiceApplicationAdmin/AddAsync`

**权限**：`Admin.InvoiceApplication.Add`

**入参** `InvoiceApplicationBatchAddDto`（Body JSON）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `settlementId` | `Guid` | 是 | 结算对象ID（Client表） |
| `orgId` | `long?` | 是 | 归属组织id（必填，须为所属人本人直属组织） |
| `require` | `string` | 否 | 开票要求 |
| `currencyGroups` | `List<InvoiceApplicationCurrencyGroupDto>` | 是 | 按币别分组的子表数据，每组生成一个InvoiceApplication |

**`InvoiceApplicationCurrencyGroupDto`**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `currencyId` | `long` | 是 | 币别ID |
| `invoiceType` | `string` | 否 | 发票类型（p=普通发票(电票)(默认)，c=普通发票(纸票)，s=专用发票），每个币别各自独立 |
| `remark` | `string` | 否 | 备注，每个币别各自独立，写入该币别 InvoiceApplication 的 `remark` |
| `invoiceApplicationItems` | `List<InvoiceApplicationItemAddDto>` | 是 | 本币别下的费用明细列表 |
| `invoiceApplicationGoodsDtls` | `List<InvoiceApplicationGoodsDtlAddDto>` | 否 | 本币别下的商品明细列表 |
| `orgBankAccountId` | `Guid?` | 否 | 我司银行ID，未传不校验不自动填充，提交审核时必填 |
| `clientInvoiceBankId` | `Guid?` | 否 | 客户银行ID，未传不校验不自动填充，提交审核时必填 |

**`InvoiceApplicationItemAddDto`**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `orderFeeId` | `Guid` | 是 | 费用ID |
| `appliedAmount` | `decimal` | 是 | 本次申请金额（可为负数，用于冲红；但不得小于 `-当前已占用额度`） |
| `remark` | `string` | 否 | 备注 |

**`InvoiceApplicationGoodsDtlAddDto`**：

| 字段            | 类型      | 必填 | 说明           |
| --------------- | --------- | ---- | -------------- |
| `codeInvoiceId` | `long`    | 是   | 发票商品编码ID |
| `specification` | `string`  | 否   | 规格型号       |
| `unit`          | `string`  | 否   | 发票单位       |
| `quantity`      | `decimal` | 是   | 数量           |
| `unitPrice`     | `decimal` | 是   | 含税单价       |
| `amount`        | `decimal` | 是   | 金额           |
| `noTaxAmount`   | `decimal` | 是   | 不含税金额     |
| `taxRate`       | `decimal` | 是   | 税率(%)        |
| `taxAmount`     | `decimal` | 是   | 税额           |
| `remark`        | `string`  | 否   | 备注           |

**出参**：`List<Guid>` — 返回生成的所有 InvoiceApplication 的 ID 列表

```json
["guid-1", "guid-2"]
```

**业务规则**：

- 前端按币别预分组传入，每个 CurrencyGroup 生成一个 InvoiceApplication
- `remark` 在**分组层**（每个币别一条备注）；`require` 仍在根层，所有分组共用
- 验证每条费用的 CurrencyId 必须与其所在分组的 CurrencyId 一致
- 申请单号自动生成（GenerateNum，TableName="InvoiceApplication.ApplicationNo"）
- 验证 OrgId 必填，且必须是数据所属人本人直属组织（完全相等，不判父子）
- OrgBankAccountId / ClientInvoiceBankId **可空**：未传则存 `null`，不自动取默认银行、不做存在性校验；传值时校验我司银行的 `OrganizationUnitId` 须等于 **orgId 所属公司**（组织串中最接近的 `IsCompany=true` 节点），客户银行须属于所选结算对象
- 每条费用的申请额必须落在合法区间内：最大值 = 该费用的剩余未开票额度（`Amount - 所有其他申请的AppliedAmount之和`）；最小值 = `-所有其他申请的AppliedAmount之和`（冲红后总占用不可小于 0）
- 商品明细的 Amount 合计必须等于同币别费用明细的 AppliedAmount 合计
- 使用 `UPDLOCK, ROWLOCK` 锁定 OrderFee 行防止并发验证问题（不再更新 OrderFee 的金额字段）
- **发票汇率验证**：验证每个币别在 ExchangeRate 表中存在当前时间有效的发票汇率（InvoiceValue），无则报错"未维护xxx币种的发票汇率，请先维护"

## 三、修改开票申请（单条）

### `PUT /api/services/app/InvoiceApplicationAdmin/EditAsync`

**权限**：`Admin.InvoiceApplication.Edit`

**入参** `InvoiceApplicationEditDto`（Body JSON）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `Guid` | 是 | 主键ID |
| `settlementId` | `Guid` | 是 | 结算对象ID |
| `orgId` | `long?` | 是 | 归属组织id（必填，须为所属人本人直属组织） |
| `orgBankAccountId` | `Guid?` | 否 | 我司银行ID，未传不校验，提交审核时必填；传 `null` 表示清空 |
| `clientInvoiceBankId` | `Guid?` | 否 | 客户银行ID，未传不校验，提交审核时必填；传 `null` 表示清空 |
| `invoiceType` | `string` | 否 | 发票类型（p=普通发票(电票)，c=普通发票(纸票)，s=专用发票） |
| `require` | `string` | 否 | 开票要求 |
| `remark` | `string` | 否 | 备注 |
| `invoiceApplicationItems` | `List<InvoiceApplicationItemAddDto>` | 否 | 费用明细列表（全量替换，可空） |
| `invoiceApplicationGoodsDtls` | `List<InvoiceApplicationGoodsDtlEditDto>` | 否 | 商品明细列表（全量替换，可空） |

**出参**：`bool`

**业务规则**：

- 只有录入状态（Entering）或驳回状态（Rejected）才能修改
- 不可修改 ApplicationNo 和 InvoiceNo
- 不可修改 CurrencyId（币别在新建时确定）
- OrgBankAccountId / ClientInvoiceBankId 可空：未传不校验；传值则校验归属；传 `null` 表示清空
- 费用明细和商品明细为全量替换（先删后插），**允许为空**；**不校验**商品金额与费用折算一致性（提交时校验）
- 验证各外键有效性（同新增）
- 费用的 CurrencyId 必须与开票申请的 CurrencyId 一致
- 使用 `UPDLOCK, ROWLOCK` 锁定 OrderFee 行防止并发验证问题（不再更新 OrderFee 的金额字段）
- **兼容保留**；局部改主表/加减费用明细请用下列拆分接口（见 `开票申请-编辑拆分-前端对接文档-2026-07-24.md`）

### `PUT /api/services/app/InvoiceApplicationAdmin/EditMainAsync`

**权限**：`Admin.InvoiceApplication.Edit`

**入参** `InvoiceApplicationEditMainDto`：`id`、`settlementId`、`orgId`、`orgBankAccountId`、`clientInvoiceBankId`、`invoiceType`、`require`、`remark`

**出参**：`bool`

**业务规则**：仅更新主表；不改费用明细/商品明细；结算对象变更时校验已关联费用结算对象一致；驳回状态保存后回录入。

### `POST /api/services/app/InvoiceApplicationAdmin/AddItemsAsync`

**权限**：`Admin.InvoiceApplication.Edit`

**入参** `InvoiceApplicationAddItemsDto`：`id`、`invoiceApplicationItems`（本次新增，可空）、`invoiceApplicationGoodsDtls`（可空；传则全量替换，null 不改商品）

**出参**：`bool`

**业务规则**：新费用不可与已关联重复；悲观锁校验额度/结算对象/币别；**不做**商品金额校验（提交时再校验）。

### `PUT /api/services/app/InvoiceApplicationAdmin/RemoveItemsAsync`

**权限**：`Admin.InvoiceApplication.Edit`

**入参** `InvoiceApplicationRemoveItemsDto`：`id`、`invoiceApplicationItemIds`（费用明细主键）、`invoiceApplicationGoodsDtls`（可空；传则全量替换，null 不改商品）

**出参**：`bool`

**业务规则**：须属于本开票申请；**允许全部移除**；**不做**商品金额校验（提交时再校验）。

### `PUT /api/services/app/InvoiceApplicationAdmin/SubmitAsync`（提交时校验）

提交时强制：费用明细、商品明细均不可为空；商品人民币合计须等于费用申请金额合计×发票汇率；我司银行/客户银行不可空。

## 四、删除开票申请

### `DELETE /api/services/app/InvoiceApplicationAdmin/DeleteAsync`

**权限**：`Admin.InvoiceApplication.Delete`

**入参** `InvoiceApplicationDeleteDto`（Body JSON）：

| 字段  | 类型         | 必填 | 说明                   |
| ----- | ------------ | ---- | ---------------------- |
| `ids` | `List<Guid>` | 是   | 主键ID列表（批量删除） |

**出参**：`bool`

**业务规则**：

- 已开票状态（Invoiced）不能删除
- 删除时自动清理关联的 InvoiceApplicationItem / InvoiceApplicationGoodsDtl（已开票金额由关联计算，无需手动回滚）

## 七、审核开票申请（仅驳回）

### `PUT /api/services/app/InvoiceApplicationAdmin/AuditAsync`

**权限**：`Admin.InvoiceApplication.Audit`

**入参** `InvoiceApplicationAuditDto`（Body JSON）：

| 字段           | 类型     | 必填 | 说明             |
| -------------- | -------- | ---- | ---------------- |
| `id`           | `Guid`   | 是   | 主键ID           |
| `rejectReason` | `string` | 是   | 驳回原因（必填） |

**出参**：`bool`

**业务规则**：

- 审核**只支持驳回**，不支持审核通过
- 设计理念：只要是已提交（Auditing）的开票申请即可开票；审核时只驳回有错误的，没问题的不处理
- 只有待审核状态（Auditing）才能驳回
- 驳回原因必填
- 驳回时：
  - 状态变为驳回（Rejected）
  - 记录驳回人（`RejectUserId` = 当前用户）、驳回时间（`RejectTime`）和原因（`RejectReason`）
  - 驳回后用户可以修改后重新提交

## 八、提交审核

### `PUT /api/services/app/InvoiceApplicationAdmin/SubmitAsync`

**权限**：`Admin.InvoiceApplication.Edit`

**入参** `InvoiceApplicationSubmitDto`（Body JSON）：

| 字段 | 类型   | 必填 | 说明   |
| ---- | ------ | ---- | ------ |
| `id` | `Guid` | 是   | 主键ID |

**出参**：`bool`

**业务规则**：

- 只有录入状态（Entering）或驳回状态（Rejected）才能提交审核
- 提交前校验 `OrgBankAccountId`、`ClientInvoiceBankId` 均不可为空，否则分别报「我司银行不能为空」「客户银行不能为空」
- 提交后状态变为待审核（Auditing），即可进入发票开出流程

## 九、撤回审核

### `PUT /api/services/app/InvoiceApplicationAdmin/WithdrawAsync`

**权限**：`Admin.InvoiceApplication.Edit`

**入参** `InvoiceApplicationSubmitDto`（Body JSON）：

| 字段 | 类型   | 必填 | 说明   |
| ---- | ------ | ---- | ------ |
| `id` | `Guid` | 是   | 主键ID |

**出参**：`bool`

**业务规则**：

- 只有待审核状态（Auditing）才能撤回（即尚未被审核通过或驳回）
- 撤回后状态恢复为录入状态（Entering）

## 状态枚举

### InvoiceApplicationStatus

| 值  | 名称     | 说明                                                |
| --- | -------- | --------------------------------------------------- |
| 0   | Entering | 录入状态/未提交                                     |
| 1   | Auditing | 已提交/待审核（已提交即可开票，审核只驳回有问题的） |
| 2   | Rejected | 审核驳回                                            |
| 3   | Invoiced | 已开票（由后续开票操作设置，非审核设置）            |

### InvoiceType（发票类型，字符串）

| 值  | 说明                   |
| --- | ---------------------- |
| p   | 普通发票(电票)（默认） |
| c   | 普通发票(纸票)         |
| s   | 专用发票               |

> 新增时每个币别分组（CurrencyGroup）各自带一个 InvoiceType；修改时单条开票申请有一个 InvoiceType。
