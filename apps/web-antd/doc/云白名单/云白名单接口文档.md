# 0. 先看这里

给某个 IP 加白名单，**日常只需要调一个接口**，不用登录、不用带 token：

```bash
curl --location 'https://你的域名/api/services/app/CloudWhitelistAdmin/AddWhitelistAsync' --header 'Content-Type: application/json' --data '{"ips":["1.1.1.1"],"remark":"张三","cipherKey":"你的加密口令"}'
```

前提是**云账号和它下面的服务器已经配好**（见第 2 章，一次性工作）。没配的话这个调用会返回「错误」。

云服务器那侧的地址模板 / 前缀列表**不需要你去云控制台建**——第一次下发时会自动建出来，并自动关联到该账号该地域的所有云服务器上（细节和风险见 4.1）。

## 怎么导进 Postman

本文所有 curl 都写成**单行**，就是为了能直接粘进 Postman：

1. Postman 左上角 **Import** → 切到 **Raw text** 页签
2. 把整行 curl 粘进去 → **Continue** → **Import**
3. 会自动生成一个请求，URL、Header、Body 都填好了，把域名和口令换成你自己的即可

Postman 是自己解析 curl 语法的，不经过命令行，所以单引号、中文都不会有问题。

> 如果要在终端里直接跑：Linux / macOS / Git Bash 原样复制即可；Windows PowerShell 里 `curl` 是 `Invoke-WebRequest` 的别名，得写成 `curl.exe`，且单引号要换成双引号并把 JSON 里的引号转义（`\"`），比较麻烦，建议直接用 Postman。

# 1. 鉴权说明

这套接口分成两组，鉴权方式**不一样**：

| 接口组 | 服务名 | 鉴权 | 说明 |
| :-- | :-- | :-- | :-- |
| **白名单操作**（下发 / 回收 / 查云端 / 查日志） | `CloudWhitelistAdmin` | **不登录**，每个请求带 `cipherKey` | 口令本身就是凭据 |
| **配置管理**（加密密钥 / 云账号 / 白名单目标） | `CloudAccountAdmin` | **需要登录**，带 `Authorization: Bearer <token>` | 能看到 AccessKeyId、能删账号，不能匿名 |

`cipherKey` 是**加密云账号密钥时用的那个口令**。服务端拿它去挨个解库里启用中的云账号密文，能解开任意一个就算持有凭据。

**所有凭据类失败一律只返回「错误」两个字**，不会告诉你是口令不对还是账号不存在——差异化的提示会变成探测工具。真实原因写在服务端日志和操作日志表里。

IP 格式不对、端口不合法这类**纯输入错误会给明确提示**，否则填错一个字符只看到「错误」没法改。

**所有接口都是 POST**：口令绝对不能出现在 URL 上，否则会被 Web 服务器的访问日志原样记下来。

# 2. 一次性配置

只在第一次接入、或者换云密钥时做。这三步都要登录。

## 2.1 加密密钥 — `POST /api/services/app/CloudAccountAdmin/EncryptSecretAsync`

把阿里云 `AccessKeySecret` / 腾讯云 `SecretKey` 的**明文**换成可以入库的**密文**。

```bash
curl --location 'https://你的域名/api/services/app/CloudAccountAdmin/EncryptSecretAsync' --header 'Content-Type: application/json' --header 'Authorization: Bearer <token>' --data '{"plainText":"真实的SecretKey明文","cipherKey":"你自己定的加密口令"}'
```

### 入参

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `plainText` | string | 是 | 待加密的密钥明文。阿里云填 `AccessKeySecret`，腾讯云填 `SecretKey` |
| `cipherKey` | string | 是 | 加密口令，至少 8 位。**这个口令不会被保存在系统的任何地方** |

### 出参

| 字段           | 类型   | 说明                                         |
| :------------- | :----- | :------------------------------------------- |
| `secretCipher` | string | 密文，填到下一步云账号的 `secretCipher` 字段 |

```json
{
  "result": { "secretCipher": "AbCd...==" },
  "success": true
}
```

> **口令请自己妥善保管。** 系统里不存它，丢了就只能到云控制台重新生成密钥再走一遍这个流程。
>
> 同一个明文配同一个口令，**每次加密出来的密文都不一样**（盐和 IV 每次随机），这是有意的，用来避免从「两个账号密文相同」反推出「两个账号密钥相同」。所以不要拿密文去比对。

## 2.2 校验口令（可选） — `POST /api/services/app/CloudAccountAdmin/VerifySecretAsync`

配完账号后，验一下口令能不能解开，并回显掩码后的密钥供肉眼核对。

```bash
curl --location 'https://你的域名/api/services/app/CloudAccountAdmin/VerifySecretAsync' --header 'Content-Type: application/json' --header 'Authorization: Bearer <token>' --data '{"cloudAccountId":"云账号id","cipherKey":"你的加密口令"}'
```

### 入参

| 字段             | 类型   | 必填 | 说明      |
| :--------------- | :----- | :--- | :-------- |
| `cloudAccountId` | guid   | 是   | 云账号 id |
| `cipherKey`      | string | 是   | 解密口令  |

### 出参

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `success` | bool | 口令是否正确 |
| `maskedSecret` | string | 掩码后的密钥，形如 `LTAI****abcd`，只留头尾各 4 位。口令不对时为空 |
| `errorMessage` | string | 口令不正确时的提示。这个接口在登录态下，所以给的是明确原因 |

## 2.3 建云账号（含全部服务器）— `POST /api/services/app/CloudAccountAdmin/AddAsync`

**一个账号下的所有配置一次提交完**：账号本身 + 它下面的全部「白名单目标」。阿里云和腾讯云共用这一张表，用 `cloudProvider` 区分。

「目标」代表一处要下发白名单的地方，怎么拆分很关键：

- **云服务器不是一台一行。** 安全组规则引用的是地址集合（腾讯云 IP 地址模板 / 阿里云前缀列表），而一个安全组挂在很多台机器上。所以 30 台 CVM 共用一个安全组只配 **1 项**，跨地域才多配。
- **轻量应用服务器必须一台一行**，`resourceId` 填**实例 id 不是服务器 IP**，云 API 就是按实例 id 定位机器的。

下面这个例子建了一个腾讯云账号，带 1 个上海地域的地址模板 + 2 台轻量：

```bash
curl --location 'https://你的域名/api/services/app/CloudAccountAdmin/AddAsync' --header 'Content-Type: application/json' --header 'Authorization: Bearer <token>' --data '{"cloudProvider":1,"name":"腾讯云主账号","accessKeyId":"你的SecretId","secretCipher":"2.1返回的密文","isEnabled":true,"sortId":1,"cloudWhitelistTargets":[{"targetType":2,"name":"上海云服务器","regionId":"ap-shanghai","resourceName":"jiayueuser","sortId":1},{"targetType":3,"name":"轻量-业务机1","regionId":"ap-shanghai","resourceId":"lhins-xxxxxxxx","sortId":2},{"targetType":3,"name":"轻量-业务机2","regionId":"ap-shanghai","resourceId":"lhins-yyyyyyyy","sortId":3}]}'
```

### 入参（行级）

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `cloudProvider` | int | 是 | 云厂商，见第 5 章枚举 |
| `name` | string | 是 | 账号名称，最长 64，全局唯一（大小写不敏感） |
| `accessKeyId` | string | 是 | 最长 128。阿里云填 `AccessKeyId`，腾讯云填 `SecretId`。这一半不算机密，明文存 |
| `secretCipher` | string | 是 | 最长 512。**必须是 2.1 返回的密文**，直接粘明文会被挡下来 |
| `isEnabled` | bool | 否 | 默认 `true`。停用的账号及其下所有目标都不参与下发 |
| `sortId` | int | 否 | 排序 id，列表按其升序 |
| `remark` | string | 否 | 最长 512 |
| `cloudWhitelistTargets` | array | 否 | 该账号下的白名单目标，见下 |

### 入参 `cloudWhitelistTargets[]`

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `targetType` | int | 是 | 目标类型，见第 5 章枚举。**必须和账号的 `cloudProvider` 匹配**，阿里云的目标挂不到腾讯云账号下 |
| `name` | string | 是 | 目标名称，最长 64，同一次提交内不可重复 |
| `regionId` | string | 是 | 地域 id，最长 64。阿里云形如 `cn-hangzhou`，腾讯云形如 `ap-shanghai` |
| `resourceId` | string | 视类型 | 最长 128。**轻量类必填**，填的是**实例 id**（腾讯云形如 `lhins-xxxxxxxx`，阿里云是 32 位十六进制）；云服务器类留空即可 |
| `resourceName` | string | 否 | 最长 128。仅云服务器类使用，即前缀列表名 / IP 地址模板名。和 `resourceId` 都不填时默认落 `jiayueuser` |
| `isEnabled` | bool | 否 | 默认 `true` |
| `sortId` | int | 否 | 排序 id，下发时按其升序逐个执行 |
| `remark` | string | 否 | 最长 512 |

### 出参

返回新建的云账号 id（guid）。目标 id 用 `DetailAsync` 或 `GetTargetPagedListAsync` 查。

## 2.4 改云账号 — `PUT /api/services/app/CloudAccountAdmin/EditAsync`

入参与 2.3 相同，多一个行级 `id`（账号 id），子表每项可带 `id`。

> **子表是全量提交。** 带 `id` 的是改已有的，不带 `id` 的是新增，**没出现在数组里的原有目标会被删除**。所以加一台机器不能只传那一台——要先用 `DetailAsync` 把现有目标读全，追加新的再整个提交回来。

> **密文留空表示不改密钥。** 前端拿不到现有密文，编辑时不填就保持原样，不会被空字符串覆盖。

# 3. 日常使用

## 3.1 添加白名单 — `POST /api/services/app/CloudWhitelistAdmin/AddWhitelistAsync`

**这就是开头那个接口。** 不登录，带口令即可。

最简：给 1.1.1.1 开白名单。

```bash
curl --location 'https://你的域名/api/services/app/CloudWhitelistAdmin/AddWhitelistAsync' --header 'Content-Type: application/json' --data '{"ips":["1.1.1.1"],"remark":"张三","cipherKey":"你的加密口令"}'
```

完整：多个 IP + 网段，指定端口，只发到某几个目标。

```bash
curl --location 'https://你的域名/api/services/app/CloudWhitelistAdmin/AddWhitelistAsync' --header 'Content-Type: application/json' --data '{"ips":["1.1.1.1","2.2.2.2","1.1.1.0/24"],"remark":"张三","ports":["3389","8172","31888"],"cipherKey":"你的加密口令","targetIds":["目标id1","目标id2"]}'
```

### 入参

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `ips` | string[] | 是 | 要放行的 IP 或网段。支持 `1.2.3.4` 和 `1.1.1.0/24` 两种写法。**不允许 `0.0.0.0/0`**，那等于把端口对全网敞开 |
| `remark` | string | 是 | 最长 64。见下面的「备注语义」，这是本接口最关键的一个字段 |
| `ports` | string[] | 否 | 不传默认 `3389`、`8172`、`31888`。**只支持单端口**，不支持端口范围 |
| `cipherKey` | string | 是 | 云账号密钥的解密口令 |
| `targetIds` | guid[] | 否 | 不传则下发到**所有启用的目标** |

> **备注语义（重要）：** `remark` 是这批 IP 的归属标识。**用同一个备注再提交一次，就是「以本次为准」全量覆盖**——之前挂在这个备注下的 IP 会被先删掉，云上最终只留本次提交的这些。
>
> 所以张三换 IP 了，只要用「张三」这个备注重提一次，旧 IP 自动收回，不用记得去手工清理。反过来，**同一个人 / 同一个用途请固定用同一个备注**，换备注等于新开一份，旧的不会被收回。

> **端口只支持单端口**：阿里云轻量的端口范围写 `1024/1055`，腾讯云轻量写 `1024-1055`，同一个输入喂不了两边。要开一段范围请拆成若干单端口传进来。
>
> **四种目标都要端口，但用法不同**：轻量是按「端口 × IP」逐条铺防火墙规则，端口直接体现在规则上；云服务器类则是拿端口去建/补安全组里引用地址集合的入站规则（每个端口一条），建好之后往集合里加 IP就跟端口无关了。所以云服务器类第一次下发时端口必须给对，否则规则会建在错误的端口上。

### 出参（行级）

| 字段           | 类型  | 说明                                    |
| :------------- | :---- | :-------------------------------------- |
| `logId`        | guid  | 操作日志 id，出问题时凭它回查（见 3.4） |
| `totalCount`   | int   | 参与本次操作的目标数                    |
| `successCount` | int   | 其中成功的目标数                        |
| `allSuccess`   | bool  | 是否全部成功                            |
| `items`        | array | 每个目标的执行结果，见下                |

### 出参 `items[]`

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `target` | object | 目标，见下 |
| `success` | bool | 该目标上是否执行成功 |
| `removedCount` | int | 实际删掉的条数（同备注的旧记录） |
| `addedCount` | int | 实际新增的条数。轻量类是「端口数 × IP 数」，云服务器类就是 IP 数 |
| `errorMessage` | string | 失败原因，成功时为 `null` |

### 出参 `items[].target`

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | guid | 目标 id |
| `targetType` | int | 目标类型 |
| `targetTypeName` | string | 目标类型名称 |
| `name` | string | 目标名称 |
| `regionId` | string | 地域 id |
| `resourceId` | string | 资源 id |
| `resourceName` | string | 资源名称，仅云服务器类有意义 |
| `isAddressSetBased` | bool | 是否走地址集合。云服务器类为 `true`，轻量为 `false` |
| `isEnabled` | bool | 是否启用 |
| `sortId` | int | 排序 id |

### 返回示例

```json
{
  "result": {
    "logId": "8f3a1c9e-....",
    "totalCount": 4,
    "successCount": 3,
    "allSuccess": false,
    "items": [
      {
        "target": {
          "id": "…",
          "targetType": 2,
          "targetTypeName": "腾讯云-云服务器(IP地址模板)",
          "name": "腾讯云主模板",
          "regionId": "ap-shanghai",
          "resourceId": null,
          "resourceName": "jiayueuser",
          "isAddressSetBased": true,
          "isEnabled": true,
          "sortId": 1
        },
        "success": true,
        "removedCount": 1,
        "addedCount": 1,
        "errorMessage": null
      },
      {
        "target": {
          "…": "…",
          "name": "轻量-业务机1",
          "isAddressSetBased": false
        },
        "success": false,
        "removedCount": 0,
        "addedCount": 0,
        "errorMessage": "调用腾讯云接口CreateFirewallRules失败:…"
      }
    ]
  },
  "success": true
}
```

> **部分失败时接口仍然返回 200、`success: true`。** 批量下发是一个目标一个目标独立跑的，一台机器不通不该把另外几台已经成功的结果一起吞掉。调用方要自己判 `allSuccess`，为 `false` 时看 `items` 里哪台的 `success` 是 `false`。

## 3.2 按备注回收白名单 — `POST /api/services/app/CloudWhitelistAdmin/RemoveWhitelistByRemarkAsync`

只删不加，用于回收某个人的临时权限。

```bash
curl --location 'https://你的域名/api/services/app/CloudWhitelistAdmin/RemoveWhitelistByRemarkAsync' --header 'Content-Type: application/json' --data '{"remark":"张三","cipherKey":"你的加密口令"}'
```

### 入参

| 字段        | 类型   | 必填 | 说明                             |
| :---------- | :----- | :--- | :------------------------------- |
| `remark`    | string | 是   | 该备注下的白名单会被**全部删除** |
| `cipherKey` | string | 是   | 解密口令                         |
| `targetIds` | guid[] | 否   | 不传则在所有启用的目标上删       |

### 出参

结构与 3.1 完全一致，`addedCount` 恒为 0。

## 3.3 查云上实际生效的白名单 — `POST /api/services/app/CloudWhitelistAdmin/GetCloudEntriesAsync`

查的是**云端实时状态**，不是本地日志。别人在控制台上手工改过的、以及阿里云前缀列表那种异步生效还没落地的，只有查这里才看得出来。

查全部：

```bash
curl --location 'https://你的域名/api/services/app/CloudWhitelistAdmin/GetCloudEntriesAsync' --header 'Content-Type: application/json' --data '{"cipherKey":"你的加密口令"}'
```

只看张三名下的：

```bash
curl --location 'https://你的域名/api/services/app/CloudWhitelistAdmin/GetCloudEntriesAsync' --header 'Content-Type: application/json' --data '{"cipherKey":"你的加密口令","remark":"张三"}'
```

### 入参

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `cipherKey` | string | 是 | 解密口令 |
| `targetIds` | guid[] | 否 | 不传则查所有启用的目标 |
| `remark` | string | 否 | 只看这个备注下的记录，不传返回该目标上的全部白名单 |

### 出参（数组，一个目标一项）

| 字段           | 类型   | 说明                                 |
| :------------- | :----- | :----------------------------------- |
| `target`       | object | 目标，字段同 3.1 的 `items[].target` |
| `success`      | bool   | 该目标是否查询成功                   |
| `errorMessage` | string | 查询失败的原因，成功时为 `null`      |
| `entries`      | array  | 该目标上当前生效的白名单，见下       |

### 出参 `entries[]`

| 字段       | 类型   | 说明                                                 |
| :--------- | :----- | :--------------------------------------------------- |
| `ip`       | string | IP 或网段                                            |
| `remark`   | string | 备注                                                 |
| `port`     | string | 端口。**走地址集合的云服务器类本身不带端口，恒为空** |
| `protocol` | string | 协议。同上，云服务器类恒为空                         |

## 3.4 查操作日志 — `POST /api/services/app/CloudWhitelistAdmin/GetLogPagedListAsync`

```bash
curl --location 'https://你的域名/api/services/app/CloudWhitelistAdmin/GetLogPagedListAsync' --header 'Content-Type: application/json' --data '{"cipherKey":"你的加密口令","keyword":"张三","pageIndex":1,"pageSize":20}'
```

### 入参

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `cipherKey` | string | 是 | 解密口令。查日志同样要带，否则不登录的情况下任何人都能翻到全部放行记录和内网 IP |
| `keyword` | string | 否 | 模糊匹配 备注 / IP |
| `action` | int | 否 | 操作类型，见第 5 章枚举。不传查全部 |
| `startTime` | date | 否 | 操作时间起，含当天 |
| `endTime` | date | 否 | 操作时间止，含当天 |
| `pageIndex` | int | 否 | 页码，默认 1 |
| `pageSize` | int | 否 | 每页条数，默认 10 |
| `sorting` | string | 否 | 排序，默认 `CreationTime DESC` |

### 出参（分页壳）

| 字段             | 类型  | 说明           |
| :--------------- | :---- | :------------- |
| `items`          | array | 日志列表，见下 |
| `totalCount`     | int   | 总条数         |
| `skipCount`      | int   | 跳过的条数     |
| `maxResultCount` | int   | 每页条数       |

### 出参 `items[]`

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | guid | 日志 id |
| `creationTime` | datetime | 操作时间 |
| `action` | int | 操作类型 |
| `actionName` | string | 操作类型名称 |
| `remark` | string | 备注 |
| `ips` | string | 本次下发的 IP / 网段，逗号分隔。按备注删除时为空 |
| `ports` | string | 本次下发的端口，逗号分隔 |
| `totalCount` | int | 参与本次操作的目标数 |
| `successCount` | int | 其中成功的目标数 |
| `creatorUserName` | string | 操作人昵称。**多数时候是空的**，见下面的说明 |

| 目标类型 | 用的云接口 | 备注字段 | 端口 | 一处改动的影响面 |
| :-- | :-- | :-- | :-- | :-- |
| 阿里云-云服务器（前缀列表） | vpc 2016-04-28<br/>`ListPrefixLists` / `CreateVpcPrefixList` / `GetVpcPrefixListEntries` / `ModifyVpcPrefixList`<br/>ecs 2014-05-26<br/>`DescribeInstances` / `DescribeSecurityGroupAttribute` / `AuthorizeSecurityGroup` | 条目 `Description`，限 128 字 | 建引用规则时用 | **改一处，所有引用该前缀列表的安全组规则同时生效** |

云账号的 AccessKey 需要覆盖上表这些接口的权限。相比只改模板的做法，现在多需要**读实例列表**和**读写安全组规则**两类权限。

## 4.1 云服务器类：地址集合会自动新建并绑定

每次下发时，云服务器类的目标会先把「地址集合 + 它的安全组引用关系」补齐，再往集合里加 IP：

1. 按 `resourceName`（默认 `jiayueuser`）查地址集合，**不存在就新建**，并把本次的 IP 直接写进去
2. 拉该账号该地域的**全部云服务器**（`DescribeInstances`），收集它们所在的安全组 id 去重
3. 逐个安全组检查有没有「引用该集合 + 对应端口」的入站规则，**缺哪个端口补哪条**
4. 最后按备注整体替换集合里的地址

> **每次下发都会走 1–3 步**，不是只在新建时做一次。因为新买的服务器不会自动进来——它的安全组里没有引用集合的规则，往集合加 IP 对它完全没作用，而且**不会报错**，是静默失效。每次补齐的代价是多几次 API 调用（1 次拉实例 + 每个安全组 1 次查规则），几十台机器会慢几秒。

> [!IMPORTANT] **这一步会改你的安全组，范围是该账号该地域的所有云服务器。** 安全组是共享的，往一个安全组加规则，该安全组下的**全部实例**都会生效，不只是你想开的那几台。如果这个云账号下混着不该动的机器（客户的、测试的、本来该完全隔离的），请**不要**把它们放在同一个账号里，或者改用「按目标 id 限定下发范围」并确保那些机器不在同一个安全组内。

自动新建只在**按名称**查找时发生。如果目标行上填的是 `resourceId`（`ipm-xxx` / `pl-xxx`）却查不到，会直接报错—— id 是云厂商生成的，新建时指定不了，查不到只可能是 id 写错了或者集合被人删了。

阿里云新建前缀列表时最大条目数取默认值 50。白名单真涨到 50 条以上时到控制台把它调大即可，不用改代码。

## 4.2 其它细节

- **轻量为什么不能用地址集合**：两家云的轻量防火墙规则都不支持引用地址集合，来源只能填死 IP/CIDR，所以只能按「端口 × IP」逐条铺规则，每台实例单独跑，也没有安全组这一层。
- **阿里云前缀列表只收 CIDR**，裸 IP 会被拒，所以下发前会自动把 `1.1.1.1` 补成 `1.1.1.1/32`。查询接口返回的也是补过掩码的形式。
- **删除一律按云端读回来的原始值删**，不用本地拼的字符串。本地拼的可能和云上存的差一个 `/32`，差一个字符就删不掉，旧白名单会永远留在那里。
- **阿里云 `ModifyVpcPrefixList` 是异步接口**：调用返回只代表阿里云收下了请求，真正生效还要几秒。不做轮询等待（批量下发时每个目标都等几秒会把整批拖到超时），要确认是否已生效请调 3.3 核对。
- **同一个 IP 只能归属一个备注**。地址集合里一个地址只能出现一次，所以本次要放行的 IP 如果正挂在别人的备注下，会被改成本次的备注。这是云 API 的物理限制，绕不过去。
- **不允许把地址集合清空**。如果一次「按备注删除」会导致腾讯云 IP 地址模板变成空的，接口会报错拒绝——腾讯云传空数组会被当成「这一项不改」而不是「清空」，与调用方预期正好相反，宁可报错也不能默默什么都没做。

# 6. 常见错误

| 提示 | 原因 |
| :-- | :-- |
| `错误` | 凭据问题：`cipherKey` 没传、口令不对、或者库里没有任何启用中的云账号能被这个口令解开。**不会区分具体是哪一种**，真实原因看服务端日志 |
| `IP【x】不是合法的IPv4地址` | IP 格式不对 |
| `IP【x】会放行全部IPv4地址 白名单接口不允许这样配置` | 传了 `0.0.0.0/0` 或掩码位数为 0。真有这个需求请到云控制台手工操作 |
| `端口【x】不正确 只支持1到65535之间的单个端口…` | 传了端口范围。拆成多个单端口 |
| `备注不能为空` | `remark` 必填 |
| `备注长度不能超过64个字符…` | 上限取的是四家云里最紧的那个（腾讯云轻量的规则描述限 64） |
| `没有可操作的白名单目标…` | 还没配目标，或者目标 / 其所属云账号被停用了。见第 2 章 |
| `密钥密文格式不正确,请先调用加密接口…` | 建账号时把明文密钥直接粘进 `secretCipher` 了。先走 2.1 |
| `目标【x】的类型【y】属于阿里云,不能挂在腾讯云账号下` | 子表项的 `targetType` 和账号的 `cloudProvider` 对不上 |
| `目标【x】的类型【y】必须填写资源id(实例id)` | 轻量类没填 `resourceId` |
| `目标【x】与另一项指向了同一个地域下的同一个资源…` | 子表里两项指向同一处，下发时会互相覆盖，去掉重复项 |
| `在腾讯云上没找到id为【x】的IP地址模板 请核对模板id` | 填了 `resourceId` 却查不到。按名称查是查不到就自动新建，按 id 查不到只能报错 |
| `腾讯云上叫【x】的IP地址模板有N个 请改用模板id指定` | 重名了，把 `resourceId` 填上 |
| `这样操作会清空整个IP地址模板…` | 按备注删除会把模板删空，腾讯云不支持空模板，到控制台处理 |
| `调用腾讯云接口X失败:…` / `阿里云接口X报错[Code]:…` | 云厂商返回的错误，原文透传，按云厂商的错误码排查。常见的有配额超限（`QuotaExceeded.PrefixListCidrCount`，前缀列表条目数超了 `MaxEntries`） |
