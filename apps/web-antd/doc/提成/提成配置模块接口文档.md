# 0. 前端必须先知道的五件事

**1. 接口地址里的 `Async` 后缀不能省。** 方法叫 `GetPagedListAsync`，地址就是 `/api/services/app/CommissionConfigAdmin/GetPagedListAsync`，写掉了会 404。

**2. 提成类型决定填哪一半。** `CommissionType = 0`（销售提成）只能传 `Sales`，`Operation` 必须不传；`CommissionType = 1`（操作提成）反过来。传错了直接报错，不是静默忽略。

**3. 海运港口和空运港口是两个不同的条件字段。** 海运港和空运港是两张独立的表、id 会重复，所以起运港/目的港各拆成海运、空运两个字段（`ConditionField` 的 0/1/2/3）。**字段本身就决定了从哪张表选港口**，条件值只传一个 `PortId`，没有「是否海运港」这种标记。海运港口从 `PortCodeAdmin/GetPagedListAsync` 选，空运港口从 `AirPortAdmin/GetPagedListAsync` 选。

**4. 「每票提多少钱」用「按票」条件表达，不是传空条件组。** 操作提成的 `ConditionGroups` 现在**必填至少一组**。不带任何筛选的计费配成一个 `ConditionField=5`（按票）的条件，它不需要比较符也不需要比较值。按票必须独占整个条件项，不能和别的条件混配。

**5. 编辑是全量提交，且子表不带 id。** 所有子表（适用人、适用组织、适用业务类型、阶梯、条件项、条件组、条件、条件值）都按本次提交整棵重建，没提交的原有数据全部删掉。**编辑后子表的 id 会全部变掉**，不要缓存。

业务口径（怎么命中、怎么算、为什么这么设计）看同目录《提成配置模块总逻辑文档.md》，本文只写接口契约。

# 1. 新增

| 项       | 值                                                      |
| :------- | :------------------------------------------------------ |
| 接口地址 | `POST /api/services/app/CommissionConfigAdmin/AddAsync` |
| 方法名   | `AddAsync`                                              |
| 入参     | `CommissionConfigAddDto`（`[FromBody]`）                |

## 1.1 入参 `CommissionConfigAddDto`

| 字段名 | 类型 | 必填 | 含义 | 说明 |
| :-- | :-- | :-: | :-- | :-- |
| `Name` | `string` | 是 | 配置名称 | 最长128，同租户唯一，大小写不敏感 |
| `SortId` | `int` | 是 | 排序id | 列表默认按其升序，也是同层级组织命中多条时的取舍依据 |
| `Remark` | `string` | 否 | 备注 | 最长1024 |
| `IsEnabled` | `bool` | 是 | 是否启用 | false 时不参与提成计算，也不参与冲突校验 |
| `OrgId` | `long?` | 否 | 所属组织 | 数据权限用。**数据权限当前停用，本字段不落库也不校验，传不传都行**。恢复后为必填且必须是当前登录人的直属组织 |
| `CommissionType` | `CommissionType` | 是 | 提成类型 | 0销售提成 1操作提成 |
| `EffectiveStartDate` | `DateTime?` | 否 | 生效起始会计期间 | **只取年月**，后端归一化到当月1号。不传=不限起始 |
| `EffectiveEndDate` | `DateTime?` | 否 | 生效截止会计期间 | 同上，**含当月**。不传=不限截止 |
| `PeriodType` | `CommissionPeriodType` | 否 | **提成周期** | 0月度 1季度 2半年度 3年度，不传=月度。决定一张提成单覆盖几个月。**配成季度及以上时，`BaseSalary` 要填一整个周期的底薪** |
| `UserIds` | `List<long>` | 二选一 | 适用人id集合 | 多选，与 `OrgIds` **至少填一个**，不允许重复 |
| `OrgIds` | `List<long>` | 二选一 | 适用组织id集合 | 多选，与 `UserIds` **至少填一个**，不允许重复 |
| `BizTypes` | `List<BizType>` | 否 | 适用业务类型 | 多选，0海运出口 1海运进口 2空运出口。**不传或空 = 全部业务类型** |
| `BaseSalary` | `decimal?` | 否 | 底薪金额 | 不能为负。与 `BaseSalaryMode` **两者都填才算底薪** |
| `BaseSalaryMode` | `BaseSalaryMode?` | 否 | 底薪模式 | 0直接加 1提成与底薪取最大值 |
| `Sales` | `CommissionSalesInputDto` | 条件必填 | 销售提成规则 | `CommissionType=0` 时**必填**，=1 时**必须不传** |
| `Operation` | `CommissionOperationInputDto` | 条件必填 | 操作提成规则 | `CommissionType=1` 时**必填**，=0 时**必须不传** |

## 1.2 `CommissionSalesInputDto`（销售提成规则）

| 字段名 | 类型 | 必填 | 含义 | 说明 |
| :-- | :-- | :-: | :-- | :-- |
| `ProfitThreshold` | `decimal?` | 是 | 利润门槛 | **不能为负**。一票利润达到该值才计入总利润 |
| `ProfitThresholdOperator` | `ProfitThresholdOperator?` | 是 | 门槛比较符 | 0大于 1大于等于 |
| `NegativeProfitRate` | `decimal?` | 是 | 负利润提成比例(%) | 取值 **0 ~ 1000** |
| `SalesCommissionType` | `SalesCommissionType?` | 是 | 计算方式 | 0固定比例 1按阶梯(阶梯内分段计费) 2按阶梯(达标后整体到档) |
| `FixedRate` | `decimal?` | 条件必填 | 固定提成比例(%) | 计算方式=0 时**必填**，取值 0~1000；其余方式**必须不传** |
| `Tiers` | `List<CommissionTierInputDto>` | 条件必填 | 提成阶梯 | 计算方式=1/2 时**必填至少一档**；=0 时**必须不传** |

### `CommissionTierInputDto`（提成阶梯，无 id）

| 字段名 | 类型 | 必填 | 含义 |
| :-- | :-- | :-: | :-- |
| `MinAmount` | `decimal` | 是 | 起始金额，**含**本值 |
| `MaxAmount` | `decimal?` | 条件必填 | 结束金额，**不含**本值。只有最后一档不传（=无上限），且最后一档必须不传 |
| `Rate` | `decimal` | 是 | 本档提成比例(%)，0~1000 |

阶梯的硬规则（不满足报错）：第一档 `MinAmount` 必须为 0；`MaxAmount > MinAmount`；相邻两档首尾相接（上档 `MaxAmount` == 下档 `MinAmount`）；只有最后一档 `MaxAmount` 为空。后端会按 `MinAmount` 升序重排，前端不用管提交顺序。

## 1.3 `CommissionOperationInputDto`（操作提成规则）

| 字段名  | 类型                           | 必填 | 含义             |
| :------ | :----------------------------- | :--: | :--------------- |
| `Rules` | `List<CommissionRuleInputDto>` |  是  | 条件项，至少一条 |

### `CommissionRuleInputDto`（条件项，无 id）

| 字段名 | 类型 | 必填 | 含义 | 说明 |
| :-- | :-- | :-: | :-- | :-- |
| `Name` | `string` | 否 | 条件项名称 | 最长128，仅用于识别 |
| `Amount` | `decimal` | 是 | 每票提成金额(人民币) | **必须 > 0** |
| `ConditionGroups` | `List<CommissionConditionGroupInputDto>` | **是** | 条件组 | **至少一组**。不带任何筛选的「每票10元」请用一个 `ConditionField=5`（按票）的条件，**不要传空数组** |

一票业务把所有条件项挨个判一遍，**命中的金额全部累加**。

### `CommissionConditionGroupInputDto`（条件组）

| 字段名 | 类型 | 必填 | 含义 |
| :-- | :-- | :-: | :-- |
| `Conditions` | `List<CommissionConditionInputDto>` | 是 | 组内条件，至少一条 |

**组内为「且」，组间为「或」**。`海运出口 且 (危险品 或 冻柜)` 这种要拆成两组来表达。

### `CommissionConditionInputDto`（条件）

| 字段名 | 类型 | 必填 | 含义 | 说明 |
| :-- | :-- | :-: | :-- | :-- |
| `ConditionField` | `CommissionConditionField` | 是 | 条件字段 | 0海运起运港 1海运目的港 2空运起运地 3空运目的地 4货物类型 **5按票** 6贸易条款 |
| `Operator` | `CommissionConditionOperator` | 是 | 比较符 | 0等于 1不等于 2包含于 3不包含于。**字段为 5（按票）时不参与判定，传什么都存 0** |
| `Values` | `List<CommissionConditionValueInputDto>` | 条件必填 | 比较值 | 除按票外**至少一个**，且**比较符为 0/1 时只能传一个值**；字段为 **5（按票）时必须不传** |

> **按票（`ConditionField=5`）是唯一不需要比较值的条件字段。** 一条业务就是一票，所以它对任何票都成立。两条硬约束：
>
> 1. 传了 `Values` 直接报错（`「按票」条件不需要比较值`）。
> 2. **按票必须独占整个条件项**——不能和别的条件放同一组，也不能自己单独一组跟别的组并列。违反报错（`「按票」对所有票都成立 必须是该条件项唯一的条件 不能和其它条件一起配`）。

### `CommissionConditionValueInputDto`（条件值）

| 字段名 | 类型 | 必填 | 含义 | 说明 |
| :-- | :-- | :-: | :-- | :-- |
| `PortId` | `long?` | 条件必填 | 港口id | `ConditionField` 为 **0/1/2/3** 时**必填**。0/1 传 `PortCode.Id`（海运港口），2/3 传 `AirPort.Id`（空运港口）。**没有「是否海运港」这个字段**，查哪张表由 `ConditionField` 决定 |
| `CargoId` | `CargoType?` | 条件必填 | 货物类型 | `ConditionField` 为 **4** 时**必填**。0普通货 1冻柜 2危险品 3超限箱 |
| `TradeTermsType` | `TradeTermsType?` | 条件必填 | 贸易条款 | `ConditionField` 为 **6** 时**必填** |

`ConditionField` 为 5（按票）时整个 `Values` 数组不传。

# 6. 输出结构 `CommissionConfigDto`

返回是**嵌套**的，按层级分节列。整体形状：

```
CommissionConfigDto
├── 行级字段（配置名称/类型/生效期/底薪/审计…）
├── ApplyUsers : List<UserSimpleDto>              ← 适用人
├── ApplyOrgs  : List<OrganizationUnitSimpleDto>  ← 适用组织
├── Orgs       : List<OrganizationUnitSimpleDto>  ← 数据权限所属组织串(≠ApplyOrgs)
├── Sales      : CommissionSalesDto               ← 仅 CommissionType=0 有值
│     └── Tiers : List<CommissionTierDto>
└── Operation  : CommissionOperationDto           ← 仅 CommissionType=1 有值
      └── Rules : List<CommissionRuleDto>
            └── ConditionGroups : List<CommissionConditionGroupDto>
                  └── Conditions : List<CommissionConditionDto>
                        └── Values : List<CommissionConditionValueDto>
```

## 6.1 行级字段

| 字段名 | 类型 | 含义 | 说明 |
| :-- | :-- | :-- | :-- |
| `Id` | `Guid` | 提成配置id |  |
| `Name` | `string` | 配置名称 |  |
| `SortId` | `int` | 排序id |  |
| `Remark` | `string` | 备注 |  |
| `IsEnabled` | `bool` | 是否启用 |  |
| `CommissionType` | `CommissionType` | 提成类型 | 0销售 1操作。**决定 `Sales` 与 `Operation` 哪个有值** |
| `EffectiveStartDate` | `DateTime?` | 生效起始会计期间 | 恒为当月1号，null=不限起始 |
| `EffectiveEndDate` | `DateTime?` | 生效截止会计期间 | 恒为当月1号，含当月，null=不限截止 |
| `PeriodType` | `CommissionPeriodType` | 提成周期 | 0月度 1季度 2半年度 3年度 |
| `BizTypes` | `List<BizType>` | 适用业务类型 | 升序。**空列表 = 全部业务类型** |
| `BaseSalary` | `decimal?` | 底薪金额 |  |
| `BaseSalaryMode` | `BaseSalaryMode?` | 底薪模式 | 0直接加 1取最大值 |
| `IsBaseSalaryEnabled` | `bool` | 是否真的算底薪 | 上面两个字段**都有值**才为 true。前端直接用这个，别自己判 |
| `ApplyUsers` | `List<UserSimpleDto>` | 适用人 | 见 6.2 |
| `ApplyOrgs` | `List<OrganizationUnitSimpleDto>` | 适用组织 | 见 6.3，按名称升序 |
| `Sales` | `CommissionSalesDto` | 销售提成规则 | 仅 `CommissionType=0` 有值，否则 null |
| `Operation` | `CommissionOperationDto` | 操作提成规则 | 仅 `CommissionType=1` 有值，否则 null |
| `UserId` | `long` | 数据所属人id | 数据权限用。**当前停用，恒为 0** |
| `OrgId` | `long?` | 数据所属组织id | 数据权限用。**当前停用，恒为 null** |
| `Orgs` | `List<OrganizationUnitSimpleDto>` | 数据所属组织串 | 从最高级组织到本组织。**当前停用，恒为空列表**。与 `ApplyOrgs` 语义不同，别混 |
| `CreatorUserName` | `string` | 创建人昵称 |  |
| `LastModifierUserName` | `string` | 最后修改人昵称 |  |
| `CreationTime` | `DateTime` | 创建时间 |  |
| `CreatorUserId` | `long?` | 创建人id |  |
| `LastModificationTime` | `DateTime?` | 最后修改时间 |  |
| `LastModifierUserId` | `long?` | 最后修改人id |  |

## 6.4 `CommissionSalesDto`（销售提成规则，仅 `CommissionType=0`）

| 字段名 | 类型 | 含义 | 说明 |
| :-- | :-- | :-- | :-- |
| `ProfitThreshold` | `decimal` | 利润门槛 |  |

# 8. 权限点

| 权限字符串                      | 控制的接口                         |
| :------------------------------ | :--------------------------------- |
| `Admin.CommissionConfig`        | 提成配置菜单（父节点）             |
| `Admin.CommissionConfig.Add`    | `AddAsync`                         |
| `Admin.CommissionConfig.Get`    | `GetPagedListAsync`、`DetailAsync` |
| `Admin.CommissionConfig.Edit`   | `EditAsync`                        |
| `Admin.CommissionConfig.Delete` | `DeleteAsync`                      |

**数据权限当前停用**：有上面的功能权限就能看到、改、删全租户的提成配置，不按所属人/所属组织过滤。输出里的 `UserId` 恒为 0、`OrgId` 恒为 null、`Orgs` 恒为空列表，入参 `OrgId` 不落库也不校验。

恢复数据权限后会变成：列表/详情/编辑/删除额外受「数据所属人在可见用户内，或数据所属组织在可见组织（含下属组织）内」约束，无权时详情/编辑/删除统一报「输入提成配置错误或无权XX」，不区分「不存在」和「没权限」。口径见《提成配置模块总逻辑文档.md》第 8 章。
