# 0. 前端必须先知道的六件事

**1. 接口地址里的 `Async` 后缀不能省。** 方法叫 `GetSalesPreviewAsync`，地址就是 `/api/services/app/CommissionOrderAdmin/GetSalesPreviewAsync`，写掉了会 404。

**2. 确认接口两个、详情接口两个、新建接口一个。** 销售提成和操作提成的确认与详情各走各的接口，返回结构完全不同；新建则共用一个接口，靠 `CommissionType` 分支。

**3. 提成月是数组，一个月生成一张提成单。** 确认接口输入几个月就返回几组；新建接口输入几个月就返回几个 id。每个月都必须**小于当前月**，而且必须**跟已有提成单连续**（已提到 7 月就只能接着提 8 月）。

**4. 一张提成单 = 一个提成人 + 一种提成类型 + 一个提成月，同组合只能有一张。** 提成人是单选。

**5. 提成单没有编辑接口。** 金额是新建那一刻算死的快照，算错了只能删掉重建。

**6. 新建就会把涉及的票锁住。** 那批票的费用、销售、会计期间从此不能改，业务也不能删——直到提成单被删除。所以新建前一定要走确认接口让人核对。

业务口径（怎么算、为什么这么设计、锁了哪些地方）看同目录《提成单模块总逻辑文档.md》，本文只写接口契约。

# 1. 销售提成 新建前确认

| 项 | 值 |
| :-- | :-- |
| 接口地址 | `POST /api/services/app/CommissionOrderAdmin/GetSalesPreviewAsync` |
| 方法名 | `GetSalesPreviewAsync` |
| 入参 | `CommissionPreviewQueryDto`（`[FromBody]`） |
| 出参 | `CommissionSalesPreviewDto` |
| 权限 | `Admin.CommissionOrder.Get` |

**只算不写库**，可以反复调。

## 1.1 入参 `CommissionPreviewQueryDto`

| 字段名 | 类型 | 必填 | 含义 | 说明 |
| :-- | :-- | :-: | :-- | :-- |
| `UserId` | `long` | 是 | 提成人id | 单选，必须在当前登录人的数据权限范围内 |
| `AccountDates` | `List<DateTime>` | 是 | 提成月集合 | 至少一个，只取年月。每个月必须小于当前月且与已有提成单连续 |

## 1.2 出参 `CommissionSalesPreviewDto`

| 字段名   | 类型                            | 含义                           |
| :------- | :------------------------------ | :----------------------------- |
| `Months` | `List<CommissionSalesMonthDto>` | 按提成月升序，输入几个月就几条 |

### `CommissionSalesMonthDto`（一个月一条，四部分）

| 字段名 | 类型 | 含义 | 说明 |
| :-- | :-- | :-- | :-- |
| `AccountDate` | `DateTime` | 提成月 |  |
| `SettledTickets` | `List<CommissionTicketDto>` | **第一部分** 参与本月计算的票 | 会计期间 ≤ 提成月、费用全部已结算、且没被任何销售提成单认领。会计期间小于提成月的是上月结清晚了、本月补提的 |
| `Calculation` | `CommissionCalculationDto` | 计算结果（含全部步骤） | 命中不到配置或汇率缺失时为 **null** |
| `UnsettledTickets` | `List<CommissionTicketDto>` | **第二部分** 未全部结算的票 | 会计期间 ≤ 提成月但费用没结清。**有值就不能提交** |
| `CanSubmit` | `bool` | **第三部分** 是否可新建/提交 |  |
| `CannotSubmitReasons` | `List<string>` | **第四部分** 不能新建/提交的原因 | `CanSubmit` 为 true 时是空列表 |

`CannotSubmitReasons` 目前有三类文案：

- `提成人在yyyy-MM没有命中任何启用中的销售提成配置`
- `币别【USD】缺少yyyy-MM的应收汇率 请先在汇率表配置`
- `存在N票在yyyy-MM及之前的费用未全部结算 销售提成要求当月及之前月全部结清`

# 3. 新建

| 项       | 值                                                     |
| :------- | :----------------------------------------------------- |
| 接口地址 | `POST /api/services/app/CommissionOrderAdmin/AddAsync` |
| 方法名   | `AddAsync`                                             |
| 入参     | `CommissionOrderAddDto`（`[FromBody]`）                |
| 出参     | `List<Guid>`（新建的提成单id集合，按提成月升序）       |
| 权限     | `Admin.CommissionOrder.Add`                            |

## 3.1 入参 `CommissionOrderAddDto`

| 字段名 | 类型 | 必填 | 含义 | 说明 |
| :-- | :-- | :-: | :-- | :-- |
| `UserId` | `long` | 是 | 提成人id | 单选，必须在当前登录人的数据权限范围内 |
| `CommissionType` | `CommissionType` | 是 | 提成类型 | 0销售提成 1操作提成 |
| `AccountDates` | `List<DateTime>` | 是 | 提成月集合 | 至少一个，只取年月。**一个月生成一张提成单** |
| `Remark` | `string` | 否 | 备注 | 最长1024，多个月共用同一个备注 |

## 3.2 入参示例

```json
{
  "userId": 101,
  "commissionType": 0,
  "accountDates": ["2026-07-01", "2026-08-01"],
  "remark": "7-8月销售提成"
}
```

## 3.3 会被拦掉的情况

除 3.1 的字段校验外，还有这些硬校验（文案见《总逻辑文档》第 13 章）：提成人不在数据权限内、提成月不小于当前月、同月同类型已有提成单、提成月跳月、命中不到配置、汇率缺失、销售提成第二部分不为空。

**第一部分为空（这个月一票都没有）是允许的**，会生成一张 0 元的提成单。

| 项       | 值                                                               |

## 4.1 出参 `CommissionSalesDetailDto`

| 字段名 | 类型 | 含义 |
| :-- | :-- | :-- |
| `CommissionOrder` | `CommissionOrderDto` | 提成单单头，见第 7 章 |

# 8. 计算结果 `CommissionCalculationDto`

确认接口里是实时算的，详情接口里是新建时落库的快照。

| 字段名 | 类型 | 含义 | 何时有值 |
| :-- | :-- | :-- | :-- |
| `CommissionConfig` | `CommissionConfigSimpleDto` | 命中的提成配置 | **仅确认接口**；详情接口恒为 null |
| `ProfitThreshold` | `decimal?` | 利润门槛 | 仅销售 |
| `ProfitThresholdOperator` | `ProfitThresholdOperator?` | 门槛比较符 0大于 1大于等于 | 仅销售 |
| `NegativeProfitRate` | `decimal?` | 负利润提成比例(%) | 仅销售 |
| `SalesCommissionType` | `SalesCommissionType?` | 计算方式 0固定比例 1分段计费 2整体到档 | 仅销售 |
| `FixedRate` | `decimal?` | 固定提成比例(%) | 仅销售且计算方式=0 |
| `TotalProfit` | `decimal?` | 总利润（达标票利润合计，本位币） | 仅销售 |
| `CountedItemCount` | `int?` | 达标票数 | 仅销售 |
| `NegativeProfit` | `decimal?` | 亏损票利润合计（负数） | 仅销售 |
| `NegativeItemCount` | `int?` | 亏损票数 | 仅销售 |
| `NegativeDeduction` | `decimal?` | 负利润扣减金额（正数） | 仅销售 |
| `CommissionAmount` | `decimal` | 提成金额（已扣负利润、不含底薪） | 恒有 |
| `BaseSalary` | `decimal?` | 底薪金额 | 选填 |
| `BaseSalaryMode` | `BaseSalaryMode?` | 底薪模式 | 选填 |
| `IsBaseSalaryEnabled` | `bool` | 是否真的计算底薪 | 上面两个都有值才为 true，**前端用这个别自己判** |
| `FinalAmount` | `decimal` | 最终应发金额 | 恒有 |
| `Steps` | `List<CommissionStepDto>` | 计算步骤，按 `SortId` 升序 | 恒有 |

## 8.1 `CommissionStepDto`（计算步骤）

| 字段名 | 类型 | 含义 | 何时有值 |
| :-- | :-- | :-- | :-- |
| `StepType` | `CommissionStepType` | 步骤类型 | 恒有 |
| `Description` | `string` | **后端拼好的整句，可直接显示** | 恒有 |
| `Amount` | `decimal` | 本步金额 | 恒有，负利润扣减为负数 |
| `BaseValue` | `decimal?` | 本步计算基数 | 阶梯档=落入本档的金额；条件项命中=每票金额 |
| `Rate` | `decimal?` | 比例(%) | 阶梯档 / 固定比例 / 负利润扣减 |
| `MinAmount` / `MaxAmount` | `decimal?` | 阶梯档区间 | 仅阶梯档；`MaxAmount` 为空代表无上限 |
| `ItemCount` | `int?` | 涉及票数 | 汇总类与条件项命中 |
| `CommissionConfigRuleId` | `Guid?` | 命中的条件项id | 仅条件项命中 |
| `SortId` | `int` | 排序id，从1开始 | 恒有 |

`StepType` 取值：0达标利润汇总、1固定比例、2阶梯档、3负利润扣减、4条件项命中、5底薪、6合计。

**销售提成的步骤序列**：达标利润汇总 → 固定比例 或 若干条阶梯档 → 负利润扣减 → 底薪 → 合计。 **操作提成的步骤序列**：若干条条件项命中 → 底薪 → 合计。

底薪那一步只有 `IsBaseSalaryEnabled` 为 true 时才有；负利润扣减那一步只有存在亏损票或扣减金额不为0时才有。

# 9. 票 `CommissionTicketDto`

一票 = 一个主单原票（`ChangeOrderId` 为空）或一个更改单。业务字段不平铺在这一层，统一挂在 `TransportOrder` 对象下。

## 9.1 行级字段

| 字段名 | 类型 | 含义 | 说明 |
| :-- | :-- | :-- | :-- |
| `TransportOrderId` | `Guid` | 业务主单id | 供前端跳转 |
| `ChangeOrderId` | `Guid?` | 更改单id | 为空代表主单原票 |
| `IsOriginal` | `bool` | 是否原票 | `ChangeOrderId == null` |
| `AccountDate` | `DateTime` | **这一票的会计期间** | 原票取主单的，更改单取更改单自己的。**可能小于提成月**，那是补提的 |
| `TransportOrder` | `CommissionTransportOrderDto` | 业务主单信息 | 见 9.2 |

## 9.2 销售提成专属字段

| 字段名 | 类型 | 含义 | 何时有值 |
| :-- | :-- | :-- | :-- |
| `Profit` | `decimal?` | 这一票的利润（本位币） | 第一部分与详情有值；**第二部分为 null**（没结清就不算利润） |
| `ProfitType` | `CommissionItemProfitType?` | 利润分类 | 0达标计入 1未达门槛 2负利润扣减；第二部分为 null |
| `TotalReceivable` | `decimal?` | 应收合计（本位币） | 同上 |
| `TotalPayable` | `decimal?` | 应付合计（本位币） | 同上 |
| `Currencies` | `List<CommissionCurrencyDto>` | 按币别分组的原币明细 | 同上 |
| `UnSettledFeeCount` | `int?` | 未结清的费用条数 | **仅第二部分有值**，供前端提示还差几条没收/没付 |

### `CommissionCurrencyDto`

| 字段名         | 类型                | 含义                                 |
| :------------- | :------------------ | :----------------------------------- |
| `Currency`     | `CurrencySimpleDto` | 币别（该 DTO 以 `Code` 为键，无 Id） |
| `CurrencyId`   | `long`              | 币别id                               |
| `Receivable`   | `decimal`           | 应收（原币）                         |
| `Payable`      | `decimal`           | 应付（原币）                         |
| `Profit`       | `decimal`           | 利润（原币）= 应收 − 应付            |
| `ExchangeRate` | `decimal`           | 本次折算用的应收汇率，人民币恒为 1   |

## 9.3 操作提成专属字段

| 字段名 | 类型 | 含义 | 说明 |
| :-- | :-- | :-- | :-- |
| `Amount` | `decimal?` | 这一票的操作提成金额 | 命中的各条件项金额之和；一条都没命中时为 **0**（不是 null） |
| `HitRules` | `List<CommissionHitRuleDto>` | 这一票命中的条件项 | 一条都没命中时为**空列表** |

### `CommissionHitRuleDto`

| 字段名                   | 类型      | 含义               |
| :----------------------- | :-------- | :----------------- |
| `CommissionConfigRuleId` | `Guid`    | 条件项id           |
| `RuleName`               | `string`  | 条件项名称         |
| `Amount`                 | `decimal` | 该条件项的每票金额 |
| `SortId`                 | `int`     | 从1开始            |

## 9.4 `CommissionTransportOrderDto`（业务主单信息）

| 字段名 | 类型 | 含义 |
| :-- | :-- | :-- |
| `Id` | `Guid` | 业务主单id |
| `BizType` | `BizType` | 业务类型 0海运出口 1海运进口 2空运出口 |
| `CommissionNum` | `string` | 委托编号 |
| `MblNum` | `string` | 主提单号 |
| `BizDate` | `DateTime?` | 业务日期（`TransportOrder.ETD`）海出=开船日 海进=到港日 空出=起飞日 |
| `CargoId` | `CargoType` | 货物类型 0普通货 1冻柜 2危险品 3超限箱 |
| `Client` | `ClientSimpleDto` | 委托单位 |
| `AccountDate` | `DateTime` | **主单**会计期间（更改单票要看行级的 `AccountDate`） |
| `Orgs` | `List<OrganizationUnitSimpleDto>` | 所属组织串 |
| `Sales` | `List<UserSimpleDto>` | 销售（有且只有一个） |
| `Operations` | `List<UserSimpleDto>` | 操作 |

# 10. 删除

| 项       | 值                                                          |
| :------- | :---------------------------------------------------------- |
| 接口地址 | `DELETE /api/services/app/CommissionOrderAdmin/DeleteAsync` |
| 方法名   | `DeleteAsync`                                               |
| 入参     | `GuidIdDto`（`[FromBody]`）                                 |
| 出参     | `bool`                                                      |
| 权限     | `Admin.CommissionOrder.Delete`                              |

**只有录入状态与驳回状态可以删。** 删除会同时清空业务表与更改单上的提成单id，把那批票放开，并删掉审核任务与工作流实例。

# 11. 提交审核 / 撤销提交

| 项 | 提交审核 | 撤销提交 |
| :-- | :-- | :-- |
| 接口地址 | `POST .../CommissionOrderAdmin/SubmitAsync` | `POST .../CommissionOrderAdmin/UnSubmitAsync` |
| 入参 | `CommissionOrderSubmitDto`（`[FromBody]`） | 同左 |
| 出参 | `bool` | `bool` |
| 权限 | `Admin.CommissionOrder.Submit` | `Admin.CommissionOrder.Submit` |

| 字段名 | 类型   | 必填 | 含义     |
| :----- | :----- | :--: | :------- |
| `Id`   | `Guid` |  是  | 提成单id |

**提交**：录入与驳回状态都可提交。销售提成会**重新校验一次**「当月及之前月的费用全部已结算」——新建到提交之间可能又冒出未结清的票。

> [!IMPORTANT] 提交前必须先在工作流模块配好并启用 `TaskType = 提成单` 的流程，否则报「未配置或未启用提成单工作流，无法提交审核」。
>
> 如果流程的所有节点都是「直接通过」，提交后状态会**直接变成审核通过**，不会停在审核中。

**撤销**：只有审核中且**还没有任何人审过**才能撤，撤销后回到录入状态。**提成单id 不清空**——撤销后还能重新提交，这批票不该被别人改动。

# 12. 审核

| 项       | 值                                                       |
| :------- | :------------------------------------------------------- |
| 接口地址 | `POST /api/services/app/CommissionOrderAdmin/AuditAsync` |
| 方法名   | `AuditAsync`                                             |
| 入参     | `CommissionOrderAuditDto`（`[FromBody]`）                |
| 出参     | `bool`                                                   |
| 权限     | `Admin.CommissionOrder.Audit`                            |

| 字段名    | 类型     |   必填   | 含义     | 说明                     |
| :-------- | :------- | :------: | :------- | :----------------------- |
| `Id`      | `Guid`   |    是    | 提成单id |                          |
| `Success` | `bool`   |    是    | 是否通过 | false 为驳回             |
| `Remark`  | `string` | 条件必填 | 审核意见 | **驳回时必填**，最长1024 |

**多级审批时，前面几级通过不会改单据状态**，接口照样返回 true，状态仍是审核中——前端不要拿返回值当"审完了"。

审核接口**不过数据权限**（审的就是别人的单子），只受权限点控制。

| :------- | :------------------------------------------------------- |
| 接口地址 | `POST /api/services/app/CommissionOrderAdmin/GrantAsync` |
| 方法名   | `GrantAsync`                                             |
| 入参     | `CommissionOrderGrantDto`（`[FromBody]`）                |

# 15. 提成单建立后，这些操作会被拦

新建提成单后，涉及的票会被锁住。前端在这些页面上要能显示出对应的报错。

| 操作 | 报错文案 |
| :-- | :-- |
| 费用提交 / 申请修改 / 申请删除 / 审核后驳回 / 导入 / 收付转 | 已提交销售提成不可操作费用 |
| 删除费用 | 已提交销售提成不可删除费用 |
| 批量编辑主单费用 | 已提交销售提成不可编辑费用 |
| 编辑更改单 | 已提交销售提成不可编辑更改单 |
| 删除更改单 | 已提交销售提成不可删除更改单 |
| 改会计期间（含改 ETD 导致会计期间变） | 已提交销售提成不可修改会计期间 |
| 改销售 | 已提交销售提成不可修改销售 |
| 删除海运出口 / 海运进口 / 空运出口 | 已提交操作提成不可删除 / 已提交销售提成不可删除 |
| 改被操作提成锁定的字段（港口、货物类型） | 已提交操作提成不可编辑提成相关字段 |
| 取消核销（银行流水） | 已提交销售提成不可取消核销 |
| 把业务改到某个销售名下，而他那个会计期间已有提成单 | 该销售在会计期间【yyyy-MM】已存在销售提成单 不可把本业务改到他名下 |

**锁定哪些字段是动态的**：只锁「这张提成单当时用到的那份配置里实际出现过的条件字段」。配置里只用了货物类型，港口就照常能改。

# 17. 权限点

| 权限字符串 | 控制的接口 |
| :-- | :-- |
| `Admin.CommissionOrder` | 提成单菜单（父节点） |
| `Admin.CommissionOrder.Add` | `AddAsync` |
| `Admin.CommissionOrder.Get` | `GetSalesPreviewAsync`、`GetOperationPreviewAsync`、`GetPagedListAsync`、`GetSalesDetailAsync`、`GetOperationDetailAsync` |
| `Admin.CommissionOrder.Delete` | `DeleteAsync` |
| `Admin.CommissionOrder.Submit` | `SubmitAsync`、`UnSubmitAsync` |
| `Admin.CommissionOrder.Audit` | `AuditAsync`、`RejectAsync` |
| `Admin.CommissionOrder.Grant` | `GrantAsync` |

除功能权限外，**确认 / 列表 / 详情 / 删除 / 提交 / 撤销**还受数据权限约束（提成人在可见用户内，或所属组织在可见组织内）。**审核 / 审核后驳回 / 发放不过数据权限**。
