# 海运出口港口服务项配置 (SeServiceConfigAdmin) 前端对接文档

## 校验规则

| 校验规则 | 错误信息 |
| --- | --- |
| 起运港id(`POLId`)不为空且不存在 | "起运港不存在" |
| 同一租户下起运港重复配置（`POLId`不为空时） | "该起运港已配置服务项目，不能重复配置" |
| 默认港口配置已存在（`POLId`为空时） | "默认港口配置已存在，不能重复配置" |
| 同一配置下 `SeServiceConfigItems` 中 `ServiceType` 重复 | "同一配置下服务项类型不能重复" |
| `SeServiceConfigItems` 中 `SortId` 小于 0 | "排序id不能小于0" |
| `seServiceShows` 传入扩展类型枚举(≥10001) | "展示字段不支持[xx]，该类型仅完成时必填项可用" |
| `seServiceLocks` 传入扩展类型枚举(≥10001) | "完成后不允许修改字段不支持[xx]，该类型仅完成时必填项可用" |
| 必填项为附件类型但未指定附件类型id | "完成时必填项为附件类型时，必须指定至少一个附件类型" |
| 指定的附件类型不存在 | "附件类型不存在: {id}" |

> **SortId 优先级说明：** `SortId` 数值越小优先级越高。多个配置项可使用**相同的 SortId**，表示同优先级并行任务；生成任务时，同一优先级的所有任务必须全部完成后，才会生成下一优先级的任务。

> **默认港口配置：** `POLId`为空(`null`)时代表默认港口配置。由于港口数量多达数千个，无法为每个港口单独配置服务项。当某个港口没有专属配置时，系统将自动使用默认港口配置。每个租户下最多只能有一条默认港口配置。

## 1. 新增

**POST** `/api/services/app/SeServiceConfigAdmin/AddAsync`

### Request Body

```json
{
  "polId": null,
  "sortId": 0,
  "remark": "默认港口配置",
  "seServiceConfigItems": [
    {
      "serviceType": 1,
      "userAttribute": 3,
      "autoComplete": false,
      "requireFee": true,
      "manualAllowed": true,
      "reminder": false,
      "sortId": 0,
      "remark": "string",
      "seServiceShows": [{ "seaExportPropEnum": 0 }],
      "seServiceLocks": [{ "seaExportPropEnum": 1 }],
      "seServiceRequires": [
        { "seaExportPropEnum": 2 },
        { "seaExportPropEnum": 10001, "requireValues": "1|2" }
      ],
      "seServiceRequireFees": [
        { "paySide": 0, "feeCodeId": 1 },
        { "paySide": 1, "feeCodeId": 2 }
      ]
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| polId | long? | 否 | 起运港id，为空时代表默认港口配置；不为空时必须存在且不能与现有配置重复 |
| sortId | int | 否 | 排序id |
| remark | string | 否 | 备注 |
| seServiceConfigItems | array | 否 | 服务项配置明细列表 |
| ├── serviceType | int | 是 | 服务项枚举(前端定义)，同一配置下不可重复 |
| ├── userAttribute | long(Flags) | 否 | 用户属性，Flags枚举可组合(Operation=1,CustomerService=2,Documentation=4,Business=8,Sale=16,Finance=32,OverseasCustomerService=64,HR=128) |
| ├── autoComplete | bool | 否 | 是否自动完成 |
| ├── requireFee | bool | 否 | 完成是否需要必填费用，为true时需配置seServiceRequireFees |
| ├── manualAllowed | bool | 否 | 允许手动完成 |
| ├── reminder | bool | 否 | 完成提醒 |
| ├── sortId | int | 否 | 排序id |
| ├── remark | string | 否 | 备注 |
| ├── seServiceShows | array | 否 | 展示字段列表 |
| │ └── seaExportPropEnum | int | 是 | 海运出口字段枚举 |
| ├── seServiceLocks | array | 否 | 完成后不允许修改字段列表 |
| │ └── seaExportPropEnum | int | 是 | 海运出口字段枚举 |
| ├── seServiceRequires | array | 否 | 完成时必填项列表（含普通字段与附件类型） |
| │ ├── seaExportPropEnum | int | 是 | 海运出口字段枚举；`10001`=附件类型（扩展类型，仅本列表可用） |
| │ └── requireValues | string | 否 | 扩展类型的具体值，多个用 `\|` 分隔。`seaExportPropEnum=10001` 时**必填**，存附件类型id，如 `"1\|2\|3"`；普通字段传空 |
| └── seServiceRequireFees | array | 否 | 完成时必填费用列表（requireFee为true时生效） |
| ├── paySide | int | 是 | 收付类型(0=收, 1=付) |
| └── feeCodeId | long | 是 | 费用代码id |

> **附件类型必填说明：**
>
> - `seaExportPropEnum=10001`（附件类型）属于扩展类型，**只能用在 `seServiceRequires`**，传入 `seServiceShows` 或 `seServiceLocks` 会报错。
> - 枚举段位约定：1000 以内为海运出口字段、1001-2000 为其 Name 派生字段，各业务类型按千位划分自有段位（如 2000-3000 为空运出口），非字段类的扩展类型统一从 **10001** 起。
> - 附件类型id 需存在于附件类型表，否则报错"附件类型不存在: {id}"。
> - 后端会对 `requireValues` 去重并按id升序规范化后再存储。

### Response

```json
"3fa85f64-5717-4562-b3fc-2c963f66afa6"
```

返回新建记录的Guid Id。

**说明：** 使用级联插入，一次请求完成主表和所有子表的插入。

### Request Body

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "ids": ["3fa85f64-5717-4562-b3fc-2c963f66afa6"]
}
```

### 字段说明

| 字段 | 类型   | 必填 | 说明       |
| ---- | ------ | ---- | ---------- |

| ids  | Guid[] | 否   | 批量删除用 |

```json
true
```

### 字段说明

| ├── remark | string | 否 | 备注 |
| ├── seServiceShows | array | 否 | 展示字段列表(差异更新：有id=修改，无id=新增，不传的=删除) |

| └── seServiceRequireFees | array | 否 | 完成时必填费用列表(差异更新规则同上) |
| ├── id | Guid? | 否 | 主键Id，传值=修改，null或空Guid=新增 |

| └── feeCodeId | long | 是 | 费用代码id |

> **注意：** 编辑接口按前端传入的 `sortId` 保存优先级。多个明细可使用相同 `sortId` 表示同优先级并行任务。`sortId` 不能小于 0。

### Response

```json
true
```

**子表差异更新规则：**

- 输入中有id且数据库中存在 → 修改
- 输入中没有id(null或空Guid) → 新增
- 数据库中存在但输入中没有 → 删除

此规则同时适用于 `seServiceConfigItems` 及其子表 `seServiceShows`、`seServiceLocks`、`seServiceRequires`、`seServiceRequireFees`。

### userAttributeServiceTypes 说明
