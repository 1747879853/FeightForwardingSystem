---

## 一、需求描述

`SeServiceConfig` 表的 `POLId`（起运港id）需要支持**可空**（`null`）。当 `POLId` 为空时，代表**默认港口配置**。

**业务背景：** 港口数量多达数千个，无法为每个港口单独创建服务项配置。引入默认港口配置后，当某个港口没有专属配置时，系统将自动回退使用默认配置，减少配置维护成本。

## 三、详细修改内容

### 3.1 实体层 - SeServiceConfig.cs

```csharp
// 修改前
public long POLId { get; set; }

// 修改后
public long? POLId { get; set; }
```

外键导航属性 `[ForeignKey("POLId")] public PortCode POL` 保持不变，EF Core 自动将其识别为可选外键关系。

### 3.2 DTO 层 - SeServiceConfigDto.cs

以下4个 DTO 的 `POLId` 均从 `long` 改为 `long?`：

| DTO 类名                   | 用途     |
| -------------------------- | -------- |
| `SeServiceConfigAddDto`    | 新增输入 |
| `SeServiceConfigEditDto`   | 编辑输入 |
| `SeServiceConfigListDto`   | 列表输出 |
| `SeServiceConfigDetailDto` | 详情输出 |

> `SeServiceConfigQueryDto` 的 `POLId` 原本已是 `long?`（可选筛选条件），无需修改。

### 3.3 应用服务层 - SeServiceConfigAdminAppService.cs

#### AddAsync 校验逻辑

```csharp
// 修改前：直接校验
var portExists = await ...AnyAsync(x => x.Id == input.POLId);
if (!portExists) throw new UserFriendlyException("起运港不存在");
var polDuplicate = await ...AnyAsync(x => x.POLId == input.POLId);
if (polDuplicate) throw new UserFriendlyException("该起运港已配置服务项目，不能重复配置");

// 修改后：区分有值和为空两种情况
if (input.POLId.HasValue)
{
    var portExists = await ...AnyAsync(x => x.Id == input.POLId.Value);
    if (!portExists) throw new UserFriendlyException("起运港不存在");
    var polDuplicate = await ...AnyAsync(x => x.POLId == input.POLId.Value);
    if (polDuplicate) throw new UserFriendlyException("该起运港已配置服务项目，不能重复配置");
}
else
{
    var defaultExists = await ...AnyAsync(x => x.POLId == null);
    if (defaultExists) throw new UserFriendlyException("默认港口配置已存在，不能重复配置");
}
```

#### EditAsync 校验逻辑

与 `AddAsync` 相同的可空适配，额外排除自身 Id 防止误判重复。

#### GetPagedListAsync / DetailAsync

映射逻辑无需修改，`config.POLId`（`long?`）直接赋值给 `dto.POLId`（`long?`），类型一致。

### 3.4 海运出口服务 - SeaExportAdminAppService.cs

#### GetServiceTypesByPOLAsync 增加默认配置回退

```csharp
// 修改前：只查指定港口
var config = await ...FirstOrDefaultAsync(x => x.POLId == input.POLId.Value);
if (config == null) return null;

// 修改后：指定港口找不到时回退到默认配置
var config = await ...FirstOrDefaultAsync(x => x.POLId == input.POLId.Value);
if (config == null)
{
    config = await ...FirstOrDefaultAsync(x => x.POLId == null);
}
if (config == null) return null;
```

## 四、校验规则变更

| 场景        | 旧规则                | 新规则                               |
| ----------- | --------------------- | ------------------------------------ |
| `POLId`有值 | 校验港口存在 + 唯一性 | **不变**                             |
| `POLId`为空 | 不支持                | 校验默认配置唯一性（每租户最多一条） |

新增错误信息：`"默认港口配置已存在，不能重复配置"`

---

## 五、API 变更对前端的影响

### 5.1 新增接口 (AddAsync)

| 字段    | 旧类型         | 新类型          | 说明                       |
| ------- | -------------- | --------------- | -------------------------- |
| `polId` | `long`（必填） | `long?`（可选） | 传 `null` 创建默认港口配置 |

### 5.2 编辑接口 (EditAsync)

| 字段    | 旧类型         | 新类型          | 说明                       |
| ------- | -------------- | --------------- | -------------------------- |
| `polId` | `long`（必填） | `long?`（可选） | 传 `null` 表示默认港口配置 |

### 5.3 列表/详情接口 (GetPagedListAsync / DetailAsync)

| 字段    | 旧类型   | 新类型    | 说明                             |
| ------- | -------- | --------- | -------------------------------- |
| `polId` | `long`   | `long?`   | 返回 `null` 时代表默认港口配置   |
| `pol`   | `object` | `object?` | `polId` 为空时 `pol` 返回 `null` |

### 5.4 海运出口服务项查询 (GetServiceTypesByPOLAsync)

行为变更：当指定港口无专属配置时，自动回退使用默认港口配置（`POLId = null` 的记录），前端无需额外处理。

## 六、数据库变更

需要生成新的 EF Core Migration，将 `App_SeServiceConfigs` 表的 `POLId` 列从 `bigint NOT NULL` 改为 `bigint NULL`，同时将外键约束改为可选（去除 `IsRequired`）。

```sql
-- 预期 SQL（仅供参考，以实际 Migration 生成为准）
ALTER TABLE App_SeServiceConfigs ALTER COLUMN POLId bigint NULL;
```

## 七、影响范围

| 影响项             | 说明                                       |
| ------------------ | ------------------------------------------ |
| 新增配置           | 支持创建默认港口配置（`polId`为空）        |
| 编辑配置           | 支持将配置设为默认港口配置                 |
| 列表/详情          | `polId`可能返回`null`，`pol`可能返回`null` |
| 海运出口服务项查询 | 无专属港口配置时自动回退默认配置           |
| 已有数据           | 不受影响，现有记录 `POLId` 均有值          |
| 删除接口           | 无变更                                     |

## 八、验收标准

| 序号 | 验收项 | 期望结果 |
| --- | --- | --- |
| 1 | 新增默认配置 | `polId` 传 `null` 可成功创建，返回新记录 Id |
| 2 | 默认配置唯一性 | 同租户下第二次传 `null` 新增时，提示 "默认港口配置已存在，不能重复配置" |
| 3 | 指定港口新增 | `polId` 传具体值，行为与修改前一致 |
| 4 | 编辑默认配置 | 可正常编辑 `polId` 为 `null` 的配置记录 |
| 5 | 列表展示 | 默认配置在列表中 `polId` 返回 `null`，`pol` 返回 `null` |
| 6 | 详情展示 | 默认配置详情 `polId` 返回 `null`，`pol` 返回 `null` |
| 7 | 服务项回退 | 海运出口新建/修改时选择一个没有专属配置的港口，`GetServiceTypesByPOLAsync` 返回默认配置的服务项 |
| 8 | 服务项优先 | 海运出口选择一个有专属配置的港口时，返回专属配置而非默认配置 |
| 9 | 无任何配置 | 港口无专属配置且无默认配置时，`GetServiceTypesByPOLAsync` 返回 `null` |
