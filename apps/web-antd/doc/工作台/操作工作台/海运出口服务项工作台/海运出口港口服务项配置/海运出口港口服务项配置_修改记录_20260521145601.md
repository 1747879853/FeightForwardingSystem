# 海运出口港口服务项配置 修改记录

**修改时间：** 2026-05-21 14:56:01

**修改人：** 后端

---

## 一、问题描述

### 1.1 列表重复显示

新建一个港口服务配置并添加 2 条服务项后，调用列表接口 `GetPagedListAsync` 返回 2 条记录（按子项展开），而非期望的 1 条主配置记录。`totalCount` 也按服务项数量计算，导致分页数据不准确。

### 1.2 软删除数据泄露

查询接口返回了 `IsDeleted = 1`（已软删除）的子项数据。通过 `.Include()` 加载子表后，内存遍历时缺少对 `IsDeleted` 的过滤，导致已删除的服务项、展示字段、锁定字段、必填字段仍被查出。

---

## 二、根因分析

### 2.1 列表查询维度错误

`GetPagedListAsync` 原实现从 `SeServiceConfig` 主表查询后，使用 `SelectMany` 将 `SeServiceConfigItems`（子表）展开为行级数据，每个子项生成一条列表行。分页和计数均基于展开后的子项行数，而非主配置数量。

**原代码关键逻辑：**

```csharp
var allItems = configs.SelectMany(config =>
    (config.SeServiceConfigItems ?? ...)
        .Select(item => new SeServiceConfigItemListDto { ... })
).ToList();

var totalCount = sorted.Count(); // 按子项计数
```

### 2.2 软删除过滤缺失

所有使用 `.Include()` 加载导航属性的场景中，从内存中遍历子集合时均未过滤 `IsDeleted` 字段。涉及接口：

- `GetPagedListAsync`（列表）
- `DetailAsync`（详情）
- `EditAsync`（编辑 — 差异比对加载）
- `DiffSubTableShows/Locks/Requires`（子表差异更新辅助方法）

## 三、修改方案

### 3.1 修改文件清单

| 文件 | 路径 | 修改类型 |
| --- | --- | --- |
| DTO 定义 | `App/SeServiceConfig/Dto/SeServiceConfigDto.cs` | 新增 DTO 类 |
| 应用服务实现 | `App/SeServiceConfig/SeServiceConfigAdminAppService.cs` | 重写查询 + 过滤修复 |
| 应用服务接口 | `App/SeServiceConfig/ISeServiceConfigAdminAppService.cs` | 返回类型变更 |

### 3.2 DTO 变更

**新增** `SeServiceConfigListDto`（主配置级别列表 DTO）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | Guid | 主配置 Id |
| polId | long | 起运港 id |
| pol | PortCodeDto | 起运港信息 |
| sortId | int | 排序 id |
| remark | string | 备注 |
| serviceItemCount | int | 服务项明细数量（仅计算未删除的） |
| serviceTypes | List\<int\> | 服务项类型集合（按 sortId 排序，仅包含未删除的） |
| seServiceConfigItems | List\<SeServiceConfigItemListDto\> | 服务项配置明细列表（按 sortId 排序） |
| creationTime | DateTime | 创建时间 |
| creatorUserId | long? | 创建人 Id |
| lastModificationTime | DateTime? | 最后修改时间 |
| lastModifierUserId | long? | 最后修改人 Id |

**保留** `SeServiceConfigItemListDto`（子项 DTO，作为主配置列表 DTO 的子集合元素），移除了原有的 `POLId` 和 `POL` 字段（已提升到父级 `SeServiceConfigListDto`）。

### 3.3 GetPagedListAsync 重写

**修改前（子项级别分页）：**

- 查询所有 `SeServiceConfig`（带 Include 子项）
- `SelectMany` 展开为子项行
- 在内存中对子项行分页和排序

**修改后（主配置级别分页）：**

- 以 `SeServiceConfig` 主表为分页主体
- 在数据库端完成筛选、排序、分页（`CountAsync` → `OrderBy` → `Skip` → `Take`）
- 每条主配置包含完整的 `SeServiceConfigItems` 子项 DTO 列表
- 同时提供 `serviceItemCount` 和 `serviceTypes` 汇总字段
- `ServiceType` 筛选条件改为：主配置下存在匹配的**未删除**服务项
- 子项加载时显式过滤 `!item.IsDeleted`

### 3.4 软删除过滤修复

在所有 `.Include()` 加载后的内存遍历中添加 `!IsDeleted` 过滤：

| 方法 | 过滤位置 |
| --- | --- |
| `GetPagedListAsync` | `config.SeServiceConfigItems` → `.Where(item => !item.IsDeleted)` |
| `GetPagedListAsync` | `ServiceType` 筛选条件 → `!item.IsDeleted && item.ServiceType == ...` |
| `DetailAsync` | `config.SeServiceConfigItems` → `.Where(x => !x.IsDeleted)` |
| `DetailAsync` | `item.SeServiceShows` → `.Where(s => !s.IsDeleted)` |
| `DetailAsync` | `item.SeServiceLocks` → `.Where(l => !l.IsDeleted)` |
| `DetailAsync` | `item.SeServiceRequires` → `.Where(r => !r.IsDeleted)` |
| `EditAsync` | `config.SeServiceConfigItems` → `.Where(x => !x.IsDeleted)` |
| `DiffSubTableShows` | `existingItem.SeServiceShows` → `.Where(x => !x.IsDeleted)` |
| `DiffSubTableLocks` | `existingItem.SeServiceLocks` → `.Where(x => !x.IsDeleted)` |
| `DiffSubTableRequires` | `existingItem.SeServiceRequires` → `.Where(x => !x.IsDeleted)` |

### 3.5 接口签名变更

```csharp
// 修改前
Task<PagedList<SeServiceConfigItemListDto>> GetPagedListAsync(SeServiceConfigQueryDto input);

// 修改后
Task<PagedList<SeServiceConfigListDto>> GetPagedListAsync(SeServiceConfigQueryDto input);
```

## 四、影响范围

| 影响项 | 说明 |
| --- | --- |
| 列表接口返回结构 | 外层从子项级别变为主配置级别，每条主配置内嵌 `seServiceConfigItems` 子项列表，前端需适配新 DTO 结构 |
| totalCount 含义 | 由"服务项总数"变为"主配置总数" |
| serviceType 筛选行为 | 由"直接筛选子项行"变为"筛选包含该服务项类型的主配置" |
| 详情接口 | 返回结构不变，仅过滤掉已软删除的子项数据 |
| 编辑接口 | 请求/响应结构不变，仅修复差异比对时的软删除过滤 |
| 新增/删除接口 | 无变更 |

## 五、验收标准

| 序号 | 验收项 | 期望结果 |
| --- | --- | --- |
| 1 | 新增验证 | 新建 1 个港口 + 2 个服务项，列表只新增 1 行 |
| 2 | 总数验证 | `totalCount` 按主配置计数，不按服务项计数 |
| 3 | 编辑验证 | 编辑增减服务项后，列表仍为 1 行，不出现拆分 |
| 4 | 删除验证 | 删除主配置后，列表对应 1 行消失 |
| 5 | 回归验证 | 按 `polId`、分页、排序查询结果稳定，不因子项数量产生重复 |
| 6 | 软删除验证 | 列表/详情中不再返回 `IsDeleted = 1` 的子项数据 |
| 7 | ServiceType 筛选 | 传入 `serviceType` 时返回包含该类型的主配置，而非子项行 |
