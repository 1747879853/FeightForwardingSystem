# 海运出口服务项任务 修改记录 2026-06-09

## 修改一：GetWorkbenchPagedListAsync 入参 `seServiceConfigItemId` 替换为 `serviceType`

**接口：** `GET /api/services/app/SeServiceTaskAdmin/GetWorkbenchPagedListAsync`

**变更类型：** 接口变更（**破坏性变更**）

### 变更原因

前端无法获取 `SeServiceConfigItemId`，改为直接传 `serviceType`（服务项类型），后端通过 serviceType 查找对应的 configItemId。

### 入参变更

| 变更前                          | 变更后               |
| ------------------------------- | -------------------- |
| `seServiceConfigItemId` (Guid?) | `serviceType` (int?) |

### 变更前

```
GET /api/services/app/SeServiceTaskAdmin/GetWorkbenchPagedListAsync
  ?polId=1
  &seServiceConfigItemId=3fa85f64-5717-4562-b3fc-2c963f66afa7
```

### 变更后

```
GET /api/services/app/SeServiceTaskAdmin/GetWorkbenchPagedListAsync
  ?polId=1
  &serviceType=1
```

### 参数说明

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| polId | long | **是** | 起运港id |
| serviceType | int? | 否 | 服务项类型（为空代表查指派任务，有值时查该服务项的非指派任务） |

### 业务逻辑变更

- **变更前**：直接用 `SeServiceConfigItemId` 过滤任务
- **变更后**：先通过 `POLId` 找到 `SeServiceConfig`，再通过 `ServiceType` 找到对应的 `SeServiceConfigItem`，然后用 configItemId 过滤任务

### 代码修改

| 文件 | 改动 |
| --- | --- |
| `SeServiceTaskDto.cs` | `SeServiceTaskWorkbenchPagedQueryDto` 删除 `SeServiceConfigItemId`，新增 `ServiceType` |
| `SeServiceTaskAdminAppService.cs` | `GetWorkbenchPagedListAsync` 查询逻辑改为通过 serviceType 查找 configItemIds |

## 修改三：支持默认港口配置（POLId可空）展开

**关联需求：** `SeServiceConfig.POLId` 改为可空，为空时代表默认港口配置。由于港口数量多达数千个，无法为每个港口单独配置服务项。

**变更类型：** 业务逻辑变更（向后兼容）

### 变更原因

`SeServiceConfig.POLId` 支持可空后，任务查询接口需要将默认配置下的任务按实际港口展开显示，确保前端看到的 `polId` 始终为具体港口值。

### 影响的接口

| 接口 | 变更内容 |
| --- | --- |
| `GetPagedListAsync` | 默认配置的任务按 `SeaExport.POLId` 分组展开为多个 ConfigGroup |
| `GetWorkbenchListAsync` | 同上，按实际港口分组展开 |
| `GetWorkbenchCountAsync` | 同上，按实际港口分组统计 |
| `GetWorkbenchPagedListAsync` | 找不到指定港口的配置时，回退使用默认配置 |

### 详细变更

#### 1. GetPagedListAsync / GetWorkbenchListAsync / GetWorkbenchCountAsync

**变更前：** 每个 `SeServiceConfig` 直接生成一个分组，`polId` 取自 `config.POLId`。

**变更后：**

- `config.POLId` 有值时：行为不变，直接生成一个分组
- `config.POLId` 为空时（默认配置）：将该配置下的所有任务按 `task.SeaExport.POLId`（实际海运出口起运港）分组，每个实际港口生成一个独立的分组。`polId` 取自任务的实际起运港，**不会为空**

**前端影响：** 无。返回结构不变，`polId` 始终为具体港口值（`long`，不为空）。只是相同的 `seServiceConfigId` 可能出现在多个分组中（对应不同的实际港口）。

#### 2. GetWorkbenchPagedListAsync

**变更前：** 通过 `input.POLId` 查找 `SeServiceConfig`，找不到直接报错 "未找到该起运港对应的服务项配置"。

**变更后：**

1. 先通过 `input.POLId` 查找专属配置
2. 如果未找到，回退查找默认配置（`POLId == null`）
3. 如果两者都不存在，报错 "未找到该起运港对应的服务项配置,请配置该港口或配置默认港口服务项"

**前端影响：** 无参数变更。报错信息变更。

### 验收标准

| 序号 | 验收项 | 期望结果 |
| --- | --- | --- |
| 1 | 有专属配置的港口 | GetPagedListAsync 等接口行为与修改前完全一致 |
| 2 | 默认配置展开 | 默认配置下的任务按实际起运港分组，每个港口一个 ConfigGroup |
| 3 | polId 不为空 | 返回的所有 ConfigGroup 的 `polId` 始终为具体港口值 |
| 4 | 工作台统计展开 | GetWorkbenchCountAsync 按实际港口分组统计数量 |
| 5 | 分页回退 | GetWorkbenchPagedListAsync 对无专属配置的港口自动使用默认配置 |
| 6 | 无配置报错 | 港口无专属配置且无默认配置时，返回更新后的错误信息 |
| 7 | 混合场景 | 部分港口有专属配置、部分使用默认配置时，列表中两类港口均正确展示 |
