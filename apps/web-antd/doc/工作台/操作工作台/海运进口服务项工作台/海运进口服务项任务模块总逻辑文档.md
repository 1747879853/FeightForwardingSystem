# 海运进口服务项任务模块总逻辑文档

面向测试与前端：讲清海运进口服务项任务怎么生成、谁能处理、完成时校验什么、完成后发生什么。接口见同目录《海运进口服务项任务模块接口文档》。配置规则见《海运进口港口服务项配置模块总逻辑文档》。

# 1. 业务定义

海运进口每勾一个服务项，按优先级依次生成待处理任务，处理人在操作工作台完成、转交。流程与海运出口服务项任务相同，区别：

| 项 | 海运出口 | 海运进口 |
| :-- | :-- | :-- |
| 配置维度 | 起运港 | **目的港** |
| 工作台分组 | 按起运港 | **按目的港** |
| 工作台港口筛选 | 目的港 | **起运港** |
| 日期筛选 | 开船日期(ETD) | **到港日期**(海运进口业务表的 ETD 就是到港日期) |
| 字段枚举 | `SeaExportPropEnum` | `SeaImportPropEnum` |
| 自动费用模板 | 业务类型=海运出口 | 业务类型=海运进口 |

# 4. 任务生成

## 4.1 第一优先级（海运进口新增 / 编辑重建 / 复制 / 业务联系单转海运进口）

1. 取本票勾选的服务项里排序号最小的一档；
2. 这一档每个服务项各生成一条待处理任务；
3. 处理人 = 本票关联人员里用户属性与配置明细要求的用户属性**有交集**的人，去重；
4. 一个都匹配不到 → 「[{目的港中文名}]港的[{服务项值}]服务项任务需要用户属性为[{用户属性名，逗号分隔}]的处理人，当前票未配置此用户属性」，整票保存失败。

## 4.2 下一优先级（完成任务时）

当前任务所在档**本票勾选了的**服务项任务全部完成后，找下一个「本票有勾选服务项」的档位（配置里有、本票没勾的档位直接跳过），给这档还没有任务的服务项生成任务，处理人匹配规则同上。

## 4.3 处理人同步（海运进口编辑，目的港与服务项都没变时）

只改关联人员时，本票**待处理且未转交**的任务按新关联人员重新匹配处理人；处理人集合没变的不动。匹配不到时报 4.1 第 4 条的文案，编辑失败。转交任务与已完成任务不动。

## 4.4 重建（海运进口编辑，目的港或服务项变了）

删除本票全部任务（含已完成）与处理人，按新配置重新生成第一优先级。

# 5. 操作逻辑

## 5.1 查询（多层结构）

按「是否指派」分两种：`isAssigned=true` 查转交给我的；`false` 查没转交且我在处理人里的。筛选：状态、到港日期区间、委托单位、船公司、主提单号(模糊)、起运港。

结构：目的港分组 → 服务项配置明细 → 任务。

- 目的港配置下的任务归在配置的目的港；**默认配置下的任务按票的目的港拆成多组**；
- 每组只列出本次结果里出现过的明细（某组下没有任务的明细也照列，任务列表为空）；
- 明细按排序号、服务项值升序；分组按配置排序号、目的港 id 升序；
- 配置明细已被删掉的任务不进任何分组，但计入总数 `totalCount`。

每条任务带海运进口数据（见 5.8）和处理人（含昵称）。

## 5.2 工作台综合查询

一次返回与我相关的全部任务（转交给我的 + 没转交且我在处理人里的），筛选比 5.1 多一个关键字（模糊匹配主提单号、订舱编号、委托编号）。

结构同 5.1，区别：每组的明细只放**没转交**的任务；每组最后追加一个 `serviceType=null` 的元素，装本组全部**转交**任务。

## 5.3 工作台统计

筛选同 5.2。每个目的港分组：总任务数、配置下**全部**明细各自的未转交任务数（没有任务的为 0），最后一项 `serviceType=null` 为转交任务数。

## 5.4 工作台分页

指定目的港（必填）和服务项分页取任务。

- 目的港有单独配置用它，没有用默认配置，都没有 → 「未找到该目的港对应的服务项配置,请配置该港口或配置默认港口服务项」；
- 用默认配置时**只取该目的港的票**（海出 2026-10-02 修复了同样的问题，之前会把其它港口用默认配置的任务也查出来）；
- 指定服务项 = 查该服务项的未转交任务；不指定 = 查转交任务。

## 5.5 批量转交

校验（逐条，命中即中断）：

1. 任务 id 为空 → 「输入不能为空」
2. 被转交人不存在 → 「被转交人不存在」（海出 2026-10-02 同步补上）
3. 有 id 查不到 → 「部分任务不存在」
4. 任务不是待处理 → 「任务{id}不是待处理状态，无法转交」
5. 转交任务的被转交人不是我 → 「任务{id}的被转交人不是当前用户，无法转交」
6. 未转交任务我不在处理人里 → 「当前用户不在任务{id}的处理人列表中，无法转交」
7. 被转交人已经是处理人 → 「被转交人已在任务{id}的处理人列表中，不能转交给处理人」

通过后写被转交人、转交时间、转交备注。转交任务还可以再转交（由当前被转交人发起）。

## 5.6 完成

校验顺序（命中即中断）：

1. 任务不存在 → 「任务不存在」
2. 配置明细已删 → 「任务对应的服务项配置已被删除」
3. 海运进口或业务表不存在 → 「未找到对应的海运进口数据」
4. 票的目的港为空 → 「海运进口的目的港为空」
5. 票没有关联人员 → 「业务未配置关联用户，无法完成」
6. 不是待处理 → 「任务不是待处理状态，无法完成」
7. 转交任务、我不是被转交人 → 「该任务为转交任务,只能由被转交人[{昵称}]完成,当前用户无法完成」
8. 未转交任务、我不在处理人里 → 「当前任务处理人为[{昵称,昵称}],当前用户不在任务的处理人列表中，无法完成」
9. **必填字段**：当前任务 + 本票**之前所有已完成任务**的完成时必填字段合在一起校验，空了报「必填字段{字段名}不能为空」。字段名：船公司、起运港、目的港、船名、航次、码头航次、主提单号、订舱编号、到港日期、合同号、码头、客户编号、联运单号、分单号、贸易方式、批次号、原产国、净重合计、换单日期、提货日期、报关日期、转站日期、免箱期、箱使日期。委托单位新增时已必填、名称类字段只做展示，不校验。
10. **必填附件**：同样合并当前与已完成任务；本票（模块编码海运进口）没上传的附件类型报「完成任务需要上传以下附件: {类型名、类型名}」，类型已删除时用 id 兜底。
11. **必填费用**：当前明细 `requireFee=true` 时，票上必须已有配置的(收付类型, 费用代码)费用，缺了报「完成任务需要以下费用: [收]{费用中文名}、[付]{费用中文名}」。
12. 下一优先级任务匹配不到处理人 → 4.1 第 4 条的文案。
13. 业务所属公司没有本位币（有命中的模板时才查）→ 「当前公司未配置本位币」
14. 自动费用模板配错 → 「自动费用模板配置有误,无法生成费用: [{模板名}]的费用明细未配置费用代码或该费用代码已被删除、[{模板名}]的费用明细未配置币别或该币别已被删除」

**以上全部在写库之前做完**，任何一条失败都不会落任何数据。通过后：

1. 任务置为已处理，写完成人、完成时间；未转交任务把我这个处理人的完成时间也写上；
2. 插入按自动费用模板生成的费用（见第 6 章）；
3. 插入下一优先级任务（见 4.2）。

返回本次生成的费用条数与简易列表。

## 5.7 取消完成

1. 任务不存在 → 「任务不存在」
2. 不是已处理 → 「任务不是已完成状态，无法取消完成」

通过后：删除本票**排序号比它大**的全部任务及其处理人；本任务回到待处理，清空完成人、完成时间以及处理人上的完成时间（海出 2026-10-02 同步改为一起清）。**已生成的费用不删**，再次完成时同一模板明细不会重复生成。

## 5.8 任务里带的海运进口数据

船名、航次、码头航次、船公司对象、起运港/目的港对象（含航线、国家）及备注、客户编号、码头对象、联运单号、分单号、贸易方式、批次号、原产国对象、净重合计、换单/提货/报关/转站日期、免箱期、箱使日期；业务表：委托编号、主提单号、订舱编号、合同号、到港日期、预抵日期、委托单位对象、件数、毛重、体积、箱型箱量汇总（如 `20GP*2 40HQ*1`）、关联人员（属性、昵称）。前端按配置的展示字段取值。

# 6. 完成时按自动费用模板生成费用

规则同海运出口：

1. 模板启用，长期有效或当前时间在有效期内（起止为空表示不限）；
2. 模板业务类型 = 海运进口；
3. 委托单位、贸易条款、货物类型、付费方式、业务来源、船公司、起运港、目的港：模板上为空 = 不限，有值就要与票一致；
4. **模板上配了订舱代理或提单类型的一律不匹配**（海运进口没有这两个字段）；
5. 所属公司：模板为空 = 所有公司；有值时票的所属组织落在该公司或其下级即可；
6. 模板明细的服务项（明细为空取主表）= 当前完成的服务项；
7. 防重：该模板明细已生成过费用就跳过；
8. 数量按单位：票 = 1，毛重 = Kgs，尺码 = Cbm，TEU = 箱型 TEU 合计，箱型名 = 该箱型箱量；单位是箱型名但本票没有这个箱型时跳过；
9. 汇率按会计期间 + 币别 + 业务所属公司本位币取应收(DRValue)/应付(CRValue)，取不到为 0；
10. 结算对象：模板明细指定了就用；没指定按行业类别从票上取——发货人、收货人、报关行、通知人、车队、委托单位、仓库、保险公司取业务表上的，**码头取海运进口的码头**；场站、订舱代理、目的港代理、地面代理海运进口没有，为空；取不到就空着，由用户补。

生成的费用：录入状态、未结算、未开票、录入方式 = 模板、会计期间取票的会计期间。
