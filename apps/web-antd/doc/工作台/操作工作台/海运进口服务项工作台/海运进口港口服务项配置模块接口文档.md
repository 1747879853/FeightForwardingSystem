# 海运进口港口服务项配置模块接口文档

前端专属，只写接口。业务规则见同目录《海运进口港口服务项配置模块总逻辑文档》。JSON 字段一律 camelCase；业务报错走 ABP 统一信封（`success=false`，`error.message` 为下表文案）。

## 接口一览

| # | 动作 | HTTP | 路径 | 权限 |
| :-- | :-- | :-- | :-- | :-- |
| 1 | 新增 | POST | `/api/services/app/SiServiceConfigAdmin/AddAsync` | `Admin.ServiceConfig.SiServiceConfig.Add` |
| 2 | 编辑 | PUT | `/api/services/app/SiServiceConfigAdmin/EditAsync` | `Admin.ServiceConfig.SiServiceConfig.Edit` |
| 3 | 删除 | DELETE（参数在请求体） | `/api/services/app/SiServiceConfigAdmin/DeleteAsync` | `Admin.ServiceConfig.SiServiceConfig.Delete` |
| 4 | 列表 | GET | `/api/services/app/SiServiceConfigAdmin/GetPagedListAsync` | `Admin.ServiceConfig.SiServiceConfig.Get` |
| 5 | 详情 | GET | `/api/services/app/SiServiceConfigAdmin/DetailAsync` | `Admin.ServiceConfig.SiServiceConfig.Get` |

菜单权限 `Admin.ServiceConfig.SiServiceConfig`（海运进口港口服务项）挂在「业务港口服务项」`Admin.ServiceConfig` 下，与海运出口 `Admin.ServiceConfig.SeServiceConfig` 平级，菜单与按钮按这组权限单独控制。

与海出配置接口(`SeServiceConfigAdmin`)结构一一对应，改名对照：`POLId/POL` → `podId/pod`；`seServiceXxx` → `siServiceXxx`；`seaExportPropEnum` → `seaImportPropEnum`。另外子表入参**不收 id**（编辑按值比对），明细新增 id 传 `null`。

## 1. 新增 AddAsync

### 入参

| 参数                 | 类型         | 必填 | 说明                         |
| :------------------- | :----------- | :--- | :--------------------------- |
| podId                | long?        | 否   | 目的港 id，`null` = 默认配置 |
| sortId               | int          | 否   | 排序                         |
| remark               | string(1024) | 否   | 备注                         |
| siServiceConfigItems | 数组         | 否   | 明细，见下表                 |

`siServiceConfigItems[]`：

| 参数 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| serviceType | int | 是 | 服务项。前端枚举，枚举管理 Name：`ServiceType`。同一配置不能重复 |
| userAttribute | int | 是 | 用户属性(Flags，多选按位或) |
| autoComplete | bool | 否 | 是否自动完成 |
| requireFee | bool | 否 | 完成时是否校验必填费用 |
| manualAllowed | bool | 否 | 允许手动完成 |
| reminder | bool | 否 | 完成提醒 |
| sortId | int | 是 | 优先级，≥0，相同 = 同一档 |
| remark | string(1024) | 否 | 备注 |
| siServiceShows | 数组 | 否 | 展示字段，元素 `{ seaImportPropEnum }` |
| siServiceLocks | 数组 | 否 | 完成后不允许修改字段，元素 `{ seaImportPropEnum }` |
| siServiceRequires | 数组 | 否 | 完成时必填项，元素 `{ seaImportPropEnum, requireValues }`；`seaImportPropEnum=10001`(附件类型)时 `requireValues` 必填，附件类型 id 竖线分隔，如 `"1\|2\|3"` |
| siServiceRequireFees | 数组 | 否 | 必填费用，元素 `{ paySide, feeCodeId }`，`paySide`：0 收 1 付 |

`seaImportPropEnum`：海运进口字段枚举，枚举管理 Name：`SeaImportPropEnum`，取值见总逻辑文档 2.4。展示/锁定字段不能用 ≥10001 的值。

### 出参

`result`：新配置 id（Guid 字符串）。

### 报错

| 文案 | 条件 |
| :-- | :-- |
| 输入不能为空 | 请求体为空 |
| 目的港不存在 | `podId` 查不到 |
| 该目的港已配置服务项目，不能重复配置 | 该目的港已有配置 |
| 默认港口配置已存在，不能重复配置 | `podId=null` 且已有默认配置 |
| 同一配置下服务项类型不能重复 | 明细 `serviceType` 重复 |
| 排序id不能小于0 | 明细 `sortId<0` |
| 展示字段不支持[{字段}]，该类型仅完成时必填项可用 | 展示字段用了 ≥10001 |
| 完成后不允许修改字段不支持[{字段}]，该类型仅完成时必填项可用 | 锁定字段用了 ≥10001 |
| 完成时必填项为附件类型时，必须指定至少一个附件类型 | `requireValues` 解析不出 id |
| 附件类型不存在: {id、id} | 附件类型 id 查不到 |
| 必填费用的费用代码不存在: {id、id} | `feeCodeId` 查不到 |

### 样例

```json
{
  "podId": 1023,
  "sortId": 1,
  "remark": "",
  "siServiceConfigItems": [
    {
      "serviceType": 1,
      "userAttribute": 1,
      "requireFee": true,
      "sortId": 1,
      "siServiceShows": [
        { "seaImportPropEnum": 14 },
        { "seaImportPropEnum": 16 }
      ],
      "siServiceLocks": [{ "seaImportPropEnum": 14 }],
      "siServiceRequires": [
        { "seaImportPropEnum": 14 },
        { "seaImportPropEnum": 10001, "requireValues": "3|5" }
      ],
      "siServiceRequireFees": [{ "paySide": 0, "feeCodeId": 12 }]
    }
  ]
}
```

## 2. 编辑 EditAsync

### 入参

新增入参全部字段 + 下列字段：

| 参数 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| id | Guid | 是 | 配置 id |
| siServiceConfigItems[].id | Guid? | 否 | `null` = 新增明细；有值必须是本配置已有明细。**入参里没有的已有明细会被删除** |

子表（展示/锁定/必填/必填费用）**不收 id**，后端按字段值（必填费用按收付类型+费用代码）与库里比对增删改，整份提交即可。

### 出参

`result`：`true`。

### 报错

新增的全部报错（重复判断排除自身）+：

| 文案 | 条件 |
| :-- | :-- |
| 配置不存在 | `id` 查不到 |
| 服务项配置明细不存在或不属于该配置: {id} | 明细 id 不属于本配置 |
| 服务项[{服务项值、…}]已被海运进口服务项任务模块引用,禁止删除 | 要删的明细已生成过任务 |

## 3. 删除 DeleteAsync

### 入参（请求体）

| 参数 | 类型   | 必填 | 说明            |
| :--- | :----- | :--- | :-------------- |
| ids  | Guid[] | 是   | 要删除的配置 id |

### 出参

`result`：`true`。

### 报错

| 文案                                    | 条件               |
| :-------------------------------------- | :----------------- |
| 输入不能为空                            | `ids` 为空         |
| 配置不存在                              | 一个都查不到       |
| 已被海运进口服务项任务模块引用,禁止删除 | 任一明细已生成任务 |

## 4. 列表 GetPagedListAsync

### 入参（QueryString）

| 参数 | 类型 | 说明 |
| :-- | :-- | :-- |
| pageIndex / pageSize | int | 分页 |
| sorting | string | 排序，默认 `CreationTime DESC` |
| podId | long? | 目的港，精确 |
| serviceType | int? | 包含该服务项的配置。枚举管理 Name：`ServiceType` |

### 出参

分页外壳 `{ totalCount, items }`，`items[]`：

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| id | Guid | 配置 id |
| podId | long? | 目的港 id，`null` = 默认配置 |
| pod | 对象 \| null | 目的港（港口对象，含 `country`、`lane`） |
| sortId / remark | - | 排序、备注 |
| serviceItemCount | int | 明细数 |
| serviceTypes | int[] | 明细服务项值，按排序号升序 |
| siServiceConfigItems | 数组 | 明细（不含子表）：`id`、`siServiceConfigId`、`serviceType`、`userAttribute`、`autoComplete`、`requireFee`、`manualAllowed`、`reminder`、`sortId`、`remark` 及审计字段 |
| creationTime / creatorUserId / lastModificationTime / lastModifierUserId | - | 审计 |

## 5. 详情 DetailAsync

### 入参（QueryString）

| 参数 | 类型 | 必填 | 说明    |
| :--- | :--- | :--- | :------ |
| id   | Guid | 是   | 配置 id |

### 出参

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| id / podId / pod / sortId / remark / 审计字段 | - | 同列表 |
| siServiceConfigItems | 数组 | 明细，在列表字段基础上多四个子表：`siServiceShows[] { id, seaImportPropEnum }`、`siServiceLocks[] { id, seaImportPropEnum }`、`siServiceRequires[] { id, seaImportPropEnum, requireValues }`、`siServiceRequireFees[] { id, paySide, feeCodeId, feeCode }`（`feeCode` 为费用代码简易对象） |
| userAttributeServiceTypes | 数组 | `{ userAttribute, serviceTypes: int[] }`，八个用户属性各一组 |

### 报错

| 文案       | 条件        |
| :--------- | :---------- |
| 配置不存在 | `id` 查不到 |
