# 海运进口港口服务项配置模块总逻辑文档

面向测试与前端：讲清楚海运进口按**目的港**配置服务项目的规则。接口地址与出入参见同目录《海运进口港口服务项配置模块接口文档》。

# 1. 业务定义

一份配置 = 一个目的港 + 若干服务项明细。海运进口新建/编辑时按票的目的港取配置，决定这票能勾哪些服务项、每个服务项的优先级、谁来处理、完成时要校验什么、完成后锁住哪些字段。

流程与海运出口港口服务项配置相同，**唯一区别：海运出口按起运港配置，海运进口按目的港配置**。两套配置互不影响，服务项枚举共用（枚举管理 Name：`ServiceType`）。

**默认配置**：目的港为空的那份。一票的目的港没有单独配置时用默认配置。默认配置最多一份。

# 2. 表结构

## 2.1 App_SiServiceConfigs（配置主表）

| 字段     | 类型         | 说明                                             |
| :------- | :----------- | :----------------------------------------------- |
| Id       | Guid         | 主键                                             |
| TenantId | int          | 租户                                             |
| PODId    | long?        | 目的港 id，为空 = 默认配置。同一目的港只能有一份 |
| SortId   | int          | 排序                                             |
| Remark   | string(1024) | 备注                                             |
| 审计字段 | -            | 创建/修改/软删除                                 |

## 2.2 App_SiServiceConfigItems（配置明细，一个服务项一行）

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| Id | Guid | 主键，海进服务项任务挂在它上面 |
| SiServiceConfigId | Guid | 所属配置 |
| ServiceType | int | 服务项。前端枚举，枚举管理 Name：`ServiceType`。同一配置下不能重复 |
| UserAttribute | int(Flags) | 处理人需要的用户属性，可多选；票上关联人员属性与之有交集的人就是处理人 |
| AutoComplete | bool | 是否自动完成（只存储，后端不用） |
| RequireFee | bool | 完成时是否校验必填费用 |
| ManualAllowed | bool | 允许手动完成（只存储，后端不用） |
| Reminder | bool | 完成提醒（只存储，后端不用） |
| SortId | int | 优先级，**不能小于 0**；相同表示同一档并行生成任务 |
| Remark | string(1024) | 备注 |

## 2.3 明细下的四张子表

| 表 | 关键字段 | 作用 |
| :-- | :-- | :-- |
| App_SiServiceShows | SeaImportPropEnum | 工作台展示哪些字段 |
| App_SiServiceLocks | SeaImportPropEnum | 该服务项**完成后**，海运进口编辑时这些字段换回原值 |
| App_SiServiceRequires | SeaImportPropEnum、RequireValues(512) | 完成该服务项时必须有值的字段；字段为 10001(附件类型)时 RequireValues 存附件类型 id，竖线分隔，如 `1\|2\|3` |
| App_SiServiceRequireFees | PaySide、FeeCodeId | 完成时票上必须已有的费用（明细 `RequireFee=true` 才校验） |

# 4. 操作逻辑

## 4.1 新增

校验（命中即中断）：

1. 输入为空 → 「输入不能为空」
2. 选了目的港但港口不存在 → 「目的港不存在」
3. 该目的港已有配置 → 「该目的港已配置服务项目，不能重复配置」
4. 没选目的港且已有默认配置 → 「默认港口配置已存在，不能重复配置」
5. 明细服务项重复 → 「同一配置下服务项类型不能重复」
6. 明细排序号小于 0 → 「排序id不能小于0」
7. 展示字段用了扩展类型(≥10001) → 「展示字段不支持[{字段}]，该类型仅完成时必填项可用」
8. 完成后不允许修改字段用了扩展类型 → 「完成后不允许修改字段不支持[{字段}]，该类型仅完成时必填项可用」
9. 必填项为附件类型却没指定附件类型 → 「完成时必填项为附件类型时，必须指定至少一个附件类型」
10. 指定的附件类型不存在 → 「附件类型不存在: {id、id}」
11. 必填费用的费用代码不存在 → 「必填费用的费用代码不存在: {id、id}」（海出没有这条，海出要到提交时才报数据库错）

保存：主表、明细、四张子表一次插入。同一明细里重复的字段 / 重复的(收付,费用代码) 只存一条；必填项同一字段传多次以最后一次的具体值为准；附件类型 id 去重、升序后存。

## 4.2 编辑

校验：配置不存在 → 「配置不存在」；第 2～11 条同新增（重复判断排除自身）；另外：

- 明细带了 Id 但不是本配置的明细 → 「服务项配置明细不存在或不属于该配置: {id}」。**新增明细 Id 传 null**，不要传空 Guid。
- 输入里没有的已有明细要删除，但它已经生成过海运进口服务项任务 → 「服务项[{服务项值、…}]已被海运进口服务项任务模块引用,禁止删除」。**与海出不同**：海出允许删，删完任务就找不到配置了。

保存：

- 主表改目的港、排序、备注。
- 明细：Id 为空 → 新增（连同子表）；Id 有值 → 改字段；输入里没有 → 连同四张子表删除。
- 已有明细的四张子表**按值比对**，不认子表 Id：展示/锁定字段按字段值增删；必填字段按字段值增删，具体值变了就改；必填费用按(收付类型, 费用代码)增删。只改真正变化的行。

改优先级、用户属性、必填/锁定字段对**已生成的任务**立刻生效（任务挂的是明细 Id，完成和锁定时读的是明细当前配置）。

## 4.3 删除

入参 `Ids` 批量删除。

1. `Ids` 为空 → 「输入不能为空」
2. 一个都查不到 → 「配置不存在」
3. 任一明细已生成海运进口服务项任务 → 「已被海运进口服务项任务模块引用,禁止删除」

通过后依次删除四张子表、明细、主表（软删除不会级联，全部显式删）。

## 4.4 列表

按主配置分页，一行一份配置。筛选：目的港（精确）、服务项（配置里包含该服务项）。每行带目的港对象（含国家、航线）、服务项个数、服务项值列表、明细列表（不含子表），明细按排序号、服务项值升序。

## 4.5 详情

返回主表、目的港对象、明细（含四张子表，必填费用带费用代码对象），以及按用户属性分组的服务项列表（操作、客服、单证、商务、销售、财务、海外客服、人事各一组）。

# 5. 被谁使用

| 使用方 | 怎么用 |
| :-- | :-- |
| 海运进口新增/编辑/复制 | 校验服务项都在配置里，服务项排序号取配置，生成第一优先级任务 |
| 海运进口「按目的港带出服务项」 | 列出配置明细与默认勾选 |
| 海进服务项任务 | 完成时读必填字段/附件/费用，生成下一档；编辑时读锁定字段 |
| 业务联系单转海运进口 | 按目的港配置生成服务项与第一档任务 |
| 委托单位排除海运进口服务项 | 按配置列出可排除的服务项 |
| 港口删除 | 被配置引用的目的港不能删，报「业务港口服务项目配置」 |
