# sea-exports 列配置历史脏数据自愈修复

## 背景意图

- 日志确认远端配置已成功拉取，但配置中的列 key 为历史值（如 `col_56`），与当前页面稳定列 key（`col_0...col_11`）完全不匹配。
- 导致表现为“加载成功但应用无效”。

## 核心技术决策 / 逻辑变更

- 在 `packages/effects/plugins/src/vxe-table/use-vxe-grid.vue` 增加脏配置识别与自愈逻辑：
  - 应用远端配置时统计匹配数量（顺序匹配、显隐匹配）。
  - 当“远端存在 key 且匹配数全为 0”时，判定为历史脏配置，不再视作成功应用。
  - 使用当前归一化列生成健康配置并回写后端（自愈覆盖）。
- 强化保存时稳定 key 采集：
  - 通过 `field/title/type` 签名映射回稳定 key，避免运行时随机 id 再次写入后端。

## 避坑指南（Gotchas & Constraints）

- 列配置 JSON 里只要 key 与当前列系统不同源，就会出现“看似加载成功但无任何视觉变化”。
- 历史坏数据不能仅靠前端“继续应用”解决，必须触发一次回写自愈，后续刷新才会稳定生效。
