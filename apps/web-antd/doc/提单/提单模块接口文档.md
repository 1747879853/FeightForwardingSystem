# 0. 通用说明

- **接口前缀**：`/api/services/app/BillOfLadingAdmin/`
- **方法名的 `Async` 后缀不能省**：方法叫 `GetPagedListAsync`，地址就是 `/api/services/app/BillOfLadingAdmin/GetPagedListAsync`。
- **分页参数**是 `PageIndex`（从 1 开始）与 `PageSize`，不是 `skipCount`。
- 提单**没有新增、编辑、删除接口**：提单随海运出口主单、海出分单、件杂货主单、件杂货分单自动创建、连带删除。
- **提单的四种来源**看出参上挂的对象：挂 `SeaExport` 的是海运出口侧（`SeaExportSeparate` 有值就是海出分单提单），挂 `BreakBulk` 的是件杂货侧（`BreakBulkSeparate` 有值就是件杂货分单提单）。`SeaExport` 与 `BreakBulk` 互斥，结构见第 9 章。件杂货本身的字段说明见《件杂货模块总逻辑文档》（`文档/件杂货/件杂货模块总逻辑文档.md`）。
- 所有 `GET` 接口参数放 query，所有 `POST` 接口参数放 body。
- 海运出口列表也会带该票提单：`GET /api/services/app/SeaExportAdmin/GetPagedListAsync` 的每条 `billOfLadings` 只含 `id` 与 `status`（主单与分单都在，状态取值同下表）。字段说明见《海运出口api.md》第 5 节。

## 0.1 枚举字典

**提单状态 `Status`**

| 值  | 名称       | 说明                       |
| :-- | :--------- | :------------------------- |
| 0   | 待签入     | 正本的初始状态             |
| 1   | 已签入     | 非正本建出来就是这个状态   |
| 2   | 已驳回     | 行为上与「已签入」完全相同 |
| 3   | 签出审核中 | 禁止任何其他操作           |
| 4   | 可签出     | 审核通过                   |
| 5   | 已签出     |                            |
| 6   | 已扣单     | 只能取消扣单               |

**操作动作 `ActionType`**

| 值  | 名称 | 值  | 名称     |
| :-- | :--- | :-- | :------- |
| 0   | 签入 | 1   | 取消签入 |
| 2   | 签出 | 3   | 取消签出 |
| 4   | 换签 | 5   | 取消换签 |
| 6   | 扣单 | 7   | 取消扣单 |

**签出方式 `SignOutType`**

| 值  | 名称     |
| :-- | :------- |
| 0   | 快递     |
| 1   | 自提     |
| 2   | 外派     |
| 3   | 邮件     |
| 4   | 电子提单 |

**我的审核状态 `MyAuditStatus`**：`0` 待我审核、`2` 我已审核（不传代表与我有关的全部）

**任务状态 `TaskStatus`**：`0` 审核中、`1` 驳回、`2` 通过、`3` 部分通过（仅主任务会出现）

**分组字段 `GroupField`**（取值与海运出口同名字段一致）

| 值  | 名称     |
| :-- | :------- |
| 3   | 委托单位 |
| 4   | 船公司   |
| 9   | 签单方式 |

# 1. 提单分页列表

- **地址**：`GET /api/services/app/BillOfLadingAdmin/GetPagedListAsync`
- **权限**：`Admin.BillOfLading.Get`
- **说明**：可见范围 = 海运出口业务数据权限内的票 ∪ 件杂货业务数据权限内的票，两边各按自己模块的数据权限与表级权限算（只能看到自己/本机构/自己是关联人员的票）。

## 1.1 入参

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| PageIndex | int | 否 | 页码，默认 1 |
| PageSize | int | 否 | 每页条数，默认 10 |
| Sorting | string | 否 | 排序，默认 `CreationTime DESC`，支持多级导航属性路径，如 `TransportOrder.ETD DESC`、`TransportOrder.SeaExport.Vessel`。**2026-09-27 提单导航由 `SeaExport` 改为 `TransportOrder`**：旧路径 `SeaExport.TransportOrder.ETD DESC` 会报「排序字段无效」，要改成 `TransportOrder.ETD DESC` |
| Status | int? | 否 | 提单状态 |
| BlNum | string | 否 | 提单号，主单提单模糊匹配主提单号、分单提单（海出分单或件杂货分单）模糊匹配分提单号 |
| ClientId | Guid? | 否 | 委托单位 id（分单提单也按其所属主单的委托单位匹配） |
| CodeIssueTypeId | long? | 否 | 签单方式 id，主单提单比主单（海运出口或件杂货）的、分单提单比分单（海出分单或件杂货分单）的 |
| CodeIssueTypeIdEmpty | bool? | 否 | 签单方式未填写。`true` 时只返回签单方式为空的提单。**与 `CodeIssueTypeId` 不可同时传入**。点分组里「未填写」组时传这个 |
| CarrierId | long? | 否 | 船公司 id。**2026-09-20 新增**，点船公司分组下钻列表时传。**只对海运出口有效**：件杂货没有船公司，传了之后件杂货提单一律不返回 |
| CarrierIdEmpty | bool? | 否 | 船公司未填写。`true` 时只返回船公司为空的提单，**件杂货提单全部算未填写**。**与 `CarrierId` 不可同时传入**。点分组里「未填写」组时传这个 |
| Vessel | string | 否 | 船名，模糊，海运出口与件杂货都匹配 |
| Voyno | string | 否 | 航次，同时模糊匹配船公司航次与码头航次，海运出口与件杂货都匹配 |
| ETDStart | DateTime? | 否 | 开船日期起（含当天），按业务表取 |
| ETDEnd | DateTime? | 否 | 开船日期止（含当天），按业务表取 |
| UserId | long? | 否 | 业务员/操作，命中业务所属人或业务关联人员即可 |
| CommissionNum | string | 否 | 委托编号，模糊，按业务表取 |
| IsOverdueUnpaid | bool? | 否 | 是否超期未付。**2026-09-20 新增**，**只接受 `true`**：为 `true` 时只返回已过应结日期且该票应收未结清的提单，**不管承诺付款日期**；`false` 与不传都不筛选。主单提单比主单应结日期，分单提单比分单自己的应结日期（存量海出分单应结日期为默认值的不算超期；件杂货分单没有这种存量） |
| IsOverdue | bool? | 否 | 是否超期（当天已过主单应结日期且该票应收未全部结清；`true`/`false` 都生效） |
| IsDeducted | bool? | 否 | 是否已扣单。**2026-09-27 新增**，**只接受 `true`**：为 `true` 时只返回状态为 `已扣单`（6）的提单；`false` 与不传都不筛选。与 `Status` 同时传时取交集，`Status` 不是 6 就查不到数据。点四个数量里的「已扣单」下钻时传这个 |
| SignInDateStart | DateTime? | 否 | 签入日期起，按当前生效的那次签入比 |
| SignInDateEnd | DateTime? | 否 | 签入日期止 |
| SignOutDateStart | DateTime? | 否 | 签出日期起，按当前生效的那次签出比 |
| SignOutDateEnd | DateTime? | 否 | 签出日期止 |
| IsSeparate | bool? | 否 | `true` 只看分单提单（海出分单与件杂货分单）、`false` 只看主单提单（海运出口主单与件杂货主单），不传两者都要 |

## 1.2 出参

`PagedList<BillOfLadingDto>`：

| 字段           | 类型 | 说明                  |
| :------------- | :--- | :-------------------- |
| Items          | 数组 | 见第 9 章「提单结构」 |
| TotalCount     | int  | 总条数                |
| SkipCount      | int  | 已跳过条数            |
| MaxResultCount | int  | 本页最大条数          |

## 1.3 分组统计

- **地址**：`GET /api/services/app/BillOfLadingAdmin/GetGroupedListAsync`
- **权限**：`Admin.BillOfLading.Get`
- **说明**：查询条件与列表 `GetPagedListAsync` **完全一致**（同一套筛选与数据权限），额外指定 `GroupField`。先筛再分组，返回每组的 id、名称、提单条数，按条数倒序。不分页，`PageIndex`/`PageSize`/`Sorting` 无效。`Count` 是**提单条数**，不是业务票数（一张主单下的主单提单和各分单提单分开计，海运出口与件杂货的提单一起计）。

点某组后带对应条件再调列表：委托单位传 `ClientId`，船公司传 `CarrierId`，签单方式传 `CodeIssueTypeId`。点「未填写」组（`id`/`name` 均为 null）时传对应 `*Empty=true`。

### 入参 `BillOfLadingGroupQueryDto`

继承列表全部查询参数，另加：

| 字段       | 类型 | 必填 | 说明                                             |
| :--------- | :--- | :--- | :----------------------------------------------- |
| GroupField | int  | 是   | 分组字段：`3` 委托单位、`4` 船公司、`9` 签单方式 |

| 分组字段 | 分组口径 | Id | Name | Logo |
| :-- | :-- | :-- | :-- | :-- |
| 3 委托单位 | 一律按所属主单（业务表）的委托单位 | Guid 字符串 | 客户名称 | 无 |
| 4 船公司 | 海运出口主单上的船公司；**件杂货提单全部落到未填写组** | long 字符串；未填写为 null | 中文简称 | 有 |
| 9 签单方式 | 主单提单比主单（海运出口或件杂货）、分单提单比该分单（海出分单或件杂货分单） | long 字符串；未填写为 null | 签单方式名称 | 无 |

### 出参 `BillOfLadingGroupDto[]`

| 字段  | 类型   | 说明                             |
| :---- | :----- | :------------------------------- |
| Id    | string | 分组值 id，未填写组为 null       |
| Name  | string | 分组名称，未填写组为 null        |
| Count | int    | 该组提单条数                     |
| Logo  | 对象   | 仅按船公司分组时有值，结构同附件 |

### 请求示例

```
GET /api/services/app/BillOfLadingAdmin/GetGroupedListAsync?GroupField=4
GET /api/services/app/BillOfLadingAdmin/GetGroupedListAsync?GroupField=9&Status=4
GET /api/services/app/BillOfLadingAdmin/GetGroupedListAsync?GroupField=3&IsOverdueUnpaid=true
GET /api/services/app/BillOfLadingAdmin/GetGroupedListAsync?GroupField=3&IsDeducted=true
```

## 1.4 四个数量

- **地址**：`GET /api/services/app/BillOfLadingAdmin/GetCountAsync`
- **权限**：`Admin.BillOfLading.Get`
- **说明**：无搜索条件。四个数量都只统计当前用户业务数据权限内能看到的提单（海运出口与件杂货两边的可见范围合在一起），与列表同一套可见范围。点某个数量下钻列表或分组时带的条件：总数量不带条件，待签出传 `Status=4`，超期未收传 `IsOverdueUnpaid=true`，已扣单传 `IsDeducted=true`。

### 入参

无。

### 出参 `BillOfLadingCountDto`

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| TotalCount | int | 总数量，当前用户能看到的全部提单，口径与列表不带任何筛选时的 `TotalCount` 相同 |
| PendingSignOutCount | int | 待签出数量，状态为 `可签出` |
| OverdueUnReceivedCount | int | 超期未收数量，口径与列表 `IsOverdueUnpaid=true` 相同：已过应结日期且应收未结清，不管承诺付款日期 |
| DeductedCount | int | 已扣单数量，状态为 `已扣单`，口径与列表 `IsDeducted=true` 相同。**2026-09-27 新增，替换原待审核数量 `PendingAuditCount`（该字段已删除，接口不再返回）** |

# 2. 提单详情

- **地址**：`GET /api/services/app/BillOfLadingAdmin/GetAsync`
- **权限**：`Admin.BillOfLading.Get`
- **说明**：按提单所属那一票判数据权限：件杂货的票按件杂货模块的业务数据权限与表级权限判，其余按海运出口判。提单操作历史（第 3 章）同一口径。

## 2.1 入参

| 字段 | 类型 | 必填 | 说明    |
| :--- | :--- | :--- | :------ |
| Id   | Guid | 是   | 提单 id |

## 2.2 出参

单个 `BillOfLadingDto`，见第 9 章「提单结构」。

## 2.3 报错

- `提单id不能为空` / `提单不存在`
- `海运出口不存在` / `件杂货不存在`（提单所属的那一票已不存在）
- `没有这条数据的数据权限,不能查看` / `没有这条数据的表级权限,不能查看`

# 4. 签入相关

## 4.1 签入

- **地址**：`POST /api/services/app/BillOfLadingAdmin/SignInAsync`
- **权限**：`Admin.BillOfLading.SignIn`
- **前置状态**：`待签入`

### 入参

| 字段        | 类型     | 必填 | 说明                                   |
| :---------- | :------- | :--- | :------------------------------------- |
| Id          | Guid     | 是   | 提单 id                                |
| SignInDate  | DateTime | 是   | 签入日期，用户自己填，不限制未来日期   |
| Remark      | string   | 否   | 签入备注，≤1024 字                     |
| Attachments | 数组     | 是   | 提单扫描件，**只能一个**。子字段见 9.7 |

### 出参

`bool`，成功返回 `true`。

### 报错

- `提单id不能为空` / `签入日期不能为空` / `提单扫描件不能为空` / `提单扫描件只能上传一个`
- `提单当前为XX,不可签入`

## 4.2 取消签入

- **地址**：`POST /api/services/app/BillOfLadingAdmin/CancelSignInAsync`
- **权限**：`Admin.BillOfLading.SignIn`
- **前置条件**：状态为 `已签入`/`已驳回`、签单方式是正本、当前有生效的签入、且未换签
- **说明**：回到 `待签入`；**原签入扫描件保留**（挂在那一次签入的历史上），再签入要重新上传。

### 入参

| 字段   | 类型   | 必填 | 说明     |
| :----- | :----- | :--- | :------- |
| Id     | Guid   | 是   | 提单 id  |
| Remark | string | 否   | 取消备注 |

### 出参

`bool`。

### 报错

- `提单当前为XX,不可取消签入`
- `提单已换签,请先取消换签`
- `非正本提单不可取消签入`
- `提单没有可取消的签入记录`

# 5. 换签（改签）相关

## 5.1 换签

- **地址**：`POST /api/services/app/BillOfLadingAdmin/SwapAsync`
- **权限**：`Admin.BillOfLading.Swap`
- **前置条件**：状态为 `已签入`/`已驳回`、签单方式是正本
- **说明**：支持批量。把签单方式改成「电放」——**主单提单改主单（海运出口或件杂货），分单提单只改该分单（海出分单或件杂货分单）**，不连带改别人。提单状态不变。基础资料里必须存在 `BillType` 精确等于「电放」的记录。一批里可以同时有海运出口和件杂货的提单。

### 入参

| 字段     | 类型     | 必填 | 说明              |
| :------- | :------- | :--- | :---------------- |
| Ids      | Guid[]   | 是   | 提单 id，支持多个 |
| SwapDate | DateTime | 是   | 换签时间          |
| Remark   | string   | 否   | 换签备注          |

### 出参

`bool`。

### 报错

- `请选择提单` / `换签时间不能为空` / `提单不存在`
- `所选提单中有您没有权限换签的票`
- `请先在签单方式基础资料中维护【电放】,否则无法换签`
- `提单当前为XX,不可换签` / `只有正本提单可以换签`
- `海运出口分单不存在` / `件杂货分单不存在` / `提单所属的业务不存在`：写回签单方式时主单或分单已不存在（数据异常才会出现）。**2026-09-27 主单不存在时的文案由「海运出口不存在」改为「提单所属的业务不存在」**

## 5.2 取消换签

- **地址**：`POST /api/services/app/BillOfLadingAdmin/CancelSwapAsync`
- **权限**：`Admin.BillOfLading.Swap`
- **说明**：把签单方式恢复成换签前那个（正本），状态不变。

### 入参

| 字段   | 类型   | 必填 | 说明     |
| :----- | :----- | :--- | :------- |
| Id     | Guid   | 是   | 提单 id  |
| Remark | string | 否   | 取消备注 |

### 出参

`bool`。

### 报错

- `提单当前为XX,不可取消换签`
- `提单没有可取消的换签记录`
- `换签记录缺少换签前的签单方式,无法恢复`

# 6. 扣单相关

`bool`。

### 报错

- `请选择提单` / `扣单日期不能为空`

## 6.2 取消扣单

- **地址**：`POST /api/services/app/BillOfLadingAdmin/CancelDeductAsync`
- **权限**：`Admin.BillOfLading.Deduct`
- **说明**：回到**扣单之前**的那个状态。

### 入参

| 字段   | 类型   | 必填 | 说明     |
| :----- | :----- | :--- | :------- |
| Id     | Guid   | 是   | 提单 id  |
| Remark | string | 否   | 取消备注 |

### 出参

`bool`。

### 报错

- `提单未扣单,无需取消` / `提单没有可取消的扣单记录`

# 7. 签出审核相关

## 7.1 提交签出审核

- **地址**：`POST /api/services/app/BillOfLadingAdmin/SubmitAsync`
- **权限**：`Admin.BillOfLading.Submit`
- **前置状态**：`已签入` 或 `已驳回`

| :---- | :--- | :--- | :--------------------- |
| Items | 数组 | 是   | 提交明细，一张提单一条 |

**Items 子字段**

### 出参

| :-- | :-- |
| Guid? | 审核主任务 id（撤销提交要用）。工作流算不出审核人而整批直接通过时返回 `null`，此时提单已经是 `可签出` |

#### 7.5.1 ClientOverdues（结算单位超期列表）

> 统计的是**本批提单的结算单位 x**（行级 `Settlement`，主单提单取主单委托单位、分单提单取分单结算对象），不是主单委托单位。范围是该结算单位名下的全部应收费用（`OrderFee.SettlementId = x`），**跨票跨时间**，不限于本批这几票。费用捞出来先按下面的口径组合，再按业务 id 分组，一票一条，按应结日期升序。

**四类超期合并在这一张表里**，靠三个天数字段区分，四个天数全为 0 的票不会出现在列表里：

| 想看哪一类         | 看哪个字段                                             |
| :----------------- | :----------------------------------------------------- |
| 客户历史超期       | `HistoryOverdueDays > 0`                               |
| 客户超期未结       | `OverdueDays > 0`                                      |
| 客户历史承诺超期   | `PromiseOverdueDays > 0` 且 `FinalSettlementTime` 有值 |
| 客户超承诺时间未结 | `PromiseOverdueDays > 0` 且该票还有没结清的费用        |

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| TransportOrderId | Guid | 业务 id，本行的分组键 |
| SeaExport | object? | 海运出口，**仅该票为海运出口时有值**。含**提单类型、装运方式、船公司、起运港、目的港、订舱代理、签单方式**，以及嵌套的业务表（**主提单号、开船日期、委托单位、贸易条款、箱型箱量、业务关联人员**）。结构见 9.2 |
| BreakBulk | object? | **2026-09-27 新增**。件杂货，**仅该票为件杂货时有值**，与 `SeaExport` 互斥。含**起运港、目的港、订舱代理、签单方式**，以及嵌套的业务表（字段同上，箱型箱量为空）。结构见 9.2.2。海运进口、空运出口的票这两个对象都为 null |
| BlNums | string[] | **分提单号**，只列本票下结算对象为本结算单位的那些分单（海出分单或件杂货分单）；主单侧欠款时为空数组 |
| SettlementDate | DateTime | 对本结算单位的应结日期 |
| HistoryOverdueDays | int | **历史超期天数**：已结清但结晚了，实际结算日期减应结日期；没超期为 0 |
| OverdueDays | int | **当前超期天数**：未结清且已过应结日期，当天减应结日期；没超期为 0 |
| UnReceivedAmount | decimal | **未结金额**，本位币 |
| PromisePayDate | DateTime? | **承诺付款日期**，没填为 null |
| FinalSettlementTime | DateTime? | **实际结算日期**，本票已结清费用里最晚的那个；一条都没结清为 null |
| PromiseOverdueDays | int | **承诺超期天数**：已结清的按实际结算日期算、未结清的按当天算；没超期或没承诺为 0 |
| OverdueAttachments | object[]? | **证明文件**，承诺付款日期最早的那张提单上的超期证明附件。结构见 9.6 |
| OverdueRemark | string | **超期备注**，同上那张提单上的 |

> **销售与操作**在 `SeaExport.TransportOrder.OrderUsers`（件杂货为 `BreakBulk.TransportOrder.OrderUsers`）里，按 `UserAttribute` 区分。

**三个取值口径：**

- **应结日期**取该票下「主单委托单位 = x」与「分单结算对象 = x」这些应结日期的**最小值**。一条都取不到的票**整票排除**——费用结算给了 x，但这票的委托单位与各分单结算对象都不是 x（指定第三方付款那种），不算这个客户的超期。
- **承诺付款日期**取该票下属于 x 的提单（主单提单／结算对象为 x 的分单提单）的**最小值**；超期备注与证明文件取的就是承诺付款日期最早的那张提单上的。没填承诺付款日期的票不算承诺超期。
- **海出分单应结日期是后加的列，存量海出分单是默认值**，取最小值时已把它们排除，否则会把所有票算成超期。件杂货分单是新表，应结日期建单时就算好，没有这种存量，不做排除。

#### 压单 / 后续新单怎么划线

三者都建立在「**同委托单位下所有未签出的提单**」这个范围上（未签出 = 状态不是已签出；委托单位取业务表的，海运出口与件杂货的提单混在一起比）：

- **单张提单的 `IsHeldUp`**：这个范围里存在**另一张**提单，它的开船日期 **≤** 本提单的开船日期。本提单或对方没填开船日期就比不出来，按不压单处理。
- **`HeldUpBillOfLadings`**：以**本批提单里最晚的那个开船日期**为基准线，取开船日期 **≤ 基准线**的，**不含本批自己**。
- **`FollowingBillOfLadings`**：同一范围、同一基准线，取开船日期 **> 基准线**的，同样不含本批自己。
- 本批提单都没填开船日期时基准线算不出来，后两个列表都返回空数组。

> 权限缺失只会让第四、五部分为 null，不会让整个详情接口报错。

### 报错

- `审核任务id不能为空` / `审核任务不存在`

出参按返回结构的层级分节。行级字段一张表，嵌套对象各自一张表。

# 10. 工作流配置说明（给配置人员）

提交签出审核前，必须在工作流配置里建一条 **任务类型 = 提单签出（`TaskType = 11`）** 且**启用**的工作流。

**可用的进入条件**（`TaskTypeCondition`）：

| 值 | 条件 | 可用比较符 | 被比较值 |
| :-- | :-- | :-- | :-- |
| 11001 | 提单-委托单位 | 属于 / 不属于 | 委托单位 id（Guid） |
| 11002 | 提单-提交人组织 | 属于 / 不属于 | 组织 id（long）。配大组织时覆盖其下属部门：配青岛分公司，青岛业务部的人提交也匹配 |
| 11003 | 提单-是否超期 | 是 / 不是 | 不需要填（本批里只要有一张超期就算满足） |

**节点审核人**支持按用户、按角色配置，**不支持按用户属性**（配了会报错）。全部节点都配成「直接通过」时，提交后整批直接变 `可签出`，不生成工作流实例，`SubmitAsync` 返回 `null`。
