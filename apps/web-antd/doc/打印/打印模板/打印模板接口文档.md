# 打印格式接口文档

**控制器**：`PrintFormatAdmin`

**服务类**：`PrintFormatAdminAppService`

> **重要说明**：本文档对应 `PrintFormat` / `PrintFormatAdminAppService`。旧版 `PrintTemplate` / `PrintTemplateAdminAppService` 已弃用，请勿再对接旧接口。

**所有接口均需要登录认证。** 部分接口权限注解当前被注释，实际以运行时配置为准。

---

## 关联数据结构

- 主表：`PrintFormat`（`App_PrintFormats`），继承 `FullAuditedEntity<Guid>`，多租户。
- 关联表：`PrintJson`（`App_PrintJsons`），打印数据源，通过 `PrintJsonId` 外键关联。
- 弱外键列（均可空，**不建库级外键约束、无导航属性**，仅在新增/编辑时做存在性校验）：`CodeIssueTypeId`（签单方式）、`CarrierId`（船公司）、`OrgId`（组织）；另有 `FileName`（打印文件名，最长 256）。
- 枚举列（可空）：`BizType`（业务类型），为空表示该格式不限业务类型（各业务通用）；**枚举不是弱外键，不做存在性校验**。
- 枚举：`PrintJsonType`（数据源类型，与业务模块对应）
- 枚举：`BizType`（业务类型）
- 枚举：`PrintExportFormat`（打印导出格式）

**`PrintJsonType` 数据源类型枚举：**

| 值 | 名称 | 说明 |
| --- | --- | --- |
| `0` | 海运出口详情 | `SeaExportDetail`，数据取自 `SeaExportAdmin/DetailAsync` |
| `500` | 海运出口分单详情 | `SeaExportSeparateDetail`，数据取自 `SeaExportSeparateAdmin/DetailAsync` |
| `1000` | 应收费用列表 | `RecOrderFeeList`，数据取自 `OrderFeeAdmin/GetPagedListAsync`（更改单打印取 `ChangeOrderAdmin/DetailAsync`） |
| `1500` | 应付费用列表 | `PayOrderFeeList`，取数同上 |
| `4000` | 海运进口详情 | `SeaImportDetail`，数据取自 `SeaImportAdmin/DetailAsync` |
| `5000` | 空运出口详情 | `AirExportDetail`，数据取自 `AirExportAdmin/DetailAsync` |
| `6000` | 空运进口详情 | `AirImportDetail`，暂未支持打印 |
| `7000` | 件杂货详情 | `BreakBulkDetail`，数据取自 `BreakBulkAdmin/DetailAsync` |
| `7500` | 件杂货分单详情 | `BreakBulkSeparateDetail`，数据取自 `BreakBulkSeparateAdmin/DetailAsync` |
| `11000` | 客户对账详情 | `StatementDetail`，数据取自 `StatementAdmin/DetailAsync` |
| `12000` | 付费申请详情 | `PaymentApplicationDetail`，数据取自 `PaymentApplicationAdmin/DetailAsync` |

**`BizType` 业务类型枚举：**

| 值     | 名称         | 说明                     |
| ------ | ------------ | ------------------------ |
| `0`    | 海运出口     | 该打印格式仅用于海运出口 |
| `1`    | 海运进口     | 该打印格式仅用于海运进口 |
| `2`    | 空运出口     | 该打印格式仅用于空运出口 |
| `3`    | 件杂货       | 该打印格式仅用于件杂货   |
| `null` | 不限业务类型 | 各业务通用的打印格式     |

> `0` 是有效值（海运出口）而非「未选择」，判空必须比 `null`。`BizType` 与 `PrintJsonType` 是两个独立维度：前者是业务标签，后者决定绑定哪套 JSON 数据结构。

**`PrintExportFormat` 打印导出格式枚举：**

| 值  | 名称  | 说明            | 文件扩展名 |
| --- | ----- | --------------- | ---------- |
| `0` | Pdf   | PDF 文档        | `.pdf`     |
| `1` | Excel | Excel 2007 文档 | `.xlsx`    |
| `2` | Word  | Word 2007 文档  | `.docx`    |

**打印文件名占位符（`PrintJsonFileNameType`）：**

打印格式的 `fileName` 里可以写下表的占位符，`GetPrintAsync` 出单时按数据源类型替换成业务值（同一占位符出现多次全部替换，取不到值替换为空串），去掉文件名非法字符后生成「替换后的文件名-{Ticks}.扩展名」；打印格式没配 `fileName` 时为「{Ticks}.扩展名」。

| 值 | 占位符 | 支持的数据源类型 |
| --- | --- | --- |
| `0` | `[委托编号]` | 海运出口详情、海运进口详情、空运出口详情、件杂货详情、空运进口详情（暂未支持打印） |
| `1` | `[主提单号]` | 上一行全部类型，以及海运出口分单详情、件杂货分单详情（取所属主单的业务表主提单号）、应收/应付费用列表 |
| `2` | `[分提单号]` | 海运出口分单详情、件杂货分单详情 |
| `3` | `[结算对象全称]` | 应收/应付费用列表、付费申请详情 |
| `4` | `[对账单号]` | 客户对账详情 |
| `5` | `[结算客户全称]` | 客户对账详情 |
| `6` | `[申请单号]` | 付费申请详情 |

## 一、新增打印格式

### `POST /api/services/app/PrintFormatAdmin/AddAsync`

**权限**：`Admin.PrintFormat.Add`（当前代码中权限注解被注释）

**入参** `PrintFormatAddDto`（Body JSON）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | `string` | 否 | 打印格式名，最长 128 字符 |
| `printFormatStr` | `string` | 是 | 打印格式字符串（FastReport `.frx` 内容） |
| `printJsonId` | `Guid` | 是 | 数据源 id，不能为空 Guid |
| `sortId` | `int` | 否 | 排序 id |
| `remark` | `string` | 否 | 备注，最长 1024 字符 |
| `codeIssueTypeId` | `long?` | 否 | 签单方式 id（弱外键，无库级外键约束，有值时校验存在性） |
| `carrierId` | `long?` | 否 | 船公司 id（弱外键，有值时校验存在性） |
| `orgId` | `long?` | 否 | 组织 id（弱外键，有值时校验存在性） |
| `bizType` | `int?` | 否 | 业务类型（`BizType` 枚举），不传/`null` 表示不限业务类型；**不做存在性校验** |
| `fileName` | `string` | 否 | 打印文件名，最长 256 字符 |

**出参**：`Guid`（新建的打印格式 id）

**业务规则（校验）**：

- `printFormatStr` 不能为空，否则提示「打印格式字符串不能为空」。
- `printJsonId` 不能为 `Guid.Empty`，否则提示「数据源id不能为空」。
- 关联的 `PrintJson` 必须存在，否则提示「关联的打印数据源不存在」。
- `name` 长度不能超过 128 字符。
- `remark` 长度不能超过 1024 字符。
- `codeIssueTypeId` 有值时对应签单方式必须存在，否则提示「签单方式不存在」。
- `carrierId` 有值时对应船公司必须存在，否则提示「船公司不存在」。
- `orgId` 有值时对应组织必须存在，否则提示「组织不存在」。
- `fileName` 长度不能超过 256 字符。

**外键简易对象结构**：

| DTO | 字段 |
| --- | --- |
| `CodeIssueTypeSimpleDto` | `id`(`long`)、`billType`(`string` 签单方式)、`enName`(`string` 英文名) |

| `OrganizationUnitSimpleDto` | `id`(`long`)、`name`(`string` 组织名) |

> 注：详情接口 `DetailAsync` 仅返回 `codeIssueTypeId`/`carrierId`/`orgId`，不返回上述简易对象；简易对象仅在两个列表接口返回。

`PagedList` 结构：

| 字段             | 类型               | 说明             |
| ---------------- | ------------------ | ---------------- |
| `items`          | `PrintFormatDto[]` | 当前页数据集合   |
| `totalCount`     | `int`              | 总记录数         |
| `skipCount`      | `int`              | 跳过的数量       |
| `maxResultCount` | `int`              | 返回的最大数据量 |
| `currentPage`    | `int`              | 当前页           |
| `totalPages`     | `int`              | 总页数           |

**业务规则**：

- `keyword` 有值时，按 `name` 或 `remark` 模糊匹配。
- `printJsonType` 有值时，按关联数据源的类型精确匹配。
- `printJsonId` 有值时，按数据源 id 精确匹配。
- `codeIssueTypeId` / `carrierId` / `orgId` 有值时，分别按签单方式/船公司/组织 id 精确匹配。
- **`bizType` 有值时，返回该列等于传入值或该列为 `null` 的记录**（口径与上面三项不同，见下方说明）。
- `fileName` 有值时，按打印文件名模糊匹配。
- 默认按 `printJsonPrintJsonType` 升序排列。

> **管理端的 `bizType` 也走「相等或为空」，与 `codeIssueTypeId` 的精确匹配不同，这是有意为之。** 打印选格式时通用模板（`bizType = null`）必须一起出现，否则只配了通用模板的业务一个格式都选不到。若管理界面需要「只看某业务专用的格式」，后端目前不支持。

## 六、执行打印（生成 PDF / Word / Excel）

### `POST /api/services/app/PrintFormatAdmin/PrintAsync`

> 此方法在 `PrintFormatAdminAppService` 中实现，未声明在 `IPrintFormatAdminAppService` 接口上，但会通过 ABP 动态 API 暴露。

**入参** `GetPrintFileDto`（Body JSON）：

| 字段            | 类型                | 必填 | 说明                      |
| --------------- | ------------------- | ---- | ------------------------- |
| `printFormatId` | `Guid`              | 是   | 打印格式 id               |
| `json`          | `string`            | 是   | 打印业务数据 JSON 文本    |
| `format`        | `PrintExportFormat` | 否   | 导出格式，默认 `0`（PDF） |

**出参**：`string`（生成的文件名，如 `{Ticks}.pdf` / `{Ticks}.xlsx` / `{Ticks}.docx`，文件保存在 `wwwroot/PrintTempFile/`）

**业务规则（校验）**：

- `json` 不能为空，否则提示「打印数据不能为空」。
- 打印格式必须存在且 `printFormatStr` 不为空。
- 加载 `printFormatStr` 作为 FastReport 模板，注册用户打印数据源及业务 JSON 数据源，按 `format` 导出对应格式文件。
- `format` 未传时默认为 `0`（PDF）。

**导出格式与文件扩展名对应关系**：

| `format` 值 | 枚举名 | 扩展名  |
| ----------- | ------ | ------- |
| `0`         | Pdf    | `.pdf`  |
| `1`         | Excel  | `.xlsx` |
| `2`         | Word   | `.docx` |

**请求示例**：

```json
{
  "printFormatId": "00000000-0000-0000-0000-000000000001",
  "json": "{ \"业务ID\": \"123\" }",
  "format": 1
}
```

## 七、按数据源类型自动取数打印（前端不传 json）

### `POST /api/services/app/PrintFormatAdmin/GetPrintAsync`

> 此方法在 `PrintFormatAdminAppService` 中实现，未声明在 `IPrintFormatAdminAppService` 接口上，但会通过 ABP 动态 API 暴露。与 `PrintAsync` 的区别：前端**不需要**拼接业务 json，而是按 `printJsonType` 传入对应业务接口的真实入参，后端自动校验权限并取数。

**入参** `GetPrintDto`（Body JSON）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `printFormatId` | `Guid` | 是 | 打印格式 id |
| `printJsonType` | `PrintJsonType` | 是 | 数据源类型，决定取数接口、权限与所用入参字段 |
| `detailInput` | `GuidIdDto` | 视类型 | 详情类入参，`SeaExportDetail` / `SeaExportSeparateDetail` / `SeaImportDetail` / `AirExportDetail` / `BreakBulkDetail` / `BreakBulkSeparateDetail` / `StatementDetail` / `PaymentApplicationDetail` 时必填，等价于对应 `DetailAsync` 的入参；**更改单费用打印时用它传更改单id** |
| `orderFeeListInput` | `OrderFeeQueryDto` | 视类型 | 费用列表类入参，`RecOrderFeeList` / `PayOrderFeeList` 非更改单打印时必填，等价于 `OrderFeeAdmin/GetPagedListAsync` 的入参（`paySide` 由类型决定，服务端覆盖） |
| `isChangeOrderPrint` | `bool?` | 否 | 是否更改单打印，仅费用列表类有效；为 `true` 时改用 `ChangeOrderAdmin/DetailAsync` 取更改单费用（用 `detailInput` 传更改单id） |
| `format` | `PrintExportFormat` | 否 | 导出格式，默认 `0`（PDF） |

**`printJsonType` 与取数逻辑对应关系**：

| `printJsonType` | 枚举值 | 使用入参 | 所需权限 | 取数接口 |
| --- | --- | --- | --- | --- |
| `SeaExportDetail` | `0` | `detailInput` | `Admin.SeaExport.Get` | `SeaExportAdmin/DetailAsync` |
| `RecOrderFeeList`（普通） | `1000` | `orderFeeListInput`（`paySide=收`） | `Admin.OrderFee.Get` | `OrderFeeAdmin/GetPagedListAsync` |
| `PayOrderFeeList`（普通） | `1500` | `orderFeeListInput`（`paySide=付`） | `Admin.OrderFee.Get` | `OrderFeeAdmin/GetPagedListAsync` |
| `RecOrderFeeList`/`PayOrderFeeList`（`isChangeOrderPrint=true`） | `1000`/`1500` | `detailInput`（更改单id） | `Admin.ChangeOrder.Get` + `Admin.OrderFee.Get` | `ChangeOrderAdmin/DetailAsync`（取 `orderFees` 按收/付过滤） |
| `SeaExportSeparateDetail` | `500` | `detailInput` | `Admin.SeaExport.Get` | `SeaExportSeparateAdmin/DetailAsync` |
| `SeaImportDetail` | `4000` | `detailInput` | `Admin.SeaImport.Get` | `SeaImportAdmin/DetailAsync` |
| `AirExportDetail` | `5000` | `detailInput` | `Admin.AirExport.Get` | `AirExportAdmin/DetailAsync` |
| `BreakBulkDetail` | `7000` | `detailInput` | `Admin.BreakBulk.Get` | `BreakBulkAdmin/DetailAsync` |
| `BreakBulkSeparateDetail` | `7500` | `detailInput` | `Admin.BreakBulk.Get`（件杂货分单没有独立权限点） | `BreakBulkSeparateAdmin/DetailAsync` |
| `StatementDetail` | `11000` | `detailInput` | `Admin.Statement.Get` | `StatementAdmin/DetailAsync` |
| `PaymentApplicationDetail` | `12000` | `detailInput` | `Admin.PaymentApplication.Get` | `PaymentApplicationAdmin/DetailAsync` |
| `AirImportDetail` | `6000` | — | — | 暂未支持，返回「该数据源类型暂未支持打印」 |

**出参**：`string`（生成的文件名，文件保存在 `wwwroot/PrintTempFile/`。打印格式没配 `fileName` 时如 `{Ticks}.pdf` / `{Ticks}.xlsx` / `{Ticks}.docx`；配了则为 `{替换占位符后的文件名}-{Ticks}.pdf` 等，见「关联数据结构」的打印文件名占位符）

**业务规则（校验）**：

- 与所选类型对应的入参不能为空（详情类及更改单打印还要求 `id` 非空 Guid），否则提示「请传入 XX 入参」。
- 打印格式必须存在且 `printFormatStr` 不为空。
- 按 `printJsonType`（及是否更改单打印）先校验对应业务查询权限，未授权抛「没有 XX 查询权限」。
- 费用列表的 `paySide` 由类型决定并被服务端覆盖，前端填写无效；普通费用打印分页字段 `pageIndex`/`pageSize` 默认 1/10，若需打印全部费用请显式传较大的 `pageSize`；更改单打印返回该更改单全部费用（无分页）。
- 费用打印顺序由服务端强制为 `sortId` 升序、相同再按创建时间升序。普通打印会覆盖 `orderFeeListInput.sorting` 为 `SortId ASC, CreationTime ASC`；更改单打印在收付过滤后再按该顺序排。前端给费用打印传 `sorting` 无效。业务费用分页列表本身仍走入参 `sorting`，不要混用。
- 校验通过后调用对应业务接口取数并序列化为 json，再复用打印流程按 `format` 导出。
- 传入暂未支持的类型返回「该数据源类型暂未支持打印」；未知类型返回「不支持的数据源类型」。

#### 每种打印所需输入（详解）

除公共字段 `printFormatId`（`Guid`，必填）、`printJsonType`（必填）、`format`（`PrintExportFormat`，默认 `0`=PDF）外，`detailInput` / `orderFeeListInput` / `isChangeOrderPrint` 按类型二选一或选填，具体如下。

**① 海运出口详情 `SeaExportDetail`（=0）**

- 使用字段：`detailInput`（`GuidIdDto`）
- 权限：`Admin.SeaExport.Get`；取数：`SeaExportAdmin/DetailAsync`

| `detailInput` 字段 | 类型         | 必填 | 说明                   |
| ------------------ | ------------ | ---- | ---------------------- |
| `id`               | `Guid`       | 是   | 海运出口 id            |
| `ids`              | `List<Guid>` | 否   | 详情接口不使用，可不传 |

**② 客户对账详情 `StatementDetail`（=11000）**

- 使用字段：`detailInput`（`GuidIdDto`）
- 权限：`Admin.Statement.Get`；取数：`StatementAdmin/DetailAsync`

| `detailInput` 字段 | 类型         | 必填 | 说明                   |
| ------------------ | ------------ | ---- | ---------------------- |
| `id`               | `Guid`       | 是   | 对账单 id              |
| `ids`              | `List<Guid>` | 否   | 详情接口不使用，可不传 |

**③ 应收 / 应付费用列表（普通）`RecOrderFeeList`（=1000）/ `PayOrderFeeList`（=1500）**

- 使用字段：`orderFeeListInput`（`OrderFeeQueryDto`）；`isChangeOrderPrint` 不传或 `false`
- 权限：`Admin.OrderFee.Get`；取数：`OrderFeeAdmin/GetPagedListAsync`

| `orderFeeListInput` 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `transportOrderId` | `Guid?` | 建议必传 | 业务(TransportOrder) id；不传会查到当前用户有权限的全部费用 |
| `paySide` | `PaySide?` | 否 | **前端不用填**，服务端按类型强制置为 收/付 |
| `feeStatus` | `FeeStatus?` | 否 | 费用状态筛选 |
| `settlementStatus` | `SettlementStatus?` | 否 | 结算状态筛选 |
| `invoiceStatus` | `InvoiceStatus?` | 否 | 开票状态筛选 |
| `feeCodeId` | `long?` | 否 | 费用代码 id 筛选 |
| `industryCategory` | `IndustryCategory?` | 否 | 行业类别筛选 |
| `settlementId` | `Guid?` | 否 | 结算对象 id 筛选 |
| `currencyId` | `long?` | 否 | 币别 id 筛选 |
| `isConfidential` | `bool?` | 否 | 是否机密筛选 |
| `keyword` | `string` | 否 | 备注模糊匹配 |
| `pageIndex` | `int` | 否 | 页码，默认 `1` |
| `pageSize` | `int` | 否 | 每页条数，默认 `10`；**打印全部费用务必传大值（如 9999）** |
| `sorting` | `string` | 否 | 排序字段。**费用打印时服务端会覆盖为 `SortId ASC, CreationTime ASC`，前端传了也无效** |

**④ 应收 / 应付费用列表（更改单）`RecOrderFeeList` / `PayOrderFeeList` + `isChangeOrderPrint=true`**

- 使用字段：`isChangeOrderPrint = true` + `detailInput`（`GuidIdDto`）——注意此时用 `detailInput`，不是 `orderFeeListInput`
- 权限：`Admin.ChangeOrder.Get` + `Admin.OrderFee.Get`（两者都需要）；取数：`ChangeOrderAdmin/DetailAsync` → 取 `orderFees` 并按类型收/付过滤

| `detailInput` 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `Guid` | 是 | 更改单 id |
| `ids` | `List<Guid>` | 否 | 指定只取这些费用 id；不传则取该更改单全部费用 |

**⑤ 付费申请详情 `PaymentApplicationDetail`（=12000）**

- 使用字段：`detailInput`（`GuidIdDto`）
- 权限：`Admin.PaymentApplication.Get`；取数：`PaymentApplicationAdmin/DetailAsync`
- FastReport 数据源名：`付费申请`（字段中文别名取 `PaymentApplicationDto` 上的 `[Description]`）

| `detailInput` 字段 | 类型         | 必填 | 说明                   |
| ------------------ | ------------ | ---- | ---------------------- |
| `id`               | `Guid`       | 是   | 付费申请 id            |
| `ids`              | `List<Guid>` | 否   | 详情接口不使用，可不传 |

**⑥ 件杂货详情 `BreakBulkDetail`（=7000）/ 件杂货分单详情 `BreakBulkSeparateDetail`（=7500）**

- 使用字段：`detailInput`（`GuidIdDto`）
- 权限：两种都校验 `Admin.BreakBulk.Get`（件杂货分单没有独立权限点，查看权限挂在件杂货上），未授权报「没有件杂货查询权限」
- 取数：`BreakBulkAdmin/DetailAsync` / `BreakBulkSeparateAdmin/DetailAsync`，服务端按打印口径（`isPrint=true`）取，带所属公司打印信息；分单没有所属公司，取所属件杂货的
- 未传 `detailInput` 或 `id` 为空 Guid：分别报「请传入件杂货详情入参」「请传入件杂货分单详情入参」
- FastReport 数据源名：`件杂货`（`BreakBulkDto`）/ `件杂货分单`（`BreakBulkSeparateDto`），列的中文别名取 DTO 上的 `[Description]`

| `detailInput` 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `Guid` | 是 | `BreakBulkDetail` 传件杂货 id（与业务 id 相同）；`BreakBulkSeparateDetail` 传件杂货分单 id |
| `ids` | `List<Guid>` | 否 | 详情接口不使用，可不传 |

**⑦ 其余详情类**：`SeaExportSeparateDetail`（500）/ `SeaImportDetail`（4000）/ `AirExportDetail`（5000）同样只用 `detailInput.id`，权限与取数接口见上表；`AirImportDetail`（6000）暂未支持，传入返回「该数据源类型暂未支持打印」。

**快速对照**

| 打印类型 | 关键输入字段 | id 含义 |

## 八、打印格式列表（登录即可访问，签单方式/船公司/组织"相等或为空"）

### `GET /api/services/app/PrintFormat/GetPagedListAsync`

> 由**新增服务** `PrintFormatAppService`（非管理端 `PrintFormatAdminAppService`）提供，控制器为 `PrintFormat`。仅需登录即可访问（`[AbpAuthorize]`），无独立功能权限。入参与出参结构与管理端列表（第五节）完全一致，**唯一区别**在于 `codeIssueTypeId` / `carrierId` / `orgId` 的匹配规则。

**入参** `PrintFormatQueryDto`（Query 参数，同第五节）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `keyword` | `string` | 否 | 关键字，对名称、备注模糊匹配 |
| `printJsonId` | `Guid?` | 否 | 按数据源 id 精确筛选 |
| `printJsonType` | `PrintJsonType?` | 否 | 按数据源类型精确筛选 |
| `codeIssueTypeId` | `long?` | 否 | 有值时返回 **等于该值或该列为空** 的记录 |
| `carrierId` | `long?` | 否 | 有值时返回 **等于该值或该列为空** 的记录 |
| `orgId` | `long?` | 否 | 有值时返回 **等于该值或该列为空** 的记录 |
| `bizType` | `int?` | 否 | 有值时返回 **等于该值或该列为空** 的记录 |
| `fileName` | `string` | 否 | 按打印文件名模糊匹配 |
| `pageIndex` | `int` | 是 | 当前页码（从 1 开始，默认 1） |
| `pageSize` | `int` | 是 | 每页条数（默认 10） |
| `sorting` | `string` | 否 | 排序字段（列表实际按 `printJsonPrintJsonType` 排序） |

**出参** `PagedList<PrintFormatDto>`：字段与第五节列表输出完全相同（不返回 `printFormatStr`，含 `bizType`），同样返回 `codeIssueType` / `carrier` / `org` 三个外键简易对象。

**业务规则**：

- `keyword`、`printJsonId`、`printJsonType`、`fileName` 的匹配规则同第五节。
- **`codeIssueTypeId` / `carrierId` / `orgId` / `bizType` 有值时**：返回该列等于传入值**或**该列为 `null` 的记录（即通用/未限定该维度的打印格式也会返回）。
- 默认按 `printJsonPrintJsonType` 升序排列。

> `bizType` 在本接口与管理端列表口径一致（都是「相等或为空」），是四个筛选维度里唯一两端一致的。

## 九、同步打印数据源 Json 到多个数据库

### `POST /api/services/app/PrintFormat/SyncPrintJsonToMultiDbAsync`

> 由 `PrintFormatAppService` 提供。权限：`Admin.PrintJson.Edit`。  
> 先遍历全部 `PrintJsonType`，在 `TryBuildPrintJsonAsync` 各分支内自行 `new` 业务入参并调用对应业务接口生成打印 Json；再遍历 `PrintJsonDbManager.ConnectionStrings`，用 ADO.NET 写入各库 `App_PrintJsons`（已存在更新，不存在新建）。  
> **无 Body 入参**：具体业务 id / 查询条件请在服务代码 `TryBuildPrintJsonAsync` 各 case 中自行填写后再调用。

**入参**：无

**出参** `List<SyncPrintJsonToMultiDbResultDto>`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `connectionSummary` | `string` | 连接摘要（server/database，隐藏密码）；跳过类型时为 null |
| `printJsonType` | `PrintJsonType` | 数据源类型 |
| `affectedRows` | `int` | 受影响行数 |
| `message` | `string` | 新建成功 / 更新成功 / 写入失败 / 更新失败 / 跳过原因 |

**业务规则**：

- 多库连接串维护在 `AdoNet/PrintJsonDbManager.ConnectionStrings`（与 `SqlServerManager` 同目录）。
- 目标库已有对应 `PrintJsonType`（`IsDeleted=0`）时仅改 `Json`、`LastModificationTime`；**没有则新建**整行（`Id` 新 Guid，`SortId` 默认取类型枚举值）。
- 空运进口暂未支持，结果中标记跳过。
- 件杂货详情、件杂货分单详情两个分支的示例 id 在代码里留空，未填写时跳过，结果里 `message` 分别为 `跳过：未填写件杂货示例业务 id`、`跳过：未填写件杂货分单示例 id`（`connectionSummary` 为 null、`affectedRows` 为 0）；需要生成这两个类型的样本 Json 时，在 `TryBuildPrintJsonAsync` 对应分支填真实 id，填了不存在的 id 会让详情接口抛错、整次同步中断。
- 若所有类型都未生成到 Json，抛出提示检查 `TryBuildPrintJsonAsync` 入参。
