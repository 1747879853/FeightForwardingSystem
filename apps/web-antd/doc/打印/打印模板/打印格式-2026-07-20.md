# 背景意图

`GetPrintAsync`（前端不传 json 的打印方法）原实现直接读取入参中的 `json` 打印，与 `PrintAsync` 无本质区别，且 `GetPrintDto` 并不包含 `json` 字段。本次改造让 `GetPrintAsync` 根据 `PrintJsonType` 自动判断业务类型，**先做对应业务的查询权限校验**，再调用对应业务接口取数生成 json，最后复用内部 `PrintAsync` 流程导出文件。前端只需按类型传入对应业务接口的真实入参即可完成打印，无需自行拼接业务数据。

# 核心逻辑变更

1. **入参 `GetPrintDto` 改为携带各业务接口的真实入参（按类型复用两类入参）**
   - 移除了对不存在的 `input.Json` 的依赖，也不再使用通用 `businessId`。
   - 四种类型的目标方法只有两种入参签名，故合并为两个字段：
     - `DetailInput`（类型 `GuidIdDto`）：详情类共用，`SeaExportDetail` / `StatementDetail` 时必填，对应各自 `DetailAsync` 的入参；**更改单费用打印时也用它传更改单id**。
     - `OrderFeeListInput`（类型 `OrderFeeQueryDto`）：费用列表类共用，`RecOrderFeeList` / `PayOrderFeeList` 非更改单打印时必填，对应 `OrderFeeAdmin/GetPagedListAsync` 的入参。
   - 收/付由 `PrintJsonType` 决定，服务端强制覆盖 `OrderFeeListInput.PaySide`，前端无需指定。
   - 新增 `IsChangeOrderPrint`（`bool?`）：仅费用列表类有效，为 `true` 时改走更改单详情接口取费用。

2. **`GetPrintAsync` 改造为「校验权限 → 取数 → 打印」**
   - 校验输入、加载打印格式后，调用私有方法 `BuildPrintJsonAsync(input)` 生成 json。
   - 生成后调用内部 `PrintAsync(json, printFormat, format)` 导出。

3. **新增私有方法 `BuildPrintJsonAsync`（按 `PrintJsonType` 分支）**

   | `PrintJsonType` | 入参字段 | 权限校验 | 调用接口 | 输出序列化 |
   | --- | --- | --- | --- | --- |
   | `SeaExportDetail` | `DetailInput`（`GuidIdDto`） | `Admin.SeaExport.Get` | `ISeaExportAdminAppService.DetailAsync` | 单对象 |
   | `RecOrderFeeList`（普通） | `OrderFeeListInput`（`OrderFeeQueryDto`，服务端置 `PaySide=收`） | `Admin.OrderFee.Get` | `IOrderFeeAdminAppService.GetPagedListAsync` | `Items` 列表 |
   | `PayOrderFeeList`（普通） | `OrderFeeListInput`（`OrderFeeQueryDto`，服务端置 `PaySide=付`） | `Admin.OrderFee.Get` | `IOrderFeeAdminAppService.GetPagedListAsync` | `Items` 列表 |
   | `RecOrderFeeList`/`PayOrderFeeList`（`IsChangeOrderPrint=true`） | `DetailInput`（`GuidIdDto`，更改单id） | `Admin.ChangeOrder.Get` + `Admin.OrderFee.Get` | `IChangeOrderAdminAppService.DetailAsync` → `OrderFees` 按 `PaySide` 过滤 | 列表 |
   | `StatementDetail` | `DetailInput`（`GuidIdDto`） | `Admin.Statement.Get` | `IStatementAdminAppService.DetailAsync` | 单对象 |
   | `SeaImportDetail` / `AirExportDetail` / `AirImportDetail` | — | — | 暂未支持 | 抛「该数据源类型暂未支持打印」 |
   | 其他 | — | — | — | 抛「不支持的数据源类型」 |
   - 每个分支先校验对应入参非空（详情类还校验 `Id` 非空 Guid），未传抛「请传入 XX 入参」。
   - 权限校验使用 `IsGrantedAsync(权限常量)`，未授权时抛 `UserFriendlyException`（如「没有海运出口查询权限」）。
   - 费用列表统一返回 `List<OrderFeeDto>`（普通取 `PagedList.Items`；更改单取 `ChangeOrderDto.OrderFees` 按 `PaySide` 过滤），与 `PrintDataSourceHelper` 反序列化对齐。

4. **新增私有方法 `GetOrderFeesForPrintAsync(input, paySide, feeSideName)`**
   - 统一费用取数：`IsChangeOrderPrint==true` 走更改单详情（用 `DetailInput` 传更改单id，取 `OrderFees` 按 `paySide` 过滤）；否则走 `OrderFeeAdmin/GetPagedListAsync`。

5. **依赖注入变更（`PrintFormatAdminAppService` 构造函数）**
   - 新增注入：`ISeaExportAdminAppService`、`IOrderFeeAdminAppService`、`IStatementAdminAppService`、`IChangeOrderAdminAppService`。

6. **涉及文件**

   | 文件 | 变更 |
   | --- | --- |
   | `PrintFormatDto.cs` | `GetPrintDto` 新增 `DetailInput`（`GuidIdDto`）、`OrderFeeListInput`（`OrderFeeQueryDto`）、`IsChangeOrderPrint`（`bool?`）字段 |
   | `PrintFormatAdminAppService.cs` | 构造函数注入四个业务 AppService；重写 `GetPrintAsync`；新增 `BuildPrintJsonAsync`、`GetOrderFeesForPrintAsync` |

# 避坑指南

- **只需填与类型对应的那一个入参**：详情类填 `DetailInput`，费用列表类填 `OrderFeeListInput`；更改单费用打印改填 `DetailInput`（更改单id）。
- **更改单费用打印**：`IsChangeOrderPrint=true` 且类型为应收/应付费用时，服务端调用更改单详情接口并按收/付过滤 `OrderFees`，需同时具备 `Admin.ChangeOrder.Get` 与 `Admin.OrderFee.Get` 权限。
- **PaySide 由类型决定**：`OrderFeeListInput.PaySide` 会被服务端按 `RecOrderFeeList`/`PayOrderFeeList` 覆盖为 收/付，前端填了也无效。
- **费用列表分页由调用方控制**：普通费用打印时 `OrderFeeQueryDto` 的 `PageIndex`/`PageSize` 默认 1/10，若要打印全部费用需前端显式传较大的 `PageSize`；更改单打印返回该更改单全部费用，无分页。
- **权限双保险**：`BuildPrintJsonAsync` 内显式 `IsGrantedAsync` 校验，被调用的业务 AppService 方法本身也带 `[AbpAuthorize]`，二者均会拦截未授权请求。
- **海运进口 / 空运进出口暂未支持**：对应业务查询接口与权限尚未落地（`PrintDataSourceHelper` 中亦为 TODO），传入这些类型会直接报「该数据源类型暂未支持打印」。

# 附加变更：PrintFormat 新增四列（签单方式 / 船公司 / 组织 / 打印文件名）

## 背景意图

打印格式需按签单方式、船公司、组织维度归类与检索，并可指定打印文件名。为此给 `PrintFormat` 增加四个可空列，并让新增/编辑/列表/详情四个接口全部支持。

## 核心逻辑变更

1. **实体 `PrintFormat` 新增四列（均可空、弱外键、无导航属性、不建库级外键约束）**
   - `CodeIssueTypeId`（`long?`，签单方式）
   - `CarrierId`（`long?`，船公司）
   - `OrgId`（`long?`，组织）
   - `FileName`（`string`，打印文件名，`[StringLength(256)]`）

2. **DTO 同步新增字段**
   - `PrintFormatAddDto` / `PrintFormatEditDto` / `PrintFormatDto`（列表/详情输出）：四列全加。
   - `PrintFormatQueryDto`（列表输入）：新增 `CodeIssueTypeId?` / `CarrierId?` / `OrgId?`（精确）与 `FileName`（模糊）。

3. **AppService 全接口改造**
   - 构造函数注入 `IRepository<Carrier, long>`、`IRepository<CodeIssueType, long>`；组织沿用基类 `OrganizationUnitRepository`。
   - 新增私有 `ValidateExtraFieldsAsync(codeIssueTypeId, carrierId, orgId, fileName)`：三个 id 有值时用 `AnyAsync` 校验存在性（分别提示「签单方式不存在」「船公司不存在」「组织不存在」），`fileName` 超 256 提示「打印文件名长度不能超过256个字符」。
   - `AddAsync`：校验后 `ObjectMapper.Map` 自动映射四列。
   - `EditAsync`：校验后局部赋值四列（遵循局部更新原则）。
   - `GetPagedListAsync`：新增 `WhereIf` —— `CodeIssueTypeId`/`CarrierId`/`OrgId` 精确匹配、`FileName` 模糊匹配。
   - `DetailAsync`：经 AutoMapper 自动带出四列。

4. **涉及文件**

   | 文件 | 变更 |
   | --- | --- |
   | `PrintFormat.cs` | 新增 `CodeIssueTypeId`/`CarrierId`/`OrgId`/`FileName` 四列 |
   | `PrintFormatDto.cs` | Add/Edit/Query/List(Dto) 同步新增字段 |
   | `PrintFormatAdminAppService.cs` | 注入两仓储；新增 `ValidateExtraFieldsAsync`；Add/Edit/List 接入新字段 |

## 避坑指南

- **弱外键**：这四个关系不在数据库层建外键，也没有导航属性，只在写入时做存在性校验；删除签单方式/船公司/组织不会级联影响打印格式。
- **migration 自行生成**：本次不生成迁移文件。
- **列表筛选语义**：管理端 `codeIssueTypeId`/`carrierId`/`orgId` 为精确匹配，`fileName` 为模糊匹配。

# 附加变更：新增 PrintFormatAppService（登录即可访问的列表）

## 背景意图

除管理端 `PrintFormatAdminAppService` 外，业务端打印取模板时需要一个"登录即可访问"的列表接口；且按签单方式/船公司/组织筛选时，希望把"限定了该维度且匹配"的模板与"未限定该维度（为空）的通用模板"一并返回。

## 核心逻辑变更

1. **新增 `IPrintFormatAppService` / `PrintFormatAppService`（控制器 `PrintFormat`，`[AbpAuthorize]`）**
   - 仅提供 `GetPagedListAsync(PrintFormatQueryDto)`，复用与管理端相同的入参/出参（`PrintFormatQueryDto` / `PagedList<PrintFormatDto>`）。
2. **筛选规则差异（唯一区别）**
   - 管理端：`codeIssueTypeId`/`carrierId`/`orgId` 精确匹配。
   - 新服务：`codeIssueTypeId`/`carrierId`/`orgId` 有值时匹配 **相等或该列为 null** —— `m.X == value || m.X == null`。
   - `keyword`/`printJsonId`/`printJsonType`/`fileName` 及排序、分页与管理端一致。
3. **涉及文件**

   | 文件 | 变更 |
   | --- | --- |
   | `IPrintFormatAppService.cs` | 新增接口，含 `GetPagedListAsync` |
   | `PrintFormatAppService.cs` | 新增实现，注入 `IRepository<PrintFormat,Guid>` 与 `IConfigurationProvider`，列表按"相等或为空"过滤三维度 |

## 避坑指南

- **两个服务并存**：管理端 `PrintFormatAdmin`（精确匹配、含增删改查）；业务端 `PrintFormat`（仅列表、三维度"相等或为空"）。
- **"为空"含义**：`orgId=X` 会同时返回 `OrgId==X` 和 `OrgId==null`（未限定组织的通用模板）。

# 附加变更：两个列表返回外键简易对象

## 背景意图

前端展示打印格式列表时需要直接看到签单方式/船公司/组织的名称，而非仅 id。为此两个列表接口都返回对应外键的简易对象。

## 核心逻辑变更

1. **`PrintFormatDto` 新增三个外键简易对象字段**
   - `CodeIssueType`（`CodeIssueTypeSimpleDto`：`Id`/`BillType`/`EnName`）
   - `Carrier`（`CarrierSimpleDto`：`Id`/`Code`/`CnName`/`EnName`）
   - `Org`（`OrganizationUnitSimpleDto`：`Id`/`Name`，取自 `CsprojBuilder` 命名空间的简易 DTO，`Name`=组织 `DisplayName`）
2. **新增 `CodeIssueTypeSimpleDto`**（`CodeIssueType/Dto/CodeIssueTypeDto.cs`）——原先没有签单方式的简易 DTO。
3. **两个列表都填充**
   - `PrintFormatAdminAppService.GetPagedListAsync` 与 `PrintFormatAppService.GetPagedListAsync` 分别新增私有 `FillForeignKeySimpleDtosAsync(List<PrintFormatDto>)`：收集三类 id → 批量查询 → 投影为简易 DTO → 回填。
   - 业务端 `PrintFormatAppService` 为此注入 `IRepository<Carrier,long>`、`IRepository<CodeIssueType,long>`（组织沿用基类 `OrganizationUnitRepository`）。
4. **详情不返回简易对象**：`DetailAsync` 只返回三个 id（AutoMapper 无源导航，简易对象为 null）。

## 涉及文件

| 文件 | 变更 |
| --- | --- |
| `CodeIssueTypeDto.cs` | 新增 `CodeIssueTypeSimpleDto` |
| `PrintFormatDto.cs` | 新增 `CodeIssueType`/`Carrier`/`Org` 三个简易对象字段 |
| `PrintFormatAdminAppService.cs` | 新增 `FillForeignKeySimpleDtosAsync`，列表回填 |
| `PrintFormatAppService.cs` | 注入两仓储；新增 `FillForeignKeySimpleDtosAsync`，列表回填 |
