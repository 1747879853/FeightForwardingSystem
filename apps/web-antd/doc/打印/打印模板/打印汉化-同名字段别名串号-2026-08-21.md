# 背景意图

客户对账打印中 `StatementDto.Client`（`[Description("客户")]`）被汉化成「委托单位」。

# 根因

`CollectDescriptions` 把「完整路径键」和「属性名扁平键」写进同一个字典，且扁平键**无条件覆盖**：

```csharp
result[key] = desc.Description;          // 路径键 如 OrderFeeGroups.TransportOrder.Client
result[prop.Name] = desc.Description;    // 扁平键 Client —— 后写的直接顶掉先写的
```

对账详情的遍历顺序：

1. `StatementDto.Client` → 写入 `["Client"] = "客户"`（根级路径键与扁平键同名，都是 `Client`）。
2. `StatementDto.OrderFeeGroups`(费用按业务分组列表) → `OrderFeeAndSeaExportDto.TransportOrder`(业务) → `TransportOrderSimpleDto.Client`（`[Description("委托单位")]`）→ 写路径键 `OrderFeeGroups.TransportOrder.Client`，同时把扁平键 `["Client"]` **覆盖成「委托单位」**。

根级 `Client` 列取别名用的正是 `fullPath = "Client"`，于是命中被污染的值。

扁平兜底当初是为了解决另一个问题：嵌套对象会被 `RegisterData` 注册成 `客户对账.OrderFeeGroups` 这样的**独立数据源**，遍历它时 `pathPrefix` 从空串重新开始，子列路径对不上 DTO 上的完整路径。真正的修法是还原路径，而不是按属性名瞎猜。

# 核心逻辑变更

`PrintDataSourceHelper`、WPF `FastReportEditorWindow`、Avalonia `FastReportEditorWindow` 三份同构逻辑同步修改：

1. **只按完整路径存 Description**，删掉扁平键与 `TryResolveAlias` 的按名兜底。
2. 独立数据源的起始路径从数据源名还原：`客户对账.OrderFeeGroups` → `pathPrefix = "OrderFeeGroups."`，子列即可精确命中 `OrderFeeGroups.TransportOrder.Client`。
3. 列别名只取该列自身的 `[Description]`：
   - 设计器（WPF / Avalonia）：命中则 `Enabled = true`；**未命中一律清掉残留中文别名并整枝禁用**（字段列表不显示）。
   - 服务端打印：未命中同样把 Alias 还原成属性名，但**全程 `Enabled = true`**——模板表达式在 `Prepare` 时编译成 C#，被禁用的列不进编译上下文会 CS0103。

# 避坑指南

- 同名属性（`Client` / `Name` / `Remark` 等）在不同层级允许有不同中文名，靠完整路径区分；别再往字典里塞属性名扁平键，也别加「按名兜底」。
- 想让字段在设计器里出现，就给它加 `[Description]`；父级没有 `Description` 时整枝都不收集、不显示。
- `CollectDescriptions` 的 `visited` 只防当前递归栈成环，同一类型可以出现在多条路径下（`DefaultBanks` / `RMBBank` / `USDBank` 都是 `CompanyBankAccountPrintDto`），各自都有独立路径键。
