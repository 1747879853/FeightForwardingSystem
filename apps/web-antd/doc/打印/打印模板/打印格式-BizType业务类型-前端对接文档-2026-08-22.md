# 一、变更概述

`App_PrintFormats` 新增一列 `BizType`（业务类型，可空）。打印格式的**增、删、改、查全部支持该字段**，筛选时按「相等或为空」匹配。

| # | 变更 | 影响 |
| :-- | :-- | :-- |
| 1 | 新增/编辑入参新增 `bizType` | 新增可选字段，不传即为 `null`（不限业务类型） |
| 2 | 详情/列表出参新增 `bizType` | 新增字段 |
| 3 | 两个列表入参新增 `bizType` 筛选，按**相等或为空**匹配 | 新增筛选项 |
| 4 | `EditAsync` 是**全字段覆盖**，漏传 `bizType` 会把它清空 | **需前端配合**，见第五节 |

受影响接口：

| # | 接口 | 方法 | 路径 |
| :-- | :-- | :-- | :-- |
| 1 | 新增 | POST | `/api/services/app/PrintFormatAdmin/AddAsync` |
| 2 | 编辑 | PUT | `/api/services/app/PrintFormatAdmin/EditAsync` |
| 3 | 详情 | GET | `/api/services/app/PrintFormatAdmin/DetailAsync` |
| 4 | 管理端列表 | GET | `/api/services/app/PrintFormatAdmin/GetPagedListAsync` |
| 5 | 业务端列表（登录即可访问） | GET | `/api/services/app/PrintFormat/GetPagedListAsync` |

删除接口 `DeleteAsync` 按 `ids` 批量删，与新列无关，**入参出参均未变化**。

# 二、`BizType` 业务类型枚举

| 值     | 名称         | 说明                       |
| :----- | :----------- | :------------------------- |
| `0`    | 海运出口     | 该打印格式仅用于海运出口   |
| `1`    | 海运进口     | 该打印格式仅用于海运进口   |
| `2`    | 空运出口     | 该打印格式仅用于空运出口   |
| `null` | 不限业务类型 | 三种业务**通用**的打印格式 |

> 注意 `0` 是有效值（海运出口），不是「未选择」。判空必须用 `bizType == null`，不能用 `!bizType` 之类的假值判断，否则海运出口会被当成没选。

`BizType` 与 `PrintJsonType`（数据源类型）是**两个独立维度**，不要混用：`PrintJsonType` 决定这份模板绑定哪套 JSON 数据结构，`BizType` 只是给同一数据源下的多个格式再打一层业务标签。

# 三、新增 — `POST /api/services/app/PrintFormatAdmin/AddAsync`

**权限**：`Admin.PrintFormat.Add`（当前代码中权限注解被注释）

**入参** `PrintFormatAddDto`（Body JSON）新增字段：

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `bizType` | `int?` | 否 | 业务类型，取值见第二节；不传/`null` 表示不限业务类型 |

其余字段（`name`、`printFormatStr`、`printJsonId`、`sortId`、`remark`、`codeIssueTypeId`、`carrierId`、`orgId`、`fileName`）与说明均无变化。

**出参**：`Guid`（新建的打印格式 id）

**校验**：`bizType` 是枚举而非弱外键，**不做存在性校验**，传枚举范围外的值不会报错但没有业务意义。

请求示例：

```json
{
  "name": "海运出口提单-标准版",
  "printFormatStr": "<?xml version=\"1.0\"...",
  "printJsonId": "11111111-1111-1111-1111-111111111111",
  "sortId": 0,
  "remark": "",
  "codeIssueTypeId": null,
  "carrierId": null,
  "orgId": null,
  "bizType": 0,
  "fileName": "[委托编号]-提单"
}
```

# 四、编辑 — `PUT /api/services/app/PrintFormatAdmin/EditAsync`

**权限**：`Admin.PrintFormat.Edit`（当前代码中权限注解被注释）

**入参** `PrintFormatEditDto`（Body JSON）新增字段：

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `bizType` | `int?` | 否 | 业务类型，取值见第二节；不传/`null` 表示不限业务类型 |

**出参**：`bool`

**更新字段**：`name`、`printFormatStr`、`printJsonId`、`sortId`、`remark`、`codeIssueTypeId`、`carrierId`、`orgId`、**`bizType`**、`fileName`。

> [!IMPORTANT] `EditAsync` 是**全字段覆盖**（PUT 语义）：上面列出的字段只要没传，就会被写成 `null`（或默认值）。改模板内容时也必须把 `bizType`、`codeIssueTypeId`、`carrierId`、`orgId`、`fileName` 原样回传，否则会被清空。建议先调 `DetailAsync` 拿全量字段，改动其中几项后整体提交。

# 五、详情 — `GET /api/services/app/PrintFormatAdmin/DetailAsync`

**入参**：`id`（`Guid`，Query），无变化。

**出参** `PrintFormatDetailDto` 新增字段：

| 字段      | 类型   | 说明                              |
| :-------- | :----- | :-------------------------------- |
| `bizType` | `int?` | 业务类型，`null` 表示不限业务类型 |

详情接口只返回 `bizType` 原始枚举值，**不返回**中文名；需要展示中文请前端按第二节的枚举表自行映射。这与 `codeIssueTypeId`/`carrierId`/`orgId` 在详情里也只给 id、不给简易对象的现状一致。

# 六、列表 — 管理端与业务端

## 6.1 `GET /api/services/app/PrintFormatAdmin/GetPagedListAsync`

**入参** `PrintFormatQueryDto`（Query）新增字段：

| 字段      | 类型   | 必填 | 说明                                     |
| :-------- | :----- | :--- | :--------------------------------------- |
| `bizType` | `int?` | 否   | 有值时返回 **等于该值或该列为空** 的记录 |

**出参** `PagedList<PrintFormatDto>`，列表项新增字段：

| 字段      | 类型   | 说明                              |
| :-------- | :----- | :-------------------------------- |
| `bizType` | `int?` | 业务类型，`null` 表示不限业务类型 |

## 6.2 `GET /api/services/app/PrintFormat/GetPagedListAsync`

入参、出参的 `bizType` 与 6.1 完全一致，匹配规则也一致（相等或为空）。

## 6.3 筛选规则（重点，容易踩）

`bizType` 的匹配规则**和同一个 DTO 里的 `codeIssueTypeId` / `carrierId` / `orgId` 不一样**，请分开记：

| 筛选字段 | 管理端 `PrintFormatAdmin` | 业务端 `PrintFormat` |
| :-- | :-- | :-- |
| `codeIssueTypeId` / `carrierId` / `orgId` | **精确相等** | 相等或为空 |
| `bizType` | **相等或为空** | **相等或为空** |
| `printJsonId` / `printJsonType` | 精确相等 | 精确相等 |
| `keyword` / `fileName` | 模糊匹配 | 模糊匹配 |

也就是说传 `bizType=1`（海运进口）时，两端都会返回两类记录：

1. `bizType = 1` 的海运进口专用格式；
2. `bizType = null` 的三种业务通用格式。

管理端也走「相等或为空」是**有意为之**，不是漏改——打印选格式时通用模板必须一起出现，否则只配了通用模板的业务会一个格式都选不到。若管理界面需要「只看某业务专用的格式」，后端目前不支持，需另提需求。

# 七、前端适配清单

- [ ] 新增/编辑表单加「业务类型」下拉，选项为 海运出口(0) / 海运进口(1) / 空运出口(2)，并提供「不限」（提交 `null`）。
- [ ] 判空一律用 `bizType === null || bizType === undefined`，**不要**用假值判断，`0` 是海运出口。
- [ ] 列表/详情展示按第二节枚举表映射中文，后端不返回中文名。
- [ ] 调 `EditAsync` 前先取 `DetailAsync` 的全量字段，`bizType` 与 `codeIssueTypeId`/`carrierId`/`orgId`/`fileName` 一并回传，避免被清空。
- [ ] 列表按 `bizType` 筛选时，向用户说明结果里会包含「不限业务类型」的通用格式。
