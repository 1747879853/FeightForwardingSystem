# 背景意图

同一份打印数据源（`PrintJsonType`）下会挂多个打印格式，但原先只能按签单方式、船公司、组织三个维度区分，**区分不出业务类型**。海运出口和海运进口共用一套费用数据源时，两边的格式混在一个列表里，选格式只能靠名字认。

本次给 `PrintFormat` 加一列 `BizType`，可空，为空表示三种业务通用。

顺带修掉一个**既有 bug**：桌面设计器保存模板时会把 `CodeIssueTypeId` / `CarrierId` / `OrgId` / `FileName` 清空——这个坑在加了 `BizType` 之后会一起把新列也清掉，必须一并处理。

# 核心逻辑变更

## 1. 实体与 DTO

`src/CsprojBuilder.Core/Entites/PrintFormat.cs` 新增 `public BizType? BizType { get; set; }`。可空枚举，EF 按 `int NULL` 建列，无需 Fluent 配置，也不建库级外键（`BizType` 是枚举不是表）。

属性名与类型名同名是 C# 合法写法（Color Color 规则），本仓库 `public SettlementType? SettlementType` 早就这么写。

`App/Print/Dto/PrintFormatDto.cs` 六个 DTO 同步加 `BizType?`：

| DTO                        | 用途                       |
| :------------------------- | :------------------------- |
| `PrintFormatAddDto`        | 新增入参                   |
| `PrintFormatEditDto`       | 编辑入参                   |
| `PrintFormatQueryDto`      | 列表筛选入参               |
| `PrintFormatDto`           | 列表出参                   |
| `PrintFormatFieldsDto`     | 桌面设计器部分字段查询出参 |
| `PrintFormatFieldsEditDto` | 桌面设计器部分字段保存入参 |

`PrintFormatDetailDto` 继承 `PrintFormatDto`，自动带上，不用改。

## 2. 三个 AppService 的增删改查

| 服务 | 改动 |
| :-- | :-- |
| `PrintFormatAdminAppService` | 列表加 `WhereIf` 筛选；`EditAsync` 赋值 |
| `PrintFormatAppService` | 列表加 `WhereIf` 筛选 |
| `PrintFormatForWpfAppService` | 列表与 `GetFieldsListAsync` 加筛选并投影；`EditAsync`、`SaveFieldsAsync` 赋值 |

新增走 `ObjectMapper.Map<PrintFormat>(input)`，`[AutoMap]` 按同名约定自动映射，无需显式赋值。删除按 `ids` 批量删，与新列无关。

## 3. 筛选口径：三处都是「相等或为空」

```csharp
.WhereIf(input.BizType.HasValue, m => m.BizType == input.BizType.Value || m.BizType == null)
```

**管理端也走「相等或为空」，与同一 DTO 里 `CodeIssueTypeId` 的口径故意不同**（那三个在管理端是精确相等、业务端才是相等或为空）。原因是打印选格式时通用模板必须一起出现，否则只配了通用模板的业务一个格式都选不到。

## 4. WPF 设计器可编辑业务类型

`CsprojBuilder.PrintDesign` 列表页的「修改」对话框新增业务类型下拉，列表行信息栏也展示业务类型中文名。

**没有复用 `OptionModel`**：已有的签单方式/船公司/组织下拉都是 `OptionModel` + `SelectedValuePath="Id"`，靠 `Id = 0`（`NoneOptionId`）表示「未选择」，而 `BizType.SeaExport` 的枚举值恰好是 `0`，套进去会撞车——选了海运出口会被当成没选、保存成 `null`。因此另建 `BizTypeOptionModel { BizType? Value; string Name; }`，下拉不设 `SelectedValuePath`，回显与取值都走 `SelectedItem`：

```csharp
CmbEditBizType.SelectedItem = bizTypeOptions.FirstOrDefault(x => x.Value == fields.BizType);
// ...
BizType = (CmbEditBizType.SelectedItem as BizTypeOptionModel)?.Value,
```

选项首项「(不限)」为 `Value = null`，其余按 `BizType` 枚举的 `Description` 生成，以后加业务类型这里不用改。

Avalonia 设计器（`CsprojBuilder.AuPrintDesign`）不走部分字段接口，**未加编辑界面**。

## 5. 修复：设计器保存模板会清空其他字段

**现象**：在设计器里改完报表保存，或在列表页点「重命名」，该打印格式的签单方式、船公司、组织、打印文件名（本次起还有业务类型）全部变成空。

**根因是两处配合失手，不在 `EditAsync` 本身**：

1. `MapDetailToModel` 从 `PrintFormatDetailDto` 映射到桌面端 `PrintFormatModel` 时，压根没带这几个字段；
2. `SavePrintFormatAsync` 构造 `PrintFormatEditDto` 时只填了 `Name / PrintFormatStr / PrintJsonId / SortId / Remark`。

而 `EditAsync` 是标准的全字段覆盖，漏传的字段一律被赋成 `null`。

**修法**：补齐客户端的往返映射，两个设计器各改两处。

| 文件 | 改动 |
| :-- | :-- |
| `CsprojBuilder.PrintDesign/Services/ServiceImplementations.cs` | `MapDetailToModel` 带回五个字段；`SavePrintFormatAsync` 的 Add / Edit 分支完整回传 |
| `CsprojBuilder.AuPrintDesign/Models/PrintFormatModel.cs` | 模型原本没有这五个字段，补上 |
| `CsprojBuilder.AuPrintDesign/Services/ServiceImplementations.cs` | `MapToModel`、`MapDetailToModel` 带回；`SavePrintFormatAsync` 的 Add / Edit 分支完整回传 |

**没有改成「只更新非 null 字段」**：那样这些可空字段就再也没法清空了——传 `null` 到底是「不改」还是「清掉」分不出来，是更难查的坑。

# 避坑指南

- **`0` 是海运出口，不是「未选择」。** 判空必须比 `null`。桌面端下拉不能复用 `OptionModel`（`NoneOptionId = 0` 会与 `BizType.SeaExport = 0` 撞车），已另建 `BizTypeOptionModel`。
- **`BizType` 与 `PrintJsonType` 是两个独立维度。** `PrintJsonType` 决定绑定哪套 JSON 数据结构，`BizType` 只是同一数据源下的业务标签，别拿一个去推另一个。
- **管理端列表的 `bizType` 是「相等或为空」，`codeIssueTypeId` 却是「精确相等」。** 同一个 `PrintFormatQueryDto` 里两种口径并存，读代码时别照着旁边那行抄。
- **`EditAsync` 全字段覆盖的坑还在。** 本次只修了两个桌面设计器的调用方。任何新接入方调 `EditAsync` 都必须先取详情、带全字段再提交，否则照样清空。
- **`BizType` 不做存在性校验。** 它是枚举不是弱外键，`ValidateExtraFieldsAsync` 没管它，传枚举范围外的值不会报错。
- **列表页「复制」仍不继承这些字段。** `BtnCopyConfirm_Click` 只拷 `PrintFormatStr / ModuleId / PrintJsonId / SortId / Remark`，副本的签单方式、船公司、组织、业务类型、文件名都是空。这属于「没带过来」而非「被清空」，本次刻意未改——改了会变更复制语义（副本与原件在「相等或为空」匹配下会同时命中）。
- **`PrintFormatFieldsEditDto` 也是覆盖式保存。** 它同样按整套字段赋值，WPF 设计器的部分字段往返已补齐 `BizType`；若以后有别的调用方接这个接口，同样要传全。
