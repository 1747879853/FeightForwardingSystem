# 背景意图

原 `PrintAsync` 接口仅固定导出 PDF，无法满足业务侧导出 Excel、Word 的需求。本次在保持原有打印流程不变的前提下，增加导出格式选择能力，并统一使用枚举约束前端入参。

# 核心逻辑变更

1. **新增枚举 `PrintExportFormat`**（`CsprojBuilderEnum.cs`）

   | 值  | 枚举名 | 说明       | 文件扩展名 |
   | --- | ------ | ---------- | ---------- |
   | `0` | Pdf    | PDF 文档   | `.pdf`     |
   | `1` | Excel  | Excel 2007 | `.xlsx`    |
   | `2` | Word   | Word 2007  | `.docx`    |

2. **入参 `GetPrintFileDto` 新增字段 `format`**
   - 类型：`PrintExportFormat`
   - 默认值：`0`（PDF）
   - 不传时行为与改造前一致，仍导出 PDF

3. **导出实现**
   - 新增 `FastReportExportHelper`，按枚举分支调用：
     - `PDFExport`（保留压缩、JPEG 质量等 PDF 优化配置）
     - `Excel2007Export`
     - `Word2007Export`
   - 文件名规则：`{Ticks}.{扩展名}`，保存路径仍为 `wwwroot/PrintTempFile/`

4. **涉及文件**

   | 文件                            | 变更                                 |
   | ------------------------------- | ------------------------------------ |
   | `CsprojBuilderEnum.cs`          | 新增 `PrintExportFormat` 枚举        |
   | `PrintFormatDto.cs`             | `GetPrintFileDto` 增加 `Format` 字段 |
   | `FastReportExportHelper.cs`     | 新增，封装三种导出逻辑               |
   | `PrintFormatAdminAppService.cs` | `PrintAsync` 按 `format` 导出        |

# 避坑指南

- **枚举值从 0 开始**：前端传 `format: 0/1/2`，不要沿用旧 CheckBill 中 `1/2/3` 的编号习惯。
- **默认即 PDF**：`format` 可省略，C# 枚举默认值为 `0`（Pdf）。
- **返回值为文件名而非 URL**：前端需自行拼接静态文件访问路径，例如 `/PrintTempFile/{返回的文件名}`。
- **模板兼容性**：Excel / Word 导出效果取决于 FastReport 模板布局，复杂报表建议在对应格式下预览验证。
