# 打印格式 - 2026-07-23

## 背景意图

打印设计器依赖 `App_PrintJsons.Json` 作为 FastReport 数据源样本。各租户/环境库中该样本需与真实业务接口输出结构保持一致。本次新增运维型同步接口：按 `PrintJsonType` 调用对应业务接口生成最新 Json，再用 ADO.NET 批量写回多个数据库的 `App_PrintJsons`。

## 核心逻辑变更

1. **新增 `PrintJsonDbManager`（`AdoNet/`，与 `SqlServerManager` 同路径）**
   - 静态列表 `ConnectionStrings`：自行维护多个库连接串。
   - `UpsertPrintJsonAsync`：按 `PrintJsonType` 判断，已存在则局部更新 `Json`/`LastModificationTime`，**不存在则新建**。

2. **`PrintFormatAppService` 新增 `SyncPrintJsonToMultiDbAsync`（无 Body）**
   - 权限：`Admin.PrintJson.Edit`。
   - 流程：遍历全部 `PrintJsonType` → `TryBuildPrintJsonAsync` 各分支内自行 `new` 入参调业务接口生成 Json → 遍历 `PrintJsonDbManager.ConnectionStrings` 逐库 Upsert。
   - 出参 `List<SyncPrintJsonToMultiDbResultDto>`：连接摘要、类型、受影响行数、说明（含跳过原因）。

3. **类型与取数对应关系（入参在代码分支内填写）**

   | PrintJsonType | 代码内 new 入参 | 调用接口 |
   | :-- | :-- | :-- |
   | SeaExportDetail | `new GuidIdDto { Id = ... }` | SeaExportAdmin/DetailAsync |
   | RecOrderFeeList | `new OrderFeeQueryDto { ... PaySide=收 }` | OrderFeeAdmin/GetPagedListAsync |
   | PayOrderFeeList | `new OrderFeeQueryDto { ... PaySide=付 }` | OrderFeeAdmin/GetPagedListAsync |
   | StatementDetail | `new GuidIdDto { Id = ... }` | StatementAdmin/DetailAsync |
   | SeaImport / AirExport / AirImport | — | 暂未支持，跳过 |

## 避坑指南

1. **连接串需先在 `PrintJsonDbManager.ConnectionStrings` 配好**，否则接口直接报「未配置多库连接字符串」。
2. **调用前务必改好 `TryBuildPrintJsonAsync` 各 case 中的 id/查询条件**（当前占位为 `Guid.Empty`）。
3. **目标库无对应 PrintJsonType 时新建**，有则仅改 Json / LastModificationTime。
4. 费用若要走更改单，可在对应 case 内自行改为调用 `ChangeOrderAdmin/DetailAsync`。
