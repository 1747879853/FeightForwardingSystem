# 客户对账-选费用返回往来单位对象-前端对接文档-2026-08-27

## 1. 变更概览

对账单「选择费用」列表的**业务行**（`items[]`）现在会返回全部往来单位对象。这些字段在 DTO 上早就声明了，但后端一直没赋值，**原先恒为 `null`**，本次起有值。

| 位置 | 变更 | 类型 |
| :-- | :-- | :-- |
| `items[].client` | 委托单位，原恒为 `null` | `ClientSimpleDtoForOrder` |
| `items[].clientContact` | 委托单位联系人，原恒为 `null` | `ClientContactSimpleDto` |
| `items[].team` | 车队，原恒为 `null` | `ClientSimpleDtoForOrder` |
| `items[].custBroker` | 报关行，原恒为 `null` | `ClientSimpleDtoForOrder` |
| `items[].warehouse` | 仓库，原恒为 `null` | `ClientSimpleDtoForOrder` |
| `items[].insurance` | 保险公司，原恒为 `null` | `ClientSimpleDtoForOrder` |
| `items[].consignee` | 收货人，原恒为 `null` | `ClientSimpleDtoForOrder` |
| `items[].shipper` | 发货人，原恒为 `null` | `ClientSimpleDtoForOrder` |
| `items[].notifier` | 通知人，原恒为 `null` | `ClientSimpleDtoForOrder` |

纯加法，没有删除或改名任何字段。业务本身没维护该往来单位时，对应字段仍是 `null`。

## 2. 主接口

| 项 | 值 |
| :-- | :-- |
| 名称 | 可对账费用按业务分组列表（对账单加费用时的「选择费用」） |
| 方法 | `GET` |
| 地址 | `/api/services/app/StatementAdmin/GetOrderFeeGroupAsync` |
| 权限 | `Admin.Statement.Get` + `Admin.OrderFee.Get` |
| 返回 | `PagedList<TransportOrderDto>`，业务在 `items[]`，费用在 `items[].orderFees[]` |

入参本次无变化。

## 3. `ClientSimpleDtoForOrder`（8 个客户类字段共用）

| JSON | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | Guid | 客户id |
| `name` | string | 客户简称 |
| `fullName` | string | 客户全称 |
| `address` | string | 地址，取客户地址子表 `isDefault=true` 那条；没维护默认地址时为 `null` |

## 4. `ClientContactSimpleDto`（`clientContact`）

| JSON       | 类型   | 说明       |
| :--------- | :----- | :--------- |
| `id`       | long   | 联系人id   |
| `name`     | string | 联系人名字 |
| `mobile`   | string | 手机       |
| `email`    | string | 邮箱       |
| `tel`      | string | 办公电话   |
| `position` | string | 职位       |
| `weChat`   | string | 微信号     |

`clientContact` 是**委托单位（`client`）下的**联系人，业务未选联系人时为 `null`。

## 5. 与已有平铺字段的关系

| JSON | 说明 |
| :-- | :-- |
| `clientId` / `clientContactId` / `teamId` / `custBrokerId` / `warehouseId` / `insuranceId` / `consigneeId` / `shipperId` / `notifierId` | 主键**仍然返回**，不受影响 |
| `consigneeContent` / `shipperContent` / `notifierContent` | 收发通的**自由文本内容**，与上面的客户对象是两回事，一直有值，本次未动 |

展示名称请读对象（`client.name`），不要再自己拿 id 去别的接口换名字。

## 7. 前端适配清单

- [ ] 业务行「委托单位」改读 `client.name` / `client.fullName`，不再用 id 换名
- [ ] 需要联系方式时读 `clientContact.name` / `mobile` / `tel`
- [ ] 车队、报关行、仓库、保险公司按需读对应对象的 `name`
- [ ] 收货人 / 发货人 / 通知人：客户对象读 `consignee`/`shipper`/`notifier`，抬头文本仍读 `consigneeContent`/`shipperContent`/`notifierContent`
- [ ] 所有对象在业务未维护时为 `null`，取值前判空
