# 客户对账-选费用返回已对账信息-前端对接文档-2026-08-14

## 1. 变更概览

对账单「选择费用」列表现在会告诉你每条费用**是否已经对过账**、以及**进过哪些对账单**（含对账单号、对账时间、对账人）。

| 位置 | 变更 | 类型 |
| :-- | :-- | :-- |
| `orderFees[].isStatemented` | **新增**，是否已对账 | bool |
| `orderFees[].statements[]` | **本接口原先恒为 `null`，现在必定返回数组** | 数组 |
| `orderFees[].statements[].creationTime` | **新增**，对账时间 | DateTime |
| `orderFees[].statements[].creatorUserName` | **新增**，对账人昵称 | string |

纯加法，没有删除或改名任何字段。

## 2. 主接口

| 项   | 值                                                           |
| :--- | :----------------------------------------------------------- |
| 名称 | 可对账费用按业务分组列表（对账单加费用时的「选择费用」）     |
| 方法 | `GET`                                                        |
| 地址 | `/api/services/app/StatementAdmin/GetOrderFeeGroupAsync`     |
| 权限 | `Admin.Statement.Get` + `Admin.OrderFee.Get`                 |
| 返回 | `PagedList<TransportOrderDto>`，费用在 `items[].orderFees[]` |

入参本次无变化。

## 3. 费用上的新字段

| JSON | 类型 | 说明 |
| :-- | :-- | :-- |
| `isStatemented` | bool | 该费用只要存在于**任意一张**对账单即为 `true`。等价于 `statements.length > 0`，两者不会矛盾，取其一判断即可 |
| `statements` | 数组 | 该费用已归属的对账单列表，按 `statementNum` **升序**；未对账时为 `[]`（不是 `null`） |

### 3.1 `statements[]` 元素（`StatementSimpleDto`）

| JSON | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | Guid | 对账单id |
| `statementNum` | string | 对账单号 |
| `creationTime` | DateTime | **对账时间**，即该对账单的创建时间 |
| `creatorUserName` | string | **对账人昵称**，即该对账单的创建人；历史数据缺创建人时为 `null` |

> [!IMPORTANT] `creationTime` / `creatorUserName` 是**对账单**的创建时间与创建人，不是「这条费用被加进该对账单」的时间与操作人。所以同一张对账单下的所有费用，这两个值都一样；事后用「加费用」往老单里补进去的费用，显示的仍是该对账单最初的创建时间与创建人。

## 4. 与 `includeStatemented` 的配合（重要）

| 场景 | 入参 | 返回费用的 `isStatemented` |
| :-- | :-- | :-- |
| 只要没对过账的（默认） | 不传 `includeStatemented` | **恒为 `false`**，`statements` 恒为 `[]` |
| 允许多次对账 | `includeStatemented=true` | 混合，`true` 表示该费用已在别的对账单里 |

也就是说这两个新字段**只有在勾选「包含已对账费用」时才有信息量**。建议：勾选后在费用行上展示「已对账」标记，鼠标悬浮或展开显示 `statements[]` 的对账单号 / 对账时间 / 对账人，让操作人在重复对账前知道这条费用之前进过哪张单。

另外，如果调用时传了 `statementId`（给已有对账单加费用），本对账单已包含的费用在后端就被过滤掉了，因此返回费用的 `statements[]` 里**不会出现该对账单**，只会是其他对账单。

## 6. 同步受影响的其他接口

这两处原本就返回 `statements[]`，现在数组元素多出 `creationTime` / `creatorUserName`，费用上多出 `isStatemented`，均为加法：

| 接口 | 位置 |
| :-- | :-- |
| `GET /api/services/app/OrderFeeAdmin/GetPagedListAsync` | `items[].statements[]`、`items[].isStatemented` |
| `GET /api/services/app/ChangeOrderAdmin/DetailAsync` | `orderFees[].statements[]`、`orderFees[].isStatemented` |

费用列表如果已经用 `statements.length > 0` 判断「是否已对账」，可以直接换成读 `isStatemented`，语义完全一致。

## 7. 前端适配清单

- [ ] 选费用弹窗费用行增加「已对账」标记，读 `isStatemented`
- [ ] 展开/悬浮展示 `statements[]`：对账单号、对账时间（`creationTime`）、对账人（`creatorUserName`）
- [ ] 该标记只在勾选「包含已对账费用」（`includeStatemented=true`）时才会出现 `true`，默认模式不必展示相关列
- [ ] `statements` 未对账时是 `[]` 而非 `null`，遍历前无需判空（本接口改造前是 `null`，如有旧的判空逻辑可保留，不影响）
- [ ] 费用列表、更改单详情若已有「对账单号」展示，可顺带补上对账时间与对账人两列
