# 1. 背景意图 (Background)

`keyword` 是单值模糊匹配。本次新增 `keys`，一次传入多个关键字做精确匹配。两个查询 DTO 的 `keyword` 覆盖字段不一样，`keys` 分别跟各自对齐。

# 2. 核心逻辑变更

| DTO / 接口 | 精确匹配字段（与该接口 keyword 相同） |
| :-- | :-- |
| `StatementQueryDto` / `GetPagedListAsync` | 对账单号、备注、客户名称、客户代码 |
| `GetOrderFeeGroupInputDto` / `GetOrderFeeGroupAsync` | 主提单号、订舱编号、委托编号 |

- 列表：`GET /api/services/app/StatementAdmin/GetPagedListAsync`
- 选费用：`GET /api/services/app/StatementAdmin/GetOrderFeeGroupAsync`

匹配规则：精确相等、列表内 OR、与 `keyword` 同时传时为 AND。GET 用 `keys=A&keys=B`。

# 3. 避坑指南 (Blockers)

> [!IMPORTANT] **两个接口的 `keys` 不是同一批字段。** 列表搜的是对账单号/客户名，选费用搜的是业务单号。不要拿提单号去筛对账单列表的 `keys`，也反过来。

> [!NOTE] 列表另有独立的 `mblNum` 模糊条件（经费用关联业务），`keys` 不包含主提单号。
