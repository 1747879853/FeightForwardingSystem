# 一、这次前端要做什么

只有两件事：

1. **用户新增/编辑界面加一个字段：开票分机号**（数字，可空，非必填）。
2. **发票开出界面把"开票员"去掉**（如果之前展示了的话）。

发票开出的开票、冲红接口**入参出参都没变**，不用改调用。

## 为什么

开票服务商确认：**只要传了分机号，服务商会按分机号自动匹配开票员**，开票员不用传。之前开票员取的是当前登录人昵称，而服务商要求它与其侧维护的开票员姓名完全一致，对不上直接开票失败——等于要求"系统里的用户昵称"长期和"服务商侧的开票员姓名"人工对齐，改个昵称就能把开票搞崩。现在这条约定没有了。

分机号原来是全局配置（全公司一个值，等于没区分人），现在落到每个用户身上。

# 二、用户新增/编辑：加"开票分机号"

## 2.1 涉及的接口

分机号在下面这些接口的出入参里都已经加好了，字段名统一是 `extensionNumber`。

| 用途 | 接口 |
| :-- | :-- |
| 新增/编辑用户（提交） | **POST** `/api/services/app/UserAdmin/CreateOrUpdateUserAsync` |
| 新增/编辑用户（提交，带数据权限的那条） | **POST** `/api/services/app/UserAdmin/CreateOrUpdateUserInAdminAsync` |
| 取用户编辑数据（回显） | **GET** `/api/services/app/UserAdmin/GetUserForEditAsync` |
| 用户详情 | **GET** `/api/services/app/UserAdmin/GetUserAsync` |
| 用户分页列表 | **GET** `/api/services/app/UserAdmin/GetUserPagedListAsync` |
| 用户分页列表（另一个） | **GET** `/api/services/app/UserAdmin/GetUserPagingListAsync` |

> 两个提交接口用的是**两个不相干的入参 DTO**，字段是各写各的。这次两个都加了 `extensionNumber`，前端调哪个都能存进去。

## 2.2 新增的入参字段

上面两个提交接口都适用，其余入参字段一个没动。

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `extensionNumber` | `int?` | 否 | 开票分机号。**数字类型**，由开票服务商分配；不填传 `null` |

**校验**：类型就是校验，输入框限制只能输数字即可，后端没有额外的位数或格式校验。

**不填会怎样**：照常开票，只是报文里不带分机号，服务商按企业默认开票员处理。 **不要**把它做成必填，也不要因为它为空就拦住任何操作。

## 2.3 新增的出参字段

回显、详情、列表都返回同一个字段。

| 字段              | 类型   | 说明                          |
| :---------------- | :----- | :---------------------------- |
| `extensionNumber` | `int?` | 开票分机号，没维护时为 `null` |

## 2.4 界面建议

放在"办公电话"旁边即可，标签用「**开票分机号**」。提示文案建议："开票时用于匹配开票员，由开票服务商分配；不填则不影响开票。"

⚠️ 文案里**不要出现服务商名称**，用"开票服务商"这类中性说法。

# 三、发票开出：把"开票员"去掉

《诺诺发票对接-发票开出调用诺诺开票-前端对接文档-2026-08-15.md》第九节第 5 条原来写着 "开票员用的是当前登录人昵称，界面上如果要展示开票员，直接显示当前用户昵称即可"——**这条作废**。开票员已不再上传，界面上不要再展示"开票员"。

同时，原来那条报错**不会再出现**了，前端如果针对它做过特殊处理可以删掉：

| 已取消的报错                                       |
| :------------------------------------------------- |
| ~~当前登录人未维护昵称，无法作为开票员提交给诺诺~~ |

开票、冲红两条链路的**接口地址、入参、出参全都没变**。

---

# 四、上线注意

如果之前靠全局配置的分机号把发票归到某个开票员名下，上线后要把该分机号维护到对应操作人的用户资料里。不维护不影响能不能开票，只影响发票在服务商侧归到哪个开票员名下。
