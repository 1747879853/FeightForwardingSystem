# 1. 背景意图 (Background)

原来 access_token 是系统自动取号的，并为此做了两级缓存（进程内存 + `App_NuonuoAccessTokens` 表）来尽量少取号，令牌失效(070301)时还会自动强制重取一次并重试。

2026-08-28 向服务商确认后，这个方向必须放弃：

> - 最好不要每次都获取新 token
> - **如果 30 天内获取超过 50 次，系统会判定被攻击，就锁死开不出来了**
> - **需要给你重置才行，默认锁死**
> - 不小心获取了 token，就保留新的 token 即可

关键点不是"配额有限"，而是**超限的后果是账号被锁死、且只能由服务商人工重置**。

原实现虽然已经尽力压低取号次数，但存在一个致命的失败模式： **令牌被判失效 → 自动重取 → 新令牌又被判失效 → 再重取……** 几分钟就能把 50 次烧光并锁死账号。而自动重取原本要解决的问题（多进程并存时令牌互相顶掉）本身就是取号带来的——不取号，这个问题也不存在。

**代价是不对称的：锁死账号（全公司开不出票、要求人工重置）≫ 这张票先开不出来（换个令牌就好）。** 所以改成：令牌向服务商索取一次，作为**固定值人工维护**，系统只读不写。

# 2. 核心逻辑变更 (Core Changes)

## 2.1 令牌存在跟 appKey 一样的地方

`AbpOrganizationUnits`（组织/公司）新增列：

| 列 | 类型 | 说明 |
| :-- | :-- | :-- |
| `InvoiceAccessToken` | `nvarchar(512)` | 开票令牌（机密）。**固定值，人工维护，系统不自动刷新** |

与已有的 `InvoiceAppKey`、`InvoiceAppSecret`、`UnifiedSocialCreditCode` 一起构成该公司的开票凭据。 `NuonuoCredential` 相应新增 `AccessToken` 属性，`BuildCredential` 从组织上取。

> **需要生成迁移。**

## 2.2 `NuonuoTokenProvider` 只读不取

接口从两个方法收缩成一个：

| 原 | 现 |
| :-- | :-- |
| `GetTokenAsync`（内存 → 数据库 → 取号） | `GetTokenAsync`（直接返回公司资料里的固定值） |
| `ForceRefreshAsync`（强制重取） | **已删除**（连同自动重取的调用点） |

`GetTokenAsync` 的行为：

- `Nuonuo:RequireToken=false` → 返回空串，请求头不带 accessToken（沙箱用）；
- 令牌为空 → 直接报错"该公司未维护开票令牌…请向开票服务商索取令牌后填到公司资料的开票令牌里（令牌是固定值，系统不会自动获取）"；
- 否则返回该固定值。

原来的取号 + 两级缓存实现**整段块注释保留**在同一个文件里（含 `FetchTokenAsync`、`LoadAsync`、 `SaveAsync`、`CacheEntry`），万一服务商放开限制可直接恢复。`App_NuonuoAccessTokens` 表也留着没删。

## 2.3 令牌失效不再自动重取

`NuonuoApiClient.SendAsync` 原来收到 `070301` 会 `ForceRefreshAsync` 后重试一次，现在改成直接抛错：

> 开票令牌已失效[070301]：{服务商描述}。请向开票服务商索取新令牌，并更新到公司资料的开票令牌里（系统不会自动刷新令牌）

`SendOnceAsync` 的 `forceRefreshToken` 参数一并去掉。

## 2.4 组织接口同步

`InvoiceAccessToken` 的读写范围与 `InvoiceAppSecret` **完全一致**：

| 接口                                    | 返回       | 可写入 |
| :-------------------------------------- | :--------- | :----- |
| `GetOrganizationUnitAsync` 获取单个组织 | ✅         | —      |
| `CreateOrganizationUnitAsync` 新建组织  | ✅         | ✅     |
| `UpdateOrganizationUnitAsync` 更新组织  | ✅         | ✅     |
| `GetOrganizationUnitsAsync` 组织列表    | 置 null    | —      |
| `MoveOrganizationUnitAsync` 移动组织    | 置 null    | —      |
| 其余接口 / 各类 Simple 输出             | 不含该字段 | —      |

# 3. 避坑指南 (Blockers & Pitfalls)

> [!IMPORTANT] **坑点 1：任何"自动取号"的想法都要先想清楚锁死的代价** 别再加"令牌失效就自动重取""定时预取""启动时刷新"这类逻辑。30 天 50 次不是软限制，超了是**锁死 + 人工重置**。真要恢复自动取号，前提是服务商书面放开限制，而不是"我们控制得住频率"。

> [!IMPORTANT] **坑点 2：`RequireToken=false` 会让令牌完全不生效** 该配置为 false 时 `GetTokenAsync` 直接返回空串、请求头不带 accessToken， **连"令牌没维护"都不会报错**。沙箱可以这样，正式环境必须改成 `true`，否则会以为配了令牌其实没用上。

> [!NOTE] **令牌换新之后不用重启** 令牌现在每次请求都从组织表读（`BuildCredential` → `NuonuoCredential.AccessToken`），没有任何缓存，在公司资料里改完立即生效。这也是砍掉内存缓存的附带好处。

> [!NOTE] **配置项 `Nuonuo:TokenUrl` 已不再使用** 只有被注释掉的取号实现用它。留在配置里不影响运行，恢复自动取号时还要用。
