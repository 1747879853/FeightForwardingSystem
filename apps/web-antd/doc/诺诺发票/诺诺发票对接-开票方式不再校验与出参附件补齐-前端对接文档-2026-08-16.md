# 发票开出/开票申请-出参补齐与附件（前端对接）

**没有新增接口，没有新增权限，没有删改任何已有字段。** 本次是**纯增量**：出参多给、按钮少拦。

> **变更 1**：「开发票」按钮**不用再按开票方式过滤**，成功后开票方式会被后端自动改成"接口开票"。 **变更 2**：发票开出**列表**补齐到与详情**完全一致**（多了 14 个字段 + 附件）。 **变更 3**：**开票申请**的列表与详情新增 `attachments`（它所挂发票开出下的发票文件）。 **变更 4**：发票附件种类变多了（XML、图片、纸质PDF），**不要写死假设只有 OFD/PDF**。

---

## 一、「开发票」按钮的可用条件变了

**改之前**：`invoiceIssueType === 0`（接口开票）才显示。 **改之后**：**不用判 `invoiceIssueType`**，只看 `editLocked === false`。

手动记录（`invoiceIssueType === 1`）的发票开出也能点「开发票」。调用成功后后端会把它改成 `0`（接口开票），请用出参里的 `invoiceIssueType` 刷新这一列，**别继续显示"手动记录"**。

`IssueByInterfaceAsync` 出参新增：

| 字段               | 类型  | 说明                               |
| ------------------ | ----- | ---------------------------------- |
| `invoiceIssueType` | `int` | 开票方式。**本接口成功后恒为 `0`** |

原来那条报错 `该发票开出的开票方式不是接口开票…` 已经不会再出现了。

「冲红」按钮同理，也不用判 `invoiceIssueType`——能走到"开票完成"的必然是接口开出来的。冲红按钮条件：`issueStatus` 为 `2`/`24` 且 `redLocked === false`。

## 二、发票开出列表补齐（`GetPagedListAsync`）

`InvoiceIssueListDto` 现在与 `InvoiceIssueDetailDto` **返回完全相同的字段**，列表页不用为了显示状态、订单号、发票代码、冲红信息或下载发票再逐条查详情。

### 本次新增（列表原来没有的）

**接口开票组**

| 字段               | 类型        | 说明                             |
| ------------------ | ----------- | -------------------------------- |
| `issueOrderNo`     | `string`    | 提交开票用的订单号               |
| `issueRequestTime` | `DateTime?` | 提交开票请求的时间               |
| `invoiceCode`      | `string`    | 发票代码。电票为空，只有纸票有值 |

**冲红组**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `redReason` | `int?` | 冲红原因 1销货退回 2开票有误 3服务中止 4销售折让 |
| `redBillId` | `string` | 红字确认单申请号 |
| `redBillNo` | `string` | 红字确认单编号 |
| `redBillUuid` | `string` | 红字确认单uuid（内部标识，一般不展示） |
| `redOrderNo` | `string` | 红票订单号 |
| `redSerialNum` | `string` | 红票开票流水号 |
| `redInvoiceCode` | `string` | 红票发票代码（纸票才有） |
| `redInvoiceTime` | `DateTime?` | 红票开票时间 |
| `redApplyTime` | `DateTime?` | 发起冲红申请的时间 |
| `redApplyUserId` | `long?` | 发起冲红申请的人 |
| `redApplyUserName` | `string` | **发起冲红申请的人昵称** |
| `redFailCause` | `string` | 冲红失败/确认单作废原因 |

**详情**也补了 `redBillUuid`、`redApplyUserId`、`redApplyUserName` 三个。

### 列表原本就有的（继续可用）

`issueStatus`、`issueSerialNum`、`issueFailCause`、`redStatus`、`combinedStatus`、`redLocked`、`editLocked`、`redInvoiceNo`。

> 列表状态列建议只绑 **`combinedStatus`**（未冲红=开票状态原值，已冲红=`redStatus+100`），不要自己拿 `issueStatus` 和 `redStatus` 再拼。按钮禁用统一用 **`editLocked`**，别自己拼 `issueStatus` + `redStatus` 的条件，后端也是同一份规则算出来的。

## 三、附件

### 3.1 发票开出列表也返回 `attachments` 了

字段结构与详情完全一致（`List<AttachmentItemDto>`，含 `url` / `friendlyFileName` / `mediaType` 等）。列表行上可以直接放"下载发票"，不用先查详情。

### 3.2 开票申请新增 `attachments`

`InvoiceApplicationAdmin` 的 `DetailAsync` 与 `GetPagedListAsync` 都新增：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `attachments` | `List<AttachmentItemDto>` | **这条开票申请所挂那张发票开出下的发票文件** |

- 开票申请自己没有附件，这里是后端替你从发票开出那边取过来的；
- **不分组**，拉平成一个数组；
- 申请还没挂发票开出（未开票）时为空；
- **冲红完成后挂靠会被解除，附件也随之消失**——这是正常的，不是数据丢失。

### 3.3 附件种类变多了，别写死

服务商返回几个文件地址后端就存几个，可能出现：

| `friendlyFileName` | 说明 |
| --- | --- |
| `{发票号}.ofd` | **法定原始凭证**，入账归档用 |
| `{发票号}.xml` | 税局原始数据格式，对接财务/税务归档系统用 |
| `{发票号}.pdf` | 版式转换产物，**不能作原始凭证**，只用于查看/打印/发客户 |
| `{发票号}-纸质.pdf` | 含底图的纸票打印版（数电纸票才有） |
| `{发票号}-{8位哈希}.jpg` | 发票图片，可能多张 |

冲红完成后会多出同一套红票文件，文件名里的号换成红票号。蓝红靠 `invoiceNo` / `redInvoiceNo` 区分，不要再按「发票」「红票」前缀判断。

⚠️ **这几种不是都会有**。哪些格式有值由服务商侧的企业资质配置决定，沙箱环境更可能只给一两个。 **请按实际返回的数组渲染，不要写死"一定有 PDF"这类假设。**

界面建议：

- 蓝票/红票按 `friendlyFileName` 前缀（`发票` / `红票`）分区展示；
- "下载原始凭证"指向 OFD 或 XML，"查看/打印"指向 PDF；
- 某个文件这次没有，用户点一次「查询开票结果」后端会自动补下载，刷新即可看到。

## 四、前端要改的地方汇总

1. 「开发票」按钮去掉 `invoiceIssueType === 0` 的判断，只留 `editLocked === false`；调用成功后用出参刷新开票方式列。
2. 「冲红」按钮同样去掉 `invoiceIssueType` 判断。
3. 发票开出列表可以直接用新补的字段与 `attachments`，不必再为展示这些去调详情。
4. 开票申请列表/详情如果要展示发票文件，直接用新的 `attachments`。
5. 附件渲染改成遍历数组，不要按固定两项（OFD/PDF）写死。
