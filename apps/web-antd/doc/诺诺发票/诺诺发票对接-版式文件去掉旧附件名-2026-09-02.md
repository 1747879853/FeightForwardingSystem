# 一、背景意图

旧附件名是 `发票OFD-{号}.ofd`、`红票图片1-{号}.jpg` 这种「前缀 + 序号」。图片曾把 `pictureUrl`（在线查看页短链，存下来打开报错）和 `imgUrls`（真图）合成列表按 1、2 编号，红票就会出现「图片1 打不开、图片2 才对」。

当前落盘已经改成 `{发票号}.ofd` / `{发票号}-{哈希}.jpg`，但去重还认旧名：库里有 `红票图片1` 时会跳过按新名再存。本次去掉旧名兼容，去重只认当前名字。

当前命名见《诺诺开票模块总逻辑文档》4.5。

# 二、核心逻辑变更

- `SaveInvoiceFilesAsync` 去掉 `label`（「发票」「红票」）和 `legacyFileName` 判断。
- 去重只比较当前 `FriendlyFileName`。
- 图片仍只取 `imgUrls`，不存 `pictureUrl`（这一点本来就有，不是这次新加的）。

# 三、避坑指南

- 前端不要再按文件名前缀「发票」「红票」分组，用详情里的 `invoiceNo` / `redInvoiceNo` 看 `friendlyFileName` 以谁开头。
- 已经落库的旧名附件不会自动改名或删除；再查一次会按新名再存一份。需要清旧文件就手工删附件。
- 图片不用序号：服务商少给一张就会把「图片1」对到另一张图上，同名被跳过，缺的那张永远进不来。
