# 一、背景意图

查询冲红结果时，【发票详情】可能已经是失败（`redFailCause` 有值，常见如税局回「需登录电子发票服务平台」）。本地此时往往已经有红票流水号/订单号，再点查询只会反复命中这条失败记录，不会把同一张票再推一次。

本次：查红票失败就按原号调一次 `nuonuo.OpeMplatform.reInvoice`。**重试接口成功时用它的返回落地**，不要再拿查询到的失败原因覆盖。

完整流程见《诺诺开票模块总逻辑文档》2.2 与卡点 8。

# 二、核心逻辑变更

发生在 `RefreshRedAsync`（`QueryRedResultAsync` 与红票回调共用）：

1. 照旧：查确认单 →（流水号为空时）快捷冲红 → 查发票详情并落地。
2. 落地后若尚未冲红完成、且 `redFailCause` 有值：按 `RedSerialNum`（没有则 `RedOrderNo`）调开票重试，一次查询只调一次。
3. 重试 `code=E0000` 且 `result` 带出发票信息（发票号/状态/版式地址/流水号任一）：走原来的 `ApplyRedResultAsync` 落地。
4. 重试失败、或成功但 `result` 只是受理回执：保持查询时写下的失败原因，等回调或下次查询。不把整次查询打成异常。

确认单作废等失败终态在查发票详情之前就返回，不会走重试。

# 三、避坑指南

- 快捷冲红首次推进仍只在红票流水号为空时调（订单号替换仅支持一次）。失败后的重推走 `reInvoice`，不要再调快捷冲红。
- 重试报文流水号/订单号必须与失败那次一致，不要新生成订单号。
- 对外报错与出参不出现服务商名称；日志里可以写诺诺、流水号、orderNo。
