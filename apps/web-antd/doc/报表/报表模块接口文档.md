# 0. 说明

本文档只写接口：地址、入参全字段、出参全字段。功能口径与业务逻辑见同目录下《报表模块总逻辑文档.md》。

**接口清单：**

| 接口 | 方法 | 地址 |
| :-- | :-- | :-- |
| 利润报表列表 | POST | `/api/services/app/ReportAdmin/GetProfitReportListAsync` |
| 欠费报表列表 | POST | `/api/services/app/ReportAdmin/GetArrearsReportListAsync` |
| 海空港口合并分页列表 | GET | `/api/services/app/PortCodeAdmin/GetSeaAirPortPagedListAsync` |

**两个报表都不分页**，直接返回数组。

# 1. 前端必须先知道的三件事

## 1.1 港口条件要成对传

海运港和空运港是两张独立的表，主键都是 `long` 且会重复。所以起运港/目的港必须传两个字段：

```
POLId + POLIsSeaPort
PODId + PODIsSeaPort
```

只传 id 不传 `IsSeaPort`，接口会直接报错「传了起运港id就必须同时传起运港是否海运港」。

港口下拉用 `GetSeaAirPortPagedListAsync` 取，返回的每一项自带 `IsSeaPort`，原样回传即可。

## 1.2 条件字段在某些业务类型上不存在，填了会把那类业务整个排除

| 填了这个条件 | 结果里会消失的业务类型 |
| :-- | :-- |
| 船公司 `CarrierId` | 空运出口、件杂货 |
| 订舱代理 `BookingAgentId` | 海运进口 |
| 场站 `YardId` | 海运进口、空运出口、件杂货（只剩海运出口） |
| 装运方式 `BLType` | 海运进口、空运出口、件杂货（只剩海运出口） |
| 船名 `Vessel` / 航次 `InnerVoyno` | 空运出口 |
| 起运港/目的港 `IsSeaPort=true` | 空运出口 |
| 起运港/目的港 `IsSeaPort=false` | 海运出口、海运进口、件杂货 |

返回时同理：业务类型对象里不声明该类型没有的字段——`seaImport` 里没有订舱代理/场站/装运方式，`airExport` 里没有船公司/场站/装运方式/船名/航次，`breakBulk` 里没有船公司/场站/装运方式；`transportOrder.ctns` 对空运出口和件杂货恒为空数组。

## 1.3 权限

| 接口 | 权限 |
| :-- | :-- |
| 利润报表 | `Admin.Report.Profit.Get`（不分应收应付，一个权限看全部） |
| 欠费报表 `PaySide=0`(收) | `Admin.Report.Arrears.Receive.Get` |
| 欠费报表 `PaySide=1`(付) | `Admin.Report.Arrears.Pay.Get` |

权限树结构（`Admin.Report` 与 `Admin.Report.Arrears` 是父节点，只用于组织菜单，接口不校验）：

```
报表 Admin.Report
├── 利润报表 Admin.Report.Profit.Get
└── 欠费报表 Admin.Report.Arrears
    ├── 应收查询 Admin.Report.Arrears.Receive.Get
    └── 应付查询 Admin.Report.Arrears.Pay.Get
```

另外没有 `Admin.OrderFee.Confidential.Get` 权限的用户，机密费用不参与统计，金额会比有权限的人看到的小。

# 2. 利润报表列表

**`POST /api/services/app/ReportAdmin/GetProfitReportListAsync`**

方法名 `GetProfitReportListAsync`，入参放 body。

> [!IMPORTANT] **行集由业务决定，不由费用决定——会返回金额全是 0 的行，这是正常的，不要当脏数据过滤掉。**
>
> | 项 | 口径 |
> | :-- | :-- |
> | 哪些业务出现 | 通过筛选条件的业务**必定出现**，哪怕它一条费用都没录 |
> | `IsMergeChangeOrder = true` | 每个业务一行 |
> | `IsMergeChangeOrder = false` | 每个业务的**原票行必定有**；更改单行只在该更改单**有参与算钱的费用**时才出现 |
> | 参与算钱的费用 | 只认 `Submitted(1) 提交审核` 和 `Passed(2) 审核通过`；`Entering(0) 录入` 与 `Rejected(3) 驳回` **不计入任何金额** |
> | 没有合格费用的行 | `currencies` 为**空数组**，五个合计全为 `0`，`totalProfitRate` 为 `null` |
>
> 这样设计是为了能看出哪些票漏录了费用。前端如果只想看有钱的行，自己按合计过滤，后端不做这个过滤。

## 2.1 入参 `ProfitReportQueryDto`

| 字段名 | 类型 | 必填 | 含义 |
| :-- | :-- | :-: | :-- |
| `IsMergeChangeOrder` | `bool` | **是** | 是否合并更改单。true=原票和所有更改单合成一组；false=原票一组、每个更改单各一组 |
| `BizType` | `int?` |  | 业务类型 0海运出口 1海运进口 2空运出口 3件杂货，不传=全部业务类型都查 |
| `ClientId` | `Guid?` |  | 委托单位id |
| `Keyword` | `string` |  | 关键词，模糊匹配主提单号**或**委托编号，命中任一即可。与下面两个单独条件是且的关系 |
| `MblNum` | `string` |  | 主提单号，模糊匹配 |
| `CommissionNum` | `string` |  | 委托编号，模糊匹配 |
| `BizDateStart` | `DateTime?` |  | 业务日期起，以天为单位，含当天 |
| `BizDateEnd` | `DateTime?` |  | 业务日期止，以天为单位，含当天 |
| `CargoId` | `int?` |  | 货物类型 0普通货 1冻柜 2危险品 3超限箱 |
| `SettlementType` | `int?` |  | 结算方式 0票结 1月结 2约定天数 |
| `OrgId` | `long?` |  | 所属组织id，实际搜索该组织及其所有下属组织 |
| `BookingAgentId` | `Guid?` |  | 订舱代理id |
| `CarrierId` | `long?` |  | 船公司id |
| `YardId` | `Guid?` |  | 场站id |
| `BLType` | `int?` |  | 装运方式 0整箱 1拼箱主票 2拼箱分票 |
| `Vessel` | `string` |  | 船名，模糊匹配 |
| `InnerVoyno` | `string` |  | 航次，模糊匹配 |
| `POLId` | `long?` |  | 起运港id，必须与 `POLIsSeaPort` 同时传 |
| `POLIsSeaPort` | `bool?` |  | 起运港是否海运港 |
| `PODId` | `long?` |  | 目的港id，必须与 `PODIsSeaPort` 同时传 |
| `PODIsSeaPort` | `bool?` |  | 目的港是否海运港 |
| `SaleUserIds` | `long[]` |  | 销售，多选 |
| `OperationUserIds` | `long[]` |  | 操作，多选 |
| `CustomerServiceUserIds` | `long[]` |  | 客服，多选 |
| `DocumentationUserIds` | `long[]` |  | 单证，多选 |
| `LanerUserIds` | `long[]` |  | 航线，多选（干系人角色，不是港口上挂的航线） |
| `OverseasCustomerServiceUserIds` | `long[]` |  | 海外客服，多选 |
| `AccountDateStart` | `DateTime?` |  | 会计期间起，以月为单位，含当月 |
| `AccountDateEnd` | `DateTime?` |  | 会计期间止，以月为单位，含当月 |

同一类人员多选之间是「或」，不同类人员之间是「且」。

## 2.2 出参 `ProfitReportDto[]`

默认按业务日期倒序、委托编号倒序。

### 业务信息（嵌套对象，不平铺）

**业务字段全部挂在 `transportOrder` 对象下**，业务类型专属的字段再往下挂一层，按 `transportOrder.bizType` 只有对应的那一个有值：

```
row
├── transportOrderId / changeOrderId / isOriginal / accountDate   ← 行级
├── localCurrencyId / localCurrencyCode                           ← 行级 合计金额的计量单位
└── transportOrder                                                ← 各业务类型共有的字段
    ├── bizType / client / bizDate / mblNum / commissionNum / ...
    ├── seaExport   ← 仅 bizType=0 时有值，其余为 null
    ├── seaImport   ← 仅 bizType=1 时有值，其余为 null
    ├── airExport   ← 仅 bizType=2 时有值，其余为 null
    └── breakBulk   ← 仅 bizType=3 时有值，其余为 null
```

**行级字段：**

| 字段名 | 类型 | 含义 |
| :-- | :-- | :-- |
| `TransportOrderId` | `Guid` | 业务id，跳转业务详情用 |
| `ChangeOrderId` | `Guid?` | 更改单id，合并模式恒为 null |
| `IsOriginal` | `bool` | 是否原票，合并模式恒为 true |
| `AccountDate` | `DateTime` | 会计期间。不合并时更改单组取该更改单自己的，合并时取主单的——因为可能来自更改单而不是主单，所以留在行级，没放进 `transportOrder` |
| `LocalCurrencyId` | `long?` | **本位币id**，取主单所属公司配置的本位币 |
| `LocalCurrencyCode` | `string` | **本位币代码**，如 `"RMB"` |
| `TransportOrder` | `ReportTransportOrderDto` | 业务主单信息，见下 |

> [!IMPORTANT] **`localCurrencyCode` 是本行所有「合计」字段的计量单位**（`totalReceivable`、`totalProfit` 等都是本位币金额），展示合计时应该配着它一起显示，不要再写死「元」或「RMB」。
>
> 它放在行级而不是 `transportOrder` 下，就是为了跟它标注的那些金额待在同一层，前端不用跨层取。
>
> 取值口径：由主单 `orgId` 沿组织串向上找到**最接近的公司节点**取其本位币，**不是**「组织串上第一个配了本位币的节点」。主单没录组织、未归属公司、或公司未配本位币时为 `null`——此时该行的合计金额没有明确的计量单位，前端应做兜底提示。

> [!NOTE] **不同行的本位币可能不一样。** 一次查询会跨多个公司，各公司本位币可以不同，所以**不要把某一行的 `localCurrencyCode` 当成整张报表的单位**，也不要跨行直接加总合计列。

**`TransportOrder`（`ReportTransportOrderDto`）——各业务类型共有的字段：**

| 字段名 | 类型 | 含义 |
| :-- | :-- | :-- |
| `BizType` | `int` | 业务类型 0海运出口 1海运进口 2空运出口 3件杂货，决定下面四个对象哪个有值 |
| `Client` | `ClientSimpleDto` | 委托单位 |
| `BizDate` | `DateTime?` | 业务日期。海运出口=开船，海运进口=到港，空运出口=起飞，件杂货=开船 |
| `MblNum` | `string` | 主提单号 |
| `CommissionNum` | `string` | 委托编号 |
| `CargoId` | `int` | 货物类型 |
| `SettlementType` | `int?` | 结算方式，存量业务为 null |
| `SettlementDate` | `DateTime` | 应结日期 |
| `Orgs` | `OrganizationUnitSimpleDto[]` | 所属组织串，从最高级到本组织 |
| `Sales` | `UserSimpleDto[]` | 销售 |
| `Operations` | `UserSimpleDto[]` | 操作 |
| `CustomerServices` | `UserSimpleDto[]` | 客服 |
| `Documentations` | `UserSimpleDto[]` | 单证 |
| `Laners` | `UserSimpleDto[]` | 航线 |
| `OverseasCustomerServices` | `UserSimpleDto[]` | 海外客服 |
| `CodeGoodss` | `CodeGoodsSimpleDto[]` | 品名 |
| `PKGS` | `int?` | 件数 |
| `Kgs` | `decimal?` | 重量 |
| `Cbm` | `decimal?` | 尺码 |
| `Ctns` | `ReportCtnSimpleDto[]` | 箱型箱量。集装箱挂在业务主单上，空运出口和件杂货恒为空数组 |
| `SeaExport` | `ReportSeaExportDto` | 仅 `bizType=0` 有值 |
| `SeaImport` | `ReportSeaImportDto` | 仅 `bizType=1` 有值 |
| `AirExport` | `ReportAirExportDto` | 仅 `bizType=2` 有值 |
| `BreakBulk` | `ReportBreakBulkDto` | 仅 `bizType=3` 有值。**2026-09-27 新增** |

**`SeaExport`（`ReportSeaExportDto`）：**

| 字段名         | 类型                  | 含义                               |
| :------------- | :-------------------- | :--------------------------------- |
| `BookingAgent` | `ClientSimpleDto`     | 订舱代理                           |
| `Carrier`      | `CarrierSimpleDto`    | 船公司                             |

| `BLType`       | `int`                 | 装运方式 0整箱 1拼箱主票 2拼箱分票 |
| `POL`          | `SeaAirPortSimpleDto` | 起运港（海运港）                   |
| `POD`          | `SeaAirPortSimpleDto` | 目的港（海运港）                   |
| `POLRemark`    | `string`              | 起运港备注                         |
| `PODRemark`    | `string`              | 目的港备注                         |

**`SeaImport`（`ReportSeaImportDto`）——没有订舱代理、场站、装运方式，这三个字段在本对象里根本不存在：**

| 字段名       | 类型                  | 含义             |

| `BookingAgent` | `ClientSimpleDto`     | 订舱代理             |
| `POL`          | `SeaAirPortSimpleDto` | 起运地（**空运港**） |
| `POD`          | `SeaAirPortSimpleDto` | 目的地（**空运港**） |

**`BreakBulk`（`ReportBreakBulkDto`）——仅 `bizType=3` 件杂货时有值；没有船公司、场站、装运方式，比海运出口多一个地面代理：**

| 字段名         | 类型                  | 含义                               |
| :------------- | :-------------------- | :--------------------------------- |

### 金额

| 字段名 | 类型 | 含义 |
| :-- | :-- | :-- |
| `Currencies` | `ProfitCurrencyDto[]` | 按币别分组的原币明细 |

| `TotalUnReceived` | `decimal` | 合计未收（本位币） |
| `TotalPayable` | `decimal` | 合计应付（本位币） |
| `TotalUnPaid` | `decimal` | 合计未付（本位币） |
| `TotalProfit` | `decimal` | 合计利润 = 合计应收 − 合计应付 |
| `TotalProfitRate` | `decimal?` | 合计利润率 = 合计利润 / 合计应付，**合计应付为 0 时返回 null** |

**`ProfitCurrencyDto`（原币，不折算）：**

| 字段名       | 类型                | 含义               |
| :----------- | :------------------ | :----------------- |
| `Currency`   | `CurrencySimpleDto` | 币别               |
| `Receivable` | `decimal`           | 应收               |
| `UnReceived` | `decimal`           | 未收               |
| `Payable`    | `decimal`           | 应付               |
| `UnPaid`     | `decimal`           | 未付               |
| `Profit`     | `decimal`           | 利润 = 应收 − 应付 |

# 3. 欠费报表列表

**`POST /api/services/app/ReportAdmin/GetArrearsReportListAsync`**

方法名 `GetArrearsReportListAsync`，入参放 body。

## 3.1 入参 `ArrearsReportQueryDto`

**包含利润报表 2.1 节的全部字段**，另加下面这些：

| 字段名 | 类型 | 必填 | 含义 |
| :-- | :-- | :-: | :-- |
| `PaySide` | `int` | **是** | 收付类型 0收 1付。决定校验哪个权限，也决定金额字段读作应收还是应付 |
| `SettlementId` | `Guid?` |  | 结算对象id（欠谁的钱/谁欠我们的钱） |
| `SettlementStatus` | `int?` |  | 结算状态 0未结算 1部分结算 2结算完毕 |
| `PaymentApplyStatus` | `int?` |  | 付费申请状态 0未提交 1提交了部分 2已全额提交 |
| `InvoiceStatus` | `int?` |  | 开票状态 0未开票 1部分开票 2已开票 |
| `IsStatemented` | `bool?` |  | 是否对账 |
| `FeeLocked` | `bool?` |  | 是否费用锁定 |

## 3.2 出参 `ArrearsReportDto[]`

默认按超期天数倒序、业务日期倒序。

**业务信息结构与利润报表 2.2 节完全一致**——同样是 `transportOrder` 对象套 `seaExport` / `seaImport` / `airExport` / `breakBulk`，不平铺；行级同样带 `localCurrencyId` / `localCurrencyCode`。另加下面这些行级字段：

| 字段名 | 类型 | 含义 |
| :-- | :-- | :-- |
| `Settlement` | `ClientSimpleDto` | 结算对象。费用录入状态时可以为空，空结算对象的费用单独归成一组，此时返回 null |
| `FeeLocked` | `bool` | 费用锁定。不合并时更改单组取该更改单自己的，合并时取主单的——因为可能来自更改单，所以留在行级 |
| `OverdueDays` | `int` | 超期天数 = 今天 − 应结日期（舍掉小时）。**未到期是负数**。应结日期本身读 `transportOrder.settlementDate` |
| `InvoiceNos` | `string[]` | 发票号，组内去重合并 |
| `Currencies` | `ArrearsCurrencyDto[]` | 按币别分组的原币明细 |
| `TotalReceivable` | `decimal` | 合计应收/应付（本位币，币种见行级 `localCurrencyCode`） |
| `TotalReceived` | `decimal` | 合计已收/已付（本位币） |
| `TotalUnReceived` | `decimal` | 合计未收/未付（本位币） |

**`ArrearsCurrencyDto`（原币，不折算）：**

| 字段名       | 类型                | 含义        |
| :----------- | :------------------ | :---------- |
| `Currency`   | `CurrencySimpleDto` | 币别        |
| `Receivable` | `decimal`           | 应收 / 应付 |
| `Received`   | `decimal`           | 已收 / 已付 |
| `UnReceived` | `decimal`           | 未收 / 未付 |

> 收付类型 = 收 时这三个字段读作「应收/已收/未收」，= 付 时读作「应付/已付/未付」，**字段名复用同一套**，表头由前端按 `PaySide` 切换。

# 4. 海空港口合并分页列表

**`GET /api/services/app/PortCodeAdmin/GetSeaAirPortPagedListAsync`**

方法名 `GetSeaAirPortPagedListAsync`，入参走 query string。

## 4.1 入参 `SeaAirPortQueryDto`

| 字段名      | 类型     | 含义                                               |
| :---------- | :------- | :------------------------------------------------- |
| `PageIndex` | `int`    | 页码，从 1 开始，默认 1                            |
| `PageSize`  | `int`    | 每页条数，默认 10                                  |

| 2026-09-27 | `Feature` | **新增业务类型件杂货 `bizType=3`，两个报表同时生效。** 入参 `bizType` 可传 3；填了船公司 `carrierId`、场站 `yardId`、装运方式 `blType` 任一，或港口传 `isSeaPort=false`，件杂货都会被排除；订舱代理、船名、航次、海运港口可以筛件杂货。出参 `transportOrder` 新增 `breakBulk`（`ReportBreakBulkDto`：`bookingAgent`、`groundAgent`、`vessel`、`innerVoyno`、`pol`、`pod`、`polRemark`、`podRemark`），件杂货行 `transportOrder.ctns` 恒为空数组。原有字段不变 |
| 2026-08-30 | `Feature` | **两个报表的每一行新增 `localCurrencyId` / `localCurrencyCode`**（行级，与合计金额同层），取主单所属公司配置的本位币。合计字段（`totalReceivable` / `totalProfit` 等）本来就是本位币金额，以前文档写的是「本位币人民币」——**本位币现在按公司配置，不再写死人民币**，展示合计时必须配着 `localCurrencyCode` 一起显示。一次查询会跨多个公司，**不同行的本位币可能不同，不要跨行加总合计列**。另：`CurrencySimpleDto` 删除了 `defaultRate` 字段。 |
| 2026-08-19 | `Feature` | 新增利润报表、欠费报表、海空港口合并分页列表三个接口。 |
| 2026-08-25 | **利润报表的行集口径变了，前端要放开对空行的过滤。** ① 原先只统计 `Passed(2) 审核通过` 的费用，现在改为统计「非录入、非驳回」——`Submitted(1)` 也计入金额了，同一批数据的金额会比之前大。② 原先一票没有合格费用就整行不返回，现在**业务通过筛选就必定返回一行**，`currencies` 为空数组、合计全 0、`totalProfitRate` 为 `null`。不合并模式下更改单行仍只在该更改单有合格费用时才出现。详见第 2 章开头的说明。欠费报表不受影响。 |
| 2026-08-22 | **返回结构由平铺改为层级，这是破坏性变更，前端取值路径全部要改。** 原先直接挂在行上的业务字段现在统一在 `transportOrder` 下，业务类型专属字段再往下挂 `seaExport` / `seaImport` / `airExport`（按 `transportOrder.bizType` 只有一个有值）。例如：委托单位 `client` → `transportOrder.client`；主提单号 `mblNum` → `transportOrder.mblNum`；船公司 `carrier` → `transportOrder.seaExport.carrier` 或 `transportOrder.seaImport.carrier`（空运没有这个字段）；起运港 `pol` → `transportOrder.seaExport.pol` / `seaImport.pol` / `airExport.pol`。**行级只保留** `transportOrderId`、`changeOrderId`、`isOriginal`、`accountDate`、`transportOrder`，以及欠费报表的 `settlement`、`feeLocked`、`overdueDays`、`invoiceNos` 和金额部分。应结日期从行级挪到了 `transportOrder.settlementDate`。 |
| 2026-08-22 | 两个报表新增 `Keyword` 查询条件（模糊匹配主提单号或委托编号，与单独的主提单号/委托编号条件是且的关系）；输出新增 `POLRemark`、`PODRemark`（起运港/目的港备注，三种业务类型都有，各自挂在对应的业务类型对象下）。船公司 `CarrierId` 与销售/操作/客服/单证/航线/海外客服六类人员多选条件此前已存在，无需新增。 |
