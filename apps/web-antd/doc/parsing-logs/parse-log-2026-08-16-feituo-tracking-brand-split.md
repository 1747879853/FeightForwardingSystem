# 解析目标

对照 `web-antd` 现有运踪实现、品牌打包机制与新服务商后端接口文档，把产品口述需求整理为可落地的分流、预警、地图与去品牌化约定。

# 核心逻辑梳理

1. **分流：** `sjtd` × 海运出口 → 保留现有运踪（订阅、查看、`/tracking-map` 分享）；其余（含 sjtd 海进/空出、其他品牌相关业务线）→ 新服务商运踪。
2. **空运范围：** 仅空出；空进未建设。
3. **预警：** 列表主提单号前黄叹号，悬停显示原因。
4. **地图：** 海运进出口用后端下发的加密轨迹页链接；空运摘要无链接，前端按 env 拼 URL。
5. **分享白标：** 其他品牌海出分享走本系统独立页，对外不暴露服务商链接与品牌信息；sjtd 海出维持现状。
6. **用户侧零品牌：** 界面文案禁止出现服务商名；接口地址与 DTO 字段名保持原样。

# 文档偏差 / 架构洞察

- **更正此前判断：** 列表并非拿不到预警。运踪摘要（列表 + 详情都返回）已含 `hasWarning`、`warningCount`、`latestWarningCategory/Code/Time/Description`，列表叹号与悬停可直接实现；仅 `feituoTrackingWarnings`（全量明细）是详情专有。
- 海运摘要包含轨迹页链接（后端加密），空运摘要不含 → 正好对应「海运用后端链接、空运前端拼」的需求。
- 海出 / 海进 / 空出的列表与详情后端均已下发运踪字段，前端属纯展示层工作；海进此前仅有 DTO 占位。
- **新增风险点：** 后端 `errorMessage` / `trackingMessage` 等文案原文含服务商名（如订阅位数校验、暂无跟踪数据），直接透传会破坏白标，需前端清洗后展示。
- 船期 AIS 的 `VITE_GLOB_FREIGHTOWER_AIS_*` 可作为空运地图 env 配置与 URL 拼装的模板。
