# 组织机构（OrganizationUnit）文档

> 本文档汇总组织机构模块的接口说明与变更记录，供前端对接使用。服务名：`OrganizationUnitAppService` 基础路径：`/api/services/app/OrganizationUnit/` 关联文档：`文档/用户/用户api.md`

## 二、组织主表接口

### 2.1 创建组织

**接口：** `POST /api/services/app/OrganizationUnit/CreateOrganizationUnitAsync`

**请求参数：**

| 字段名 | 类型 | 必填 | 最大长度 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| parentId | long? | 否 | - | 父级组织id，null表示根级 |
| displayName | string | **是** | 128 | 组织名称 |
| isCompany | bool | 否 | - | 是否是公司，false=部门，默认false |
| localCurrencyId | long? | 否 | - | 本位币id（需为有效的Currency记录） |
| shortName | string | 否 | 64 | 组织简称 |
| enName | string | 否 | 64 | 英文名 |
| chargeUserId | long? | 否 | - | 负责人用户id（需为有效的User记录） |
| contactPhone | string | 否 | 64 | 联系电话 |
| email | string | 否 | 64 | 邮箱 |
| address | string | 否 | 64 | 办公地址 |
| webUrl | string | 否 | 128 | 官方网址 |
| enable | bool | 否 | - | 是否启用，默认true |
| unifiedSocialCreditCode | string | 否 | 128 | 统一社会信用代码/纳税人识别号 |
| invoiceAddress | string | 否 | 256 | 开票地址 |
| invoiceTel | string | 否 | 64 | 开票电话 |
| logo | AttachmentItemForItemInputDto | 否 | - | 公司 Logo；传 `{ attachmentId, displayOrder }`；清空传 `null` |

**返回：** `OrganizationUnitDto`

**业务校验：**

- `localCurrencyId` 如传值，需存在于Currency表，否则报错："本位币不存在。"
- `chargeUserId` 如传值，需存在于User表，否则报错："负责人不存在。"

**请求参数：**

| 字段名 | 类型 | 必填   | 说明   |
| :----- | :--- | :----- | :----- |
| id     | long | **是** | 组织id |

**返回：** `OrganizationUnitDto`（含 `orgBankAccounts` 银行账户数组）

### 2.4 获取组织列表

**接口：** `GET /api/services/app/OrganizationUnit/GetOrganizationUnitsAsync`

**请求参数：**

| 字段名     | 类型  | 必填 | 说明                                       |
| :--------- | :---- | :--- | :----------------------------------------- |
| isCompany  | bool? | 否   | 筛选：true=仅公司，false=仅部门，null=全部 |
| isDisabled | bool? | 否   | 筛选：true=仅禁用，false=仅启用，null=全部 |

**返回：** `OrganizationUnitDto[]`

> 说明：组织的禁用状态对应字段 `enable`（`enable=false` 即禁用）。组织选择器若只取可用组织，传 `isDisabled=false`。
>
> 其余各组织搜索/树接口（`GetOrganizationUnitsWithLevelAsync`、`GetCurrentOrganizationUnitsAsync`、`GetAllOrganizationUnitsAsync`、`GetCurrentOrganizationUnitUserAsync`、`GetAllOrganizationUnitUserAsync`、`GetOrganizationUnitsUserTreeAsync`、`GetOrganizationUnitTreeAsync`、`GetHandleCCTreeAsync`、`GetOrganizationUnitsTreeAsync`）入参统一改为 DTO 承载查询条件（`isCompany` + `isDisabled`，语义一致）。其中带用户id 的接口使用 `OrganizationUnitCurrentQueryDto`（含 `id`、`isCompany`、`isDisabled`）。
>
> 校验：新增/编辑用户分配组织时，若所选组织已禁用将报错「所选组织已被禁用，无法分配用户。」
>
> 列表接口不返回 `orgBankAccounts`，需查看银行账户请调用单独接口。

### 2.5 获取当前登录人有数据权限的公司列表

按**当前登录人的数据权限**返回其拥有权限的**分公司（公司）列表**，结果只包含公司（`isCompany=true`），**不含部门**。用于业务表单中的「所属公司」选择器等场景。

**接口：** `GET /api/services/app/OrganizationUnit/GetMyPermissionCompaniesAsync`

**权限：** 仅需登录（`[AbpAuthorize]`），无需额外功能权限。

**请求参数：** 无

**返回：** `OrganizationUnitSimpleDto[]`（按组织 `code` 升序排列）

**数据权限规则（取 `ManageType=Get` 的查询权限）：**

| 数据权限类型 | 枚举值 | 返回的公司范围 |
| :-- | :-- | :-- |
| 全部（All） | 5 | 系统内**所有公司**（不含部门） |
| 本人（My） | 0 | 仅**自己所属公司**（自动拥有，无需配置） |
| 自己部门（MyPart） | 1 | 自己部门所归属的公司（即自己所属公司） |
| 自己公司（MyCompany） | 2 | 自己所属公司 |
| 部分（ManyPart，多部门/多公司） | 4 | 所配置组织向上追溯得到的**所属公司**（部门→其所属公司；公司→自身） |
| 人员（ManyUser，多人） | 3 | 所配置人员的**所属公司** |

**逻辑说明：**

1. 命中 `All`（全部权限）时，直接返回所有 `isCompany=true` 的组织。
2. 非全部时，先并入**当前登录人自己所属公司**（本人权限自动拥有），再根据各权限项累加：
   - `ManyPart`：把每个配置的组织 id 向上追溯到最近的公司节点（自身即公司则取自身）；
   - `ManyUser`：把每个配置的人员映射到其所属公司（每条组织链取最靠近叶子的公司节点）。
3. 结果按公司 id 去重后返回。

**返回示例：**

```json
[
  {
    "id": 5,
    "name": "上海分公司",
    "localCurrencyId": 1,
    "localCurrencyCode": "CNY"
  },
  {
    "id": 8,
    "name": "青岛分公司",
    "localCurrencyId": 1,
    "localCurrencyCode": "CNY"
  }
]
```

**接口：** `GET /api/services/app/OrganizationUnit/GetOrgBankAccountAsync?Id={id}`

| :----- | :--- | :----- | :--------- |
| id     | guid | **是** | 银行账户id |

**返回：** `OrgBankAccountDto`

### 3.3 创建银行账户

**接口：** `POST /api/services/app/OrganizationUnit/CreateOrgBankAccountAsync`

**请求参数：**

| 字段名 | 类型 | 必填 | 最大长度 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| organizationUnitId | long | **是** | - | 所属组织id |
| currencyId | long | **是** | - | 账户币种id（需为有效的Currency记录） |
| accountName | string | 否 | 256 | 账户名称 |
| bankShortName | string | **是** | 32 | 开户银行简称 |
| bankName | string | **是** | 128 | 开户银行全称 |
| bankAddress | string | 否 | 128 | 开户银行地址 |
| bankAccount | string | **是** | 128 | 银行账号 |
| swiftCode | string | 否 | 128 | SwiftCode |
| default | bool | 否 | - | 是否默认，默认false |
| enable | bool | 否 | - | 是否启用，默认true |
| sortId | int | 否 | - | 排序号，默认0 |
| remark | string | 否 | 1024 | 备注 |

**返回：** `OrgBankAccountDto`

**业务校验：**

- `currencyId` 必须存在于Currency表，否则报错："币别不存在。"
- 同一 `organizationUnitId` 下 `bankAccount` 不可重复，否则报错："同一组织下银行账号已存在。"
- 若 `default=true`，同一 `organizationUnitId` + `currencyId` 下已有默认账户则报错："同一组织同一币种下已存在默认账户。"

## 四、组织成员相关接口

### 4.1 获取不在指定组织的用户分页列表（为添加组织成员查找用户）

在**组织机构管理**中，向某个组织添加成员时，需要先从候选用户中挑选**尚未归属该组织**的用户。

本接口用于分页查询**不在指定组织**的用户列表（即在 `UserOrganizationUnit` 关联表中不存在该 `organizationUnitId` 记录的用户），常用于组织成员添加弹窗中的用户选择器。

**与 `FindUserPagedListForOuAsync` 的区别：**

| 接口 | 筛选范围 | 典型用途 |
| :-- | :-- | :-- |
| `GetUserPagingListForOuAsync` | **返回不在指定组织的用户**（需传 `organizationUnitId`） | 向组织添加成员时，排除已在本组织的用户 |
| `FindUserPagedListForOuAsync` | 返回**全部用户**（可按关键字/角色/启用状态过滤） | 查找用户，不排除已有组织的用户 |

**接口：** `GET /api/services/app/OrganizationUnit/GetUserPagingListForOuAsync`

**权限：** 需登录（`OrganizationUnitAppService` 类级别 `[AbpAuthorize]`）

**请求方式：** `GET`（Query String 传参）

**入参模型：** `UsersForOuPagingQueryDto`（继承 `Paging`）

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| organizationUnitId | long | 是 | — | 当前组织 Id，用于排除已在该组织的用户 |
| pageIndex | int | 否 | 1 | 当前页码，从 1 开始 |
| pageSize | int | 否 | 10 | 每页条数，范围 1～1000 |
| keyWords | string | 否 | null | 关键字，模糊匹配用户**邮箱**、**昵称** |

**筛选逻辑：**

1. 传入 `organizationUnitId`，排除已在该组织中的用户，返回其余用户。
2. 传入 `keyWords` 时，额外按邮箱、昵称模糊过滤。
3. 结果按**昵称**（`NickName`）升序排列。

**返回模型：** `PagingList<NameValueDto>`

| 字段名     | 类型           | 说明                                          |
| :--------- | :------------- | :-------------------------------------------- |
| items      | NameValueDto[] | 当前页数据列表                                |
| totalCount | int            | 符合条件的总记录数                            |
| pageIndex  | int            | 当前页码                                      |
| pageSize   | int            | 每页条数                                      |
| totalPages | int            | 总页数（只读，由 totalCount / pageSize 计算） |

**列表项字段（NameValueDto）：**

| 字段名 | 类型   | 说明                           |
| :----- | :----- | :----------------------------- |
| name   | string | 展示名称，格式：`昵称(用户名)` |
| value  | string | 用户 Id（long 转字符串）       |

> `name` 由后端拼接：`{SafeNickName}({UserName})`。`SafeNickName` 在用户不存在时返回「佚名」。

**请求示例：**

```
GET /api/services/app/OrganizationUnit/GetUserPagingListForOuAsync?organizationUnitId=100&pageIndex=1&pageSize=10
GET /api/services/app/OrganizationUnit/GetUserPagingListForOuAsync?organizationUnitId=100&pageIndex=1&pageSize=20&keyWords=张三
```

**返回示例：**

```json
{
  "items": [
    {
      "name": "张三(zhangsan)",
      "value": "1001"
    },
    {
      "name": "李四(lisi)",
      "value": "1002"
    }
  ],
  "totalCount": 2,
  "pageIndex": 1,
  "pageSize": 10,
  "totalPages": 1
}
```

**前端对接说明：**

1. 下拉/穿梭框的 `label` 使用 `name`，`value` 使用 `value`（用户 Id 字符串，提交添加成员接口时需转为 `long`）。
2. 本接口仅用于**查找候选用户**；选定用户后，需再调用 `AddUserToOrganizationUnitAsync` 或 `AddUsersToOrganizationUnitAsync` 将用户加入目标组织。
3. 分页参数使用 `pageIndex`、`pageSize`，不要使用 `skipCount`。
4. `keyWords` 建议在前端输入框做防抖后再请求。
5. 返回的是「从未加入过任何组织」的用户；`UserOrganizationUnit` 表中存在任意关联即视为「有组织」，不存在关联即视为「无组织」。
6. 本接口不返回用户邮箱、手机号、角色、组织名称等扩展字段。若需要完整信息，请使用 `UserAdmin/GetUserPagedListAsync` 或 `OrganizationUnit/FindUserPagedListForOuAsync`。

## 六、错误码说明

| 错误信息 | 触发条件 |
| :-- | :-- |

| 负责人不存在。 | 创建/更新组织时 chargeUserId 无效 |

| 同一组织下银行账号已存在。 | 同一 organizationUnitId 下 bankAccount 重复 |
| 同一组织同一币种下已存在默认账户。 | 同一 organizationUnitId + currencyId 已有 default=true 的记录 |
| 所选组织不存在。 | 新增/编辑用户分配组织时组织 id 无效 |
| 所选组织已被禁用，无法分配用户。 | 新增/编辑用户时选择了已禁用的组织 |

## 七、注意事项

1. **组织列表接口**（`GetOrganizationUnitsAsync`）不返回 `orgBankAccounts` 字段，需要银行账户请调用 `GetOrganizationUnitAsync`（单条）或 `GetOrgBankAccountListAsync`。
2. `localCurrencyCode`、`chargeUserNickName`、`currencyCode` 为只读关联字段，前端提交时无需传递。
3. 银行账户的**默认**逻辑：同一组织 + 同一币种下，最多只能有一条 `default=true`。如需切换默认，请先将原默认记录更新为 `default=false`，再设置新记录。
4. `enable` 字段在创建时默认为 `true`，前端如不传则自动启用。
5. 所有接口需要登录认证（Bearer Token）。
6. 组织选择器若只取可用组织，传 `isDisabled=false`（`IsDisabled` 映射到实体 `Enable` 时需取反：`Enable == !IsDisabled.Value`）。

## 八、变更记录（2026-06-27）

> 模块：组织机构（OrganizationUnitAppService） + 用户后台（UserAdminAppService）

### 8.1 背景意图

测试反馈缺陷：**新增用户时，已被禁用的组织仍能被选择并保存。**

预期行为：

1. 禁用的组织不应被分配给用户。新增/编辑用户时若所选组织已禁用，应直接报错拦截。
2. 所有"搜索组织"的接口都应支持一个可空的"是否禁用"入参，便于前端在组织选择器中只拉取启用的组织。

> 组织的启用状态字段为 `OrganizationUnit.Enable`（`true`=启用，`false`=禁用）。本项目无 `IsDisabled` 实体字段，禁用即 `Enable == false`。

### 8.2 核心逻辑变更

**用户分配组织时校验禁用状态：**

`UserManager.AddToOrganizationUnitsDataPermissionAsync(long userId, long organizationId)` 中新增校验。该方法是新增/编辑用户统一的组织绑定入口：

- 组织不存在 → 抛 `所选组织不存在。`
- 组织已禁用（`Enable == false`）→ 抛 `所选组织已被禁用，无法分配用户。`

**组织搜索接口统一改用 DTO 承载查询条件：**

所有组织搜索接口的入参统一使用 DTO（不再使用散列的 `bool?` 参数），并把过滤条件（`IsCompany` + `IsDisabled`）都补全。

过滤语义：`IsDisabled` 为 `null` 查全部、`true` 只查禁用（`Enable==false`）、`false` 只查启用（`Enable==true`）；`IsCompany` 为 `null` 查全部、`true` 仅公司、`false` 仅部门。

DTO（位于 `Organizations/OrganizationUnitQueryDto.cs`）：

- `OrganizationUnitQueryDto`：`IsCompany`(bool?)、`IsDisabled`(bool?)
- `OrganizationUnitCurrentQueryDto : EntityDto<long>`：`Id`(long，用户id)、`IsCompany`(bool?)、`IsDisabled`(bool?)

| 接口（Async）                         | 入参 DTO                          |
| :------------------------------------ | :-------------------------------- |
| `GetOrganizationUnitsAsync`           | `OrganizationUnitQueryDto`        |
| `GetOrganizationUnitsWithLevelAsync`  | `OrganizationUnitQueryDto`        |
| `GetCurrentOrganizationUnitsAsync`    | `OrganizationUnitCurrentQueryDto` |
| `GetAllOrganizationUnitsAsync`        | `OrganizationUnitCurrentQueryDto` |
| `GetCurrentOrganizationUnitUserAsync` | `OrganizationUnitCurrentQueryDto` |
| `GetAllOrganizationUnitUserAsync`     | `OrganizationUnitQueryDto`        |
| `GetOrganizationUnitsUserTreeAsync`   | `OrganizationUnitQueryDto`        |
| `GetOrganizationUnitTreeAsync`        | `OrganizationUnitQueryDto`        |
| `GetHandleCCTreeAsync`                | `OrganizationUnitQueryDto`        |
| `GetOrganizationUnitsTreeAsync`       | `OrganizationUnitQueryDto`        |

> 带用户id的接口（`GetCurrent...`/`GetAll...`）改用 `OrganizationUnitCurrentQueryDto`，其继承 `EntityDto<long>`，`Id` 字段名保持不变，前端原有 `{ id }` 入参兼容。
>
> `GetOrganizationUnitAsync`（按 id 取单个组织详情）属于"详情"而非"搜索"，未加查询条件。

### 8.3 避坑指南

- **过滤方向易反**：`IsDisabled` 是"是否禁用"，映射到实体的 `Enable` 时需取反。前端组织选择器若只想要可用组织，传 `isDisabled=false`。
- **入参统一为 DTO**：所有组织搜索接口不再使用散列 `bool?` 参数，统一用 DTO 承载。带用户id 的接口用 `OrganizationUnitCurrentQueryDto : EntityDto<long>`，保持 `Id` 字段名以兼容旧调用。
- **`WhereIf` 命名空间区分**：
  - `IQueryable`（`GetAll()...`）的 `WhereIf` 来自 `Abp.Linq.Extensions`；
  - `IEnumerable/List`（`GetAllListAsync()` 返回值）的 `WhereIf` 来自 `Abp.Collections.Extensions`。
- **树形接口过滤后健壮性**：4 个树接口过滤后结果可能为空或出现"父节点被过滤、子节点保留"的情况。已补充防御：结果为空提前返回；挂载子节点时 `FindIndex` 为 -1 则跳过，避免数组越界崩溃。
- **校验集中在 UserManager**：组织禁用校验放在 `AddToOrganizationUnitsDataPermissionAsync`，新增、编辑用户两条路径都会被拦截，无需在每个 AppService 方法里重复写。

## 九、变更记录（2026-07-02）

> 模块：组织机构（OrganizationUnitAppService）

### 9.1 背景意图

业务表单需要一个「所属公司」下拉选择器，且下拉内容必须**受当前登录人的数据权限约束**——不同数据权限的人看到的可选公司范围不同，但该接口本身只要求登录、不挂具体功能权限。

### 9.2 核心逻辑变更

新增接口 `GetMyPermissionCompaniesAsync`（`GET`，仅 `[AbpAuthorize]`），返回 `List<OrganizationUnitSimpleDto>`（公司列表，`isCompany=true`，不含部门）。

- 复用 `UserDataPermission`（`ManageType=Get`）判定数据权限类型。
- `All` → 返回所有公司；`My/MyPart/MyCompany` → 自己所属公司；`ManyPart` → 配置组织向上追溯到的所属公司；`ManyUser` → 配置人员的所属公司。
- 组织→公司换算：`ResolveCompanyId` 用组织字典向上找最近公司节点；用户→公司换算：`GetUserCompanyIdsAsync` 复用 `GetUserOrganizationsByCacheAsync`，每条组织链取最靠近叶子的公司节点（与 `SetDataPermissionPropsAsync` 中 `Companys` 语义一致）。
- 复用 `OrganizationUnitSimpleDto`（位于 `Core/DataPermission.cs`，命名空间 `CsprojBuilder`），附带本位币信息。

### 9.3 避坑指南

- **本人权限自动拥有**：非 `All` 分支会**无条件并入当前登录人自己所属公司**（对应 `My`，无需配置），与数据权限过滤 `DataPermissionFilterAsync` 中「总是加上自己」的语义保持一致。
- **返回的是「公司」不是「所在组织」**：部门 id 会被向上折叠成其所属公司；不要直接把部门 id 当公司返回。
- **多组织/多公司**：一个用户可能属于多个组织链，逐链取公司后需去重。
- **`OrganizationUnitSimpleDto` 命名空间**：该 DTO 在 `CsprojBuilder` 根命名空间，`Organizations` 子命名空间可直接使用，无需额外 `using`。
