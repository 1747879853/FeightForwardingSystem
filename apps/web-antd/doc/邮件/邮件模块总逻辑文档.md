# 1. 业务背景说明 (Background)

**白话解释：** 系统原本只能「往外发一封新邮件」（账号激活、重置密码、登录验证码），走的是 ABP 的 `IEmailSender` + 租户邮件设置里的 SMTP 账号。业务上真正需要的是**把邮箱搬进系统里用**：报价询价、订舱确认、放单催付这些事情全在邮件里来回，业务员得能在系统里**翻邮件、看正文、下附件**，并且**对着某一封直接回复**——回过去的邮件必须落在对方邮件客户端的**同一个会话**里，否则对方看到的是一封莫名其妙的新邮件，前因后果全断。

全部能力都在 `IMailboxService` 这一个服务里，供各业务接口直接注入调用：

- **查看邮件**：邮箱文件夹列表、邮件分页列表、邮件详情（正文 + 附件清单）、附件内容。
- **发邮件**：回复（串进原会话）、转发、写新邮件、存草稿（存进邮箱服务器的草稿箱）。
- **整理邮件**：批量标记已读未读、移动、删除。
- **测试连接**：分别试登录收信、发信服务器。
- **取新邮件**：按「邮箱版本号 + 上次处理到的序号」取出某个文件夹里新到的邮件，给后台新邮件监听用。

目前的正式调用方是**个人邮箱**模块（`文档/个人邮箱/`）：每个人在个人设置里配置自己的邮箱，在系统里收发自己的邮件；后台每分钟用「取新邮件」检查每个人的收件箱，推送新邮件提醒。

**本服务不存邮件原文**：邮件、草稿都只在邮箱服务器上，服务每次实时去取、只做转手；日志和抛出的报错文案里也不写主题、正文、收件人、搜索关键字、发信服务器回执（见卡点 11）。（2026-10-02 起规则为「不存邮件原文，可以存提取出的业务数据」：调用方从邮件里提取的业务字段、需要时的附件可以存进业务单，本服务自身仍什么都不存。）

# 2. 功能与操作说明 (Features & Operations)

| 能力 | 方法 | 说明 |
| :-- | :-- | :-- |
| 发新邮件（原有，本次未改） | `IEmailer.SendEmail` | 收件人 + 主题 + 正文，账号取租户邮件设置里的 SMTP 配置 |
| 邮箱文件夹列表 | `IMailboxService.GetFolderListAsync` | 收件箱/已发送/垃圾邮件等，带邮件总数与未读数，收件箱排最前 |
| 邮件分页列表 | `IMailboxService.GetMailPagedListAsync` | 按文件夹翻页，支持关键字、只看未读、收件时间范围，最新在前，**不含正文** |
| 邮件详情 | `IMailboxService.GetMailAsync` | Html/纯文本正文、收发件人、附件清单，默认看完标记已读 |
| 附件内容 | `IMailboxService.GetMailAttachmentAsync` | 按附件序号取已解码的字节内容 |
| 回复某封邮件 | `IMailboxService.ReplyAsync` | 取原邮件 → 组装回复 → 发出 → 标记已回复 → 存已发送，一次调用走完 |
| 转发某封邮件 | `IMailboxService.ForwardAsync` | 附言 + 签名 + 转发头 + 原文，原文内嵌图片与原附件一并带上 |
| 写新邮件 | `IMailboxService.SendAsync` | 传了草稿序号时沿用草稿的回复关系与选中的旧附件，发出后删掉草稿 |
| 存草稿 | `IMailboxService.SaveDraftAsync` | 存进邮箱服务器的草稿箱；传了旧草稿序号时存好后删掉旧草稿 |
| 标记已读 / 未读 | `IMailboxService.SetReadAsync` | 同一文件夹批量，一次最多 500 封 |
| 移动邮件 | `IMailboxService.MoveAsync` | 同上 |
| 删除邮件 | `IMailboxService.DeleteAsync` | 默认移到「已删除」；本来就在「已删除」里或要求彻底删除时直接删掉 |
| 测试连接 | `IMailboxService.TestConnectionAsync` | 收信、发信各给结论，连不上不抛错 |
| 取新邮件 | `IMailboxService.GetNewMessagesAsync` | 调用方记住上次的邮箱版本号和处理到的序号，传回来取之后新到的邮件摘要，不标已读，见 3.5 |

- **收信协议：** IMAP（列文件夹、翻列表、取正文附件、改标记、移动、删除、存已发送副本、存草稿）。**发信协议：** SMTP。
- **邮箱账号来源：** 由调用方以参数传入，服务本身不存账号。个人邮箱模块把账号存在 `App_PersonalMailAccounts`（密码加密），每次调用时查出当前登录人的账号、解密后传进来。
- **收信连接复用：** 收信服务器(IMAP)的连接走连接池 `ImapConnectionPool`，同一个邮箱登录好的连接留着给后续请求用，省掉每次请求的握手和登录（这部分原来占了每个接口 0.5~1 秒）。每个邮箱最多 2 条连接，空闲 20 分钟断开，细节见卡点 14。发信服务器(SMTP)不复用，每次发信现连现断；测试连接也不走连接池，每次都用页面上填的配置新建。
- **只下载用得到的部分：** 看详情先取邮件结构；不超过 300KB 的小邮件一次整封取回，在本地拆出正文和图片（一个来回）；超过的多半带了大附件，只下载 Html 正文（没有 Html 才取纯文本）和正文里真正引用到的内嵌图片。下载附件只下那一个附件。不再为了看一封邮件把它的全部附件一起拉下来。
- **文件夹打开着就不重开：** 复用的连接上文件夹已经按够用的权限打开着，详情、下载附件、标记、移动、删除就直接用，省一个来回。邮件列表要拿最新的邮件总数，每次强制重开，并且读写打开，这样接着点进详情（要标已读）不用再开一次。

# 3. 处理流程说明 (Flow)

## 3.1 查看邮件

| 步骤 | 动作 | 失败时的表现 |
| :-- | :-- | :-- |
| 1 | 校验邮箱账号（地址格式、密码、收信服务器） | 抛业务异常，不会连服务器 |
| 2 | 从连接池借一条已登录的收信连接，没有就连 IMAP 并登录 | 区分「连不上服务器」与「账号密码(授权码)不对」两种提示；同一邮箱 2 条连接都在用时排队，排 60 秒还轮不到报「邮箱正忙，请稍后重试」 |
| 3 | 打开文件夹（不传则收件箱）。已经按够用的权限打开着就不重开；列表强制重开并读写打开。要标记已读时优先读写打开，只读权限则退回只读 | 只读时跳过标记，仅记日志 |
| 4 | 列表：**不带筛选条件**时不搜，按打开文件夹时拿到的邮件总数算出这一页的编号区间直接取摘要；**带筛选条件**时按条件搜出命中的邮件序号 → 倒序切页 → 批量取摘要 | 搜索/取摘要失败抛「查询邮件列表失败」 |
| 4' | 详情：定位序号 → 取邮件结构（信封、标记、大小、部件清单）→ 不超过 300KB 的整封取回，本地拆出正文和图片；超过的只下载 Html 正文（没有 Html 才取纯文本）和正文里引用到的内嵌图片 | 结构取不到报「找不到这封邮件」；部件取不到报「读取邮件内容失败」 |
| 4'' | 下载附件：定位序号 → 取邮件结构 → 按序号只下载那一个附件部件 | 序号越界报「刷新邮件详情后重试」 |
| 5 | 详情：把邮件标记为已读 | **失败只记日志不抛错**，正文已经取到了 |
| 6 | 归还连接（不断开）。用的过程中连接已断开就丢掉，不放回池里 | — |

## 3.2 回复邮件

| 步骤 | 动作 | 失败时的表现 |
| :-- | :-- | :-- |
| 1 | 校验账号与入参（含发信服务器、原邮件标识、正文、附件） | 抛业务异常，不会连服务器 |
| 2-3 | 连 IMAP、打开文件夹（要标记已回复所以优先读写打开） | 同 3.1 |
| 4 | 定位原邮件：有序号直接取；只给了唯一标识则按 `Message-Id` 邮件头搜，命中多条取最新 | 找不到提示「原邮件可能已被移动或删除」 |
| 5 | 组装回复邮件（收件人、主题、会话头、正文、附件下载） | **在连发信服务器之前全部做完**，避免发了一半才发现附件下不来 |
| 6 | 连 SMTP 登录并发出 | 发送失败按类别提示（收件人被拒收 / 发件人被拒 / 邮件被拒收）并带状态码，**不透传服务器回执原文**（见卡点 10） |
| 7 | 把原邮件标记为「已回复」 | **失败只记日志不抛错** |
| 8 | 把回复存一份到「已发送」文件夹 | **失败只记日志不抛错** |
| 9 | 断开收信、发信服务器连接 | **失败只记日志不抛错** |

> [!IMPORTANT] **发出之后的步骤为什么不能抛错** 邮件在第 6 步已经真的发出去了。后面任何一步再抛错，调用方会以为整个发信失败而重试，结果是**同一封邮件重复发给客户**。「少一个已回复标记」远比「重复骚扰客户」便宜，所以发出之后的步骤一律吞掉异常、只记日志。转发、写新邮件同理；存草稿成功之后删旧草稿、断开连接也同理（重存会多出一封草稿）。

## 3.3 转发、写新邮件、存草稿

| 步骤 | 转发 `ForwardAsync` | 写新邮件 `SendAsync` | 存草稿 `SaveDraftAsync` |
| :-- | :-- | :-- | :-- |
| 1 校验 | 账号（含发信服务器）、定位入参、收件人至少一个、附件 | 账号（含发信服务器）、收件人至少一个、草稿序号、附件 | 账号（不要求发信服务器）、草稿序号、附件；收件人可空 |
| 2 连 IMAP | 打开原邮件所在文件夹，取回原邮件 | 传了 `DraftUid` 时找到草稿箱、读写打开、取回旧草稿 | 找到草稿箱（找不到报错）；传了 `DraftUid` 时读写打开、取回旧草稿 |
| 3 组装 | 主题默认 `Fw: 原主题`；正文 = 附言 + logo 签名 + 转发头 + 原文；原文内嵌图片按原 cid 带上；默认带原附件 | 收件人去重；会话头取 `InReplyToMessageId`，没传则沿用旧草稿的；正文 + logo 签名；旧草稿里勾选保留的附件 + 新附件 | 同写新邮件，但**不加 logo**（真正发出时才加，否则会叠两个） |
| 4 | 连 SMTP 发出 | 连 SMTP 发出 | 以「已读 + 草稿」标记追加进草稿箱，取回新序号 |
| 5 收尾（失败只记日志） | 存已发送、断开 | 存已发送、删旧草稿、断开 | 删旧草稿、断开 |

组装阶段（收件人解析、附件下载、旧附件序号校验）全部在连发信服务器之前做完，避免发了一半才发现附件下不来。

## 3.4 整理邮件

`SetReadAsync`、`MoveAsync`、`DeleteAsync` 都是「同一个文件夹里的若干封」：

| 步骤 | 动作 | 失败时的表现 |
| :-- | :-- | :-- |
| 1 | 校验账号；序号集合非空、不含 0、不超过 500 | 抛业务异常 |
| 2 | 读写打开文件夹 | **只拿到只读权限时直接报错**——整理本身就是要改邮箱，不能像「标记已读」那样静默跳过 |
| 3 | 标记已读未读：增删已读标记。移动：目标文件夹不能是自己。删除：找「已删除」文件夹，判断移入还是彻底删除 | 找不到目标文件夹、找不到「已删除」又没要求彻底删除时报错 |
| 4 | 执行 | 报「邮件可能已被移动或删除，请刷新列表后重试」 |

彻底删除 = 打删除标记 + 只清除这几封（`UID EXPUNGE`）。服务器不支持按序号清除时，MailKit 会先临时摘掉同文件夹里其他邮件的删除标记再清除，不会把别人标了删除的邮件一起清掉。

## 3.5 取新邮件

`GetNewMessagesAsync` 本身不存进度，进度由调用方记（个人邮箱记在 `App_PersonalMailWatchStates`），每次传回来：

| 步骤 | 动作 |
| :-- | :-- |
| 1 | 校验账号，从连接池借连接，只读打开文件夹（不标已读，不改邮箱里任何东西） |
| 2 | 调用方没传邮箱版本号(`UidValidity`)，或和文件夹当前的不一致：**只建立起点**——取出当前最大序号返回，`IsBaseline = true`，不返回邮件 |
| 3 | 版本号一致：搜出序号大于 `LastUid` 的邮件（一个来回），从小到大排，只取前 `MaxCount` 封的摘要（一个来回） |
| 4 | 返回 `LastUid` = 这次取到的最后一封的序号，`NewCount` = 实际新到的总数。`NewCount` 比返回的封数多时，调用方下次接着取剩下的 |

- **为什么要版本号**：IMAP 的序号只在「文件夹版本号不变」时有意义，邮箱被服务商重建、文件夹被删了重建后序号会重新从小开始编，拿旧的 `LastUid` 比会把所有邮件都当旧的或都当新的。版本号一变就重新建立起点。
- **为什么搜完还要再筛一次**：按 RFC 3501，「序号 N:_」在文件夹里最大的序号小于 N 时，`_`取的是最大的那个序号， 服务器会把最后一封旧邮件也返回来，所以结果里再筛一遍「大于`LastUid`」。
- **第一次不提醒**：建立起点时只记最大序号，已有的邮件不当新邮件，避免一上线把几百封旧邮件都推一遍。

# 4. 核心字段说明 (Field Definitions)

## 4.1 邮箱账号配置 `MailAccountConfig`（收、发、回复共用）

| 字段名 | 📖 字段含义说明 | 🛡️ 校验限制 |
| :-- | :-- | :-- |
| **EmailAddress** | 邮箱地址，同时作为回复邮件的发件人地址 | **必填**，须是合法邮箱格式 |
| **DisplayName** | 发件人显示名称 | 选填，不填时用邮箱地址 |
| **UserName** | 登录用户名 | 选填，不填时用邮箱地址 |
| **Password** | 登录密码。多数邮箱要求填**客户端授权码**而不是网页登录密码 | **必填** |
| **ImapHost** | 收信服务器地址，例如 `imap.163.com` | **必填** |
| **ImapPort** | 收信端口 | 默认 `993`（加密），不加密一般 `143` |
| **ImapEnableSsl** | 收信是否启用 SSL | 默认 `true`。`true` 走 SslOnConnect，`false` 走 StartTls |
| **SmtpHost** | 发信服务器地址，例如 `smtp.163.com` | **回复时必填**，只查看邮件时可不填 |
| **SmtpPort** | 发信端口 | 默认 `465`（SSL），STARTTLS 一般 `587` |
| **SmtpEnableSsl** | 发信是否启用 SSL | 默认 `true` |

## 4.2 邮件列表查询入参 `MailQueryInput`

| 字段名 | 📖 字段含义说明 | 🛡️ 校验限制 |
| :-- | :-- | :-- |
| **FolderName** | 要看哪个文件夹，传文件夹**全名**（`MailFolderSummary.FullName`） | 选填，不填默认收件箱 |
| **Keyword** | 关键字，按**主题或发件人**模糊匹配 | 选填 |
| **UnreadOnly** | 只看未读 | 默认 `false` |
| **StartDate** | 收件时间起，**含当天** | 选填 |
| **EndDate** | 收件时间止，**含当天** | 选填 |
| **PageIndex** | 当前页码 | 默认 `1` |
| **PageSize** | 每页条数 | 默认 `10` |

## 4.3 定位某封邮件的入参

`MailLocateInput` 是公共基类，「看详情」和「取附件」各自在它上面加一个字段。

| 字段名 | 📖 字段含义说明 | 🛡️ 校验限制 |
| :-- | :-- | :-- |
| **FolderName** | 邮件所在文件夹全名 | 选填，不填默认收件箱 |
| **Uid** | 邮件在该文件夹里的序号（IMAP UID），取自列表 | 与 `MessageId` **至少填一个**，都填时优先用它 |
| **MessageId** | 邮件的全局唯一标识（`Message-Id` 邮件头），带不带尖括号都行 | 同上 |
| **MarkAsRead**（仅 `MailDetailInput`） | 看完是否标记已读。打开草稿编辑时应传 `false` | 默认 `true` |
| **EmbedInlineImages**（仅 `MailDetailInput`） | 是否把 Html 正文里的内嵌图片（`cid:xxx`）直接换成 data URI | 默认 `true`。不换的话前端拿不到图（img 标签带不上登录凭证去调附件接口） |
| **AttachmentIndex**（仅 `MailAttachmentQueryInput`） | 要取第几个附件，传详情里附件的 `Index` | 越界报「找不到指定的附件」 |

## 4.4 邮件摘要 `MailSummary`（列表行）

| 字段名 | 📖 字段含义说明 |
| :-- | :-- |
| **Uid** | 邮件序号，**看详情、取附件、回复都靠它**。只在 `FolderName` 这个文件夹里有效 |
| **FolderName** | 邮件所在的文件夹全名，配 `Uid` 一起用才能定位到这封 |
| **MessageId** | 邮件的全局唯一标识 |
| **Subject** | 主题 |
| **From** | 发件人，嵌套对象，见 4.7 |
| **To** / **Cc** | 收件人 / 抄送人，嵌套对象数组 |
| **Date** | 发件时间（本地时间）。邮件头里没有时退回服务器收件时间 |
| **IsRead** | 是否已读 |
| **IsAnswered** | 是否已回复过（回复成功后由系统打上的标记） |
| **HasAttachment** | 是否带附件 |
| **Size** | 邮件大小（字节） |

## 4.5 邮件详情 `MailDetail`（继承 `MailSummary`，多出以下字段）

| 字段名 | 📖 字段含义说明 |
| :-- | :-- |
| **ReplyTo** | 对方指定的回复地址，为空则回复给发件人。邮件没写 Reply-To 时服务器会按发件人填，和发件人完全一样时返回空 |
| **Bcc** | 密送人。只有草稿和已发送里的副本才有，收到的邮件永远为空 |
| **HtmlBody** | Html 正文，原邮件是纯文本时为空。`EmbedInlineImages = true` 时内嵌图片已换成 data URI |
| **TextBody** | 纯文本正文，**只在邮件没有 Html 正文时返回**；有 Html 时为空，按 Html 显示即可（2026-10-02 起） |
| **Attachments** | 附件清单，**含正文里的内嵌图片**，见 4.6 |

`HasAttachment` 在详情里按「除内嵌图片外还有没有真附件」算，和列表口径一致。

## 4.6 附件 `MailAttachmentSummary` / `MailAttachmentContent`

| 字段名 | 📖 字段含义说明 |
| :-- | :-- |
| **Index** | 附件序号，取附件内容时传它 |

# 5. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **卡点 1：回复必须串进同一个会话** 回复邮件会写入 `In-Reply-To` 与 `References` 两个邮件头（取自原邮件的 `Message-Id` 及其引用链）。缺了这两个头，对方邮件客户端会把回复当成一封孤立的新邮件，业务上就断了上下文。原邮件本身没有 `Message-Id` 时（极少见的非规范邮件）这两个头写不了，只能退化成新邮件。

> [!IMPORTANT] **卡点 2：邮件序号 `Uid` 只在同一个文件夹里有意义** `Uid` 是「这封邮件在这个文件夹里的编号」，换文件夹就不是同一封。所以传 `Uid` 时**必须连 `FolderName` 一起传**，列表给的是哪个文件夹的，看详情/取附件/回复就传哪个。邮件被用户在邮件客户端里移动过之后 `Uid` 会失效，这时用 `MessageId`（全局唯一、跨文件夹有效）更稳，代价是要在服务器上搜一次。

> [!IMPORTANT] **卡点 3：分页分两种走法**
>
> - **不带任何筛选条件**（关键字、只看未读、时间范围都没给）：不搜。打开文件夹时服务器会给出最新的邮件总数，邮件按到达先后编号、最新的编号最大，直接算出这一页是第几封到第几封按编号取。一个来回，和收件箱有多少封无关。列表一律强制重开文件夹（`OpenFolderAsync(…, forceReopen: true)`），MailKit 的打开每次都会真的发打开命令（4.7.1.1 和 4.18.1 源码都确认过，它自己没有「已经打开就跳过」），所以总数一定是最新的，不会漏掉新到的邮件。其他操作会跳过重开，**按总数分页的地方不能去掉 forceReopen**，否则复用连接上的总数可能是旧的。
> - **带筛选条件**：邮箱服务器的搜索命令只能返回命中的全部邮件序号，不支持按页取，只能全量拿回再在内存里切页。 `TotalCount` 是准的，但每次翻页都会把命中序号全取回来一遍，几万封的邮箱里条件尽量给窄一些。正文不在列表里返回也是这个原因：取正文要按封单独下载正文部件，一页十封就是十几次往返。

> [!IMPORTANT] **卡点 4：发出去的邮件(回复、转发、写新邮件)自动带公司 logo，只对 Html 正文生效，草稿不带** logo 取**本地文件**：路径常量 `MailboxService.LogoFilePath`，当前是 `document/20260612/jiayuelogo.png`，相对于附件存储根目录（配置 `FileServer:Local:RootPath`，即 `wwwroot\Uploads`），实际文件为 `wwwroot\Uploads\document\20260612\jiayuelogo.png`。换 logo 覆盖文件或改这行常量即可，留空则不带。显示宽度在 `MailboxService.LogoWidth`（默认 300px，高度按原图比例自适应）。
>
> 实现上是**内嵌图片**（`cid`）而不是外链 `<img src="http...">`——外链图片被绝大多数邮件客户端默认拦掉，收件人看到的是占位框还得手动点「显示图片」。位置在正文之后、引用原文之前。
>
> **`isBodyHtml = false` 的邮件不带 logo**：纯文本正文放不了图片。**存草稿不带 logo**：logo 在真正发出时才加，否则草稿再发出去会叠两个。文件读不到（不存在、权限不足）时本次发信不带 logo 并记一条 Warn 日志， **绝不会因为 logo 拿不到而让邮件发不出去**。字节不做缓存：本地读几十 KB 开销可忽略，换 logo 覆盖文件立刻生效，不用重启。

> [!IMPORTANT] **卡点 5：发给服务器的邮件序号集合必须升序** 列表要「最新在前」，但**不能**把倒序的序号集合直接发给服务器——腾讯企业邮这类邮箱会回 `BAD ... UID parameters!`，表现是「读取邮件列表失败」。所以取摘要时统一用 `UniqueIdSet(uids, SortOrder.Ascending)` 升序发出（顺带把连号压成 `3:12` 区间，命令更短、不容易撞命令长度限制），**显示顺序由拿到结果后再排**。同理，单封邮件的序号也走 `UniqueIdSet` 包一层，不要直接传数组。

> [!IMPORTANT] **卡点 6：序号不存在时部分邮箱回 BAD 而不是空结果** 标准做法是 FETCH 一个不存在的序号返回空结果，腾讯企业邮直接回 `BAD`。代码把这种回应统一翻译成「邮箱里没有序号为 N 的邮件」，所以**序号必须取自邮件列表接口**，而且要和 `FolderName` 成对使用——拿收件箱的序号去查「已发送」同样会报这个。序号传 0 会在入口就被挡掉（IMAP 序号从 1 起）。

> [!IMPORTANT] **卡点 7：附件序号 `Index` 跟着邮件结构走，不是稳定 ID** `Index` 是按邮件内部结构顺序编的号，所以**必须先拿详情再按它取附件**，不要把 `Index` 存下来隔很久再用。取附件时越界会提示「刷新邮件详情后重试」。
>
> 序号在两个地方数，**数法必须完全一致**：
>
> - 详情的附件清单、下载附件：在邮件结构(BODYSTRUCTURE)上数，`EnumerateAttachmentParts`，不用下载整封邮件；
> - 保留草稿附件(`KeepDraftAttachmentIndexes`)、转发带原附件：在下载下来的整封邮件上数，`EnumerateAttachments`。
>
> 两边都是「深度优先列出叶子部件、不进入附件里那封邮件的内部」，再按「转发进来的邮件 / 以附件方式挂的 / 带文件名的」过滤。结构那边是自己写的遍历，没用 MailKit 的 `IMessageSummary.BodyParts`——它会不会进入附件里那封邮件文档没写清，口径一旦和 MimeKit 的 `BodyParts` 不同，详情给的序号拿去保留草稿附件就会挂错文件。**改任何一边都要同步改另一边。**

> [!IMPORTANT] **卡点 8：内嵌图片也在附件清单里** 正文里的图片在邮件结构里同样是「部件」，会以 `IsInline = true` 出现在 `Attachments` 里。前端的附件列表要**过滤掉 `IsInline`**，否则一封带签名图的邮件会莫名多出两三个「附件」。正文里的图默认已由详情接口换成 data URI（`EmbedInlineImages`），前端直接渲染 `HtmlBody` 即可。
>
> `IsInline` 只认「有 Content-Id、不是以附件方式挂的、类型是图片」。不能只看「不是附件」：有的客户端发 PDF 不写 `Content-Disposition`，只看这一条会把真附件误当成内嵌图片藏掉。
>
> 回复（引用原文时）和转发会把原文的内嵌图片按原 Content-Id 一起带上，引用的原文不会裂图。

> [!IMPORTANT] **卡点 8.1：正文里粘贴的 data URI 图片发出前转成内嵌图片** 富文本编辑器里粘贴的截图是 `src="data:image/png;base64,..."`，Gmail 等网页版邮箱会直接拦掉这种图片。回复、转发、写新邮件、存草稿时，Html 正文里的 data URI 图片一律转成 cid 内嵌图片；不是合法 base64 的原样保留，不会因为一张图发不出去。草稿再打开时详情接口又把它们换回 data URI，编辑器里看到的和存之前一样。

> [!IMPORTANT] **卡点 9：「标记已读」和「标记已回复」都可能静默跳过** 有些邮箱只给只读权限，这时打开文件夹会自动退回只读，改标记的动作跳过并记日志，**不报错**。表现是「看过的邮件下次还是未读」。判断依据在日志里（`邮件文件夹只有只读权限`）。

> [!IMPORTANT] **卡点 10：报错文案里不出现邮箱服务商细节，也不出现邮件内容** 对外只说业务语义（连不上收信服务器 / 账号或授权码不对 / 邮件找不到 / 附件下载失败），服务器地址、端口、账号、异常原文一律只进日志。
>
> **发送失败也不透传服务器回执原文**：回执里常带收件人地址，而 ABP 会把 `UserFriendlyException` 按 WARN 记进日志文件，透传等于把邮件信息写进日志。改为按 `SmtpCommandException.ErrorCode` 给类别提示并附状态码：收件人被拒收 / 发件人被拒 / 邮件被拒收（附件过大、频率超限、被判垃圾）/ 其他异常状态。地址格式错误同理只提示「收件人里第 N 个邮箱地址格式不正确」，不回显地址本身。
>
> **账号或授权码不对**时（收信、发信都一样）抛的 `UserFriendlyException` 带错误码 `MailboxService.AuthenticationFailedCode`（40101），后台调用方按这个码区分「授权码错了」和「网络不通」：新邮件监听授权码连续错就暂停，免得反复登录被邮箱服务商锁号。

> [!IMPORTANT] **卡点 11：本服务不留存任何邮件内容** 邮件和草稿都只在邮箱服务器上，本服务每次实时去取，不缓存文件夹、不落库、不落盘。调用方可以存从邮件里提取的业务数据（规则「不存邮件原文，可以存提取出的业务数据」），但不能把邮件原文存下来。日志里不写主题、正文、收件人、搜索关键字、发信回执（只写文件夹、序号、Message-Id、错误类别这些排查用的技术信息）；报错文案同理，见卡点 10。调用方的 AppService 要加 `[DisableAuditing]`，否则 ABP 审计会把入参整个记进 `AbpAuditLogs`。

> [!IMPORTANT] **卡点 12：草稿箱、已发送、已删除、垃圾邮件怎么认** 各家邮箱这几个文件夹的名字不一样（163 叫「草稿箱」「已发送」，腾讯企业邮/QQ 叫 `Drafts`、`Sent Messages`、`Deleted Messages`）。按顺序认：
>
> 1. 服务器声明了用途（SPECIAL-USE / XLIST 扩展），MailKit 登录时已认好，最准；
> 2. 文件夹列表里自带用途标记的；
> 3. 按常见默认名（`MailboxService` 顶部的 `DraftsFolderNames` / `SentFolderNames` / `TrashFolderNames` / `JunkFolderNames`，不区分大小写）。
>
> 都认不出时：存草稿报「找不到草稿箱」，删除（非彻底）报「找不到已删除」，存已发送副本静默跳过。遇到某家邮箱认不出，往对应名单里加名字即可。

> [!IMPORTANT] **卡点 13：存「已发送」副本可能和服务器自动保存重复** 部分邮箱（如 Gmail、开启了「SMTP 发信保存到已发送」的 QQ/腾讯企业邮）会自己把 SMTP 发出的邮件存进已发送，再加上本服务追加的副本就是两封。遇到这种邮箱时调用方把 `AppendToSentFolder` 传 `false`。

> [!IMPORTANT] **卡点 14：收信连接池 `ImapConnectionPool`**
>
> - **只在内存里**，不落盘，也不缓存任何邮件内容；程序重启就清空。多台服务器各有各的池，互不影响。
> - **每个邮箱最多 2 条连接**（`MaxConnectionsPerAccount`）。邮箱服务器对单账号并发连接数有限制，不要调大。同一个邮箱同时来的请求超过 2 个就排队，一条连接同一时刻只给一个请求用（`ImapClient` 不是线程安全的）；排队 60 秒还没轮到报「邮箱正忙，请稍后重试」——一般是有个大附件邮件在发。
> - **空闲 20 分钟断开**，由定时器每 30 秒清一次。原来是 2 分钟，但业务员看一封邮件常常好几分钟，超过就得重连，服务器实测重连 + 登录要多 300~500ms；邮箱服务器一般空闲 30 分钟以上才断开，取 20 分钟留出余量。空闲超过 90 秒的连接借出前先发 NOOP 确认还活着，不通就丢掉重连，免得借出一条已被邮箱服务器断开的连接；90 秒以内不探，省一个来回。个人邮箱解密后的密码缓存滑动过期时间与此保持一致（20 分钟），改一边要同步改另一边。
> - **用的过程中出了网络或协议错误**，MailKit 会自己断开这条连接，归还时发现已断开就丢掉，不放回池里，下个请求重新连。
> - **池的键**由服务器、端口、加密方式、登录名、密码算 SHA256 摘要，不含明文密码。改了邮箱配置（包括只改密码）自然换一组新连接，旧连接没人用、20 分钟后自己断开。
> - 各方法里**只借还连接、不断开**（放在 `using` 里，Dispose 就是归还）。不要再在方法里调 `DisconnectAsync`，那样会把池里的连接断掉。
> - **文件夹列表的数量**：服务器声明支持 LIST-STATUS 时，一条命令把各文件夹的邮件数、未读数连同列表一起取回（一个来回）；不支持或这样取失败就逐个文件夹查。复用的连接上可能还开着上一次用过的文件夹，服务器一般不随列表返回它的数量，对它单独查数量也不被协议提倡，所以它单独处理：未读数搜一次（搜出全部未读序号数个数），总数用服务器随回执更新的值。后台新邮件监听让收件箱一直在复用连接上打开着，所以收件箱的未读数一直走这条路。

> [!IMPORTANT] **卡点 15：搜索不能带 `SearchOptions`（只要个数、最大序号这类）** `folder.SearchAsync(SearchOptions.Count / Max / Min, …)` 让服务器只回一个数字，但要服务器支持 ESEARCH 扩展。腾讯企业邮不支持，MailKit 4.18.1 遇到不支持的服务器**直接抛 `NotSupportedException`**，不会自己退回普通搜索。所以一律用普通的 `SearchAsync(SearchQuery)` 搜出序号再在本地数个数、取最大值：多传一些序号，但哪家邮箱都能用。

> [!IMPORTANT] **卡点 16：要支持所有邮箱，凡是 IMAP 扩展都要有不支持时的退路** 各家邮箱支持的 IMAP 扩展不一样。本服务用到的、依赖扩展的地方，不支持时的处理如下；以后加功能用到新的扩展，要在这里补一行：
>
> | 用在哪 | 依赖的扩展 | 服务器不支持时 |
> | :-- | :-- | :-- |
> | 文件夹列表一次取回数量 | LIST-STATUS | 先看服务器声明，不支持就逐个文件夹查数量 |
> | 只要个数、最大序号的搜索 | ESEARCH | 不用，一律普通搜索，见卡点 15 |
> | 认草稿箱、已发送、已删除、垃圾邮件 | SPECIAL-USE / XLIST | 按列表里的用途标记、再按常见名字认，见卡点 12 |
> | 登录后报客户端身份 | ID | 声明支持才发。**网易邮箱（163/126/yeah.net 及网易企业邮）必须发**，否则登录能过、打开任何文件夹都回「Unsafe Login」 |
> | 移动邮件 | MOVE | MailKit 自动改为复制 → 标删除 → 清除，不是原子操作，中途断线可能两边都有 |
> | 彻底删除只清选中的几封 | UIDPLUS | MailKit 先临时摘掉同文件夹其他邮件的删除标记再清除，见 3.4 |
> | 存草稿后拿到新草稿的序号 | UIDPLUS | 返回 `null`，前端刷新草稿箱列表再取 |
> | 中文关键字搜索 | 服务器支持 UTF-8 搜索 | MailKit 收到 BADCHARSET 会换字符集重试一次；不支持 UTF-8 的服务器中文关键字搜不到，但不报错 |
>
> 测试连接除了登录还会打开一次收件箱，像网易这种「登录能过、打开文件夹才被拒」的情况在测试时就能暴露。
>
> **用不了的邮箱**：只能用 OAuth 登录、不再接受密码/授权码的邮箱（如微软的 Outlook.com、Microsoft 365）本模块接不了，要另做 OAuth 授权。Gmail 要开两步验证后用「应用专用密码」。

| `IMailboxService.cs` | 服务接口，十三个对外方法：查看 `GetFolderListAsync`、`GetMailPagedListAsync`、`GetMailAsync`、`GetMailAttachmentAsync`；发信 `ReplyAsync`、`ForwardAsync`、`SendAsync`、`SaveDraftAsync`；整理 `SetReadAsync`、`MoveAsync`、`DeleteAsync`；`TestConnectionAsync`；`GetNewMessagesAsync` |
| `MailboxService.cs` | 全部实现。十三个 public 方法各自一个 region，公开常量 `AuthenticationFailedCode`，其余**全是 private**，统一收在末尾的「私有」region 里：连收信/发信服务器、认特殊文件夹、开文件夹、定位邮件、搜序号与取摘要、组装回复/写信、引用原文、logo、内嵌图片、附件、SMTP 发出、改标记、存已发送、删旧草稿等 |

| `MailboxDto.cs` | 全部模型，按「账号配置 / 查看入参 / 查看返回 / 回复入参与返回 / 写信存草稿转发 / 整理邮件 / 测试连接」分 region：`MailAccountConfig`、`MailQueryInput`、`MailLocateInput`、`MailDetailInput`、`MailAttachmentQueryInput`、`MailAddressInfo`、`MailFolderSummary`、`MailSummary`、`MailDetail`、`MailAttachmentSummary`、`MailAttachmentContent`、`MailReplyInput`、`MailAttachmentInput`、`MailReplyResult`、`MailComposeInput`、`MailSendInput`、`MailForwardInput`、`MailSendResult`、`MailDraftSaveResult`、`MailBatchInput`、`MailSetReadInput`、`MailMoveInput`、`MailDeleteInput`、`MailConnectionTestResult`、`MailNewMessagesQueryInput`、`MailNewMessagesResult` |

`MailDetailInput`、`MailAttachmentQueryInput`、`MailReplyInput`、`MailForwardInput` 都继承 `MailLocateInput`，「是哪个文件夹的哪一封」这三个字段只定义一处；`MailSetReadInput`、`MailMoveInput`、`MailDeleteInput` 继承 `MailBatchInput`。以上模型均为方法入参/返回值，不对应任何实体，所以都不挂 AutoMap（各自类上已注明原因）。

另外 `TestAppService` 上挂着一组**调试用**端点，**只为联调邮箱用，不是正式接口，正式功能不要挂在它上面**。邮箱账号写死在 `TestAppService.TestMailAccount` 这个静态属性里（腾讯企业邮），所以请求体里只有业务参数：

| `/api/services/app/Test/GetMailAsync` | POST | `MailDetailInput` |
| `/api/services/app/Test/GetMailAttachmentAsync` | POST | `MailAttachmentQueryInput` |
| `/api/services/app/Test/ReplyAsync` | POST | `MailReplyInput` |

取附件返回的 `content` 是 `byte[]`，JSON 里是 base64 字符串。换邮箱账号联调时改那个静态属性即可，**别把真实密码提交上去**。后续哪个 AppService 把它暴露成接口，就在那个模块自己的接口文档里登记接口地址与出入参，并回到本文档 7.1 补一行「调用方」。届时注意：

- 分页接口方法名要带 `PagedList` 并返回 `PagedList`（`GetMailPagedListAsync` 已符合）。
- 接口地址里的 `Async` 后缀不能省。
- 附件内容返回的是 `byte[]`，暴露成 HTTP 接口时按文件流下载返回，不要塞进 JSON。
