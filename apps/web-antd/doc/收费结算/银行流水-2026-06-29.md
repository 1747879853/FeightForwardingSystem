# 1. 背景意图 (Background)

**白话解释：** 银行流水（BankStatement）需要快速展示「这笔钱核销到什么程度了」。以前判断核销情况要实时去聚合关联的收费结算（ReceiveSettlement）明细，列表/筛选成本高。本次给银行流水表增加两个冗余字段，把核销结果直接落库，便于列表展示与按状态筛选。

- **已结算金额（SettledAmount）**：该银行流水下所有收费结算的总结算金额（收为正、付为负）。
- **核销状态（WriteOffStatus）**：待核销 / 部分核销 / 核销完成。

# 2. 核心逻辑变更 (Core Changes)

## 2.1 实体与枚举

- `BankStatement` 实体新增字段：
  - `SettledAmount`：`decimal(18,2)`，已结算金额。
  - `WriteOffStatus`：枚举 `BankStatementWriteOffStatus`，核销状态。
- 新增枚举 `BankStatementWriteOffStatus`（`CsprojBuilderEnum.cs`）：
  - `PendingWriteOff = 0` 待核销 —— 没有对应的收费结算。
  - `PartialWriteOff = 1` 部分核销 —— 收费结算总结算金额 ≠ 银行流水 `Amount`。
  - `WriteOffCompleted = 2` 核销完成 —— 收费结算总结算金额 = 银行流水 `Amount`。

## 2.2 冗余字段重算领域服务

- 新增 `IBankStatementWriteOffManager` / `BankStatementWriteOffManager`（Core 层 `App/BankStatement/`）。
- `RecalculateAsync(Guid bankStatementId)`：
  1. 先 `CurrentUnitOfWork.SaveChangesAsync()` 刷新当前事务挂起更改；
  2. 查该流水下的所有收费结算 ID；
  3. 无结算 → `SettledAmount = 0`、状态 `待核销`；
  4. 有结算 → 关联 `OrderFee.PaySide`，对「按费用」「按开票申请」两张子表分别算净额（付为负、收为正）后求和作为已结算金额；
  5. 已结算金额 == `Amount` → `核销完成`，否则 `部分核销`。

## 2.3 每次操作回写冗余字段

- `BankStatementAdminAppService`：
  - `AddAsync`：直接初始化 `SettledAmount = 0`、`WriteOffStatus = 待核销`。
  - `EditAsync`：更新后调用 `RecalculateAsync`（金额变更可能改变状态）。
- `ReceiveSettlementAdminAppService` 所有改动结算明细的接口，在事务 `CompleteAsync` 前调用 `RecalculateAsync`：
  - `AddAsync`、`AddItemsAsync`、`DeleteItemsAsync`
  - `AddByInvoiceApplicationAsync`、`AddItemsByInvoiceApplicationAsync`、`DeleteInvoiceItemsAsync`
  - `DeleteAsync`（含「无明细」分支）。

## 2.4 接口变更

- 查询输入 `BankStatementQueryDto` 新增可空筛选条件 `WriteOffStatus`（已结算金额不作为查询条件）。
- `BankStatementListDto`、`BankStatementDetailDto` 均新增返回字段 `SettledAmount`、`WriteOffStatus`（AutoMapper 自动映射）。
- `BankStatementAdminAppService.GetPagedListAsync` 与 `BankStatementAppService.GetPagedListAsync` 均加入 `WriteOffStatus` 过滤。

# 3. 避坑指南 (Pitfalls)

> [!IMPORTANT] **重算前必须刷新事务挂起更改。** 收费结算的新增/删除明细在 ABP 仓储下默认未即时落库，若不先 `SaveChangesAsync` 再聚合查询，重算会读到旧数据导致状态错误。`RecalculateAsync` 内部已统一处理，调用方只需在 `uow.CompleteAsync()` 之前调用即可（同一事务内可见）。

> [!IMPORTANT] **已结算金额是净额（收-付）。** 与收费结算列表 `TotalSettledAmount` 口径一致：付费用计负、收费用计正。判断「核销完成」时是与银行流水 `Amount` 直接相等比较，注意金额精度均为 `decimal(18,2)`。

> [!IMPORTANT] **数据库列需手动补充。** 实体新增了 `SettledAmount`、`WriteOffStatus` 两列，但本次未生成迁移文件（按要求由人工生成 / 补 SQL）。上线前务必为 `App_BankStatements` 表补齐这两列，否则查询会因列不存在而报错。存量数据可执行一次全量重算补齐冗余值。
