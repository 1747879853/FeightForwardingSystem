# 1. 背景意图 (Background)

分组统计要对齐列表侧的四个维度：付款方、我司银行、对方银行、核销状态。可空字段点选「未填写」分组后，列表要能按 Empty 条件筛回来，口径与海运出口 `CodeIssueTypeIdEmpty` 相同。

# 2. 核心逻辑变更

## 2.1 分组字段 `BankStatementGroupField`

| 值 | 含义 | 相对上一版 |
| :-- | :-- | :-- |
| 1 | 付款方 `Settlement` | 已有（注释从「结算对象」改为「付款方」） |
| 2 | 我司银行 `OrgBankAccount` | 已有（注释从「公司银行账户」改为「我司银行」） |
| 3 | 对方银行 `ClientInvoiceBank` | **新增** |
| 4 | 核销状态 `WriteOffStatus` | **新增**。`id` 为枚举 int 字符串 `0/1/2`，`name` 为待核销/部分核销/核销完成 |

核销状态名称靠 `BankStatementWriteOffStatus` 新增的 `[Description]`，分组里 `GetDescription()`。

## 2.2 列表/分组共用筛选

`BankStatementQueryDto` 新增：

- `clientInvoiceBankId`：对方银行指定值
- `clientInvoiceBankIdEmpty`：对方银行未填写，仅 `true` 生效；与 `clientInvoiceBankId` 互斥

我司银行的 `orgBankAccountId` / `orgBankAccountIdEmpty` 原本就有。付款方 `SettlementId`、核销状态 `WriteOffStatus` 实体上都不可空，**不加** Empty。

Empty 与指定 id 同时传时报 `{字段名}筛选：未填写与指定id不可同时传入`。列表、分组共用 `BuildBankStatementFilterQuery`，Admin / 非 Admin 两边都改。

点选空组后调列表：

| 空组     | 列表传参                        |
| :------- | :------------------------------ |
| 我司银行 | `orgBankAccountIdEmpty=true`    |
| 对方银行 | `clientInvoiceBankIdEmpty=true` |

# 3. 避坑指南 (Pitfalls)

> [!IMPORTANT] **付款方、核销状态没有 Empty。** 付款方新增时必填；核销状态是非空枚举，没填银行流水也会是待核销(0)。分组结果不会出现这两维的 `id=null` 空组。

> [!IMPORTANT] **Empty 只认 `true`。** `false` / 不传都不筛。不要和对应 id 一起传。

> [!IMPORTANT] **核销状态分组的 `id` 不是 Guid。** 点选后传 `writeOffStatus=0|1|2`，不要当成银行/客户 id。
