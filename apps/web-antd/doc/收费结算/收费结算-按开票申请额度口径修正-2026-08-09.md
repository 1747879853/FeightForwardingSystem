# 1. 背景意图 (Background)

`GetInvoiceApplicationGroupForSettlementAsync` / `AddByInvoiceApplicationAsync` / `AddItemsByInvoiceApplicationAsync` 误用了按费用共用池公式，扣减了开票申请占用，导致已全额开票费用的可结算余额恒为 0，列表搜不到、提交也会被拒。

# 2. 核心逻辑变更 (Core Logic)

## 2.1 正确口径

```text
remaining
= Amount
- Sum(PaymentApplicationItems.AppliedAmount)   // 付费申请
- Sum(ReceiveSettlementItems.SettledAmount)    // 按费用结算
- Sum(ReceiveSettlementInvoiceItems.SettledAmount) // 按发票结算
```

**不扣** `InvoiceApplicationItems.AppliedAmount`（开票申请占用）。

## 2.2 影响接口

| 接口 | 地址 | 说明 |
| :-- | :-- | :-- |
| 按开票申请拉可结算明细 | `GET /api/services/app/ReceiveSettlementAdmin/GetInvoiceApplicationGroupForSettlementAsync` | 过滤与 `invoiceSettleableAmount` |
| 按开票申请新建 | `POST /api/services/app/ReceiveSettlementAdmin/AddByInvoiceApplicationAsync` | 锁内额度校验 |
| 按开票申请追加 | `POST /api/services/app/ReceiveSettlementAdmin/AddItemsByInvoiceApplicationAsync` | 锁内额度校验 |

## 2.3 与按费用路径的区别

| 路径                        | 第三项扣减                                 |
| :-------------------------- | :----------------------------------------- |
| 按费用结算 / 付费申请共用池 | 开票申请占用 `InvoiceApplicationItems`     |
| 按开票申请结算              | 按发票结算 `ReceiveSettlementInvoiceItems` |

# 3. 避坑指南 (Pitfalls)

- 已开票不等于已结算；扣开票占用会把按开票申请结算整条路卡死。
- 列表过滤与提交校验必须同一口径，否则会出现“列表能选、提交报额度不足”或反过来。
