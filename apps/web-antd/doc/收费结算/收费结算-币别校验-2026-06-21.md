# 1. 背景意图 (Background)

**白话解释：** 一笔银行流水(`BankStatement`)只有一种币别(`CurrencyId`)，收费结算只能拿同币别的费用去核销。此前：

1. `GetOrderFeeGroupAsync`(按业务分组拉取可结算费用)没有按币别过滤，会把不同币别的费用一起拉出来，容易选错。
2. 新增/追加费用结算时，未校验所选费用的币别是否与银行流水币别一致，存在跨币别结算的风险。

本次：

- `GetOrderFeeGroupAsync` 新增**必填**入参 `CurrencyId`，只返回该币别的费用。
- 收费结算的**新增 / 追加费用**统一增加“费用币别必须与银行流水币别一致”的校验。

## 2.2 费用币别与银行流水币别一致校验

复用并扩展私有方法 `ValidateFeesSettlementAsync`，新增 `currencyId` 参数，在原“结算对象一致”校验基础上增加“币别一致”校验：

```csharp
private async Task ValidateFeesSettlementAsync(List<Guid> orderFeeIds, Guid settlementId, long currencyId)
{
    if (orderFeeIds == null || orderFeeIds.Count == 0) return;

    // 结算对象一致
    var settlementMismatch = await _orderFeeRepository.GetAll()
        .Where(x => orderFeeIds.Contains(x.Id) && x.SettlementId != settlementId).AnyAsync();
    if (settlementMismatch) throw new UserFriendlyException("存在费用的结算对象与银行流水的结算对象不一致");

    // 币别一致(新增)
    var currencyMismatch = await _orderFeeRepository.GetAll()
        .Where(x => orderFeeIds.Contains(x.Id) && x.CurrencyId != currencyId).AnyAsync();
    if (currencyMismatch) throw new UserFriendlyException("存在费用的币别与银行流水的币别不一致");
}
```

接入点（全部传入 `银行流水.CurrencyId`）：

| 接口                                | 说明                       |
| :---------------------------------- | :------------------------- |
| `AddAsync`                          | 按费用新增收费结算         |
| `AddItemsAsync`                     | 按费用结算追加费用明细     |
| `AddByInvoiceApplicationAsync`      | 按开票申请新增收费结算     |
| `AddItemsByInvoiceApplicationAsync` | 按开票申请结算追加开票明细 |

# 5. 避坑指南 (Pitfalls)

1. `CurrencyId` 为 `long` 值类型，`[Required]` 对其无效，故在方法内用 `<= 0` 守卫判断“必填”。
2. 校验在写入接口的“锁外预校验”阶段执行；与结算对象校验合并在同一个方法内，保证四个写入入口口径一致。
3. 银行流水币别取自 `BankStatement.CurrencyId`，费用币别取自 `OrderFee.CurrencyId`，二者均为 `long`。
