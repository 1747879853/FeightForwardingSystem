# 银行流水接口文档

**控制器**：`BankStatementAdmin` / `BankStatement`

**所有接口均需要登录认证**

---

## 一、新增银行流水（Admin）

### `POST /api/services/app/BankStatementAdmin/AddAsync`

**权限**：`Admin.BankStatement.Add`

**入参** `BankStatementAddDto`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `amount` | `decimal` | 是 | 总金额 |
| `currencyId` | `long` | 是 | 币别ID |
| `statementTime` | `DateTime` | 是 | 交易时间 |
| `transactionFee` | `decimal?` | 否 | 手续费 |
| `statementRemark` | `string` | 否 | 交易备注 |
| `remark` | `string` | 否 | 备注 |
| `orgId` | `long?` | **是** | 所属组织id（须为当前登录人直属组织） |
| `orgBankAccountId` | `Guid?` | 否 | 收款方银行ID（我司银行） |
| `settlementId` | `Guid` | 是 | 付款方ID（结算对象/客户） |
| `clientInvoiceBankId` | `Guid?` | 否 | 付款方银行ID（对方银行） |
| `message` | `string` | 否 | 留言 |
| `bankStatementUsers` | `List<BankStatementUserAddDto>` | 否 | 操作人列表 |

**`BankStatementUserAddDto`**：

| 字段          | 类型     | 说明         |
| ------------- | -------- | ------------ |
| `operationId` | `long`   | 操作人用户ID |
| `remark`      | `string` | 备注         |

**入参示例**：

```json
{
  "amount": 50000.0,
  "currencyId": 1,
  "statementTime": "2026-05-20T00:00:00",
  "transactionFee": 10.0,
  "statementRemark": "货款",
  "remark": "",
  "orgBankAccountId": "bank-guid",
  "settlementId": "client-guid",
  "clientInvoiceBankId": null,
  "message": "",
  "bankStatementUsers": [{ "operationId": 1, "remark": "" }]
}
```

**出参**：`Guid`（新建的银行流水ID）

**业务规则**：

- 校验所有外键（结算对象、币别、我司银行、对方银行、操作人用户）
- 流水号自动生成
- 操作人可选，如果不配置则所有人都能在非Admin端看到该条流水
- 新增时无关联收费结算，冗余字段初始化为：`settledAmount = 0`、`writeOffStatus = 待核销(0)`

## 二、修改银行流水（Admin）

### `PUT /api/services/app/BankStatementAdmin/EditAsync`

**权限**：`Admin.BankStatement.Edit`

**入参** `BankStatementEditDto`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `Guid` | 是 | 银行流水ID |
| `amount` | `decimal` | 是 | 总金额 |
| `currencyId` | `long` | 是 | 币别ID |
| `statementTime` | `DateTime` | 是 | 交易时间 |
| `transactionFee` | `decimal?` | 否 | 手续费 |
| `statementRemark` | `string` | 否 | 交易备注 |
| `remark` | `string` | 否 | 备注 |
| `orgId` | `long?` | **是** | 所属组织id（须为数据所属人直属组织） |
| `orgBankAccountId` | `Guid?` | 否 | 收款方银行ID |
| `settlementId` | `Guid` | 是 | 付款方ID |
| `clientInvoiceBankId` | `Guid?` | 否 | 付款方银行ID |
| `message` | `string` | 否 | 留言 |
| `bankStatementUsers` | `List<BankStatementUserAddDto>` | 否 | 操作人列表（全量替换） |

**出参**：`bool`

**业务规则**：

- 校验所有外键
- **流水下已有收费结算时，不能修改币别（`currencyId`）和付款方（`settlementId`）**，否则报「银行流水下存在收费结算,不能修改币别和付款方」（**2026-09-26 新增**）。已有收费结算的本次结算、按费用结算的汇率、按发票结算所结发票开出的币别、已结费用的结算对象，都是按当时的币别和付款方定的，改了会全部对不上。要改就先删掉这些收费结算
- 操作人列表全量替换（先删除旧的，再插入新的）
- 修改金额（`amount`）可能影响核销状态，更新后会重算 `settledAmount`、`writeOffStatus` 冗余字段；有收费结算时金额照样能改
- 修改交易时间（`statementTime`）会重算这张流水结算过的费用的最终结算时间（`OrderFee.FinalSettlementTime`）与客户超期历史，详见第十节

## 五、银行流水列表（Admin）

### `GET /api/services/app/BankStatementAdmin/GetPagedListAsync`

**权限**：`Admin.BankStatement.Get`

**入参** `BankStatementQueryDto`（Query参数）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `bankStatementNo` | `string` | 否 | 流水号（模糊） |
| `keys` | `List<string>` | 否 | 流水号列表，**精确匹配**流水号；列表内满足任意一个即可。Query 重复传参：`keys=BS20260001&keys=BS20260002`。空串/空白项忽略。本模块没有 `keyword`，`keys` 对应的是流水号 |
| `settlementId` | `Guid?` | 否 | 付款方ID（结算对象）。实体必填，无 Empty |
| `orgBankAccountId` | `Guid?` | 否 | 我司银行ID |
| `orgBankAccountIdEmpty` | `bool?` | 否 | 我司银行未填写（true=仅查 OrgBankAccountId 为空；与 `orgBankAccountId` 互斥） |
| `clientInvoiceBankId` | `Guid?` | 否 | 对方银行ID |
| `clientInvoiceBankIdEmpty` | `bool?` | 否 | 对方银行未填写（true=仅查 ClientInvoiceBankId 为空；与 `clientInvoiceBankId` 互斥） |
| `currencyId` | `long?` | 否 | 币别ID |
| `statementTimeStart` | `DateTime?` | 否 | 交易时间起 |
| `statementTimeEnd` | `DateTime?` | 否 | 交易时间止 |
| `creatorUserId` | `long?` | 否 | 创建人ID |
| `orgId` | `long?` | 否 | 组织ID（筛选：含本组织及下属组织） |
| `writeOffStatus` | `int?`（枚举） | 否 | 核销状态：0=待核销，1=部分核销，2=核销完成 |
| `pageIndex` | `int` | 是 | 当前页码（从1开始） |
| `pageSize` | `int` | 是 | 每页条数 |
| `sorting` | `string` | 否 | 排序字段 |

**出参** `PagedList<BankStatementListDto>`

银行流水主表列全部返回：`bankStatementNo`、`amount`、`currencyId`、`statementTime`、`transactionFee`、`statementRemark`、`remark`、`orgBankAccountId`、`settlementId`、`clientInvoiceBankId`、`message`、`settledAmount`、`writeOffStatus`。另有 `creatorUserName`、`creationTime`、`lastModificationTime`、`localCurrencyCode`、`orgs`（每级只有 `name`）。不返回 `userId`、`orgId`、`creatorUserId`、`lastModifierUserId`、`isDeleted`、`deleterUserId`、`deletionTime`、`localCurrencyId`，也不返回 `receiveSettlements`。详情仍返回完整组织对象和收费结算。

嵌套对象只留列表要读的字段，**不要**再取已删除的平铺名称字段：

| 业务含义 | JSON 字段 | 留下的内容 |
| --- | --- | --- |
| 付款方 | `settlement` | `name` |
| 币别 | `currency` | `code` |
| 我司银行 | `orgBankAccount` | `bankName`。`orgBankAccountId` 为空或账户不在时为 `null` |
| 对方银行 | `clientInvoiceBank` | `bankName`。`clientInvoiceBankId` 为空或银行不在时为 `null` |
| 操作人 | `bankStatementUsers` | `operationId`、`operationName` |

**不再返回** `settlementName` / `orgBankAccountName` / `clientInvoiceBankName`。银行账号、开户行全称以外的银行字段只在详情。

**业务规则**：

- 使用 `DataPermissionFilterAsync` 进行数据权限过滤
- 列表填充 `orgs` 名称串（`SetListDtoDataPermissionPropsAsync`）。详情仍用 `SetDataPermissionPropsAsync` 返回完整组织对象
- 操作人只返回 `operationId` 和 `operationName`
- 支持按 `writeOffStatus` 核销状态筛选
- 按 `orgId` 筛选时包含该组织及其所有下属组织
- 可空字段「未填写」筛选与分组统计联动：仅**我司银行、对方银行**可空。点击分组中 `id`/`name` 为 null 的「未填写」分组后，列表分别传 `orgBankAccountIdEmpty=true` 或 `clientInvoiceBankIdEmpty=true`；与对应 id 不可同时传入。付款方实体必填、核销状态枚举必有值，都不提供 Empty。

## 五.1、银行流水分组统计（Admin）

### `GET /api/services/app/BankStatementAdmin/GetGroupedListAsync`

**权限**：`Admin.BankStatement.Get`

**说明**：查询条件与列表接口 `GetPagedListAsync` **完全一致**（复用同一套筛选与数据权限），并额外指定一个 `groupField` 分组字段。先用查询条件筛出全部数据，再按指定字段分组，返回每个分组的 id、名称及数据总条数。结果按 `count` 倒序排列。

**入参** `BankStatementGroupQueryDto`（Query）：继承 `BankStatementQueryDto` 全部字段，额外：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `groupField` | `BankStatementGroupField` | 是 | 分组字段：1=付款方，2=我司银行，3=对方银行，4=核销状态 |

**出参** `List<BankStatementGroupDto>`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `string` | 分组值id（付款方/我司银行/对方银行为 Guid 字符串；核销状态为枚举 int 字符串 `0/1/2`；可空字段未填写时为 null） |
| `name` | `string` | 分组名称（见下表；可空字段未填写时为 null） |
| `count` | `int` | 该分组下的数据总条数 |

| groupField | 含义 | 分组依据 | id 来源 | name 来源 | 点选后列表传参 |
| --- | --- | --- | --- | --- | --- |
| 1 | 付款方 | `SettlementId` | Guid 字符串 | 客户简称 `Name` | `settlementId` |
| 2 | 我司银行 | `OrgBankAccountId` | Guid 字符串；空为 null | 开户银行全称 `BankName` | `orgBankAccountId`；空组传 `orgBankAccountIdEmpty=true` |
| 3 | 对方银行 | `ClientInvoiceBankId` | Guid 字符串；空为 null | 开户银行 `BankName` | `clientInvoiceBankId`；空组传 `clientInvoiceBankIdEmpty=true` |
| 4 | 核销状态 | `WriteOffStatus` | `0`/`1`/`2` | 待核销 / 部分核销 / 核销完成 | `writeOffStatus` |

## 六、银行流水下的收费结算分页列表（Admin）

### `GET /api/services/app/BankStatementAdmin/GetReceiveSettlementPagedListAsync`

**权限**：`Admin.BankStatement.Get`

**入参** `BankStatementReceiveSettlementQueryDto`（Query参数）：

| 字段              | 类型     | 必填 | 说明                |
| ----------------- | -------- | ---- | ------------------- |
| `bankStatementId` | `Guid`   | 是   | 银行流水ID          |
| `settlementNo`    | `string` | 否   | 结算单号（模糊）    |
| `pageIndex`       | `int`    | 是   | 当前页码（从1开始） |
| `pageSize`        | `int`    | 是   | 每页条数            |
| `sorting`         | `string` | 否   | 排序字段            |

**出参** `PagedList<ReceiveSettlementListDto>`（行字段见 [收费结算.md](./收费结算.md) 第八节；金额读 `actualSettled`，**2026-09-26 删除 `totalSettledAmount`**；每行另有 `originalSettledAmount`、`diffAmount`。列表不返回 `invoiceIssues`）

**业务规则**：

- 不进行 `DataPermissionFilterAsync` 过滤
- 只返回指定银行流水下的收费结算
- `originalSettledAmount`、`diffAmount`（两种类型）和按合并后「发票开出 + 费用」行数算的 `itemCount`（按发票）由 `ReceiveSettlementAdmin` 的 `FillListComputedFieldsAsync` 现算（2026-09-26），与收费结算列表同一段代码。列表不再返回发票开出简要

- 使用 `DataPermissionFilterAsync` 进行数据权限过滤
- 返回收费结算的本次结算 `actualSettled` 与明细条数 `itemCount`（**2026-09-26 删除 `totalSettledAmount`**）
- 每行另返回原始结算金额 `originalSettledAmount` 与差值 `diffAmount`（两种类型），`itemCount` 为合并后的「发票开出 + 费用」行数，均由 `FillListComputedFieldsAsync` 现算（2026-09-26）。列表不返回 `invoiceIssues`

## 十、核销状态说明（冗余字段）

银行流水新增两个冗余字段，用于快速展示与筛选核销情况，无需前端实时聚合计算。

### 字段含义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `settledAmount` | `decimal(18,2)` | 已结算金额 = 该银行流水下所有收费结算的**本次结算 `actualSettled` 之和**（银行流水币别）。**2026-09-26 起不再由明细金额相加**：按费用结算的明细是各费用自己的原币，币别不同不能直接相加 |
| `writeOffStatus` | `int`（枚举 `BankStatementWriteOffStatus`） | 核销状态 |

各收费结算的 `actualSettled` 怎么来：两种结算都由前端录入（新增、追加明细、删除明细、修改主表时传；明细删光后端恒置 0）。按发票结算在 2026-09-26 第二部分之前由后端取明细净额（收−付）自动维护，现已改为录入。口径见 [收费结算模块总逻辑文档.md](./收费结算模块总逻辑文档.md)。

### 核销状态枚举

| 枚举值 | 名称 | 含义 |
| --- | --- | --- |
| `0` | 待核销 `PendingWriteOff` | 已结算金额为 0（包括没有任何收费结算） |
| `1` | 部分核销 `PartialWriteOff` | 已结算金额 ≠ 0 且 ≠ 银行流水 `amount` |
| `2` | 核销完成 `WriteOffCompleted` | 已结算金额 = 银行流水 `amount` |

### 冗余字段维护时机

冗余字段由领域服务 `BankStatementWriteOffManager.RecalculateAsync(bankStatementId)` 统一重算回写，每次相关操作都会触发：

- **银行流水**：新增（初始化为待核销）、修改（金额变更可能改变状态）、银行流水侧删除收费结算明细（第十一、十二节）
- **收费结算（ReceiveSettlement）**：新增（按费用 / 按发票）、追加明细、删除明细、删除整单、修改主表时改了本次结算（两种类型）

> [!IMPORTANT] 重算前会调用 `CurrentUnitOfWork.SaveChangesAsync()` 刷新当前事务挂起更改，保证本次新增/删除的收费结算、改过的 `actualSettled` 在同一事务内对聚合查询可见，从而得到正确的已结算金额与核销状态。

### 交易时间与费用最终结算时间

费用表 `App_OrderFees` 上有冗余字段 `FinalSettlementTime`（最终结算时间）：费用结算完毕时，取该费用**全部**关联结算里业务时间最大的那条。走收费结算的部分，参与比较的是该结算单所属银行流水的**交易时间 `StatementTime`**（不是收费结算自己的 `SettlementTime`）。

因此修改银行流水的交易时间时，`BankStatementAdminAppService.EditAsync` 会调用 `BankStatementWriteOffManager.SyncFinalSettlementTimeAsync(bankStatementId, 旧交易时间, 新交易时间)`：把这张流水结算过的费用**整批重算**（交给 `OrderFeeSettlementManager` 按来源重新取最大值），不做筛选——时间改大可能让这张流水占上最大值，改小则可能让位给别的流水或付费结算单。

重算同时会刷新这些费用的**客户超期历史**：不再超期的记录会被删掉，超期天数变了的会改过来，口径见 [收费结算.md](./收费结算.md) 第十三之三节。

费用结算状态退回未结算 / 部分结算时（删明细、删结算单、取消核销），最终结算时间会被清空，口径见 [收费结算.md](./收费结算.md) 第十三之二节。

## 十一、删除银行流水关联的收费结算明细（Admin）

### `POST /api/services/app/BankStatementAdmin/DeleteReceiveSettlementItemsAsync`

**权限**：`Admin.BankStatement.Edit`

**入参** `BankStatementDeleteReceiveSettlementItemsDto`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `bankStatementId` | `Guid` | 是 | 银行流水ID |
| `receiveSettlements` | `List<BankStatementReceiveSettlementItemsDto>` | 是 | 要删除明细的收费结算集合 |

**`BankStatementReceiveSettlementItemsDto`**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `Guid` | 是 | 收费结算（ReceiveSettlement）ID |
| `actualSettled` | `decimal?` | 条件必填 | **2026-09-26 新增** 删除之后这张收费结算的本次结算（银行流水币别）。这张单还剩明细时必填，后端直接覆盖；明细全部删掉时可不传，后端恒置 0 |
| `receiveSettlementItemIds` | `List<Guid>` | 是 | 要删除的收费结算明细（ReceiveSettlementItem）ID列表 |

**入参示例**：

```json
{
  "bankStatementId": "bank-statement-guid",
  "receiveSettlements": [
    {
      "id": "receive-settlement-guid-1",
      "actualSettled": 850.0,
      "receiveSettlementItemIds": ["item-guid-1", "item-guid-2"]
    },
    {
      "id": "receive-settlement-guid-2",
      "receiveSettlementItemIds": ["item-guid-3"]
    }
  ]
}
```

上例第二张单假设只有 `item-guid-3` 一条明细，删光后本次结算自动归 0，所以没传 `actualSettled`。

**出参**：`bool`

**业务规则**：

- 校验银行流水存在
- 校验每条收费结算存在、且归属该银行流水、且未锁定（`Locked`）
- 校验每个明细ID确实属于对应的收费结算
- 删除后还剩明细的收费结算必须传 `actualSettled`，否则报「收费结算[xxx]的本次结算不能为空」
- 明细涉及的费用已提交销售提成时不允许删除（「已提交销售提成不可取消核销」）
- 悲观锁（`UPDLOCK,ROWLOCK`）锁定相关费用，删除明细后按费用毛额回滚 `OrderFee.SettledAmount` 与结算状态
- 每张收费结算：删除后单上不再出现的币别，其汇率行一并删除；`actualSettled` 覆盖为入参值（删光为 0）
- 事务内重算银行流水核销冗余字段（`settledAmount`、`writeOffStatus`）

## 十四、错误提示汇总

| 错误信息 | 触发条件 |
| --- | --- |
| `输入不能为空` | 入参为null |
| `结算对象不存在` | settlementId 无效 |
| `币别不存在` | currencyId 无效 |
| `我司银行不存在` | orgBankAccountId 无效 |
| `对方银行不存在` | clientInvoiceBankId 无效 |
| `操作人不存在` | operationId 无效 |
| `银行流水不存在` | 查询/修改/删除时ID无效 |
| `银行流水下存在收费结算,不能删除` | 删除时有关联的收费结算 |
| `银行流水下存在收费结算,不能修改币别和付款方` | **2026-09-26 新增** 修改时有关联的收费结算，且传入的 `currencyId` 或 `settlementId` 与原值不同 |
| `要删除的收费结算不能为空` | 删除明细时 `receiveSettlements` 为空 |
| `要删除的收费结算明细不能为空` | 传入的收费结算未提供任何明细ID |
| `部分收费结算不存在` | 传入的收费结算ID有无效项 |
| `收费结算[xxx]不属于该银行流水` | 收费结算不归属传入的银行流水 |
| `收费结算[xxx]已锁定,不能编辑` | 目标收费结算已锁定 |
| `部分明细不属于收费结算[xxx]` | 明细ID不属于对应收费结算 |
| `收费结算[xxx]的本次结算不能为空` | 删除明细后这张收费结算还剩明细，却没传 `actualSettled` |
| `已提交销售提成不可取消核销` | 要删的明细所属费用已被销售提成单引用 |
| `我司银行筛选：未填写与指定id不可同时传入` | `orgBankAccountId` 与 `orgBankAccountIdEmpty=true` 同时传入 |
| `对方银行筛选：未填写与指定id不可同时传入` | `clientInvoiceBankId` 与 `clientInvoiceBankIdEmpty=true` 同时传入 |
| `不支持的分组字段` | `groupField` 不是 1–4 |
| `当前用户不是该银行流水的操作人,无权操作` | 非Admin接口操作人权限校验不通过 |
