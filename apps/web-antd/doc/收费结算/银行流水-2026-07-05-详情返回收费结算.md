# 1. 背景意图 (Background)

**白话解释：** 银行流水详情页需要直接展示这笔流水下挂的收费结算及其明细，而不只是流水本身的字段。本次让 `BankStatementAdmin/DetailAsync` 与 `BankStatement/DetailAsync` 返回 `receiveSettlements`，结构与「收费结算详情」`ReceiveSettlementAdmin/DetailAsync` 完全一致（含明细、费用、业务单、结算总额、创建/修改人昵称）。

- **Admin 端**：返回该银行流水下的全部收费结算。
- **非 Admin 端（操作人端）**：与 Admin 一致，返回该银行流水下的全部收费结算（2026-08-06 起不再按当前用户创建人过滤）。

同时修正了核销状态的一个判定 bug（见 2.3）。

# 2. 核心逻辑变更 (Core Changes)

## 2.1 收费结算详情逻辑复用

- `ReceiveSettlementAdminAppService.DetailAsync` 的明细构建逻辑抽取为私有方法 `BuildReceiveSettlementDetailAsync(ReceiveSettlement data)`，`DetailAsync` 仅负责按 Id 加载实体后调用它。
- 新增公开方法 `GetDetailsByBankStatementAsync(Guid bankStatementId, long? creatorUserId = null)`：
  - 加载该银行流水下的收费结算（含相同 Include 关联），可空按创建人过滤；
  - 逐条调用 `BuildReceiveSettlementDetailAsync` 复用同一套映射逻辑；
  - 标注 `[RemoteService(false)]`，不对外暴露为独立 HTTP 接口，仅供内部（银行流水详情）调用。
- 该方法已加入 `IReceiveSettlementAdminAppService` 接口。

## 2.2 银行流水详情返回收费结算

- `BankStatementDetailDto` 新增字段 `ReceiveSettlements`（`List<ReceiveSettlementDetailDto>`）。
- `BankStatementAdminAppService` 与 `BankStatementAppService` 构造函数注入 `IReceiveSettlementAdminAppService`。
  - Admin / 非 Admin：`result.ReceiveSettlements = await _receiveSettlementAdminAppService.GetDetailsByBankStatementAsync(id);`（均返回全部）

## 2.3 核销状态判定修正

- `BankStatementWriteOffManager.RecalculateAsync`：已结算金额为 0 时统一判为「待核销」。
  - 修复前：有收费结算但无关联明细数据(已结算金额=0)会被误判为「部分核销」。
  - 修复后：`settledAmount == 0 → 待核销`；`== Amount → 核销完成`；否则「部分核销」。

# 3. 避坑指南 (Pitfalls)

> [!IMPORTANT] **非 Admin 详情与 Admin 一样返回全部收费结算。** 历史版本曾按 `CreatorUserId == 当前用户` 过滤，已取消；勿再按「仅本人创建」对接。

> [!IMPORTANT] **复用而非复制。** 银行流水详情里的收费结算明细完全走 `BuildReceiveSettlementDetailAsync`,与收费结算详情保持一致;后续若调整收费结算详情结构,两处会同步生效。

> [!IMPORTANT] **核销状态是落库冗余字段。** 2.3 的修正只影响之后触发重算的数据;历史脏数据需重新触发 `RecalculateAsync`(编辑流水/增删结算明细)或跑一次全量重算才会纠正。
