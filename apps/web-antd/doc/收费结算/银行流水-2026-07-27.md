# 银行流水-2026-07-27

## 1. 背景意图

为银行流水 Admin / 非Admin 列表补充分组统计能力，分组维度为结算对象（`SettlementId`）与公司银行账户（`OrgBankAccountId`），便于前端按维度聚合筛选；并补齐列表对应的「未填写」Empty 条件与公司银行账户筛选。

## 2. 核心逻辑变更

1. 新增枚举 `BankStatementGroupField`：`Settlement=1`、`OrgBankAccount=2`。
2. 新增 DTO：`BankStatementGroupQueryDto`（继承列表查询 + `groupField`）、`BankStatementGroupDto`（`id`/`name`/`count`）。
3. `BankStatementQueryDto` 新增：
   - `orgBankAccountId`
   - `orgBankAccountIdEmpty`（与 `orgBankAccountId` 互斥，查 `OrgBankAccountId` 为空）
   - **不提供** `settlementIdEmpty`（结算对象实体必填，不可能为空）
4. Admin / 非Admin 均新增 `GetGroupedListAsync`：
   - Admin：权限 `Admin.BankStatement.Get`，筛选含 `DataPermission` + `orgId`
   - 非Admin：权限 `Admin.ReceiveSettlement.Get`，筛选含操作人权限（操作人匹配或未配置操作人）
5. 列表与分组共用 `BuildBankStatementFilterQuery`；分组名称查询禁用软删除过滤器，保证已删主数据仍能显示名称。

## 3. 避坑指南

- `orgBankAccountIdEmpty` 与 `orgBankAccountId` 不可同时传入，否则报「公司银行账户筛选：未填写与指定id不可同时传入」。
- 仅公司银行账户分组可能出现 `id`/`name` 为 null 的「未填写」分组；点选后传 `orgBankAccountIdEmpty=true` 调列表。
- 结算对象必填，分组结果始终有 id/name（关联客户若已软删仍可通过禁用软删过滤器取名称）。
