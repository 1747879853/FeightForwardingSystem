# 1. 背景意图 (Background)

**白话解释：** 一条银行流水（BankStatement）下可能挂了多条收费结算（ReceiveSettlement），每条收费结算又有多条明细（ReceiveSettlementItem）。以往只能在收费结算维度逐单删除明细（`ReceiveSettlementAdmin/DeleteItemsAsync`，一次只针对一条结算单）。本次在银行流水维度新增一个批量删除接口：一次传入银行流水ID + 多条收费结算（每条含要删除的明细ID列表），跨结算单批量删除明细，删除后自动回滚费用已结算额并重算银行流水核销状态。

Admin 端与非 Admin 端（操作人端）都需要该能力，故 `BankStatementAdminAppService` 与 `BankStatementAppService` 同时新增该接口。

# 2. 核心逻辑变更 (Core Changes)

## 2.1 领域服务下沉共用逻辑

为避免在两个 AppService 重复实现「锁费用 + 删明细 + 回滚已结算额 + 重算核销」逻辑，将其下沉到既有领域服务 `IBankStatementWriteOffManager` / `BankStatementWriteOffManager`（Core 层 `App/BankStatement/`），新增方法：

```csharp
Task DeleteReceiveSettlementItemsAsync(Guid bankStatementId, Dictionary<Guid, List<Guid>> settlementItemIds);
```

该方法内部：

1. 锁外校验：结算单存在、归属传入的银行流水、未锁定（`Locked`）；每条结算单要删的明细ID非空且确实属于该结算单。
2. 按 `OrderFeeId` 汇总本次删除的已结算毛额（`settledByFee`）。
3. 开启事务（`ReadCommitted` + `IsTransactional`），用悲观锁 `SELECT ... WITH (UPDLOCK, ROWLOCK)` 锁定相关 `App_OrderFees`。
4. 逐条删除 `ReceiveSettlementItem`。
5. `RollbackSettledAmountWriteback`：按毛额回滚 `OrderFee.SettledAmount`（不小于 0）并更新 `SettlementStatus`（未结算 / 部分结算 / 已结算）。
6. 事务内调用 `RecalculateAsync(bankStatementId)` 重算银行流水 `SettledAmount`、`WriteOffStatus`。
7. `uow.CompleteAsync()` 提交。

`LockOrderFeesAsync`、`RollbackSettledAmountWriteback` 两个私有辅助方法从 `ReceiveSettlementAdminAppService` 的同名实现移植到本领域服务（逻辑一致），领域服务复用 `AbpServiceBase.UnitOfWorkManager` 开启嵌套事务，无需额外注入。

## 2.2 应用服务接口

- `IBankStatementAdminAppService` / `BankStatementAdminAppService` 新增：
  - `DeleteReceiveSettlementItemsAsync(BankStatementDeleteReceiveSettlementItemsDto input)`，权限 `Admin.BankStatement.Edit`。
- `IBankStatementAppService` / `BankStatementAppService` 新增：
  - `DeleteReceiveSettlementItemsAsync(BankStatementDeleteReceiveSettlementItemsDto input)`，权限 `Admin.ReceiveSettlement.Edit`；
  - 额外做操作人权限校验 `ValidateBankStatementOperationPermissionAsync`（该银行流水未配置操作人，或操作人包含当前用户拥有的权限用户才放行）。
  - 为此该服务构造函数新增注入 `IBankStatementWriteOffManager`。

两端应用服务都只负责入参校验与权限，把 DTO 的 `ReceiveSettlements` 按 `Id` 分组归并成 `Dictionary<Guid, List<Guid>>` 后委托领域服务执行。

## 2.3 DTO

`BankStatementDto.cs` 新增：

- `BankStatementDeleteReceiveSettlementItemsDto`：`BankStatementId`（Guid）、`ReceiveSettlements`（`List<BankStatementReceiveSettlementItemsDto>`）。
- `BankStatementReceiveSettlementItemsDto`：`Id`（收费结算ID）、`ReceiveSettlementItemIds`（`List<Guid>`）。

# 3. 避坑指南 (Pitfalls)

> [!IMPORTANT] **只删除按费用结算明细（ReceiveSettlementItem），不含开票申请明细（ReceiveSettlementInvoiceItem）。** 本接口对应的是「按费用结算」的子表；如需删除按开票申请结算的明细，走收费结算维度的 `DeleteInvoiceItemsAsync`。

> [!IMPORTANT] **回滚与重算必须在同一事务内。** 领域服务在悲观锁事务里先删明细、回滚 `OrderFee.SettledAmount`，再调用 `RecalculateAsync`；`RecalculateAsync` 内部会先 `SaveChangesAsync` 刷新挂起更改，保证聚合查询读到删除后的最新数据。

> [!IMPORTANT] **归属与锁定校验一次性完成。** 任一收费结算不存在 / 不属于该银行流水 / 已锁定，或任一明细ID不属于对应结算单，整批操作直接抛错终止，不会部分删除。
