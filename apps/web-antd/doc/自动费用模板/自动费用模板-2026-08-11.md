# 背景意图

自动费用模板明细的「单位(`Unit`)」除了 `票`/`毛重`/`尺码`/`TEU` 这几个固定值外，还可以选箱型名（`CtnCode.CtnName`，如 `20GP`/`40GP`/`40HQ`）。

原逻辑里箱型名是按本单箱子（`OrderCtn` → `CtnCode.CtnName`）匹配数量，**匹配不到就返回数量 0**，于是会生成一条数量 0、金额 0 的垃圾费用。

现实业务是：模板配了 `40HQ` 的费用，但这票海运出口/进口根本没有 `40HQ` 这个箱型，那这条费用就**不应该存在**，而不是生成一条 0 数量的空费用。空费用还会被带进费用审核、对账单口径，操作人员得手工去删。

# 核心逻辑变更

## 公共方法 `ResolveQuantityByUnit`（`CsprojBuilderAppServiceBase.cs`）

- 返回值由 `decimal` 改为 **`decimal?`**。
- `null` 的唯一含义：**单位是箱型名，但本单没有这个箱型**（`ctnNameCountMap` 里查不到），调用方必须跳过该条费用。
- 其余分支语义不变：

  | 单位           | 返回值                                      |
  | -------------- | ------------------------------------------- |
  | 空 / 空白      | `0`（不跳过，保持原行为）                   |
  | `票`           | `1`                                         |
  | `毛重`         | `TransportOrder.Kgs ?? 0`                   |
  | `尺码`         | `TransportOrder.Cbm ?? 0`                   |
  | `TEU`          | `Σ(OrderCtn 对应 CtnCode.TEU)`              |
  | 其余（箱型名） | 命中箱型返回箱子数量；**未命中返回 `null`** |

## 三个调用方统一改为「取不到箱型就 `continue`」

| 调用位置 | 场景 | 跳过后的表现 |
| :-- | :-- | :-- |
| `SeServiceTaskAdminAppService.GenerateOrderFeesByTemplateAsync` | 完成服务项按模板自动生成费用 | 该模板明细不生成 `OrderFee`，也不写 `OrderFeeTemplateItemId`（下次业务补了箱型再完成服务项时可正常生成） |
| `OrderFeeAdminAppService.ImportOrderFeesToTransportOrderAsync` | 历史费用批量引入到目标业务 | 该条费用不引入，返回的 `newIds` 里不含它 |
| `PreOrderAdminAppService`（业务联系单转海运出口） | 联系单费用带到业务 | 该条费用不生成，也不进费用审核提交列表 |

统一写法（三处一致）：

```csharp
var resolvedQuantity = ResolveQuantityByUnit(unit, transportOrder, totalTeu, ctnNameCountMap);
if (!resolvedQuantity.HasValue) continue;
var quantity = resolvedQuantity.Value;
```

# 避坑指南

- **`null` 与 `0` 必须分清**：`null` = 箱型不匹配要跳过；`0` = 单位为空或重量/体积本身是 0，仍然照常生成费用。不要用 `?? 0M` 兜底，那等于把本次改动废掉。
- **单位为空不跳过**，仍生成数量 0 的费用，保持历史行为不变（这是数据没填全，不是箱型不匹配）。
- **default 分支即箱型分支**：单位只要不是 `票`/`毛重`/`尺码`/`TEU`，就一律当箱型名处理。若前端将来放开单位自由输入，写了个不存在的箱型名（错别字、空格以外的脏值），费用会被静默跳过而不是生成 0。单位建议维持下拉选择（固定项 + 箱型基础资料）。
- **单位比对用 `Trim()` 后的原文精确匹配 `CtnCode.CtnName`**，大小写敏感。基础资料里箱型名是 `40HQ`，模板写 `40hq` 匹配不上会被跳过。
- **静默跳过、不报错**：箱型未匹配时跳过不生成。出现「模板配了但费用没生成」时，排查顺序是：箱型是否存在 → 是否被 `OrderFeeTemplateItemId` 防重拦截。汇率匹配不到会写入 `0`（不跳过），提交时再拦「汇率为0」。
- **批量引入的返回条数可能少于入参条数**：前端不能拿 `newIds.Count == input.OrderFeeIds.Count` 做成功判定。
- 数量来源是 `OrderCtn`（本单箱子），**箱型必须先录到业务的箱子信息里**，否则模板里所有箱型单位的费用都不会生成。
