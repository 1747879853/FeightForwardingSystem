# 背景意图

1. **服务项保底**：完成服务项自动生成费用时，明细 `ServiceType` 为空会回退使用主表 `ServiceType`。主表与明细均为空则无法命中，需保存前拦截。
2. **启用模板条件唯一性**：多个启用模板若匹配条件完全一致且生效时间重叠，完成服务项时会重复生成费用，需在新增/编辑时拦截。

# 核心逻辑变更

## 服务项保底校验

- `ValidateInput`：明细任意一条 `ServiceType` 为空时，主表 `ServiceType` 必填。
- 全部明细都填了服务项时，主表仍可为空。

## 启用模板条件唯一性

- `ValidateDuplicateConditionAsync`：`Enable=false` 跳过；`Enable=true` 时比对其他启用模板。
- 比对字段（含 null=null）：`BizType`、`PaySide`、`ClientId`、`TradeTermsType`、`CargoId`、`CodeFrtId`、`CodeSourceId`、`CarrierId`、`BookingAgentId`、`POLId`、`PODId`、`BLType`。
- 生效时间重叠：任一方 `Efficient=true` 视为全时间覆盖；否则按 `[StartTime, EndTime]` 闭区间（空端点该端不限）。
- 编辑时排除自身 `Id`。
- `AddAsync` / `EditAsync` / `SetEnableAsync`(启用时) 均调用。
- `SetEnableAsync` 启用时额外做**批次内两两冲突**校验，再与库中其他启用模板比对。
- `CopyAsync` **不做**该校验，复制结果强制 `Enable=false`。

# 避坑指南

- 服务项报错：`存在未配置服务项的费用明细时，主表服务项不能为空`。
- 重复条件报错：`已存在与当前模板重复条件的模板`。
- EF Core 默认按 C# 空值语义翻译可空 `==`，`null == null` 为 true，无需手写双方皆空分支。
- `OrgId`、`ServiceType` 不在条件唯一性比对范围内。
- 复制模板默认禁用，用户编辑调整后再启用，避免与源模板条件撞车。
- 禁用模板可与启用模板条件相同，互不影响。
