# 1. 背景意图 (Background)

付费审批列表原来只能看到申请单号、结算对象、金额这些单据级信息，看不出这张付费申请到底涉及哪几票业务。审核人要判断该不该批，往往得先点进详情看业务，来回切换效率低。本次把详情里已有的「按业务分组」结构搬到审批列表上，让审核人在列表页就能看到涉及的业务票。

只搬**业务简要**，不搬费用明细与金额分组：列表是一页多条付费申请，每条又挂多票业务，若把明细和币别分组一起算，查询量和响应体都会成倍膨胀，而审核人在列表阶段并不需要看到每条费用。

# 2. 核心逻辑变更 (Core Logic)

## 2.1 影响接口

| 接口 | 地址 |
| :-- | :-- |
| 付费审核任务分页列表 | `GET /api/services/app/PaymentApplicationAdmin/PayAppTaskListAsync` |

## 2.2 出参新增

| DTO | 字段 | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| `PayAppTaskItemDto` | `PayAppFeeBySeaExportGroup` | `List<PayAppFeeAndSeaExportDto>` | 该付费申请涉及的业务分组，**组内只填 `TransportOrder`** |

复用详情已有的 `PayAppFeeAndSeaExportDto`，前端拿到的结构与详情一致。组内其余三个字段本接口**一律不赋值**：

| 字段                                  | 本接口 | 详情 |
| :------------------------------------ | :----- | :--- |
| `TransportOrder`                      | 有值   | 有值 |
| `PaymentApplicationItems`             | `null` | 有值 |
| `CurrencyGroup`                       | `null` | 有值 |
| `TotalPayPrice` / `TotalReceivePrice` | `null` | 有值 |

`PayAppFeeAndSeaExportDto.PaymentApplicationItems` 的注释本来就写着「详情有 列表没有」，本次的取舍与该约定一致；新增字段的注释里也写明了哪些不给，避免后来者当成漏赋值去补。

## 2.3 实现要点

**投影补字段**：`paymentApplicationOrigins` 里 `OrderFee` 原来只取 `Id`/`CurrencyId`/`PaySide`，拿不到业务 id，本次补上 `TransportOrderId`。

**整页批量查，业务对象跨申请共享**：

```csharp
var orderIdsByApp = paymentApplicationOrigins.ToDictionary(
    x => x.Id,
    x => x.PaymentApplicationItems.Select(i => i.OrderFee.TransportOrderId).Distinct().ToList());
var taskTransportOrderIds = orderIdsByApp.SelectMany(x => x.Value).Distinct().ToList();
var taskTransportOrders = await _transportOrderRepository.GetAll().AsNoTracking()
    .Where(m => taskTransportOrderIds.Contains(m.Id))
    .ProjectTo<TransportOrderSimpleDto>(_mapperConfiguration).ToListAsync();
```

销售/操作/客服昵称同样按整页查一次，直接填在业务对象上，多条付费申请引用同一票业务时共用同一个对象。

# 3. 避坑指南 (Pitfalls)

- **不要照抄详情的按申请循环写法**。详情只处理一条付费申请，业务可以一一对应地查；审批列表一页有多条申请，同一票业务常被多条申请引用，必须先整页去重再查一次，否则就是按行查库的 N+1。
- **业务对象是跨申请共享的同一个实例**。序列化输出没问题，但如果以后要在某条申请上给 `transportOrder` 挂只属于该申请的数据（比如该申请在这票业务上的金额），不能直接改这个共享对象，否则会串到别的申请行上，届时要改成每条申请各自克隆。
- **没有调用 `SetDataPermissionPropsAsync`**，所以 `transportOrder.companys` / `organizationUnits` 为空。这与详情的 `PayAppFeeBySeaExportGroup[].transportOrder` 行为一致（详情也没调）。若审批列表要显示业务所属公司，需参照 `GetOrderFeeGroupAsync` 的做法：先给 DTO 赋 `UserId`，再批量调用填充。
- 一条付费申请的费用可能横跨多票业务，所以 `payAppFeeBySeaExportGroup` 是数组而非单值；付费申请必然挂着费用，正常不会为空数组。
