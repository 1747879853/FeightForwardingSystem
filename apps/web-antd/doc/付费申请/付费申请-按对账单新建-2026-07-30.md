# 1. 背景意图 (Background)

对账单（Statement）汇总了同一客户下的费用。业务需要一键将某张对账单下的**全部应付费用**按剩余额度生成一张**原币、录入态**付费申请，且不指定结算币别、不填银行。前端**只传对账单 Id**。

# 2. 核心逻辑变更 (Core Logic)

## 2.1 接口

`POST /api/services/app/PaymentApplicationAdmin/AddByStatementAsync`

**权限**：同时需要 `Admin.PaymentApplication.Add` 与 `Admin.Statement.Edit`

**入参** `PaymentApplicationAddByStatementDto`（仅一字段）：

| 字段          | 类型   | 说明      |
| :------------ | :----- | :-------- |
| `statementId` | `Guid` | 对账单 Id |

**后端固定生成**：

| 项 | 规则 |
| :-- | :-- |
| `settlementId` | 对账单 `clientId` |
| `currencyId` | 不填（原币） |
| `paymentApplicationBanks` | 不填 |
| `status` | 录入 |
| `orgId` | 对账单 `orgId` |
| `userId` / `applyUserId` | 对账单 `userId` |
| 明细 | 对账单下全部费用；`appliedAmount`=remaining；`rate`=null |
| 附件/发票/备注等 | 不写 |

**出参**：新建付费申请 `Guid`

## 2.2 校验

1. 对账单、结算对象存在。
2. 对账单必须带 `orgId`、`userId`，并通过 `EnsureUserOwnsOrgAsync(statement.OrgId, [statement.UserId])`。
3. 对账单须有费用；存在应收 → `存在应收费用 不可提交付费申请`。
4. 待审核费用任务、多本位币：同 `AddAsync`。
5. 锁内 `remaining = Amount - Sum(PaymentApplicationItems.AppliedAmount) - Sum(ReceiveSettlementItems.SettledAmount) - Sum(InvoiceApplicationItems.AppliedAmount)`；若 `remaining <= 0` → `存在无可申请额度的费用，不可提交付费申请`。

# 3. 避坑指南 (Pitfalls)

- 本接口不再取当前用户默认组织，组织与申请人完全继承自对账单。
- 创建后为录入态，银行/提交审核走后续编辑或提交接口。
