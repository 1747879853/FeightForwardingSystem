# 1. 背景意图 (Background)

付费申请列表接口 `PaymentApplicationAdminAppService.GetPagedListAsync`（`GET /api/services/app/PaymentApplicationAdmin/GetPagedListAsync`）需要让前端在列表每条记录上**直接展示**两类金额，无需二次拼装：

1. **申请币别及对应金额**（原币申请按原币分列；固定币别申请只展示指定结算币别一条折算合计）。
2. **已通过付费结算完成的币别及金额**（来源为付费结算模块 `PaymentSettlementAdmin` 产生的结算明细，支持多次/分次结算累计）。

原实现已能返回申请金额，但存在两点不满足需求：固定币别申请仍**按费用原币分列**展示多条，且整个接口**没有返回任何已结算金额**。

# 2. 核心逻辑变更 (Core Logic)

涉及文件：

- `src/CsprojBuilder.Application/App/PaymentApplication/PaymentApplicationAdminAppService.cs`（`GetPagedListAsync`）

复用既有 DTO 字段（`CurrencyGroupDto.SettledAmount` / `SettledPrice`、`PaymentApplicationDto.TotalSettledPrice`），未新增字段。

## 2.1 已结算金额批量查询（新增）

在组装结果前，按当前页 `paymentApplicationIds` 批量查询付费结算明细 `PaymentSettlementItem`，并在内存中聚合为两个字典：

| 字典 | 聚合维度 | 取值 | 用途 |
| :-- | :-- | :-- | :-- |
| `settledAmountByAppCurrency` | `(PaymentApplicationId, OriginalCurrencyId)` | `Sum(SettledAmount)` 原币累计 | 原币申请按原币分列已结算 |
| `settledPriceByApp` | `PaymentApplicationId` | `Sum(SettledAmount * Rate)` 折算结算币别累计 | 固定币别申请已结算合计 |

> `PaymentSettlementItem.SettledAmount` 始终为**原币金额**，`Rate` 为该次结算时原币→结算币别的快照汇率；折算金额 = `SettledAmount * Rate`。多次结算自然累计（多条明细求和）。

## 2.2 固定币别申请（`CurrencyId` 有值）

由「按 `OrderFee.CurrencyId` 分列多条」改为**只返回指定结算币别一条**：

- `Id` / `Code` = 申请头的结算币别（`PaymentApplication.CurrencyId`）。
- `PayPrice` / `ReceivePrice` = 全部付/收明细 `Sum(AppliedAmount * Rate)`，折算到结算币别后的**合计**，区分收付方向。
- `SettledPrice` = `settledPriceByApp`（未结算时为 `0`）。
- `TotalSettledPrice` = 同 `SettledPrice`；`TotalPayPrice` / `TotalReceivePrice` 同单条 Price。

## 2.3 原币申请（`CurrencyId` 为空）

保持按 `OrderFee.CurrencyId` 分列、不做汇率转换，**新增** `SettledAmount` 字段：

- `SettledAmount` = `settledAmountByAppCurrency[(申请id, 原币id)]`，即该原币**累计已结算原币金额**；某原币有申请但尚未结算时为 `0`。
- 申请金额与已结算金额在同一原币维度上一一对应。

# 3. 避坑指南 (Pitfalls)

- **固定币别申请的 `CurrencyGroup` 现在恒为 1 条**：前端不要再假设它会按费用原币分多条；多原币的折算金额已合计进这一条。
- **已结算金额数据源是结算明细，不是申请的 `UnSettledAmount`**：需求明确要求来源于 `PaymentSettlementAdmin` 的结算记录，因此直接聚合 `PaymentSettlementItem`，可天然累计多次/分次结算。
- **未结算约定为 `0` 而非 `null`**：原币的 `SettledAmount`、固定币别的 `SettledPrice` 在无结算时统一返回 `0`，前后端按此约定。
- **币别维度必须对应**：原币申请已结算按原币（`OriginalCurrencyId`）分列，与申请金额的 `OrderFee.CurrencyId` 同维度；固定币别只给结算币别一条合计，不按原币分列。
- **仅改 `GetPagedListAsync`**：付费结算选单用的 `GetPagedListForSettlementAsync` 仍保留原有「按原币分列 + 可结算上下限」逻辑，未受影响。
- **软删除已自动过滤**：`PaymentSettlementItem` 走 ABP 仓储 `GetAll()`，已删除结算明细不计入累计。
