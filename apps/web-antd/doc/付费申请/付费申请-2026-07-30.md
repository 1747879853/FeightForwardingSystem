# 1. 背景意图 (Background)

`PaymentApplicationDto` 此前列表/详情出参不一致：结算对象多用字符串 `clientName`，币别用 `currencyCode`，关联付费结算附件则平铺为 `paymentSettlementAttachments`。前端无法复用统一的客户/币别 SimpleDto，也无法按结算单维度展示附件。

本次做破坏性结构调整：**删除** `clientName`、`currencyCode`、`paymentSettlementAttachments`；**列表与详情统一**返回对象化的 `settlement`、`currency`，以及按结算单聚合的 `paymentSettlements`（内含 `attachments`）。组装展示用币别/用户昵称一律走内存缓存，不再按 id 查库。

## 2.4 组装逻辑要点

- 列表批量：`GetLinkedPaymentSettlementsMapAsync` 按本页申请 Id 查关联结算头信息（单号/时间/结算对象/币别 Id），再按结算 Id 汇总 `TotalSettledPrice`、批量拉附件挂到 `attachments`。
- 详情：`GetLinkedPaymentSettlementsAsync` 复用同一套 Map 逻辑。
- 结算对象列表侧与详情侧均投影为 `ClientSimpleDtoForOrder`（含默认地址，仍查客户表）。
- 币别有 `currencyId` 时投影为 `CurrencySimpleDto`，否则 `currency` 为 `null`。

## 2.5 币别 / 用户走缓存（展示侧）

列表、详情、关联结算、附件创建人、任务列表、可申请费用分组等**展示用**币别与用户，统一改走内存缓存，禁止再按 id 查 `Currency` / `User` 表：

| 数据 | 缓存入口 | 说明 |
| :-- | :-- | :-- |
| 币别 | `BasicDataCache.GetCurrenciesAsync()` | 缓存项含 `Code`/`Name`(中文名)/`EnName`/`DefaultRate`；组装 `CurrencySimpleDto` 时 `CnName` ← `Name` |
| 用户 | `GetUserInfoMapAsync()` / `GetCachedUserInfosByIdsAsync()` | 取 `NickName`（创建人、审核人、附件创建人、业务人员等） |

写库/校验路径（如新增时校验币别是否存在、缺失币别代码排查）仍可直查 `_currencyRepository`，与展示侧分离。

币别缓存变更：`BasicDataCacheItem` 新增 `DefaultRate`；`GetCurrenciesAsync` 回源时一并加载，保证 `CurrencySimpleDto.defaultRate` 有值。币别资料变更后仍由既有 `BasicDataCacheInvalidator` 失效。

# 3. 避坑指南 (Pitfalls)

- **破坏性变更**：前端必须改读 `settlement` / `currency` / `paymentSettlements`，旧字段已不存在，不要再兼容 `clientName`、`currencyCode`、`paymentSettlementAttachments`。
- **与 2026-07-25 文档冲突处**：当时写明「`clientName` 保留、仅详情返回 `settlement`」已作废；现以本文为准——`clientName` 已删，列表也返回 `settlement`。
- **`attachmentGroup` 仍是付费申请自身附件**（详情有、列表无）；`paymentSettlements[].attachments` 是**付费结算**附件，二者模块类型不同，勿混用。
- **原币申请**：`currencyId` 为空时 `currency` 为 `null`，金额展示仍看 `currencyGroup`。
- **无关联结算**：`paymentSettlements` 返回空数组，不是 `null`（列表组装侧保证空列表）。
- **`totalSettledPrice` 是整单金额**：一张结算单若关联多笔付费申请，各申请下看到的该结算 `totalSettledPrice` 相同，不是「仅本申请分摊」。
- **缓存一致性**：改币别默认汇率或用户昵称后，需依赖缓存失效；若本地调试看到旧汇率/旧昵称，先确认 `BasicDataCache` / `UserInfoCache` 是否已刷新。
- **勿在循环内查库翻名称**：后续维护列表接口时继续用 `BasicDataCache` / `GetUserInfoMapAsync`，不要退回 `_currencyRepository` / `_userRepository` 按批查展示名。
