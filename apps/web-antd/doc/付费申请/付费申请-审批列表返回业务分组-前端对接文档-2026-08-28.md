# 付费申请 — 审批任务列表返回业务分组（前端对接）

**变更日期**：2026-08-28  
**关联后端文档**：《付费申请-审批列表返回业务分组-2026-08-28》  
**破坏性**：否（仅新增字段）

## 接口

| 项     | 内容                                                                |
| ------ | ------------------------------------------------------------------- |
| 方法名 | `PayAppTaskListAsync`                                               |
| 路由   | `GET /api/services/app/PaymentApplicationAdmin/PayAppTaskListAsync` |
| 权限   | `Admin.PaymentApplication.Audit`                                    |
| 返回   | `PagedList<PayAppTaskItemDto>`                                      |

入参不变。

## 字段变更

| 操作 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 新增 | `payAppFeeBySeaExportGroup` | `PayAppFeeAndSeaExportDto[]` | 该行付费申请涉及的业务票列表；**组内只有 `transportOrder` 有值** |

其余出参不变。

### `payAppFeeBySeaExportGroup[]`

结构与详情接口的同名字段一致，但本接口只填业务，其余字段恒为 `null`。

| 字段 | 类型 | 本接口 | 说明 |
| --- | --- | --- | --- |
| `transportOrder` | `TransportOrderSimpleDto` | **有值** | 业务简要 |
| `paymentApplicationItems` | `PaymentApplicationItemDto[]` | `null` | 该业务下的申请明细，需要请调详情 |
| `currencyGroup` | `CurrencyGroupDto[]` | `null` | 该业务的币别分组合计，需要请调详情 |
| `totalPayPrice` | `number` | `null` | 该业务应付合计，需要请调详情 |
| `totalReceivePrice` | `number` | `null` | 该业务应收合计，需要请调详情 |

### `transportOrder`

字段口径与详情接口 `payAppFeeBySeaExportGroup[].transportOrder` **完全同源**，全量字段见《TransportOrderSimpleDto外键对象化-全量接口对接文档-2026-08-10》。列表页常用的几个：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `string(guid)` | 业务id |
| `bizType` | `number` | 业务类型（决定 `seaExport`/`seaImport`/`airExport` 哪个有值） |
| `commissionNum` | `string` | 委托编号 |
| `etd` | `string(date)` | 开船日期 |
| `saleNames` | `string[]` | 销售昵称，本接口已填充 |
| `operatorNames` | `string[]` | 操作昵称，本接口已填充 |
| `customerServiceNames` | `string[]` | 客服昵称，本接口已填充 |
| `saleNamesStr` / `operatorNamesStr` / `customerServiceNamesStr` | `string` | 上面三个的逗号拼接串，无值时为 `null`，可直接展示 |

> `companys` / `organizationUnits`（业务所属公司）本接口**不返回**，与详情行为一致。列表页若要展示业务所属公司，请提需求，后端需另行填充。

## 前端注意

1. 空数组兜底：`item.payAppFeeBySeaExportGroup ?? []`。付费申请必然挂着费用，正常情况下不会为空。
2. 一条付费申请可能横跨多票业务，这是数组，列表行内建议折叠或只展示前 N 票加「共 N 票」。
3. **不要在列表页读 `currencyGroup` / `totalPayPrice` / `totalReceivePrice`（组内的那三个）**，它们恒为 `null`。金额请用付费申请行级的 `currencyGroup` / `totalPayPrice` / `totalReceivePrice`（这几个字段在 `PayAppTaskItemDto` 根上，本次未改动，仍有值）。
4. 组内的 `currencyGroup`（业务级）与行根上的 `currencyGroup`（整单级）是两个不同层级的字段，名字相同，取值时注意层级，别取错。
5. 需要费用明细就跳详情 `DetailAsync`，那里 `payAppFeeBySeaExportGroup` 的四个字段都有值。
