# 付费申请（PaymentApplication）变更 — 前端对接文档

**变更日期**：2026-07-18

**变更概述**：本次对付费申请做了三类变更：

| # | 变更类型 | 内容 |
| --- | --- | --- |
| 1 | **结构变更（破坏性）** | 附件由「平铺数组」改为「按类型分组」，涉及新增/编辑入参与详情出参 |
| 2 | **新增字段** | 发票流程 `invoiceProcess`、发票号 `invoiceNo`、开票日期 `invoiceDate`（均可空），并加入列表搜索条件 |
| 3 | **新增接口** | 给指定付费申请追加附件 `AddAttachments`（平铺、仅新增、不校验状态） |

---

## 一、附件结构变更（破坏性）⚠️

附件从平铺数组 `attachments` 改为按附件详细类型（`attachmentDtlTypeId`）分组的结构 `attachmentGroup`。

### 1.1 入参结构（新增 `AddAsync` / 编辑 `EditAsync`）

变更前：

```json
{
  "attachments": [
    {
      "attachmentId": 1,
      "attachmentDtlTypeId": 10,
      "clientVisible": true,
      "displayOrder": 0
    },
    {
      "attachmentId": 2,
      "attachmentDtlTypeId": 20,
      "clientVisible": false,
      "displayOrder": 1
    }
  ]
}
```

变更后：

```json
{
  "attachmentGroup": [
    {
      "attachmentDtlTypeId": 10,
      "items": [{ "attachmentId": 1, "clientVisible": true, "displayOrder": 0 }]
    },
    {
      "attachmentDtlTypeId": 20,
      "items": [
        { "attachmentId": 2, "clientVisible": false, "displayOrder": 1 }
      ]
    }
  ]
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `attachmentGroup` | `array` | 分组集合 |
| `attachmentGroup[].attachmentDtlTypeId` | `long?` | 该组的附件详细类型Id（分组依据，可空） |
| `attachmentGroup[].items` | `array` | 该组下的附件明细 |
| `items[].attachmentId` | `long` | 附件Id（必填，`<=0` 会被忽略） |
| `items[].attachmentDtlTypeId` | `long?` | 明细自身类型；若组上 `attachmentDtlTypeId` 有值则以组为准 |
| `items[].clientVisible` | `bool` | 客户是否可见 |
| `items[].displayOrder` | `int` | 排序 |

> 编辑（`EditAsync`）仍是「先清空该付费申请的全部附件关联，再按 `attachmentGroup` 重建」，即全量覆盖。

### 1.2 出参结构（详情 `DetailAsync`）

变更前 `attachments`（平铺）→ 变更后 `attachmentGroup`（分组）：

```json
{
  "attachmentGroup": [
    {
      "attachmentDtlTypeId": 10,
      "attachmentDtlType": { "id": 10, "name": "发票", "sortId": 1 },
      "items": [
        {
          "id": 100,
          "attachmentId": 1,
          "attachmentDtlTypeId": 10,
          "clientVisible": true,
          "displayOrder": 0,
          "url": "https://...",
          "friendlyFileName": "发票.pdf",
          "creatorUserId": 5,
          "creatorUserName": "张三",
          "creationTime": "2026-07-18T10:00:00"
        }
      ]
    }
  ]
}
```

**出参说明**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `attachmentGroup[].attachmentDtlTypeId` | `long?` | 分组类型Id |
| `attachmentGroup[].attachmentDtlType` | `object` | 类型信息（含 `sortId`，分组按其排序） |
| `attachmentGroup[].items` | `array` | 该类型下附件，按 `displayOrder` 升序 |
| `items[].creatorUserName` | `string` | 上传人昵称（后端已回填） |

> 分组排序规则：先按 `attachmentDtlType.sortId` 升序，再按 `attachmentDtlTypeId` 升序；组内按 `displayOrder` 升序。

### 1.3 新增出参：关联付费结算的附件列表（仅详情 `DetailAsync`）

详情额外返回一个字段 `paymentSettlementAttachments`：当前付费申请所关联的**付费结算**的附件列表（平铺，非分组）。

```json
{
  "paymentSettlementAttachments": [
    {
      "id": 200,
      "attachmentId": 8,
      "attachmentDtlTypeId": 30,
      "attachmentDtlType": { "id": 30, "name": "付款水单", "sortId": 2 },
      "clientVisible": true,
      "displayOrder": 0,
      "url": "https://...",
      "friendlyFileName": "水单.pdf",
      "creatorUserId": 6,
      "creatorUserName": "李四",
      "creationTime": "2026-07-18T12:00:00"
    }
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `paymentSettlementAttachments` | `array` | 关联付费结算的附件列表（**平铺**，`AttachmentItemDto`） |
| `paymentSettlementAttachments[].creatorUserName` | `string` | 上传人昵称（后端已回填） |

> 说明：
>
> - 该字段**只读**，来源于关联付费结算的附件，付费申请侧无法直接增删（如需变更请到对应付费结算操作）。
> - 一个付费申请可能关联多个付费结算，返回的是所有关联结算的附件**合并列表**；无关联时为空数组 `[]`。
> - 与付费申请自身的 `attachmentGroup`（分组）区分开：这是「结算侧」的附件，平铺返回，按 `displayOrder` 升序。
> - 仅**详情**返回，列表不返回。

## 二、新增字段：发票流程 / 发票号 / 开票日期

三个字段均**可空**，贯穿新增、编辑、详情、列表。

| 字段 | JSON Key | 类型 | 说明 |
| --- | --- | --- | --- |
| 发票流程 | `invoiceProcess` | `int?`（枚举） | `0` 先票后付、`1` 先付后票、`2` 不开票 |
| 发票号 | `invoiceNo` | `string?` | 最长 128 字符 |
| 开票日期 | `invoiceDate` | `datetime?` | — |

### 2.1 发票流程枚举 `invoiceProcess`

| 值     | 含义     |
| ------ | -------- |
| `0`    | 先票后付 |
| `1`    | 先付后票 |
| `2`    | 不开票   |
| `null` | 未设置   |

### 2.2 入参（`AddAsync` / `EditAsync`）示例

```json
{
  "settlementId": "guid",
  "currencyId": 1,
  "require": "支付要求",
  "remark": "备注",
  "invoiceProcess": 0,
  "invoiceNo": "INV-20260718-001",
  "invoiceDate": "2026-07-18",
  "attachmentGroup": [],
  "paymentApplicationItems": []
}
```

### 2.3 出参（`DetailAsync` / `GetPagedList`）

详情与列表的每条数据都会返回 `invoiceProcess`、`invoiceNo`、`invoiceDate` 三个字段。

## 三、列表搜索条件新增

接口：`GetPagedListAsync`（`/api/services/app/PaymentApplicationAdmin/GetPagedList`）

新增以下查询参数（均可空，不传即不过滤）：

| 参数               | 类型        | 说明                         |
| ------------------ | ----------- | ---------------------------- |
| `invoiceProcess`   | `int?`      | 按发票流程精确过滤（0/1/2）  |
| `invoiceNo`        | `string`    | 按发票号模糊匹配（Contains） |
| `invoiceDateStart` | `datetime?` | 开票日期 起（`>=`）          |
| `invoiceDateEnd`   | `datetime?` | 开票日期 止（`<=`）          |

> 注意：付费结算选择列表接口 `GetPagedListForSettlement` 未加入以上过滤（保持其原有语义）。如需支持请告知。

## 四、新增接口：追加附件

**接口**：`AddAttachmentsAsync` **路由**：`POST /api/services/app/PaymentApplicationAdmin/AddAttachments` **权限**：`Admin_PaymentApplication_Edit`

**说明**：给指定付费申请**追加**多个附件。仅新增、不删除已有附件；只校验付费申请是否存在，**不校验单据状态**（任意状态均可追加）。

**入参**（平铺，不分组）：

```json
{
  "id": "付费申请guid",
  "attachments": [
    {
      "attachmentId": 1,
      "attachmentDtlTypeId": 10,
      "clientVisible": true,
      "displayOrder": 0
    },
    {
      "attachmentId": 2,
      "attachmentDtlTypeId": 20,
      "clientVisible": false,
      "displayOrder": 1
    }
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `guid` | 付费申请Id（必填，不存在会报「付费申请不存在」） |
| `attachments[].attachmentId` | `long` | 附件Id（必填，`<=0` 会被忽略） |
| `attachments[].attachmentDtlTypeId` | `long?` | 附件详细类型Id |
| `attachments[].clientVisible` | `bool` | 客户是否可见 |
| `attachments[].displayOrder` | `int` | 排序 |

**出参**：`true`

> 与新增/编辑不同，此接口是**追加**语义（不会清空已有附件），且入参为**平铺**结构。

## 五、接口路径速查表

| 接口路径 | 方法 | 变更 |
| --- | --- | --- |
| `/api/services/app/PaymentApplicationAdmin/Add` | POST | 附件入参 `attachments`→`attachmentGroup`；新增 `invoiceProcess`/`invoiceNo`/`invoiceDate` |
| `/api/services/app/PaymentApplicationAdmin/Edit` | PUT | 同上 |
| `/api/services/app/PaymentApplicationAdmin/Detail` | GET | 附件出参 `attachments`→`attachmentGroup`；返回三个发票字段；新增只读 `paymentSettlementAttachments`（关联付费结算附件列表） |
| `/api/services/app/PaymentApplicationAdmin/GetPagedList` | GET | 返回三个发票字段；新增 `invoiceProcess`/`invoiceNo`/`invoiceDateStart`/`invoiceDateEnd` 搜索 |
| `/api/services/app/PaymentApplicationAdmin/AddAttachments` | POST | **新增接口**，追加附件（平铺、仅新增、不校验状态） |

## 六、前端改动清单

1. **附件（新增/编辑表单、详情展示）**：由平铺 `attachments` 改为分组 `attachmentGroup`，读写结构都要调整；详情按分组展示（组标题取 `attachmentDtlType.name`）。详情页可另加一块「关联付费结算附件」区域，展示只读的 `paymentSettlementAttachments`（平铺列表）。
2. **发票信息**：新增/编辑表单增加「发票流程」下拉（0/1/2）、「发票号」输入、「开票日期」选择；详情、列表展示这三个字段。
3. **列表筛选**：增加发票流程、发票号、开票日期区间筛选控件。
4. **追加附件**：如有「单独补传附件」场景，调用 `AddAttachments`（平铺入参，追加不覆盖）。
