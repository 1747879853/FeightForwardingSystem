# 付费申请 — 发票附件批量下载（前端对接）

**变更日期**：2026-09-04 **关联后端文档**：《付费申请-发票批量下载-2026-09-04》 **前置变更**：《付费申请-发票改子表与流程必填-前端对接文档-2026-09-04》 **破坏性**：否（纯新增接口）

## 接口

| 项 | 内容 |
| --- | --- |
| 方法名 | `DownloadInvoicesAsync` |
| 路由 | `POST /api/services/app/PaymentApplicationAdmin/DownloadInvoicesAsync` |
| 权限 | `Admin.PaymentApplication.Get` |
| 返回 | `PaymentApplicationInvoiceDownloadResultDto` |

> 路由里的 `Async` 后缀不能省。

## 入参

```json
{
  "ids": ["3fa85f64-...-0001", "3fa85f64-...-0002"]
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `ids` | `guid[]` | **是** | 付费申请id集合，取这些申请下**全部发票**的附件；内部会去重 |

> 传的是**付费申请id**，不是发票id。一条付费申请下的多张发票会全部打进包里。

## 出参

```json
{
  "url": "http://xxx/Uploads/document/20260904/6389012345671234.zip",
  "fileName": "付费申请发票_20260904132015.zip",
  "fileCount": 5,
  "missingInvoiceNos": ["INV-0007", "INV-0008"]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `url` | `string` | 压缩包下载地址，直接用它下载 |
| `fileName` | `string` | 建议的另存文件名 |
| `fileCount` | `int` | 实际打进压缩包的附件数 |
| `missingInvoiceNos` | `string[]` | 没有附件、或附件文件在服务器上已缺失的发票号；都正常时为 `[]` |

## 压缩包结构

包内按「付费申请单号」分目录，文件名用发票号：

```
付费申请发票_20260904132015.zip
├── PY260904001/
│   ├── INV-0001.pdf
│   └── INV-0002.jpg
└── PY260904002/
    ├── INV-0005.pdf
    └── INV-0005(1).pdf     ← 发票号撞名时自动追加序号
```

## 报错

| 报错 | 触发条件 |
| --- | --- |
| 「付费申请不能为空」 | `ids` 没传或为空数组 |
| 「付费申请不存在」 | 传的 id 一个都查不到 |
| 「所选付费申请没有发票信息」 | 这些申请下一张发票都没有 |
| 「所选付费申请的发票都没有附件 无可下载内容」 | 有发票但**一个附件都打不进去** |

> **部分缺失不会报错**：只要有一个附件成功打包，接口就正常返回，缺的那些放在 `missingInvoiceNos` 里。

## 前端接入建议

1. **入口**：列表页多选后放一个「批量下载发票」按钮，把选中行的 `id` 收成 `ids` 提交。
2. **下载**：拿到 `url` 后触发下载即可，例如创建 `<a href=url download=fileName>` 点击，或 `window.location.href = url`。
3. **部分缺失要提示**，不要静默忽略：

```js
const res = await downloadInvoices({ ids });
if (res.missingInvoiceNos?.length) {
  message.warning(
    `已下载 ${res.fileCount} 个附件；以下发票没有附件：${res.missingInvoiceNos.join('、')}`,
  );
}
triggerDownload(res.url, res.fileName);
```

4. **加 loading**：打包在服务端同步完成，附件多时耗时会明显，按钮要置灰防重复点击。
5. **选中数量建议自行限制**：后端目前没有数量上限，一次选几百张申请会有明显等待和内存压力。建议前端先限制在几十张以内；如果业务确实需要大批量，提需求由后端加上限校验或改流式打包。
6. 发票流程为「不开票」的付费申请必然没有发票，若用户全选的都是这类单据，会直接收到「所选付费申请没有发票信息」。可在前端先过滤掉 `invoiceProcess === 2` 的行，或把该报错友好化展示。
