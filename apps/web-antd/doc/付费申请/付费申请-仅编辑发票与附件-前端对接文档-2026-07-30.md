# 付费申请 — 仅编辑发票与附件（前端对接）

**变更日期**：2026-07-30  
**关联后端文档**：《付费申请-仅编辑发票与附件-2026-07-30》

## 接口

| 项     | 内容                                                             |
| ------ | ---------------------------------------------------------------- |
| 方法名 | `EditInvoiceAsync`                                               |
| 路由   | `PUT /api/services/app/PaymentApplicationAdmin/EditInvoiceAsync` |
| 权限   | `Admin.PaymentApplication.Edit`                                  |

## 状态规则（重要）

**本接口不判断 `status`。**  
无论付费申请是录入、审核中、驳回、已通过、部分结算还是已结算，只要单据存在即可调用。  
完整编辑 `EditAsync` 仍只允许录入/驳回，二者不要混用预期。

## 入参 `PaymentApplicationInvoiceEditDto`

```json
{
  "id": "付费申请Guid",
  "invoiceProcess": 0,
  "invoiceNo": "发票号，可空，最长128",
  "invoiceDate": "2026-07-30T00:00:00",
  "attachmentGroup": [
    {
      "attachmentDtlTypeId": 10,
      "items": [
        {
          "attachmentId": 1,
          "clientVisible": true,
          "displayOrder": 0
        }
      ]
    }
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `guid` | 必填 |
| `invoiceProcess` | `int?` | 发票流程：`0` 先票后付、`1` 先付后票、`2` 不开票；可空 |
| `invoiceNo` | `string` | 发票号，可空 |
| `invoiceDate` | `datetime?` | 开票日期，可空 |
| `attachmentGroup` | 数组 | 分组附件，结构同详情出参/完整编辑入参；**全量覆盖** |

## 与现有接口区别

| 接口 | 用途 | 是否判断 Status |
| --- | --- | --- |
| `EditAsync` | 完整编辑 | 是（仅录入/驳回） |
| `EditInvoiceAsync` | 只改发票流程、发票号、开票日期、附件 | **否** |
| `AddAttachmentsAsync` | 平铺追加附件，不删旧、不改发票字段 | 否 |

## 前端注意

1. 只改发票信息时，仍须把当前详情的 `attachmentGroup` 原样带回，否则附件会被清空。
2. 需要清空附件时：传 `attachmentGroup: []` 或 `null`。
3. 审核通过后补录发票：用本接口，不要走 `EditAsync`（会被状态拦住）。
