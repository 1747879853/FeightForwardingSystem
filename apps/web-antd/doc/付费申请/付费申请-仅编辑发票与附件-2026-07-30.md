# 1. 背景意图 (Background)

完整编辑接口 `EditAsync` 会改组织、支付要求、备注、发票流程、银行等，且**仅允许录入/驳回状态**。业务上常需在审核中、已通过、已结算等任意状态下单独维护**发票流程、发票号、开票日期**并同步**分组附件**，因此新增专用局部更新接口 `EditInvoiceAsync`。

# 2. 核心逻辑变更 (Core Logic)

- `src/CsprojBuilder.Application/App/PaymentApplication/Dto/PaymentApplicationDto.cs`（`PaymentApplicationInvoiceEditDto`）
- `src/CsprojBuilder.Application/App/PaymentApplication/IPaymentApplicationAdminAppService.cs`
- `src/CsprojBuilder.Application/App/PaymentApplication/PaymentApplicationAdminAppService.cs`

## 2.2 接口

`PUT /api/services/app/PaymentApplicationAdmin/EditInvoiceAsync`

**权限**：`Admin.PaymentApplication.Edit`

**入参** `PaymentApplicationInvoiceEditDto`：

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `id` | `Guid` | 是 | 付费申请主键 |
| `invoiceProcess` | `InvoiceProcess?` | 否 | 发票流程：`0` 先票后付、`1` 先付后票、`2` 不开票 |
| `invoiceNo` | `string` | 否 | 发票号，最长 128 |
| `invoiceDate` | `DateTime?` | 否 | 开票日期 |
| `attachmentGroup` | `List<AttachmentGroupInputDto>` | 否 | 分组附件；**全量覆盖**（先删该申请全部附件关联，再按分组重建），结构同 `EditAsync` |

**出参**：无（`Task`）

## 2.3 状态规则（重要）

- **本接口不校验 `Status`**：只要付费申请存在即可调用，录入、审核中、驳回、已通过、部分结算、已结算等状态均可修改上述发票字段与附件。
- 对比：`EditAsync` 仍要求 `Status` 为录入或驳回，否则抛「非录入状态不可编辑」。
- 实现上不对 `paymentApplication.Status` 做任何判断或赋值，不会因本接口改变申请状态。

## 2.4 与 `EditAsync` 对比

| 项 | `EditAsync` | `EditInvoiceAsync` |
| :-- | :-- | :-- |
| 可改字段 | 组织/状态提交/最晚付款/要求/备注/发票流程/发票号/开票日期/银行/附件 | **仅** `invoiceProcess`、`invoiceNo`、`invoiceDate`、`attachmentGroup` |
| 状态限制 | 仅录入、驳回可编辑 | **不校验 Status**（任意状态可调） |
| 更新方式 | 曾调用 `UpdateAsync` | 局部赋值，依赖 UoW 落库，避免全列 UPDATE |
| 附件 | 全量覆盖 | 同左 |

不修改：银行、费用关联、支付要求、备注、组织、申请状态等。

# 3. 避坑指南 (Pitfalls)

- **`attachmentGroup` 为空或 null**：会先删光该申请附件，且不再写入，效果是清空附件；前端若只想改发票字段需带上当前完整 `attachmentGroup`。
- 与 `AddAttachmentsAsync` 不同：后者是**平铺追加、不删旧**；本接口是**分组全量覆盖**。
- 清空发票流程/号/日期：对应字段传 `null`（发票号可空字符串）即可写入。
- 不要用本接口代替完整 `EditAsync` 去改银行或提交审核。
