# 付费申请-选择费用分组港口改业务类型简要-前端对接文档-2026-08-14

> ⚠️ **破坏性变更**：根级 14 个平铺港口字段已删除，改为按 `bizType` 返回业务类型简要对象。读根级 `pol` / `pod` 等字段的地方必须改取数路径。

## 1. 接口

| 项   | 值                                                                |
| :--- | :---------------------------------------------------------------- |
| 方法 | `GET`                                                             |
| 地址 | `/api/services/app/PaymentApplicationAdmin/GetOrderFeeGroupAsync` |
| 权限 | `Admin.PaymentApplication.Get` + `Admin.OrderFee.Get`             |
| 返回 | `PagedList<PayAppFeeGroupDto>`                                    |
| 用途 | 付费申请加费用时的「选择费用」列表，按 业务 + 结算对象 分组       |

入参 `PayAppFeeGroupInputDto` 不变。

## 2. 已删除的出参字段（根级）

以下 14 个字段从 `items[]` 根级**移除**：

| 已删除字段 | 原含义 | 替代取数路径 |
| :-- | :-- | :-- |
| `pol` | 起运港 | `seaExport.pol` / `seaImport.pol` / `airExport.pol` |
| `polRemark` | 起运港备注 | `seaExport.polRemark` / `seaImport.polRemark` / `airExport.polRemark` |
| `pod` | 目的港 | `seaExport.pod` / `seaImport.pod` / `airExport.pod` |
| `podRemark` | 目的港备注 | `seaExport.podRemark` / `seaImport.podRemark` / `airExport.podRemark` |
| `signingPort` | 签单地点 | **本接口不再返回**，需要请调海运出口详情 |
| `prepareAt` | 付费地点 | **本接口不再返回** |
| `pot1` / `pot1Remark` | 中转港1 | **本接口不再返回**（空运中转地见 `airExport.pot`） |
| `pot2` / `pot2Remark` | 中转港2 | **本接口不再返回** |
| `receivePort` / `receivePortRemark` | 收货地 | **本接口不再返回** |
| `deliverPort` / `deliverPortRemark` | 交货地 | **本接口不再返回** |

## 3. 新增的出参字段（根级）

按 `bizType` 挂载，**三者互斥**，非当前业务类型恒为 `null`：

| JSON 字段 | 类型 | 填充条件 |
| :-- | :-- | :-- |
| `bizType` | int 枚举 | 始终返回。0=海运出口 / 1=海运进口 / 2=空运出口 |
| `seaExport` | `SeaExportSimpleDto` | 仅 `bizType=0` |
| `seaImport` | `SeaImportSimpleDto` | 仅 `bizType=1` |
| `airExport` | `AirExportSimpleDto` | 仅 `bizType=2` |

> 本次同时修复了「海运进口与空运出口业务拿不到任何港口信息」的问题——原先 14 个平铺字段只取自海运出口，这两类业务全为 `null`。

### 3.1 `SeaExportSimpleDto` / `SeaImportSimpleDto`

两者字段完全一致。

| JSON         | 类型                | 说明                    |
| :----------- | :------------------ | :---------------------- |
| `id`         | Guid                | 主键（与业务 id 相同）  |
| `vessel`     | string              | 船名                    |
| `innerVoyno` | string              | 航次                    |
| `pol`        | `PortCodeSimpleDto` | 起运港对象，可为 `null` |
| `polRemark`  | string              | 起运港备注              |
| `pod`        | `PortCodeSimpleDto` | 目的港对象，可为 `null` |
| `podRemark`  | string              | 目的港备注              |
| `carrier`    | `CarrierSimpleDto`  | 船公司对象，可为 `null` |

### 3.2 `AirExportSimpleDto`

| JSON        | 类型               | 说明                    |
| :---------- | :----------------- | :---------------------- |
| `id`        | Guid               | 主键（与业务 id 相同）  |
| `flightNo`  | string             | 航班                    |
| `pol`       | `AirPortSimpleDto` | 起运地对象，可为 `null` |
| `polRemark` | string             | 起运地备注              |
| `pot`       | `AirPortSimpleDto` | 中转地对象，可为 `null` |
| `potRemark` | string             | 中转地备注              |
| `pod`       | `AirPortSimpleDto` | 目的地对象，可为 `null` |
| `podRemark` | string             | 目的地备注              |

### 3.3 外键对象结构

| Dto | 字段 |
| :-- | :-- |
| `PortCodeSimpleDto` | `id` / `portName` / `cnName` / `ediCode` / `lane`（航线对象，可为 `null`） / `country`（国家对象，可为 `null`） |
| `CarrierSimpleDto` | `id` / `code` / `cnName` / `cnShortName` / `enName` / `ediCode` |
| `AirPortSimpleDto` | `id` / `iataCode` / `enName` / `cnName` |

> **注意类型变化**：原平铺字段用的是 `PortCodeSimpleDtoForOrder`，简要对象里用的是 `PortCodeSimpleDto`，两者字段结构略有差别，替换时请核对。

## 4. 其余出参

结算对象、委托单位、包装、业务来源、付费方式、运输条款、箱信息、货物信息、业务关联人员、`orderFees` 等字段均不变。

## 5. 前端适配清单

- [ ] 删除对根级 `pol` / `polRemark` / `pod` / `podRemark` 的读取，改为按 `bizType` 走 `seaExport` / `seaImport` / `airExport`
- [ ] 删除对根级 `signingPort` / `prepareAt` / `pot1` / `pot2` / `receivePort` / `deliverPort` 及其 `*Remark` 的读取（本接口不再提供）；若页面确需展示，改调海运出口详情接口
- [ ] 港口对象类型由 `PortCodeSimpleDtoForOrder` 变为 `PortCodeSimpleDto`，核对字段是否够用
- [ ] 空运出口的中转地是 `airExport.pot`（单个），与原来的 `pot1` / `pot2` 不是同一概念
- [ ] 空运出口没有航次，只有 `airExport.flightNo`（航班），语义与海运 `innerVoyno` 无关，不要混用

## 6. 已知限制（本次未改动）

按港口筛选的入参 `polId` / `podId` **仍只匹配海运出口业务**，海运进口与空运出口会被整条排除。即：出参已覆盖三种业务类型，入参筛选还没有。如需扩展请另提需求。
