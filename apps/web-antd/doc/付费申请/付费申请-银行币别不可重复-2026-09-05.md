# 1. 背景意图 (Background)

新增、修改付费申请时，`PaymentApplicationBanks` 里可以挂多条客户银行。业务要求**同一申请下不能出现重复币别**：各条银行对应的 `ClientInvoiceBank.CurrencyId` 必须互不相同。原先这条只在原币申请里拦，指定币别申请只靠「只能选一条银行」间接保证；本次抽成两种申请共用的硬校验。

# 2. 核心逻辑变更 (Core Logic)

涉及文件：`PaymentApplicationAdminAppService.ValidatePaymentApplicationBanksAsync`。

`AddAsync`、`EditAsync` 仍走同一方法，未改调用点。

| 项 | 规则 |
| :-- | :-- |
| 判定口径 | 已解析出的 `ClientInvoiceBank.CurrencyId` 去重后条数必须等于银行条数 |
| 生效范围 | 原币申请、指定币别申请都拦 |
| 报错 | `银行币别不能重复：USD`（多个重复币别用顿号拼接） |
| 空银行 | 仍与「银行可空」一致：没有任何有效 `clientInvoiceBankId` 时直接跳过整段银行校验 |

指定币别申请「只能选一条银行」、原币申请「银行币别须落在费用原币里」等原有规则不变。

原报错 `原币结算下每种币别只能选择一个银行` 已删除，前端若按原文匹配需改成新文案。

# 3. 接口

无入参/出参字段变更。仍是：

| 接口 | 路径                                                      |
| :--- | :-------------------------------------------------------- |
| 新增 | `POST /api/services/app/PaymentApplicationAdmin/AddAsync` |
| 修改 | `PUT /api/services/app/PaymentApplicationAdmin/EditAsync` |

`AddByStatementAsync`、`PayAppItemAddAsync`、`EditInvoiceAsync` 不改银行，不走本校验。

# 4. 避坑指南 (Pitfalls)

> [!IMPORTANT] **重复的是币别，不是银行主键。** 两条不同的 `clientInvoiceBankId` 只要 `CurrencyId` 相同就会失败；同一银行 id 提交两次仍是原来的 `银行不可重复选择`。

> [!IMPORTANT] **只传部分银行不再拦。** 原币申请不再查「费用原币是否都有银行」；已选银行的币别仍须落在费用原币里，同币别仍不能两条。
