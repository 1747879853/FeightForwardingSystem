# 背景意图

`GetOrderFeeGroupAsync`（付费申请加费用时的「选择费用」分组列表）此前把**海运出口的 14 个港口字段平铺在 `PayAppFeeGroupDto` 这一层**：

`prepareAt` / `signingPort` / `pod` / `podRemark` / `pol` / `polRemark` / `pot1` / `pot1Remark` / `pot2` / `pot2Remark` / `receivePort` / `receivePortRemark` / `deliverPort` / `deliverPortRemark`

这带来三个问题：

1. **只有海运出口有值。** 平铺字段全部取自 `transportOrder.SeaExport`，海运进口和空运出口业务这 14 个字段恒为 `null`，等于「选择费用」列表对这两类业务不显示任何港口。
2. **字段远超所需。** 选择费用只需要起运港/目的港/船名/航次/船公司这一档信息，签单地点、中转港1/2、收货地、交货地、付费地点在这个场景用不上，白白增加出参体积与港口表查询量。
3. **与其他模块口径不一致。** 开票申请、发票开出、客户对账、业务费用等接口都已统一为「按 `bizType` 挂 `seaExport` / `seaImport` / `airExport` 简要对象」，只有本接口还是平铺。

# 核心逻辑变更

## 1. 删除 `PayAppFeeGroupDto` 上的 14 个平铺港口字段

这 14 个属性**是声明在 `PayAppFeeGroupDto` 自身**的（不是继承自 `TransportOrderDto`），且 `PayAppFeeGroupDto` 只被 `GetOrderFeeGroupAsync` 这一个接口使用，因此整块删除的影响范围严格限定在本接口，不波及任何其他模块。

## 2. 改为返回业务类型简要

`PayAppFeeGroupDto : TransportOrderDto`，而 `TransportOrderDto` 已实现 `ITransportOrderBizSimple` 契约（2026-08-14 新增），因此直接在结果组装完成后调用一次共享填充器即可：

```csharp
// 按业务类型挂海运出口/海运进口/空运出口简要 三种业务口径一致
await _transportOrderBizSimpleFiller.FillAsync(result);
```

`BizType` 由 `ObjectMapper.Map<PayAppFeeGroupDto>(transportOrder)` 自动映射（实体与 Dto 同名），无需手工补赋值——这点与开票申请/发票开出那几处手工 `new` Dto 的场景不同。

## 3. 顺带删除的查询与代码

- **`#region 港口` 整块预加载**：原先按 8 个港口 id 去 `_portCodeRepository` 批量查 `PortCodeSimpleDtoForOrder`，现由填充器只查起运港/目的港。
- **`portMap` 与本地函数 `FindPort`**：随平铺赋值一起删除。
- **`.Include(x => x.SeaExport)`**：业务主查询不再需要物化整个海运出口实体（原注释「业务一定要查 因为要返回港口」的前提已不成立），去掉一次 JOIN。`WhereIf(input.POLId...)` 这类筛选谓词由 EF 直接翻译成 SQL，不依赖 `Include`，不受影响。
- **注入的 `_portCodeRepository`**：变成死依赖，连同构造函数参数一并移除。

# 避坑指南

- **平铺字段是删除，不是改名，属于破坏性变更。** 前端读 `pol` / `pod` 等根级字段的地方必须改为读 `seaExport.pol` / `seaExport.pod`，否则显示为空。
- **签单地点 / 中转港1 / 中转港2 / 收货地 / 交货地 / 付费地点在本接口不再返回。** 简要对象（`SeaExportSimpleDto`）里没有这些字段。如果「选择费用」页面确实要展示它们，不要在这里加回平铺字段，应改调海运出口详情接口。
- **按港口筛选（`polId` / `podId`）仍只命中海运出口**，谓词是 `m.SeaExport.POLId == ...`，海运进口与空运出口的 `SeaExport` 导航为空会被整条排除。这是本次**未改动**的既有行为：出参已覆盖三种业务类型，但入参筛选还没有。若要扩展，需参照业务费用的做法引入 `isSea` 入参（海运港口在 `App_PortCodes`、空运港口在 `App_AirPorts`，两张表 id 会重号，不能只凭 id 定位）。
- **`PortCodeSimpleDtoForOrder` 与 `PortCodeSimpleDto` 是两个类型。** 平铺时用的是前者（含航线/国家），简要对象里用的是后者。前端字段结构略有差别，替换取数路径时要一并核对。
