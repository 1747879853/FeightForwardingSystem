# 1. 背景意图 (Background)

> [!WARNING] **部分结论已废止（2026-07-30）**：本文写的「clientName 保留」「仅详情返回 settlement」已不再成立。现以《付费申请-2026-07-30》为准：clientName 已删除，列表与详情均返回 settlement，并新增 currency / paymentSettlements。

`PaymentApplicationAdminAppService.DetailAsync`（付费申请详情）此前对于结算对象只返回一个 `clientName`（客户简称字符串），前端在详情页/打印页需要展示结算对象的**全称**与**地址**时拿不到数据，只能再调客户接口。

本次详情出参新增 `settlement` 字段，返回 `SettlementId` 对应客户的对象化信息（`ClientSimpleDtoForOrder`），与业务单据上其它往来单位字段（`client`/`team`/`shipper` 等）的结构保持一致。

## 2.3 查询逻辑

原先按 `SettlementId` 用 `FirstOrDefaultAsync` 取整个客户实体、只用到 `Name`；现改为投影查询，一次取出 `Id`/`Name`/`FullName` 与默认地址：

```csharp
var settlementClient = await _clientRepository.GetAll().AsNoTracking()
    .Where(x => x.Id == paymentApplication.SettlementId)
    .Select(x => new ClientSimpleDtoForOrder
    {
        Id = x.Id,
        Name = x.Name,
        FullName = x.FullName,
        Address = x.ClientAddresses.Where(a => a.IsDefault).Select(a => a.Address).FirstOrDefault()
    })
    .FirstOrDefaultAsync();
result.Settlement = settlementClient;
result.ClientName = settlementClient?.Name;
```

地址取值口径与 `SeaExportAdminAppService`、`PaymentApplicationAdminAppService.GetOrderFeeGroupAsync` 中的 `MapClient` 完全一致。

# 3. 避坑指南 (Pitfalls)

- **`clientName` 未删除**：老字段继续返回（值等于 `settlement.name`），前端可平滑迁移，不要在后端直接删掉造成兼容问题。
- **仅详情返回**：`GetPagedListAsync`（付费申请列表）仍只返回 `clientName`，列表页不要去取 `settlement`。
- **地址依赖默认标记**：客户地址子表没有 `IsDefault=true` 的记录时 `address` 为 `null`，打印场景需做空值兜底。
- **查询用投影**：不要退回成查整实体再取字段，投影 + `AsNoTracking()` 才能避免把地址子表整表带出来。
