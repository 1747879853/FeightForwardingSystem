# 1. 背景意图 (Background)

付费审核任务列表 `PayAppTaskListAsync` 原先只返回**本条付费申请**自身的申请金额分组（`currencyGroup` / `totalPayPrice` / `totalReceivePrice`）。审核人需要同时看到该结算对象在业务费用表中的**应收欠款余额**（与本申请明细无关），以便判断付费风险。

本次在任务列表出参新增 `settlementReceivableGroup`：按当前付费申请的结算对象，汇总其全部「审核通过 + 收」费用的未结算金额，并按币别分组。

## 2.5 取数口径（关键）

对本页所有付费申请的 `SettlementId` 去重后，查 `OrderFee`：

| 条件       | 口径                                              |
| :--------- | :------------------------------------------------ |
| 结算对象   | `OrderFee.SettlementId` = 付费申请 `SettlementId` |
| 收付类型   | `PaySide = 收`                                    |
| 费用状态   | `FeeStatus = Passed`（仅审核通过）                |
| 未结算过滤 | `Amount != SettledAmount`（排除已结清）           |
| 未结算金额 | `Sum(Amount - SettledAmount)`                     |
| 分组       | 按 `(SettlementId, CurrencyId)` 分组              |
| 精度       | `ToFinancialRound` 保留 2 位                      |

挂回列表行时：按该行付费申请的 `SettlementId` 过滤分组结果写入 `settlementReceivableGroup`；无欠款时为空数组。

> 注意：该字段统计的是**结算对象维度**的全部应收欠款，**不是**本条付费申请明细费用的未结算额。与 `currencyGroup` 口径不同，不要混用。

查询使用 `AsNoTracking()`；币别代码走 `BasicDataCache.GetCurrenciesAsync()`。

# 3. 避坑指南 (Pitfalls)

- **不要用 `currencyGroup.totalUnSettledAmount` 替代**：那是本申请明细费用在付费申请额度语义下的未结算，不是结算对象全量应收欠款。
- **只含审核通过应收**：录入/提交中/驳回费用不计入；付费费用(`PaySide=付`)不计入。
- **已结清币别不返回**：`Amount == SettledAmount` 的费用被过滤；若某币别全部结清，则该币别不出现在数组中。
- **同结算对象多行任务共享同一汇总**：本页多条任务若结算对象相同，其 `settlementReceivableGroup` 内容一致（按结算对象批量查一次后挂回）。
- **无欠款返回 `[]`**：前端展示时需空数组兜底，不要假定一定有 USD/CNY。
