# 付费申请 — 按对账单新建（前端对接）

**变更日期**：2026-07-30

## 接口

| 项   | 内容                                                                  |
| ---- | --------------------------------------------------------------------- |
| 方法 | `AddByStatementAsync`                                                 |
| 路由 | `POST /api/services/app/PaymentApplicationAdmin/AddByStatementAsync`  |
| 权限 | `Admin.PaymentApplication.Add` + `Admin.Statement.Edit`（须同时具备） |

## 入参（仅此一字段）

```json
{
  "statementId": "对账单Guid"
}
```

其余一律不传。后端固定：结算对象=对账单客户、原币、不填银行、录入态、所属组织/申请人=对账单上的 `orgId` / `userId`、费用全额 `remaining`。

## 主要报错

| 文案                                     | 含义             |
| ---------------------------------------- | ---------------- |
| 存在应收费用 不可提交付费申请            | 对账单含应收     |
| 费用存在待审核任务 不可进行付费申请      | 同普通新增       |
| 不可添加不同本位币的费用                 | 同普通新增       |
| 存在无可申请额度的费用，不可提交付费申请 | `remaining <= 0` |

## 前端注意

`remaining` 的最新口径为：`费用金额 - 已存在付费申请额 - 按费用收费结算额 - 开票申请已申请额`。其中会扣掉“已在开票申请中、但还没进入收费结算”的那部分金额。

成功后跳转详情补银行并提交审核即可。
