# 付费申请接口变动文档 - PaymentApplicationBank 银行子表

## 一、背景

付费申请（`PaymentApplication`）新增子表 `PaymentApplicationBank`，用于记录每条付费申请关联的结算银行。

---

## 二、新增/编辑接口入参变动

### 1. 新增接口 `POST AddAsync`

`PaymentApplicationAddDto.PaymentApplicationBanks` 字段类型 `List<PaymentApplicationBankAddDto>`：

```json
{
  "paymentApplicationBanks": [{ "clientInvoiceBankId": "guid" }]
}
```

`paymentApplicationBanks` **可不填**（`null` / 空列表 / 全是空的 `clientInvoiceBankId` 都行），此时跳过整段银行校验。

**传了有效 `clientInvoiceBankId` 时的后端校验：**

| 场景 | 规则 |
| --- | --- |
| **原币结算**（`currencyId` 为空） | 已选银行的币别必须落在费用原币里，且属于当前结算对象；**不要求**每种费用原币都有银行（**2026-09-17 取消**「以下币别未指定银行」） |
| **指定币别结算**（`currencyId` 有值） | 只能选一条银行，币别须与结算币别一致，且属于当前结算对象 |
| **通用** | 银行必须存在且属于当前结算对象；**同一申请下各银行的 `ClientInvoiceBank.CurrencyId` 不可重复**。**不校验**开户行 `bankName`、账号 `bankAccount`（**2026-09-17 取消**） |

### 2. 编辑接口 `PUT EditAsync`

`PaymentApplicationEditDto.PaymentApplicationBanks` 字段类型 `List<PaymentApplicationBankEditDto>`：

```json
{
  "id": "付费申请guid",
  "paymentApplicationBanks": [
    { "id": "guid或null", "clientInvoiceBankId": "guid" }
  ]
}
```

**行为**：每次编辑都是**全量替换**，后端会删除旧的银行记录并重新创建。校验规则同新增接口。

---

## 三、详情接口返回值变动

### `GET DetailAsync`

返回的 `PaymentApplicationDto` 中，`currencyGroup` 列表的每一项 `CurrencyGroupDto` 新增了 `paymentApplicationBank` 字段。

**`CurrencyGroupDto` 变动后结构：**

```json
{
  "id": 1,
  "code": "USD",
  "receiveAmount": 0,
  "receivePrice": null,
  "payAmount": 100,
  "payPrice": 700,
  "totalUnSettledAmount": 0,
  "paymentApplicationBank": {
    "id": "付费申请银行记录guid",
    "paymentApplicationId": "付费申请guid",
    "clientInvoiceBankId": "客户银行guid",
    "clientInvoiceBanks": [
      {
        "id": "客户银行guid",
        "clientInvoiceInfoId": "开票信息guid",
        "bankName": "中国银行",
        "bankAccount": "6222xxxxxxxx",
        "accountName": "xxx公司",
        "currencyId": 1,
        "currencyCode": "USD",
        "swiftCode": "BKCHCNBJ",
        "isDefault": true,
        "sortId": 0
      }
    ]
  }
}
```

**映射逻辑：**

| 场景 | 映射方式 |
| --- | --- |
| **原币结算** | 每个币别分组匹配**对应币别**的银行，返回开户行（`bankName`）、账号（`bankAccount`）、SWIFT（`swiftCode`） |
| **指定币别结算** | 所有币别分组共享同一条结算币别银行，返回完整银行展示信息 |
| **未设置银行** | `paymentApplicationBank` 为 `null`（银行可不填，属正常） |

> 注意：`payAppFeeBySeaExportGroup` 内的子 `currencyGroup` **不包含**银行信息，银行信息只在最外层的 `currencyGroup` 中返回。

---

## 四、列表接口

`GET GetPagedListAsync` **无变动**，不返回银行信息。

---

## 五、删除接口

`DELETE DeleteAsync` **无入参/出参变动**，后端会自动级联删除关联的银行记录。

---

## 七、错误提示汇总

| 错误信息 | 触发条件 |
| --- | --- |
| `银行不可重复选择` | 同一 `clientInvoiceBankId` 重复提交 |
| `银行信息不存在` | 传入的 `clientInvoiceBankId` 无效 |
| `银行【xx - xx】不属于当前结算对象` | 银行所属客户与付费申请的结算对象不一致 |
| `银行币别不能重复：USD` | 同一申请下多条银行的 `ClientInvoiceBank.CurrencyId` 相同（原币/指定币别都拦） |
| `银行【xx - xx】的币别与费用原币不匹配` | 原币模式下银行币别在费用中不存在 |
| `指定币别结算只能选择一个银行` | 指定币别模式下传了多条银行 |
| `银行【xx - xx】的币别与结算币别不一致` | 指定币别模式下银行币别与结算币别不同 |

以下报错**已不再抛出**（**2026-09-17**）：`请为每种付费币别指定银行`、`以下币别未指定银行`、`主数据缺少开户行信息`、`主数据缺少账号信息`、`主数据缺少SWIFT代码`。不传银行、只传部分币别银行都不会报错。

| 日期 | 变更类型 | 📝 业务功能变动 | 🤖 代码解析与架构洞察 |
| :-- | :-- | :-- | :-- |
| 2026-09-17 | `Breaking` | 银行子表可不填；传了也不再校验开户行、账号是否为空；原币也不再要求每种费用原币都有银行 | `ValidatePaymentApplicationBanksAsync` 去掉 `BankName`/`BankAccount` 空值拦截和「以下币别未指定银行」；空 `bankIds` 仍直接 return。归属、存在性、币别重复、已选银行须落在费用原币/结算币别里仍保留 |
