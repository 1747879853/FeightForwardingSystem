# 付费申请接口文档

**控制器**：`PaymentApplicationAdmin`

**所有接口均需要登录认证**

> 路由里的 `Async` 后缀不能省，本项目动态 API 不会剥掉它。写成不带 `Async` 的地址会 404。

发票子域（挑选进项、发票子表、仅编辑发票、批量下载）见 [付费申请-发票接口文档.md](./付费申请-发票接口文档.md)。

# 0. 列表

### `GET /api/services/app/PaymentApplicationAdmin/GetPagedListAsync`

**权限**：`Admin.PaymentApplication.Get`

**出参** `PagedList<PaymentApplicationListDto>`。详情、审批列表、付费结算选申请仍用 `PaymentApplicationDto`。

付费申请主表列全部返回：`applicationNo`、`status`、`submitTime`、`endTime`、`require`、`remark`、`invoiceProcess`、`currencyId`、`settlementId`、`totalPayPrice`、`totalReceivePrice`。另有 `id`、`creationTime`、`lastModificationTime`、`localCurrencyCode`、`orgs`（每级只有 `name`）、`creatorUserName`。不返回 `userId`、`orgId`、`creatorUserId`、`localCurrencyId`。

嵌套对象只留列表页和它点开的弹窗要读的字段：

| 字段 | 留下的内容 |
| :-- | :-- |
| `settlement` | `name` |
| `currency` | `code` |
| `payAppFeeBySeaExportGroup[].transportOrder` | `mblNum`、`commissionNum`。没有业务类型简要，也没有 `recSettlementStatus` |
| `paymentSettlements` | `id`、`settlementNo`、`settlementTime`、`totalSettledPrice`、`settlement.name`、`currency.code`、附件 `id`/`attachmentId`/`friendlyFileName`/`url` |
| `paymentApplicationInvoices` | `invoiceNo`、`invoiceDate`、`sellerHeader`、`amount` |
| `currencyGroup` | `id`、`code`、`payAmount`、`receiveAmount` |

# 1. 详情

### `GET /api/services/app/PaymentApplicationAdmin/DetailAsync`

**权限**：`Admin.PaymentApplication.Get`

**Summary：** 付费申请详情。费用按业务分组；每组的 `transportOrder` 为 `TransportOrderSimpleDto`，并赋值应收整票结算状态 `recSettlementStatus`。

## 1.1 入参 `GuidIdDto`（Query）

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `id` | `Guid` | 是 | 付费申请 id。不存在报「付费申请不存在」 |
| `ids` | `Guid[]` | 否 | 批量删除用，本接口不读 |
| `isPrint` | `bool?` | 否 | 打印入口会传 `true`；当前详情实现不读此字段，行为与普通详情相同 |

## 1.2 出参 `PaymentApplicationDto`（行级）

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | `Guid` | 付费申请 id |
| `applicationNo` | `string` | 申请单号 |
| `status` | `PaymentApplicationStatus` | 申请状态：0录入 / 1审核中 / 2驳回 / 3通过 / 4部分结算 / 5结算完毕 |
| `submitTime` | `DateTime?` | 提交时间 |
| `endTime` | `DateTime?` | 最晚付款时间 |
| `settlementId` | `Guid` | 结算对象 id |
| `settlement` | `ClientSimpleDtoForOrder` | 结算对象（简称/全称/默认地址） |
| `currencyId` | `long?` | 申请币别 id；原币申请为 null |
| `currency` | `CurrencySimpleDto` | 申请币别；原币申请为 null |
| `require` | `string` | 支付要求 |
| `remark` | `string` | 备注 |
| `invoiceProcess` | `InvoiceProcess` | 发票流程：0先票后付 / 1先付后票 / 2不开票 |
| `paymentApplicationInvoices` | `PaymentApplicationInvoiceDto[]` | 发票子表，字段见发票接口文档 |
| `creatorUserName` | `string` | 申请人昵称 |
| `payAppFeeBySeaExportGroup` | `PayAppFeeAndTransportOrder[]` | 费用按业务分组，见下节 |
| `attachmentGroup` | `AttachmentGroupDto[]` | 分组附件，详情有 |
| `paymentSettlements` | `PaymentSettlementForApplicationSimpleDto[]` | 关联付费结算简要 |
| `currencyGroup` | `CurrencyGroupDto[]` | 整单按币别合计 |
| `totalPayPrice` | `decimal?` | 应付总金额（结算币别）；原币申请为 null |
| `totalReceivePrice` | `decimal?` | 应收总金额（结算币别）；原币申请为 null |
| `totalSettleablePriceUpperLimit` | `decimal?` | 可结算上限（结算币别）；原币申请为 null |
| `totalSettleablePriceLowerLimit` | `decimal?` | 可结算下限（结算币别）；原币申请为 null |
| `totalSettledPrice` | `decimal?` | 总结算金额 |
| `auditUserId` | `long?` | 审核人 id |
| `auditUserNickName` | `string` | 审核人昵称 |
| `auditTime` | `DateTime?` | 审核时间 |
| `creationTime` | `DateTime` | 创建时间 |
| `lastModificationTime` | `DateTime?` | 最后修改时间 |

数据权限基类上的 `orgId` / `companys` / `organizationUnits` 等仍随 `DataPermissionFullAuditedEntityDto` 返回。

### 1.2.2 `currency`（`CurrencySimpleDto`）

仅固定币别申请有值。

| 字段     | 类型     | 说明     |
| :------- | :------- | :------- |
| `code`   | `string` | 币别代码 |
| `cnName` | `string` | 中文名   |
| `enName` | `string` | 英文名   |

### 1.2.3 `payAppFeeBySeaExportGroup[]`（`PayAppFeeAndTransportOrder`）

详情四个字段全填。列表/审批列表同名数组只填 `transportOrder`，其余为 null。

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `transportOrder` | `TransportOrderSimpleDto` | 业务简要，见下节 |
| `paymentApplicationItems` | `PaymentApplicationItemDto[]` | 该业务下本申请的明细，按费用 `sortId`、创建时间升序 |
| `currencyGroup` | `CurrencyGroupDto[]` | 该业务下本申请的币别合计 |
| `totalPayPrice` | `decimal?` | 该业务应付合计（结算币别）；原币申请为 null |
| `totalReceivePrice` | `decimal?` | 该业务应收合计（结算币别）；原币申请为 null |

### 1.2.4 `payAppFeeBySeaExportGroup[].transportOrder`（`TransportOrderSimpleDto`）

主体字段由 `ProjectTo<TransportOrderSimpleDto>` 映射。详情在映射之后额外赋值：

| 字段 | JSON Key | 类型 | 本接口 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| `saleNames` | `saleNames` | `string[]` | 有值 | 销售昵称 |
| `operatorNames` | `operatorNames` | `string[]` | 有值 | 操作昵称 |
| `customerServiceNames` | `customerServiceNames` | `string[]` | 有值 | 客服昵称 |
| `recSettlementStatus` | `recSettlementStatus` | `int \| null` | **有值** | **应收整票结算状态**。按该业务下**全部应收费用**汇总，不限于本申请收录的费用。无应收费用为 `null` |
| `paySettlementStatus` | `paySettlementStatus` | `int \| null` | 恒 `null` | 应付整票结算状态，本接口不赋值 |

`recSettlementStatus` 与费用行 `settlementStatus` 同一套枚举 `SettlementStatus`：

| 值 | 含义 | 何时出现 |
| :-- | :-- | :-- |
| `null` | 无应收 | 该业务下一条应收费用都没有。展示为「-」或留空，不要显示成「未结算」 |
| `0` | 未结算 | 全部应收费用都是未结算 |
| `1` | 部分结算 | 既不是全未结算，也不是全结算完毕 |
| `2` | 结算完毕 | 全部应收费用都已结算完毕 |

其余 `TransportOrderSimpleDto` 字段（`bizType`、`commissionNum`、`mblNum` 等）按 ProjectTo 返回。业务类型简要对象也是 ProjectTo 顺业务主单的导航一并投影出来的（本接口不调填充器），按 `bizType` 四选一，见 1.2.4.1。

**2026-09-20 由空值改为赋值** `recSettlementStatus`：此前详情只 ProjectTo 并填人员，该字段恒为 null。

#### 1.2.4.1 业务类型简要对象（按 `bizType` 四选一）

非当前业务类型的对象恒为 `null`。

| 字段 | 类型 | 何时有值 | 说明 |
| :-- | :-- | :-- | :-- |
| `seaExport` | `SeaExportSimpleDto` | `bizType = 0` 海运出口 | 船名、航次、起运港/目的港（海运港）、船公司 |
| `seaImport` | `SeaImportSimpleDto` | `bizType = 1` 海运进口 | 船名、航次、起运港/目的港（海运港）、船公司 |
| `airExport` | `AirExportSimpleDto` | `bizType = 2` 空运出口 | 航班号、起运地/中转地/目的地（空运港） |
| `breakBulk` | `BreakBulkSimpleDto` | `bizType = 3` 件杂货 | 见 1.2.4.2。**2026-09-27 新增** |

审批列表 `PayAppTaskListAsync` 的 `payAppFeeBySeaExportGroup[].transportOrder` 仍是 ProjectTo，结构与本节一致。列表 `GetPagedListAsync` 的业务分组只留 `mblNum`、`commissionNum`。选可申请费用 `GetOrderFeeGroupAsync` 每一行（`PayAppFeeGroupDto`）上的同名四个对象由填充器 `ITransportOrderBizSimpleFiller` 赋值，结构也一致。

#### 1.2.4.2 `transportOrder.breakBulk`（`BreakBulkSimpleDto`）

仅 `bizType = 3`（件杂货）时有值。件杂货没有船公司、场站、装运方式、集装箱，所以本对象没有 `carrier`。

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | `Guid` | 业务 id，件杂货表与业务表共用主键 |
| `vessel` | `string` | 船名 |
| `innerVoyno` | `string` | 航次（船公司航次） |
| `terminalVoyno` | `string` | 码头航次（港区航次），与 `innerVoyno` 是两套编号 |
| `pol` | `PortCodeSimpleDto` | 起运港（海运港），见 1.2.4.3；未填为 `null` |
| `polRemark` | `string` | 起运港备注 |
| `pod` | `PortCodeSimpleDto` | 目的港（海运港），见 1.2.4.3；未填为 `null` |
| `podRemark` | `string` | 目的港备注 |

#### 1.2.4.3 `breakBulk.pol` / `breakBulk.pod`（`PortCodeSimpleDto`）

与海运出口、海运进口的港口对象是同一结构。

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | `long` | 海运港 id（`PortCode.Id`） |
| `portName` | `string` | 港口代码 / 英文名 |
| `cnName` | `string` | 港口中文名 |
| `ediCode` | `string` | 港口 EDI 代码 |
| `lane` | `LaneCodeSimpleDto` | 航线，可为 `null`，字段见《港口模块总逻辑文档》4.1 |
| `country` | `CountryCodeSimpleDto` | 国家，可为 `null`，字段见《港口模块总逻辑文档》4.1 |

### 1.2.5 `payAppFeeBySeaExportGroup[].paymentApplicationItems[]`（`PaymentApplicationItemDto`）

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | `Guid` | 明细 id |
| `paymentApplicationId` | `Guid` | 付费申请 id |
| `orderFeeId` | `Guid` | 费用 id |
| `rate` | `decimal?` | 费用原币 ÷ 申请币别的汇率；原币申请为 null |
| `appliedAmount` | `decimal` | 本次申请原币金额 |
| `remark` | `string` | 明细备注 |
| `feeAmount` | `decimal` | 费用金额（取 `orderFee.amount`） |
| `orderFee` | `OrderFeeDto` | 关联费用对象 |
| `creationTime` | `DateTime` | 创建时间 |
| `lastModificationTime` | `DateTime?` | 最后修改时间 |

`orderFee` 外键以对象返回（`feeCode` / `currency` / `settlement`），计算字段含已开票量、已申请量、未申请量、未结算量、结算已占用额度等，口径与业务费用详情一致。

### 1.2.6 `currencyGroup[]`（整单）与组内 `currencyGroup[]`（`CurrencyGroupDto`）

两套同名数组：根上是整单合计，组内是该业务合计。详情里整单由各业务分组合计相加，不要两处各算一遍。

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | `long` | 币别 id |
| `code` | `string` | 币别代码 |
| `payAmount` | `decimal` | 申请量（付） |
| `payPrice` | `decimal?` | 申请金额（付，结算币别）；原币申请为 null |
| `receiveAmount` | `decimal` | 申请量（收） |
| `receivePrice` | `decimal?` | 申请金额（收，结算币别）；原币申请为 null |
| `settledAmount` | `decimal?` | 结算量 = 申请量 − 明细未结算量 |
| `totalUnSettledAmount` | `decimal` | 未结算量（付取正、收取负后求和） |
| `settleableUpperLimit` | `decimal` | 可结算上限（正数有效金额之和） |
| `settleablePriceUpperLimit` | `decimal?` | 可结算上限（结算币别）；原币申请为 null |
| `settleableLowerLimit` | `decimal` | 可结算下限（负数有效金额之和） |
| `settleablePriceLowerLimit` | `decimal?` | 可结算下限（结算币别）；原币申请为 null |
| `paymentApplicationBank` | `PaymentApplicationBankDto` | 该币别匹配到的收款银行；未指定为 null |
| `orderFees` | `OrderFeeDto[]` | 付费结算用，详情不填 |

### 1.2.7 `paymentSettlements[]`（`PaymentSettlementForApplicationSimpleDto`）

无关联时为 `[]`。同一申请多次结算到同一结算单时按「申请 + 结算」去重。

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | `Guid` | 付费结算 id |
| `settlementNo` | `string` | 结算单号 |
| `settlementTime` | `DateTime` | 结算时间 |
| `settlement` | `ClientSimpleDtoForOrder` | 结算单上的结算对象 |
| `currency` | `CurrencySimpleDto` | 结算币别 |
| `totalSettledPrice` | `decimal` | 该结算单金额合计（整张单，不按本申请过滤）。与付费结算列表的 `totalSettledPrice` 同口径：按结算行折算取整再加汇兑尾差，等于录入时填的金额合计（**2026-10-02 起补上尾差，此前是未取整的折算合计，可能差几分**） |
| `attachments` | `AttachmentItemDto[]` | 该结算单附件；无附件为 `[]` |

## 1.4 前端注意

1. 读 `payAppFeeBySeaExportGroup[].transportOrder.recSettlementStatus`，不要自己按本申请费用加总。
2. `null` 与 `0` 含义不同：`null` 是没有应收，`0` 是有应收但全未结算。
3. 列表业务分组只有主提单号和委托编号，没有 `recSettlementStatus`。审批列表 `PayAppTaskListAsync` 的这一列恒为 `null`。需要看整票状态请调详情。
4. `paySettlementStatus` 仍恒为 `null`，先不要用。
5. 件杂货业务（`bizType = 3`）的船名、航次、起运港、目的港在 `transportOrder.breakBulk` 下，没有船公司，不要去 `seaExport` 里取。
