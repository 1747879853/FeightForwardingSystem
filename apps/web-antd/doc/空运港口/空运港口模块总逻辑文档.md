# 1. 业务背景说明 (Background)

**白话解释：** 空运港口就是**机场**。它是一份给空运业务用的机场主数据，回答「这票货从哪个机场飞、飞到哪个机场」时可选的机场清单从哪来。

一条机场记录要说清楚四件事：这个机场的**代码**（三字码，例如 `PEK`、`PVG`；以及 ICAO 码，例如 `ZBAA`）、它的**名称**（英文名 + 中文名）、它在**哪里**（国家、城市）、它的**当地时间**相对世界标准时间差几个小时（时区）。

## 1.1 这份数据是全公司共用的，不分租户

和大多数基础资料不一样，**空运港口不区分租户**：全系统只有一份机场数据，所有租户看到的、用到的都是同一份。这跟「国家」表是一样的做法，而**海运港口是分租户的**（每个租户维护自己的一套港口）。

这一点带来两个必须知道的后果：

1. **任何一个租户改了机场资料，所有租户立刻都会看到改后的结果。** 不存在「A 公司改了 B 公司不受影响」。
2. **测试时不能用"换个租户账号看看数据是否隔离"来验证。** 换租户登录后看到的机场列表应当**完全相同**，如果出现某个租户看不到某条机场，那就是 Bug。

## 1.2 和海运港口是两张独立的表

空运港口是**新表**，与海运港口（`App_PortCodes`）没有任何关系，不是在海运港口上加个「类型=空运」来区分的。所以：

- 机场的 Id 和海运港口的 Id 是**两套独立编号**，可能出现两者 Id 相同但完全无关的情况，不能混用。
- 海运业务单据上的港口下拉，取的仍是海运港口，**不会**出现机场；反之空运业务选机场时也不会出现海港。
- 已有的海运港口字段（航线、EDI 代码、统计区域、港口类型）机场表里都**没有**，不要按海运港口的字段去对照测试。

## 1.3 本期范围

本期只做机场这份**基础资料自身的维护**（增、删、改、查、下拉）。系统里目前**还没有任何空运业务模块**（没有空运出口、空运进口、空运运价），所以机场此刻还没有任何地方在引用它。这直接影响到删除功能的表现，详见第 5 章。

# 2. 表结构

**通用约定**（适用于本章所有表）：

- 本表是**软删除**：删除只是把 `IsDeleted` 置为 `true`，之后所有查询都会自动过滤掉这条数据，数据行仍然物理存在于数据库中。
- 字符串长度均指**字符数**，超长直接报错，不会自动截断。
- 录入内容的**首尾空格会被系统自动去掉**（全局统一处理），并且**长度、空值判断、重复判断全部是按去掉首尾空格之后的内容来算的**。也就是说只填几个空格等于没填。
- 「可空」列写的是**数据库层面**是否允许为空。数据库允许为空、但业务上要求必填的字段，在「生成逻辑 / 校验」列里会明确标注「**必填（逻辑校验）**」——这类字段的必填是在新增和编辑时由后端代码校验的，不是靠数据库约束卡住的。
- `decimal` 未特殊说明为 `decimal(18,2)`，即小数最多 2 位，超出会四舍五入到 2 位入库。

- 唯一的外键是 `CountryId` → `App_CountryCodes.Id`（国家表，同样是不分租户的全局数据）。
- 三字码和英文名在数据库里建的是**普通索引，不是唯一索引**。重复判断完全由后端代码在新增/编辑时执行。这样设计的原因见第 4.2 节。

| 功能 | 说明 |
| :-- | :-- |

# 4. 校验规则与业务逻辑

## 4.1 必填与非必填

**只有四个字段是必填的**：三字码、英文名称、状态（是否启用）、排序 id。

其余字段（中文名、ICAO 码、国家、城市、时区、备注）**全部可以不填**，并且不填时**不做任何补默认值的处理**，就是空。

这条规则的另一面同样重要：**文档没有写明校验规则的字段就是没有校验规则**。ICAO 码不校验是不是 4 位、城市不校验是否属于所选国家、时区不校验是否在 -12 到 +14 之间、中文名不校验是否重复。测试时不要按「常理」去期待这些校验存在。

## 4.2 三字码与英文名的重复判断（本模块最核心的规则）

1. **判断范围是全表全局**。因为不分租户，所以是拿全系统所有机场来比，不存在「不同租户可以有同一个三字码」。
2. **大小写不敏感**。已经存在 `PEK` 时，再录 `pek`、`Pek` 都算重复，会被拦下。
3. **三字码会先自动转成大写再入库**，所以录入 `pek` 最终库里存的是 `PEK`。英文名**不转大小写**，`Beijing` 存 `Beijing`。
4. **首尾空格先去掉再比**。已有 `PEK` 时，录入 `" PEK "` 算重复。
5. **已软删除的机场不参与重复判断**。这是一条会直接影响使用感受的规则：把 `PEK` 删掉之后，可以重新新增一条 `PEK`，系统不会提示重复。这也是为什么数据库不建唯一索引——如果建了，被删除的那行会一直占着 `PEK` 不放，导致「列表里明明没有，却说重复」。
6. **编辑时排除自身**。编辑一条机场但没改三字码，直接保存不会报「已重复」。
7. **三字码和英文名是两个各自独立的判断**，不是组合判断。三字码没重但英文名重了，同样保存不了。

## 4.3 三字码为什么允许 8 位

字段名叫「三字码」，但**长度上限是 8 位，且不校验必须是 3 位字母**。这是为了兼容一些非标准写法和内部自定义代码。测试时录入 4 位、6 位、纯数字、带符号都应该能保存成功，只有**超过 8 位**才会被拦。

## 4.4 时区怎么填

时区存的是**相对 UTC 的小时数**，不是「时区名称」也不是「分钟数」。

- 北京填 `8`，东京填 `9`，伦敦填 `0`，纽约填 `-5`，洛杉矶填 `-8`。
- 印度填 `5.5`，尼泊尔填 `5.75`，这类半小时/45 分钟时区靠小数表示。
- 小数最多 2 位，多余位数会四舍五入。
- **不考虑夏令时**：一个机场只有一个固定的时区值，系统不会因为进入夏令时而自动 +1。所以像纽约这种有夏令时的机场，夏天用这个时区算出来的当地时间会**差一小时**，这是既定设计，不是 Bug。

## 4.5 排序规则

`SortId` **降序**排列，也就是**数值大的排在前面**，常用的机场可以给一个大数字把它顶到最上面。

- 允许多条机场填同一个 `SortId`。
- 排序值相同时的先后顺序由后端追加的次级排序决定（按 Id 降序，即新建的在前），前端和测试不应依赖「相同排序值时的具体顺序」做用例断言，只需保证分页翻页时不重复、不遗漏。
- `SortId` 是必填的，**新增时前端必须传值**，系统不会自动帮它排到末尾。前端可以在新增界面给一个默认值（例如 0）。
- 排序规则是**后端固定的**，前端不能通过参数改变列表排序字段。管理端列表和业务端下拉都是同一套排序。

## 4.6 国家可以不选

国家是非必填的，所以列表和详情里**机场的国家可能是空的**，前端要能正常显示空值而不是报错。填了国家则会校验这个国家是否真实存在。

# 5. 状态与删除

## 5.1 启用/停用流转

| 当前状态 | 触发人/动作 | 目标状态 | 状态说明 |
| :-- | :-- | :-- | :-- |
| 启用 `Status=0` | 管理端编辑为禁用 | 禁用 | 数据仍在，仍能在管理端列表查到 |
| 禁用 `Status=1` | 管理端编辑为启用 | 启用 | 恢复正常使用 |

## 5.2 停用之后会发生什么

- **管理端列表默认展示全部**（启用和禁用都在），可以用状态筛选条件单独看某一类。
- **业务端选择列表不做状态过滤**，禁用的机场依然会返回给前端，是否把它藏起来或置灰由前端决定。这样做是为了避免历史单据上引用了一个已禁用的机场后显示不出名字。
- 禁用**不影响任何历史数据**，已经用过这个机场的单据照常展示。

## 5.3 删除的表现

- 删除是**软删除**，删掉的机场从所有列表里消失，但数据还在库里。
- 删除后**三字码和英文名会被释放**，可以重新录入同名同码的机场（见 4.2 第 5 条）。
- 删除接口**带引用校验**：如果这条机场已经被别的模块用了，会直接拦住并提示「该空运港口已被【xx】模块引用,禁止删除」。**但本期系统里还没有任何空运业务模块，所以现阶段任何机场都能删掉，引用校验永远不会触发。** 等空运出口/进口/运价上线后，需要把这些模块加进校验清单，届时表现会变成「用过的机场删不掉」。
- 反向的一条同样要注意：**机场引用了国家，所以国家不能随便删。** 一个国家只要被任意一条机场引用，删除这个国家时就会被拦住并提示被空运港口引用。这是在国家模块上追加的校验，测试国家删除功能时要一并覆盖。

# 6. 查询与展示逻辑

## 6.1 关键字搜索

搜索框输入一段内容，会去匹配以下字段，**任意一个包含即命中**（模糊匹配）：

三字码、ICAO 码、英文名称、中文名称、城市、所属国家的中文名、所属国家的英文名。

## 6.2 筛选条件

- **状态**：可空。不传等于不筛，看全部；传 `0` 只看启用，传 `1` 只看禁用。
- **国家**：可空。按国家 id 精确筛选。注意国家为空的机场在按国家筛选时不会出现。

## 6.3 列表返回内容的两个约定

1. **外键一律以对象形式返回**。机场的国家不会平铺成 `countryId` / `countryName` / `countryEnName` 三个字段，而是给一个国家对象，里面带 id、中文名、英文名。国家没选时这个对象为 `null`，前端需要判空。
2. **创建人和修改人返回的是昵称**（不是登录名），字段是创建人昵称和修改人昵称。取不到用户时为空。

## 6.4 分页

**管理端列表和业务端选择列表都是分页接口，系统不提供任何一次性返回全部机场的接口。**

分页参数是**页码 + 每页条数**这一组（`PageIndex` / `PageSize`），不是「跳过多少条」。返回结构里带总条数。

业务端选机场时的正确用法是：**关键字搜索 + 分页加载**。前端不要试图循环翻页把几千条机场全捞到本地再做本地过滤，应当把用户输入的关键字传给后端，由后端筛完再分页返回。

# 7. 界面交互说明（给前端）

1. **列表页**：表格 + 顶部关键字搜索框 + 启用状态下拉 + 国家下拉。默认排序为排序 id 降序，不需要前端额外指定。
2. **新增/编辑弹窗**：
   - 三字码输入框建议**输入时即时转大写**，让用户看到的和最终存的一致，避免「我填的小写怎么变大写了」的疑问。
   - 三字码最长 8 位，前端可以做长度限制，但**不要限制必须 3 位字母**。
   - 排序 id 是必填数字，建议给默认值并说明「数字越大越靠前」。
   - 时区建议用数字输入框并给提示文案「相对 UTC 的小时数，东八区填 8，可填小数如 5.5」，**不要做成时区名称下拉**，因为后端存的是数字。
   - 国家是可清空的下拉（数据来自国家基础资料），城市是普通文本框，两者**没有联动**，选了国家不会带出城市，也不会限制城市可填的内容。
3. **重复提示**：三字码或英文名重复时后端返回友好提示，前端直接展示提示文案即可，不需要自己先查一遍重不重。
4. **业务界面选机场**：用业务端的**分页**接口，做成「输入关键字 → 后端搜索 → 滚动加载下一页」的远程搜索下拉，不要一次拉全量。禁用的机场也会在返回数据里，需要前端自行决定是否过滤或置灰。已保存的单据回显机场时，靠机场 id 单独取详情，不要依赖下拉的当前页数据。
5. **删除**：需要二次确认。删除被拦时后端会返回「被 xx 模块引用」的提示文案，前端原样展示。

# 8. 难点与风险点

> [!IMPORTANT] **[风险 1：数据全局共享，一改影响所有租户]** 机场不分租户，任何租户改动都是全局生效。测试跨租户场景时的正确预期是「所有租户看到的完全一致」。运营上需要留意谁有权改这份数据，避免一个租户误删导致所有租户业务受影响。

> [!IMPORTANT] **[风险 2：删除后三字码可以重复使用]** 软删除的数据不参与重复判断。所以「删了 PEK 又新建了一个 PEK」是**合法**的，此时库里存在两条三字码为 PEK 的数据（一条已删除、一条正常）。如果哪天要做数据对账或历史追溯，不能把三字码当成永久唯一标识，只有 Id 是永久唯一的。

> [!IMPORTANT] **[风险 3：数据库没有唯一约束]** 唯一性完全靠应用层校验。极端并发下（两个人同一瞬间提交同一个三字码）理论上可能插进两条重复数据。日常使用不会遇到，但如果将来用脚本或外部程序直接往表里写数据，**绕过接口就绕过了全部校验**，会造成脏数据。批量导数据必须走接口或自行查重。

> [!IMPORTANT] **[风险 4：时区不含夏令时]** 有夏令时的国家（美国、欧洲部分国家）用这个时区值换算出的当地时间，在夏令时期间会差一小时。这是设计取舍，不要当 Bug 提。

> [!IMPORTANT] **[风险 5：三字码不是真的"三字"]** 字段叫三字码但允许 1~8 位任意内容。前端不要加 3 位字母的强校验，测试也不要以「必须 3 位」为预期。

> [!IMPORTANT] **[风险 6：机场 Id 与海运港口 Id 不通用]** 两张独立表、两套自增 Id。任何把机场 Id 传给海运港口字段（或反之）的地方都是 Bug，且因为两边 Id 都是数字，这类错误不会报错，只会静默取到一条完全无关的港口，排查困难。

# 9. 测试要点提示

- 三字码：小写录入是否自动转大写；`" pek "` 是否算与 `PEK` 重复；8 位能存、9 位报错；纯数字/4 位能存。
- 英文名：大小写不同是否算重复；首尾空格是否算重复；是否保持原样大小写。
- 编辑自身不改码保存不应报重复；把 A 的三字码改成 B 的应报重复。
- 删除 `PEK` 后重新新增 `PEK` 应成功，且列表里只有一条。
- 必填校验：三字码/英文名为空或纯空格时报错；状态、排序 id 缺失时报错。
- 国家不填能保存；填一个不存在的国家 id 应报错；列表和详情里国家为空时展示正常。
- 时区：填 `8`、`-5`、`5.75` 均能保存；填 3 位小数 `5.755` 应四舍五入为 `5.76`（或 `5.75`，按四舍五入规则）。
- 排序：给不同 `SortId` 后列表是否大的在前；相同 `SortId` 时翻页无重复无遗漏。
- 状态筛选（0 启用 / 1 禁用，注意别把 0 当成禁用）、国家筛选、关键字搜索七个字段各命中一次。
- 禁用后业务端选择列表是否仍能取到该机场（预期：能取到）。
- 业务端选择列表是否为分页返回、是否支持关键字搜索；不传关键字时只返回第一页而不是全部。
- 换租户登录后机场数据是否完全一致（预期：一致）。
- 国家删除：给某国家挂一条机场后删该国家，应被拦住并提示被空运港口引用。
- 列表/详情是否返回创建人、修改人昵称；国家是否是对象结构而非平铺字段。
