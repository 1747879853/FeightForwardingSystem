# 1. 背景意图 (Background)

列表关键字 `keyword` 是单值模糊匹配费用对应业务的主提单号、委托编号。本次新增 `keys`，一次传入多个单号做精确匹配。

# 2. 核心逻辑变更

`PaymentSettlementQueryDto` 新增 `List<string> Keys`。覆盖字段与 `keyword` 相同：`TransportOrder.MblNum`、`TransportOrder.CommissionNum`。

生效接口：`GET /api/services/app/PaymentSettlementAdmin/GetPagedListAsync`

匹配规则：精确相等、列表内 OR、与 `keyword`/`mblNum`/`commissionNum` 同时传时为 AND。空串忽略。GET 用 `keys=A&keys=B`。

选可结算付费申请不在本服务，走 `PaymentApplicationAdmin` 的 `GetPagedListForSettlementAsync` / `GetPagedListByCurrencyForSettlementAsync`，那两个接口同步加了 `keys`（字段是主提单号/订舱编号/委托编号）。

# 3. 避坑指南 (Blockers)

> [!IMPORTANT] **`keys` 不是模糊搜索，也不含订舱编号。** 本列表的 `keyword` 本来就只搜主提单号和委托编号，`keys` 跟它对齐，不要拿订舱号来搜本列表。
