# Application 入参字符串自动 Trim（修复生效）— 前端说明

**日期：** 2026-07-31 **范围：** 全部 HTTP 接口入参（body / query / route） **接口变更：** 无。没有新增、删除或重命名任何接口和字段，仅行为变化。

## 一句话

2026-07-29 那版说的「后端会自动 Trim」当时其实**没有真正生效**，本次修复后才真正开始生效。如果你们的前端之前是靠后端 Trim 的，那段时间的数据可能带着首尾空格进库了。

## 行为说明

- 请求进入业务逻辑之前，入参中所有 `string` 会被执行 `Trim()`，包括嵌套对象、数组元素、字典的值。
- 覆盖 `[FromBody]` 的 JSON、`[FromQuery]` 的查询串、路由参数，三者一致。
- **返回值不会**被 Trim；展示侧若需去空格请自行处理。

## 对接注意

1. 唯一性校验、模糊搜索、精确匹配均以 Trim 后的值为准。
2. 纯空格字符串 Trim 后变为 `""`，必填校验会失败，属预期行为。
3. **长度校验按 Trim 前的原始值计算。** 后端的 `MaxLength` / `StringLength` 判定发生在 Trim 之前，例如上限 50 的字段传入「50 个字符 + 末尾 1 个空格」会直接返回校验失败，而不是先去掉空格再放行。因此前端提交前**仍建议自行 Trim**，不要依赖后端兜底来规避长度报错。
4. 库里 2026-07-31 之前写入的历史数据可能仍带首尾空格，做精确匹配时请留意。
