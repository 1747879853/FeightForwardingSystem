# Keys 精确搜索 — 涉及接口总览

本次在多个查询入参上新增 `List<string> Keys`。本文是**唯一总入口**，只列接口与覆盖字段；各模块细节见文末分文档。

## 1. 统一规则

| 项 | 规则 |
| :-- | :-- |
| 匹配方式 | **精确相等**（SQL `IN`），不是 `keyword` 的模糊 `Contains` |
| 列表内部 | OR：任意一个 key 命中该接口覆盖字段中的**任意一个**即可 |
| 与 `keyword` 及其它筛选 | AND |
| 空值 | `null` / 空列表 / 全是空白项 → 不筛 |
| 单项处理 | 去空白、`Trim`、去重后再进查询。统一走基类 `CsprojBuilderAppServiceBase.NormalizeKeys`，无有效项返回 `null` |
| GET 传参 | 重复 query 键：`keys=MBL001&keys=CO20260001` |
| 不要写成 | `keys=MBL001,CO20260001`（会被当成一个精确值 `"MBL001,CO20260001"`） |
| 前端交互 | 统一走 `#/utils/keys-search` 的 `createKeysSearchSchema`，组件是**普通输入框**（不再是 Select tags 打标签）；多个值直接用中英文逗号、顿号、分号、竖线、空格或换行分隔，也可从 Excel 整列粘贴。提交时由 `normalizeKeysParam` 拆分、去空白、去重后再按 repeat 键名下发，因此后端拿到的仍是 `List<string>` |

`keys` 的覆盖字段**跟该接口原来的 `keyword` 对齐**，接口之间并不相同。银行流水没有 `keyword`，`keys` 对齐的是流水号。
