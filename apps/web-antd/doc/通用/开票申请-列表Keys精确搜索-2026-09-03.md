# 1. 背景意图 (Background)

`keyword` 是单值模糊匹配费用对应业务的主提单号、委托编号。本次新增 `keys` 做精确多值搜索。

# 2. 核心逻辑变更

`InvoiceApplicationQueryDto`、`InvoiceApplicationFeeQueryDto` 均新增 `List<string> Keys`。覆盖字段与各自 `keyword` 相同：主提单号、委托编号（不含订舱编号；订舱编号仍用独立的 `bookingNum` 模糊条件）。

| 接口 | 路径 |
| :-- | :-- |
| 开票申请列表 | `GET /api/services/app/InvoiceApplicationAdmin/GetPagedListAsync` |
| 选可开票费用 | `GET /api/services/app/InvoiceApplicationAdmin/GetOrderFeeGroupAsync` |

匹配规则：精确相等、列表内 OR、与 `keyword` 同时传时为 AND。GET 用 `keys=A&keys=B`。

# 3. 避坑指南 (Blockers)

> [!IMPORTANT] **`keys` 不含订舱编号。** 本模块 `keyword` 本来就只搜主提单号和委托编号，按订舱号精确找费用请用 `bookingNum`（仍是模糊）。
