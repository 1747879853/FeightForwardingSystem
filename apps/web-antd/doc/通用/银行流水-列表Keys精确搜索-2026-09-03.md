# 1. 背景意图 (Background)

银行流水列表没有 `keyword`，模糊搜流水号用的是 `bankStatementNo`。本次新增 `keys`，一次传入多个流水号做精确匹配。Admin 端与非 Admin 端共用 `BankStatementQueryDto`，两边列表和分组统计一起生效。

# 2. 核心逻辑变更

`BankStatementQueryDto` 新增 `List<string> Keys`，精确匹配 `BankStatementNo`。

| 接口 | 路径 |
| :-- | :-- |
| Admin 列表 | `GET /api/services/app/BankStatementAdmin/GetPagedListAsync` |
| Admin 分组 | `GET /api/services/app/BankStatementAdmin/GetGroupedListAsync` |
| 非 Admin 列表 | `GET /api/services/app/BankStatement/GetPagedListAsync` |
| 非 Admin 分组 | `GET /api/services/app/BankStatement/GetGroupedListAsync` |

`GetReceiveSettlementPagedListAsync` 没有关键字类字段，本次不加 `keys`。

匹配规则：精确相等、列表内 OR、与 `bankStatementNo` 同时传时为 AND。GET 用 `keys=A&keys=B`。

# 3. 避坑指南 (Blockers)

> [!IMPORTANT] **本模块 `keys` 只认流水号。** 不要拿主提单号/委托编号来搜银行流水列表，那些字段不在流水主表上。

> [!IMPORTANT] **GET 列表要用重复 query 键。** `keys=A,B` 会被当成一个精确值 `"A,B"`。
