# 1. 背景意图 (Background)

**白话解释：** 前端或调用方传入的字符串常带首尾空格（复制粘贴、输入框未清理等），会导致唯一性校验误判、模糊查询不准、入库脏数据。需要在 `CsprojBuilder.Application` 全部 ApplicationService 的增删改查入参上统一 Trim，而不是在每个业务方法里手写。

# 2. 核心逻辑变更 (Core Changes)

在 Application 层注册 Castle 拦截器，对所有实现 `IApplicationService` 的服务：

1. 方法调用前递归 Trim 入参中的 `string`（含嵌套 DTO、`List<T>`、`string[]`、字典的值）。
2. 拦截器插入链最外层（`Insert(0)`），保证先于 ABP Validation，使 `[Required]` / `MaxLength` 等基于 Trim 后的值校验。
3. 可选跳过：属性 / 参数 / 类型上标记 `[DisableStringTrim]`。

涉及文件：

| 文件                                       | 说明                       |
| :----------------------------------------- | :------------------------- |
| `Shared/StringTrimInterceptor.cs`          | 拦截器                     |
| `Shared/StringTrimInterceptorRegistrar.cs` | 注册到 IApplicationService |
| `Shared/StringTrimHelper.cs`               | 递归 Trim 工具             |
| `Shared/DisableStringTrimAttribute.cs`     | 跳过标记                   |
| `CsprojBuilderApplicationModule.cs`        | PreInitialize 中初始化注册 |

# 3. 避坑指南 (Pitfalls)

> [!IMPORTANT]
>
> 1. 只处理**入参**，不处理返回值；库里历史脏数据不会被读接口自动清理。
> 2. 密码等若必须保留首尾空格，给属性或参数加 `[DisableStringTrim]`（当前默认也会 Trim，与既有 `Password.Trim()` 行为一致）。
> 3. 只读集合中的 `string` 元素无法就地替换；业务入参请用 `List<string>` / `string[]`。
> 4. 内部直接 `new` DTO 再调私有逻辑、未走 AppService 代理时，不会触发拦截器。
