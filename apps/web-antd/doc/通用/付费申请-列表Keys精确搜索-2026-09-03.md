# 1. 背景意图 (Background)

列表关键字 `keyword` 是单值模糊匹配。本次需要一次传入多个单号、且必须整段相等才算命中，因此新增 `keys`。覆盖字段与各接口原有 `keyword` 相同。

# 2. 核心逻辑变更

## 2.1 入参

| DTO | 新增字段 | 精确匹配字段（与 keyword 相同） |
| :-- | :-- | :-- |
| `PaymentApplicationQueryDto` | `List<string> Keys` | 主提单号、订舱编号、委托编号 |
| `PayAppFeeGroupInputDto` | 同上 | 同上 |
| `PayAppTaskItemQueryDto` | 同上 | 同上 |

查询 DTO 不对应实体，不挂 AutoMap。

## 2.2 匹配规则

| 项           | 规则                                   |
| :----------- | :------------------------------------- |
| 匹配方式     | 精确相等（`IN`），不是 `Contains` 模糊 |
| 列表内部     | OR：任意一个 key 命中上述任一字段即可  |
| 与 `keyword` | AND                                    |
| 空值         | `null` / 空列表 / 全是空白项 → 不筛    |
| 单项处理     | 去空白、`Trim`、去重后再进查询         |

GET 传参：`keys=MBL001&keys=CO20260001`。不要写成逗号拼接的一个字符串。

## 2.3 生效接口

| 接口 | 路径 |
| :-- | :-- |
| 付费申请列表 | `GET /api/services/app/PaymentApplicationAdmin/GetPagedListAsync` |
| 选可申请费用 | `GET /api/services/app/PaymentApplicationAdmin/GetOrderFeeGroupAsync` |
| 付费结算选申请 | `GET /api/services/app/PaymentApplicationAdmin/GetPagedListForSettlementAsync` |
| 付费结算选申请(按原币拆行) | `GET /api/services/app/PaymentApplicationAdmin/GetPagedListByCurrencyForSettlementAsync` |
| 审核任务列表 | `GET /api/services/app/PaymentApplicationAdmin/PayAppTaskListAsync` |

# 3. 避坑指南 (Blockers)

> [!IMPORTANT] **`keys` 不是模糊搜索。** `keyword=ABC` 能命中 `ABCD123`；`keys=ABC` 只能命中字段值恰好等于 `ABC` 的单据。

> [!IMPORTANT] **GET 列表要用重复 query 键。** 正确：`keys=A&keys=B`。`keys=A,B` 会被当成一个精确值 `"A,B"`。
