# 1. 背景意图 (Background)

**白话解释：** 系统中 `User` 实体已禁用父类 `AbpUser` 的 `Name` / `Surname` 字段（`private new` + `[NotMapped]`），真实姓名统一存放在 `NickName` 字段（`username` 为登录名，`NickName` 为真实姓名）。

历史代码中仍有多处在关联 `User` 表时返回 `Name`（即 `AbpUser.Name`），这既不符合“真实姓名=NickName”的约定，也存在取不到值/无法映射到数据库列的风险。

本次按项目约定 **“所有关联 User 表查 name 的，都需要返回 nickname，不要返回 name”** 进行统一排查与修复（`User` 自身的 Service 方法除外）。

# 2. 核心逻辑变更 (Core Changes)

将所有“通过关联/Join `User` 表获取姓名”的位置，由返回 `Name` 改为返回 `NickName`：

- 投影 `Select(... u.Name ...)` 改为 `u.NickName`；同时存在 `u.Name, u.NickName` 的投影，移除冗余的 `u.Name`。
- 消费端 `?.Name` / `.Name` 改为 `?.NickName` / `.NickName`。
- `user?.Name ?? user?.UserName` 形态改为 `user?.NickName ?? user?.UserName`（保留登录名兜底）。

# 3. 避坑指南 (Pitfalls)

> [!IMPORTANT]
>
> 1. `User.Name` / `User.Surname` 已被 `private new` + `[NotMapped]` 禁用，业务侧严禁再用它取真实姓名，统一使用 `NickName`。
> 2. `UserName` 是登录名，与真实姓名不同。本次报价模块 `QuotationUserName` 原先返回的是登录名 `UserName`，按“关联用户表返回真实姓名”的口径改为 `NickName`；若该字段确需展示登录名，请单独回退此处。
> 3. `User` 自身的 Service 方法（如 `UserAppService` / `UserAdminAppService`）不在本次范围内，保持原有逻辑。
