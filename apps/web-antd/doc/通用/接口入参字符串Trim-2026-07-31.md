# 1. 背景意图 (Background)

**白话解释：** 2026-07-29 上线的「接口入参字符串统一 Trim」实测完全没有生效，前后空格照样进库。排查后确认不是 Trim 逻辑写错，而是拦截器根本没被挂上去，一次都没触发过。本次把实现方式从 Castle 拦截器换成 MVC 全局过滤器，让该功能真正生效。

# 2. 核心逻辑变更 (Core Changes)

## 2.1 失效根因

| 环节 | 事实 |
| :-- | :-- |
| Controller 来源 | `CsprojBuilderWebCoreModule` 调用 `CreateControllersForAppServices(...)`，AppService 直接充当 Controller |
| 激活方式 | ABP 在 `AbpServiceCollectionExtensions` 里把 `IControllerActivator` 换成 `ServiceBasedControllerActivator`，按**具体类**从 Windsor 解析 |
| 注册方式 | ABP `BasicConventionalRegistrar` 使用 `WithService.Self()` + `WithService.DefaultInterfaces()`，`ComponentModel.Services` 里含类本身 |
| 代理类型 | Services 含类 → Windsor 生成**继承式类代理**，而非接口代理 |
| 致命限制 | 类代理只能拦截 `virtual` 方法；本项目 `App` 目录下 `public virtual Task` 命中数为 **0** |

结论：`StringTrimInterceptor` 对任何 HTTP 请求都不会触发。

之所以一直没被发现，是因为 ABP 在 ASP.NET Core 下的校验、审计、工作单元、权限全部走 MVC 过滤器（`AbpValidationActionFilter` / `AbpUowActionFilter` / `AbpAuthorizationFilter` 等），不依赖 Castle 拦截器，所以只有纯拦截器实现的 Trim 静默失效，其余横切能力表现正常。

## 2.2 新实现

在 MVC 层加全局 `IActionFilter`，卡在**模型绑定完成之后、Action 执行之前**，对 `context.ActionArguments` 就地 Trim。MVC 在 Action Filter 跑完后会重新从 `ActionArguments` 取值拼装调用参数，因此替换字典的值（含裸 `string` 参数）会真正作用到 Action 上。

涉及文件：

| 文件 | 操作 | 说明 |
| :-- | :-- | :-- |
| `Shared/StringTrimActionFilter.cs` | 新增 | 全局 ActionFilter，遍历 `ActionArguments` 执行 Trim |
| `Shared/StringTrimHelper.cs` | 保留 | 递归 Trim 工具，被过滤器复用 |
| `Shared/DisableStringTrimAttribute.cs` | 保留 | 跳过标记，属性/参数/类型三处均生效 |
| `Startup.cs` | 修改 | `options.Filters.AddService(typeof(StringTrimActionFilter))`，排在 `PropMaskActionFilter` 之前 |
| `Shared/StringTrimInterceptor.cs` | **删除** | 死代码，从未触发 |
| `Shared/StringTrimInterceptorRegistrar.cs` | **删除** | 同上 |
| `CsprojBuilderApplicationModule.cs` | 修改 | 移除 PreInitialize 中的拦截器注册及相关 using |

## 2.3 过滤器执行顺序

`AddControllersWithViews` 在 `Startup.ConfigureServices` 第 96 行，`services.AddAbp<...>` 在第 281 行；两者的 `MvcOptions` 配置委托按注册先后执行，全局过滤器 `Order` 均为 0 时按插入顺序执行。因此实际顺序为：

`StringTrimActionFilter` → `PropMaskActionFilter` → `AbpAuthorizationFilter` → `AbpAuditActionFilter` → `AbpValidationActionFilter` → `AbpUowActionFilter` → Action

即 Trim 先于 ABP 校验和业务逻辑。

# 3. 避坑指南 (Pitfalls)

> [!IMPORTANT] **1. DataAnnotations 校验用的是 Trim 前的值。** `MvcActionInvocationValidator.SetDataAnnotationAttributeErrors()` 直接读 `ActionContext.ModelState`，而 ModelState 在**模型绑定阶段**就已算完，早于任何 ActionFilter。所以 `[MaxLength]` / `[StringLength]` / `[RegularExpression]` 判定的是原始值：50 长度上限 + 末尾一个空格的 51 字符输入会被 400 拒绝，不会先 Trim 成 50 再放行。 `[Required]` 不受影响，`RequiredAttribute` 内部本来就按 Trim 后判空。ABP 的 `ICustomValidate` / `IShouldNormalize` 和业务代码里的手写校验都在 Action 内部，拿到的是 Trim 后的值。

> [!IMPORTANT] **2. 只覆盖 HTTP 入口。** body、query、route 参数都落在 `ActionArguments` 里，全部覆盖。覆盖不到的是：后台任务、SignalR Hub、AppService 之间的内部互调。这些场景需要 Trim 请显式调 `StringTrimHelper.TrimStrings(dto)`。

> [!IMPORTANT] **3. 不要再往 AppService 上加 Castle 拦截器。** 只要方法不是 `virtual`，任何基于 `IApplicationService` 的 Castle 拦截器在本项目都是死代码。要做方法级横切，写 MVC 过滤器，或者给目标方法显式加 `virtual`。

> [!IMPORTANT] **4. 只处理入参，不处理返回值。** 库里 2026-07-31 之前写入的历史脏数据不会被读接口自动清理。

> [!IMPORTANT] **5. 只读集合中的 `string` 元素无法就地替换。** 业务入参请用 `List<string>` / `string[]`，不要用 `IReadOnlyList<string>`。
