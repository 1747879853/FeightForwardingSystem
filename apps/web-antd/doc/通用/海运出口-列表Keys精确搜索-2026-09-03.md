# 1. 背景意图 (Background)

列表关键字 `keyword` 是单值模糊匹配。本次需要一次传入多个关键字、且必须整段相等才算命中（例如批量提单号/委托编号精确查找），因此新增 `keys`。

# 2. 核心逻辑变更

## 2.1 入参

`SeaExportQueryDto` 新增 `List<string> Keys`。查询 DTO 不对应实体，不挂 AutoMap。

覆盖字段与 `keyword` 相同：

- `Vessel`（船名）
- `InnerVoyno`（船公司航次）
- `TransportOrder.Remark`（业务备注）
- `TransportOrder.MblNum`（主提单号）
- `TransportOrder.BookingNum`（订舱编号）
- `TransportOrder.ContractNum`（合同号）
- `TransportOrder.CommissionNum`（委托编号）

**不含**码头航次 `TerminalVoyno`（与 `keyword` 一致）。

## 2.2 匹配规则

| 项           | 规则                                   |
| :----------- | :------------------------------------- |
| 匹配方式     | 精确相等（`IN`），不是 `Contains` 模糊 |
| 列表内部     | OR：任意一个 key 命中上述任一字段即可  |
| 与 `keyword` | AND：两个都传时必须同时满足            |
| 空值         | `null` / 空列表 / 全是空白项 → 不筛    |
| 单项处理     | 去空白、`Trim`、去重后再进查询         |

GET 传参示例：

```
GET /api/services/app/SeaExportAdmin/GetPagedListAsync?keys=MBL001&keys=CO20260001&pageIndex=1&pageSize=10
```

## 2.3 生效接口

过滤写在 `BuildSeaExportFilterQuery`，因此以下两个接口同时生效：

- `GET /api/services/app/SeaExportAdmin/GetPagedListAsync`
- `GET /api/services/app/SeaExportAdmin/GetGroupedListAsync`

# 3. 避坑指南 (Blockers)

> [!IMPORTANT] **1. `keys` 不是模糊搜索。** `keyword=ABC` 能命中 `ABCD123`；`keys=ABC` 只能命中字段值恰好等于 `ABC` 的单据。批量粘贴提单号走 `keys`，用户输入联想走 `keyword`。

> [!IMPORTANT] **2. GET 列表要用重复 query 键。** 正确：`keys=A&keys=B`。不要指望逗号分隔 `keys=A,B` 会被拆成两项（会当成一个精确值 `"A,B"`）。

> [!NOTE] **3. 与其它筛选仍是 AND。** `keys` 只放宽「多个关键字之间」的关系。再加 `polId`、`carrierId` 等条件时，必须同时满足。
