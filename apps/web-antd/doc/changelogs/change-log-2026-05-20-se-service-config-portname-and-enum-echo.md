# 海运出口港口服务项配置起运港与枚举回显修复

## 背景意图

`/basic-data/se-service-config` 列表中“起运港”展示口径与业务预期不一致，且服务项类型在部分数据形态下存在枚举文案回显不稳定的问题，影响列表识别和编辑效率。

## 核心逻辑变更

1. 列表“起运港”列统一按 `portName` 回显，并保留 `pol.portName`、`pol.cnName` 的兼容兜底，避免历史数据结构差异导致空值。
2. 服务项类型列表展示新增多级回显策略：优先使用后端直接返回的枚举文案字段（`serviceTypeName` / `serviceTypeDisplayName`），否则回退到前端枚举映射。
3. 编辑弹窗详情回填时，对 `serviceType` 做数值化归一处理，修复枚举值在字符串/数字混用场景下下拉不选中、标题不显示枚举文案的问题。

## 避坑指南

- 若后端返回 DTO 字段存在扩展（如 `portName`、`serviceTypeName`），请同步更新前端类型声明，避免类型检查误报。
- 枚举字段参与下拉回填时，建议统一进行 `Number` 归一，规避 `"1"` 与 `1` 的严格匹配差异。
- 列表展示尽量优先使用后端提供的“已翻译文案字段”，前端枚举映射仅作为兜底，避免枚举缓存未刷新时出现数字值直出。
