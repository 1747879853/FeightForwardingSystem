# 提单签出审核决策信息前置

## 背景意图

放单前要先认出压单和这个客户一共欠多少。申请放单把「是否压单」放在表格末尾，摘要只有本批未收，空列和顶上的操作条占掉首屏。

## 核心逻辑变更

- 申请放单里只要有压单，该行用淡橙底，并在行首显示红色「压单」。整批都没有压单时，不占这一列。
- 摘要增加「客户欠款」，把本页应收欠费按本位币加总未收。其中超期天数大于 0 的部分，用红色写在标题旁。本批未收仍单独一格，并改名为「本批未收」。没有欠费报表权限时显示「未能读取」。
- 金额和天数列右对齐。申请放单、压单业务、后续新单在结算对象都一样时不再重复这一列。分提单号、超期备注、审核人、审核意见整列为空时隐藏；有内容的列仍显示。审核结论继续放在状态浮层里。
- 通过和驳回改到申请放单表格下方，表格滚动时操作条留在抽屉底部。通过是主按钮，驳回是危险色幽灵按钮。全选只勾当前可审核的提单；全部通过先勾上可以通过的，再弹出原来的确认框。
- 摘要高度压低。页签上的数量改成浅底圆角胶囊。金额下面的虚线仍然表示可以悬浮查看折算前原币；没有原币明细时不画虚线。

## 避坑指南

- 客户欠款按本位币分开加，不要把人民币和美元合成一个数。超期只统计 `overdueDays > 0`，当天到期和未到期不写进「超期」。
- 应收欠费表仍保留结算对象。这张表的合计行按固定列数对齐，藏掉结算对象会让合计错位。
- 全部通过会换成「当前可以通过的提单」，不会把只能驳回的行一起通过。确认之前不会提交。
- 审核人、审核意见要整列都空才隐藏。这一批里只要有一张已经有结论，列就会留下。

## 验证

- 列隐藏、同一结算对象、压单列，以及本位币合计和超期分计的单测通过。
- 本地打开宜必思酒业这批：摘要为申请人、申请时间、提单 / 未完成 2 / 2、本批未收 ￥ 33,546.00、客户欠款 ￥ 145,218.00，摘要格高 58px。申请放单表头没有结算对象、分提单号、超期备注、审核人和审核意见；压单行底色为淡橙，标签为红色「压单」。未收金额右对齐。页签数字是圆角浅底。底栏有全选、全部通过、驳回和通过。全选后为「已选 2 张」，通过按钮变为可点。这 27 笔欠费都还没超期，所以没有红色「超期」金额。没有提交审核。
