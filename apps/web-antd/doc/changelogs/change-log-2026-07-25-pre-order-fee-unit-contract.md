# 2026-07-25 业务联系单费用单位对齐后端重算契约

## 背景意图

后端梳理确认：业务联系单审核通过时，`PreOrderAdminAppService` 会按 `ResolveQuantityByUnit(unit, ...)` **重算**数量与金额并覆盖联系单录入值，可识别的单位字面量只有 `票 / 重量 / 体积 / TEU` + 具体箱型名，**不做任何别名映射**，匹配不上即按数量 `0` 落库；同时只转换 `feeCodeId + currencyId + paySide` 三者齐全的行，缺一即静默丢弃且前端收不到提示。

而前端此前沿用海运出口口径的 `票 / TEU / 尺码 / 毛重 / 件数`，其中 `尺码 / 毛重 / 件数` 三个单位在后端全部落入 default 分支 → 预估页面看着有金额，审核通过后应收应付实际为 `0`。

## 核心逻辑变更

- 新增 `views/pre-order/modules/fee-unit.ts`，把单位契约、别名归一与费用体检集中一处：
  - `PRE_ORDER_GENERIC_UNITS = ['票', '重量', '体积', 'TEU']`，单位下拉 = 该列表 + 已选箱型名。
  - `normalizePreOrderFeeUnit`：`毛重/KGS/WEIGHT → 重量`、`尺码/CBM/MEASUREMENT → 体积`、`order → 票`；箱型名与未知值原样返回。
  - `checkPreOrderFees`：产出 `errors`（收付/费用代码/币别缺失、单位不在可识别范围）与 `warnings`（按当前单位算出的数量为 0）。
- `fee-table.vue` 带量口径逐条对齐后端：`票=1`、`重量=kgs`、`体积=cbm`、`TEU=Σ(箱型 teu × 箱量)`、`箱型名=箱量`（应收另带箱型卖价），**其余一律置 0**（原先保留旧数量，与落库结果不符）。
- 数量列改为**始终只读**，由单位派生（tooltip 说明后端会按单位重算覆盖）；箱型卖价/箱量或货物毛重/体积变化后，`syncDerivedRows` 全表按单位重新带量，避免与后端重算结果漂移。
- 费用代码带出的默认单位先归一；若归一后仍不可识别（如「件数」），退回「票」并提示用户。
- 详情/复制回显时对 `unit` 做一次归一，历史数据里的「毛重/尺码」自动变成「重量/体积」。
- `editor.vue`：保存时对费用做非阻断提示；**提交审核前硬拦截** `errors`，避免费用行进后端被静默丢弃或算成 0。
- 费用侧不再消费件数：`PreOrderFeeCargo` 与 `feeCargo` 只保留 `kgs / cbm`，`bindCargoMetricsLinkage` 仅监听这两个字段。

## 避坑指南

1. **单位字面量是硬契约**：改动单位下拉前先确认后端 `ResolveQuantityByUnit`（`PreOrderAdminAppService` 与 `SeServiceTaskAdminAppService` 两处实现）是否同步；前端自造别名一定算成 0。
2. **联系单没有「件数」计价**：需要按件数报价时只能改后端加分支，前端不要私自把 `件数` 放回下拉。
3. **数量别再放开手改**：后端一律按单位重算，放开只会让预估与落库对不上；要改数量就改单位或改货物计量/箱量。
4. **三要素校验只挡在提交审核**：保存草稿允许缺费用代码等，但提交前会拦，别把保存当成最终校验。
5. **仍存在的后端侧缺口**（前端拦不住，需后端跟进）：`PreOrderFee` 无数值/机密权限校验、`NoTaxAmount` 恒为 null、费用转换段 `try/catch` 静默吞异常。
