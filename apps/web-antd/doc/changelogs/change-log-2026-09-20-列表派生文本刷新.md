# 背景意图

海运出口港口列修复后，对其它列表的跨字段和集合派生文本继续排查。VXE formatter 缓存只比较 column.field；接口数据或行内集合改变而该字段不变时，会显示旧文本。

# 核心逻辑变更

- 新增 `utils/row-text-column.ts`：多字段派生列通过函数插槽读取当前行，安全渲染纯文本，导出用同一取值函数。单字段正常格式化保持原样。
- 18 份列配置中的 64 处派生文本定义改为显式使用该工具；动态币别列会生成多列。覆盖海出/海进/空运人员与收发通、空运重量与机场、联系单港口、监装船名航次、客户身份、对账金额、付款关联单号、审核港口、运价日期、提成生效期间、权限条件显示文案、港口回退等。
- 菜单管理源码的链接/内嵌地址也改为实时派生；该菜单路由当前注释，本次不启用。
- 保留 field、排序映射、用户列设置及权限包装；海出默认列应用补显式列类型，并允许 VXE 的字符串宽度，避免泛型推断丢失列结构。

# 避坑指南

- 单纯读取主字段的日期/枚举 formatter 不受此问题影响，不应全局替换。
- 已有具名业务插槽不能被普通文本插槽覆盖。运价订舱代理、船公司和箱型报价使用现有业务插槽，保留交互实现。
- 更正上次排查记录：运价订舱代理只在直接调用其 formatter 的模拟中复现，真实单元格走 bookingAgentId 插槽，因此不能算已确认页面缺陷。
- 函数插槽需经字段权限包装转发；受限行仍显示 \*\*\*。保留列键，避免用户配置迁移和排序行为变化。

# 验证

- 真实 VXE Grid 加载同一票两次，验证人员、港口、金额、航次、手填文本刷新；覆盖原地集合变动、零值、清空、文本转义和导出。
- 字段权限测试验证函数插槽转发、掩码、原列键及排序，共 10 项通过；文本列组件测试 2 项通过。
- 抽取真实业务列执行 12 个回归样例，显示值与导出值均更新。
- 全项目 vue-tsc 检查仍存在历史错误；另对改动文件使用 HEAD 源码作为基线比较类型诊断；本次暴露的海出列泛型约束已修正，海出列配置、默认列工具和新文本列工具的定向类型检查为零错误。
- 未执行各页面真实业务保存操作，未部署。
