# 工作台动态列回退默认港口配置

## 背景意图

工作台海运出口业务列表按当前起运港、当前服务项的 `seServiceShows` 生成动态列。此前港口专属配置缺少该服务项或未配置展示字段时，列表直接退化为无业务动态列，没有沿用系统已有的默认港口配置。

## 核心逻辑变更

1. 当前服务项存在非空 `seServiceShows` 时继续优先使用港口专属配置。
2. 当前服务项没有动态列配置时，懒加载 `POLId = null` 的默认港口配置，并按相同 `serviceType` 读取 `seServiceShows`。
3. 默认配置详情在页面生命周期内缓存；首次加载、刷新、切换港口和切换服务项都会确保回退配置已就绪，但不会重复请求。
4. 「转交任务」节点不使用动态列，也不会触发默认配置查询。

## 避坑指南

- `SeServiceConfigAdmin/GetPagedListAsync` 的 `polId` 是可选筛选条件，省略并不等于筛选 `POLId = null`；实现通过 `POLId ASC` 取首条并再次校验 `polId == null`，再调用详情接口。
- 默认配置只补动态展示字段，不替换当前港口的任务节点、完成校验等其他配置。
- 港口专属 `seServiceShows` 为非空数组时必须保持最高优先级，不能与默认配置合并，否则会改变管理员明确配置的列顺序。
