# 提单顶部数量改为已扣单并下钻筛选

## 背景意图

提单管理顶部四个数量里的待审核已经由后端改成已扣单。页面上的第四张卡要跟着换成已扣单，点下去后列表和分组都只看已扣单。

## 核心逻辑变更

第四张数量卡不再显示待我审核，也不再跳到签出审核。它改成「已扣单」，数字来自数量接口的 `deductedCount`。数量大于 0 时数字为品红，为 0 时与普通数字同色。

点全部提单不附加条件，点待签出仍传 `Status=4`，点超期未收仍传 `IsOverdueUnpaid=true`，点已扣单传 `IsDeducted=true`。分组请求走同一套列表条件，所以点已扣单时分组也会带上 `IsDeducted=true`。只传 `true` 才筛选；查询区里另选了状态时，和已扣单条件取交集。

## 避坑指南

已扣单数量是提单条数，按状态「已扣单」统计，不要再当成审核子任务数。签出审核仍从审核审批菜单进入。`IsDeducted` 传 `false` 或不传都不会筛已扣单。
