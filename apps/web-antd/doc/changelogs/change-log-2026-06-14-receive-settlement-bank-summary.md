# 收费结算表单银行流水摘要与结算进度

## 背景意图

财务在收费结算时需要在同一页面看到银行流水基础信息（总金额、交易备注等），并实时掌握该流水已被其他结算单占用的金额、剩余可结算额度及本单合计，避免与银行流水详情页来回切换。

## 核心逻辑变更

1. 收费结算新建/编辑/只读页在「结算信息」Card 上方新增「银行流水信息」Card，选中或预填流水后展示。
2. 基础字段：流水号、交易时间、总金额、币别、付款方、交易备注、我司银行；数据来源统一为 `BankStatementAdmin/DetailAsync`。
3. 汇总三列：`已结算（不含本单）`、`剩余可结算`、`本单本次合计`。
   - 已结算 = 该流水下其他收费结算单 `totalSettledAmount` 之和（编辑时排除当前 `editId`）。
   - 剩余可结算 = 流水 `amount` − 已结算（不含本单）− 本单明细 `settledAmount` 合计。
   - 本单合计随明细 InputNumber 实时变化。
4. 其他单已结算通过 `GetReceiveSettlementPagedListAsync`（`pageSize=500`）一次拉取汇总。
5. 剩余可结算 ≤ 0 时数值与提示文案标红；保存时若剩余 < 0 则 `message.warning` 阻断提交。

## 避坑指南

- Picker 列表行字段不完整，选中流水后必须走 `DetailAsync`，不要直接复用列表 DTO。
- 编辑态「已结算」必须排除当前结算单，否则本单金额会被重复计入。
- 明细级 `remainingAmount` 与流水级「剩余可结算」是两层校验，InputNumber 的 `max` 仍绑定费用剩余额度。
