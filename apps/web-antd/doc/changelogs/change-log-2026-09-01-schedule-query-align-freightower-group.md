# 船期查询方案分组对齐港到港方案卡

## 背景意图

方案工作台第一版按「直达/中转 + 星期 + 航程 + 两端码头 + 中转港」拆组，同一港口对、同一 ETD、同一 8 周查询会拆出几百张单班卡。对照港到港船期页的方案卡后，确认对方用的是「船公司(航线) 共舱串」作为方案身份，星期只作展示，不按航程/码头/中转港拆开。

本仓库后端仍只转扁平班次接口，没有方案分组接口，因此在前端用全量班次重建同一套分组规则。

## 核心逻辑变更

- 分组键改为 `直达|中转` + `groupName`。`groupName` 有共舱时只用共舱 `船公司(航线)` 去重后按英文字母序以 `/` 拼接；无共舱时退回本班次承运人+航线。
- 计划班期 `routeEtd`（SUN–SAT）只决定卡片上的星期，取组内众数；不再进入分组键，避免同一服务被拆到星期一/三/六多张卡。
- 航程、码头原文、中转港路径不再拆组。卡片航程取组内最大 `totalDuration`/`transitTime`；码头只展示标准化短名众数，空则显示 —。
- 查询结果先丢掉无船名以及船名为 `feeder` / 含 `to be` / `tbn` 的班次，再按 `船名$航次` 去重（保留更早 ETD）。
- 方案卡与班次表改为：星期、最大航程、两端标准码头、`groupName`；表内船名、航次、计划离到港（相对计划时刻的准点/延误）、总航程、详情。一次只展开一组。
- 二次筛选（直达/中转、船公司、标准码头、关键词）仍只作用于已拉取数据。

## 避坑指南

- 前端仍传 `pageSize=9999`，后端转第三方时 **上限 1000**。本次 CNTAO→SGSIN 清洗后 613 条未触顶；超过 1000 条时分组会缺班次。
- 有共舱时不要再把本班次 `carrierCd(routeCode)` 并进 `groupName`：班次上的航线代码经常和共舱里的本线代码不一致，会拼出 `ONE(PS3)/ONE(NPI)` 这种脏串，反而拆组。
- 重建分组做不到与方案接口 100% 逐字一致。完整规则与对照口径见 [方案分组规则](../modules/schedule-query/grouping.md)。青岛→新加坡、ETD 2026-09-01、8 周对照为 **62 组（直达 47 / 中转 15）**，对方 **62 组（直达 46 / 中转 16）**，差在本地多 `WHL(AA1)`、少一组中转 `CNC`。
- 折叠方案不挂载班次表；筛选或改排序后首批仍从 80 个起算（本组 62 个可一次看完）。
- 用户可见文案不出现第三方供应商名称；AIS 未配置时仍提示联系管理员。
