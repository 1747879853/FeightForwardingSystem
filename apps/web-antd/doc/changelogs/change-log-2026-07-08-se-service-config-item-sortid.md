# 港口服务项配置：服务项排序改为维护 sortId

## 背景意图

原实现通过「上移/下移」调整服务项顺序，保存时用数组下标覆盖 `sortId`。业务希望直接维护排序数值，数字越小越靠前，便于批量配置与跨环境对齐。

## 核心逻辑变更

- 服务项明细新增「排序」输入框（`InputNumber`，最小值 0）。
- 移除「上移/下移」按钮及 `moveUp` / `moveDown` / `moveItem` 逻辑。
- 弹窗内服务项列表通过 `sortedItemRows` 按 `sortId` 升序展示；修改排序值后界面即时重排。
- 提交时 `sortId` 取用户维护值，不再用数组 index 覆盖。
- 新增服务项默认 `sortId = max(现有 sortId) + 1`（首条为 0）。
- 编辑回显继续从详情 `sortId` 映射到 `ItemRow`。

## 避坑指南

- 列表页、工作台等消费方已按 `sortId` 升序读取，与本次弹窗口径一致。
- 同一配置内若多条服务项 `sortId` 相同，展示顺序以排序算法稳定次序为准，建议维护唯一递增值。
