# 编辑页固定本页业务 ID

## 背景意图

多个页面用计算属性读取全局 `route.params.id`。缓存页切走后实例还在，或者切页瞬间监听还在，就会把别的单据 ID 传进当前页，并触发详情或审核流程请求。

## 核心逻辑变更

- 用户编辑页已开缓存。打开时记下用户 ID，基础信息、最终权限、角色、银行账户和修改密码都用这个 ID。
- 银行流水编辑页去掉对流水 ID 的监听，只在进入页面时按打开时的 ID 拉详情。新建保存后仍跳到新的编辑地址，由新页面实例读取新 ID。
- 进项发票详情去掉对发票 ID 的监听。每个详情页只请求自己打开时的那张发票。
- 付费申请编辑页记下打开时的申请 ID，以及是否刚从新建跳入。审核时间轴监听的是这个 ID，切到其他单据不会改拉对方的流程。
- 客户对账、收费核销的编辑路由没有开缓存。ID 只在进入页面，以及保存、锁定等点击时读取，没有在 ID 变化后自动拉详情。收费核销抽屉使用传入的核销单 ID，不读当前路由。这两处本次不改。

## 避坑指南

- 页签按完整地址区分。不同 ID 是不同页面实例，不要再监听全局 `params.id` 来切换同一实例里的详情。
- 新建保存后的 `replace` 会换地址并创建新实例，新实例在创建时读取新 ID，不依赖旧实例跟着路由变。

## 验证记录

- 对照路由缓存开关和调用链：用户编辑会把 ID 传给仍挂着的子面板；银行流水、进项发票在 ID 变化时会请求详情；付费申请的审核时间轴会随 ID 重新请求。
- 客户对账和收费核销没有这条自动请求链。
- 未做登录后的多页签切换验收。
