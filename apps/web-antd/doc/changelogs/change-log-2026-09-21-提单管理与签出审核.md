# 提单管理与签出审核

## 背景意图

根据 [TAPD 母需求 1000152](https://www.tapd.cn/61580498/prong/stories/view/1161580498001000152) 及子需求 1000154—1000157，接入后端已完成的提单模块。开发分支为 `codex/bill-of-lading`，从本地 `main` 创建。

已同步后端仓库，契约来源为 `D:\code\Freight\aspnet-core\文档\提单\提单模块接口文档.md`（2026-09-21）和同目录总逻辑文档，并核对当前后端提单、分单源码。

## 核心逻辑变更

- 操作管理增加 `/bill-of-lading`：检索、主分单列、四个数量、委托单位/船公司/签单方式分组、详情与历史。勾选后从顶部操作，无操作列；列直接使用对象路径。
- 接入签入、取消签入、换签、取消换签、扣单、取消扣单、签出、取消签出。打开操作前重新取详情校验状态；签入扫描件限一个，提交时等待上传完成；历史保留取消记录和附件查看入口。
- 提交审核按行级 `settlement.id` 限制同批，逐张根据 `isOverdue` 要求承诺日期、备注和证明；撤销按 `taskBaseId` 整批执行。
- 审核审批增加 `/audit-approval/bill-of-lading-review`：默认待我审核，一次提交一行；详情展示申请放单业务、压单业务、后续新单、客户信息、应收欠费、客户历史异常和审批流程。只在一个批次内勾选提单，审核接口传提单 ID。支持原通过人的通过后驳回。
- 海出主单新建/单条编辑签单方式必填；分单增加必填结算对象和只读应结日期，更改结算对象时清空旧日期，保存重拉后显示后端重算日期。
- 工作流增加提单签出类型 11 和条件 11001/11002/11003。客户条件保留 Guid，组织保留雪花 ID 字符串；用户属性审核在配置入口与保存处均拦截。

## 避坑指南

- 接口统一为 `/api/services/app/BillOfLadingAdmin/{方法}Async`；请求客户端已有 `/api` 前缀。没有提单新增/编辑/删除接口，也不创建独立申请单。
- 列表 `isOverdueUnpaid=true` 与提交的 `isOverdue` 是两个口径；待我审核数量是子任务数，不是审核列表行数。
- 分组空值传 `CarrierIdEmpty` / `CodeIssueTypeIdEmpty`，不与具体 ID 同传。改变检索条件后清理旧分组下钻。
- 分单提单提交比结算对象；未收金额和提交超期判定仍按主单，分单日期不用于承诺日期校验。
- 附件先上传，操作请求只传附件 ID 等字段；签入模块 160130、超期证明模块 160140 由后端绑定。
- 审核详情的客户/欠费为空时独立显示空态；不额外请求需要其它权限的接口。
- 上线前需要启用提单签出工作流，基础资料需有「正本」「电放」。存量业务不补建提单，已有分单缺结算对象时需补齐。

## 验证

- `pnpm exec vitest run --config apps/web-antd/vitest.bill-of-lading.config.ts`：8 项通过，覆盖状态机、分单结算对象、审核人限制、空分组、ID 精度、接口地址和工作流序列化。
- `pnpm -F @vben/web-antd exec vite build --mode jytest`：通过。
- 本地浏览器连接测试后端：提单卡片总数与分页均为 2；船公司分组各 1 条，下钻结果一致；非正本已签入行启用扣单/提交；超期缺材料确认被拦截；审核列表默认待我审核并正常显示空态。
- 浏览器验证未创建测试数据、上传附件或提交流转/审核。因此完整签入到签出与部分审核仍需使用指定测试数据做联调验收。
- 全量类型检查被仓库既有错误阻塞；本次新增页面的类型错误已修正。直接 ESLint 命令因仓库无根级配置无法执行，未将其记为通过。
