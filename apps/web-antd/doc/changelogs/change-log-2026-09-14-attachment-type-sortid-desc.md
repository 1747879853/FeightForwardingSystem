# 业务附件类型按原始 sortId 降序

## 背景意图

附件类型管理列表默认 `SortId DESC`（值越大越靠前）。各业务附件分组此前有的升序、有的把手动添加/历史类型垫到末尾（`5000`/`9999`），和类型自己的排序号不一致。要求所有模块一律用类型原始 `sortId` 降序，手动加的类型不特殊处理。

## 核心逻辑变更

- 抽出 `compareAttachmentTypeSortIdDesc`，海出 / 海进 / 空出 / 客户 / 业务联系单 / 付费申请 / 付费审批附件分组共用。
- 手动添加类型、模块外历史组都读类型原始 `sortId`（缺省 `0`），不再用 `5000`/`9999` 垫底。
- 「添加其他类型」下拉同样降序。
- 海出监装照片槽位、小程序监装箱照槽位同样按原始 `sortId` 降序混排。
- 组内文件仍跟接口 `items`（后端 `DisplayOrder` 升序）。

## 避坑指南

- `GetListAsync` / `GetListByModuleTypesAsync` 后端仍升序返回，展示顺序以前端为准。
- 不要再给手动类型写假 `sortId`，否则会插到错误位置。
- 未分类（无类型）没有原始 `sortId`，按 `0` 参与降序。
