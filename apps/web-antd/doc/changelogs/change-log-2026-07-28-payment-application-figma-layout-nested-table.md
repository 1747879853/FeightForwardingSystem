# 付款申请表单按 Figma 重排并引入 NestedDataTable

## 背景意图

付款申请新增/编辑页（共用 `form.vue`）按设计稿重做视觉与信息架构：顶部操作条、申请人信息、费用合计/银行、费用明细与工作流分区更清晰；费用明细改用可展开的嵌套表，并支持页内筛选，便于在大量费用中定位订单组。

## 核心逻辑变更

- 新增通用组件 `NestedDataTable`：外层订单组 + 内层费用明细，支持受控展开、`outer/inner` 插槽与滚动高度。
- `form.vue` 布局重构：申请号顶栏、状态章/插画资源、费用筛选（编号/费用名/委托单位/币别/ETD）、费用合计与银行绑定区重排；导出 `FeeNameSelect` 供筛选使用。
- `add-fee-modal` / `form-data` 透传 `clientId`，订单分组携带委托单位 id，支撑页内按委托单位筛选。
- 外层列宽统一为设计稿等分宽度；内层去掉独立 checkbox 列，序号列保留。

## 避坑指南

- 新增与编辑共用同一 `form.vue`，布局改动会同时影响 `/add` 与 `/:id/edit`。
- 页内筛选只过滤已加载的 `orderGroups` 展示，不重新请求添加费用接口。
- `NestedDataTable` 展开态由父组件 `expandedRowKeys` 控制，筛选后需注意展开键与当前可见行是否仍匹配。
