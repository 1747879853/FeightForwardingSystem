# 更改单编辑工作流重构（选择 → 编辑 → 确认利润 → 整体保存）

- 日期：2026-07-21
- 范围：海运出口更改单页面（`sea-export-admin/changeOrder`）及其复用的费用表组件
- 类型：Feature / Refactor（前端交互与信息架构优化，无后端接口变更）

## 背景意图

更改单页面原为「更改单列表 + 应收表 + 应付表」纵向堆叠，主任务不突出，用户难以判断：当前在编辑哪张更改单、哪些修改未保存、顶部「保存」的作用域、锁定后还能做什么。本次按评审文档把页面重构为清晰的「选择更改单 → 编辑费用 → 确认利润 → 整体保存」工作流。

## 核心逻辑变更

1. **保存语义显性化**：移除更改单列表工具栏的重复「保存」按钮；保存唯一入口移到当前更改单详情区右上角，文案为「保存更改单」，明确一次性保存该更改单的基本信息与应收、应付费用。新增保存中 loading、保存时间、`Ctrl/Cmd+S` 快捷键。

2. **状态可见性**：详情区标题展示当前更改单标识与状态标签（已锁定 / 有未保存修改 / 已保存），并显示最近保存时间。

3. **费用应收/应付改为页签**：不再同时纵向展开两张空表；页签标题带条数（如「应收费用 3」）。两个页签均 `force-render` 以保证汇总实时计算。

4. **未保存保护**：切换更改单、删除当前更改单、离开页面（`beforeunload`）时，如存在未保存修改会二次确认或提示；修复了「加载费用被误判为已修改」的脏标记问题（加载期间抑制脏检测）。

5. **锁定只读**：锁定时详情区展示告警（锁定人/时间/联系财务解锁），费用表新增 / 删除 / 保存按钮禁用，并对费用表加只读遮罩，避免编辑到最后被后端拒绝。

6. **新建更改单表单化**：列表「新建更改单」不再插入可编辑行，而是进入详情区录入态；会计期间（MonthPicker）、更改原因（AutoComplete，必填，内置常用原因：代理费调整/汇率调整/漏录费用/客户要求）、备注。保存前校验更改原因必填。

7. **列表按当前票过滤 + 保持选中**：列表查询补传 `TransportOrderId`；父组件监听 `transportOrderId` 就绪后加载列表；保存成功后按更改单 id 重新定位选中行；行选择由双击改为单击。

8. **利润固定汇总栏**：在费用页签下方固定展示应收合计 / 应付合计 / 预计利润 / 利润率（本位币，千分位、两位小数），多币种时展开分币种明细；存在缺失汇率的外币费用时提示「本位币利润暂未完整计算」。

9. **左侧订单摘要瘦身**：默认只展示有值字段，空值字段收进「查看更多订单信息」；卡片支持整体收起/展开。

10. **费用表更改单模式收敛操作**：更改单模式隐藏历史引入、提交审核、撤销提交、设为未完结等主单专用操作，并透传 `parentChangeOrderId`；应收/应付空状态给出「新增费用」引导。

## 避坑指南

- **脏标记时序**：费用表 `dataSource` 深度 watch 会在异步回填时触发 `change`，加载更改单后用 `isLoadingChangeOrder` + 短延时抑制，避免刚切换就被标为「有未保存修改」。
- **KeepAlive 监听**：`Ctrl/Cmd+S` 与 `beforeunload` 监听需在 `onActivated` 重新绑定、`onDeactivated`/`onBeforeUnmount` 解绑，否则切 Tab 回来后快捷键失效。
- **锁定只读为前端防呆**：只读遮罩与按钮禁用不替代后端锁费校验；最终以 `EditAsync`/锁费接口结果为准。
- **保存仍走整包 `EditAsync`**：费用删除在更改单模式下仅本地移除，靠下次「保存更改单」整包提交生效。
