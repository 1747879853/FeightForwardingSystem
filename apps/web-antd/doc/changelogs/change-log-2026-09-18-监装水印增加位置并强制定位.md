# 监装水印增加位置并强制定位

## 背景意图

在监装照片已有上传人、上传时间水印基础上，增加上传设备的当前位置。用户明确要求：定位失败或拒绝授权时禁止上传。

## 核心逻辑变更

- PC 和小程序新增第三行 `上传位置：纬度 xx.xxxxxx，经度 xxx.xxxxxx`，使用 WGS84 坐标，保留六位小数。水印底色高度随行数调整，位置固化在最终 JPEG 文件里。
- 每次选图后重新定位，同批图片共用此次定位结果。PC 禁用定位缓存；不复用上一批位置，不用堆场地址、IP 地址或图片拍摄位置替代设备当前位置。
- 定位失败、拒绝授权、超时、无效坐标均中止该批上传，不生成或上传缺少位置的图片；重试必须重新选择图片。已有附件不受影响。
- PC 使用浏览器定位，高精度优先，15 秒定位超时、20 秒总等待兜底；小程序使用 `uni.getLocation({ type: 'wgs84', isHighAccuracy: true })`，20 秒总等待兜底。
- 小程序新增 `scope.userLocation` 用途说明和 `requiredPrivateInfos: ["getLocation"]`，生成的微信 `app.json` 已验证包含这两项。

## 避坑指南

- PC 必须运行于浏览器允许定位的安全上下文；普通 HTTP 会提示改用 HTTPS，并阻止上传。浏览器或系统拒绝授权时，提示用户开启位置权限后重试。依据 [浏览器定位文档](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition)。
- 小程序须确认微信后台接口权限及用户隐私保护指引已声明位置用途，并在真机授权后验证定位。代码中的 manifest 声明不能替代后台配置。定位 API 说明见 [uni-app 官方文档](https://uniapp.dcloud.net.cn/api/location/location)。
- 当前显示经纬度，不做中文地址逆解析，也不新增第三方位置服务请求。坐标的小数位数不代表设备定位精度保证。
- PC 多选只发起一次定位，失败只提示一次；等待中的每张图均跳过上传。定位超时后的迟到回调不能恢复已经失败的批次。
- 历史图片保持原样，不追补位置，也不修改后端附件接口。

## 验证

- 六个测试文件共 20 项测试通过，覆盖定位成功、权限拒绝、再次定位、超时、无效坐标、坐标为零、三行水印、多图附件提交及画布导出。
- 小程序微信构建通过，定位权限声明已进入构建产物。
- 浏览器真实 Canvas 导出通过，人工查看三行水印，姓名、时间、经纬度均完整可读。
- 全量类型检查仍受既有错误影响；新增定位、水印文件未发现类型错误。
- 未在微信真机或正式站点完成真实定位上传联调。
