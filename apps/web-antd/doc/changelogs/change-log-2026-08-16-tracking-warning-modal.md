# 1. 背景意图 (Background)

运踪面板原来把异常预警明细表常驻在页面底部，绝大多数票没有预警，于是长期显示「异常预警（共 0 条）」加一个空态占位，白占版面还让人以为漏了数据。改为顶部按钮入口，点击才弹窗看明细。

# 2. 核心逻辑变更 (Changes)

## 2.1 新增共享弹窗

新增 `components/tracking/tracking-warning-modal.vue`，按 `kind` 切换列：

| kind    | 列                                          |
| :------ | :------------------------------------------ |
| `ocean` | 发生时间 / 预警类型 / **箱号** / 预警说明   |
| `air`   | 发生时间 / 预警类型 / **发生地** / 预警说明 |

预警说明统一经 `sanitizeVendorText` 清洗；无预警时弹窗内是空态提示。

## 2.2 面板改为按钮入口

海运运踪面板与空运出口运踪 Tab 都删掉底部常驻的预警标题、明细表与空态，改为顶部操作区一个「异常预警」按钮：

- **只有存在预警时才显示按钮**（带条数、`danger` 样式），无预警完全不占位；
- 判断条件统一为 `warnings.length > 0`，不需要再叠加 `loadDetail` 或订阅状态：列表场景拿不到全量明细、未订阅票没有预警，两种情况下 `warnings` 本就是空数组。

顺带删掉两个面板里各自维护的一份预警列定义与行映射（已收敛到弹窗组件）。

# 3. 避坑指南 (Pitfalls)

> [!IMPORTANT] **1. 列表弹窗不会出现这个按钮，是设计如此。** 全量预警明细只在业务单详情里下发，列表场景 `warnings` 恒为空。列表弹窗仍用摘要里的「最近一条预警」Alert 提示，并引导去运踪详情看全部；不要为了「入口一致」在列表弹窗里硬塞按钮，点开只会是空弹窗。

> [!NOTE] **2. 按钮的条数用 `warnings.length`，不是摘要的 `warningCount`。** 摘要计数是后端累计值，明细才是当前落库的实际条数，两者可能不同步；按钮既然直接开明细弹窗，就用明细口径避免「按钮显示 3 条、弹窗只有 2 行」。

> [!NOTE] **3. 弹窗内仍保留空态分支。** 正常路径下按钮只在有预警时出现，走不到空态；保留是为了防止将来把弹窗用在别处（如从预警叹号直接打开）时出现空白弹窗。

# 4. 影响面自检

- 触及文件 `vue-tsc` 无新增报错；
- 预警数据来源与清洗口径未变，仅展示位置改变；
- `sjtd` 品牌海运出口走现有运踪，不受影响。
