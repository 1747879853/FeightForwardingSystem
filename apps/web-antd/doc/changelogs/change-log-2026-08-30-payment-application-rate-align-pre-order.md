# 背景意图

指定结算币别添加费用时，折算弹窗原先只按「今天 + 应付 crValue」预填，并把 RMB/CNY 代码硬编码为 1。业务联系单费用行已经改成：公司本位币优先匹配汇率行、有开船日期按 ETD 筛有效期、未维护且是本位币才兜底 1。付费申请要跟同一套取值，否则同一币别在联系单和付费申请上会对出不同汇率。

# 核心逻辑变更

- 打开折算弹窗仍 `ensureExchangeRateCache(true)`，但 `peekExchangeRate` 传入申请主体所属公司 `localCurrencyId`，以及费用行 `etd`（无则今天）。
- 1 原币兑结算币 = 两边「1 该币兑公司本位币」相除；应付仍取 `crValue`。
- 汇率表未命中时，只有币别等于公司本位币才预填 1；不再用 RMB/CNY 代码判断。
- 同原币、不同开船日拆成多组汇率，回写按 `currencyId + ETD` 对上对应费用行。
- 申请主体切换组织时沿组织串解析所属公司本位币（与预配单 `resolveOrganizationLocalCurrency` 同口径）；编辑态优先读单据 `localCurrencyId`。

# 避坑指南

- 不要再把人民币代码当成本位币。公司本位币可能是 USD，RMB 也要走汇率表。
- 不要按「今天」筛掉 ETD 那天才有效的记录；缓存加载阶段只排除未启用。
- 原币申请、或费用原币已等于结算币，仍然不弹折算窗。
- 交叉相除只用于预填，用户仍可手改；两边都缺有效汇率时留空，须手填后才能确定。
