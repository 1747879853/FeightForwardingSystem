# 海运出口列表与基础信息接入字段权限

日期：2026-09-15

## 背景意图

海运出口已能在权限里配置字段屏蔽，但列表和基础信息表单没有按规则处理：条件屏蔽的单元格仍是空白，非条件屏蔽的列也不会藏起来。需要按报表同一套 PropMask 口径落地。

## 核心逻辑变更

- 条件屏蔽（`alwaysMasked=false`）：列表单元格和基础信息表单显示 `***`。只看后端 JSON 里 key 在不在，不把业务空值当成无权限。
- 非条件屏蔽（`alwaysMasked=true`）：列表直接隐藏该列（列设置里也不可再勾出），对应搜索项隐藏；基础信息表单仍显示 `***`，不拆布局。
- 海出页同时认 `SeaExport` 与 `TransportOrder` 两套规则。保存时剔除已打码字段，避免把 `***` 写回；编辑由后端输入侧回填原值。
- 规则走已有 `use-masked-fields` 缓存；拉取失败 fail-open，不误藏列。

## 避坑指南

- 被屏蔽字段是从 JSON 里消失，不是 `null`。用 `'prop' in obj`，不要用 `== null`。
- 条件屏蔽绝不能整列隐藏，否则未命中条件的行也被藏掉。
- 基础信息表单不要隐藏表单项，统一换成只读 `***`。页头委托编号、归属组织、装运方式等自定义控件同样要打码。
- 服务锁定 `updateSchema` 不能把已打码字段改回可编辑控件。
- 列持久化可能在首查后把隐藏列再显示出来，所以在 `submitForm` 之后再 `hideColumn`。

## 验证

字段权限纯函数单测覆盖：未加载、非条件隐藏列、条件打码、运输单嵌套 key、搜索项、提交剔除。未在浏览器联调真实权限账号。
