# 背景意图

监装照片采集原先一类占一整行，且同一类型可传多张，弹窗和小程序面板都偏长。改成每个附件类型只留一个槽位，类型彼此挨着排成网格，分享页、PC 照片采集、小程序监装处理三处一致。

# 核心逻辑变更

- PC「照片采集」弹窗、小程序监装处理面板、客户公开分享页：类型改为固定边长方格横排，不再一类一行。
- 槽位边长与 antd `picture-card` 一致（PC/分享 104px）；已传缩略图强制 `object-fit: cover`，与空槽等大，避免原图把格子撑开。
- 每个类型最多 1 张：有图则隐藏「添加图片」；PC 关闭多选，小程序相册也只选 1 张。
- 历史上同一类型已有多张时仍全部展示，可逐张删除；删到 0 才能再传。保存仍按箱全量替换，不会自动丢掉多出来的旧图。

# 避坑指南

- **换图要先删再传。** 槽位满了不会覆盖，点「添加图片」会提示「该类型只能上传一张图片」。
- **分享页空类型不占格。** 客户页只渲染已有 URL 的照片；没传的类型不会出现空槽。
- **槽位必须写死边长。** `minmax(104px, 1fr)` 在只有两列时会把格子拉满，原图再把 `min-width: auto` 撑爆，空槽还是小方块。用 `repeat(auto-fill, 104px)`，缩略图宽高都钉死。
- **不要在保存前截断到 1 张。** 历史多图要用户自己删，漏传某组才等于删组。
