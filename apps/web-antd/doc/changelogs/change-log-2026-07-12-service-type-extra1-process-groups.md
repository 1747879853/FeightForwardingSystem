# 背景意图

`ServiceType` 枚举项新增 `extra1`，用于标记服务项目是否属于业务主流程。海运出口配置服务项目时需要按该标记分组，降低服务项较多时的识别成本。

# 核心逻辑变更

- 枚举项新增、编辑、详情 DTO 对接 `extra1`；枚举管理编辑页仅在 `ServiceType` 枚举中展示「是否业务流程」，详情同步展示主流程状态。
- 港口服务项配置弹窗在每条服务项标题栏的「排序」后增加「是否主流程（全局）」开关；保存时先完整提交 `ServiceType` 枚举子表，再保存港口配置。
- 服务项目选项将 `extra1 === true` 映射为 `isBusinessProcess`，服务节点继续保留原有 `sortId`，同时携带流程分类。
- 海运出口「配置服务项目」弹窗改为「主流程 / 非主流程」两组；组内仍按 `sortId`、`serviceType` 排序，顶部 Chevron 流水线的 `sortId` 分组与任务推进规则不变。
- `ServiceType` 改为直接请求后端带缓存的 `GetItemsByNameAsync`，避免浏览器旧枚举缓存缺少 `extra1` 时把所有服务项误归为非主流程。

# 避坑指南

- `extra1` 只属于枚举子项，不应添加到枚举主表或分页列表 DTO。
- 港口服务项中的开关修改的是全局 `ServiceType` 枚举，同一服务项目在所有港口共用该标记，并非港口级独立配置。
- 更新枚举时必须先通过详情接口取得完整子表；`GetItemsByNameAsync` 只返回启用项，不能直接用于编辑提交，否则可能删除未包含的已有子项。
- 只有 `extra1 === true` 才视为主流程；字段缺失、`null` 或 `false` 均归入非主流程。
- 弹窗分组依据 `extra1`，任务执行顺序仍依据港口服务配置的 `sortId`，两种分组语义不可混用。
