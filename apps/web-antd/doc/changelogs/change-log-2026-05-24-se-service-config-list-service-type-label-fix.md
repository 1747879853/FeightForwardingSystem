# 海运出口港口服务项配置 — 列表服务类型显示文本修复

**日期：** 2026-05-24  
**变更类型：** Fix  
**影响模块：** 基础资料 / 海运出口港口服务项配置

---

## 背景意图

列表「服务项类型」列出现 `2、3` 等数字，而非「报关、仓库」等可读文案。根因是列 `formatter` 依赖运行时枚举选项构建映射表，当 `getEnumItems('serviceType')` 未命中或返回空时，映射失败并回退为原始数值。

---

## 核心逻辑变更

### 1. 列定义（`data.ts`）

| 变更项 | 内容 |
| --- | --- |
| 新增 `DEFAULT_SERVICE_TYPE_OPTIONS` | 与后端 `ServiceType` 枚举一致的 6 项兜底文案 |
| 新增 `buildServiceTypeOptionsFromEnum` | 统一从枚举项构建下拉选项，空结果时回退默认选项 |
| 新增 `buildServiceTypeMap` | 默认文案 + 动态枚举合并，枚举优先覆盖默认 |
| 新增 `normalizeServiceTypes` | 兼容 `number[]` 与逗号/顿号分隔字符串 |

### 2. 列表页（`list.vue`）

| 变更项   | 内容                                                             |
| -------- | ---------------------------------------------------------------- |
| 枚举加载 | 先请求 `serviceType`，无结果再请求 `ServiceType`                 |
| 选项构建 | 复用 `buildServiceTypeOptionsFromEnum`，保证筛选下拉与列展示同源 |

---

## 影响范围

- 列表「服务项类型」列：数值 `2、3` 将显示为「报关、仓库」
- 筛选下拉：枚举接口不可用时仍可使用默认 6 项服务类型

---

## 避坑指南

1. **formatter 不要只依赖闭包内的动态 Map**：枚举异步加载失败时，必须有与后端枚举一致的静态兜底。
2. **枚举名称大小写**：本模块需同时兼容 `serviceType` 与 `ServiceType` 两种注册名。
