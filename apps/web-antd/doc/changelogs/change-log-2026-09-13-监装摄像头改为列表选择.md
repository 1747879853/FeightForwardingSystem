# 监装摄像头改为列表选择

日期：2026-09-13

## 背景意图

师傅在现场对照摄像头机身号牌绑定工单。后端台账由 `GetCameraListAsync` 下发并带占用情况，不再要求手填编号。

## 核心逻辑变更

- 已认领详情点「摄像头」才拉 `LoadingOrder/GetCameraListAsync`，其它状态不调该接口。
- 底部列表按名称选择；`isOccupied` 置灰不可选，同公司显示「已被 {工单号} 占用」，跨公司显示「已被其它工单占用」；当前绑定高亮。
- 选中空闲摄像头立即 `EditCameraNoAsync`；解绑仍确认后传 null。保存失败展示后端原文并刷新占用。
- 去掉编号输入、整数校验和单独的保存按钮。取消完成后提示重新选择，而不是重新填写编号。

## 避坑指南

- 应用服务方法保留 Async 后缀；列表入参只有工单 `id`。
- `isOccupied` 只是提前告知，拉完到保存之间别人可能刚占用，真正拦截在保存。
- 已停用摄像头不在列表里；历史工单详情仍可能带出名称，但重新选不到。
- 不要在待认领或已完成状态拉列表，后端会报错。
- 选摄像头只刷新详情，不覆盖未提交的箱型照片草稿。

## 验证

摄像头列表与占用文案回归测试通过。全包类型检查仍有既有错误，本次新增文件未引入新的类型报错。真实摄像头列表需在已认领工单上联调。
