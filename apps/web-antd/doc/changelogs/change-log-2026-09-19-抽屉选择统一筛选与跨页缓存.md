# 抽屉选择统一筛选与跨页缓存

## 背景意图

延伸修复 [TAPD #0916](https://www.tapd.cn/61580498/bugtrace/bugs/view/1161580498001000916)。其他抽屉存在筛选条件变化后旧勾选残留、保留跨页 ID 却只提交当前页数据的问题。

## 核心逻辑变更

- 客户对账添加费用：全部实际查询条件参与范围比较，缓存跨页业务及费用，锁定对象、合计和确认共用缓存。
- 付费结算添加申请：跨页保留完整申请行及填写金额，全选和取消全选仅作用当前页。
- 收费结算添加费用、添加开票申请：跨页保留明细，合计和提交覆盖已访问页的选择。
- 开票申请选费用、发票开具选申请：普通查询条件变化时清空选择，重新打开时清空历史选择；保留已有业务校验。
- 六处统一拒绝旧请求结果，加载期间禁止确认。

## 验证记录

新增 13 项共享状态回归测试，加上原付费申请 8 项测试，共 21 项通过。6 个 Vue 组件编译检查通过。尚未实际页面联调。完整类型检查未通过，仓库现有未使用变量、收费结算表格行类型及共享表格组件类型等诊断仍需另行处理；本次新增的节流函数取消调用类型错误已移除。

## 避坑指南

1. 页码、每页条数不属于筛选范围；新增实际查询条件自动参与比较。
2. 不得只缓存选择 ID，却从当前页生成提交内容。编辑金额应保留响应式引用或独立金额表。
3. 同一结算对象、结算币别、可申请或可结算金额等业务校验继续保留；后端仍负责最终可用额度校验。
4. 手工回归：每个分页抽屉在两页各选一条并修改金额，检查总数和提交均包含两页；切换每个筛选条件检查清空；回到第一页验证金额；取消第二页全选不影响第一页；快速切换查询及关闭重开验证旧结果不回写。
