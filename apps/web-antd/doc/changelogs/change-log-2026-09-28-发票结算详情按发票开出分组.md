# 发票结算详情改为发票开出到费用两层

## 背景意图

按发票结算保存时，一行「发票开出 + 费用」会拆到多条开票明细上。详情要把它们合回一行，删除也按这一对整行删。TAPD #1000178。选票和新建入参仍是开票申请明细，留给相邻需求。

## 核心逻辑变更

- 发票结算编辑页按 `invoiceIssues` 分组。组头是开出单号、发票号、开票时间、币别、本组原始结算金额。`id` 为空的一组显示「无发票开出（已冲红解绑）」。
- 组内一行一个费用，展示结算金额、开票金额、汇率、原始结算金额。金额为 null 时显示「-」，并提示缺汇率。
- 删除改为传 `invoiceIssueId` + `orderFeeId`。还剩明细时弹窗填写删除后的本次结算；明细删光则不传。
- 同一流水下其他核销单：发票结算按发票开出并进这张表，按费用核销收成一组只读行。按费用核销页里的他单发票行改从 `invoiceIssues` 摊平，不再读已删除的 `receiveSettlementInvoiceItems`。

## 避坑指南

- 无发票开出那一组删除时 `invoiceIssueId` 必须传 null，不能改成空字符串或不传。
- 费用行不再有结算明细 id。不要再用 `receiveSettlementInvoiceItemIds` 删除。
- 费用行的原始结算金额与结算金额同号，付方向也是正数；汇总到发票开出时付方向才取负。
