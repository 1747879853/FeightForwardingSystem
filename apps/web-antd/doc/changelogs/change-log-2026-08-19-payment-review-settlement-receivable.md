# 背景意图

审核应付付费申请时，部分结算对象同时有应收。审批人需要一眼看到「这个客户现在还欠我们多少钱」，再决定是否通过本次付款。对应 TAPD 1000609；后端已在 `PayAppTaskListAsync` 增加 `settlementReceivableGroup`。展示放在右侧费用合计卡片，避免和列表「申请合计」列混在一起。

# 核心逻辑变更

- DTO 对齐：`currencyId` / `currencyCode`（或 `currency.code`）/ `unSettledAmount`（原币 2 位小数，不乘汇率）。
- 列表不新增「应收未结算」列；点击任务行后，把该行 `settlementReceivableGroup` 传入详情面板。
- 费用合计卡片底部用橙色分区展示各币别金额；无欠款显示「无欠款」。
- 不把该字段并入「申请合计」动态币别列，也不从前端按费用明细重算。

# 避坑指南

- 这不是「本申请可结算余额」，而是结算对象维度的应收欠款总览。
- 数据来自任务列表，不是 `DetailAsync`；切行后必须跟选中行走。
- 已结清的币别不会出现在数组里；不要前端再按 0 补列。
- 口径是：同一结算对象 + 收 + 费用已审核通过 + 仍有未结；未结算 = 费用金额 − 已结算金额。
