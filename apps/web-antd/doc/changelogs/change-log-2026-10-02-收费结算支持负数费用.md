# 收费结算支持负数费用

## 背景意图

折扣、返利会录成金额为负的费用。收费结算原先把结算金额限制成大于 0，这类费用选不中，也结不进去。按发票结算时，一张只开了部分金额的发票，剩余可结金额仍按整条费用显示。

## 核心逻辑变更

- 按费用选费用时，负数费用可以显示和勾选。本次结算金额默认带出剩余额度，输入范围与费用同号：正数费用从 0 到剩余额度，负数费用从剩余额度到 0。
- 按发票选择时，每行最多可结金额改用接口返回的剩余可结算额度。负数行允许填负数。同一费用出现在多张发票开出下时，页面提示合计受该费用额度约束，保存以后端校验为准。
- 净额、原币净额和按发票的本次结算参考值继续按收减付计算，负数应收会把合计拉低。原始结算金额仍是结算金额乘汇率，负数照算。
- 银行流水里的按费用、按发票核销同样可以结负数费用。只有正数费用时，核销净额仍须大于 0。按金额自动核销的本次结算仍须大于 0，分配结果里可以出现负数明细。
- 业务费用列表上，审核通过的费用按已结算量的绝对值显示部分结算或结算完毕。

## 避坑指南

- 已保存的收费结算明细可以是负数。再点保存时不要把它们当成未填金额拦下。
- 按发票时不要再用其中一行的剩余额度，去拦同一费用在其他发票开出上的合计。每一行自己的上限仍要守住。
- 正数费用再填负数会被拦住，并提示须与费用同号。
