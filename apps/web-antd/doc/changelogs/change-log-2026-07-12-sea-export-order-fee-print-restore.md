# 2026-07-12 恢复应收应付费用表打印按钮

## 背景意图

海运出口编辑页「应收应付」Tab 的打印按钮在 `74d0eabf`（修改费用表格）中被误删，用户勾选费用后无法打印。需按 `f071268c` 原能力恢复。

## 核心逻辑变更

1. **`order-fee-table.vue` 工具栏**
   - 在「保存」后恢复「打印」按钮（更改单模式仍隐藏）。
   - 勾选已保存费用行后，按应收/应付分别调用 `PrintJsonType.RecOrderFeeList`（1000）/ `PayOrderFeeList`（1500）。
   - 未保存行（无 `id`）拦截并提示「请先保存费用后再打印」。

2. **与近期勾选行为兼容**
   - 不恢复旧版 `checkboxConfig.trigger: 'row'`，沿用仅点击 checkbox 勾选，避免与列表统一交互冲突。

3. **修复「点了没反应」交互（同日二次修复）**
   - 打印按钮去掉 `:disabled="!selectedRowKeys.length"`：此前未勾选行时按钮置灰，点击无任何反馈，易被误判为「功能坏了」。
   - 改为始终可点，未勾选时由 `handlePrint` 内 `message.warning` 明确提示。
   - 提示文案由缺失的 i18n key `common.selectDataFirst`（页面直接显示原始 key）改为中文「请先勾选要打印的费用」。

## 避坑指南

- 根因是整文件级费用表改动覆盖了打印相关导入与按钮，合并/改表时需对照工具栏能力清单。
- 打印 JSON 仍为选中 `OrderFeeDto` 数组（去掉 `_rowKey`），不是整份 `SeaExportDto`。
- 浏览器实测验证：勾选已保存费用行 → 打印按钮激活 → 弹出「选择打印模板」（如「应收测试」）→ 可打印；后端已配置 `1000`/`1500` 模板。
- `common.selectDataFirst` 在本仓库 locale 中不存在，勿再引用；需要「请先选择」类提示请用明确中文或已存在的 key。
