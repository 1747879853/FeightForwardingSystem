# 包装类型-明细包装子表-2026-08-20

# 1. 业务背景说明 (Background)

**白话解释：** 包装类型（`CodePackage`，如「纸箱」「托盘」「木箱」）原来是一张单层的小字典表，只能表达「这票货用的是纸箱」，表达不了「用的是哪一种纸箱」。业务上同一个大类下面往往还要再分若干具体规格（例如纸箱下面还分 A 型箱、B 型箱），本次给包装类型挂上一张**明细包装子表**（`CodePackageItem`），在基础资料里跟主表一起维护。

明细包装只有三个字段：**名称、排序id、备注**。其中**排序id 不由前端输入**，后端按提交数组的顺序自动自增生成，返回时按其升序排列，保证「录入什么顺序、看到什么顺序」。

# 2. 功能与操作说明 (Features & Operations)

- **新建包装类型带明细：** 在包装类型新建页的「明细包装」表格里录入名称、备注，随主表一次提交；`sortId` 由后端按数组下标自增生成（1、2、3……）。
- **编辑包装类型带明细：** 子表按**全量提交 + 差异比对**处理——传了 `id` 的更新、`id` 为 null 的新增、原有但本次未提交的删除；`sortId` 按本次提交的数组顺序**整体重排**。
- **删除包装类型：** 先做主表引用校验，再显式删除明细包装子表，最后软删除主表。
- **列表 / 详情：** 都返回该包装类型下的全部明细包装，**按 `SortId` 升序**（与录入顺序一致）。

# 3. 状态流转说明 (Status Transitions)

本模块为基础资料，无状态机。存在一处删除卡点：

| 当前状态 | 触发人/动作 | 目标状态 | 状态说明 |
| :-- | :-- | :-- | :-- |
| 包装类型未被业务单引用 | 操作员 删除包装类型 | 删除成功 | 主表软删除，明细包装同步软删除 |
| 包装类型已被业务单引用 | 操作员 删除包装类型 | 删除被拒绝 | 抛 `该包装类型已被【xx】模块引用,禁止删除` |
| 明细包装从编辑数组中移除 | 操作员 提交编辑 | 删除成功 | 该明细被软删除；**当前没有任何模块引用明细包装，故未做引用校验** |

# 5. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **[卡点 1：`sortId` 是后端生成的，前端传了也没用]** 明细包装的 Add/Edit 入参 DTO 里**根本没有 `sortId` 字段**，前端传了会被 JSON 反序列化直接忽略。后端一律按数组下标自增赋值（`i + 1`）。想调整顺序就调整数组元素的顺序，不要试图传 `sortId`。

> [!IMPORTANT] **[卡点 2：子表是全量提交，漏传等于删除]** 编辑时以本次提交数组中出现的 `id` 集合为准，原有明细中不在该集合里的**一律删除**。传 `null` 或 `[]` 表示清空该包装类型下的全部明细包装。前端编辑页必须把保留行的 `id` 原样回传，只提交增量会导致其余明细被删掉。

> [!IMPORTANT] **[卡点 3：ABP 软删除不级联，子表必须显式删]** `AbpDbContext` 在 `SaveChanges` 前会把 `ISoftDelete` 主表的 `EntityState` 从 `Deleted` 改回 `Modified`，等 EF 执行级联时主表已不是删除态，**子表一条都不会被删**（即使外键配了 `Cascade`）。因此 `DeleteAsync` 在软删主表之前用带谓词的批量删除显式清理明细包装。

> [!IMPORTANT] **[卡点 4：明细包装目前没有引用校验]** 现阶段没有任何业务表引用 `CodePackageItem.Id`，所以编辑时删除明细不做引用校验。 **后续一旦有业务表（如箱表）开始存明细包装 id，必须在 `EditAsync` 的删除段补上引用校验**，否则业务单上的 id 会指向已软删明细，界面表现为「明细包装凭空消失」。

# 8. 避坑指南 (Pitfalls)

- **`sortId` 前端不要传**：Add/Edit 的子表 DTO 里没有这个字段，排序完全由数组顺序决定，从 1 开始自增。
- **返回是升序**：`SortId` 升序 = 提交时的数组顺序，前端直接按返回顺序渲染，不要再排一遍。
- **子表全量提交**：前端必须回传保留行的 `id`，只提交增量会导致其余明细被删除。
- **软删除不级联**：新增任何 `CodePackage` 子表都要在 `DeleteAsync` 里补一条显式批量删除。
- **局部更新不要调 `UpdateAsync`**：本项目 ABP 的 `Update` 会把整行标记为 `Modified` 产生全列 UPDATE，依赖 UoW 的 `SaveChangesAsync` 即可只更新改动列。
- **明细 id 不能重复提交**：同一数组里出现两条相同 `id`，后一条会静默覆盖前一条，已加 `明细包装id重复` 拦截。
- **明细 id 必须属于当前主表**：传了不属于本包装类型的 `id` 报 `输入明细包装id错误`，整个编辑回滚。
- **将来加引用后要补校验**：见第 5 节卡点 4。
- **`CodePackageSimpleDto` 没变**：外键关联处（业务委托单、海运出口分单、海运出口派车等）返回的包装对象仍只有 `id` / `name` / `ediCode`，**不带明细包装**，需要明细请单独调详情接口。
