# 商品信息-规格型号子表-前端接口文档-2026-08-13

**变更日期**：2026-08-13 **受众**：前端 **性质**：品名新增两个子表；海运进口箱表的规格/型号由自由文本改为 id（**破坏性变更**）

路由前缀：`/api/services/app/CodeGoodsAdmin`

> 本文档针对海运业务用的商品信息 `CodeGoods`（表 `App_CodeGoodses`）。仓库的品名 `GoodsInfo`（路由 `GoodsInfoAdmin`）是另一个模块，没有规格/型号子表。

## 2. 新建 — `AddAsync`

`POST /api/services/app/CodeGoodsAdmin/AddAsync`，请求体 `CodeGoodsAddDto`。

### 2.1 入参 `CodeGoodsAddDto`

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 编码 | `code` | string | 否 | 最长 128 |
| 名称 | `name` | string | 是 | 最长 128 |
| 货物类型 | `cargoId` | CargoType | 是 | `S=普通货`、`R=冻柜`、`D=危险品`、`O=超限箱` |
| 物料号 | `goodNo` | string | 否 | 最长 128 |
| 英文名称 | `enName` | string | 否 | 最长 128 |
| 商品描述 | `description` | string | 否 | 最长 256 |
| 海关代码 | `hsCode` | string | 否 | 最长 64 |
| 申报计量单位 | `ruleUnit` | string | 否 | 最长 64 |
| 是否启用 | `enable` | bool | 否 |  |
| 排序id | `sortId` | int | 否 | 主表排序 |
| 备注 | `remark` | string | 否 | 最长 1024 |
| **规格明细** | `codeGoodsSpecs` | `CodeGoodsSpecAddDto[]` | 否 | 不传或传 `[]` 表示该品名下没有规格 |
| **型号明细** | `codeGoodsModels` | `CodeGoodsModelAddDto[]` | 否 | 不传或传 `[]` 表示该品名下没有型号 |

### 2.2 入参 `CodeGoodsSpecAddDto`（规格明细，数组元素）

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 规格名称 | `name` | string | 是 | 最长 128，自动去首尾空格；同一品名下不允许重复（大小写不敏感） |
| 排序id | `sortId` | int? | 否 | 不传则按数组下标自动生成（从 0 开始） |
| 备注 | `remark` | string | 否 | 最长 1024 |

### 2.3 入参 `CodeGoodsModelAddDto`（型号明细，数组元素）

字段与规格完全一致：`name`（必填，最长 128，同品名下不重名）、`sortId`（int?）、`remark`（最长 1024）。

### 2.4 出参

| 字段     | 类型 | 说明          |
| :------- | :--- | :------------ |
| `result` | long | 新增的品名 id |

### 2.5 请求示例

```json
{
  "code": "LCD-001",
  "name": "液晶显示屏",
  "cargoId": "S",
  "enable": true,
  "sortId": 0,
  "remark": "常规品名",
  "codeGoodsSpecs": [
    { "name": "15.6寸", "sortId": 0, "remark": "笔电常用" },
    { "name": "21.5寸", "sortId": 1, "remark": null }
  ],
  "codeGoodsModels": [{ "name": "LM156LF-2F01", "sortId": 0, "remark": null }]
}
```

## 3. 编辑 — `EditAsync`

`PUT /api/services/app/CodeGoodsAdmin/EditAsync`，请求体 `CodeGoodsEditDto`。

> **子表为全量提交**：后端按 `id` 做差异比对——**没传的删除、传了 id 的修改、id 为 null 的新增**。前端必须把该品名下**保留的全部明细**都提交上来，只提交增量会导致未提交的明细被删除。

### 3.1 入参 `CodeGoodsEditDto`

在 `CodeGoodsAddDto` 全部字段基础上增加 `id`（long，必填），子表元素类型换成 Edit 版：

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 品名id | `id` | long | 是 | 主表 id |
| 规格明细 | `codeGoodsSpecs` | `CodeGoodsSpecEditDto[]` | 否 | 全量提交；不传或传 `[]` 表示清空该品名下所有规格 |
| 型号明细 | `codeGoodsModels` | `CodeGoodsModelEditDto[]` | 否 | 全量提交；不传或传 `[]` 表示清空该品名下所有型号 |

其余主表字段（`code`、`name`、`cargoId`、`goodNo`、`enName`、`description`、`hsCode`、`ruleUnit`、`enable`、`sortId`、`remark`）同新建。

### 3.2 入参 `CodeGoodsSpecEditDto` / `CodeGoodsModelEditDto`（数组元素）

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 明细id | `id` | Guid? | 否 | **传 id = 修改这一条；传 null 或不传 = 新增一条** |
| 名称 | `name` | string | 是 | 最长 128；同一品名下不允许重复（大小写不敏感） |
| 排序id | `sortId` | int? | 否 | 不传则按数组下标自动生成（从 0 开始） |
| 备注 | `remark` | string | 否 | 最长 1024 |

### 3.3 出参

| 字段     | 类型 | 说明     |
| :------- | :--- | :------- |
| `result` | bool | 是否成功 |

### 3.4 请求示例（一次请求同时完成 删/改/增）

原有 3 条规格：A(`id=aaa...`)、B(`id=bbb...`)、C(`id=ccc...`)。目标：删除 C、修改 B 的名称、新增一条 D。

```json
{
  "id": 1001,
  "code": "LCD-001",
  "name": "液晶显示屏",
  "cargoId": "S",
  "enable": true,
  "sortId": 0,
  "remark": "常规品名",
  "codeGoodsSpecs": [
    {
      "id": "aaaaaaaa-1111-2222-3333-444444444444",
      "name": "15.6寸",
      "sortId": 0,
      "remark": "笔电常用"
    },
    {
      "id": "bbbbbbbb-1111-2222-3333-444444444444",
      "name": "21.5寸(改)",
      "sortId": 1,
      "remark": null
    },
    { "id": null, "name": "27寸", "sortId": 2, "remark": "新增规格" }
  ],
  "codeGoodsModels": []
}
```

上例执行结果：C 被删除（未提交）、B 被更新、D 被新增；`codeGoodsModels` 传空数组 → 该品名下所有型号被清空。

> [!IMPORTANT] **已被箱子引用的规格/型号删不掉**：如果要删除的明细已被海运进口的箱表（`orderCtns`）选中，会报 `待删除的规格已被【业务委托单】的箱型引用,禁止删除`（型号同理），整个编辑请求回滚。前端遇到这个提示应提示用户先去业务单上换掉该规格/型号。

## 4. 删除 — `DeleteAsync`

`DELETE /api/services/app/CodeGoodsAdmin/DeleteAsync`，请求体 `IdDto`。

### 4.1 入参

| 字段   | JSON  | 类型   | 必填 | 说明                                       |
| :----- | :---- | :----- | :--- | :----------------------------------------- |
| 品名id | `id`  | long   | 是   | 要删除的品名 id                            |
| 批量id | `ids` | long[] | 否   | 本接口当前**未使用**该字段，只按 `id` 删除 |

### 4.2 出参

| 字段     | 类型 | 说明     |
| :------- | :--- | :------- |
| `result` | bool | 是否成功 |

### 4.3 行为说明

删除主表的同时**自动删除该品名下所有规格、型号明细**，前端无需单独调用子表删除接口。品名被引用时禁止删除，提示 `该商品信息(品名)已被【业务委托单、海运出口分单、海运出口派车】模块引用,禁止删除`（实际列出命中的模块）。

## 8. 海运进口箱表联动（破坏性变更）

海运进口的箱表（最外层 `orderCtns`）原有的两个自由文本字段**已删除**：

| 原字段 | JSON | 现字段 | JSON | 类型 |
| :-- | :-- | :-- | :-- | :-- |
| Specification（规格） | `specification` | CodeGoodsSpecId | `codeGoodsSpecId` | Guid? |
| Model（型号） | `model` | CodeGoodsModelId | `codeGoodsModelId` | Guid? |

出参新增两个对象：`codeGoodsSpec`、`codeGoodsModel`，字段为 `id`、`codeGoodsId`、`name`、`sortId`；未选或查不到时为 `null`。

联动规则：

1. 箱行先选品名 `codeGoodsId`。
2. 用品名详情接口拿该品名的 `codeGoodsSpecs` / `codeGoodsModels` 作为这一行规格/型号下拉的候选项（已按 `sortId` 升序，直接按返回顺序渲染）。
3. **切换品名时必须清空该行已选的 `codeGoodsSpecId` / `codeGoodsModelId`**，否则提交被后端拦下。
4. 两个字段都可空，不选就传 `null`。

相关错误提示：

| 提示文案 | 触发条件 |
| :-- | :-- |
| `选择规格前必须先选择箱内商品信息(品名)` | 传了 `codeGoodsSpecId` 但 `codeGoodsId` 为空 |
| `选择型号前必须先选择箱内商品信息(品名)` | 传了 `codeGoodsModelId` 但 `codeGoodsId` 为空 |
| `规格ID:xxx不存在` | `codeGoodsSpecId` 查不到 |
| `型号ID:xxx不存在` | `codeGoodsModelId` 查不到 |
| `规格不属于该箱所选的商品信息(品名)` | 规格的 `codeGoodsId` 与本行的 `codeGoodsId` 不一致 |
| `型号不属于该箱所选的商品信息(品名)` | 型号的 `codeGoodsId` 与本行的 `codeGoodsId` 不一致 |

## 9. 品名接口错误提示对照表

| 提示文案 | 触发接口 | 触发条件 |
| :-- | :-- | :-- |
| `输入不能为空` | 新建/编辑 | 请求体为 null |
| `商品名称不能为空` | 新建/编辑 | `name` 为空或纯空格 |
| `规格名称不能为空` | 新建/编辑 | 规格数组中存在 `name` 为空或纯空格 |
| `型号名称不能为空` | 新建/编辑 | 型号数组中存在 `name` 为空或纯空格 |
| `规格名称长度不能超过128个字符` | 新建/编辑 | 规格名称超长（型号同理） |
| `规格名称【xxx】重复` | 新建/编辑 | 同一次提交的规格数组内名称重复（去空格、大小写不敏感） |
| `型号名称【xxx】重复` | 新建/编辑 | 同一次提交的型号数组内名称重复 |
| `规格明细id重复` | 编辑 | 同一次提交的规格数组内出现相同 `id`（型号同理） |
| `输入商品信息(品名)错误` | 编辑/删除/详情 | 主表 id 不存在 |
| `输入规格明细id错误` | 编辑 | 传的规格 `id` 不属于当前品名（型号同理） |
| `待删除的规格已被【业务委托单】的箱型引用,禁止删除` | 编辑 | 要删掉的规格已被箱表选中（型号同理） |
| `该商品信息(品名)已被【xx】模块引用,禁止删除` | 删除 | 品名被业务单/分单/派车引用 |

## 10. 前端适配清单

### 品名维护页

- [ ] 新建/编辑表单增加「规格」「型号」两个可增删行的明细表格，列为：名称（必填，上限 128）、排序、备注
- [ ] 编辑页进入时用详情接口返回的 `codeGoodsSpecs` / `codeGoodsModels` 回填，**原样保留每行的 `id`**
- [ ] 编辑提交时：保留行带 `id`、新增行 `id` 传 `null`、删除行直接从数组移除（**不要**传删除标记）
- [ ] `sortId` 可以不传，由后端按数组顺序生成；若支持拖拽排序则按拖拽后下标传 `sortId`
- [ ] 返回是**升序**，与提交时的数组顺序一致，直接按返回顺序渲染即可，不需要前端再排
- [ ] 提交前做前端同名校验，避免走到后端才报「名称重复」
- [ ] 处理「已被箱型引用禁止删除」的错误提示

### 海运进口箱表

- [ ] 删除「型号」「规格」两个文本输入框，改为下拉选择
- [ ] 请求体不要再带 `model` / `specification`，改为 `codeGoodsSpecId` / `codeGoodsModelId`
- [ ] 下拉候选项来自该行所选品名的 `codeGoodsSpecs` / `codeGoodsModels`
- [ ] 切换品名时清空该行的规格、型号
- [ ] 列表/详情展示改为读 `codeGoodsSpec.name` / `codeGoodsModel.name`
- [ ] 旧数据的自由文本规格/型号已随列删除，历史单据这两列会显示为空，需要业务侧重新选一次
