# 包装类型-明细包装子表-前端接口文档-2026-08-20

**变更日期**：2026-08-20 **受众**：前端 **性质**：包装类型新增一张明细包装子表，增删改查全链路带子表（**向后兼容的增量变更**，不传子表数组即为无明细）

路由前缀：`/api/services/app/CodePackageAdmin`

> **一句话要点**：明细包装的 `sortId` **由后端按数组顺序自动生成，前端不要传**；返回时按 `sortId` **升序**，即与提交时的数组顺序完全一致，前端直接按返回顺序渲染即可。

---

| 详情 | GET | `/api/services/app/CodePackageAdmin/DetailAsync` | 是 |

## 2. 新建 — `AddAsync`

`POST /api/services/app/CodePackageAdmin/AddAsync`，请求体 `CodePackageAddDto`。

### 2.1 入参 `CodePackageAddDto`

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 名称 | `name` | string | 是 | 最长 128 |
| 描述 | `description` | string | 否 | 最长 256 |
| AFR代码 | `afrCode` | string | 否 | 最长 10 |
| EDI代码 | `ediCode` | string | 否 | 最长 8 |
| 是否启用 | `enable` | bool | 否 |  |
| 排序id | `sortId` | int | 否 | **主表自己的排序，这个照旧由前端传** |
| 备注 | `remark` | string | 否 | 最长 1024 |
| **明细包装** | `codePackageItems` | `CodePackageItemAddDto[]` | 否 | 不传或传 `[]` 表示该包装类型下没有明细 |

### 2.2 入参 `CodePackageItemAddDto`（明细包装，数组元素）

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 明细包装名称 | `name` | string | 是 | 最长 128，自动去首尾空格；同一包装类型下不允许重复（大小写不敏感） |
| 备注 | `remark` | string | 否 | 最长 1024 |

> **注意：明细包装没有 `sortId` 入参。** 后端按数组下标自增生成（第 1 条 = 1，第 2 条 = 2……），传了这个字段也会被忽略。要调整顺序请调整数组元素顺序。

### 2.3 出参

| 字段     | 类型 | 说明              |
| :------- | :--- | :---------------- |
| `result` | long | 新增的包装类型 id |

### 2.4 请求示例

```json
{
  "name": "纸箱",
  "description": "通用纸质包装",
  "afrCode": "CT",
  "ediCode": "CT",
  "enable": true,
  "sortId": 10,
  "remark": "常用包装",
  "codePackageItems": [
    { "name": "A型纸箱", "remark": "小箱" },
    { "name": "B型纸箱", "remark": null },
    { "name": "C型纸箱", "remark": "加固" }
  ]
}
```

落库后三条明细的 `sortId` 依次为 `1`、`2`、`3`。

## 3. 编辑 — `EditAsync`

`PUT /api/services/app/CodePackageAdmin/EditAsync`，请求体 `CodePackageEditDto`。

> **子表为全量提交**：后端按 `id` 做差异比对——**没传的删除、传了 id 的修改、id 为 null 的新增**。前端必须把该包装类型下**保留的全部明细**都提交上来，只提交增量会导致未提交的明细被删除。
>
> **`sortId` 按本次提交的数组顺序整体重排**（1、2、3……），无论这一条是新增还是修改。

### 3.1 入参 `CodePackageEditDto`

在 `CodePackageAddDto` 全部字段基础上增加 `id`（long，必填），子表元素类型换成 Edit 版：

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 包装类型id | `id` | long | 是 | 主表 id |
| 明细包装 | `codePackageItems` | `CodePackageItemEditDto[]` | 否 | 全量提交；不传或传 `[]` 表示清空该包装类型下所有明细 |

其余主表字段（`name`、`description`、`afrCode`、`ediCode`、`enable`、`sortId`、`remark`）同新建。

### 3.2 入参 `CodePackageItemEditDto`（数组元素）

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 明细id | `id` | Guid? | 否 | **传 id = 修改这一条；传 null 或不传 = 新增一条**；同一数组内不允许重复 |
| 明细包装名称 | `name` | string | 是 | 最长 128；同一包装类型下不允许重复（大小写不敏感） |
| 备注 | `remark` | string | 否 | 最长 1024 |

> 同样**没有 `sortId` 入参**。

### 3.3 出参

| 字段     | 类型 | 说明     |
| :------- | :--- | :------- |
| `result` | bool | 是否成功 |

### 3.4 请求示例（一次请求同时完成 删/改/增）

原有 3 条明细：A(`id=aaa...`, sortId=1)、B(`id=bbb...`, sortId=2)、C(`id=ccc...`, sortId=3)。目标：删除 C、修改 B 的名称、新增一条 D，并把 D 排到 B 前面。

```json
{
  "id": 1001,
  "name": "纸箱",
  "description": "通用纸质包装",
  "afrCode": "CT",
  "ediCode": "CT",
  "enable": true,
  "sortId": 10,
  "remark": "常用包装",
  "codePackageItems": [
    {
      "id": "aaaaaaaa-1111-2222-3333-444444444444",
      "name": "A型纸箱",
      "remark": "小箱"
    },
    { "id": null, "name": "D型纸箱", "remark": "新增" },
    {
      "id": "bbbbbbbb-1111-2222-3333-444444444444",
      "name": "B型纸箱(改)",
      "remark": null
    }
  ]
}
```

执行结果：

- C 未出现在数组里 → 被删除；
- A 保留，`sortId` 重排为 `1`；
- D 是新增，`sortId` = `2`；
- B 被更新，`sortId` 重排为 `3`。

## 4. 删除 — `DeleteAsync`

`DELETE /api/services/app/CodePackageAdmin/DeleteAsync`，请求体 `IdDto`。

### 4.1 入参

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 包装类型id | `id` | long | 是 | 要删除的包装类型 id |
| 批量id | `ids` | long[] | 否 | 本接口当前**未使用**该字段，只按 `id` 删除 |

### 4.2 出参

| 字段     | 类型 | 说明     |
| :------- | :--- | :------- |
| `result` | bool | 是否成功 |

### 4.3 行为说明

删除主表的同时**自动删除该包装类型下所有明细包装**，前端无需单独调用子表删除接口。包装类型被引用时禁止删除，提示 `该包装类型已被【业务委托单、海运出口分单、海运出口派车】模块引用,禁止删除`（实际只列出命中的模块）。

## 5. 分页列表 — `GetPagedListAsync`

`GET /api/services/app/CodePackageAdmin/GetPagedListAsync`，查询参数 `CodePackageQueryDto`。

### 5.1 入参（query string）

| 字段 | JSON | 类型 | 必填 | 默认值 | 说明 |

请求示例：

### 5.2 出参 `PagedList<CodePackageDto>`

| 字段     | JSON             | 类型               | 说明                     |

## 8. 错误提示对照表

| 提示文案 | 触发接口 | 触发条件 |
| :-- | :-- | :-- |
| `输入不能为空` | 新建/编辑 | 请求体为 null |
| `包装类型名称不能为空` | 新建/编辑 | `name` 为空或纯空格 |
| `明细包装名称不能为空` | 新建/编辑 | 明细数组中存在 `name` 为空或纯空格 |
| `明细包装名称长度不能超过128个字符` | 新建/编辑 | 明细名称超长 |
| `明细包装名称【xxx】重复` | 新建/编辑 | 同一次提交的明细数组内名称重复（去空格、大小写不敏感） |
| `明细包装id重复` | 编辑 | 同一次提交的明细数组内出现相同 `id` |
| `输入包装类型错误` | 编辑/删除/详情 | 主表 id 不存在 |
| `输入明细包装id错误` | 编辑 | 传的明细 `id` 不属于当前包装类型 |
| `该包装类型已被【xx】模块引用,禁止删除` | 删除 | 包装类型被业务委托单/海运出口分单/海运出口派车引用 |

## 9. 前端适配清单

- [ ] 新建/编辑表单增加「明细包装」可增删行的明细表格，列为：名称（必填，上限 128）、备注
- [ ] 明细表格**不要**做排序列输入框，顺序由行顺序决定；如需拖拽排序，拖完直接按新数组顺序提交即可
- [ ] 编辑页进入时用详情接口返回的 `codePackageItems` 回填，**原样保留每行的 `id`**
- [ ] 编辑提交时：保留行带 `id`、新增行 `id` 传 `null`、删除行直接从数组移除（**不要**传删除标记）
- [ ] 返回已是**升序**，直接按返回顺序渲染，不需要前端再排一次
- [ ] 提交前做前端同名校验，避免走到后端才报「明细包装名称重复」
- [ ] 列表页如需展示明细，可直接用列表接口返回的 `codePackageItems`，无需再逐行调详情
