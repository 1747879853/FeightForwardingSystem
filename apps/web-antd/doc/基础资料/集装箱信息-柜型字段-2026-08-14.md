# 集装箱信息-新增柜型字段-2026-08-14

## 1. 背景意图

箱型基础资料原本只有「集装箱类型 CtnSize」「集装箱尺寸 CtnType」「表现形式 CtnName」三个自由文本字段，无法用一个稳定的、可枚举的口径区分**普通干货柜**与**特种柜**（冻柜、开顶、框架、罐柜等）。

业务侧（业务委托单、海运出口/进口、派车、运价、报价单）需要按柜型做差异化处理与筛选，因此在 `CtnCode`（表 `App_CtnCodes`）上新增**不可为空**的枚举列「柜型」，并让所有以对象形式返回箱型的接口一并带出该字段。

## 2. 核心逻辑变更

### 2.1 新增枚举 `CtnCabinetType`

文件：`src/CsprojBuilder.Core/CsprojBuilderEnum.cs`（置于命名空间顶部的 `#region 柜型`）

| 值  | 枚举项 | 含义                          |
| :-- | :----- | :---------------------------- |
| 0   | 普柜   | 普通干货柜                    |
| 1   | 特种柜 | 冻柜/开顶/框架/罐柜等非普通柜 |

### 2.2 实体新增列

文件：`src/CsprojBuilder.Core/Entites/CtnCode.cs`

```csharp
/// <summary>
/// 柜型 0普柜 1特种柜
/// </summary>
public CtnCabinetType CabinetType { get; set; }
```

- 列名 `CabinetType`，位置紧跟 `CtnName` 之后。
- **不可为空**（非可空枚举），EF 默认按 `int` 落库，CLR 默认值 0 即「普柜」。

### 2.3 DTO 同步（`src/CsprojBuilder.Application/App/CtnCode/Dto/CtnCodeDto.cs`）

| DTO                | 新增字段      | 可空 | 说明                             |
| :----------------- | :------------ | :--- | :------------------------------- |
| `CtnCodeAddDto`    | `CabinetType` | 否   | 新建入参，必填                   |
| `CtnCodeEditDto`   | `CabinetType` | 否   | 编辑入参，必填                   |
| `CtnCodeQueryDto`  | `CabinetType` | 是   | 列表筛选项，不传不筛选           |
| `CtnCodeDto`       | `CabinetType` | 否   | 列表/详情出参                    |
| `CtnCodeSimpleDto` | `CabinetType` | 否   | 箱型简易对象，所有外键关联处出参 |

### 2.4 AppService（`CtnCodeAdminAppService`）

1. `AddAsync`：新增枚举合法性校验 `Enum.IsDefined(typeof(CtnCabinetType), input.CabinetType)`，非法值抛「柜型输入错误」。实体由 AutoMapper 映射，同名同类型自动带入，无需手工赋值。
2. `EditAsync`：同样先做枚举合法性校验，再在逐字段赋值段落中补 `ctnCode.CabinetType = input.CabinetType;`（保持只改动列的局部更新语义）。
3. `GetPagedListAsync`：新增筛选 `WhereIf(input.CabinetType.HasValue, x => x.CabinetType == input.CabinetType)`。
4. `DetailAsync`：走 AutoMapper 映射，自动带出新字段，无代码改动。

### 2.5 基础资料缓存链路

箱型在业务单里不是实时查库的，而是走 `BasicDataCache` 的整表快照，因此新字段必须在缓存链路上逐层补齐，否则业务单返回的箱型对象里 `cabinetType` 会恒为 0。

| 文件 | 改动 |
| :-- | :-- |
| `Caching/BasicDataCacheItem.cs` | `CtnCodeCacheItem` 新增 `CabinetType` |
| `Caching/BasicDataCache.cs` | `GetCtnCodesAsync` 的投影补 `CabinetType = x.CabinetType` |
| `Caching/BasicDataCacheExtensions.cs` | `ToCtnCode()` 扩展方法补 `CabinetType = item.CabinetType` |

缓存失效无需改动：`BasicDataCacheInvalidator` 已订阅 `EntityChangedEventData<CtnCode>`，编辑柜型后会自动清空 `BasicData.CtnCode` 整表快照。

### 2.6 其余两处 `CtnCodeSimpleDto` 手工构造点

除缓存扩展方法外，项目里还有两处**没有复用** `ToCtnCode()` 的手工构造点，同样补齐：

| 文件 | 位置 | 说明 |
| :-- | :-- | :-- |
| `App/SeaImport/SeaImportAdminAppService.cs` | 私有方法 `MapCtnCode(CtnCodeCacheItem)` | 海运进口自建的缓存项→简易对象映射 |
| `App/PreOrder/PreOrderAdminAppService.cs` | `FillDetailSimpleDtosAsync` 内直接查库投影 | 业务联系单详情不走缓存，直接 `Select` 出简易对象 |

### 2.7 下游自动受益（无需改动的接口）

以下接口通过 `ToCtnCode()` / `MapCtnCode()` / AutoMapper 返回箱型对象，改动后自动带出 `cabinetType`：

| 模块 | 方法 |
| :-- | :-- |
| 业务委托单 | `TransportOrderAdmin/GetPagedListAsync` |
| 业务联系单 | `PreOrderAdmin/DetailAsync`（经 `FillDetailSimpleDtosAsync`） |
| 海运出口 | `SeaExportAdmin/GetPagedListAsync`、`SeaExportAdmin/DetailAsync` |
| 海运出口分单 | `SeaExportSeparateAdmin/GetPagedListAsync`、`SeaExportSeparateAdmin/DetailAsync` |
| 海运出口派车 | `SeaExportDispatchAdmin/GetPagedListAsync`、`SeaExportDispatchAdmin/DetailAsync` |
| 海运进口 | `SeaImportAdmin/GetPagedListAsync`、`SeaImportAdmin/DetailAsync` |
| 海运出口服务项任务 | 经私有方法 `MapSeaExportsAsync` 的列表/详情类接口 |
| 客户对账 | `StatementAdmin/GetOrderFeeGroupAsync` |
| 付费申请 | `PaymentApplicationAdmin/GetOrderFeeGroupAsync` |
| 海运出口运价 | `SeFreiPriceAdmin/GetCtnCodesByPriceIdsAsync`（返回完整 `CtnCodeDto`，AutoMapper 自动带出） |

## 3. 避坑指南

- **不生成 Migration**：按项目约定迁移文件自行生成。本次需要给 `App_CtnCodes` 增加非空 `CabinetType`（int，NOT NULL），**存量数据必须带默认值 0**，否则加列会失败。参考：`ALTER TABLE App_CtnCodes ADD CabinetType int NOT NULL DEFAULT 0;`
- **缓存必须逐层补齐**：只改实体和 DTO 不改 `CtnCodeCacheItem` / `GetCtnCodesAsync` / `ToCtnCode()`，业务单里的 `cabinetType` 会恒为 0 且不报错，属于最容易漏且最难发现的坑。
- **手工构造点容易漏**：`CtnCodeSimpleDto` 有三处构造点（缓存扩展、海运进口私有方法、业务联系单直查投影），新增字段时必须一起改。后续如再加字段，优先考虑把海运进口与业务联系单收敛到 `ToCtnCode()`。
- **非空枚举的默认值语义**：前端不传 `cabinetType` 时会按 0（普柜）落库，不会报错。若业务上要求前端显式选择，需在前端表单侧做必填校验；后端仅拦截「不是 0/1 的非法值」。
- **旧数据默认全是普柜**：上线后需要业务侧人工把冻柜/开顶/框架/罐柜等箱型改成「特种柜」。
