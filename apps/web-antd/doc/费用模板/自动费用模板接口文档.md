# 自动费用模板接口文档

**控制器**：`OrderFeeTemplateAdmin`

**所有接口均需要登录认证**

---

# 1. 业务背景说明 (Background)

**白话解释：** 自动费用模板（`OrderFeeTemplate` + 明细 `OrderFeeTemplateItem`）用于在**海运出口（后续支持空运出口）完成某个服务项时，按模板自动生成对应的业务费用（`OrderFee`）**，减少人工录费工作量。

- 模板按**业务类型 / 适用组织 / 委托单位 / 起运港 / 目的港 / 船公司 / 装运方式**等条件匹配；**模板字段为空代表"全部"**（例如适用组织不填即代表所有组织都适用）。
- 模板有**有效期**控制：长期有效，或当前时间落在 `[StartTime, EndTime]` 内；起始时间不填代表起始不限，结束时间不填代表结束不限。
- 模板按**服务项（`ServiceType`，前端定义枚举）**触发：明细级 `ServiceType` 为空时取主表 `ServiceType`。
- 用户只能查询/管理自己 **DataPermission 数据权限范围内** 的模板。

# 2. 数据结构

- 主表：`OrderFeeTemplate`（`App_OrderFeeTemplates`），继承 `DataPermissionFullAuditedEntity<Guid>`。
- 子表：`OrderFeeTemplateItem`（`App_OrderFeeTemplateItems`），费用明细列表。
- 已在 `CsprojBuilderDbContext` 注册 `DbSet`（**迁移文件由人工生成**）。

> 说明：新增/编辑/详情/列表接口均携带子表明细。列表接口额外返回主表与子表对应外键的 SimpleDto（所属公司/委托单位/付费方式/业务来源/船公司/订舱代理/起运港/目的港，以及明细的费用代码/币别/结算对象）。

## 一、新增自动费用模板

### `POST /api/services/app/OrderFeeTemplateAdmin/AddAsync`

**权限**：`Admin.OrderFeeTemplate.Add`

**入参** `OrderFeeTemplateAddDto`（Body JSON）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | `string` | 是 | 模板名称（最长64） |
| `bizType` | `BizType` | 是 | 业务类型（0=海运出口） |
| `paySide` | `PaySide` | 是 | 收付类型（0=收，1=付） |
| `efficient` | `bool` | 是 | 是否长期有效 |
| `enable` | `bool` | 是 | 是否启用（生成费用时只筛选启用的模板，默认 true） |
| `startTime` | `DateTime?` | 否 | 生效起始时间，为空=起始不限 |
| `endTime` | `DateTime?` | 否 | 生效终止时间，为空=结束不限 |
| `orgId` | `long?` | 否 | 适用组织id，为空=适用所有组织（不做本人校验） |
| `clientId` | `Guid?` | 否 | 委托单位id，为空=所有 |
| `tradeTermsType` | `TradeTermsType?` | 否 | 贸易条款，为空=所有 |
| `cargoId` | `CargoType?` | 否 | 货物类型，为空=所有 |
| `codeFrtId` | `long?` | 否 | 付费方式id，为空=所有 |
| `codeSourceId` | `long?` | 否 | 业务来源id，为空=所有 |
| `carrierId` | `long?` | 否 | 船公司id，为空=所有 |
| `bookingAgentId` | `Guid?` | 否 | 订舱代理id，为空=所有 |
| `polId` | `long?` | 否 | 起运港id，为空=所有 |
| `podId` | `long?` | 否 | 目的港id，为空=所有 |
| `blType` | `BLType?` | 否 | 装运方式，为空=所有 |
| `serviceType` | `int?` | 条件必填 | 服务项保底字段：子表未配置服务项时使用主表值；**存在任意明细 `serviceType` 为空时，主表本字段必填** |
| `sortId` | `int` | 否 | 排序id |
| `remark` | `string` | 否 | 备注（最长4096） |
| `orderFeeTemplateItems` | `OrderFeeTemplateItemAddDto[]` | 是 | 费用明细列表（至少一条） |

**明细** `OrderFeeTemplateItemAddDto`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `serviceType` | `int?` | 否 | 服务项，为空则取主表服务项 |
| `feeCodeId` | `long` | 是 | 费用代码id（费用名称来源） |
| `industryCategory` | `IndustryCategory` | 是 | 行业类别/结算对象类别 |
| `settlementId` | `Guid` | 是 | 结算对象id（客户表） |
| `currencyId` | `long` | 是 | 币别id |
| `unitPrice` | `decimal` | 是 | 含税单价 |
| `noTaxUnitPrice` | `decimal` | 是 | 不含税单价 |
| `amount` | `decimal` | 否 | 金额（生成费用时按单价×数量计算覆盖） |
| `unit` | `string` | 是 | 单位字符串（票、重量、体积、TEU、20GP、40GP 等） |
| `taxRate` | `decimal` | 是 | 税率(%) |
| `noTaxAmount` | `decimal` | 否 | 不含税金额（生成费用时计算覆盖） |
| `sortId` | `int` | 否 | 排序id |
| `remark` | `string` | 否 | 备注 |

**出参**：`Guid`（新建模板ID）

**业务规则（校验）**：

- 模板名称非空且≤64；填了起始与终止时间时起始不能晚于终止；明细至少一条。
- **服务项保底校验**：若任意明细 `serviceType` 为空，则主表 `serviceType` 必填（子表不填时用主表值生成费用）。
- **启用模板条件唯一性**：`enable=false` 不校验；`enable=true` 时，与其他 `enable=true` 的模板比对 `bizType`/`paySide`/`clientId`/`tradeTermsType`/`cargoId`/`codeFrtId`/`codeSourceId`/`carrierId`/`bookingAgentId`/`polId`/`podId`/`blType` 是否完全相等（**null 与 null 视为相等**）；若条件完全一致且生效时间有重叠（长期有效视为全时间覆盖；否则按 `[startTime, endTime]` 闭区间，空端点该端不限），则报错：`已存在与当前模板重复条件的模板`。

## 二、编辑自动费用模板

## 二点五、复制自动费用模板

### `POST /api/services/app/OrderFeeTemplateAdmin/CopyAsync`

**权限**：`Admin.OrderFeeTemplate.Add`

**入参** `OrderFeeTemplateCopyDto`（Body JSON）：

| 字段    | 类型     | 必填 | 说明                        |
| ------- | -------- | ---- | --------------------------- |
| `ids`   | `Guid[]` | 是   | 要复制的模板id集合          |
| `count` | `int`    | 否   | 每条源数据复制的份数，默认1 |

**出参**：`List<Guid>`（新生成的模板id集合）

**业务规则**：

- 复制主表全部字段及子表明细（明细全部生成新 id），直接保存（批量插入）。
- **复制出的模板强制 `Enable=false`**，不做重复条件校验（避免与源模板条件冲突；需启用时再走 `SetEnableAsync`/`EditAsync` 校验）。
- 复制出的模板名称为 `原名-复制N`，`N` 从 1 自动递增且不与现有名称冲突；同一次请求内多份复制依次递增。
- 名称超过 64 长度限制时自动截断原名以容纳 `-复制N` 后缀。
- 复制出的数据所属用户(`UserId`)为当前操作人。

### `PUT /api/services/app/OrderFeeTemplateAdmin/SetEnableAsync`

**权限**：`Admin.OrderFeeTemplate.Edit`

**入参** `OrderFeeTemplateSetEnableDto`（Body JSON）：

| 字段     | 类型     | 必填 | 说明                            |

| `ids`    | `Guid[]` | 是   | 要设置的模板id集合              |

**业务规则**：批量将指定模板的 `Enable` 设为入参值；禁用后完成服务项时不会再按该模板生成费用。

- 仅改 `Enable` 字段，依赖 UoW 局部更新。

# 3. 核心业务卡点 (Business Blockers / 自动生成费用逻辑)

> [!IMPORTANT] **完成服务项时自动生成费用** —— 入口在 `SeServiceTaskAdminAppService.CompleteAsync`，标记任务为"已完成"后调用私有方法 `GenerateOrderFeesByTemplateAsync(configItem, seaExport)`。

生成流程：

1. **仅筛选启用模板**：`Enable == true`，禁用模板不参与费用生成。
2. **业务类型分支**：当前仅处理 `BizType.SeaExport`（海运出口）。**空运出口已预留 TODO 注释与分支位置**（空运数量单位逻辑不同，待实现）。
3. **有效期筛选**：`Efficient == true`（长期有效）**或**（`StartTime` 为空或 ≤ 当前时间）且（`EndTime` 为空或 ≥ 当前时间）。
4. **条件匹配（字段为空=全部）**：业务类型、委托单位、贸易条款、货物类型、付费方式、业务来源、船公司、订舱代理、起运港、目的港、装运方式；**适用组织 `OrgId`** 通过业务所属用户（`TransportOrder.UserId`）向上找到组织后比对（`GetUserCompanyByCacheAsync`）。
5. **服务项一致**：明细 `ServiceType` 为空则取主表 `ServiceType`，等于当前完成服务项的 `ServiceType` 才生成。**保存时**：若存在明细服务项为空，主表服务项必填（保底字段），否则新增/编辑直接报错。
6. **数量按单位生成**（`Unit` 字符串）：

   | 单位 | 数量取值 |
   | --- | --- |
   | 空 | 0（仍生成费用） |
   | `票` | 1 |
   | `毛重` | `TransportOrder.Kgs` |
   | `尺码` | `TransportOrder.Cbm` |
   | `TEU` | `Σ(OrderCtn 对应 CtnCode.TEU)` |
   | 箱型（如 `20GP`/`40GP`） | 按 `CtnCode.CtnName` 匹配 `OrderCtn` 的总数量；**本单没有该箱型则整条费用不生成（静默跳过，不报错）** |

7. **汇率匹配**：按业务会计期间 `TransportOrder.AccountDate` 命中 `ExchangeRate`（`CurrencyId` 一致且 `StartDate`/`EndDate` 覆盖会计期间）；收付类型为"收"取应收 `DRValue`，"付"取应付 `CRValue`。**匹配不到汇率则写入 `0`（不跳过该条）**。走基类公共方法 `ResolveExchangeRateAsync`（与费用批量引入共用）。
8. **防重复生成**：先查当前业务下所有 `OrderFeeTemplateItemId` 非空的 `OrderFee`，得到"已生成过的模板明细id集合"；若某明细 id 已在集合中则跳过。这样**取消服务项不删费用、二次完成时不会重复生成**。
9. **金额计算**：`Amount = Round(含税单价 × 数量, 2)`；`NoTaxAmount = Round(不含税单价 × 数量, 2)`（四舍五入 `ToFinancialRound`）。
10. **生成 `OrderFee`**：`DataEntryMethod = Template`（自动费用模板生成）、`OrderFeeTemplateItemId = 来源明细id`、`FeeStatus = Entering`、`SettlementStatus = UnSettled`、`InvoiceStatus = NotIssued`，`TransportOrderId` 取业务id，`AccountDate`、`UserId` 取自业务。所有费用先收集到列表后**批量插入**（`IRepository.InsertAsync(List<OrderFee>)`），不逐条插入。

> [!IMPORTANT] **避坑指南**
>
> - **TransportOrder 无 OrgId 字段**，所属公司必须通过 `UserId` 向上找公司，不能直接取字段。
> - `OrderFee` 与模板是**值复制**关系，无外键关联；模板修改/删除不会回溯影响已生成费用。`OrderFee.OrderFeeTemplateItemId` 仅记录来源明细 id（不建外键），用于防重；模板明细删除/修改后该 id 仍按值保留。
> - **防重依据 `OrderFeeTemplateItemId`**：人工删除了模板生成的费用后再次完成服务项会重新生成（因为防重集合里查不到了），这是预期行为。
> - 汇率缺失是**静默跳过**（不报错），需要前端/运维确保汇率维护完整，否则会出现"应生成而未生成"的费用。
> - **箱型单位未匹配也是静默跳过**：单位填箱型名（非 `票`/`毛重`/`尺码`/`TEU` 的一律按箱型名处理）但本单 `OrderCtn` 里没有该箱型时，整条费用不生成，**不会再生成数量为 0 的空费用**。排查"模板配了却没生成"的顺序：箱型是否存在 → 汇率是否维护 → 是否被 `OrderFeeTemplateItemId` 防重拦截。
> - 箱型名按 `Trim()` 后与 `CtnCode.CtnName` **精确匹配且大小写敏感**（`40hq` 匹配不到 `40HQ`），单位应由下拉选择而非自由输入。
> - 单位为空与箱型不匹配是两回事：**单位为空仍按数量 0 生成费用**，只有箱型不匹配才跳过。
> - `ExchangeRate` 为通用表（不分租户）。
