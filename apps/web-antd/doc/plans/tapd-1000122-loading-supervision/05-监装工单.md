# 05 监装真正模块

## 需求是什么

海运出口一票货开一张 **监装工单**：填明细包装/件数/预计到货/堆场，勾监装要求，可指派最多 2 个监装师傅（也可不指派进公共池）。师傅在小程序认领、填箱号封号、拍照、勾完成。

**本仓库只做内部管理端**（海出编辑工作台新 Tab）。管理端 **没有工单列表接口**，只能按海运出口 id 查。

管理端前缀：`/api/services/app/LoadingOrderAdmin`

| 接口 | HTTP | 地址 | 权限 |
| :-- | :-- | :-- | :-- |
| 新建 | POST | `/LoadingOrderAdmin/AddAsync` | `.Add` |
| 编辑 | PUT | `/LoadingOrderAdmin/EditAsync` | `.Edit` |
| 删除 | DELETE | `/LoadingOrderAdmin/DeleteAsync` | `.Delete` |
| 提交 | POST | `/LoadingOrderAdmin/SubmitAsync` | `.Edit` |
| 撤回 | POST | `/LoadingOrderAdmin/WithdrawAsync` | `.Edit` |
| 按海出查详情 | GET | `/LoadingOrderAdmin/DetailBySeaExportIdAsync?id={海出id}` | `.Get` |
| 已排师傅提示 | GET | `/LoadingOrderAdmin/GetYardUsersAsync` | `.Get`（**本轮不做**） |

`DetailBySeaExportIdAsync` 的 `id` 是 **海运出口 id**，不是工单 id。没有工单时 `result: null` → 显示「新建」。

### 状态 `status`

| 值  | 名称   | 管理端能做什么         |
| :-- | :----- | :--------------------- |
| 0   | 未提交 | 编辑 / 删除 / 提交     |
| 1   | 待认领 | **只能撤回**           |
| 2   | 已认领 | 全部禁用，提示联系师傅 |
| 3   | 已完成 | 同上                   |

提交时：有师傅 → 已认领；无师傅 → 待认领。海出没有箱子不能提交。已认领后管理端改不了人，只能等师傅拒接。

### 新建/编辑入参（编辑把 `seaExportId` 换成工单 `id`，海出不能改）

| JSON | 必填 | 说明 |
| :-- | :-- | :-- |
| `seaExportId` | 新建是 | 与业务委托单 id 相同；一票只能一张工单 |
| `codePackageItemId` | 否 | 必须属于主单包装下的明细 |
| `pkgs` | 否 | 明细包装件数 |
| `estimatedArrivalTime` | 否 |  |
| `carrierYardId` | 否 | 必须属于该海出船公司下的堆场 |
| `userIds` | 否 | long[]；用户属性必须含监装；**前端最多 2 个**；数组顺序即监装顺序 |
| `loadingRequirementItemIds` | 否 | 勾选的明细 id；全量提交，漏传=清空 |

工单号后端按 `LoadingOrder.LoadingOrderNum` 生成，前端不传。

`userIds` / `loadingRequirementItemIds` **不要传 sortId**。

**已拍板：干系人「监装」与工单师傅两套独立，不同步。** 工单只提交 `userIds`，不读、不写订单干系人。

**已拍板：明细包装 / 堆场只认已保存海出。** 进 Tab 用当前票落库的 `codePackageId` / `carrierId` 再打包装详情、船公司详情拉子表。基础信息未保存修改不联动。主单没包装则禁用明细包装，文案对齐后端「该海运出口未填写包装,不能选择明细包装」；没船公司则禁用堆场，文案对齐「该海运出口未选择船公司,不能选择监装堆场」。可选：基础信息 dirty 时给一句弱提示「以下拉已保存数据为准」，不要自动带未保存值。

详情里管理端返回 **全部监装要求**，明细带 `isChecked`，勾选树直接回填。箱型只读：箱型/箱号/封号/是否完成/分组附件，**不要在管理端编辑箱**。

## 验收

1. 海出编辑页在派车与分单之间出现「监装工单」Tab；无 `.Get` 时不出现；无工单可新建。
2. 未选船公司（已保存）不能选堆场；未填包装（已保存）不能选明细包装；基础信息未保存修改不改变这些下拉。
3. 师傅最多 2 人，且只能选属性含监装的用户。
4. 不指派师傅提交 → 待认领，可撤回；指派后提交 → 已认领，管理端不能再改。
5. 无箱子提交失败并提示。
6. 勾选要求再打开，勾选状态与 `isChecked` 一致。
7. 同一海出不能建第二张工单。

## 避坑

- 详情 query 的 `id` 是海出 id。
- 管理端不要调师傅端 `/LoadingOrder/*`。
- 取消完成（师傅端）不会清箱子 `isLoadingCompleted`，与管理端无关，但联调时别误判。
- `GetYardUsersAsync` **本轮不调、不封装 UI**；同一天同一船公司可以多个堆场，该接口不是冲突拦截。
- 附件分组 `attachmentGroups` 全量替换是师傅端行为；管理端只读。

## 本仓库不做

监装师傅端（小程序）接口：`/api/services/app/LoadingOrder`

- `GetMyPagedListAsync` / `DetailAsync` / `ClaimAsync` / `RejectAsync` / `EditOrderCtnsAsync` / `CancelCompleteAsync`

登录人需 `userAttribute & 512`。待认领是全公司公共池，不做地区过滤。  
小程序不在 `FeightForwardingSystem`，不要在本仓库里做页面。
