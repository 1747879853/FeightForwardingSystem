# 04 基础资料新增监装要求模块

## 需求是什么

基础数据下新增 **监装要求**：一条要求名带着一堆明细（主子表），对齐商品信息 + 规格/型号。这是给监装工单勾选用的可复用模板。

## 接口文档在哪

| 用途 | 完整路径 |
| :-- | :-- |
| **前端对接（权威）** | `D:\code\Freight\aspnet-core\文档\监装\监装要求模块接口文档.md` |
| 业务规则 | `D:\code\Freight\aspnet-core\文档\监装\监装要求模块总逻辑文档.md` |
| UI / 列表骨架参照 | `CodeGoodsAdmin` 或 `CodePackageAdmin` |

路由前缀：`/api/services/app/LoadingRequirementAdmin`

| 接口 | HTTP | 地址 | 权限 |
| :-- | :-- | :-- | :-- |
| 新建 | POST | `/LoadingRequirementAdmin/AddAsync` | `Admin.LoadingRequirement.Add` |
| 编辑 | PUT | `/LoadingRequirementAdmin/EditAsync` | `Admin.LoadingRequirement.Edit` |
| 删除 | DELETE | `/LoadingRequirementAdmin/DeleteAsync` | `Admin.LoadingRequirement.Delete` |
| 分页 | GET | `/LoadingRequirementAdmin/GetPagedListAsync` | 仅登录 |
| 详情 | GET | `/LoadingRequirementAdmin/DetailAsync` | 仅登录 |

### 主表入参

| JSON | 必填 | 说明 |
| :-- | :-- | :-- |
| `name` | 是 | 最长 128；**全表唯一**（去空格、忽略大小写） |
| `sortId` | 否 | **前端输入**，列表默认 `SortId ASC`（不是 CreationTime DESC） |
| `remark` | 否 | 最长 1024 |
| `loadingRequirementItems` | 否 | 明细数组 |

### 明细入参

| JSON     | 必填       | 说明                             |
| :------- | :--------- | :------------------------------- |
| `id`     | 编辑保留行 | Guid；新增 `null`                |
| `name`   | 是         | 最长 128；**同一条要求内**不重名 |
| `remark` | 否         | 最长 1024                        |

明细 **不要传 `sortId`**。跨要求的明细可以同名。

当前删除 **没有引用校验**（工单上线后才会拦）。`DeleteAsync` 的 `ids` 批量字段未使用，只按单个 `id`。

## 验收

1. 菜单在基础数据下可见（有权限时）。
2. 新建一条要求 + 多条明细，列表按 `sortId` 升序。
3. 编辑：删/改/增明细一次保存，顺序按提交数组重排。
4. 两条要求同名被拦；同一要求两条明细同名被拦；不同要求明细同名允许。
5. 删除主表后明细一起没了。

## 避坑

- 两个 `sortId` 不是一回事：主表前端填，子表后端生成。
- 列表默认排序是 `SortId ASC`，抄其他基础资料的 `CreationTime DESC` 会和产品预期反掉。
- 后端文档文件名在 TAPD 截图里曾写「业务逻辑文档」，仓库实际是「总逻辑文档」。
