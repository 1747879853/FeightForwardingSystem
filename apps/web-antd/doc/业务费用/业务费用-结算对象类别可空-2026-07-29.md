# 1. 背景意图 (Background)

业务费用（`OrderFee`）的结算对象类别 `IndustryCategory` 此前在**提交审核 / 申请修改**时强制必填。实际业务中类别可不填，只需保留结算对象 `SettlementId` 在提交时必填即可。因此去掉提交环节对 `IndustryCategory` 的非空校验。

# 2. 核心逻辑变更 (Core Changes)

| 位置 | 变更 |
| :-- | :-- |
| `OrderFeeAdminAppService.SubmitOrderFeeAsync` | 删除「提交时结算对象类别不能为空」校验 |
| `OrderFeeAdminAppService.ModifyOrderFeeAsync` | 删除「结算对象类别不能为空」校验 |
| `OrderFee` 实体 / `OrderFeeDto` 相关 DTO 注释 | 由「录入可空、提交必填」改为「全程可空」 |

> `SettlementId` 规则不变：录入可空，提交/申请修改仍必填。

## 2.1 校验规则对比

| 接口                  | 字段               | 变更前 | 变更后       |
| :-------------------- | :----------------- | :----- | :----------- |
| `SubmitOrderFeeAsync` | `IndustryCategory` | 必填   | **可空**     |
| `SubmitOrderFeeAsync` | `SettlementId`     | 必填   | 必填（不变） |
| `ModifyOrderFeeAsync` | `IndustryCategory` | 必填   | **可空**     |
| `ModifyOrderFeeAsync` | `SettlementId`     | 必填   | 必填（不变） |

# 3. 避坑指南 (Blockers)

> [!IMPORTANT]
>
> - **结算对象类别可空不等于结算对象可空**：提交时仍须有 `SettlementId`。
> - 列表/详情出参 `industryCategory` 可能为 `null`，前端展示需容错。
