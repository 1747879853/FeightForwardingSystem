# 背景意图

已审核通过的费用若已进入收费结算（按费用结算明细 `ReceiveSettlementItem`），再发起申请修改或申请删除会导致结算金额与费用金额脱节。此前仅拦截对账、付费申请、开票申请，现补齐收费结算卡点。

# 核心逻辑变更

| 接口 | 变更 |
| :-- | :-- |
| `OrderFeeAdmin/ModifyOrderFeeAsync` | 存在 `ReceiveSettlementItems` 时抛「已进行收费结算的费用不可申请修改」 |
| `OrderFeeAdmin/DeleteOrderFeeAsync` | 存在 `ReceiveSettlementItems` 时抛「已进行收费结算的费用不可申请删除」 |

判定口径：费用在任意收费结算单下存在按费用结算明细即可，不区分结算单状态。

按开票申请结算（`ReceiveSettlementInvoiceItem`）依赖开票申请明细，已由「已关联开票申请」卡点覆盖，本次不再重复校验。

# 避坑指南

- 前端可据费用是否已收费结算预禁用「申请修改 / 申请删除」；服务端仍会硬拦。
- 需改费用时先从收费结算中移除该费用明细，再提交申请。
