# 业务费用任务详情返回录入人 — 前端对接文档

**变更日期**：2026-08-09

**变更概述**：`OrderFeeTaskDetailAsync` 的 `orderFeeTasks[]` 补齐费用录入人昵称 `creatorUserName`（取 `CreatorUserId` 对应缓存用户的 `NickName`）。任务上的审核人/创建人昵称同步改为从用户缓存取值。

---

## 一、受影响的接口

| # | 接口 | 方法 | 路径 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 1 | OrderFeeTaskDetailAsync | GET | `/api/services/app/OrderFeeAdmin/OrderFeeTaskDetailAsync` | 费用任务详情，`orderFeeTasks[].creatorUserName` 有值 |

---

## 二、接口 — OrderFeeTaskDetailAsync

**Summary：** 费用所有任务详情，与列表的行一一对应；每条费用返回录入人昵称。

**路径：** `GET /api/services/app/OrderFeeAdmin/OrderFeeTaskDetailAsync`

**权限：** `Admin.OrderFee.Audit`

### 2.1 请求参数（OrderFeeTaskDetailInputDto）

| 字段名 | JSON Key | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| Id | `id` | Guid | 是 | 关联业务 id，就是 `TransportOrder.Id` |
| ChangeOrderId | `changeOrderId` | Guid? | 否 | 更改单 id。不传代表查主单费用任务；传了代表查该更改单费用任务 |

### 2.2 请求示例

```
主单行：  GET /api/services/app/OrderFeeAdmin/OrderFeeTaskDetailAsync?id=a1b2c3d4-e5f6-7890-abcd-ef1234567890
更改单行：GET /api/services/app/OrderFeeAdmin/OrderFeeTaskDetailAsync?id=a1b2c3d4-e5f6-7890-abcd-ef1234567890&changeOrderId=11111111-1111-1111-1111-111111111111
```

### 2.3 本次出参变化（orderFeeTasks[]）

| 字段名 | JSON Key | 类型 | 变化 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| CreatorUserName | `creatorUserName` | string | **本次补齐赋值** | 费用录入人昵称。来源：费用 `CreatorUserId` → 用户缓存 `NickName`；无创建人或缓存未命中时为 `null` |
| Task.AuditUserName | `task.auditUserName` | string | 取值来源调整 | 审核人昵称，改为用户缓存 |
| Task.CreatorUserName | `task.creatorUserName` | string | 取值来源调整 | 任务创建人昵称，改为用户缓存 |

> DTO 上 `CreatorUserName` 字段原本就存在（`OrderFeeDto` / `OrderFeeAndTaskDto`），本次是详情接口真正赋值返回。

### 2.4 响应结构要点（OrderFeeTaskListDto）

| 字段名 | JSON Key | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| EntityId | `entityId` | Guid | 业务 id |
| ChangeOrderId | `changeOrderId` | Guid? | 更改单 id，主单为 `null` |
| TransportOrder | `transportOrder` | object | 业务简要信息 |
| ChangeOrder | `changeOrder` | object | 更改单简要信息，主单为 `null` |
| OrderFeeTasks | `orderFeeTasks` | array | 费用+任务列表（不含录入中/已驳回） |

`orderFeeTasks[]` 中与本次相关的字段：

| 字段名 | JSON Key | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| Id | `id` | Guid | 费用 id |
| CreatorUserId | `creatorUserId` | long? | 费用创建人 id（录入人） |
| CreatorUserName | `creatorUserName` | string | **费用录入人昵称（本次）** |
| Task | `task` | object | 对应该费用的当前展示任务，无任务时为 `null` |
| Task.AuditUserName | `task.auditUserName` | string | 审核人昵称 |
| Task.CreatorUserName | `task.creatorUserName` | string | 任务创建人昵称 |

### 2.5 响应示例（节选）

```json
{
  "result": {
    "entityId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "changeOrderId": null,
    "orderFeeTasks": [
      {
        "id": "f1111111-1111-1111-1111-111111111111",
        "creatorUserId": 1001,
        "creatorUserName": "张三",
        "task": {
          "id": "t1111111-1111-1111-1111-111111111111",
          "auditUserName": "李四",
          "creatorUserName": "张三"
        }
      }
    ]
  }
}
```

### 2.6 报错

| 报错文案           | 触发条件                               |
| :----------------- | :------------------------------------- |
| `输入信息不能为空` | 入参为 `null`                          |
| `业务id错误`       | `id` 对应业务不存在                    |
| `更改单id错误`     | `changeOrderId` 不存在，或不属于该业务 |

---

## 三、前端对接注意

- 展示「录入人」请用 `orderFeeTasks[].creatorUserName`，不要用 `Name`。
- 该字段与分页列表 `GetPagedListAsync` 的 `creatorUserName` 含义一致，都是费用创建人昵称。
- 无录入人或缓存未命中时字段为 `null`，前端按空展示即可。
