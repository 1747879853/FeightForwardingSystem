# 业务费用任务详情返回录入人

**日期**：2026-08-09  
**类型**：`Feature`  
**模块**：业务费用 / OrderFeeAdmin

---

## 背景意图

费用任务详情页需要展示每条费用的「录入人」。此前 `OrderFeeTaskDetailAsync` 虽映射了 `OrderFeeAndTaskDto`（继承 `OrderFeeDto.CreatorUserName`），但未赋值；任务上的审核人/创建人昵称则直接查用户表。本次与列表接口对齐：录入人取费用 `CreatorUserId` 对应缓存用户的 `NickName`。

---

## 核心逻辑变更

**接口：** `GET /api/services/app/OrderFeeAdmin/OrderFeeTaskDetailAsync`  
**实现：** `OrderFeeAdminAppService.OrderFeeTaskDetailAsync`

1. 用户信息改为 `GetUserInfoMapAsync()`（用户缓存），不再按任务上的 userId 列表查 `_userRepository`。
2. 每条费用赋值：`data.CreatorUserName = users.GetNickName(orderFee.CreatorUserId)`。
3. 任务上的 `AuditUserName` / `CreatorUserName` 同步改为 `users.GetNickName(...)`。

### 字段说明

| 字段 | 含义 | 来源 |
| :-- | :-- | :-- |
| `orderFeeTasks[].creatorUserName` | 费用录入人昵称 | `OrderFee.CreatorUserId` → 用户缓存 `NickName` |
| `orderFeeTasks[].task.auditUserName` | 任务审核人昵称 | `TaskItem.AuditUserId` → 用户缓存 |
| `orderFeeTasks[].task.creatorUserName` | 任务创建人昵称 | `TaskItem.CreatorUserId` → 用户缓存 |

---

## 避坑指南

1. **录入人是费用创建人，不是任务创建人。** 前端展示「录入人」必须用费用级 `creatorUserName`；任务级 `task.creatorUserName` 是任务提交人，二者可能不同（如申请修改/删除场景）。
2. **统一返回 Nickname。** 禁止回退查 `User.Name`；空 id 或缓存未命中返回 `null`。
3. **详情仍不返回录入中/已驳回费用**（既有过滤逻辑未变），录入人只会出现在详情可见的费用行上。
4. **局部影响面：** 仅详情赋值逻辑；DTO 字段未新增，列表 `GetPagedListAsync` 原本已返回同名字段。
