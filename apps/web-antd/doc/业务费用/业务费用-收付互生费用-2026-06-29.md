# 1. 业务背景说明 (Background)

**白话解释：** 一票业务上录好了一组“应收”费用后，往往需要据此自动生成对应的“应付”费用（反之亦然），手工再录一遍既慢又容易选错结算对象。本次在 `OrderFeeAdmin` 控制器新增 `GenerateOppositeOrderFeesAsync` 接口，实现“收付互生费用”：

- 输入收付类型为**收**：根据所选费用生成对应的**应付（付）**费用（收转付）。
- 输入收付类型为**付**：根据所选费用生成对应的**应收（收）**费用（付转收）。

新费用的结算对象（`SettlementId`）不再手工指定，而是按费用代码（`FeeCode`）上配置的默认收/付费客户类型自动从业务的往来单位中取。

---

# 2. 功能与操作说明 (Features & Operations)

- **收付互生费用（GenerateOppositeOrderFeesAsync）：** 校验所选费用归属（业务/收付类型/更改单）与费用锁定后，按费用代码默认客户类型解析结算对象，生成对应收付类型的费用，返回新生成的费用 id 列表。

---

# 3. 接口：收付互生费用

| 项       | 内容                                |
| :------- | :---------------------------------- |
| 控制器   | `OrderFeeAdmin`                     |
| 接口     | `GenerateOppositeOrderFeesAsync`    |
| 方法     | `POST`                              |
| 权限     | `Admin.OrderFee.Add`                |
| 入参 DTO | `GenerateOppositeOrderFeesInputDto` |
| 出参     | `List<Guid>`（新生成的费用id列表）  |

## 3.1 入参 `GenerateOppositeOrderFeesInputDto`

| 字段名 | JSON Key | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| TransportOrderId | `transportOrderId` | `Guid` | 业务id（`TransportOrder.Id`） |
| PaySide | `paySide` | `int`（枚举） | 输入费用的收付类型（0=收 1=付）。收→生成应付；付→生成应收 |
| OrderFeeIds | `orderFeeIds` | `Guid[]` | 源费用id列表（均需属于该业务、该收付类型、该更改单） |
| ChangeOrderId | `changeOrderId` | `Guid?` | 更改单id，可空。不为空时校验源费用归属该更改单，新费用归属该更改单，并判断该更改单是否费用锁定 |

## 3.2 处理逻辑

1. 校验 `OrderFeeIds` 非空；按 `TransportOrderId` 找业务，不存在报“业务不存在”。
2. 传 `ChangeOrderId` 时校验更改单存在且归属该业务。
3. **费用锁定校验**（复用 `FeeLockedCheckAsync`）：传更改单则校验更改单锁定，否则校验业务锁定。
4. **源费用校验**：按 `OrderFeeIds` 查出源费用，逐条校验：
   - 存在（缺失则报“费用不存在”）；
   - `TransportOrderId` 与输入一致（否则报“不属于该业务”）；
   - `PaySide` 与输入一致（否则报“收付类型与输入不一致”）；
   - `ChangeOrderId` 与输入一致（否则报“不属于指定的更改单”）。
5. **确定目标收付类型与录入方式**：收→付（`DataEntryMethod=ToPay`，收转付）；付→收（`DataEntryMethod=ToReceive`，付转收）。
6. **解析结算对象**：对每条源费用取其 `FeeCode`：
   - 生成应收（收）取 `FeeCode.DefaultDebitName`；生成应付（付）取 `FeeCode.DefaultCreditName`；
   - 该字段为 `IndustryCategory` 枚举的英文字母（`a`=船公司、`b`=发货人、`c`=场站…，即枚举值 n 对应字母 `'a'+n-1`）；
   - 据此定位行业类别，再从业务/海运出口取对应往来单位 id 作为 `SettlementId`，并写入 `IndustryCategory`。
7. 生成新 `OrderFee`：`PaySide`=目标收付类型；`AccountDate` 传更改单取更改单会计期间否则取业务会计期间；`UserId` 取业务 `UserId`；状态初始化 `FeeStatus=Entering`、`SettlementStatus=UnSettled`、`InvoiceStatus=NotIssued`、`SettledAmount=0`；金额/单价/数量/税率/币别/费用代码/单位/备注/是否开票/是否机密沿用源费用。
8. 返回新生成的费用 id 列表。

## 3.3 结算对象类别映射（字母 → 类别 → 取数来源）

> 仅支持下列类别，否则报错提示（“…不支持，仅支持：发货人、场站、收货人、报关行、通知人、车队、订舱代理、委托单位、仓库、保险公司、国外代理(目的港代理)”）。

| 字母 | 行业类别               | 取数来源字段                  |
| :--- | :--------------------- | :---------------------------- |
| b    | 发货人                 | `TransportOrder.ShipperId`    |
| c    | 场站                   | `SeaExport.YardId`            |
| e    | 收货人                 | `TransportOrder.ConsigneeId`  |
| f    | 报关行                 | `TransportOrder.CustBrokerId` |
| h    | 通知人                 | `TransportOrder.NotifierId`   |
| i    | 车队                   | `TransportOrder.TeamId`       |
| o    | 订舱代理               | `SeaExport.BookingAgentId`    |
| p    | 委托单位               | `TransportOrder.ClientId`     |
| q    | 仓库                   | `TransportOrder.WarehouseId`  |
| r    | 保险公司               | `TransportOrder.InsuranceId`  |
| s    | 目的港代理（国外代理） | `SeaExport.PodAgentId`        |

# 4. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **[卡点 1：费用锁定]** 业务（或指定更改单）已费用锁定时，禁止互生费用，直接报错。

> [!IMPORTANT] **[卡点 2：源费用归属一致性]** 所选费用必须同时满足“属于该业务、收付类型与输入一致、归属同一更改单”，任一条不满足即整体报错，不会部分生成。

> [!IMPORTANT] **[卡点 3：费用代码默认客户类型配置]** 费用代码未配置默认收/付费客户类型，或配置的类别不在支持范围内，则报错；类别落在“场站/订舱代理/目的港代理”但业务无对应海运出口或业务未维护该往来单位时，报“业务未设置[xx]”错误。
