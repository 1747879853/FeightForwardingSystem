# 1. 背景意图 (Background)

费用申请修改流程中存在两份 JSON 快照，前端做修改前/后对比时都需要可读的**费用代码 Code、结算对象 Name、币别 Code**：

- **修改前快照**：`OrderFeeTaskAuditAsync`（费用所有任务审核）审核**通过费用申请修改（ModifyOrderFee）**时，把修改前的费用序列化为 `OrderFeeEditDto` 存入 `TaskItem.OriginalInfo`。
- **修改后快照**：`ModifyOrderFeeAsync`（费用申请修改）创建任务时，把要修改为的费用序列化为 `OrderFeeDto` 存入 `TaskItem.Info`。

原先这两份快照主要保存的是 `FeeCodeId`、`SettlementId`、`CurrencyId` 等 **ID**（`Info` 虽有名称但缺费用代码 Code/币别 Code），前端展示需额外回查关联表。因此两份快照都补充冗余记录：**费用代码 Code、结算对象 Name、币别 Code**。

# 2. 核心逻辑变更 (Core Logic)

涉及文件：

- `src/CsprojBuilder.Application/App/OrderFee/Dto/OrderFeeDto.cs`（`OrderFeeEditDto`、`OrderFeeDto`）
- `src/CsprojBuilder.Application/App/OrderFee/OrderFeeAdminAppService.cs`（`OrderFeeTaskAuditAsync`、`ModifyOrderFeeAsync`）

## 修改前快照 `OriginalInfo`（`OrderFeeEditDto`）

`OrderFeeEditDto` 新增 3 个仅在记录 `OriginalInfo` 快照时填充的字段：

| 字段             | 业务含义            | 数据来源        |
| :--------------- | :------------------ | :-------------- |
| `FeeCodeCode`    | 修改前费用代码 Code | `FeeCode.Code`  |
| `SettlementName` | 修改前结算对象名称  | `Client.Name`   |
| `CurrencyCode`   | 修改前币别 Code     | `Currency.Code` |

在 `OrderFeeTaskAuditAsync` 中，对涉及 `ModifyOrderFee` 类型任务的费用，在进入审核循环前一次性批量查出 `FeeCode.Code`、`Client.Name`、`Currency.Code` 三个映射字典（避免循环内 N+1）。审核通过记录 `OriginalInfo` 时，根据修改前费用的 `FeeCodeId` / `SettlementId` / `CurrencyId` 从字典取值填充到快照 DTO 后再序列化。

## 修改后快照 `Info`（`OrderFeeDto`）

`Info` 由 `ModifyOrderFeeAsync` 序列化 `OrderFeeDto` 得到。`OrderFeeDto` 已有 `CurrencyCode`、`SettlementName`，本次新增 `FeeCodeCode`：

| 字段 | 业务含义 | 数据来源 | 状态 |
| :-- | :-- | :-- | :-- |
| `FeeCodeCode` | 修改后费用代码 Code | `FeeCode.Code` | 新增字段 |
| `SettlementName` | 修改后结算对象名称 | `Client.Name` | 已有，原已填充 |
| `CurrencyCode` | 修改后币别 Code | `Currency.Code` | 已有，本次补充填充 |

在 `ModifyOrderFeeAsync` 构建 `OrderFeeDto`（`Info` 数据源）时，原先只填了 `FeeCodeName`、`CurrencyName`、`SettlementName`，本次补充 `data.FeeCodeCode = feeCode.Code` 与 `data.CurrencyCode = currency.Code`。

# 3. 避坑指南 (Pitfalls)

- **取值时机**：`OriginalInfo` 必须在用 `newFeeInfo` 覆盖 `orderFee` 字段**之前**取原始 `FeeCodeId` / `SettlementId` / `CurrencyId`，否则记录到的是修改后的值。本次实现通过循环前批量构建字典，并在覆盖前读取，规避该问题。
- **Code vs CnName**：费用代码与币别记录的是 `Code`（不是 `CnName`），结算对象记录的是 `Name`。
- **`OrderFeeDto` 已有 CurrencyCode/SettlementName**：`Info` 用的 `OrderFeeDto` 早已定义 `CurrencyCode`、`SettlementName`，但 `ModifyOrderFeeAsync` 此前只赋值了 `SettlementName`，`CurrencyCode` 一直为空，本次补齐；`FeeCodeCode` 为新增字段。
- **OriginalInfo 仅快照填充**：`OrderFeeEditDto` 的这三个字段只在写入 `OriginalInfo` 时填充，反序列化还原费用时不会用到，仅供前端展示。
- **批量审核未改动**：`OrderFeeTaskBatchAuditAsync`、`ModifyOrderFeeAuditAsync` 同样存在记录 `OriginalInfo` 的逻辑，本次未同步，如需展示需另行处理。
