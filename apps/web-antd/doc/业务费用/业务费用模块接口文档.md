# 业务费用模块接口文档

前端专属，只写接口。业务含义、卡点、校验口径见同目录《业务费用模块总逻辑文档》。

本稿先覆盖申请修改、申请删除、按入参改排序、按录入时间恢复顺序。其它业务费用接口仍见同目录历史对接文档，后续改动再往本文归拢。

接口地址里的 `Async` 后缀不能省。

---

# 1. 申请修改

| 项 | 值 |
| :--- | :--- |
| 接口地址 | `POST /api/services/app/OrderFeeAdmin/ModifyOrderFeeAsync` |
| 方法名 | `ModifyOrderFeeAsync` |
| 入参 | `ModifyOrderFeeDto`（`[FromBody]`） |
| 出参 | `Guid`（主任务 `TaskBase.Id`） |
| 权限 | `Admin.OrderFee.Edit` |

## 1.1 入参 `ModifyOrderFeeDto`

| 字段名 | JSON Key | 类型 | 必填 | 含义 | 说明 |
| :--- | :--- | :--- | :---: | :--- | :--- |
| TransportOrderId | `transportOrderId` | Guid | 是 | 业务主单 id | 就是 `TransportOrder.Id` |
| Remark | `remark` | string | 是 | 申请修改原因 | **2026-09-18 由可空改为必填**。`null` / 空 / 纯空白报「申请修改原因不能为空」；最长 4096。落到每条子任务 `TaskItem.Remark`。**不是**费用行 `orderFees[].remark` |
| OrderFees | `orderFees` | `OrderFeeEditDto[]` | 是 | 要改成的费用列表 | 不能为空；每条必须已有 id，且属于本业务；只能是已审核通过的费用 |

## 1.2 入参嵌套 `OrderFeeEditDto`（`orderFees[]`）

申请修改会用这些字段生成修改后快照，审批通过后才写回费用。收付类型、更改单归属以库里为准，入参改了也不落库。

| 字段名 | JSON Key | 类型 | 必填 | 含义 | 说明 |
| :--- | :--- | :--- | :---: | :--- | :--- |
| Id | `id` | Guid? | 是 | 费用 id | 申请修改必须带已有 id |
| PaySide | `paySide` | int | 否 | 收付类型 | 不落库 |
| ChangeOrderId | `changeOrderId` | Guid? | 否 | 更改单 id | 归属以后端按库里解析为准 |
| TransportOrderId | `transportOrderId` | Guid | 是 | 业务 id | 必须等于外层 `transportOrderId` |
| FeeCodeId | `feeCodeId` | long | 是 | 费用代码 id | `<=0` 报「费用名称不能为空」 |
| IndustryCategory | `industryCategory` | int? | 否 | 结算对象类别 | 申请修改允许为空 |
| SettlementId | `settlementId` | Guid? | 是 | 结算对象 id | 空报「结算对象不能为空」 |
| CurrencyId | `currencyId` | long | 是 | 币别 id | `<=0` 报「币别id不能为空」 |
| ExchangeRate | `exchangeRate` | decimal | 是 | 汇率 | 不能为负 |
| UnitPrice | `unitPrice` | decimal | 是 | 含税单价 | 后端按单价×数量重算金额 |
| NoTaxUnitPrice | `noTaxUnitPrice` | decimal | 否 | 不含税单价 | 原样写入快照 |
| Amount | `amount` | decimal | 否 | 金额 | 后端重算覆盖；重算后为 0 报「金额为0的费用不可提交」 |
| NoTaxAmount | `noTaxAmount` | decimal | 否 | 不含税金额 | 原样写入快照 |
| Unit | `unit` | string | 否 | 单位 | — |
| Quantity | `quantity` | decimal | 是 | 数量 | 不能为负 |
| TaxRate | `taxRate` | decimal | 否 | 税率(%) | 不能为负 |
| InvoiceBlocked | `invoiceBlocked` | bool | 否 | 是否禁开发票 | — |
| IsConfidential | `isConfidential` | bool | 否 | 是否机密 | 没有机密编辑权限时不会写入快照 |
| SortId | `sortId` | int | 否 | 排序id | 越小越靠前，允许相同；不传按 `0`。写入修改后快照 |
| Remark | `remark` | string | 否 | 费用行备注 | 写入修改后快照；可空，最长 4096。**不要当成任务级备注** |

## 1.3 出参

返回主任务 id（`Guid`）。没有嵌套对象。

## 1.4 报错

| 报错文案 | 触发条件 |
| :--- | :--- |
| `输入信息不能为空` | body 为空 |
| `业务id错误` | 业务不存在 |
| `费用不能为空` | `orderFees` 为空 |
| `费用与业务不一致` | 某条费用的 `transportOrderId` 与外层不一致 |
| `非审核通过状态费用不可提交` | 勾选费用不是已审核通过 |
| `已参与对账的费用不可申请修改` | 费用已进对账单 |
| `已进行付费申请的费用不可申请修改` | 费用已进付费申请 |
| `已关联开票申请的费用不可申请修改` | 费用已进开票申请 |
| `已进行收费结算的费用不可申请修改` | 费用已进收费结算 |
| `费用已申请修改/删除,请等待审批` | 同一条费用已有审核中的修改或删除任务 |
| `申请修改原因不能为空` | **2026-09-18 新增。** 任务级 `remark` 为空或纯空白 |
| `备注长度不能超过4096个字符` | 任务级 `remark` 或费用行 `remark` 超长 |
| `结算对象不能为空` | 费用未填结算对象（字段屏蔽会先回填，被屏蔽的用户不会误报这条） |
| `金额为0的费用不可提交` | 重算后金额为 0 |
| `未配置或未启用费用变更工作流，无法提交审核` | 费用变更工作流没配好 |

# 4. 费用行 `sortId` 与列表顺序

费用表新增 `sortId`（int，越小越靠前，允许相同，不传按 `0`）。录入、编辑、提交、申请修改、更改单保存都按入参写入；复制、批量引入、收付互生沿用源费用。

## 4.1 有 `sorting` 入参的列表——不要改

这些接口前端本来就有排序字段，后端仍走入参 `sorting`。基类 `PagingAndSorting` 默认值是 `CreationTime DESC`，前端不传也会按创建时间倒序，**不会**自动改成 `sortId`。

| 接口 | 说明 |
| :--- | :--- |
| `GET /api/services/app/OrderFeeAdmin/GetPagedListAsync` | 业务费用分页列表 |
| 付费申请 / 对账 / 开票申请 / 收费结算 / 付费结算等外层分页 | 外层单据列表仍走各自的 `sorting` |

## 4.2 没有费用级排序入参的嵌套清单——按 `sortId` 升序

下面这些返回值里的费用数组没有单独的 `sorting`，服务端固定 `sortId` 升序、相同再按 `creationTime` 升序。前端按返回顺序渲染即可。

- 海运出口 / 海运进口 / 空运出口列表与详情：`transportOrder.orderFees`
- 更改单详情：`orderFees`
- 费用任务列表 / 详情、批量引入候选费用
- 付费申请、客户对账、开票申请、收费结算、付费结算里挂在单据下的费用清单

## 4.3 费用打印——服务端强制 `sortId` 升序

`POST /api/services/app/PrintFormatAdmin/GetPrintAsync` 打应收/应付费用时：

- 普通打印：覆盖 `orderFeeListInput.sorting` 为 `SortId ASC, CreationTime ASC`，再调 `OrderFeeAdmin/GetPagedListAsync`
- 更改单打印：`ChangeOrderAdmin/DetailAsync` 取费用后按收付过滤，再按 `sortId`、`creationTime` 升序

前端给费用打印传 `sorting` 无效。分页仍要自己传够大的 `pageSize`。

# 5. 按入参改费用排序

| 项 | 值 |
| :--- | :--- |
| 接口地址 | `POST /api/services/app/OrderFeeAdmin/SortOrderFeesAsync` |
| 方法名 | `SortOrderFeesAsync` |
| 入参 | `OrderFeeSortDto`（`[FromBody]`） |
| 出参 | 无 |
| 权限 | `Admin.OrderFee.Edit` |

不做锁定、状态、对账、付费申请、开票、字段屏蔽等任何判断。只改 `sortId`。列表为空直接返回。费用 id 不存在就跳过。同一个 id 出现多次时以列表最后一次为准。

## 5.1 入参 `OrderFeeSortDto`

| 字段名 | JSON Key | 类型 | 必填 | 含义 | 说明 |
| :--- | :--- | :--- | :---: | :--- | :--- |
| OrderFees | `orderFees` | `OrderFeeSortItemDto[]` | 否 | 费用排序列表 | 空或 `null` 直接返回，不报错 |

## 5.2 入参嵌套 `OrderFeeSortItemDto`（`orderFees[]`）

| 字段名 | JSON Key | 类型 | 必填 | 含义 | 说明 |
| :--- | :--- | :--- | :---: | :--- | :--- |
| Id | `id` | Guid | 是 | 费用 id | 找不到就跳过 |
| SortId | `sortId` | int | 是 | 排序id | 越小越靠前，允许相同 |

## 5.3 请求示例

```json
{
  "orderFees": [
    { "id": "00000000-0000-0000-0000-000000000011", "sortId": 0 },
    { "id": "00000000-0000-0000-0000-000000000012", "sortId": 1 }
  ]
}
```

# 6. 按录入时间恢复费用顺序

| 项 | 值 |
| :--- | :--- |
| 接口地址 | `POST /api/services/app/OrderFeeAdmin/RestoreOrderFeeSortAsync` |
| 方法名 | `RestoreOrderFeeSortAsync` |
| 入参 | `RestoreOrderFeeSortDto`（`[FromBody]`） |
| 出参 | 无 |
| 权限 | `Admin.OrderFee.Edit` |

同样不做任何业务判断。命中 `transportOrderId` + `changeOrderId` + `paySide` 的费用，按录入时间升序把 `sortId` 写成 `0、1、2…`。录入时间相同再按主键。没有命中任何费用也直接返回。

## 6.1 入参 `RestoreOrderFeeSortDto`

| 字段名 | JSON Key | 类型 | 必填 | 含义 | 说明 |
| :--- | :--- | :--- | :---: | :--- | :--- |
| TransportOrderId | `transportOrderId` | Guid | 是 | 业务 id | 不存在则一条都不改，不报错 |
| ChangeOrderId | `changeOrderId` | Guid? | 否 | 更改单 id | **空 / 不传 = 只恢复主单费用**。有值只恢复该更改单下、该收付类型的费用 |
| PaySide | `paySide` | int | 是 | 收付类型 | `0` 收 / `1` 付。一次只恢复一种 |

## 6.2 请求示例

主单应收：

```json
{
  "transportOrderId": "00000000-0000-0000-0000-000000000001",
  "paySide": 0
}
```

某更改单应付：

```json
{
  "transportOrderId": "00000000-0000-0000-0000-000000000001",
  "changeOrderId": "00000000-0000-0000-0000-000000000002",
  "paySide": 1
}
```
