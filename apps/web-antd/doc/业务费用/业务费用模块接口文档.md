# 业务费用模块接口文档

前端专属，只写接口。业务含义、卡点、校验口径见同目录《业务费用模块总逻辑文档》。

本稿覆盖申请修改、申请删除、按入参改排序、按录入时间恢复顺序、费用预警，以及件杂货上线涉及的费用任务分组统计、费用任务列表与详情（业务类型相关部分）、批量引入候选查询、为业务批量引入费用、收付互生费用。其它业务费用接口仍见同目录历史对接文档，后续改动再往本文归拢。

**业务类型 `bizType` 取值**：0 海运出口、1 海运进口、2 空运出口、3 件杂货。件杂货的港口是海运港口表（与海运出口、海运进口同一张），没有船公司、装运方式、订单类型、场站、集装箱。

接口地址里的 `Async` 后缀不能省。

# 1. 申请修改

| 项       | 值                                                         |
| :------- | :--------------------------------------------------------- |
| 接口地址 | `POST /api/services/app/OrderFeeAdmin/ModifyOrderFeeAsync` |
| 方法名   | `ModifyOrderFeeAsync`                                      |
| 入参     | `ModifyOrderFeeDto`（`[FromBody]`）                        |
| 出参     | `Guid`（主任务 `TaskBase.Id`）                             |
| 权限     | `Admin.OrderFee.Edit`                                      |

## 1.1 入参 `ModifyOrderFeeDto`

| 字段名 | JSON Key | 类型 | 必填 | 含义 | 说明 |
| :-- | :-- | :-- | :-: | :-- | :-- |
| TransportOrderId | `transportOrderId` | Guid | 是 | 业务主单 id | 就是 `TransportOrder.Id` |
| Remark | `remark` | string | 是 | 申请修改原因 | **2026-09-18 由可空改为必填**。`null` / 空 / 纯空白报「申请修改原因不能为空」；最长 4096。落到每条子任务 `TaskItem.Remark`。**不是**费用行 `orderFees[].remark` |
| OrderFees | `orderFees` | `OrderFeeEditDto[]` | 是 | 要改成的费用列表 | 不能为空；每条必须已有 id，且属于本业务；只能是已审核通过的费用 |

## 1.2 入参嵌套 `OrderFeeEditDto`（`orderFees[]`）

申请修改会用这些字段生成修改后快照，审批通过后才写回费用。收付类型、更改单归属以库里为准，入参改了也不落库。

| 字段名 | JSON Key | 类型 | 必填 | 含义 | 说明 |
| :-- | :-- | :-- | :-: | :-- | :-- |
| Id | `id` | Guid? | 是 | 费用 id | 申请修改必须带已有 id |
| PaySide | `paySide` | int | 否 | 收付类型 | 不落库 |
| ChangeOrderId | `changeOrderId` | Guid? | 否 | 更改单 id | 归属以后端按库里解析为准 |
| TransportOrderId | `transportOrderId` | Guid | 是 | 业务 id | 必须等于外层 `transportOrderId` |
| FeeCodeId | `feeCodeId` | long | 是 | 费用代码 id | `<=0` 报「费用名称不能为空」 |
| IndustryCategory | `industryCategory` | int? | 否 | 结算对象类别 | 申请修改允许为空 |
| SettlementId | `settlementId` | Guid? | 是 | 结算对象 id | 空报「结算对象不能为空」 |
| CurrencyId | `currencyId` | long | 是 | 币别 id | `<=0` 报「币别id不能为空」 |
| ExchangeRate | `exchangeRate` | decimal | 是 | 汇率 | 不能为负 |
| UnitPrice | `unitPrice` | decimal | 是 | 含税单价 | 后端按单价×数量重算金额 |
| NoTaxUnitPrice | `noTaxUnitPrice` | decimal | 否 | 不含税单价 | 原样写入快照 |
| Amount | `amount` | decimal | 否 | 金额 | 后端重算覆盖；重算后为 0 报「金额为0的费用不可提交」 |
| NoTaxAmount | `noTaxAmount` | decimal | 否 | 不含税金额 | 原样写入快照 |
| Unit | `unit` | string | 否 | 单位 | — |
| Quantity | `quantity` | decimal | 是 | 数量 | 不能为负 |
| TaxRate | `taxRate` | decimal | 否 | 税率(%) | 不能为负 |
| InvoiceBlocked | `invoiceBlocked` | bool | 否 | 是否禁开发票 | — |
| IsConfidential | `isConfidential` | bool | 否 | 是否机密 | 没有机密编辑权限时不会写入快照 |
| SortId | `sortId` | int | 否 | 排序id | 越小越靠前，允许相同；不传按 `0`。写入修改后快照 |
| Remark | `remark` | string | 否 | 费用行备注 | 写入修改后快照；可空，最长 4096。**不要当成任务级备注** |

## 1.3 出参

返回主任务 id（`Guid`）。没有嵌套对象。

## 1.4 报错

| 报错文案 | 触发条件 |
| :-- | :-- |
| `输入信息不能为空` | body 为空 |
| `业务id错误` | 业务不存在 |
| `费用不能为空` | `orderFees` 为空 |
| `费用与业务不一致` | 某条费用的 `transportOrderId` 与外层不一致 |
| `非审核通过状态费用不可提交` | 勾选费用不是已审核通过 |
| `已参与对账的费用不可申请修改` | 费用已进对账单 |
| `已进行付费申请的费用不可申请修改` | 费用已进付费申请 |
| `已关联开票申请的费用不可申请修改` | 费用已进开票申请 |
| `已进行收费结算的费用不可申请修改` | 费用已进收费结算 |
| `费用已申请修改/删除,请等待审批` | 同一条费用已有审核中的修改或删除任务 |
| `申请修改原因不能为空` | **2026-09-18 新增。** 任务级 `remark` 为空或纯空白 |
| `备注长度不能超过4096个字符` | 任务级 `remark` 或费用行 `remark` 超长 |
| `结算对象不能为空` | 费用未填结算对象（字段屏蔽会先回填，被屏蔽的用户不会误报这条） |
| `金额为0的费用不可提交` | 重算后金额为 0 |
| `未配置或未启用费用变更工作流，无法提交审核` | 费用变更工作流没配好 |

# 4. 费用行 `sortId` 与列表顺序

费用表新增 `sortId`（int，越小越靠前，允许相同，不传按 `0`）。录入、编辑、提交、申请修改、更改单保存都按入参写入；复制、批量引入、收付互生沿用源费用。

## 4.1 有 `sorting` 入参的列表——不要改

这些接口前端本来就有排序字段，后端仍走入参 `sorting`。基类 `PagingAndSorting` 默认值是 `CreationTime DESC`，前端不传也会按创建时间倒序，**不会**自动改成 `sortId`。

| 接口 | 说明 |
| :-- | :-- |
| `GET /api/services/app/OrderFeeAdmin/GetPagedListAsync` | 业务费用分页列表 |
| 付费申请 / 对账 / 开票申请 / 收费结算 / 付费结算等外层分页 | 外层单据列表仍走各自的 `sorting` |

## 4.2 没有费用级排序入参的嵌套清单——按 `sortId` 升序

下面这些返回值里的费用数组没有单独的 `sorting`，服务端固定 `sortId` 升序、相同再按 `creationTime` 升序。前端按返回顺序渲染即可。

- 海运出口 / 海运进口 / 空运出口列表与详情：`transportOrder.orderFees`
- 更改单详情：`orderFees`
- 费用任务列表 / 详情、批量引入候选费用
- 付费申请、客户对账、开票申请、收费结算、付费结算里挂在单据下的费用清单

## 4.3 费用打印——服务端强制 `sortId` 升序

`POST /api/services/app/PrintFormatAdmin/GetPrintAsync` 打应收/应付费用时：

- 普通打印：覆盖 `orderFeeListInput.sorting` 为 `SortId ASC, CreationTime ASC`，再调 `OrderFeeAdmin/GetPagedListAsync`
- 更改单打印：`ChangeOrderAdmin/DetailAsync` 取费用后按收付过滤，再按 `sortId`、`creationTime` 升序

前端给费用打印传 `sorting` 无效。分页仍要自己传够大的 `pageSize`。

## 6.1 入参 `RestoreOrderFeeSortDto`

| ChangeOrderId | `changeOrderId` | Guid? | 否 | 更改单 id | **空 / 不传 = 只恢复主单费用**。有值只恢复该更改单下、该收付类型的费用 |
| PaySide | `paySide` | int | 是 | 收付类型 | `0` 收 / `1` 付。一次只恢复一种 |

## 6.2 请求示例

```json
}
```

```json
{
  "transportOrderId": "00000000-0000-0000-0000-000000000001",
```

# 7. 费用预警

| 项       | 值                                                             |
| :------- | :------------------------------------------------------------- |
| 接口地址 | `GET /api/services/app/OrderFeeAdmin/GetOrderFeeWarningsAsync` |
| 方法名   | `GetOrderFeeWarningsAsync`                                     |
| 入参     | `OrderFeeWarningQueryDto`（`[FromQuery]`）                     |
| 出参     | `OrderFeeWarningGroupDto[]`                                    |
| 权限     | `Admin.OrderFee.Get`                                           |

按 `transportOrderId` + `changeOrderId` 取出这一行的全部费用，按下面 11 类规则现场计算预警。无命中返回空数组。有机密查看权限才把机密费用算进去。

## 7.1 入参 `OrderFeeWarningQueryDto`

| 字段名 | JSON Key | 类型 | 必填 | 含义 | 说明 |
| :-- | :-- | :-- | :-: | :-- | :-- |
| TransportOrderId | `transportOrderId` | Guid | 是 | 业务 id | 空报「业务id不能为空」；业务不存在报「业务id错误」 |
| ChangeOrderId | `changeOrderId` | Guid? | 否 | 更改单 id | **空 / 不传 / 全 0 = 只匹配主单费用**。有值只匹配该更改单下的费用；更改单不存在报「更改单不存在」；不属于该业务报「更改单不属于该业务」 |

## 7.2 出参 `OrderFeeWarningGroupDto[]`

数组按预警类型分组，**每种 `type` 最多一组**。组内 `items` 条数看类型：按费用名/币别拆开的可以有多条；负数金额这类合并成一条；整行汇总的 `items` 为空数组。无命中返回 `[]`。

| 字段名 | JSON Key | 类型 | 含义 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| Type | `type` | int | 预警类型 | 见 7.3。JSON 是数字 |
| PaySide | `paySide` | int? | 收付类型 | **2026-09-19 由 `side`（`OrderFeeWarningSide`）改为 `paySide`。** 沿用费用的 `PaySide`：`0` 收、`1` 付；不分收付为 `null` |
| Items | `items` | `OrderFeeWarningItemDto[]` | 该类型下的明细 | 恒有值，不会是 `null`。整行汇总（2.1 / 11）为空数组 |

### 7.2.1 出参嵌套 `items[]`（`OrderFeeWarningItemDto`）

| 字段名 | JSON Key | 类型 | 含义 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| FeeCode | `feeCode` | `FeeCodeSimpleDto` | 费用名 | **按 `FeeCodeId` 拆开的类型才有**（1.1 / 1.2 / 1.3 / 1.4 / 3 / 4 / 7.1 / 7.2）。其它类型为 `null` |
| Currency | `currency` | `CurrencySimpleDto` | 币别 | **按 `CurrencyId` 拆开的类型才有**（2.2）。其它类型为 `null`。只有 `code` / `cnName` / `enName`，没有 id |
| OrderFeeIds | `orderFeeIds` | Guid[] | 本条明细对应的费用 id | 整行汇总的组没有明细，故没有这个字段。合并型预警把该类型下所有命中费用 id 放进这一条 |

`FeeCodeSimpleDto` 字段与费用模块其它接口相同（`id` / `code` / `cnName` / `enName` 等），此处不重复列。

## 7.3 预警类型 `type`

| 值 | 编号 | paySide | items | 含义 |
| :-: | :-- | :-- | :-- | :-- |
| 11 | 1.1 | `0` 收 | 每个汇率不一致的费用名一条，带 `feeCode` | 同一 `feeCodeId` 的应收费用存在不同汇率 |
| 12 | 1.2 | `1` 付 | 每个汇率不一致的费用名一条，带 `feeCode` | 同一 `feeCodeId` 的应付费用存在不同汇率 |
| 13 | 1.3 | `0` 收 | 每个税率不一致的费用名一条，带 `feeCode` | 同一 `feeCodeId` 的应收费用存在不同税率 |
| 14 | 1.4 | `1` 付 | 每个税率不一致的费用名一条，带 `feeCode` | 同一 `feeCodeId` 的应付费用存在不同税率 |
| 21 | 2.1 | **`null`** | **空数组** | 合计利润 &lt; 0（金额×汇率折本位币，应收合计 − 应付合计） |
| 22 | 2.2 | **`null`** | 每个亏损币别一条，带 `currency` | 单一币别利润 &lt; 0（**不乘汇率**，按 `currencyId` 分组，应收金额 − 应付金额） |
| 30 | 3 | **`null`** | 每个亏损费用名一条，带 `feeCode` | 同一 `feeCodeId` 利润 &lt; 0（金额×汇率，应收 − 应付） |
| 40 | 4 | `1` 付 | 每个缺失的应付费用名一条，带 `feeCode` | 应付的 `feeCodeId` 在应收中一次都没出现 |
| 51 | 5.1 | `0` 收 | **一条**，合并全部负数应收费用 id | 应收存在负数金额 |
| 52 | 5.2 | `1` 付 | **一条**，合并全部负数应付费用 id | 应付存在负数金额 |
| 61 | 6.1 | `0` 收 | **一条**，合并汇率对不上的应收费用 id | 应收汇率不是本月汇率。本位币必须 = 1；其它币别取会计期间对应汇率表 `DRValue` |
| 62 | 6.2 | `1` 付 | **一条**，合并汇率对不上的应付费用 id | 应付汇率不是本月汇率。本位币必须 = 1；其它币别取会计期间对应汇率表 `CRValue` |

## 8.4 下钻

- 起运港/目的港分组：**`isSea` 和 `id` 一起回传**，如 `OrderFeeTaskListAsync?isSea=true&polId=1001`（海港，海运出口 + 海运进口 + 件杂货）。
- 空分组（`id` 为 `null`）：改传对应的 `*Empty=true`，如 `polIdEmpty=true`、`carrierIdEmpty=true`，不要再传 `isSea`/`polId`。
- `isSea` 与 `bizType` 可以叠加：`isSea=true&bizType=3&polId=1001` 表示只看该海港下的件杂货。

# 11. 为业务批量引入费用

| 项 | 值 |
| :-- | :-- |
| 接口地址 | `POST /api/services/app/OrderFeeAdmin/ImportOrderFeesToTransportOrderAsync` |
| 方法名 | `ImportOrderFeesToTransportOrderAsync` |
| 入参 | `ImportOrderFeesToTransportOrderInputDto`（`[FromBody]`） |
| 出参 | `Guid[]`（新生成的费用 id） |
| 权限 | `Admin.OrderFee.Add` |

把第 10 节选出的来源费用复制到目标业务下，新费用一律是录入状态。数量按单位在**目标业务**上重算（单位是箱型名而目标业务没有这个箱型的，那条不引入；件杂货、空运出口没有集装箱，箱型单位的费用都会跳过），金额随数量重算；汇率按目标业务（或更改单）的会计期间重取；排序号、备注、禁开、机密沿用来源费用。

## 11.1 入参 `ImportOrderFeesToTransportOrderInputDto`

| 字段名 | JSON Key | 类型 | 必填 | 含义 | 说明 |
| :-- | :-- | :-- | :-: | :-- | :-- |
| TransportOrderId | `transportOrderId` | Guid | 是 | 目标业务 id | 费用插到这一票下 |
| OrderFeeIds | `orderFeeIds` | Guid[] | 是 | 来源费用 id | 取第 10 节 `orderFees[].id` |
| ChangeOrderId | `changeOrderId` | Guid? | 否 | 更改单 id | 有值时新费用归属该更改单，并按该更改单判费用锁定、取会计期间 |
| ImportOriginalSettlement | `importOriginalSettlement` | bool | 否 | 是否引入原结算对象 | 不传按 `false`。`true`：保留来源费用的结算对象类别与结算对象。`false`：按来源费用的结算对象类别，从**目标业务**上重新取往来单位，映射见 11.2 |

## 11.2 `importOriginalSettlement=false` 时结算对象怎么取

按来源费用的结算对象类别（`industryCategory`）去目标业务上取：

| 类别 | 取目标业务上的 |
| :-- | :-- |
| 发货人 / 收货人 / 通知人 / 报关行 / 车队 / 委托单位 / 仓库 / 保险公司 | 业务表上对应的往来单位 |
| 场站 | 海运出口的场站；其它业务取不到 |
| 订舱代理 | 海运出口的订舱代理；**件杂货取件杂货的订舱代理**；海运进口、空运出口取不到 |
| 目的港代理 | 海运出口的目的港代理；**件杂货取件杂货的目的港代理**；海运进口、空运出口取不到 |
| **地面代理** | **2026-09-27 新增**。件杂货的地面代理；其它业务取不到 |
| 其余类别 | 不支持 |

取不到（类别支持但目标业务上没有这个往来单位）时**保留类别、结算对象为空**；类别为空或不支持时**类别和结算对象都为空**。都不报错，由用户补齐后再提交。 **2026-09-27 起「地面代理」是支持的类别**：目标业务不是件杂货时，类别会保留为地面代理、结算对象为空（此前类别也会被清空）。

## 11.3 出参

`Guid[]`：新生成的费用 id。没有嵌套对象。

## 11.4 报错

| 报错文案 | 触发条件 |
| :-- | :-- |
| `引入的费用id列表不能为空` | `orderFeeIds` 为空 |
| `业务不存在` | 目标业务不存在 |
| `更改单不存在` / `更改单不属于该业务` | 传了 `changeOrderId` 但对不上 |
| `业务已费用锁定不可操作` / `更改单已费用锁定不可操作` | 目标主单或更改单已费用锁定 |
| `已提交销售提成不可操作费用` | 目标主单或更改单已提交销售提成 |
| `引入的费用不存在` | 来源费用一条都找不到 |

# 12. 收付互生费用（收转付 / 付转收）

| 项 | 值 |
| :-- | :-- |
| 接口地址 | `POST /api/services/app/OrderFeeAdmin/GenerateOppositeOrderFeesAsync` |
| 方法名 | `GenerateOppositeOrderFeesAsync` |
| 入参 | `GenerateOppositeOrderFeesInputDto`（`[FromBody]`） |
| 出参 | `Guid[]`（新生成的费用 id） |
| 权限 | `Admin.OrderFee.Add` |

传一批同一业务、同一收付类型、同一更改单的费用，生成对面收付类型的费用：收 → 生成应付（收转付），付 → 生成应收（付转收）。新费用是录入状态，币别、汇率、单价、金额、数量、单位、税率、禁开、机密、排序号、备注都照抄来源费用。**结算对象**按费用代码上配置的默认客户类型字母取：生成应收取 `DefaultDebitName`，生成应付取 `DefaultCreditName`；字母换成结算对象类别后，去本业务上取往来单位，映射与 11.2 相同（件杂货的订舱代理、目的港代理、地面代理都从件杂货上取）。字母为空、不合法或类别不支持时，类别和结算对象都为空，不报错。

## 12.1 入参 `GenerateOppositeOrderFeesInputDto`

| 字段名 | JSON Key | 类型 | 必填 | 含义 | 说明 |
| :-- | :-- | :-- | :-: | :-- | :-- |
| TransportOrderId | `transportOrderId` | Guid | 是 | 业务 id | 来源费用都必须属于这一票 |
| PaySide | `paySide` | int | 是 | 来源费用的收付类型 | `0` 收（生成应付）、`1` 付（生成应收）；来源费用的收付类型必须都等于它。非空枚举，不传会按 `0` 处理 |
| OrderFeeIds | `orderFeeIds` | Guid[] | 是 | 来源费用 id | 不能为空 |
| ChangeOrderId | `changeOrderId` | Guid? | 否 | 更改单 id | 为空代表主单费用；来源费用必须都属于它，新费用也归属它，并按它判费用锁定 |

## 12.2 出参

`Guid[]`：新生成的费用 id。没有嵌套对象。

## 12.3 报错

| 报错文案 | 触发条件 |
| :-- | :-- |
| `费用id列表不能为空` | `orderFeeIds` 为空 |
| `业务不存在` | 业务不存在 |
| `更改单不存在` / `更改单不属于该业务` | 传了 `changeOrderId` 但对不上 |
| `业务已费用锁定不可操作` / `更改单已费用锁定不可操作` | 主单或更改单已费用锁定 |
| `已提交销售提成不可操作费用` | 主单或更改单已提交销售提成 |
| `费用不存在:{id,...}` | 有来源费用 id 查不到 |
| `费用(id=…)不属于该业务` / `费用(id=…)的收付类型与输入不一致` / `费用(id=…)不属于指定的更改单` | 来源费用与入参对不上 |
| `费用代码不存在(id=…)` | 来源费用的费用代码已不存在 |
