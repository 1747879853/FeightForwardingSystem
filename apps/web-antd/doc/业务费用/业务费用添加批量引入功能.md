# 1. 业务背景说明 (Background)

**白话解释：** 录费用时经常要从一票已有费用的海运出口里，把同样的一组费用“抄”到另一票业务上，重复手工录入效率低。本次在 `OrderFeeAdmin` 控制器新增两个接口，组成“费用批量引入”能力：

1. **查询海运出口费用** —— 提供按委托单位/船公司/起运港/目的港/编号/收付类型的筛选，列出海运出口及其名下费用，供前端勾选要引入哪些费用。
2. **为某条业务批量引入费用** —— 把勾选的费用复制插入到目标业务（可指定更改单）下，支持选择是否沿用原结算对象。

> 输入与返回均为本次新建的 DTO，未复用原有的 `OrderFeeDto` / `OrderFeeAddDto` 等。

---

# 2. 功能与操作说明 (Features & Operations)

- **查询海运出口费用（GetSeaExportFeesAsync）：** 按条件检索海运出口，返回带费用列表的海运出口集合，仅返回“存在符合条件费用”的海运出口；不含更改单费用。
- **批量引入费用（ImportOrderFeesToTransportOrderAsync）：** 校验目标业务/更改单费用锁定后，将源费用复制插入目标业务，返回新生成的费用 id 列表。

# 3. 接口一：查询海运出口费用

| 项       | 内容                        |
| :------- | :-------------------------- |
| 控制器   | `OrderFeeAdmin`             |
| 接口     | `GetSeaExportFeesAsync`     |
| 方法     | `GET`                       |
| 权限     | `Admin.OrderFee.Get`        |
| 入参 DTO | `SeaExportFeeQueryInputDto` |
| 出参     | `List<SeaExportFeeListDto>` |

## 3.3 查询逻辑说明

1. 海运出口列表按入参条件过滤，并经过数据权限（`DataPermissionFilterAsync`）与表权限（`TablePermissionsAsync(FrightModule.SeaExport)`）过滤。
2. 费用范围：仅取主单费用（`ChangeOrderId` 为空，不含更改单费用），并按 `PaySide` 过滤。
3. 机密费用：当前用户无 `Admin.OrderFee.Confidential.Get` 权限时，机密费用（`IsConfidential=true`）不返回。
4. 仅返回名下存在符合条件费用的海运出口（无费用的海运出口会被过滤掉）。

# 4. 接口二：为某条业务批量引入费用

| 项       | 内容                                      |
| :------- | :---------------------------------------- |
| 控制器   | `OrderFeeAdmin`                           |
| 接口     | `ImportOrderFeesToTransportOrderAsync`    |
| 方法     | `POST`                                    |
| 权限     | `Admin.OrderFee.Add`                      |
| 入参 DTO | `ImportOrderFeesToTransportOrderInputDto` |
| 出参     | `List<Guid>`（新生成的费用id列表）        |

## 4.1 入参 `ImportOrderFeesToTransportOrderInputDto`

| 字段名 | JSON Key | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| TransportOrderId | `transportOrderId` | `Guid` | 目标业务id，费用将插入到该业务下 |
| OrderFeeIds | `orderFeeIds` | `Guid[]` | 要引入的来源费用id列表 |
| ChangeOrderId | `changeOrderId` | `Guid?` | 更改单id，可空。不为空时新费用归属该更改单，并改判更改单费用锁定 |
| ImportOriginalSettlement | `importOriginalSettlement` | `bool` | 是否引入原费用结算对象。`true`：保留源费用 `SettlementId`；`false`：将 `SettlementId` 改为目标业务的委托单位 `ClientId` |

## 4.2 处理逻辑

1. 校验 `OrderFeeIds` 非空，按 `TransportOrderId` 找到目标业务，不存在则报“业务不存在”。
2. **费用锁定校验**（复用 `FeeLockedCheckAsync`）：
   - 传入 `ChangeOrderId` 时，校验该更改单是否费用锁定（锁定报“更改单已费用锁定不可操作”）；
   - 未传 `ChangeOrderId` 时，校验业务是否费用锁定（锁定报“业务已费用锁定不可操作”）。
   - 另校验更改单存在且归属于该业务。
3. 按 `OrderFeeIds` 查出源费用，复制为新 `OrderFee` 批量插入目标业务：
   - `TransportOrderId` = 输入的 `TransportOrderId`；`ChangeOrderId` = 输入的 `ChangeOrderId`；
   - `SettlementId`：`ImportOriginalSettlement=true` 保留源费用结算对象，否则改为目标业务 `ClientId`；
   - `AccountDate`：传更改单时取更改单会计期间，否则取业务会计期间；`UserId` 取业务 `UserId`；
   - 状态初始化：`FeeStatus=Entering`、`SettlementStatus=UnSettled`、`InvoiceStatus=NotIssued`、`DataEntryMethod=Manual`、`SettledAmount=0`；
   - 其余金额/单价/数量/税率/币别/费用代码/单位/备注/是否开票等沿用源费用；
   - 机密：无 `Admin.OrderFee.Confidential.Edit` 权限时强制 `IsConfidential=false`。
4. 返回新生成的费用 id 列表。

# 5. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **[卡点 1：费用锁定]** 目标业务（或指定更改单）已费用锁定时，禁止引入费用，直接报错。

> [!IMPORTANT] **[卡点 2：结算对象引入开关]** `ImportOriginalSettlement=false` 时，所有引入费用的结算对象会被统一改写为目标业务的委托单位（`ClientId`），请前端在交互上明确提示。

> [!IMPORTANT] **[卡点 3：机密费用]** 查询接口对无机密查看权限者隐藏机密费用；引入接口对无机密编辑权限者强制将新费用置为非机密。
