# 业务费用「是否允许开票」→「是否禁开发票」字段变更 — 前端对接文档

**变更日期**：2026-07-17

**变更类型**：⚠️ **破坏性变更（字段改名 + 语义反转）**

---

## 一、变更概述

原「是否允许开票」字段被替换为「是否禁开发票」，**字段名和布尔语义同时发生变化**，前端必须同步调整取值与传值逻辑，不能只改字段名。

| 项目     | 变更前            | 变更后                    |
| -------- | ----------------- | ------------------------- |
| JSON Key | `canInvoice`      | `invoiceBlocked`          |
| C# 字段  | `CanInvoice`      | `InvoiceBlocked`          |
| 中文含义 | 是否允许开票      | 是否禁开发票              |
| 布尔语义 | `true` = 允许开票 | `true` = 禁止开票         |
| 默认值   | `true`（允许）    | `false`（不禁止，即允许） |

> **语义完全相反**：`canInvoice: true` 等价于 `invoiceBlocked: false`。
>
> **换算公式**：`invoiceBlocked = !canInvoice`

---

## 二、前端迁移要点（重要）

1. **字段改名**：所有请求体、响应解析中的 `canInvoice` 全部改为 `invoiceBlocked`。
2. **取值反转**：原来判断"能否开票"用 `canInvoice`，现在要用 `!invoiceBlocked`。
3. **开关控件**：如果界面上是「允许开票」开关，需改成「禁开发票」开关，并把绑定值取反（开关打开 = `invoiceBlocked: true` = 禁止开票）。
4. **默认值**：不传该字段时后端默认为 `false`（即允许开票），与旧版默认「允许」行为一致，新增费用无需特意传值即可保持可开票。
5. **已删除 `canInvoice`**：后端不再接收也不再返回 `canInvoice`，请彻底移除。

## 七、前端改动清单

### 7.1 费用表单（新增/编辑/提交/更改单/预录单）

- 把「允许开票」控件改为「禁开发票」控件；
- 绑定值取反：控件表示「禁开发票」，勾选 = `invoiceBlocked: true`；
- 提交字段名由 `canInvoice` 改为 `invoiceBlocked`；
- 不勾选时默认 `false`（允许开票）。

### 7.2 费用列表 / 详情展示

- 读取字段由 `canInvoice` 改为 `invoiceBlocked`；
- 展示"是否允许开票"时用 `!invoiceBlocked`。

### 7.3 注意事项

- 后端已彻底移除 `canInvoice`，即使继续传该字段也会被忽略（ABP 忽略多余字段），但请务必清理，避免误以为生效；
- 该字段为全量更新，传入什么值即更新为什么值；
- 校验规则：开票申请时若某费用 `invoiceBlocked === true`，后端会拒绝并返回「费用不允许开票」。
