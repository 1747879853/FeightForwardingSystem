# 业务费用组合费用状态 — 前端对接文档

**变更日期**：2026-07-12

**变更概述**：`OrderFeeDto` 新增计算字段 `combinedFeeStatus`（组合费用状态），与海运出口列表 `receiveFeeStatus` / `payFeeStatus` 使用同一枚举 `SeaExportFeeStatus`，便于前端统一展示费用进度。

> [!NOTE] 该枚举已于 2026-08-20 更名为 `CombinedFeeStatus`（下文出现的 `SeaExportFeeStatus` 均指它）。**只是后端 C# 类型名变了，JSON 仍是 int，取值 0~7 与含义完全不变**，前端无需改动。详见《客户对账/客户对账-整票结算状态与组合费用状态-2026-08-20.md》。

---

## 一、新增字段

| 字段名 | JSON Key | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| CombinedFeeStatus | `combinedFeeStatus` | int | 组合费用状态（计算字段，非数据库列） |

### 1.1 枚举值（SeaExportFeeStatus）

| 值  | 含义     | 展示优先级（数字越小越优先展示） |
| :-- | :------- | :------------------------------- |
| 0   | 录入状态 | 4                                |
| 1   | 提交审核 | 5                                |
| 2   | 审核通过 | 6                                |
| 3   | 部分结算 | 7                                |
| 4   | 结算完毕 | 8                                |
| 5   | 驳回     | 1                                |
| 6   | 申请修改 | 2                                |
| 7   | 申请删除 | 3                                |

**业务优先级（计算规则）：** 驳回 > 申请修改 > 申请删除 > 录入状态 > 提交审核 > 审核通过 > 部分结算 > 结算完毕

### 1.2 与原有字段的区别

| 字段 | JSON Key | 说明 |
| :-- | :-- | :-- |
| FeeStatus | `feeStatus` | 费用审核状态（录入/提交/通过/驳回） |
| SettlementStatus | `settlementStatus` | 结算状态（未结算/部分结算/已结算），接口内会重算 |
| CombinedFeeStatus | `combinedFeeStatus` | **综合上述状态 + 待审核修改/删除任务** 后的展示状态 |

---

## 二、受影响的接口

| # | 接口 | 方法 | 路径 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 1 | GetPagedListAsync | GET | `/api/services/app/OrderFeeAdmin/GetPagedListAsync` | 业务费用分页列表，每条 `OrderFeeDto` 返回 |
| 2 | OrderFeeTaskListAsync | GET | `/api/services/app/OrderFeeAdmin/OrderFeeTaskListAsync` | 费用任务列表，每条业务单的 `orderFeeTasks[]` 返回 |
| 3 | OrderFeeTaskDetailAsync | GET | `/api/services/app/OrderFeeAdmin/OrderFeeTaskDetailAsync` | 费用任务详情，`orderFeeTasks[]` 返回 |

> 本次**仅上述 3 个接口**返回 `combinedFeeStatus`；`DetailAsync`、各类审核详情等暂未同步。

## 三、接口 1 — GetPagedListAsync

**Summary：** 分页查询业务费用（不含更改单），每条费用返回组合费用状态。

**权限：** `Admin.OrderFee.Get`

### 3.1 请求参数（OrderFeeQueryDto）

继承 `PagingAndSorting`。

| 字段名           | JSON Key           | 类型   | 必填 | 说明                 |
| :--------------- | :----------------- | :----- | :--- | :------------------- |
| PageIndex        | `pageIndex`        | int    | 否   | 当前页码，默认 1     |
| PageSize         | `pageSize`         | int    | 否   | 每页条数，默认 10    |
| Sorting          | `sorting`          | string | 否   | 排序，默认 `Id DESC` |
| TransportOrderId | `transportOrderId` | Guid?  | 否   | 业务 id              |
| PaySide          | `paySide`          | int?   | 否   | 收付类型。0=收，1=付 |
| FeeStatus        | `feeStatus`        | int?   | 否   | 费用审核状态         |
| SettlementStatus | `settlementStatus` | int?   | 否   | 结算状态             |
| InvoiceStatus    | `invoiceStatus`    | int?   | 否   | 开票状态             |
| FeeCodeId        | `feeCodeId`        | long?  | 否   | 费用代码 id          |
| IndustryCategory | `industryCategory` | int?   | 否   | 行业类别             |
| SettlementId     | `settlementId`     | Guid?  | 否   | 结算对象 id          |
| CurrencyId       | `currencyId`       | long?  | 否   | 币别 id              |
| IsConfidential   | `isConfidential`   | bool?  | 否   | 是否机密             |
| Keyword          | `keyword`          | string | 否   | 备注模糊匹配         |

### 3.2 请求示例

```
GET /api/services/app/OrderFeeAdmin/GetPagedListAsync?transportOrderId=a1b2c3d4-e5f6-7890-abcd-ef1234567890&pageIndex=1&pageSize=20
```

## 四、接口 2 — OrderFeeTaskListAsync

**Summary：** 费用所有任务分页列表（按业务单汇总），每条业务单下返回该单全部费用及组合状态。

**权限：** `Admin.OrderFee.Audit`

### 4.1 请求参数

与 `OrderFeeTaskListInputDto` 一致（含分页、`processed`、业务筛选、空值筛选等），详见 [业务费用任务空值筛选-2026-07-07.md](./业务费用任务空值筛选-2026-07-07.md)。

| 字段名    | JSON Key    | 类型  | 必填 | 说明              |
| :-------- | :---------- | :---- | :--- | :---------------- |
| PageIndex | `pageIndex` | int   | 否   | 当前页码，默认 1  |
| PageSize  | `pageSize`  | int   | 否   | 每页条数，默认 10 |
| Processed | `processed` | bool? | 否   | 是否已处理完毕    |

### 4.2 请求示例

```
GET /api/services/app/OrderFeeAdmin/OrderFeeTaskListAsync?pageIndex=1&pageSize=20&processed=false
```

### 4.3 响应变更（节选）

```json
{
  "result": {
    "items": [
      {
        "entityId": "order-guid-001",
        "submitOrderFeeItemCount": 1,
        "modifyOrderFeeItemCount": 0,
        "deleteOrderFeeItemCount": 0,
        "orderFeeTasks": [
          {
            "id": "fee-guid-001",
            "paySide": 0,
            "feeStatus": 1,
            "settlementStatus": 0,
            "combinedFeeStatus": 1,
            "feeCodeName": "海运费",
            "amount": 1000.0
          }
        ],
        "transportOrder": {}
      }
    ],
    "totalCount": 1
  },
  "success": true
}
```

### 4.4 列表项外层汇总字段变更

| 字段名 | JSON Key | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| FeeStatusReceive | `feeStatusReceive` | int? | 应收组合费用状态，规则同海运出口 `receiveFeeStatus` |
| FeeStatusPay | `feeStatusPay` | int? | 应付组合费用状态，规则同海运出口 `payFeeStatus` |

枚举值与 `combinedFeeStatus` 相同（0~7），见 [业务费用-组合费用状态-前端对接文档-2026-07-12.md](./业务费用-组合费用状态-前端对接文档-2026-07-12.md)。

### 4.5 列表项字段变更（orderFeeTasks）

| 字段名 | JSON Key | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| OrderFeeTasks | `orderFeeTasks` | OrderFeeAndTaskDto[] | **2026-07-12 起列表也返回**；不含 `task` 字段（仅详情填充） |
| OrderFeeTasks[].CombinedFeeStatus | `orderFeeTasks[].combinedFeeStatus` | int | 该条费用的组合费用状态 |

## 五、接口 3 — OrderFeeTaskDetailAsync

**Summary：** 费用所有任务详情，返回指定业务单下全部费用（含已删除但有删除任务的费用）及每条费用的任务信息。

## 六、前端改动建议

1. **展示映射**：复用海运出口列表 `receiveFeeStatus` / `payFeeStatus` 的标签色与文案映射表，key 改为 `combinedFeeStatus`。
2. **列表页**：业务费用列表直接读 `item.combinedFeeStatus`；费用任务列表读 `item.orderFeeTasks[].combinedFeeStatus`。
3. **详情页**：费用任务详情读 `orderFeeTasks[].combinedFeeStatus`。
4. **不要与 `feeStatus` 混用**：`feeStatus=2`（审核通过）时，`combinedFeeStatus` 可能为 3（部分结算）或 6（申请修改）等。
