# 业务费用-批量引入支持全业务类型-前端对接文档-2026-08-14

> ⚠️ **破坏性变更**：接口改名 + 出参结构调整。原根级平铺的港口/船公司/订舱代理/船名/航次字段全部收进 `transportOrder` 下的业务类型对象里。**字段没有删除，只是位置变了。**

## 1. 接口改名

| 项 | 原 | 新 |
| :-- | :-- | :-- |
| 地址 | `GET /api/services/app/OrderFeeAdmin/GetSeaExportFeesAsync` | `GET /api/services/app/OrderFeeAdmin/GetTransportOrderFeesAsync` |
| 权限 | `Admin.OrderFee.Get` | 不变 |
| 用途 | 费用批量引入时挑选来源费用 | 不变，但**查询范围由「仅海运出口」扩展到三种业务类型** |

## 2. 入参 `TransportOrderFeeQueryInputDto`

| JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `bizType` | int | **是** | **新增且必填**。0=海运出口 / 1=海运进口 / 2=空运出口。一次只查一种业务类型 |
| `clientId` | Guid? | 否 | 委托单位id |
| `bookingAgentId` | Guid? | 否 | 订舱代理id。仅海运出口与空运出口有此字段，`bizType=1`（海运进口）时传了**不生效** |
| `carrierId` | long? | 否 | 船公司id。仅海运出口与海运进口有此字段，`bizType=2`（空运出口）时传了**不生效** |
| `polId` | long? | 否 | 起运港id。`bizType=0/1` 传海港id，`bizType=2` 传空港id |
| `podId` | long? | 否 | 目的港id。同上 |
| `keyword` | string | 否 | 模糊匹配 委托编号 + 主提单号 |
| `paySide` | int? | 否 | 费用收付类型，用于过滤费用 |

> ⚠️ **`bizType` 必须显式传。** 后端未做非空校验，字段是非空枚举，**不传会被模型绑定静默填成 `0`（海运出口）**，结果就是「明明想查空运出口，却返回了海运出口」。海港表（`App_PortCodes`）与空港表（`App_AirPorts`）的 id 各自编号会重号，`polId`/`podId` 必须依赖 `bizType` 才能定位到正确的港口表。

## 3. 出参 `List<TransportOrderFeeListDto>`

```
[
  {
    "id": "业务id",
    "transportOrder": {
      "id": "业务id",
      "bizType": 0,
      "commissionNum": "委托编号",
      "mblNum": "主提单号",
      "client": { ...ClientSimpleDto },
      "totalCtn": "20GP*2 40HQ*1",
      "seaExport": { ... },   // 仅 bizType=0，其余为 null
      "seaImport": null,      // 仅 bizType=1
      "airExport": null       // 仅 bizType=2
    },
    "orderFees": [ { ...费用明细，字段完全不变 } ]
  }
]
```

### 3.1 字段迁移对照（取数路径改这里）

| 原路径 | 新路径 |
| :-- | :-- |
| `id` | `id`（不变，另外 `transportOrder.id` 也有） |
| `pol` | `transportOrder.seaExport.pol` / `seaImport.pol` / `airExport.pol` |
| `pod` | `transportOrder.seaExport.pod` / `seaImport.pod` / `airExport.pod` |
| `carrier` | `transportOrder.seaExport.carrier` / `seaImport.carrier`（空运没有） |
| `bookingAgent` | `transportOrder.seaExport.bookingAgent` / `airExport.bookingAgent`（海进没有） |
| `vessel` | `transportOrder.seaExport.vessel` / `seaImport.vessel`（空运没有） |
| `innerVoyno` | `transportOrder.seaExport.innerVoyno` / `seaImport.innerVoyno`（空运没有） |
| `transportOrder.commissionNum` | 不变 |
| `transportOrder.mblNum` | 不变 |
| `transportOrder.client` | 不变 |
| `transportOrder.totalCtn` | 不变，但**原先恒为 null，现在才真正返回值** |
| `orderFees[].*` | 全部不变 |

### 3.2 `transportOrder` 新增字段

| JSON | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | Guid | 业务id |
| `bizType` | int | 0=海运出口 / 1=海运进口 / 2=空运出口。**用它决定读哪个业务类型对象** |

### 3.3 `seaExport`（仅 `bizType=0`）

| JSON           | 类型                | 说明           |
| :------------- | :------------------ | :------------- |
| `id`           | Guid                | 与业务id相同   |
| `vessel`       | string              | 船名           |
| `innerVoyno`   | string              | 航次           |
| `pol`          | `PortCodeSimpleDto` | 起运港（海港） |
| `pod`          | `PortCodeSimpleDto` | 目的港（海港） |
| `carrier`      | `CarrierSimpleDto`  | 船公司         |
| `bookingAgent` | `ClientSimpleDto`   | 订舱代理       |

### 3.4 `seaImport`（仅 `bizType=1`）

字段同 `seaExport`，但**没有 `bookingAgent`**（海运进口表无此字段）：`id` / `vessel` / `innerVoyno` / `pol` / `pod` / `carrier`。

### 3.5 `airExport`（仅 `bizType=2`）

| JSON | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | Guid | 与业务id相同 |
| `flightNo` | string | 航班。**与海运的航次语义无关，不要合并展示** |
| `pol` | `AirPortSimpleDto` | 起运地（空港） |
| `pot` | `AirPortSimpleDto` | 中转地（空港，单个） |
| `pod` | `AirPortSimpleDto` | 目的地（空港） |
| `bookingAgent` | `ClientSimpleDto` | 订舱代理 |

无 `carrier` / `vessel` / `innerVoyno`（空运出口表无这些字段）。

### 3.6 外键对象结构

| Dto | 字段 |
| :-- | :-- |
| `PortCodeSimpleDto` | `id` / `portName` / `cnName` / `ediCode` / `lane`（航线对象，可为 null） / `country`（国家对象，可为 null） |
| `AirPortSimpleDto` | `id` / `iataCode` / `enName` / `cnName` |
| `CarrierSimpleDto` | `id` / `code` / `cnName` / `cnShortName` / `enName` / `ediCode` |
| `ClientSimpleDto` | `id` / `name` / `code` / `fullName` / `enName` |

## 4. 前端适配清单

- [ ] 接口地址改为 `GetTransportOrderFeesAsync`
- [ ] **每次请求都要带 `bizType`**（页面上通常是个业务类型下拉/页签），漏传会静默按海运出口查
- [ ] 按 `transportOrder.bizType` 分支读取 `seaExport` / `seaImport` / `airExport`，不要再读根级 `pol` / `pod` / `carrier` / `bookingAgent` / `vessel` / `innerVoyno`
- [ ] 列表若要展示「船名/航次」列，空运出口行请改显示 `airExport.flightNo`（或留空），不要拼到航次列
- [ ] 港口筛选控件按 `bizType` 切换数据源：`bizType=0/1` 用海港选择器，`bizType=2` 用空港选择器；切换 `bizType` 时应清空已选港口
- [ ] `carrierId`（空运出口）与 `bookingAgentId`（海运进口）在对应业务类型下不生效，筛选面板建议按 `bizType` 隐藏这些控件
- [ ] `transportOrder.totalCtn` 现在会有值，若之前按「恒为空」做过兜底请复查

## 5. 兼容性说明

- 引入接口 `ImportOrderFeesToTransportOrderAsync` **未改动**，入参出参完全不变。
- `orderFees[]` 内所有费用字段完全不变。
- 原有字段没有任何删除，只是从根级移到了 `transportOrder` 下的业务类型对象里。
