# 业务费用（OrderFee）字段变更 — 前端对接文档

**变更日期**：2026-06-07

**变更概述**：本次对 `OrderFee`（业务费用）的 `UnitEmum` 字段进行重命名和类型变更：

| # | 变更类型 | 原字段 | 新字段 | 原JSON Key | 新JSON Key | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | **重命名+类型变更** | UnitEmum | Unit | `unitEmum` | `unit` | 字段名从 `unitEmum` 改为 `unit`，类型从枚举(int)改为字符串(string) |

---

## 一、字段变更详情

### 1.1 变更前

| 字段名 | JSON Key | 类型 | 取值 | 说明 |
| --- | --- | --- | --- | --- |
| UnitEmum | `unitEmum` | `int`（枚举） | 0=箱, 1=件, 2=台, 3=托盘, 4=集装箱, 5=吨, 6=立方米, 7=千克, 8=升, 9=捆, 10=袋, 11=卷, 12=套 | 通过枚举值传递单位 |

### 1.2 变更后

| 字段名 | JSON Key | 类型 | 最大长度 | 取值 | 说明 |
| --- | --- | --- | --- | --- | --- |
| Unit | `unit` | `string` | 16字符 | "箱", "件", "台", "托盘", "集装箱", "吨", "立方米", "千克", "升", "捆", "袋", "卷", "套" 等 | 直接传入中文单位字符串 |

## 六、前端需要做的改动

### 6.1 全局替换

在前端代码中全局搜索并替换：

| 搜索       | 替换为 | 说明                        |
| ---------- | ------ | --------------------------- |
| `unitEmum` | `unit` | JSON key 变更（入参和出参） |

### 6.2 类型处理变更

**变更前**：`unitEmum` 是一个枚举整数值，前端需要维护枚举映射表来显示中文：

```javascript
// 旧代码示例（需删除）
const unitMap = { 0: '箱', 1: '件', 2: '台', 3: '托盘', ... };
const displayText = unitMap[item.unitEmum];
```

**变更后**：`unit` 直接是中文字符串，可直接展示：

```javascript
// 新代码示例
const displayText = item.unit; // 直接使用，无需映射
```

### 6.3 表单输入变更

- **变更前**：下拉框选择枚举值（int），提交时传递数字
- **变更后**：下拉框/输入框选择或输入单位文本（string），提交时传递中文字符串（最大16字符）

### 6.4 涉及页面

- 业务费用新增（`AddAsync`）
- 业务费用编辑（`EditAsync`）
- 业务费用批量新增（`BatchAddAsync`）
- 业务费用批量编辑（`BatchEditAsync`）
- 费用提交审核（`SubmitOrderFeeAsync`）
- 更改单编辑（`ChangeOrderAdmin/EditAsync`）
- 费用列表/详情展示页面
- 各类审核详情页
- 海运出口详情
- 更改单详情
- 付费申请/付费结算/对账单

### 6.5 注意事项

- `unit` 字段如果不传，默认值为 `null`（空字符串）
- `unit` 最大长度为 **16字符**
- 后端传入已删除的 `unitEmum` 不会报错（ABP 框架忽略多余字段），但建议尽快清理
- 原有的枚举值映射表可以删除，不再需要前端维护单位枚举
