# 1. 业务背景说明 (Background)

> [!WARNING] **本文档描述的 `statementId` / `statement` 实现已于 2026-08-11 被取代。** 客户对账改为允许多次对账：新增子表 `App_StatementFees`，`OrderFee.StatementId` 字段已删除，`OrderFeeDto` 改为返回数组 `statements`。判断费用是否已对账改为查子表。最新口径见 [客户对账-多次对账StatementFee子表-2026-08-11.md](../客户对账/客户对账-多次对账StatementFee子表-2026-08-11.md)。下文保留仅作历史记录。

**白话解释：**

业务费用一旦参与「客户对账(Statement)」后，费用上会写入 `StatementId`。前端在业务费用列表、更改单详情中需要知道每条费用「是否已参与对账、属于哪张对账单」，用于展示对账单号以及禁止对已对账费用做编辑/删除等操作。本次在费用输出 `OrderFeeDto` 上新增 `statementId` 与 `statement`（对账单简要信息，仅含 id 与对账单号），并让 `OrderFeeAdmin/GetPagedListAsync`、`ChangeOrderAdmin/DetailAsync` 两个返回费用的接口同步填充。

同时更改单详情 `ChangeOrderAdmin/DetailAsync` 支持按费用 id 列表 `ids` 过滤返回的费用（与业务费用列表 `GetPagedListAsync` 的 `ids` 口径一致）。

另：**费用实体不再参与数据权限**（改为 `FullAuditedEntity`），列表/详情仍返回展示用 `orgId`/`orgs`，统一取主单 `TransportOrder` 的组织并批量填充。

# 2. 功能与操作说明 (Features & Operations)

- **业务费用列表：** 调用 `GetPagedListAsync`，每条费用返回 `statementId` 与 `statement`（对账单简要信息）。
- **更改单详情：** 调用 `DetailAsync`，`orderFees[]` 每条费用返回 `statementId` 与 `statement`；并可用 `ids` 过滤只返回指定费用。

# 5. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **[卡点 1：statement 仅两列]** `statement` 使用 `ProjectTo<StatementSimpleDto>` 在数据库层只查 `Id`、`StatementNum` 两列，不含客户、时间等信息，避免全表映射，前端不要依赖其它字段。

> [!IMPORTANT] **[卡点 2：statementId 决定可否编辑/删除]** 已参与对账（`statementId` 有值）的费用不可编辑、删除、申请修改/删除，服务端会抛「已参与对账的费用不可…」。前端可据 `statementId` 预先禁用操作。

> [!IMPORTANT] **[卡点 3：费用组织取主单]** 费用实体无自身 `UserId`/`OrgId`；DTO 上的 `orgId`/`orgs` 一律来自主单，费用可见性也跟随主单数据权限。

## 7.2 填充方式（性能）

两个接口均按费用的 `StatementId` 去重后，用 `ProjectTo<StatementSimpleDto>(_mapperConfiguration)` 只查 `Id`、`StatementNum` 两列，再按 `StatementId` 回填到每条费用，避免拉整表实体。
