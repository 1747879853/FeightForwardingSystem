# 业务费用（OrderFee）结算对象可空 — 前端对接文档

**变更日期**：2026-07-02

**变更概述**：业务费用的**结算对象 `settlementId`** 由「必填」改为「**录入可空、提交必填**」。即：费用在**录入 / 编辑**阶段允许不选结算对象；但在**提交审核 / 申请修改**时后端会强制校验，未选择会报错。字段类型由 `Guid` 变为 `Guid?`（可空）。

| # | 字段 | JSON Key | 原类型 | 新类型 | 变更 |
| --- | --- | --- | --- | --- | --- |
| 1 | SettlementId | `settlementId` | `Guid`（必填） | `Guid?`（可空） | 入参可不传/传 null；出参可能为 null |

---

## 一、前端必须注意的核心点

### 1.1 入参：录入可不传，提交必须传

| 场景 | 接口 | `settlementId` 要求 |
| --- | --- | --- |
| 新增 / 编辑（录入草稿） | `Add` / `BatchAdd` / `Edit` / `BatchEdit` | **可空**：可不选、传 `null` 或不传 |
| 更改单费用保存 | `ChangeOrderAdmin/Edit` | **可空** |
| **提交审核** | `SubmitOrderFee` | **必填**：为空后端报错「提交时结算对象不能为空」 |
| **申请修改** | `ModifyOrderFee` | **必填**：为空后端报错「结算对象不能为空」 |

> 建议前端在「保存/暂存」时不强制校验结算对象；在「提交/申请修改」按钮点击时做前端必填校验，提前拦截，避免依赖后端报错。

### 1.2 出参：`settlementId` / `settlementName` 可能为 null

- 录入状态的费用，返回的 `settlementId` 可能是 `null`，`settlementName` 也可能是 `null`/空。
- 列表、详情、各类费用嵌套展示处均需**做空值容错**，不要直接 `.settlementName.xxx` 或假设一定有值。

```javascript
// 展示时容错
const display = fee.settlementName || '—'; // 未设置结算对象时显示占位符
```

```json

  "paySide": 0,
  "feeCodeId": 1,
  "industryCategory": 0,
  "settlementId": null,
```

## 五、后端报错话术（前端可捕获提示）

| 触发接口 | 触发条件 | 报错信息 |
| --- | --- | --- |
| `SubmitOrderFee` | 提交时某条费用未选结算对象 | `提交时结算对象不能为空` |
| `ModifyOrderFee` | 申请修改时未选结算对象 | `结算对象不能为空` |
| 生成对生费用 `GenerateOppositeOrderFees` | 业务未设置对应往来单位 | **不再报错**，生成的费用结算对象为空，由用户后续补充 |

---

## 六、前端需要做的改动清单

1. **表单校验**：结算对象在「保存/暂存」时不强制；在「提交」「申请修改」时前端做必填校验。
2. **展示容错**：所有展示 `settlementName` / `settlementId` 的地方处理 `null`（列表、详情、各审核页、海运出口、付费申请、付费结算、对账、开票申请等）。
3. **提交前拦截**：提交/申请修改前遍历费用列表，若存在 `settlementId` 为空的费用，给出明确提示并高亮，避免依赖后端逐条报错。
4. **"生成对生费用"交互**：生成后可能出现结算对象为空的费用（此前会直接报错阻断），需在列表提示用户补全后再提交。
