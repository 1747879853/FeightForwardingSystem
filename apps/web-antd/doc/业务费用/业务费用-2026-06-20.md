# 1. 背景意图 (Background)

`/services/app/OrderFeeAdmin/OrderFeeTaskListAsync` 接口返回的 `TransportOrderSimpleDto` 此前仅包含起运港、目的港的中文名（`SeaExportPOLCnName`、`SeaExportPODCnName`）以及毛重 `GrossWeight`。

前端对接需要展示海运出口关联的**所有港口英文名**，以及独立的**毛重KGS**字段，因此在 `TransportOrderSimpleDto` 中补充对应字段。

# 2. 核心逻辑变更 (Core Logic)

涉及文件：`src/CsprojBuilder.Application/App/TransportOrder/Dto/TransportOrderDto.cs` 中的 `TransportOrderSimpleDto`。

接口本身（`OrderFeeAdminAppService.OrderFeeTaskListAsync`）使用 `ProjectTo<TransportOrderSimpleDto>` 进行投影，依赖 AutoMapper 的扁平化（Flattening）按命名自动映射，**无需逐个手动赋值**，只需新增字段命名与导航属性路径对应即可。

# 3. 避坑指南 (Pitfalls)

- **命名即映射**：`PortCode` 实体中“港口英文名称”属性名为 `PortName`（中文名为 `CnName`）。英文名字段必须命名为 `SeaExport{港口}PortName`（如 `SeaExportPOLPortName`），AutoMapper 才能扁平化匹配 `SeaExport.POL.PortName`，命名写错将静默返回 null。
- **毛重区分**：实体 `TransportOrder` 中 `GrossWeight` 是“毛重”，`Kgs` 才是“毛重KGS”，二者为不同字段，DTO 字段名须为 `Kgs`。
- **无需 Include**：`ProjectTo` 会根据投影自动生成 SQL Join，新增导航属性字段无需在查询中额外 `Include`。
