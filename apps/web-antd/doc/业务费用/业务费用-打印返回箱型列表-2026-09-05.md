# 背景意图

费用列表打印需要逐箱信息（箱号、封号、箱型对象等）。`TransportOrderSimpleDto` 原先只有箱型箱量合计字符串 `totalCtn`，打印模板拿不到箱子明细。本次把 `OrderCtns` 挂到简易业务 DTO 上，仅费用列表打印时填充。

# 核心逻辑变更

- `TransportOrderSimpleDto` 新增 `OrderCtns`（`List<OrderCtnDto>`）。`TransportOrderSimplePrintDto` 继承该字段。
- `OrderFeeAdmin/GetPagedListAsync`：`input.IsPrint == true` 且本页有费用时，给**首条**费用的 `transportOrder` 赋值箱型列表；箱型/包装/品名走基础资料缓存，口径与海运出口详情一致。`totalCtn` 改为由这批箱子汇总，不再单独只查 `CtnCodeId`。
- 映射仍只用 `TransportOrderSimpleDto` 类上的 `[AutoMapFrom]`，不另写 `CreateMap`。`OrderCtns` 由打印接口手动赋值。

# 避坑指南

- 普通列表不要传 `isPrint`。不传时 `transportOrder` 仍为 `null`，自然没有 `orderCtns`。
- 打印时只有**第一条**费用挂 `transportOrder`（含 `orderCtns`），其余条目仍为 `null`。
- 空运出口不用 `App_OrderCtns`，该票打印时 `orderCtns` 为 `[]`；货物明细不在这个字段里。
- 其它返回 `TransportOrderSimpleDto` 的接口本次不手动赋值；走 `ProjectTo` 的接口若带出 `orderCtns` 也不在本次处理范围。
