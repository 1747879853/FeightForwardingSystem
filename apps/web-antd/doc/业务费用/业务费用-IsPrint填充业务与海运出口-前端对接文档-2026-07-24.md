# 业务费用列表-IsPrint填充业务与海运出口-前端对接文档-2026-07-24

## 接口

`GET /api/services/app/OrderFeeAdmin/GetPagedListAsync`  
权限：`Admin.OrderFee.Get`

## 入参新增

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 是否打印 | `isPrint` | bool? | 否 | 为 `true` 时填充业务与海运出口；默认不传/false 行为与原来一致 |

## 出参变化（仅 `isPrint=true`）

首条 `OrderFeeDto` 额外填充（其余条目 `transportOrder` 为 null）：

| 字段 | 说明 |
| :-- | :-- |
| `transportOrder` | `TransportOrderSimplePrintDto` 业务简要（打印扩展） |
| `transportOrder.seaExport` | `SeaExportSimpleDto` 海运出口简要，仅 `bizType=0` 时有值 |
| `transportOrder.seaImport` | `SeaImportSimpleDto` 海运进口简要，仅 `bizType=1` 时有值 |
| `transportOrder.airExport` | `AirExportSimpleDto` 空运出口简要，仅 `bizType=2` 时有值 |
| `transportOrder.orderCtns` | `OrderCtnDto[]` 箱型列表；无箱子或空运出口为 `[]` |
| `transportOrder.totalCtn` | 由本票 `orderCtns` 按箱型名汇总，如 `20GP*2 40HQ*1` |

> 2026-08-14 起补齐 `seaImport` / `airExport`。此前只填 `seaExport`，海运进口与空运出口业务打印时船名／航次／港口／船公司／航班全部为空。三个字段恒互斥，请按 `transportOrder.bizType` 分支取值。
>
> 2026-09-05 起补齐 `orderCtns`。普通列表不传 `isPrint` 时整段 `transportOrder` 仍为 `null`，不要按其它接口去取这个字段。

### `transportOrder.orderCtns[]`（`OrderCtnDto`）

仅 `isPrint=true` 且本页有费用时，挂在**首条**费用的 `transportOrder` 上。结构与海运出口详情的 `transportOrder.orderCtns` 相同。

| JSON | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | long | 箱型行主键 |
| `transportOrderId` | Guid | 业务 id |
| `ctnCodeId` | long | 箱型资料 id |
| `ctnNo` | string | 箱号 |
| `sealNo` | string | 封号 |
| `pkgs` | int? | 件数 |
| `codePackageId` | long? | 包装 id |
| `grossWeight` | decimal? | 毛重 |
| `tareWeight` | decimal? | 皮重 |
| `overLength` | decimal? | 超长 |
| `overWidth` | decimal? | 超宽 |
| `overHeight` | decimal? | 超高 |
| `volume` | decimal? | 体积 |
| `codeGoodsId` | long? | 品名 id |
| `bookingNo` | string | 订舱号 |
| `remark` | string | 备注 |
| `ctnCode` | `CtnCodeSimpleDto` | 箱型对象，见下表；资料缺失时为 `null` |
| `codePackage` | `CodePackageSimpleDto` | 包装对象；未填包装时为 `null` |
| `codeGoods` | `CodeGoodsSimpleDto` | 品名对象；未填品名时为 `null` |

#### `ctnCode`（`CtnCodeSimpleDto`）

| JSON          | 类型   | 说明                  |
| :------------ | :----- | :-------------------- |
| `id`          | long   | 主键                  |
| `ctnName`     | string | 表现形式（如 `20GP`） |
| `cabinetType` | int    | 柜型 0普柜 1特种柜    |
| `ctnSize`     | string | 集装箱类型            |
| `ctnType`     | string | 集装箱尺寸            |
| `teu`         | int    | TEU                   |

#### `codePackage`（`CodePackageSimpleDto`）

| JSON      | 类型   | 说明     |
| :-------- | :----- | :------- |
| `id`      | long   | 主键     |
| `name`    | string | 包装名   |
| `ediCode` | string | EDI 代码 |

#### `codeGoods`（`CodeGoodsSimpleDto`）

| JSON     | 类型   | 说明     |
| :------- | :----- | :------- |
| `id`     | long   | 主键     |
| `code`   | string | 编码     |
| `name`   | string | 名称     |
| `enName` | string | 英文名称 |
| `hsCode` | string | 海关代码 |

`SeaExportSimpleDto` / `SeaImportSimpleDto` 字段一致：`id`、`vessel`、`innerVoyno`、`pol`（`PortCodeSimpleDto`）、`polRemark`、`pod`（`PortCodeSimpleDto`）、`podRemark`、`carrier`（`CarrierSimpleDto`）。

`AirExportSimpleDto` 含：`id`、`flightNo`、`pol`/`pot`/`pod`（均为 `AirPortSimpleDto`：`id`、`iataCode`、`enName`、`cnName`）及各自 `*Remark`。

`PortCodeSimpleDto` 含：`id`、`portName`、`cnName`、`ediCode`、`lane`（航线对象，可为 null）、`country`（国家对象，可为 null），完整结构见《港口模块总逻辑文档》4.1。

## 说明

- 普通列表勿传 `isPrint`，避免多余查询。
- 打印模板取数（`PrintFormatAdmin/GetPrintAsync` 应收/应付费用）已自动设 `isPrint=true`。
- 打印模板若写死了海运出口字段路径，需按 `bizType` 增加海运进口／空运出口分支，否则这两类业务打印仍为空。
- 打印模板需要逐箱信息时取首条费用的 `transportOrder.orderCtns`；空运出口该数组为 `[]`。
- 填充逻辑详见 [业务-三种业务类型简要统一填充-2026-08-14.md](../业务/业务-三种业务类型简要统一填充-2026-08-14.md)；本次箱型字段见 [业务费用-打印返回箱型列表-2026-09-05.md](./业务费用-打印返回箱型列表-2026-09-05.md)。
