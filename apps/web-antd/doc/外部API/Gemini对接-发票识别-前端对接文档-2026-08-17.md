# 1. 说明

`ExtractInvoiceAsync`：上传发票文件、或传已上传附件 Id，识别发票号码、开票日期、销售方抬头、销售方纳税人识别号、价税合计。

2026-09-06 起在原有发票号码、开票日期之外新增 `sellerTaxNo`、`totalAmount`。接口地址与入参不变。

# 2. 接口

| 项目 | 内容 |
| :-- | :-- |
| 方法 | `POST` |
| 地址 | `/api/services/app/GeminiAdmin/ExtractInvoiceAsync` |
| 请求体 | `multipart/form-data`，单个文件 **或** 字段 `attachmentId`（二选一） |
| 返回 | `GeminiInvoiceDto` |
| 超时 | 前端须设 **180 秒** loading，不要用默认 20 秒 |

付费申请走附件 Id：`formData.append('attachmentId', String(attachmentId))`。禁止 JSON 请求体。

# 3. 出参与付费申请回填

| 识别字段 | 类型 | 付费申请发票行 |
| :-- | :-- | :-- |
| `invoiceNo` | string / null | → `invoiceNo` |
| `invoiceDate` | datetime / null | → `invoiceDate`（YYYY-MM-DD） |
| `sellerHeader` | string / null | → `sellerHeader`（销售方抬头，开票方名称） |
| `sellerTaxNo` | string / null | 不写入抬头 |
| `totalAmount` | decimal / null | → `amount`（价税合计，允许用户再改） |

识别字段都可能为 `null`，只作预填，不自动保存。

# 4. 避坑

- 抬头回填用识别结果的 `sellerHeader`，不要把 `sellerTaxNo` 填进抬头。
- `totalAmount` 是含税合计，不要拿去和申请金额比对。
- 同一文件内容有识别缓存；2026-09-06 加字段后旧缓存失效，第一次会重新调 AI。
