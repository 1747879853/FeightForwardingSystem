### 1. 新增 API 文件

**文件**: `apps/web-antd/src/api/sea-export/gemini-admin.ts`

**包含的接口**:

#### 1.1 海运报价解析接口

- `extractSeFreiPriceByGemini(file: File)` - Gemini AI 识别运价
- `extractSeFreiPriceByQwen(file: File)` - 通义千问 AI 识别运价

**支持的文件类型**（已更新）:

- PDF (`.pdf`)
- 图片: PNG, JPG, JPEG, WebP, HEIC, HEIF, GIF, BMP
- 文本: TXT
- **Excel: XLSX, XLS** ✨ 新增（会在后端转为 HTML 表格保留合并单元格再识别）

**返回数据类型**:

```typescript
interface GeminiSeFreiPriceDto {
  podName: string; // 目的港名称（原始文本）
  podId: string | number; // 目的港ID（匹配不到为-1）
  isDirect?: boolean; // 是否直航
  pot1Name?: string; // 中转港1名称
  pot1Id?: string | number; // 中转港1ID
  pot2Name?: string; // 中转港2名称
  pot2Id?: string | number; // 中转港2ID
  currencyCode: string; // 币别代码
  currencyId: string | number; // 币别ID（匹配不到为-1）
  validTimeStart?: string; // 有效期开始（ISO 8601格式）
  validTimeEnd?: string; // 有效期结束（ISO 8601格式）
  remark?: string; // 备注
  seFreiPriceCtns: SeFreiPriceCtnDto[]; // 箱型价格明细列表
}
```

#### 1.2 提单数据提取接口

- `extractBillData(file: File)` - 提单数据提取（gemini-3.5-flash）
- `extractBillDataBy31FlashLite(file: File)` - 提单数据提取-轻量模型（gemini-3.1-flash-lite）

**支持的文件类型**: PDF

**返回数据类型**:

```typescript
type BillDataExtractionResult = Record<string, any>;
```

**可提取的字段**:

- BookingNo（订舱号）
- Vessel / 船名
- Voyage / 航次
- ContainerNo（集装箱号）
- Shipper / 发货人
- Consignee / 收货人
- Notify Party / 通知人
- B/L NO（提单号）
- Seal No（封条号）
- Number of containers or packages（集装箱或包裹数量）
- Kind of Packages（包装种类）
- Description of Goods（货物描述）
- Gross Weight（毛重）
- Measurement（体积）
- Port of Loading / 起运港
- Port of Discharge / 卸货港
- Place of Receipt / 收货地
- Place of Delivery / 交货地
- NO.of Packages（件数）
- Marks（唛头）
- 船期、船公司、箱型箱量、CNTRTOTAL

## 技术要点

### 1. 文件类型支持扩展

根据后端文档，Gemini 接口现在支持 Excel 文件（xlsx/xls），后端会自动将 Excel 转换为 HTML 表格（保留合并单元格）再进行识别。

### 2. 接口地址不变

虽然后端将访问 Gemini 的请求拆分到了独立的外网服务器（Freight.GlobalServer），但接口地址、入参、出参对前端完全没有变化，前端无需做任何改动。

### 3. 动态返回结构

提单数据提取接口返回的是动态 JSON 对象，字段不固定，根据模型提示词输出。值为 `null` 表示全文未出现该字段，模型不会编造数据。

### 4. ID 匹配规则

- 所有 `xxId` 为 `-1` 表示模型识别到了名称，但系统基础资料里没匹配上
- 名称为空时，对应的 ID 为 `null`
- 名称字段始终返回，便于人工核对

### 5. 超时设置

- 单证解析通常耗时 10~60 秒
- 后端超时设置为 180 秒
- 前端务必显示 loading 状态，不要设置过短的超时时间

## 注意事项

### TypeScript 类型安全

- `BillDataExtractionResult` 使用 `Record<string, any>` 类型，因为返回字段是动态的
- 访问字段时建议使用可选链操作符：`result?.Vessel` 或 `result['B/L NO']`

### 错误处理

- 所有接口在失败时统一抛出 `UserFriendlyException`
- 前端按常规错误提示展示即可
- 建议在 try-catch 中捕获异常并给用户友好提示

### 用户体验

- 识别过程需要较长时间（10-60秒），必须显示 loading 状态
- 提供清晰的提示信息，告知用户当前状态
- 识别完成后显示成功提示和识别到的字段数量
