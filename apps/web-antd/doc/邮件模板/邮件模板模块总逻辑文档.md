# 1. 业务背景说明 (Background)

**白话解释：** 操作每天要给客户、订舱代理发大量格式固定的邮件：订舱确认、开船通知、到港通知、发票寄送……内容大同小异，只是订舱号、船名、日期不一样。邮件模板就是把这类邮件做成模板：标题和正文里用占位符代替会变化的业务字段，收件人可以直接写邮箱，也可以选「委托单位联系人」「业务关联销售」这类来源。

用的时候在业务页面（海运出口、海运进口、空运出口、件杂货、发票开出）里点一下：

1. 后端按这票业务列出能用的模板；
2. 选一个模板，后端把占位符换成这票业务的数据、把收件人来源算成实际邮箱，生成一封邮件（系统不保存）；
3. 用户在页面上微调，带上附件（系统里这票业务的附件、打印出来的文件、自己上传的文件），然后：
   - **发送**：用当前登录人的**个人邮箱**发出，系统记一条发送记录；
   - **存草稿**：存进当前登录人个人邮箱的草稿箱，之后用户去自己的邮箱里处理，系统不记录。

三条硬要求：

- **不越权**：生成、存草稿、发送前都要校验这票业务的查看权限、数据权限、表级权限；拼文本用到的每个字段都过字段级屏蔽，被屏蔽的字段当取不到。
- **不存邮件原文**：生成的邮件不保存；正文和附件都不落库；发送记录只记发件人、发件箱、收件人、抄送人、标题、邮件唯一标识（这几项是需求方明确要求记录的）。
- **模板全公司共用**：模板不走数据权限，所有人都能看。

## 2.3 哪些模板可用

同时满足：

1. 适用模块就是这票业务的模块；
2. 已启用；
3. 服务项为空（通用模板），**或者**服务项是这票业务**正在进行**的服务项。

「正在进行」= 这票业务的服务项任务里状态为「待处理」（`ServiceTaskStatus.Pending`）的那些任务，取任务对应的服务项配置明细的 `ServiceType`。目前只有海运出口（`SeServiceTask`）和海运进口（`SiServiceTask`）有服务项任务。空运出口、件杂货、发票开出模板**可以配服务项**（给以后接入留口子），但配了服务项的模板现在不会出现在可用列表里。

排序：排序id降序、创建时间降序。生成邮件时会再校验一遍这三条，过期的选择（比如模板刚被停用、服务项刚完成）会报错。

## 2.4 生成邮件

- **标题**：占位符替换后是单行纯文本，替换进来的值里的换行、连续空白都压成一个空格。
- **正文**：HTML，替换进来的值先做 HTML 转义，再把换行变成 `<br>`；模板里原有的 HTML 不动。
- **取不到的占位符**替换成空：业务上没填、或者这个字段对当前用户被屏蔽。模板保存后占位符清单又改过、本模块已不认识的占位符**原样保留**。
- **收件人**：按模板里收件人的顺序，直接填的邮箱原样放进去，来源算出实际邮箱（见 4.4）；业务上没选的（比如没选订舱代理）就是空，不报错，用户发送前可以自己补。 **发票开出例外**：发票开出自己有收件人或抄送人（`App_InvoiceIssueMailRecipients`，新建时前端从开票申请带过来、用户可再改）时，收件人和抄送人**整份用发票开出的**，模板配置的收件人、抄送人都不用（哪怕发票开出只有收件人没有抄送人，抄送人也是空）；发票开出一个都没有，或这个字段对当前用户被字段屏蔽时，才按模板算。名字不进邮件，只取邮箱。联系人邮箱一格里用分号、逗号、空白隔开写了多个的会拆开；收件人、抄送人各自去重（不区分大小写），已在收件人里的不再出现在抄送人里；格式不正确的邮箱丢掉，放进 `invalidAddresses` 给前端提示。
- **系统附件**：一并返回这票业务**自己**的附件（附件模块 + 业务id，见 4.5）供用户勾选；附件在详情里被字段屏蔽时返回空数组。

## 2.5 存草稿 / 发送

两个接口入参相同（发送多一个模板id）。共同校验：

- 标题必填、最长 1024；收件人、抄送人逐个校验纯邮箱格式，有不对的直接报「邮箱【x】格式不正确」；发送时至少要有一个收件人，存草稿不要求。
- 业务查看权限（2.2）。
- 当前登录人要配过个人邮箱，否则报「还没有配置个人邮箱，请先在个人设置里配置」（在读附件之前就报）。
- 三类附件：
  - **系统附件**：传附件id，必须是这票业务自己的附件且没被字段屏蔽，否则报「所选系统附件不属于这票业务或已被删除」。后端从服务器磁盘读文件，附件名用上传时的文件名。
  - **打印文件**：传打印接口返回的文件名（也接受 `PrintTempFile/xxx`、`/PrintTempFile/xxx`）。只认打印临时目录 `wwwroot/PrintTempFile` 里的文件，去掉前缀后必须是单纯的文件名，否则报「打印文件【x】不正确」；文件不在了报「请重新打印」。附件名去掉打印时加的「-时间戳」。
  - **上传附件**：文件名 + base64 内容，只在内存里用一次，不走系统附件上传。
  - 三类合计不能超过 50MB。上传附件还受 Web 服务器请求体上限（约 30MB，折合附件约 20MB）约束。

**发送**还要校验模板存在、适用模块一致（模板停用了照样能发，生成那一步已经校验过）。用 `IMailboxService.SendAsync` 发出并存一份到「已发送」，**发出后**才写发送记录，收件人、标题以邮件服务实际发出的为准。

**存草稿**调 `IMailboxService.SaveDraftAsync`，系统不记录，也不把草稿序号返回给前端：用户之后在自己的邮箱里处理这封草稿，和系统再无交互。

# 3. 状态流转说明 (Status Transitions)

模板只有「启用 / 未启用」两种状态，编辑时直接改，没有流转限制。未启用的模板不出现在可用列表里，也不能生成邮件。

- 联系人邮箱取 `ClientContact.Email`，不取往来单位主表的邮箱，也不取海运出口单子上的场站邮箱；**客户联系人的数据权限（对接人）不参与**。

- 以上来源只在单据自己没定收件人时用。目前只有发票开出能自己定（见 2.4），判断字段屏蔽用 InvoiceIssue 模块的 `InvoiceIssueMailRecipients`。

| **CreatorUserId / CreationTime** | 发送人 / 发送时间 |
| **FrightModule / EntityId** | 哪票业务：业务模块是业务表id，发票开出是发票开出id |
| **MailTemplateId / MailTemplateName** | 哪个模板；模板名是发送时的快照，模板删了记录照样能看 |
| **FromAddress** | 发件箱（所用个人邮箱的地址） |
| **ToAddresses / CcAddresses** | 实际发出的收件人 / 抄送人，英文分号分隔 |
| **Subject** | 实际发出的标题，最长 1024 |
| **MessageId** | 邮件唯一标识（Message-Id 邮件头），拿不到或超过 512 不记 |

不存正文、不存附件。只在发送成功后写，存草稿不写。

# 5. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **[卡点 1：模块数字是 FrightModule，不是 BizType]** 适用模块与业务所属模块都用 `FrightModule`：海运出口 0、海运进口 4、空运出口 5、件杂货 12、发票开出 15。快捷文本用的是 `BizType`（0/1/2/3），两套数字不一样，前端别混用。发票开出 15 是为本模块新加的，与 `DataPermissionModule.InvoiceIssue` 同值，同时给发票开出接上了字段级屏蔽。

> [!IMPORTANT] **[卡点 2：适用模块创建后不能改]** 占位符和收件人来源都是按模块校验的，换模块后原来的配置可能全部失效，所以编辑入参里没有适用模块。要换模块只能新建。

> [!IMPORTANT] **[卡点 3：被屏蔽的字段不会出现在生成的邮件里]** 字段级屏蔽只在序列化 DTO 时自动生效，邮件正文是后端拼出来的字符串，所以生成时逐个字段手动判断（拿数据库实体求值，判据取不到时按屏蔽处理）。屏蔽了的字段对应的占位符替换成空、收件人来源算不出邮箱、附件不返回。测试时要配了规则再看生成结果。

> [!IMPORTANT] **[卡点 4：系统附件和打印文件都防越权]** 系统附件只认这票业务自己的附件id，拿别的业务的附件id会报错；打印文件只认打印临时目录里的单纯文件名，带路径（`../xxx`、`C:\xxx`）一律报「不正确」。

> [!IMPORTANT] **[卡点 5：发送成功但记录可能没写进去]** 邮件发出后才写发送记录，写记录在同一个工作单元里随接口结束提交。极端情况下（邮件已发出、提交数据库时失败）邮件发出去了但没有记录，这种情况不重发。

> [!IMPORTANT] **[卡点 6：附件大小]** 三类附件合计超过 50MB 直接报错；上传附件随请求 base64 传，Web 服务器请求体上限约 30MB，超过会被服务器直接拒掉（不是业务报错）。
