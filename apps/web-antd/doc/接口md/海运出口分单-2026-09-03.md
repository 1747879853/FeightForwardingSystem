# 背景意图

分单主表原先没有备注，箱型子表才有。业务要在分单头上单独记一句话，并且能把已有分单复制成新单：收发通、货物信息、签单付费条款都带走，分提单号和箱型箱量不要带（一票多份分单时提单号不能撞，箱子要重新勾）。

# 核心逻辑变更

1. `App_SeaExportSeparates` 新增可空 `Remark`（`nvarchar(1024)`）。新增/编辑入参、列表/详情出参都带 `remark`。新增走 `ObjectMapper.Map` 自动映上；编辑在跟踪实体上赋 `separate.Remark = input.Remark`。超过 1024 报「备注长度不能超过1024个字符」。
2. 列表关键字 `keyword` 增加对 `Remark` 的模糊匹配（原先只搜分提单号、唛头、货物描述）。
3. 新增 `CopyAsync`：入参只要分单 `id`，返回新分单 Guid。主表业务字段原样复制（含备注、仍挂同一 `SeaExportId`），`BlNum` 置空，`SeaExportSeparateCtns` 不复制。权限与新增/编辑相同（`Admin.SeaExport.Edit`）。
4. 未生成 Migration。

删除接口不用改：删的是整行，子表清理逻辑不变。

# 避坑指南

- **主表备注和子表备注不是同一个字段。** 箱型行上本来就有 `SeaExportSeparateCtn.Remark`，这次加的是分单头的 `SeaExportSeparate.Remark`。列表/详情两层都会返回 `remark`，前端按嵌套取值，不要把子表备注填到主表上去。
- **复制不带子表。** 源分单有箱型，复制出来的新单 `seaExportSeparateCtns` 是空数组。这是需求，不是漏了。用户要自己再勾箱。
- **复制仍挂原海运出口。** 新分单的 `seaExportId` 与源单相同，不是新开一票业务。
- **分提单号一定是空。** 即使源单有 `blNum`，新单也是 `null`，避免两张分单共用一个提单号。
- **复制只认 `id`。** 入参复用 `GuidIdDto`，`ids` / `isPrint` 传了也没用。源单不存在报「分单记录不存在」。
