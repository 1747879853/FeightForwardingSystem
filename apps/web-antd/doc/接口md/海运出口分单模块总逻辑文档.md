# 1. 业务背景说明 (Background)

**白话解释：**

一票海运出口可能要出多份分提单（HBL）：不同收货人、不同货物描述、不同签单条款。分单挂在海运出口下面，不单独成票，也没有自己的委托编号和组织。箱型箱量是分单的子表，和业务主单的集装箱不是同一张表。

# 2. 功能与操作说明 (Features & Operations)

- **新增：** 在某票海运出口下新建分单，可同时写入箱型箱量。结算对象必填，应结日期按它的账期算、不接受录入。权限走海运出口编辑。
- **编辑：** 改主表字段；结算对象换了才按新账期重算应结日期。箱型子表按「有 id 改、无 id 增、没传来的删」。
- **列表：** 必须带 `seaExportId`，只返回这一票下的分单。关键字模糊匹配分提单号、唛头、货物描述、备注。
- **详情：** 按分单 id 取一条，结构与列表行相同。打印时 `isPrint=true` 会带上所属公司打印信息、分单自己的箱型箱量合计和件数大写，以及所属海运出口 `seaExport`。列表和普通详情里这些打印字段为 null。
- **删除：** 支持单条 `id` 或批量 `ids`。先批量删箱型子表，再软删分单主表。
- **复制：** 输入源分单 id，在同一票海运出口下再插一条。主表信息全带（含结算对象、备注），分提单号置空，箱型箱量不带，应结日期按当前账期重算。

# 3. 状态流转说明 (Status Transitions)

分单没有独立审批或业务状态机。生命周期就是新增 / 编辑 / 复制 / 删除。主表是软删除（`FullAuditedEntity`），箱型子表是硬删除。

| 当前状态 | 触发人/动作 | 目标状态 | 状态说明                         |
| :------- | :---------- | :------- | :------------------------------- |
| 不存在   | 新增或复制  | 有效分单 | 复制出的分单无分提单号、无箱型   |
| 有效分单 | 编辑        | 有效分单 | 局部改主表；子表按提交列表增删改 |
| 有效分单 | 删除        | 软删     | 子表先硬删干净，避免孤儿箱型     |

## 4.3 打印时附带的所属海运出口 `SeaExportSeparateSeaExportDto`

仅详情 `IsPrint=true` 时有值。列表、普通详情为 null。不是分单自己的字段，是所属那票海运出口的打印快照。

港口、船名、航次、船公司、提单份数、副本份数取海运出口扩展表。开船日期、主提单号、订舱编号在 `TransportOrder`。船名、船公司航次、码头航次、起运港、目的港、船公司与 `SeaExportSimpleDto` 一致，并补上付费地点、签单地点、两个中转港、收货地、交货地及各自备注。

# 5. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **[卡点 0：结算对象必填，应结日期只读]** 新增/编辑不传 `settlementId` 直接报「结算对象不能为空」。`settlementDate` 不要往入参里塞——后端按结算对象账期算。编辑时结算对象没变就不重算，避免每次保存刷日期。

> [!IMPORTANT] **[卡点 1：复制不带箱子、不带分提单号]** 点复制后新单 `blNum` 为空、`seaExportSeparateCtns` 为空。这是接口约定，前端不要用源单数据回填这两处。应结日期会按当前账期重算，不要拿源单那天的值去覆盖。

> [!IMPORTANT] **[卡点 2：复制仍属同一票海运出口]** 新分单 `seaExportId` 不变。不要当成「复制一票业务」。海运出口自己的 `CopyAsync` 明确不复制分单。

> [!IMPORTANT] **[卡点 3：主表备注 ≠ 箱型备注]** 两层都叫 `remark`。表单、列表、打印都要按嵌套取：分单头一份，每一行箱子一份。

> [!IMPORTANT] **[卡点 4：删除必须先清子表]** 主表是软删，EF 级联在本项目无效。删除接口已经先 `DeleteAsync` 箱型再删主表。不要只调主表删除。
