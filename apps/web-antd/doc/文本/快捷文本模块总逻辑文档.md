# 1. 业务背景说明 (Background)

**白话解释：**

货代日常操作中，操作员要在海运出口、海运进口、空运出口等模块里反复填写一些格式固定的长文本，比如订舱备注、发货通知、给客户的说明文案。这些文案的骨架每次都一样，只有委托编号、提单号、船名航次这类具体值不同。

「快捷文本」就是让每个操作员把自己常用的文案存成模板，模板里用**占位符**代表会变化的字段。用的时候在业务页面点一下，前端自动把占位符换成当前这票业务的真实数据，一次性填进输入框。

三个关键定位：

1. **完全私有**。每个人只能看到、只能操作自己创建的快捷文本，看不到同事的，管理员也看不到别人的。
2. **按模块隔离**。海运出口的模板不会出现在空运出口的面板里，因为两个模块的字段不同、可用占位符也不同。
3. **后端不碰文本**。后端只负责原样存、原样取，占位符的定义和替换全部由前端完成。后端不校验占位符写得对不对，用户写了一个不存在的占位符也照样能保存。

# 2. 名词与范围约定 (Glossary & Scope)

| 名词 | 含义 |
| :-- | :-- |
| **快捷文本** | 一条用户自定义的文本模板，正文里可以带占位符 |
| **占位符** | 文本中代表业务字段的标记，由**前端自行定义和维护**，后端完全不参与 |
| **业务类型 (BizType)** | 标识这条快捷文本属于哪个业务模块，决定它在哪个模块的面板里出现 |
| **默认项 (Default)** | 同一用户在同一业务类型下的置顶项，列表里排在最前面 |
| **管理页** | 独立的「我的快捷文本」页面，是唯一的增删改入口 |
| **业务面板** | 业务模块输入框旁边弹出的快捷文本选择列表，**只读**，不能在这里增删改 |

**适用业务类型范围（本期）：**

| 枚举值 | 名称     | 说明 |
| :----- | :------- | :--- |
| 0      | 海运出口 | 支持 |
| 1      | 海运进口 | 支持 |
| 2      | 空运出口 | 支持 |

> 本期沿用系统现有的 `BizType` 枚举，该枚举目前**只有以上三项，不含空运进口**。空运进口如需支持，属于后续需求，需要先扩展枚举。

# 3. 完整表结构 (Table Schema)

## 3.1 表基本信息

| 项目 | 值 |
| :-- | :-- |
| 表名 | `App_QuickTexts` |
| 实体类 | `CsprojBuilder.Entites.QuickText` |
| 实体基类 | `AuditedEntity<Guid>` + `IMustHaveTenant` |
| 主键 | `Guid`，**非自增**，由后端 `Guid.NewGuid()` 生成 |
| 是否分租户 | **是**，`TenantId` 非空 |
| 是否软删除 | **否**，删除即物理删除，表中无 `IsDeleted` 字段 |
| 是否走数据权限 | **否**，不参与 `UserDataPermission` 体系，仅按 `UserId` 硬过滤 |
| 物理外键 | **无**。本表不建任何数据库外键约束 |

## 3.2 字段明细

| 字段名 | 类型 | 长度 | 库可空 | 业务含义 | 生成逻辑 / 数据来源 | 校验规则 | 外键关联 |
| :-- | :-- | :-- | :-- | :-- | :-- | :-- | :-- |
| **Id** | `Guid` | — | 否 | 主键 | 新增时由**后端**生成 `Guid.NewGuid()`。前端新增时不传；编辑、删除时必传 | 编辑/删除时必填，且必须是当前用户自己的数据 | 无 |
| **TenantId** | `int` | — | 否 | 所属租户 | 新增时由**后端**从当前登录会话取 `AbpSession.TenantId`。前端不传 | 宿主(host)用户没有租户，无法使用本功能 | 逻辑关联 `Sys_Tenants.Id`，**不建物理外键** |
| **UserId** | `long` | — | 否 | 所属人 | 新增时由**后端**从当前登录会话取 `AbpSession.GetUserId()`。**前端即使传了也会被忽略** | 所有查询、编辑、删除都强制按此字段过滤 | 逻辑关联 `Sys_Users.Id`，**不建物理外键** |
| **BizType** | `int`（枚举 `BizType`） | — | 否 | 业务类型，决定这条快捷文本用于哪个模块 | 新增时由**前端**传入。**编辑时不允许修改** | 必填，取值只能是 0 / 1 / 2 | 无（枚举值，非外键） |
| **Default** | `bool` | — | 否 | 是否默认项 | 由**前端**传入，不传视为 `false` | 同一用户同一 BizType 下**最多 1 条为 true，可以 0 条** | 无 |
| **Title** | `nvarchar` | 32 | **是** | 标题，用于列表展示 | 由**前端**传入 | 非必填。最长 **32 个字符**。**允许重复** | 无 |
| **Text** | `nvarchar` | 4096 | **是** | 快捷文本正文，可含占位符 | 由**前端**传入。后端原样存储，**不做任何解析和替换** | **库中可空，但应用层强制必填**。Trim 后不能为空字符串。最长 **4096 个字符** | 无 |
| **Remark** | `nvarchar` | 4096 | **是** | 备注，用户自己的说明文字 | 由**前端**传入 | 非必填。最长 **4096 个字符** | 无 |
| **SortId** | `int` | — | 否 | 排序值，**降序**，值大的排前面 | 由**前端**传入，不传默认 `0` | 无范围限制，可为负数 | 无 |
| **CreationTime** | `datetime2` | — | 否 | 创建时间 | ABP 框架**自动**写入 | 只读，前端不可传 | 无 |
| **CreatorUserId** | `bigint` | — | 是 | 创建人 | ABP 框架**自动**写入 | 只读。本表中其值**恒等于 `UserId`** | 逻辑关联 `Sys_Users.Id` |
| **LastModificationTime** | `datetime2` | — | 是 | 最后修改时间 | ABP 框架**自动**写入 | 只读 | 无 |
| **LastModifierUserId** | `bigint` | — | 是 | 最后修改人 | ABP 框架**自动**写入 | 只读。本表中其值**恒等于 `UserId`** | 逻辑关联 `Sys_Users.Id` |

> **字符长度说明：** 32 和 4096 都指**字符数**，不是字节数。一个汉字算 1 个字符。

## 3.3 索引

| 索引 | 字段 | 是否唯一 | 用途 |
| :-- | :-- | :-- | :-- |
| `IX_App_QuickTexts_TenantId_UserId_BizType` | `TenantId`, `UserId`, `BizType` | **否** | 支撑业务面板和管理页的列表查询 |

> **为什么默认项不建唯一索引？** 「同用户同类型最多一个默认」这条约束由应用层保证。如果建数据库唯一索引，执行「把 A 设为默认」时会出现 A、B 短暂同时为 true 的中间态，唯一索引会直接把这次更新打回去。所以唯一性交给应用层的互斥逻辑处理。

# 4. 功能与操作说明 (Features & Operations)

## 4.1 两个入口的职责划分

这是本模块最需要先分清的一点：

| 入口 | 位置 | 能做什么 | 不能做什么 |
| :-- | :-- | :-- | :-- |
| **管理页**「我的快捷文本」 | 独立菜单页面 | 新增、编辑、删除、设为默认、分页查询、按业务类型筛选、关键字搜索 | — |
| **业务面板** | 各业务模块输入框旁的弹出列表 | 按当前模块拉取列表、选中一条、把内容替换占位符后填入输入框 | **不能新增、编辑、删除** |

## 4.2 具体操作

- **新增：** 在管理页点「新增」，填写业务类型、标题、正文、备注、排序值，可勾选「设为默认」。保存后归属人自动为当前登录用户。
- **编辑：** 在管理页选中一条修改。**业务类型是锁定的，不能改**，页面上应置灰或只读展示。其余字段都可改。
- **删除：** 在管理页删除，支持单条和勾选多条批量删除。**物理删除，不可恢复**，前端必须有二次确认弹窗。本表不被任何其他业务模块引用，因此**删除时不需要做引用校验**。批量删除采取全有或全无策略，详见卡点 8。
- **设为默认：** 勾选「默认」并保存。系统会自动把当前用户在**同一业务类型**下的其他记录全部改为非默认。
- **取消默认：** 取消勾选并保存。系统直接放行，**不会阻止你把该业务类型下唯一的默认项取消掉**，取消后该业务类型就没有默认项了。
- **列表查询（管理页）：** 分页返回，支持按业务类型筛选（可不传，不传则返回全部业务类型）、按标题或正文关键字搜索。
- **列表查询（业务面板）：** 业务类型**必传**，不分页，一次性返回该类型下的全部记录。

# 5. 状态流转说明 (Status Transitions)

本模块没有审批流或业务状态机，唯一有流转概念的是「默认项」标记。

| 当前状态 | 触发人 / 动作 | 目标状态 | 状态说明 |
| :-- | :-- | :-- | :-- |
| 该业务类型下无默认项 | 用户把 A 设为默认 | A 为默认 | 直接生效 |
| A 为默认 | 用户把 B 设为默认 | B 为默认，**A 自动变为非默认** | 系统自动互斥，不弹提示、不报错 |
| A 为默认 | 用户取消 A 的默认 | 该业务类型下无默认项 | **允许，不拦截** |
| A 为默认 | 用户删除 A | 该业务类型下无默认项 | **不会自动把其他记录提升为默认** |
| 该业务类型下无默认项 | 用户新增第一条 B（未勾选默认） | 仍无默认项 | **不会因为是第一条就自动设为默认** |
| A 为默认 | 用户新增 B 并勾选默认 | B 为默认，**A 自动变为非默认** | 新增时同样触发互斥 |

# 6. 核心业务规则 (Core Rules)

## 6.1 数据归属与可见性

- 归属人 `UserId` **由后端从登录态取**，前端传什么都不生效。
- 查询、编辑、删除**一律强制加 `UserId = 当前登录用户` 条件**。
- **没有任何角色可以看到或操作别人的快捷文本**，包括租户管理员和超级管理员。这一点和系统里其他走数据权限的模块不同，本模块**不接入数据权限体系**。
- 试图编辑或删除别人的数据（比如直接构造 Id 调接口），返回的结果与「数据不存在」一致，不区分「无权限」和「不存在」。
- 数据按租户隔离。**宿主(host)用户无法使用本功能**，因为 `TenantId` 不允许为空。

## 6.2 默认项互斥规则

约束是「同一用户 + 同一业务类型」维度下，**最多 1 个默认，最少 0 个**。

- 设为默认时，系统**自动**把同维度下其他记录置为非默认，属于静默处理，不需要用户确认，也不报错。
- 互斥的作用范围是**同一业务类型内部**。海运出口有一个默认、海运进口有一个默认，两者互不影响，这是正常状态。
- 允许某个业务类型下**一个默认都没有**。
- 新增、删除都不会自动补位或自动指定默认。默认项完全由用户手动控制。

## 6.3 排序规则

无论管理页还是业务面板，列表排序**统一**为三级：

1. **`Default` 降序** —— 默认项永远排在最前面
2. **`SortId` 降序** —— 值大的在前
3. **`CreationTime` 降序** —— 新建的在前

第三级排序是必需的：`SortId` 默认值是 `0`，如果用户从来不去调整排序值，那么所有记录的 `SortId` 都是 0，没有第三级键的话列表顺序会不稳定，每次刷新可能都不一样。

`SortId` 由前端在新增/编辑时直接填数字，**本期不提供拖拽排序，也没有批量调序功能**。

## 6.4 业务类型与占位符

- `BizType` 决定这条快捷文本会在哪个模块的业务面板里出现。业务面板只拉取与当前模块匹配的那一类。
- **占位符清单完全由前端维护**。每个业务类型有哪些占位符可选、占位符长什么样、点选后如何插入到编辑框，都是前端的事。
- **后端不提供占位符列表接口，也不校验正文里的占位符是否合法**。用户手写一个不存在的占位符，保存照样成功，只是使用时替换不出值。
- 正因为占位符和业务类型强绑定，`BizType` 创建后**不允许修改**。允许改会导致一条海运出口的模板被搬到空运出口下，里面的占位符全部失效，产生脏数据。

## 6.5 校验规则汇总

| 字段 | 校验规则 | 违反时的表现 |
| :-- | :-- | :-- |
| `BizType` | 必填，取值只能是 0 / 1 / 2 | 提示业务类型不正确 |
| `Text` | 必填。**先 Trim 再判空**，纯空格、纯换行视为空 | 提示快捷文本不能为空 |
| `Text` | 最长 4096 字符 | 提示超长 |
| `Title` | 非必填，最长 32 字符 | 提示超长 |
| `Remark` | 非必填，最长 4096 字符 | 提示超长 |
| `Id` | 编辑/删除时必填，且必须属于当前用户 | 提示数据不存在 |

**不做的校验（明确不限制）：**

- 同一用户同一业务类型下，**标题允许重复**。
- 同一用户同一业务类型下，**正文内容允许完全重复**，不做去重。
- 单个用户单个业务类型下的**条数没有上限**。

# 7. 前端交互说明 (Frontend Interaction)

## 7.1 管理页「我的快捷文本」

- 列表按 6.3 的三级排序展示，默认项建议加一个明显的标记（比如「默认」徽标）。
- 支持按业务类型下拉筛选、按关键字搜索。
- 正文最长 4096 字符，列表里不要整段铺开，建议截断显示或只展示标题。
- **标题是非必填的**，标题为空时列表要有兜底显示方案，建议截取正文前若干字符作为展示名，不要显示成空白行。
- 编辑弹窗里的**业务类型必须置灰或只读**。
- 删除必须二次确认，并明确提示「删除后不可恢复」。

## 7.2 业务面板

- 打开时按当前所在模块的业务类型拉取列表，一次性全部返回，不分页。
- 列表已由后端排好序，**前端直接按返回顺序渲染即可，不要自己重排**。
- 面板里**没有增删改按钮**，需要维护时引导用户跳转到管理页。
- 「默认项」在本模块的语义**仅仅是排序置顶**，并不代表打开输入框时要自动填入。是否要做「自动填入默认项」属于前端的产品决策，接口层面只是返回 `Default` 字段供前端判断。

## 7.3 占位符的插入与替换

- 编辑快捷文本时，前端根据当前选择的业务类型，展示该类型可用的占位符按钮，点击插入到光标位置。
- 使用快捷文本时，前端拿到正文，用当前这票业务的实际数据替换占位符，再填入目标输入框。
- 替换不到值时如何处理（留空、保留原占位符、还是提示），由前端统一约定，后端不介入。

# 8. 难点与易错点 (Blockers & Pitfalls)

> [!IMPORTANT] **卡点 1：默认项互斥是静默的，不是报错**
>
> 系统里已有的「发票备注模板」「组织银行账户」采用的是**冲突就报错**的策略——已存在默认项时再设一个会被拒绝。**快捷文本用的是相反的策略：自动把旧的挤掉，不报错**。测试时不要按「应该报错」去验收。正确预期是：把 B 设为默认后，A 静默变成非默认，界面上默认标记从 A 转移到 B。

> [!IMPORTANT] **卡点 2：不做软删除，删除即物理删除**
>
> 本表**没有 `IsDeleted` 字段**，删除是真的从库里删掉，不可恢复，回收站里也找不到。与此相关的一个连带效应：因为不存在软删除数据，所有查询和校验都**不需要**考虑「软删除数据是否参与」的问题。这一点与「空运港口」等模块的规则不同，不要照搬。

> [!IMPORTANT] **卡点 3：业务类型创建后锁定**
>
> 编辑时改不了 `BizType`。用户如果建错了类型，只能删掉重建。前端必须在编辑态把该字段置灰，否则用户改了保存不生效会以为是 Bug。测试需要覆盖「绕过前端直接提交修改后的 BizType，后端应忽略该字段」这一场景。

> [!IMPORTANT] **卡点 4：排序的第三级键容易被忽略**
>
> `SortId` 默认值是 0，实际使用中绝大多数记录的 `SortId` 都会是 0。此时列表顺序完全由 `CreationTime` 降序决定。如果实现时漏了第三级排序，测试现象会是「列表顺序时不时变化」，且难以稳定复现。这是本模块最隐蔽的缺陷点，需要专门验证：建多条 `SortId` 都为 0 的记录，反复刷新，顺序必须恒定为「新建的在前」。

> [!IMPORTANT] **卡点 5：数据完全私有，测试必须多账号验证**
>
> 单账号测试无法发现越权问题。必须用两个账号交叉验证：A 账号建的数据，B 账号在列表里看不到，且 B 拿着 A 的数据 Id 去调编辑/删除也必须失败。同时注意本模块**不接入数据权限**，所以不要用「给 B 配了 A 的数据权限，B 就该看得到」这种思路去测——配了也看不到，这是正确行为。

> [!IMPORTANT] **卡点 6：正文的必填校验发生在应用层，不在数据库**
>
> 数据库里 `Text` 是可空列，但保存时后端会强制校验非空。**且是 Trim 之后再判空**，所以提交一串空格或换行会被拦截，不会存进去。测试需要覆盖：空字符串、纯空格、纯换行、空格加换行的混合，全部应被拦截并给出「快捷文本不能为空」的提示。

> [!IMPORTANT] **卡点 7：宿主用户不可用**
>
> 未切换到具体租户的宿主(host)管理员账号无法使用本功能。测试时若用宿主账号登录发现功能异常，属于预期行为，不是缺陷。

> [!IMPORTANT] **卡点 8：批量删除是全有或全无**
>
> 批量删除的集合里只要混进**一条**不属于当前用户的数据，或者混进一个已经被删掉的 id，**整批都不会删除**，直接报「输入快捷文本错误」。不存在「删掉了自己的、跳过了别人的」这种部分成功的结果。测试时需要专门构造混合集合来验证：预期是数据库里一条都没少，而不是自己的那几条被删了。

> [!IMPORTANT] **卡点 9：切换默认项要回传整条数据**
>
> 「设为默认」没有独立接口，走的是编辑接口。前端在列表里点星标切换默认时，必须把该行的标题、正文、备注、排序值一并回传，只传 id 和默认标记会把其余字段覆盖成空值。这是本模块最容易在联调阶段暴露的问题，测试需要覆盖：切换默认后，该条的标题和正文是否原样保留。
