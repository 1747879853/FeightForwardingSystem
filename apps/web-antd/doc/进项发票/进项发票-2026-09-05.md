# 进项发票-2026-09-05

## 背景意图

进项票拉取时原先只把开票接口的文件地址写在主表上。需要和销项发票开出一样，把版式文件下载进本系统附件；并且只有开票完成（有发票号、版式地址已返回）才存，避免缺号或缺地址时存出废文件、号码回来后再存一遍。

## 核心逻辑变更

相对上一版（只存外链、不落附件）：

- 定时拉取在本页票头提交之后，对「有发票号 + 至少一个可下载版式地址」的票下载文件，挂到 `ModuleTypeId=160120`。
- 存 `pdfUrl`（OFD/PDF）、`backupUrl`（备份 PDF）、`xmlUrl`、`voucherUrl`。**不存 `pictureUrl`**（在线查看页短链）。
- 附件名按发票号：`{发票号}.ofd` / `{发票号}.pdf` / `{发票号}-备份.pdf` / `{发票号}.xml` / `{发票号}-凭证.*`。同名跳过，缺的下次该票再被拉到时补。
- 下载失败只记日志，不回滚票头。
- 列表、详情都返回 `attachments`。当前完整字段与卡点见总逻辑 4、5.卡点 5、6.1，接口见接口文档列表/详情的 `attachments` 节。
- 拉取不再 `Begin` 独立工作单元：`PullAllAsync` 挂 `[UnitOfWork(IsTransactional = false)]`，拦截器开工作单元；跨租户用 `CurrentUnitOfWork.SetTenantId`。本页票头、游标、附件写入后立刻 `SaveChangesAsync`。整轮中间有开票接口和文件下载，不能套事务。

## 避坑指南

- 不要在没有发票号时存附件，文件名会对不上，同一份会存两遍。
- 不要把 `pictureUrl` 当图片下。
- 附件写入走仓储而不是带 `[AbpAuthorize]` 的附件 AppService：定时任务没有登录用户，走 AppService 会被拦。
- `clientVisible` 为 false，进项给内部看，不要抄销项的 true。
- 拉取入口用 `[UnitOfWork(IsTransactional = false)]`，不要再 `Begin` 独立工作单元。租户切 `CurrentUnitOfWork.SetTenantId`；本页票头、游标、附件写入后 `SaveChangesAsync`。整轮中间有开票接口和文件下载，不能套事务。

# 手动拉取

## 背景意图

定时任务按更新时间增量扫池，等下一轮太慢，也筛不了「这一张 / 这一段开票日期」。需要按公司立刻从发票池拉进本地，其它条件可选。

## 核心逻辑变更

相对上一版（只有定时拉取）：

- 新增 `POST /api/services/app/InputInvoiceAdmin/PullAsync`，`companyId` 必填，其余走发票池筛选（号码、开票时间、更新时间、销方、票种、状态等）。
- 落库、查明细、存附件与定时任务同一套。传了发票号码/代码/数电号码时不分页。
- **不推进** `LastPullTime`。权限用 `Admin.InputInvoice.Add`（新增）。当前完整规则见总逻辑 2、5.卡点 6、6.2，接口见接口文档第三节。

## 避坑指南

- 角色要勾「进项发票 / 添加」，只勾查看调不通。没有单独的拉取权限。
- 不要在手动拉取成功后改定时游标，带筛选时尤其会漏票。
- 池里没有的票拉不来，不要在这个接口里申请下载。
