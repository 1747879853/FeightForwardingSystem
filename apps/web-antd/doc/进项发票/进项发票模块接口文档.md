# 进项发票接口文档

**控制器**：`InputInvoiceAdmin`

**所有接口均需要登录认证**

票由后台定时从开票接口发票池落入本地（该公司从没拉过则取更新时间最近 5 天，之后按游标增量），也可按公司手动拉取。没有新增/编辑/删除票面。

---

# 1. 业务背景说明 (Background)

**白话解释：** 进项发票是开给我们（购方）的票。列表、详情读的是本地表。手动拉取会现查开票接口发票池并写入本地。

- 用户只能看到数据权限覆盖到的**公司**下的票（人在部门下时，向上找到所属公司）。
- `orgId` 存的是公司 id。
- 版式文件在开票完成后下载存成本系统附件。

# 2. 数据结构

- 主表：`InputInvoice`（进项发票）
- 子表：`InputInvoiceItem`（商品明细）
- 特定业务（建筑/运输/不动产/旅客/铁路/航空）以 JSON 存在主表，详情里拆成嵌套数组

## 二、进项发票分组统计

### `GET /api/services/app/InputInvoiceAdmin/GetGroupedListAsync`

**权限**：`Admin.InputInvoice.Get`

按指定字段分组统计条数，供列表左侧/顶部的分组导航使用。**筛选条件与列表接口完全一致**（同一套 `InputInvoiceQueryDto`，同一套数据权限），所以各分组条数相加等于当前筛选下列表的 `totalCount`。

**入参** `InputInvoiceGroupQueryDto`（Query 参数）：列表接口的全部入参 + 下面一个字段。`pageIndex` / `pageSize` / `sorting` 传了也不生效，分组结果不分页。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `groupField` | `InputInvoiceGroupField` | 是 | 分组字段 `1`发票类型 `2`购方名称 `3`销方名称。传其它值报「不支持的分组字段」 |

**出参** `InputInvoiceGroupDto[]`（数组，不分页，按 `count` 倒序）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `string` | 分组值。`groupField=1` 时为发票类型枚举的 int 字符串（`"1"`蓝票 / `"2"`红票）；`groupField=2/3` 时为名称本身；该字段未填写的那一组为 `null` |
| `name` | `string` | 分组显示名。`groupField=1` 时为「蓝票」/「红票」；`groupField=2/3` 时同 `id`；未填写组为 `null` |
| `count` | `int` | 该分组下的条数 |

**点某个分组回列表怎么传**（分组 → 列表筛选字段的对应关系）：

| `groupField` | `id` 有值时                    | `id` 为 `null`（未填写组）时 |
| ------------ | ------------------------------ | ---------------------------- |
| `1` 发票类型 | `invoiceType` = `id`（转数字） | `invoiceTypeEmpty=true`      |
| `2` 购方名称 | `payerName` = `id`             | `payerNameEmpty=true`        |
| `3` 销方名称 | `sellerHeader` = `id`          | `sellerHeaderEmpty=true`     |

**业务规则**：

- 名称类分组（购方名称 / 销方名称）把 `null` 和空串**合并成同一组**返回（`id`、`name` 均为 `null`），与列表的 `payerNameEmpty` / `sellerHeaderEmpty` 口径一致。发票池两种空值都会给，不合并会出现两个空白分组。
- 名称类分组的 `id` 回填到列表时走的是**模糊匹配**（`payerName` / `sellerHeader` 本身是模糊筛选）。某个名称是另一个名称的子串时，列表条数会大于该分组的 `count`。
- `orgId` 解析不到公司、或当前用户没有任何公司的数据权限时返回空数组。
- 没有数据的分组不会出现（不补 0 行）。

## 四、手动拉取进项发票

### `POST /api/services/app/InputInvoiceAdmin/PullAsync`

**权限**：`Admin.InputInvoice.Add`

按指定公司现查开票接口发票池，写入或更新本地进项发票；开票完成的票同时存版式附件。落库规则与定时任务相同（公司+发票号码+发票代码 upsert）。**不推进**定时游标 `LastPullTime`。

**入参** `InputInvoicePullDto`（Body）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `companyId` | `long?` | 是 | 所属公司组织 id。传部门时向上找到所属公司再拉 |
| `invoiceNo` | `string` | 否 | 发票号码。有值时按号码（及代码/数电号码）查，不再分页 |
| `invoiceCode` | `string` | 否 | 发票代码。数电票不传 |
| `elecInvoiceNumber` | `string` | 否 | 数电号码 |
| `invoiceTimeStart` | `DateTime?` | 否 | 开票时间起。与止必须一起传 |
| `invoiceTimeEnd` | `DateTime?` | 否 | 开票时间止 |
| `updateTimeStart` | `DateTime?` | 否 | 更新时间起。与止必须一起传 |
| `updateTimeEnd` | `DateTime?` | 否 | 更新时间止 |
| `sellerHeader` | `string` | 否 | 销售方抬头，即销方名称。**2026-09-06 由 `sellerTaxName` 改名** |
| `sellerTaxNo` | `string` | 否 | 销方税号 |
| `totalAmount` | `decimal?` | 否 | 含税总金额 |
| `invoiceLine` | `InputInvoiceLine?` | 否 | 发票种类。**2026-09-07 由 string 改为枚举，JSON 为数字** |
| `invoiceStatus` | `InputInvoiceStatus?` | 否 | 发票状态。**2026-09-07 由 string 改为枚举，JSON 为数字** |
| `checkedStatus` | `InputInvoicePoolCheckedFilter?` | 否 | 查验筛选 0未查验 1已查验。不是票面查验状态。**2026-09-07 改为枚举** |
| `reimbursementStatus` | `InputInvoiceReimbursementStatus?` | 否 | 报销状态。**2026-09-07 改为枚举** |
| `signStatus` | `InputInvoiceSignStatus?` | 否 | 签收状态。**2026-09-07 改为枚举** |
| `enterAccountStatus` | `InputInvoiceEnterAccountStatus?` | 否 | 入账状态。**2026-09-07 由 string 改为枚举，JSON 为数字**（1 对应对方 `01`） |

**出参** `InputInvoicePullResultDto`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `count` | `int` | 本次写入或更新的张数。**本地已有、且发票池那边没再动过的票会被跳过、不计入**，所以重复拉同一批票会返回 0；池里没有符合条件的票时也是 0 |

**业务规则**：

- 必须登录，且角色勾了「进项发票 / 添加」。列表查看权限不能调本接口。
- 只能拉当前用户数据权限能覆盖到的公司。
- 公司未配置开票资料时提示「未配置开票资料，无法拉取进项发票」。
- 开票时间、更新时间的起止必须成对；起不能晚于止。
- 传了发票号码/代码/数电号码时只查这些票，不再按页扫池。
- 不传筛选条件则按该公司发票池分页全量拉取（可能较慢），仍不推进定时游标。
- 池里还没有的票拉不来。申请下载不在本接口。
- **没更新的票会被跳过。** 判断口径：发票池的 `max(归集时间, 更新时间)` 早于本地的 `max(创建时间, 最近同步时间)`（留了几分钟时钟容差）就跳过，跳过的票不查明细、不重写、不计入 `count`。所以「`count` 返回 0」通常不是失败，而是这批票本地已经是最新的。 **指定发票号码也照样跳过**，本接口不能当成「强制重新同步某张票」用。
- 跳过只影响票面数据；**版式文件附件仍会尝试补齐**（上次下载失败的这次会重试，同名不重复下载）。
