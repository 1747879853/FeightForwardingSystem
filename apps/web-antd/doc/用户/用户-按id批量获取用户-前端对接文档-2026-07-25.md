> **服务名**：`UserAppService`

> **接口基础路径**：`/api/services/app/User/`
>
> **说明**：本文档只描述本次新增的一个接口，供前端对接使用。通用约定（Token、响应包装等）见 `文档/用户/用户通用api.md`。

## 1. 按用户id批量获取用户

**Summary：** 传入一批用户 id，一次性返回这些用户的昵称、启用状态、手机号、邮箱、角色列表与所属组织机构路径。**不分页**，用于前端已持有若干 `userId`（如单据上的业务员、操作员、审批人）时批量回显用户信息，避免逐个调用 `GetUserAsync`。**不传 `ids` 时返回全部用户**。

**GET** `/api/services/app/User/GetUserListByIdsAsync`

**权限**：`[AbpAuthorize]`（登录即可，无需后台管理权限）

### 入参 Query Parameters（`UserListByIdsQueryDto`）

| 字段 | JSON Key | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| Ids | `ids` | `long[]` | 否 | 用户 id 集合。**为空或不传时返回全部用户**；内部自动去重；不存在的 id 直接忽略，不报错 |

### 请求示例

按 id 批量获取：

```
GET /api/services/app/User/GetUserListByIdsAsync?ids=2&ids=5&ids=9
```

获取全部用户：

```
GET /api/services/app/User/GetUserListByIdsAsync
```

> 数组参数按 `ids=1&ids=2&ids=3` 的形式重复传递，不要传 JSON 字符串。

### 出参列表项字段说明（`UserInfoDto`）

| 字段 | JSON Key | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| Id | `id` | `long` | 用户主键 id |
| NickName | `nickName` | `string` | 昵称（真实姓名，页面展示统一用此字段） |
| Enable | `enable` | `bool` | 是否启用。`false` 表示该用户已停用（不可被检索选择），但历史单据仍需展示其姓名 |
| PhoneNumber | `phoneNumber` | `string` | 手机号 |
| EmailAddress | `emailAddress` | `string` | 帐号邮箱 |
| Roles | `roles` | `UserRoleDto[]` | 用户角色列表，无角色时为空数组 |
| Organizations | `organizations` | `UserOrganizationPathDto[]` | 所属组织机构路径列表（一个用户可属于多个组织），无组织时为空数组 |

#### UserRoleDto 字段

| 字段 | JSON Key | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| RoleId | `roleId` | `int` | 角色 id |
| RoleName | `roleName` | `string` | 角色名称（编码，用于程序判断） |
| RoleDisplayName | `roleDisplayName` | `string` | 角色显示名（用于页面展示） |

#### UserOrganizationPathDto 字段

| 字段 | JSON Key | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| OneOrganizationPath | `oneOrganizationPath` | `UserOrganizationPathItemDto[]` | 单条组织路径，按「从顶级组织到末级组织」顺序排列 |
| Default | `default` | `bool` | 是否为该用户的默认组织 |

#### UserOrganizationPathItemDto 字段

| 字段 | JSON Key | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| Id | `id` | `long` | 组织 id |
| Name | `name` | `string` | 组织名称 |
| IsCompany | `isCompany` | `bool` | 是否为公司节点（`false` 表示部门等非公司节点） |
| LocalCurrencyId | `localCurrencyId` | `long?` | 该组织的本位币 id，未配置时为 `null` |

> **注意**：本接口**不返回** `userName`、`avatar`、`enName`、`employeeID`、`gender`、`status`、`isActive`、`userAttribute`、`idNumber`、`emailPwd`、`receiveAddrPort`、`sendAddrPort`、`officeTel` 等字段，也**不返回**创建人/修改人及创建时间。需要完整信息请调用 `GetUserAsync`。

### 业务规则

1. `ids` 为 `null` 或空数组时**返回当前租户下的全部用户**（不分页、不做数量限制）。
2. `ids` 内部自动 `Distinct` 去重；传入重复 id 只返回一条。
3. 传入的 id 在系统中不存在时**静默忽略**，不抛「用户不存在」，因此返回条数可能少于传入的 id 数量，前端需自行处理缺失项。
4. 排序规则：传了 `ids` 时，返回顺序与传入 `ids` 的顺序**严格一致**，前端可按下标直接对应；未传 `ids` 时按用户 id 升序。
5. **不过滤**审核状态与激活状态：已停用（`enable = false`）、未激活、待审核的用户也会返回。因为本接口用于按 id 回显历史数据，停用用户的姓名仍需展示。这与 `GetUserSimplePagedListAsync`（仅返回审核已通过且已激活用户）的取数范围不同。
6. 角色一次性批量查出（`GetRolesByUserIds`），组织路径读取租户级缓存字典，传入几十上百个 id 也不会产生 N+1 查询。

### 与相近接口的选用建议

| 场景 | 推荐接口 |
| :-- | :-- |
| 已有一批 `userId`，需要批量回显姓名/角色/组织 | `User/GetUserListByIdsAsync`（本接口，传 `ids`） |
| 一次性加载全部用户做本地缓存/前端自行筛选 | `User/GetUserListByIdsAsync`（本接口，不传 `ids`） |
| 下拉框搜索选人（关键字 + 分页） | `User/GetUserSimplePagedListAsync` |
| 单个用户的完整信息（含用户资料 `UserProfile`） | `User/GetUserAsync` |
| 后台用户管理列表（含管理字段、可按状态筛选） | `UserAdmin/GetUserPagedListAsync` |
