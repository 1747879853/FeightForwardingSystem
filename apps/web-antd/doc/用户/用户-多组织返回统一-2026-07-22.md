# 1. 背景意图 (Background)

**白话解释：** 一个用户现在可以同时隶属**多个组织机构**。此前用户读取类接口的返回并不一致：

- `GetUserPagedListAsync` 已返回多组织 `organizations`，但仍保留一个遗留单值字段 `organization`（"部门名"字符串，只能表示一个组织）。
- `GetUserPagingListAsync`（另一套分页）只返回单值 `organization`，**没有**返回多组织 `organizations`。
- `GetUserAsync`（用户详情）返回的 `UserDto` 虽然继承了 `organizations` 字段，但代码里**从未填充**，前端拿到的始终是空数组。

本次改造把「用户可属多个组织」这一当前逻辑贯彻到**所有**用户读取接口，统一返回 `organizations`，并**下线遗留单值字段 `organization`**，避免前端误用单值字段。

# 2. 核心逻辑变更 (Core Changes)

## 2.1 受影响接口

| 接口 | 地址 | 变更 |
| :-- | :-- | :-- |
| 获取用户分页列表 | `GET /api/services/app/UserAdmin/GetUserPagedListAsync` | 移除返回 `organization`；保留并继续返回 `organizations` |
| 获取用户分页列表(旧版) | `GET /api/services/app/UserAdmin/GetUserPagingListAsync` | 移除返回 `organization`；**新增**返回 `organizations` |
| 获取用户详情 | `GET /api/services/app/UserAdmin/GetUserAsync` | **新增**返回 `organizations`（此前恒为空数组） |

> `GetUserForEditAsync`（编辑回显）与 `GetMyAsync`（我的信息）此前已返回多组织，本次不变。

## 2.2 返回字段变更（`UserListDto` / `UserDto`）

- ❌ 移除：`organization`（`string`，遗留"部门名"单值）
- ✅ 统一返回：`organizations`（`UserOrganizationPathDto[]`）

`organizations` 结构：

```json
"organizations": [
  {
    "default": true,
    "oneOrganizationPath": [
      { "id": 1, "name": "总公司", "isCompany": true, "localCurrencyId": 1 },
      { "id": 3, "name": "技术部", "isCompany": false, "localCurrencyId": null }
    ]
  }
]
```

### UserOrganizationPathDto 字段

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| default | bool | 是否默认组织（对应用户 `DefaultOrgId`） |
| oneOrganizationPath | UserOrganizationPathItemDto[] | 单条组织链，从顶级组织到当前组织，按层级顺序 |

### UserOrganizationPathItemDto 字段

| 字段            | 类型   | 说明         |
| :-------------- | :----- | :----------- |
| id              | long   | 组织id       |
| name            | string | 组织名称     |
| isCompany       | bool   | 是否公司节点 |
| localCurrencyId | long?  | 本位币id     |

## 2.3 实现要点

- 三个读取接口均按用户逐个调用 `GetUserOrganizationPathsAsync(userId)`（带缓存）取全部组织路径填充 `organizations`。
- 从 `UserListDto` 删除 `Organization` 属性（`UserDto : UserListDto` 一并生效）。
- 移除了三处对 `UserManager.GetOrganizationNames(userIds)` 的调用（原仅用于填充单值 `organization`）。

# 3. 避坑指南 (Pitfalls)

> [!IMPORTANT]
>
> 1. **`organization` 字段已彻底移除**：前端若还在读取 `items[].organization` 需改为读取 `organizations`。取"主组织/部门"请用 `organizations` 中 `default=true` 的那条的 `oneOrganizationPath` 末节点。
> 2. **`UserSimpleDto` 不在本次范围**：`UserAppService.GetUserSimplePagedListAsync` 返回的是轻量选择器 DTO（`UserSimpleDto`），仍保留单值 `organization` 名称字段，未改动。
>    - ⚠️ **本条已于 2026-08-16 失效**：该接口的 `organization` 也已移除，改为返回所属公司 id 集合 `companyIds`，详见 `用户-简易分页返回所属公司ids-2026-08-16.md`。
> 3. **用户可能未挂任何组织**：`organizations` 为空数组，前端需做空态处理。
