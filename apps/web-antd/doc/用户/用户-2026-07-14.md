# 1. 背景意图 (Background)

后台用户分页列表 `UserAdmin/GetUserPagedListAsync` 需额外返回每个用户所属的组织机构路径，从**最顶级组织**开始，直到**当前挂载组织**为止，以列表形式展示。当前业务约束下，一个用户只会挂在一个组织下。

# 2. 核心逻辑变更 (Core Logic)

涉及文件：

- `src/CsprojBuilder.Application/Authorization/Users/Dto/UserDto.cs`（`UserListDto`、`UserOrganizationPathItemDto`）
- `src/CsprojBuilder.Application/Authorization/Users/UserAdminAppService.cs`（`GetUserPagedListAsync`）
- `src/CsprojBuilder.Application/CsprojBuilderAppServiceBase.cs`（`GetUserOrganizationPathsByCacheAsync`）

## 2.1 返回结构变更（`UserListDto`）

新增字段：

| DTO 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `OrganizationPath` | `List<UserOrganizationPathItemDto>` | 从根到叶的组织路径；无组织时返回空列表 |

`UserOrganizationPathItemDto` 字段：

| DTO 字段    | 类型     | 说明         |
| :---------- | :------- | :----------- |
| `Id`        | `long`   | 组织id       |
| `Name`      | `string` | 组织名称     |
| `IsCompany` | `bool`   | 是否公司节点 |

## 2.2 填充逻辑

复用基类组织缓存 `GetAllUsersWithOrganizationInfoAsync`，通过新增批量方法 `GetUserOrganizationPathsByCacheAsync` 按页内 `userIds` 一次性取路径，避免逐用户 SQL 查询。

```csharp
var organizationPathMap = await GetUserOrganizationPathsByCacheAsync(userIds);
dto.OrganizationPath = organizationPathMap.TryGetValue(item.Id, out var organizationPath)
    ? organizationPath.Select(o => new UserOrganizationPathItemDto { ... }).ToList()
    : new List<UserOrganizationPathItemDto>();
```

原有 `organization` 字段保持不变，仍表示用户直接挂载的组织名称。

# 3. 避坑指南

- 组织路径依赖租户级组织缓存，用户组织变更后需确保缓存已刷新，否则列表可能短暂显示旧路径。
- 当前仅取用户第一条组织层级链；若后续支持一人多组织，需同步调整批量取值策略。
