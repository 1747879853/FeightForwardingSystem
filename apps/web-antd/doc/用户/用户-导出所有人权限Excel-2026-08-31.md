# 1. 背景意图 (Background)

**白话解释：** 以前想核对「谁有哪些权限」，只能一个人一个人点进「用户权限」页面看勾选状态（页面调的是 `GetUserPermissionsAsync`），几十号人核一遍要点几百次，也没法整体比对「同一批人权限是不是配一致了」。本次新增导出，把全公司所有人的权限一次性拉成一张 Excel 矩阵：**一行一个人，一列一项权限，交叉格打勾**，权限审计、交接、对比一眼就能扫完。

按两种下载方式各给了一个接口：**落盘返回文件名** 和 **直接返回文件流**，两者产出的 Excel 内容完全一样，前端按页面交互习惯挑一个用。

# 2. 核心逻辑变更 (Core Changes)

## 2.1 新增接口（两个）

| # | 接口 | 地址 | 返回 | 权限 |
| :-- | :-- | :-- | :-- | :-- |
| 1 | 导出所有人权限（**落盘**） | `POST /api/services/app/UserAdmin/ExportUserPermissionsToLocalFileAsync` | 文件名（`string`） | `Admin.Team.User.Get`（查看用户） |
| 2 | 导出所有人权限（**文件流**） | `GET /api/ExportFile/ExportUserPermissionsAsync` | xlsx 文件流 | `Admin.Team.User.Get`（查看用户） |

**为什么地址不在同一个前缀下**：本项目返回文件流的导出一律走 `ExportFileController`（与「导出库存列表」同一套），ABP 动态 API 不适合吐二进制；而落盘版返回的是普通字符串，就是标准的 `UserAdmin` 动态 API。

两个接口在 AppService 里的对应方法：

| 接口 | AppService 方法 | 说明 |
| :-- | :-- | :-- |
| 落盘 | `ExportUserPermissionsToLocalFileAsync()` → `string` | 动态 API，内部调下面那个拿到字节再落盘 |
| 文件流 | `ExportUserPermissionsExcelAsync()` → `byte[]` | 标了 `[RemoteService(false)]`，只给 Controller 用，Excel 生成逻辑都在这里 |

## 2.2 入参

**两个接口都没有入参。** 「所有人」就是当前租户下的全部用户，不做任何筛选（**未激活、已禁用的用户同样导出**）。落盘版是 POST，body 传空对象 `{}` 即可。

## 2.3 出参

### 接口 1：落盘版

返回落盘后的文件名（ABP 标准包装）：

```json
{
  "result": "用户权限-20260831143000-638939520000000000.xlsx",
  "success": true,
  "error": null
}
```

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| result | string | 文件名。文件保存在服务端 `wwwroot/excel/` 下，**下载地址 = `/excel/` + 这个文件名** |

文件名格式 `用户权限-{yyyyMMddHHmmss}-{Ticks}.xlsx`。带 `Ticks` 是必须的：时间戳只到秒，多租户在同一秒各导一次会撞名并互相覆盖，那就等于把别人租户的权限表给了对方。

### 接口 2：文件流版

直接返回 xlsx 文件流，不是 JSON：

| 响应头 | 值 |
| :-- | :-- |
| Content-Type | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` |
| Content-Disposition | `attachment; filename="用户权限{yyyyMMddHHmmss}.xlsx"` |

## 2.4 Excel 结构（两个接口一致）

工作表名 `用户权限`，第 1 行为表头，第 1 列为用户昵称，表头行与首列已冻结。

|  | A 列 | B 列 | C 列 | … |
| :-- | :-- | :-- | :-- | :-- |
| **第 1 行（表头）** | 昵称 | 后台-团队管理-用户-查看用户 | 后台-团队管理-用户-编辑用户 | … |
| 第 2 行 | 张三 | √ | √ | … |
| 第 3 行 | 李四 | √ |  | … |

| 位置 | 内容 | 说明 |
| :-- | :-- | :-- |
| A1 | `昵称` | 固定表头 |
| B1 及之后 | 权限的中文名**全路径** | 用 `-` 连接各级父权限的中文名，如 `后台-团队管理-用户-查看用户`；列的顺序按权限树深度优先展开，同一模块的权限连在一起 |
| A2 及之后 | 用户昵称（`NickName`） | 按昵称排序 |
| 交叉单元格 | `√` 或空 | 有该权限为 `√`，没有则留空（**不写 `×`**，几百列全填 × 没法看） |

## 2.5 实现要点

- **权限口径与 `GetUserPermissionsAsync` 完全一致**：逐个用户调 `UserManager.GetGrantedPermissionsAsync(user)`，结果 = 用户自身的授权 ∪ 其角色带来的授权。所以导出的勾选状态与「用户权限」编辑页看到的勾选状态是同一份数据。
- **列顺序自己按树展开**：`IPermissionManager.GetAllPermissions()` 返回的是字典值集合，顺序不作保证，直接拿来当列顺序会让同一模块的权限散落在表格各处。因此新增私有方法 `GetPermissionsInTreeOrder()`，从根权限深度优先遍历 `Permission.Children`；父权限被多租户/功能开关过滤掉时，其子权限自己充当遍历起点，避免整片子权限丢列。
- **表头拼全路径**：叶子权限的中文名大量重复（`Admin.Warehouse.Get`、`Admin.FeeName.Get` 等一律叫「查看」），只取叶子名会出现一排分不清的「查看」列。中文名取法与前端权限树一致（按权限名走本地化 `L(permission.Name)`），两边显示的名字不会打架。
- **用户一次查全**：`GetGrantedPermissionsAsync` 只用到 `user.Id`，所以用 `UserManager.Users.AsNoTracking()` 一次拉出全部用户，不逐个 `GetUserByIdAsync`。
- **落盘目录 `wwwroot/excel`**：由默认的静态文件中间件按 `/excel/{文件名}` 提供访问，无需在 `Startup` 里额外挂中间件。目录不存在时自动创建。

# 3. 避坑指南 (Pitfalls)

> [!IMPORTANT]
>
> 1. **两个接口的地址前缀不一样，别弄混**：落盘版在 `/api/services/app/UserAdmin/` 下，文件流版在 `/api/ExportFile/` 下。调 `/api/services/app/UserAdmin/ExportUserPermissionsExcelAsync` 会 404，因为那个方法标了 `[RemoteService(false)]`。
> 2. **`Async` 后缀不能省**：Web.Host 里 `SuppressAsyncSuffixInActionNames = false`，Controller 路由也保留 `Async`。写成 `/api/ExportFile/ExportUserPermissions` 直接 404。
> 3. **文件流版下载要带 token**：这是需要鉴权的 GET。裸 `window.open` 不会带 `Authorization` 头，会 401；请照「导出库存列表」现有做法用 blob 下载（带鉴权头请求后本地存盘）。**落盘版没这个问题**——`/excel/{文件名}` 是静态文件，不鉴权，`window.open` / `<a download>` 直接能下。
> 4. **落盘版返回的是文件名，不是完整 URL**：前端自己拼 `/excel/` 前缀（跨域时还要拼上后端域名），跟打印接口返回 `/PrintTempFile/{文件名}` 的用法一致。
> 5. **落盘的文件是静态资源，谁拿到地址谁都能下**：接口本身校验了 `Admin.Team.User.Get`，但落盘后的 xlsx 走静态文件不鉴权。全公司权限表算敏感数据，如果不接受这一点就用文件流版，别用落盘版。
> 6. **`wwwroot/excel` 目前没有清理机制**：每次导出都会留一个文件，跟 `PrintTempFile`、`UserImportFail` 一样只增不减。量大了要单独做定时清理。
> 7. **如果前端要用 axios/fetch 读 `/excel/` 里的字节**（而不是浏览器直接下载），跨域会因为静态文件缺 CORS 头而失败——`PrintTempFile` 是专门在 `Startup` 里挂了带 CORS 头的静态文件中间件才解决的。普通下载链接不是 CORS 请求，不受影响。
> 8. **前端不要按固定列号解析 Excel**：权限列会随 `FreightAuthorizationProvider` 增删权限而整体位移。这份 Excel 是给人看的，不要当接口数据用。
> 9. **导出的是「有效权限」，不是「用户自身授权记录」**：靠角色继承来的权限同样会打勾。看到某人有权限但「用户权限」页面上那一项不是他单独勾的，去查他的角色，不是 Bug。
> 10. **人多时会慢**：复杂度是 用户数 × 权限数，每个用户都要走一遍权限缓存（首次还要落库查一次）。别挂在页面首屏自动调，做成手动点「导出」。
> 11. **权限用的是 `Admin.Team.User.Get`（查看用户）**，与用户列表、用户导出同一个权限点。没有单独建「导出用户权限」权限节点，所以能看用户列表的人就能导出这张表——如果要收紧，需要单独加权限节点并同步 `FreightAuthorizationProvider` 与中文名。
