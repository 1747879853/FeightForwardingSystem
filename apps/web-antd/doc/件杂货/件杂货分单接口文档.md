# 件杂货分单接口文档

件杂货模块的接口按子域拆成两份，本文只写**件杂货分单** `BreakBulkSeparateAdmin` 的 6 个接口：地址、HTTP 方法、权限、入参全部字段、出参全部字段、报错文案、报文样例。

- 件杂货主表接口见同目录《件杂货模块接口文档》；
- 业务口径（结算对象与应结日期、复制规则、与提单的联动）见同目录《件杂货模块总逻辑文档》2.12、4.3。

---

# 1. 对接总纲

## 1.1 服务地址与鉴权

| 项         | 值                                                      |
| :--------- | :------------------------------------------------------ |
| 接口基址   | `{host}/api/services/app/BreakBulkSeparateAdmin/`       |
| 完整路径   | 基址 + 方法名，**方法名保留 `Async` 后缀**              |
| 鉴权头     | `Authorization: Bearer {accessToken}`                   |
| 租户头     | `Abp.TenantId: {租户id}`（租户账号登录时带）            |
| 请求体类型 | `Content-Type: application/json`（POST / PUT / DELETE） |

## 1.2 接口一览

| # | 业务动作 | HTTP | 完整路径 | 参数位置 | `result` 类型 | 权限 |
| :-- | :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | 列表 | GET | `/api/services/app/BreakBulkSeparateAdmin/GetPagedListAsync` | QueryString | 分页对象 | `Admin.BreakBulk.Get` |
| 2 | 详情 | GET | `/api/services/app/BreakBulkSeparateAdmin/DetailAsync` | QueryString | 对象 | `Admin.BreakBulk.Get` |
| 3 | 新增 | POST | `/api/services/app/BreakBulkSeparateAdmin/AddAsync` | 请求体 | `string`（新分单 Guid） | `Admin.BreakBulk.Edit` |
| 4 | 编辑 | PUT | `/api/services/app/BreakBulkSeparateAdmin/EditAsync` | 请求体 | `bool` | `Admin.BreakBulk.Edit` |
| 5 | 复制 | POST | `/api/services/app/BreakBulkSeparateAdmin/CopyAsync` | 请求体 | `string`（新分单 Guid） | `Admin.BreakBulk.Edit` |
| 6 | 删除 | DELETE | `/api/services/app/BreakBulkSeparateAdmin/DeleteAsync` | **请求体** | `bool` | `Admin.BreakBulk.Edit` |

> [!WARNING] 删除接口的参数在请求体里，`axios` 要写成 `axios.delete(url, { data: payload })`。

## 1.3 权限

**件杂货分单没有独立权限点**，权限挂在件杂货上：

| 权限标识 | 控制的接口 |
| :-- | :-- |
| `Admin.BreakBulk.Get` | `GetPagedListAsync`、`DetailAsync` |
| `Admin.BreakBulk.Edit` | `AddAsync`、`EditAsync`、`CopyAsync`、**`DeleteAsync`**（删除也用编辑权限，不是 `Admin.BreakBulk.Delete`） |

在功能权限之外，每个接口还要过**所属件杂货那一票**的数据权限与表级权限：列表、详情按查询口径，新增、编辑、复制、删除按编辑口径。挡掉时报「没有这条数据的数据权限,不能{动作}」/「没有这条数据的表级权限,不能{动作}」，动作取：列表/详情「查看」、新增/编辑/复制「编辑」、删除「删除」。

## 1.4 通用约定

- 响应统一 ABP 信封，判成功只看 `success`；业务报错是 **HTTP 500**，`error.message` 为本文报错文案原文；参数格式或特性校验不通过是 HTTP 400。
- 出参 camelCase，入参不区分大小写（例：`BlNum` → `blNum`，`PKGS` → `pkgs`）。
- 入参字符串自动去首尾空格，长度按去空格后计算。
- 毛重、体积入参自动四舍五入到 **4 位小数**。
- 签单日期原样保存，不截时分秒。
- **分单不做字段屏蔽**，出参字段恒全量返回。

## 1.5 分页与排序

| 参数 | 类型 | 默认 | 范围 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| PageIndex | int | 1 | 1 ~ 2147483647 | 页码，越界 HTTP 400 |
| PageSize | int | 10 | 1 ~ 100000 | 每页条数，越界 HTTP 400 |
| Sorting | string | `CreationTime DESC` | - | 排序根对象是**分单**，如 `BlNum ASC`、`CreationTime DESC`、`Settlement.Name ASC`；字段名写错返回 HTTP 500 |

分页返回 `items`、`totalCount`、`skipCount`、`maxResultCount`、`currentPage`、`totalPages`，含义同《件杂货模块接口文档》1.8。

# 2. 公共数据结构

## 2.1 GuidIdDto

用于详情、复制、删除。

| 字段    | 类型   | 说明                                                     |
| :------ | :----- | :------------------------------------------------------- |
| Id      | Guid   | 分单 id                                                  |
| Ids     | Guid[] | **仅删除接口使用**：有值时按它批量删，忽略 `Id`          |
| IsPrint | bool?  | **仅详情接口使用**：`true` 时额外返回 `companyPrintInfo` |

## 2.2 往来单位对象 `ClientSimpleDto`

用于 `settlement`、`consignee`、`shipper`、`notifier`、`podAgent`，对应 id 为空时整个对象为 `null`。

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| Id | Guid | 单位 id |
| Name | string | 简称 |
| Code | string | 客户代码 |
| FullName | string | 全称 |
| EnName | string | 英文名 |
| TaxRate | decimal? | 税率（%） |
| IsDishonest / DishonestRemark / EnterpriseType / ClientType / IsShared / ClientStatus / OrgId / Orgs | - | **本服务不填**，恒为类型默认值（`false` / `null` / `0`），不要使用 |

## 2.3 港口对象 `PortCodeSimpleDtoForOrder`

用于 `signingPort`、`prepareAt`。字段：`Id`、`PortName`（港口英文名）、`CnName`、`EdiCode`、`Lane`（`Id`、`Code`、`LaneName`、`LaneEnName`、`EdiCode`）、`Country`（`Id`、`Code`、`CountryName`、`CountryEnName`），与《件杂货模块接口文档》3.4 相同。

## 2.4 基础资料对象

| 对象 | 位置 | 字段 |
| :-- | :-- | :-- |
| `CodeIssueTypeSimpleDto` 签单方式 | `codeIssueType` | `Id`、`BillType`（名称，恰好是「正本」才按正本处理）、`EnName` |
| `CodePackageSimpleDto` 包装 | `codePackage` | `Id`、`Name`、`EdiCode` |
| `CodeFrtSimpleDto` 付费方式 | `codeFrt` | `Id`、`CnName`、`EnName` |
| `CodeServiceSimpleDto` 运输条款 | `codeService` | `Id`、`CnName`、`EnName`、`EdiCode` |

对应 id 为空或资料已删除时为 `null`。

## 2.5 公司打印信息 `CompanyPrintInfoDto`

仅详情 `IsPrint = true` 时返回；分单没有所属组织，取**所属件杂货**的所属组织向上找公司节点，找不到为 `null`。字段与《件杂货模块接口文档》3.14 相同：`CompanyDisplayName`、`CompanyShortName`、`CompanyEnName`、`CompanyAddress`、`CompanyContactPhone`、`CompanyEmail`、`UnifiedSocialCreditCode`、`Logo`、`DefaultBanks`、`RMBBank`（key `rmbBank`）、`USDBank`（key `usdBank`）；银行账户元素为 `CurrencyCode`、`AccountName`、`BankShortName`、`BankName`、`BankAccount`。

## 2.6 分单输出对象 `BreakBulkSeparateDto`

列表 `items` 元素与详情 `result` 结构相同。

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| Id | Guid | 分单 id |
| BreakBulkId | Guid | 所属件杂货 id |
| SettlementId | Guid | 结算对象 id |
| Settlement | 对象 | 结算对象，见 2.2 |
| SettlementDate | datetime | 应结日期，后端按结算对象账期算，只读 |
| ConsigneeId / Consignee / ConsigneeContent | Guid? / 对象 / string | 收货人及内容 |
| ShipperId / Shipper / ShipperContent | Guid? / 对象 / string | 发货人及内容 |
| NotifierId / Notifier / NotifierContent | Guid? / 对象 / string | 通知人及内容 |
| PodAgentId / PodAgent / PodAgentContent | Guid? / 对象 / string | 目的港代理及内容 |
| BlNum | string | 分提单号 |
| Marks | string | 唛头 |
| PKGS | int? | 件数（key `pkgs`） |
| CodePackageId / CodePackage | long? / 对象 | 包装，对象见 2.4 |
| Kgs / Cbm | decimal? | 毛重 / 体积（4 位小数） |
| GoodsDes | string | 货物描述 |
| CodeIssueTypeId / CodeIssueType | long? / 对象 | 签单方式 |
| SigningPortId / SigningPort | long? / 对象 | 签单地点，对象见 2.3 |
| SigningTime | datetime? | 签单日期 |
| CodeFrtId / CodeFrt | long? / 对象 | 付费方式 |
| PrepareAtId / PrepareAt | long? / 对象 | 付费地点（预付地点），对象见 2.3 |
| CodeServiceId / CodeService | long? / 对象 | 运输条款 |
| Remark | string | 备注 |
| CreationTime / CreatorUserId | datetime / long? | 创建时间 / 创建人 id |
| CreatorUserName | string | **创建人昵称** |
| LastModificationTime / LastModifierUserId | datetime? / long? | 修改时间 / 修改人 id |

**分单没有箱型箱量**，也不返回提单；分单提单在件杂货列表行的 `billOfLadings` 里（主单在前，分单按创建时间），或在提单模块查。

## 2.8 分单字段校验文案

新增、编辑共用，按下表从上到下的顺序校验：

| 报错文案 | 触发条件 |
| :-- | :-- |
| 结算对象不能为空 | 未传 `SettlementId` |
| 结算对象不存在 | 结算对象不存在 |
| 签单方式不能为空 | 未传 `CodeIssueTypeId` |
| 签单方式ID:{id}不存在 | 签单方式不存在 |
| 收货人不存在 / 发货人不存在 / 通知人不存在 / 目的港代理不存在 | 往来单位不存在 |
| 签单地点ID:{id}不存在 / 付费地点ID:{id}不存在 | 港口不存在 |
| 包装ID:{id}不存在 | 包装不存在 |
| 付费方式ID:{id}不存在 | 付费方式不存在 |
| 运输条款ID:{id}不存在 | 运输条款不存在 |
| 收货人内容/发货人内容/通知人内容/目的港代理内容长度不能超过1024个字符 | 超长 |
| 分提单号长度不能超过64个字符 | 超长 |
| 备注长度不能超过1024个字符 | 超长 |

分单的外键报错带 id（「签单方式ID:{id}不存在」等），写法与件杂货主表（「签单方式不存在」）不同，测试断言时注意区分。

## 3.3 新增 AddAsync

### 3.3.1 地址与权限

| 项       | 值                                                              |
| :------- | :-------------------------------------------------------------- |
| 方法     | `POST`                                                          |
| 地址     | `/api/services/app/BreakBulkSeparateAdmin/AddAsync`             |
| 参数位置 | 请求体 `BreakBulkSeparateAddDto`                                |
| 权限点   | `Admin.BreakBulk.Edit` + 所属件杂货编辑口径的数据权限与表级权限 |
| 返回     | `result` 为新分单 Guid                                          |

### 3.3.2 输入参数

| 参数        | 类型  | 必填   | 说明                                      |
| :---------- | :---- | :----- | :---------------------------------------- |
| BreakBulkId | Guid? | **是** | 所属件杂货 id；建好后不能再改到别的件杂货 |
| 其余字段    | -     | -      | 见 2.7                                    |

**后端处理**：应结日期按结算对象的账期算（业务类型、销售、组织、业务来源、开船日期取所属件杂货的；取数异常时兜底为开船日期当天，开船日期为空取当前时间）；保存后按签单方式建一张**分单提单**：正本 → 待签入，其余 → 已签入。

### 3.3.3 报错文案

| 报错文案 | 触发条件 |
| :-- | :-- |
| 输入不能为空 | 请求体为 `null` |

## 3.6 删除 DeleteAsync

### 3.6.1 地址与权限

| 项 | 值 |
| :-- | :-- |
| 方法 | `DELETE` |
| 地址 | `/api/services/app/BreakBulkSeparateAdmin/DeleteAsync` |
| 参数位置 | **请求体** `GuidIdDto` |
| 权限点 | `Admin.BreakBulk.Edit`（不是 Delete）+ 每个所属件杂货编辑口径的数据权限与表级权限 |
| 返回 | `result` 为 `true` |

### 3.6.2 输入参数

| 参数 | 类型   | 必填   | 说明                                                |

**删除范围**：分单提单及其历史、签入扫描件、超期证明附件、签出审核任务与工作流实例，然后软删分单。查不到的 id 静默忽略，只要有一条存在就继续。

# 4. 与提单、打印的联动（前端需知）

| 事件 | 提单的变化 |
| :-- | :-- |
| 新增 / 复制分单 | 建一张分单提单：签单方式为正本 → 待签入，其余 → 已签入 |
| 编辑分单改签单方式 | 按新签单方式纠正该分单提单（见 3.4.2） |
| 删除分单 | 分单提单连带删除；提单在签出审核中/已签出/已扣单时拒绝删除 |
| 提单模块换签 / 签出 | 会把签单方式回填到分单（签出时连所属件杂货一起写） |
| 删除整票件杂货 | 全部分单与分单提单一起删除 |

打印件杂货分单用 `PrintFormatAdmin/GetPrintAsync`，`printJsonType = 7500`，`detailInput.id` 传分单 id，权限 `Admin.BreakBulk.Get`；文件名占位符支持「主提单号」（取所属件杂货的）与「分提单号」。详见 `文档/打印/打印模板/打印模板接口文档.md`。

# 5. 常见对接坑位

1. **没有独立权限点**：查看用 `Admin.BreakBulk.Get`，增、改、复制、删除都用 `Admin.BreakBulk.Edit`。
2. **结算对象、签单方式都必填**；应结日期只读，不要往入参里塞。
3. **编辑是整单覆盖**，没传的字段会被清空；所属件杂货不能改。
4. **件杂货改了开船日期，已有分单的应结日期不会跟着变**，要换结算对象保存才会重算。
5. **复制后分提单号为空**，要提醒用户补填。
6. **删除支持批量 `ids`**，参数在请求体。
7. **外键报错带 id**（「签单方式ID:{id}不存在」），与件杂货主表写法不同。
8. **分单没有箱型箱量**，也不做字段屏蔽。
9. **结算对象对象里只有 `id`/`name`/`code`/`fullName`/`enName`/`taxRate` 有意义**，其余客户属性不填。
