# 件杂货模块接口文档

本文档只讲**怎么调用**件杂货主表 `BreakBulkAdmin` 的接口：地址、HTTP 方法、权限、入参全部字段、出参全部字段、报错文案、报文样例。

- 业务口径（字段含义、校验顺序、计算规则、联动）见同目录《件杂货模块总逻辑文档》，本文只在需要时标注「见逻辑文档 x.x」。
- 件杂货分单的 6 个接口见同目录《件杂货分单接口文档》。
- 飞驼运踪对象 `feituoTracking` / `feituoTrackingDetail` 的字段见 `文档/外部Api对接/飞驼/飞驼对接-件杂货货物跟踪-前端对接.md` 第 5、6 章，本文不重抄。

# 1. 对接总纲

## 1.1 服务地址与鉴权

| 项         | 值                                                      |
| :--------- | :------------------------------------------------------ |
| 接口基址   | `{host}/api/services/app/BreakBulkAdmin/`               |
| 完整路径   | 基址 + 方法名，**方法名保留 `Async` 后缀**              |
| 鉴权头     | `Authorization: Bearer {accessToken}`                   |
| 租户头     | `Abp.TenantId: {租户id}`（租户账号登录时带）            |
| 请求体类型 | `Content-Type: application/json`（POST / PUT / DELETE） |

全部接口都要求已登录，并要求各自的功能权限点（见 1.7）。

## 1.2 接口一览

| # | 业务动作 | HTTP | 完整路径 | 参数位置 | `result` 类型 | 权限 |
| :-- | :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | 列表 | GET | `/api/services/app/BreakBulkAdmin/GetPagedListAsync` | QueryString | 分页对象 | `Admin.BreakBulk.Get` |
| 2 | 分组统计 | GET | `/api/services/app/BreakBulkAdmin/GetGroupedListAsync` | QueryString | 数组 | `Admin.BreakBulk.Get` |
| 3 | 详情 | GET | `/api/services/app/BreakBulkAdmin/DetailAsync` | QueryString | 对象 | `Admin.BreakBulk.Get` |
| 4 | 新增 | POST | `/api/services/app/BreakBulkAdmin/AddAsync` | 请求体 | `string`（新票 Guid） | `Admin.BreakBulk.Add` |
| 5 | 复制 | POST | `/api/services/app/BreakBulkAdmin/CopyAsync` | 请求体 | `string`（新票 Guid） | `Admin.BreakBulk.Add` |
| 6 | 删除 | DELETE | `/api/services/app/BreakBulkAdmin/DeleteAsync` | **请求体** | `bool` | `Admin.BreakBulk.Delete` |
| 7 | 更新委托编号 | PUT | `/api/services/app/BreakBulkAdmin/UpdateCommissionNumAsync` | 请求体 | `string`（新编号） | `Admin.BreakBulk.Edit` |
| 8 | 编辑 | PUT | `/api/services/app/BreakBulkAdmin/EditAsync` | 请求体 | `bool` | `Admin.BreakBulk.Edit` |
| 9 | 批量编辑 | PUT | `/api/services/app/BreakBulkAdmin/BatchEditAsync` | 请求体 | `int`（实际处理的票数） | `Admin.BreakBulk.Edit` |
| 10 | 获取附件 | GET | `/api/services/app/BreakBulkAdmin/GetAttachmentsAsync` | QueryString | 数组 | `Admin.BreakBulk.Get` |
| 11 | 添加附件 | POST | `/api/services/app/BreakBulkAdmin/AddAttachmentsAsync` | 请求体 | `bool` | `Admin.BreakBulk.Edit` |
| 12 | 删除附件 | DELETE | `/api/services/app/BreakBulkAdmin/DeleteAttachmentsAsync` | **请求体** | `bool` | `Admin.BreakBulk.Edit` |

> [!WARNING] **两个 DELETE 接口的参数在请求体里。** `axios` 必须写成 `axios.delete(url, { data: payload })`，写成 `axios.delete(url, payload)` 后端会收到空入参。

## 1.3 响应包装与状态码

所有接口（含报错）都返回 ABP 信封，业务数据在 `result` 里：

```json
{
  "result": {},
  "targetUrl": null,
  "success": true,
  "error": null,
  "unAuthorizedRequest": false,
  "__abp": true
}
```

失败时 `success = false`，`error.message` 就是本文各「报错文案」表里的原文。

| 状态码 | 场景 |
| :-- | :-- |
| 200 | 成功 |
| **500** | **业务校验失败**（本文所有业务报错都走这里） |
| 401 / 403 | 未登录 / 缺少功能权限点，`unAuthorizedRequest = true` |
| 400 | 模型绑定或特性校验不通过（`PageIndex`/`PageSize` 越界、关联人员的用户属性不是单个值、关联人员备注超 1024 等），`error.validationErrors` 里是具体字段 |

判成功只看 `success`，不要按状态码判。看到不在本文清单里的报错文案，就是系统异常。

## 1.4 JSON 字段命名

出参统一 camelCase；入参 JSON 与 QueryString 都不区分大小写。本文参数表写 C# 属性名（PascalCase），样例写实际 key。几个容易写错的：

| 属性名 | 出参 key | 说明 |
| :-- | :-- | :-- |
| `POLId` / `POL` / `POLRemark` | `polId` / `pol` / `polRemark` | 开头连续大写整体转小写 |
| `PODId` / `POD` / `PODRemark` | `podId` / `pod` / `podRemark` | 同上 |
| **`POT1Id` / `POT1` / `POT1Remark`** | **`poT1Id` / `poT1` / `poT1Remark`** | 大写后面紧跟数字时 `T` 保持大写，**不是 `pot1Id`** |
| **`POT2Id` / `POT2` / `POT2Remark`** | **`poT2Id` / `poT2` / `poT2Remark`** | 同上 |
| `ETD` / `ATD` / `ETA` | `etd` / `atd` / `eta` |  |
| `ETDStart` / `ETAEnd` | `etdStart` / `etaEnd` |  |
| `POLIdEmpty` / `PODIdEmpty` | `polIdEmpty` / `podIdEmpty` |  |
| `PKGS` / `UpperPKGS` / `TEU` | `pkgs` / `upperPKGS` / `teu` |  |
| `HSCode` | `hsCode` |  |
| `RMBBank` / `USDBank` | `rmbBank` / `usdBank` |  |

## 1.5 数据类型

| 类型 | 写法 | 说明 |
| :-- | :-- | :-- |
| `Guid` | `"3f2504e0-4f89-11d3-9a0c-0305e82c3301"` | 全零 Guid 等价于没传 |
| `long` / `int` | `123` |  |
| `decimal` | `12.3456` | 业务主表毛重/体积入参自动四舍五入到 **4 位小数** |
| `DateTime` | `"2026-09-27"` 或 `"2026-09-27T10:00:00"` | 不带时区；开船、实际开船、预抵日期保存时截成日期；货好时间、截港日期、签单日期原样保存 |
| `enum` | 数字 | 不接受也不返回枚举名 |

入参字符串会被自动去首尾空格，长度按去空格后计算。

## 1.6 字段屏蔽会让 key 消失

被屏蔽的字段在 JSON 里**整个不出现**，不是 `null`。前端读取要同时兜住「key 不存在」和「值为 null」。按下表分层、各层独立配置：

| 层级 | 模块标识 | 作用范围 |
| :-- | :-- | :-- |
| 件杂货层 | `BreakBulk = 12` | 响应顶层（件杂货）的字段 |
| 业务主表层 | `TransportOrder = 2` | `transportOrder` 对象内部的字段 |
| 费用层 | `OrderFee = 1` | `transportOrder.orderFees[]` 内的字段，沿用业务费用模块的规则 |

编辑接口会用库里原值回填件杂货层与业务主表层被屏蔽的字段，批量编辑会忽略被屏蔽字段（见逻辑文档 2.1.4）。

## 1.7 权限点与接口

| 权限标识 | 控制的接口 |
| :-- | :-- |
| `Admin.BreakBulk` | 菜单可见，不直接控制接口 |
| `Admin.BreakBulk.Add` | `AddAsync`、`CopyAsync` |
| `Admin.BreakBulk.Get` | `GetPagedListAsync`、`GetGroupedListAsync`、`DetailAsync`、`GetAttachmentsAsync`；另控制件杂货分单的列表/详情、件杂货打印 |
| `Admin.BreakBulk.Edit` | `EditAsync`、`BatchEditAsync`、`UpdateCommissionNumAsync`、`AddAttachmentsAsync`、`DeleteAttachmentsAsync`；另控制件杂货分单的新增/编辑/复制/删除 |
| `Admin.BreakBulk.Delete` | `DeleteAsync` |

按 Id 操作的接口还要过数据权限与表级权限，挡掉时报「没有这条数据的数据权限,不能{动作}」/「没有这条数据的表级权限,不能{动作}」（口径见逻辑文档 2.1.2）。

## 1.8 分页与排序

| 参数 | 类型 | 默认 | 范围 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| PageIndex | int | 1 | 1 ~ 2147483647 | 页码，越界 HTTP 400 |
| PageSize | int | 10 | 1 ~ 100000 | 每页条数，越界 HTTP 400 |
| Sorting | string | `CreationTime DESC` | - | 逗号分隔多字段，每段可跟 `ASC`/`DESC`；支持多级导航路径；排序根对象是**件杂货层**，业务主表字段写 `TransportOrder.XXX`；字段名用 PascalCase |

示例：`CreationTime DESC`、`TransportOrder.ETD DESC, CreationTime DESC`、`Vessel ASC`、`TransportOrder.Client.Name ASC`。字段名写错时返回 HTTP 500 与解析异常原文，前端应固定使用列头白名单。

**分页返回结构**：

| 字段           | 类型 | 说明                                   |
| :------------- | :--- | :------------------------------------- |
| Items          | 数组 | 当前页数据，无数据时 `[]`              |
| TotalCount     | int  | 总条数（**已叠加数据权限与表级权限**） |
| SkipCount      | int  | (PageIndex − 1) × PageSize             |
| MaxResultCount | int  | = PageSize                             |
| CurrentPage    | int  | 当前页                                 |
| TotalPages     | int  | 总页数                                 |

## 1.9 筛选语义

| 方式     | 行为                                                        |
| :------- | :---------------------------------------------------------- |
| 模糊     | `LIKE '%值%'`，不区分大小写；该字段为 null 的行**不会**命中 |
| 精确     | `=`                                                         |
| 区间     | 闭区间，两端可只传一端                                      |
| 空白入参 | `null`、`""`、全空白一律视为不筛                            |
| 多个条件 | 一律 AND；只有 `Keyword`、`Keys` 内部多字段之间是 OR        |

「未填写」开关与指定值同时传有效值时直接报错，见 4.1 列表的报错文案。开关传 `false` 或不传等于不筛。

## 3.11 附件输出 `AttachmentGroupDto`

| 字段                | 类型  | 说明                                         |
| :------------------ | :---- | :------------------------------------------- |
| AttachmentDtlTypeId | long? | 分组的附件明细类型 id                        |

# 6. 常见对接坑位

1. **起运港、签单方式必填**；签单方式决定主单提单是不是正本，改签单方式会自动纠正提单状态。
2. **`POT1Id` 出参 key 是 `poT1Id`**（中转港2 同理），不是 `pot1Id`。
3. **编辑必须原样回传委托编号与是否业务锁定**，传空会覆盖；编辑不收附件，附件走 4.11 / 4.12。
4. **品名、关联人员整表提交**，漏传的行会被删除；关联人员必须恰好 1 个销售。
5. **所属组织必须是销售的直属组织**，换销售要重新选组织。
6. **两个 DELETE 接口参数在请求体**，`axios.delete(url, { data })`。
7. **删除附件传 `attachmentId`**，不是关联记录 `id`。
8. **提单只在列表行上**（`billOfLadings`），详情为 `null`；运踪完整数据只在详情。
9. **件杂货没有集装箱**：`transportOrder.orderCtns`、`totalCtn` 恒为 `null`，`teu` 恒为 0，界面不要展示。
10. **发票号、危险品、冻柜、货物类型不要展示也不要传**。
11. **开船、实际开船、预抵日期会被截成日期**；货好时间、截港日期、签单日期原样保存，区间筛选止端要补到当天最后一刻。
12. **「未填写」开关与指定值互斥**，同时传直接报错；模糊搜索搜不到空值。
13. **批量编辑只传要改的字段**；港口备注要和港口 id 一起传，否则不生效；报错文案里是「付款方式」「付款地点」。
14. **字段屏蔽会让 key 整个消失**，读取要兜住 key 不存在。
15. **业务错误是 HTTP 500**，按 `success` 判。
16. **飞驼订阅只认主提单号**，改了主提单号要重新订阅；订阅会消耗调用次数。
17. **件杂货不返回 `feituoTrackingWarnings`**。
18. **编号规则 `BreakBulk.CommissionNum` 没配**时，不填编号的新增、复制、更新委托编号都会失败。
