# 1. 业务背景说明 (Background)

## 1.1 白话解释

件杂货（BreakBulk）是**不装集装箱**、按件按票走件杂货船、散杂货船或滚装船（RORO）的海运货物，例如钢材、设备、车辆。系统里它是一种独立的业务类型 `BizType.BreakBulk = 3`，**不分进出口**。

一票件杂货 = 一条业务主表记录 + 一条件杂货扩展记录 + 若干品名、关联人员、费用 + 若干件杂货分单 + 一张主单提单（每条分单再各带一张提单）。

## 1.2 表结构

- **业务主表 `App_TransportOrders`**：各业务类型共用，存委托单位、收发通、货物、日期、费用锁定等通用信息，件杂货固定 `BizType = 3`。
- **件杂货扩展表 `App_BreakBulks`**：只存件杂货独有信息，**与业务主表共用主键**（`App_BreakBulks.Id == App_TransportOrders.Id`，一对一）。写入次序固定：先插业务主表拿 Id，再用同一个 Id 插扩展表。
- **件杂货分单表 `App_BreakBulkSeparates`**：挂在件杂货上（外键 `BreakBulkId`），一票可以有多条。字段与海运出口分单一致，但**没有箱型箱量子表**。

同一票的字段分散在两层：界面上并排的两个输入框可能一个属于扩展表、一个属于业务主表。第 4 章逐层标注。

## 1.3 挂载关系

```
App_TransportOrders (Id，BizType=3)
├── App_BreakBulks                      (Id 相同，一对一，件杂货扩展表)
│   └── App_BreakBulkSeparates          (BreakBulkId，一对多，件杂货分单)
├── App_OrderCodeGoodss                 (TransportOrderId，品名)
├── App_OrderUsers                      (TransportOrderId，业务关联人员/干系人)
├── App_ChangeOrders                    (TransportOrderId，更改单)
├── App_OrderFees                       (TransportOrderId，费用)
├── App_TransportOrderQuestions         (TransportOrderId，业务问题)
├── App_BillOfLadings                   (SeaExportId = 业务id；主单提单 1 张，每条分单再 1 张)
│   └── App_BillOfLadingHistories       (提单操作历史)
└── App_FeituoBreakBulkSubscriptions    (BreakBulkId = 件杂货id，飞驼货物跟踪订阅，一票一条)
    └── App_FeituoBreakBulkTrackings    (跟踪快照) + 发生地/路径/集装箱/集装箱物流节点/船舶 子表
```

附件不是子表，走通用附件模块：模块编码 `160150`，归属键是件杂货 Id 字符串。

**业务主表那一层的集装箱表 `App_OrderCtns` 件杂货完全不用**：新增时丢弃入参里的箱子，列表/详情里箱型箱量恒为空、TEU 恒为 0。

## 1.4 与海运出口的差异

件杂货的字段在海运出口的基础上删减，再加一个地面代理：

| 类别 | 内容 |
| :-- | :-- |
| **没有的字段** | 装运方式（BLType）、订单类型（BillType）、船公司（Carrier）、场站（Yard）及场站邮箱/联系人/电话/手机、截单日期、截VGM、截舱单（截关）日期 |
| **业务主表上不用的字段** | 发票号 `InvoiceNum`、危险品 `Dg*`、冻柜 `Reefer*`：新增时丢弃、编辑时不改、复制时发票号清空；货物类型 `CargoId` 固定普通货 `0`（S） |
| **没有的子功能** | 集装箱（OrderCtn）、服务项目与服务项任务、派车、监装工单、自动费用模板 |
| **新增的字段** | 地面代理 `GroundAgentId`（往来单位）。后端只校验往来单位存在，**不校验行业类别**；下拉只列行业类别含「地面代理」（`w`）的单位由前端过滤 |
| **变成必填的字段** | 起运港 `POLId`、签单方式 `CodeIssueTypeId`（签单方式决定提单是不是正本、要不要签入） |
| **保留的海运字段** | 船名、船公司航次、码头航次、提单份数、副本份数、截港日期、签单日期、签单地点、付费地点、收货地/起运港/中转港1/中转港2/目的港/交货地及备注、订舱代理及联系人、船代、目的港代理、第二通知人 |

## 1.5 本期范围

**本期要做**：件杂货的新增、编辑、批量编辑、详情、列表、分组统计、复制、删除、更新委托编号、附件查/增/删；件杂货分单的新增、编辑、复制、删除、列表、详情；主单与分单提单随建随删；飞驼散货/RORO 运踪（订阅、推送、列表摘要、详情完整数据）；打印（件杂货详情、件杂货分单详情）；单证识别生成新建入参；业务联系单、提单、业务费用、客户对账、付费申请、开票申请、提成单、报表、业务表、基础资料删除校验、客户供应商统计等上下游接入（见 2.17）。

**本期没做**：

- 按船名航次自动带出开船/截港等日期（海运出口有，件杂货没有）；
- 费用单位「运费吨」：按单位算数量时只认票、毛重、尺码、件数、TEU、箱型名，件杂货常用的运费吨还不支持；
- 客户 Excel 导入不映射地面代理：导入模板的行业类别列没有「地面代理」，导入的客户不会带 `w`，要在客户资料里手工补；
- 合合（TextIn）识别已弃用，没有接件杂货。

# 2. 功能与操作说明 (Features & Operations)

## 2.1 权限

权限分四层叠加：**能不能用这个功能**（功能权限点）→ **能看到/能改哪些票**（数据权限）→ **表级动态条件**（表级权限）→ **票上能看到哪些字段**（字段屏蔽）。

### 2.1.1 功能权限点

五个权限点均为**租户级**，所有接口还要求已登录。

| 权限标识 | 名称 | 覆盖的操作 |
| :-- | :-- | :-- |
| `Admin.BreakBulk` | 件杂货（父级） | 菜单可见 |
| `Admin.BreakBulk.Add` | 添加 | 新增、复制 |
| `Admin.BreakBulk.Get` | 查看 | 列表、分组统计、详情、获取附件；**件杂货分单的列表、详情**；件杂货详情与件杂货分单详情的打印 |
| `Admin.BreakBulk.Edit` | 编辑 | 编辑、批量编辑、更新委托编号、添加附件、删除附件；**件杂货分单的新增、编辑、复制、删除** |
| `Admin.BreakBulk.Delete` | 删除 | 删除（从业务表删除入口删件杂货票，也走件杂货删除） |

> [!IMPORTANT] **件杂货分单没有独立权限点。** 查看分单用 `Admin.BreakBulk.Get`，分单的增、改、复制、**删除**都用 `Admin.BreakBulk.Edit`（不是 Delete），并且都要过所属件杂货那一票的数据权限与表级权限。

### 2.1.2 数据权限（行级）

列表、分组统计、详情上一票/下一票在功能权限之外叠加行级数据权限：

1. 解析当前用户在该操作类型下的数据权限配置（用户自己的 + 所有角色的）。命中「全部数据」则不过滤。
2. 否则解析出**可见用户集合**（配置的用户 + 自己）与**可见组织集合**（配置的组织、我的部门、我的公司，各自展开到全部下级）。
3. 一票满足任一条即可见：所属人在可见用户内；创建人在可见用户内；所属组织在可见组织内；业务关联人员里有可见用户且其属性是销售、商务、操作、客服、单证、海外客服、航线之一。

按 Id 操作的接口先过数据权限、再过表级权限，两层都通过才继续。数据权限的操作类型只有「查询」和「编辑」，删除按编辑判：

| 接口 | 口径 | 记录不存在时的提示 |
| :-- | :-- | :-- |
| 详情、获取附件 | 查询 | 「输入件杂货错误」 |
| 复制 | **查询**（复制等于把源票读出来） | 「件杂货不存在」 |
| 编辑、添加附件、删除附件 | 编辑 | 「输入件杂货错误」 |
| 删除 | 编辑 | 「件杂货不存在」 |
| 更新委托编号 | 编辑 | 「件杂货不存在」 |
| 批量编辑 | 编辑 | 不报错，没权限的票直接过滤掉；一票都不剩时报「所选件杂货都没有编辑权限」 |
| 分单列表、分单详情 | 查询（按所属件杂货判） | 「件杂货不存在」 |
| 分单新增、编辑、复制、删除 | 编辑（按所属件杂货判） | 「件杂货不存在」 |

记录在但被挡掉时，提示分两种：「没有这条数据的数据权限,不能{动作}」与「没有这条数据的表级权限,不能{动作}」，动作取查看 / 编辑 / 删除 / 复制。逗号是**半角**。

列表与详情都返回「是否可编辑」`IsEditable`：按编辑口径的数据权限 + 表级权限判定，与编辑接口是同一套代码，前端据此禁用编辑、删除按钮。

### 2.1.3 表级权限

在数据权限之后，再按用户/角色在「表级权限」里给件杂货模块（`FrightModule.BreakBulk = 12`）配置的动态条件过滤一次。列表、分组统计、详情、按 Id 操作都会叠加。

### 2.1.4 字段屏蔽

字段屏蔽的语义是**命中的字段不出现在响应 JSON 里**（不是返回 null）。件杂货的输出按下表分层、各层独立配置：

| 层级 | 模块标识 | 作用范围 |
| :-- | :-- | :-- |
| 件杂货层 | `BreakBulk = 12` | 列表/详情的件杂货层字段（`BreakBulkDto`），以及报表里的件杂货信息（`ReportBreakBulkDto`） |
| 业务主表层 | `TransportOrder = 2` | 列表/详情里 `transportOrder` 对象内部的字段 |
| 费用层 | `OrderFee = 1` | 列表/详情里 `transportOrder.orderFees[]` 的字段，沿用业务费用模块的规则，件杂货不另配 |

输入侧保护：

- **编辑**：先用库里原值回填当前用户被屏蔽的字段（件杂货层按 `BreakBulk`、业务主表层按 `TransportOrder`，条件一律拿库里的旧值求值），再做长度、外键、组织等校验，避免用户因看不到字段而没传、保存时把库里的值抹掉。子表集合（品名、关联人员）类型对不上，不参与回填。
- **批量编辑**：一份输入改多票，不能回填，改为把两层被屏蔽的字段在输入上清空，使其不参与更新。清空发生在「至少输入一个要修改的字段」判断之前，所以只填了被屏蔽字段时会报「请至少输入一个要修改的字段」。

**件杂货分单不做字段屏蔽**。挂在业务表输出上的件杂货简要（`BreakBulkSimpleDto`）、业务联系单里的件杂货运踪对象也不参与屏蔽。

## 2.2 新增

**校验顺序与提示语**（命中即中断，一次只报一条）：

1. 没有输入 →「输入信息不能为空」
2. 没有业务主表信息 →「业务信息不能为空」
3. 关联人员为空 →「业务关联人员不能为空」
4. 销售条数不等于 1 →「销售有且只能有一个」
5. 委托单位不存在（含没选）→「委托单位不存在」；委托单位联系人（可多个）任一个查不到 →「委托单位联系人id错误」，任一个不属于该委托单位 →「委托单位与联系人id不一致」
6. 委托编号 > 32、主提单号 > 64 →「{字段}长度不能超过{N}个字符」
7. 主提单号在当前租户业务表内重复 →「主提单号【{号码}】已存在」（去首尾空格、忽略大小写；空值不校验；已软删除不参与；海运出口、海运进口、空运出口、件杂货互相也不能撞号）
8. 订舱编号、合同号 > 64；内部备注、收货人内容、发货人内容、通知人内容、备注 > 1024 →「{字段}长度不能超过{N}个字符」
9. 包装不存在 →「包装ID:{id}不存在」；业务来源 →「业务来源不存在」；付费方式 →「付费方式不存在」；运输条款 →「运输条款不存在」
10. 车队、报关行、仓库、保险公司、收货人、发货人、通知人 →「{字段}不存在」
11. **起运港没选 →「起运港不能为空」**
12. **签单方式没选 →「签单方式不能为空」**；签单方式不存在 →「签单方式不存在」
13. 第二通知人内容、目的港代理内容 > 1024；船名、航次、码头航次 > 64；目的港/起运港/中转港1/中转港2/收货地/交货地备注 > 128 →「{字段}长度不能超过{N}个字符」
14. 第二通知人、目的港代理、订舱代理不存在 →「{字段}不存在」；订舱代理没选却传了联系人 →「订舱代理未填写时不能选择联系人」，联系人（可多个）任一个查不到 →「订舱代理联系人id错误」，任一个不属于该订舱代理 →「订舱代理与联系人id不一致」
15. 船代、地面代理不存在 →「船代不存在」「地面代理不存在」
16. 付费地点、签单地点、目的港、起运港、中转港1、中转港2、收货地、交货地不存在 →「{字段}不存在」
17. 品名没选 →「商品信息(品名)ID不能为空」；品名不存在 →「商品信息(品名)ID:{id}不存在」
18. 关联人员的用户不存在 →「用户ID:{id}不存在」
19. 销售用户为空 →「销售不能为空」
20. 所属组织校验（见 4.7.5）：没选 →「所属组织不能为空。」；组织不存在 →「所选组织不存在。」；不是销售的直属组织 →「所选组织不在数据所属人(本人)所属组织范围内。」（三句结尾都有句号）

关联人员每条的用户属性只能是一个值，传 0 或多个位组合的值在模型绑定阶段就返回 HTTP 400「用户属性值只能为一个」。

**保存过程**：

1. 开船日期、实际开船日期、预抵日期截成日期部分（货好时间、截港日期、签单日期**不截**，原样保存）。
2. 写业务主表：所属人 = **当票销售**（不是录入人），所属组织 = 顶层 `OrgId`，业务类型强制 3，录入方式 = 手动录入，未完结 = 否；发票号、危险品、冻柜清空，货物类型置普通货，入参里的集装箱丢弃。
3. 会计期间、应结日期、结算方式由后端算（见 4.7.1）。
4. 委托编号：**手填了用手填的**，没填按编号规则 `BreakBulk.CommissionNum` 生成（见 4.7.2）。
5. 品名、关联人员随业务主表一起写入。
6. 用同一个 Id 写件杂货扩展表，所属人同样 = 销售；船名为空白时存 null。
7. 分组附件逐个建关联（附件 id ≤ 0 的项静默跳过）。
8. 按签单方式建**一张主单提单**：签单方式名称恰好是「正本」→ 待签入，其余 → 已签入。

返回新票 Id（与业务主表 Id 相同）。

## 2.3 编辑

**校验顺序**：

1. 「输入信息不能为空」「业务信息不能为空」「业务关联人员不能为空」「销售有且只能有一个」——这 4 条在权限与字段回填之前执行；
2. 数据权限（编辑口径）+ 表级权限：记录不存在 →「输入件杂货错误」，挡掉时报「没有这条数据的数据权限,不能编辑」/「没有这条数据的表级权限,不能编辑」；
3. 业务主表不存在（脏数据）→「对应的业务信息不存在」；
4. 字段屏蔽回填（件杂货层、业务主表层各一次）；
5. 开船/实际开船/预抵日期截日期；
6. 与新增第 5～20 条完全相同的校验（主提单号查重时排除自身）；
7. 提成单守卫（见 4.7.6）。

**保存过程**（局部更新，只改真正变化的列，不调 `UpdateAsync`）：

1. 业务主表逐字段覆盖。所属人随销售变化；**委托编号、是否业务锁定也按入参覆盖**，前端必须原样回传，传空会被清空。发票号、货物类型、危险品、冻柜不从入参取，保持库里的值。
2. 会计期间按新的开船日期重算；变了就把该票**原票费用**（不属于任何更改单的费用）的会计期间一起改掉，更改单费用不动。
3. 应结日期、结算方式重算（口径见 4.7.1）。
4. 品名、关联人员**全量比对**：带主键的行更新，不带主键（或 0）的行新增，库里有但本次没传的行删除。界面必须整表提交。
5. 件杂货扩展表逐字段覆盖，船名空白存 null。**编辑不收附件**，附件走单独的添加/删除接口。
6. 按新的签单方式纠正**主单提单**状态（见 3.1）。分单提单不受主单签单方式影响。

## 2.4 批量编辑

把选中的若干票统一改成输入的值。**只提交要改的字段**：id 为 null、字符串为空白的字段一律保持每票原值。日期、船名、航次只能改成某个值，不能用本接口清空。

**可改字段**：所属组织、委托单位、船代、订舱代理、地面代理、车队、保险公司、仓库、船名、航次（船公司航次）、开船日期、实际开船日期、预抵日期、货好时间、截港日期、签单日期、签单方式、付费方式、付费地点、运输条款、贸易条款、业务来源、收货地/起运港/中转港1/中转港2/目的港/交货地（及备注），以及操作、单证、客服、销售、航线五种干系人。

**校验与处理顺序**：

1. 「输入信息不能为空」；没选票 →「请选择要修改的件杂货」；
2. 字段屏蔽：清空两层被屏蔽字段；
3. 船名、航次 > 64，六个港口备注 > 128 →「{字段}长度不能超过{N}个字符」；
4. 一个字段都没提交 →「请至少输入一个要修改的字段」；
5. 过滤出有编辑权限的票（编辑口径数据权限 + 表级权限），一票不剩 →「所选件杂货都没有编辑权限」；
6. 外键校验（整批只校验一次）：「委托单位不存在」「船代不存在」「订舱代理不存在」「地面代理不存在」「车队不存在」「保险公司不存在」「仓库不存在」「付款地点不存在」「收货地不存在」「起运港不存在」「中转港1不存在」「中转港2不存在」「目的港不存在」「交货地不存在」「签单方式不存在」「付款方式不存在」「运输条款不存在」「业务来源不存在」「用户ID:{id}不存在」。**注意这里是「付款」，新增/编辑是「付费」**；
7. **逐票校验阶段**（全部校验完才开始落库，任何一票失败整批回滚）：
   - 业务主表不存在 →「对应的业务信息不存在」；
   - 改了所属组织或销售时校验组织归属：该票没有销售 →「委托编号[{委托编号}]没有销售，无法校验所属组织」，其余提示同 4.7.5；只改销售而该票本来没填所属组织时不拦；
   - 会计期间、销售、贸易条款、委托单位、起运港、目的港任一变化时跑提成单守卫（见 4.7.6）；
8. **落库阶段**：
   - 换了委托单位 → 该票全部委托单位联系人清空；换了订舱代理 → 该票全部订舱代理联系人清空（分别删业务表子表 `App_OrderClientContacts`、件杂货子表 `App_BreakBulkBookingAgentContacts` 里这票的行）；
   - 港口备注跟着港口 id 走：只有同时传了港口 id 才写备注；传了 id 没带备注时，后端按港口资料生成「港口英文名, 国家英文名」（超过 128 截断）；
   - 会计期间只在开船日期**真的变了**时重算，变了连带改原票费用的会计期间；
   - 开船日期、委托单位、业务来源、所属组织任一变化时，重算应结日期与结算方式（没有开船日期时以创建时间为基准）；
   - 干系人按属性逐个换人：该属性没人就新增一条；有多条时第一条改成新用户、其余删除；输入里没提到的属性一概不动。换了销售，所属人跟着变；
   - 传了签单方式 → 按新签单方式纠正主单提单状态。

返回**实际处理的票数**（有编辑权限的票数）。

## 2.6 列表

**过滤链**：按筛选条件过滤 → 数据权限（查询口径）→ 表级权限 → 排序 → 统计总数 → 取当前页。总条数是已过权限的条数。

**关键字** `Keyword` 模糊匹配 7 个字段（或）：船名、航次、业务外部备注、主提单号、订舱编号、合同号、委托编号。`Keys` 是同一组 7 个字段的**精确**匹配（去空白、去重，命中任意一个即可）。码头航次、发票号不在关键字范围内。

**筛选维度**（多个条件之间是「并且」；模糊匹配搜不到空值行；区间两端闭区间，可只填一端）：

| 分组 | 可筛内容 |
| :-- | :-- |
| 组织 | 所属组织，自动包含全部下级 |
| 件杂货层 | 第二通知人、第二通知人内容（模糊）、目的港代理、目的港代理内容（模糊）、订舱代理、船代、地面代理（带「未填写」开关）、签单方式（带开关）、船名（模糊，带开关）、航次（模糊）、码头航次（模糊）、提单份数、副本份数、截港日期区间、签单日期区间、付费地点、签单地点、目的港（带开关）及备注（模糊）、起运港（带开关）及备注（模糊）、中转港1/中转港2/收货地/交货地及各自备注（模糊）、创建时间区间 |
| 业务主表层 | 委托编号（模糊）、会计期间区间、应结日期区间、结算方式、业务来源、是否业务锁定、主提单号/订舱编号/合同号（模糊）、付费方式（带开关）、运输条款、贸易条款、内部备注/唛头/货物描述（模糊）、包装、委托单位、车队、报关行、仓库、保险公司、收发通及其内容（模糊）、货好时间区间、开船日期区间、实际开船日期区间、预抵日期区间、是否费用锁定 |
| 关联人员 | 销售（带开关）、操作（带开关）、单证、商务、客服 |

**「未填写」开关**：起运港、目的港、付费方式、签单方式、销售、操作、地面代理、船名这 8 项同时提供「指定值」与「未填写」。两者同时用直接报错，且在所有筛选之前执行：

| 字段 | 冲突提示 |
| :-- | :-- |
| 起运港 / 目的港 / 付费方式 / 签单方式 / 销售 / 操作 | 「{字段}筛选：未填写与指定id不可同时传入」 |
| 地面代理 | 「地面代理筛选：未填写与指定id不可同时传入」 |
| 船名 | 「船名筛选：未填写与指定船名不可同时传入」 |

开关传 false 或不传等于不筛，不会反向筛出「已填写」。销售/操作的「未填写」判的是「没有该属性且用户 id > 0 的干系人」。

**每行内容**：与详情基本一致（含完整费用、品名、关联人员、费用状态汇总、运踪摘要、是否可编辑），差异如下：

| 值  | 维度     | 分组依据          | 显示名                             |
| :-- | :------- | :---------------- | :--------------------------------- |
| 3   | 委托单位 | 业务主表 委托单位 | 往来单位简称                       |
| 5   | 起运港   | 件杂货 起运港     | 港口英文名（`PortName`）           |
| 6   | 目的港   | 件杂货 目的港     | 港口英文名                         |
| 7   | 船名     | 件杂货 船名       | 船名本身（分组 id 也是船名字符串） |
| 8   | 付费方式 | 业务主表 付费方式 | 付费方式中文名                     |
| 9   | 签单方式 | 件杂货 签单方式   | 签单方式名称                       |
| 19  | 销售     | 关联人员 销售     | 用户昵称                           |
| 20  | 操作     | 关联人员 操作     | 用户昵称                           |

## 2.8 复制

以现有票为模板开新票，可选是否连费用一起复制。

**校验**：「输入信息不能为空」→ 源票的查询口径数据权限与表级权限（不存在 →「件杂货不存在」，挡掉 →「没有这条数据的数据权限,不能复制」/「没有这条数据的表级权限,不能复制」）→ 源票业务主表不存在 →「业务信息不存在」→ 源票关联人员为空 →「业务关联人员不能为空」→ 源票销售不是恰好 1 个 →「销售有且只能有一个」→ 编号规则问题（见 4.7.2）。

| 处理 | 字段 |
| :-- | :-- |
| 重新生成 | 委托编号（一律按规则生成，不沿用） |
| 重新计算 | 会计期间、应结日期、结算方式（基准是源票的开船日期） |
| 清空 | 主提单号、订舱编号、合同号、发票号 |
| 重置 | 业务锁定 = 否、未完结 = 否、费用锁定 = 否及四个锁定人/时间 = 空、录入方式 = 复制、**所属人 = 当前登录人**（不是销售）、租户 = 当前租户 |
| 原样复制 | 两层其余字段，含签单方式、地面代理、各港口及备注、船名航次、各日期、所属组织 |
| 连子表复制 | 品名、关联人员（主键重新生成） |
| 不复制 | 附件、更改单、**件杂货分单**、业务问题、飞驼订阅 |
| 新建 | 按新票签单方式建一张主单提单 |

**费用复制**（勾选时）：只复制源票的**原票费用**（更改单费用不复制），每条重置为：费用状态录入、结算状态未结算、开票状态未开票、录入方式「业务复制」、已结算金额 0、费用模板项为空、会计期间取新票的；其余（收付、费用代码、行业类别、结算对象、币别、汇率、单价、金额、单位、数量、税率、禁开发票、机密、排序号、备注）沿用。

复制**不做组织归属校验**，所属组织沿用源票。复制别人的票后，新票所属人是自己、所属组织还是源票的，下次编辑可能撞上组织归属校验，需要先改所属组织；编辑保存后所属人会改回当票销售。

## 2.9 删除

**校验**：

1. 「输入不能为空」；
2. 编辑口径数据权限 + 表级权限：不存在 →「件杂货不存在」，挡掉 →「没有这条数据的数据权限,不能删除」/「没有这条数据的表级权限,不能删除」；
3. 该票还有任意一条未删除费用（含更改单费用）→「当前票包含未删除费用，请先删除费用」；
4. 提成单守卫：被操作提成算过 →「已提交操作提成不可删除」；主单或任一更改单被销售提成算过 →「已提交销售提成不可删除」；
5. 提单守卫：主单及其全部分单的提单，只要有一张处于签出审核中、已签出、已扣单 →「提单处于{状态}状态,禁止删除」。

**删除范围**（主表软删除不级联，后端逐项显式删）：

1. 费用相关的审核任务：提交费用、修改费用、删除费用三类任务及其明细，以及挂在上面的工作流实例；
2. 更改单、品名、关联人员；
3. 集装箱（件杂货不用，防御性清理残留）；
4. **件杂货分单**（软删）；
5. 业务问题及其附件关联；
6. 本票附件关联（只解除关联，不删文件）；
7. **全部提单**（主单与各分单的提单）及其历史、签入扫描件、超期证明附件、签出审核任务与工作流实例；
8. 飞驼货物跟踪：订阅记录软删（之后的推送就认领不到这票）；跟踪快照主表及发生地、路径、集装箱、集装箱物流节点、船舶子表硬删；
9. 最后软删件杂货扩展表与业务主表。

从业务表的删除入口删件杂货票时，只要存在件杂货扩展记录，就整体交给件杂货删除，走上面同一套校验与清理。

## 2.10 更新委托编号

按最新编号规则给某一票重新取号，用户不能指定编号内容。校验：「输入不能为空」→ 编辑口径权限（不存在 →「件杂货不存在」）→ 业务主表不存在 →「对应的业务信息不存在」→ 编号规则问题（见 4.7.2）。生成后立即落库并返回新编号，原编号不保留。

## 2.11 附件

- **获取**：查询口径权限，不存在 →「输入件杂货错误」。按附件明细类型分组返回，组之间按类型排序号升序（无类型的排最后），组内按顺序号升序；上传人返回昵称。
- **添加**：编辑口径权限。追加不覆盖；附件 id ≤ 0 的项静默跳过；集合为空也成功。
- **删除**：编辑口径权限；没传附件 id →「附件Id集合不能为空」。只解除本票与这些附件的关联，不删文件、不影响其它票。传的是附件 id，不是关联记录 id。

新增接口可以随单提交分组附件；**编辑接口不收附件**，编辑页的附件增删只能走这两个接口。

## 2.12 件杂货分单

分单挂在件杂货下面，不单独成票，没有委托编号、所属组织、所属人。字段与海运出口分单一致但**没有箱型箱量**。

| 操作 | 规则 |
| :-- | :-- |
| 新增 | 件杂货 id 必填（「件杂货id不能为空」）；先过所属件杂货的编辑口径权限，再校验字段（见 4.3）；**结算对象、签单方式必填**；应结日期按结算对象的账期算；建一张分单提单 |
| 编辑 | 所属件杂货不能改；结算对象变了（或存量应结日期是默认值）才重算应结日期；按新签单方式纠正**该分单**的提单状态 |
| 复制 | 在同一票件杂货下再插一条：全部字段照搬，**分提单号置空**，应结日期按当前账期重算，新分单自带一张提单 |
| 删除 | 可传单个 `id` 或批量 `ids`；一个都查不到 →「分单记录不存在」；按每个所属件杂货校验编辑口径权限（动作名「删除」）；分单提单处于签出审核中/已签出/已扣单 →「提单处于{状态}状态,禁止删除」；连带删分单提单及其历史、附件、审核任务与工作流实例，再软删分单 |
| 列表 | 件杂货 id 必填；只返回这一票下的分单；关键字模糊匹配分提单号、唛头、货物描述、备注；支持分页排序 |
| 详情 | 按分单 id 取；`isPrint=true` 时带所属公司打印信息（分单没有组织，取所属件杂货的所属组织） |

分单的应结日期：与主单同一套账期算法，只把客户换成分单结算对象；业务类型、销售、组织、业务来源和计算基准日（开船日期，空则当前时间）都取所属件杂货的；账期取数异常时兜底为基准日当天。**件杂货改了开船日期，已有分单的应结日期不会自动跟着变**，要换结算对象保存才会重算。

## 2.13 提单联动

- 件杂货主单与每条件杂货分单各对应一张提单，**随建随删，不提供手工新增与删除**。
- 提单表的业务列 `SeaExportId`（列名沿用历史）现在指向业务主表，海运出口与件杂货共用；分单分两列：海出分单 `SeaExportSeparateId`、件杂货分单 `BreakBulkSeparateId`，**两列都为空才是主单提单**。
- 提单本身不存签单方式：正本/电放一律直读件杂货或件杂货分单上的签单方式。提单模块的**换签、签出**会把签单方式回填到件杂货或件杂货分单（签出时分单提单还会连主单一起写），并按新签单方式纠正状态。
- 提单列表/分组的可见范围 = 海运出口与件杂货各自数据权限 + 表级权限的并集；对提单动作按所属业务类型判权限，批量里有没权限的票报「所选提单中有您没有权限{动作}的票」。
- 件杂货没有船公司：提单按船公司筛选时件杂货提单不会命中，按船公司分组时落入未填写组。

## 2.14 飞驼运踪

件杂货走飞驼「散货/RORO 货物跟踪」，订阅、跟踪快照、推送日志都是件杂货自己的表，与海运出口/海运进口的集装箱跟踪互不相干。件杂货业务表本身没有集装箱；飞驼这个接口返回的 `containers[]`（文档里 `containerNo` 标为货物编码，如 `RORO000001`）原样存进跟踪快照的集装箱子表。

| 项 | 口径 |
| :-- | :-- |
| 订阅 | `FeituoAdmin/SubscribeBreakBulkAsync`，权限 `Admin.ExternalApi.Use`，可批量，单条失败不影响其它票 |
| 订阅单号 | **只用主提单号**；未填 → 该条「该件杂货未填写主提单号，无法订阅」；件杂货不存在 → 该条「未找到指定的件杂货」；没传 id → 整批「请至少选择一条件杂货」 |
| 船公司代码 | 固定 `AUTO`（件杂货没有船公司，由飞驼识别） |
| 港口 | 起运港/目的港取港口资料的 EDI 代码，没维护照常订阅 |
| 重复订阅 | 一票只保留一条订阅记录；再调一次就是重新订阅，**会再消耗一次飞驼调用次数** |
| 查询已落库数据 | `FeituoAdmin/GetBreakBulkTrackingAsync`，权限 `Admin.ExternalApi.Get`，入参件杂货 id，读本地最新快照不请求飞驼 |
| 推送 | 飞驼 →中转站 `/relay/feituo/breakbulk-push` →业务端 `/api/feituo/breakbulk-push`，按提单号认领件杂货订阅，同一提单号取最近一次订阅；本地无快照时把推送当全量落库 |
| 推送路由 | 订阅成功后业务端向中转站登记「提单号 → 本机客户标识」，中转站查不到登记时广播给全部下游 |
| 列表/详情字段 | `IsFeituoSubscribed`、`IsFeituoSubscribeSuccess`、`FeituoTracking`（摘要，列表与详情都有）；`FeituoTrackingDetail`（完整数据，仅详情）。散货/RORO 推送不带预警，**没有预警字段** |
| 字段屏蔽 | 跟踪相关表与运踪对象都不接字段屏蔽 |

> [!IMPORTANT] 推送回调地址 `{中转站}/relay/feituo/breakbulk-push` **要另找飞驼客服配置**，与集装箱增量推送不是同一个地址。没配之前件杂货只有订阅时带回的那一份快照。件杂货改了主提单号要重新订阅，否则推送认领不到。

## 2.16 单证识别

`GeminiAdmin/ExtractBreakBulkToAddDtoAsync`：上传单证，返回新建件杂货的入参 `BreakBulkAddDto`。复用海运出口的抽取字段、识别场景与提示词版本，**同一份文件按海运出口识别过再按件杂货识别直接命中缓存，不再调用一次 AI**。

回填的字段：船名、航次、船代、签单方式、签单地点、签单日期、起运港及备注、目的港及备注、交货地；业务主表的主提单号、订舱编号、唛头、货物描述、收发通内容、件数、毛重、体积、货好日期、开船日期、贸易条款、运输条款、包装、委托单位、品名。名称匹配不到的 id 返回空（委托单位匹配不到返回全零 Guid），由前端补录；关联人员返回空列表。船公司、装运方式、服务项目、集装箱即使识别出来也不回填，货物类型由新增接口固定为普通货。

## 2.17 联动与上下游

### 2.17.1 业务联系单

- 业务类型可选件杂货。件杂货联系单新增/编辑时，**装运方式置默认、船公司置空、货物类型置普通货、箱型箱量与服务项目清空**，入参里这些值不参与校验，按默认值/空值落库；起运港必填 →「件杂货业务联系单起运港不能为空」。
- 审核通过生成业务主表（录入方式 = 业务联系单导入，委托编号用 `BreakBulk.CommissionNum`）与件杂货扩展表（带船名、航次、订舱代理、六个港口及备注），并**建主单提单**；联系单附件带到件杂货附件模块 `160150`。
- 联系单上没有签单方式、地面代理、第二通知人等件杂货专属字段，转出来的票这些字段为空，提单按非正本建成**已签入**。操作第一次编辑这票件杂货时**必须补签单方式**（否则「签单方式不能为空」），补成正本时提单会退回待签入。
- 已通过的联系单驳回时，若已生成的件杂货还在 →「请先删除件杂货数据」。
- 联系单列表 `transportOrder.breakBulk` 带件杂货 id、是否已订阅、是否订阅成功、运踪摘要（取数与件杂货列表一致）。
- 同批改动：空运出口联系单的箱型改为非必填（`PreOrderCtn.CtnCodeId` 可空），海运出口/海运进口仍报「箱型ID不能为空」。

### 2.17.2 业务费用

- 费用任务分组与列表：按船名、航次、起运港、目的港、签单方式及其「未填写」筛选时并入件杂货；按起运港、目的港、船名、签单方式分组时件杂货落入对应分组（与海运出口、海运进口同港口表的同一港口合并为一组）。
- 费用批量引入的查询支持业务类型 3，可按起运港、目的港、订舱代理过滤，返回件杂货对象（船名、航次、起运港、目的港、订舱代理、地面代理）；按船公司过滤对件杂货不生效。
- 导入费用（不引入原结算对象时）、收转付/付转收：按费用代码的行业类别取结算对象时，订舱代理、目的港代理取件杂货上的，**地面代理（`w`）取件杂货的地面代理**。

### 2.17.3 自动费用模板

新增、编辑模板时业务类型选件杂货直接拒绝 →「件杂货没有服务项目，不支持自动费用模板」（模板只在完成服务项时触发，件杂货没有服务项目，配了也永远不生效）。

### 2.17.4 客户对账、付费申请、开票申请

- 客户对账、付费申请的费用分组查询：按起运港、目的港筛选时并入件杂货。客户对账分组查询与详情里的业务类型简要统一走业务表简要填充器，件杂货返回件杂货简要。
- 开票申请的费用分组查询：按起运港、目的港、船名、航次筛选时并入件杂货；**按船公司筛选时件杂货整体不参与**。

### 2.17.5 提成单

件杂货的起运港、目的港与海运出口同为海运港，参与「海运起运港/海运目的港」提成条件判断；票面返回件杂货的起运港、目的港；件杂货没有集装箱，箱型箱量恒为空。件杂货编辑时受提成单守卫约束（见 4.7.6）。

### 2.17.6 报表

利润报表、欠费报表纳入件杂货：各业务类型按自己模块的数据权限与表级权限过滤后取并集。**填了船公司、场站或装运方式，或按空运港筛港口时，件杂货整体排除**；可按订舱代理、船名、航次、起运港、目的港过滤。报表行的件杂货信息（`ReportBreakBulkDto`：订舱代理、地面代理、船名、航次、起运港、目的港及备注）字段屏蔽归件杂货模块；箱型箱量恒为空；业务日期取开船日期。

### 2.17.7 业务表

- 业务表输出（`TransportOrderDto`、`TransportOrderSimpleDto`）新增件杂货简要 `BreakBulk`：船名、航次、码头航次、起运港及备注、目的港及备注，仅业务类型为件杂货时有值，由统一的业务类型简要填充器批量填充。
- 业务表详情、费用锁定列表的业务类型简要改走同一个填充器，件杂货票返回件杂货简要。
- 业务表删除：件杂货票整体交给件杂货删除（见 2.9）。

### 2.17.8 基础资料删除校验

被件杂货或件杂货分单引用的基础资料禁止删除，提示「该{资料名}已被【{模块}】模块引用,禁止删除」，多个模块用顿号连接，逗号是半角：

| 基础资料 | 件杂货（模块名「件杂货」） | 件杂货分单（模块名「件杂货分单」） | 提示语里的资料名 |
| :-- | :-- | :-- | :-- |
| 往来单位 | 订舱代理、地面代理、船代、目的港代理、第二通知人 | 结算对象、收货人、发货人、通知人、目的港代理 | 合作客户 |
| 港口 | 起运港、目的港、中转港1、中转港2、收货地、交货地、签单地点、付费地点 | 签单地点、付费地点 | 港口信息 |
| 签单方式 | 签单方式 | 签单方式 | 签单方式 |
| 包装 | —（业务主表的包装由原有「业务委托单」校验覆盖） | 包装 | 包装类型 |
| 付费方式 | —（同上） | 付费方式 | 付费方式 |
| 运输条款 | —（同上） | 运输条款 | 运输条款 |

另外，客户详情的供应商统计（订舱代理的合作起始时间、最后交易时间、年票数）纳入件杂货的订舱代理；件杂货没有集装箱，对「年 TEU」的贡献恒为 0。

# 3. 状态流转说明 (Status Transitions)

件杂货本身没有审批状态机。与它相关的状态变化集中在提单、业务联系单和飞驼订阅上。

## 3.1 提单状态

「正本」按签单方式名称去空格后恰好等于「正本」判定，其余（含没选）都是非正本。

| 当前状态 | 触发人/动作 | 目标状态 | 状态说明 |
| :-- | :-- | :-- | :-- |
| 无提单 | 新增件杂货 / 复制件杂货，签单方式为正本 | 主单提单 待签入 | 同一主单只允许一张提单，重复调用不再新建 |
| 无提单 | 新增件杂货 / 复制件杂货，签单方式非正本 | 主单提单 已签入 | 非正本不需要签入 |
| 无提单 | 业务联系单审核通过生成件杂货 | 主单提单 已签入 | 联系单没有签单方式，按非正本建 |
| 无提单 | 新增/复制件杂货分单 | 分单提单 待签入 或 已签入 | 按分单自己的签单方式判 |
| 待签入 | 编辑（或批量编辑）把签单方式改成非正本 | 已签入 | 电放没有签入这一步，自动放行 |
| 已签入 / 已驳回 | 编辑把签单方式改成正本，且没有有效的人工签入记录 | 待签入 | 签入次数 ≤ 取消签入次数即视为没签入；有真实签入的不退回 |
| 签出审核中 / 可签出 / 已签出 / 已扣单 | 编辑签单方式 | 不变 | 不能冲掉审核与签出结果 |
| 签出审核中 / 已签出 / 已扣单 | 删除件杂货或分单 | 拒绝删除 | 「提单处于{状态}状态,禁止删除」 |
| 任意 | 删除件杂货（或分单）成功 | 提单连带删除 | 连同历史、附件、审核任务、工作流实例 |

主单签单方式只影响主单提单，分单签单方式只影响该分单提单。签入、签出、扣单等其余动作在提单模块，见 `文档/提单/提单模块总逻辑文档.md`。

| :-- | :-- | :-- | :-- |
| 联系单审核中 | 审核通过 | 生成件杂货（录入方式 = 业务联系单导入）+ 主单提单 | 联系单附件带到件杂货 |

| 联系单已通过、件杂货已删 | 驳回 | 联系单驳回 | 断开与业务表的关联 |

## 3.3 飞驼订阅

| 当前状态 | 触发人/动作 | 目标状态 | 状态说明 |
| :-- | :-- | :-- | :-- |
| 未订阅 | 订阅，飞驼返回成功（20000 有数据 / 20001 暂无数据） | 已订阅、订阅成功 | 当场带回的数据落库；登记中转站路由 |

# 4. 核心字段说明 (Field Definitions)

通用约定：两张新表都是**软删除**（`IsDeleted`），查询自动过滤；软删除不级联，子表由后端显式删。入参字符串会被自动去首尾空格，长度按去空格后计算，超长报错不截断。`datetime` 对应 `datetime2`，系统不做时区换算。

## 4.1 件杂货扩展表 `App_BreakBulks`

| 字段名 | 📖 字段含义说明 | 🔌 数据来源 (接口/字典) | 🔗 联动规则 (依赖与触发) | 🛡️ 校验限制 (Validation) |
| :-- | :-- | :-- | :-- | :-- |
| **Id** | 主键，与业务主表共用 | 后端取业务主表 Id | 外键 → `App_TransportOrders.Id`，一对一，不自增 | `Guid` |
| **TenantId** | 租户 | 当前登录租户 | — | `int`，非空 |
| **UserId** | 所属人（数据权限归属人） | 新增/编辑 = 当票销售；复制 = 当前登录人 | 批量编辑换销售时跟着变 | `long`，非空 |
| **OrgId** | 所属组织 | 顶层 `OrgId` | 与业务主表同值 | `long?`；业务上必填，须为销售直属组织 |

## 4.7 计算与派生规则

### 4.7.1 会计期间与应结日期

- **会计期间** = 开船日期所在月 1 号；开船日期为空取当前时间所在月。新增、编辑、复制都重算；批量编辑只在开船日期真的变了时重算。会计期间变化时，该票原票费用的会计期间同步更新，更改单费用不动。
- **应结日期、结算方式**按委托单位的账期规则算：取当前生效的规则（长期有效，或生效/失效时间为空表示该端不限）；按「业务类型含件杂货、销售有交集、组织有交集、业务来源相等」筛出第一条（规则没配的条件视为不限）；没有规则 → 票结，取基准日当天；票结 → 基准日 + 加天数；月结 → 基准日往后 N 个月的第 D 天；约定天数 → 基准日 + 天数。取数异常时保持原值。
- 基准日：新增/编辑/复制取开船日期，空取当前时间；批量编辑取开船日期，空取**创建时间**。
- 现行实现的两个口径（与海运出口、空运出口相同）：**新增时**关联人员还没落库，账期里「销售」条件匹配不到本票销售；**单票编辑时**应结日期在写入新的委托单位、业务来源、关联人员之前计算，所以本次改了委托单位、业务来源或销售，要到下一次保存才按新值算。批量编辑先写入委托单位、业务来源、所属组织再算，这三项没有这个问题；批量换销售不触发重算，账期里的销售条件仍按库里原销售匹配。
- 客户账期规则的「业务类型」要能选到件杂货，否则配了业务类型的规则永远匹配不上件杂货票。

### 4.7.2 委托编号

- 新增：填了用填的（≤ 32），没填按规则生成；复制、更新委托编号、业务联系单转件杂货：一律生成。
- 规则键 **`BreakBulk.CommissionNum`**，与海运出口、海运进口、空运出口各自独立。
- 匹配优先级：绑定当前用户的规则 → 按**业务所属组织**从本级往上逐级找 → 既没绑组织也没绑用户的全局规则。
- 没找到 →「未配置单号生成规则」；规则没有自增项 →「未配置自增编号规则」；取号过程异常 →「生成编号失败: {原因}」。
- 规则里的「开船日期年月」类片段取开船日期，空取当前时间。

### 4.7.3 船名规范化

船名空白一律存 null，保证「未填写」筛选与船名分组不会出现「空」和「空字符串」两种。

### 4.7.4 日期截断

开船日期、实际开船日期、预抵日期保存时只保留日期部分。货好时间、截港日期、签单日期、分单签单日期**原样保存**，界面带了时分秒回看也会带回，区间筛选「止」端建议补到当天最后一刻。

### 4.7.5 组织归属校验

新增、编辑执行，复制不执行。本票销售（有且只有一个）就是「本人」，所选所属组织必须是该销售的**直属组织**（用户与组织的直接绑定，不看父子）；销售挂多个组织时命中任一即可。依次报「所属组织不能为空。」「所选组织不存在。」「所选组织不在数据所属人(本人)所属组织范围内。」。所属组织实际是必填项。

### 4.7.6 提成单守卫

编辑、批量编辑、删除都受约束：

| 情形 | 提示 |
| :-- | :-- |
| 票已被销售提成算过，又改了会计期间 | 「已提交销售提成不可修改会计期间」 |
| 票（或它的任一更改单）已被销售提成算过，又换了销售 | 「已提交销售提成不可修改销售」 |
| 换成的新销售在本票涉及的任一会计期间已有销售提成单 | 「该销售在会计期间【yyyy-MM、…】已存在销售提成单 不可把本业务改到他名下」 |
| 票被操作提成算过，又改了提成单锁定的条件字段（件杂货涉及贸易条款、委托单位、起运港、目的港；货物类型固定普通货不会变） | 「已提交操作提成不可编辑提成相关字段」 |
| 删除时票被操作提成算过 | 「已提交操作提成不可删除」 |
| 删除时主单或更改单被销售提成算过 | 「已提交销售提成不可删除」 |

### 4.7.7 费用状态汇总

- 应付/应收费用状态最小值：该方向全部费用的费用状态取最小值，没有费用时为空。
- 应付/应收组合费用状态：该方向全部费用（含更改单费用）按优先级逐条判断，命中即返回：任一驳回 → 驳回；任一在待审核的修改申请里 → 申请修改；任一在待审核的删除申请里 → 申请删除；任一录入 → 录入；任一提交审核 → 提交审核；全部结算完毕 → 结算完毕；任一不是未结算 → 部分结算；否则 → 审核通过。

### 4.7.8 件数大写

详情里 `件数的英文单词 + 空格 + 包装名` 整体转大写；件数为空时为空；没选包装时末尾会多一个空格。

# 5. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **[卡点 1：编号规则未配置]** 编号规则 `BreakBulk.CommissionNum` 必须预先配置。未配置时新增（不手填编号）报「未配置单号生成规则」，复制、更新委托编号、业务联系单审核通过生成件杂货**无论如何都失败**。它和海运出口、空运出口的键互相独立，**是上线硬前置条件**。

> [!IMPORTANT] **[卡点 2：起运港、签单方式必填]** 新增/编辑不选起运港报「起运港不能为空」，不选签单方式报「签单方式不能为空」。分单的签单方式同样必填。业务联系单转来的件杂货签单方式为空，第一次编辑必须补上。

> [!IMPORTANT] **[卡点 3：销售有且只有一个，所属组织必须是销售直属组织]** 0 个、2 个销售都报「销售有且只能有一个」；父组织不算直属。换销售后要重新选组织。

> [!IMPORTANT] **[卡点 4：签单方式驱动提单状态]** 签单方式名称恰好是「正本」才按正本处理（待签入），其余都按非正本（已签入）。签单方式基础资料里「正本」「电放」的名称要维护准确，否则提单状态全错、换签找不到电放（「请先在签单方式基础资料中维护【电放】,否则无法换签」）。

> [!IMPORTANT] **[卡点 5：有费用、有提成、提单已签出的票删不掉]** 有任意未删除费用 →「当前票包含未删除费用，请先删除费用」；被提成单算过 →「已提交操作提成不可删除」/「已提交销售提成不可删除」；主单或任一分单提单在签出审核中、已签出、已扣单 →「提单处于{状态}状态,禁止删除」。

> [!IMPORTANT] **[卡点 6：编辑是整单覆盖，子表全量比对]** 编辑时件杂货层与业务主表层按入参整单写入（被屏蔽字段除外），委托编号、是否业务锁定也要原样回传；品名、关联人员库里有而本次没传的行会被删掉。

> [!IMPORTANT] **[卡点 7：分单没有独立权限点]** 分单的查看用 `Admin.BreakBulk.Get`，增、改、复制、删除用 `Admin.BreakBulk.Edit`，还要过所属件杂货的数据权限。给角色配权限时别去找「件杂货分单」。

> [!IMPORTANT] **[卡点 8：飞驼推送要另配回调]** 件杂货推送地址 `{中转站}/relay/feituo/breakbulk-push` 要另找飞驼客服配置；中转站要配 `BreakBulkForwardPath`，业务端要配 `Relay:BaseUrl`、`Relay:Customer`、`Relay:Token`（没配客户标识时跳过路由登记，推送走广播）。改了主提单号要重新订阅；每次订阅都消耗调用次数，不要做成自动重试。

> [!IMPORTANT] **[卡点 9：主提单号不能重复]** 当前租户业务表内所有业务类型共用主提单号查重，冲突报「主提单号【{号码}】已存在」；空值不校验，编辑排除自身。

> [!IMPORTANT] **[卡点 10：复制后所属人暂为当前登录人]** 复制出来的票所属人是复制的人、所属组织沿用源票，数据权限按这两项算；下次编辑保存时所属人改回销售，届时可能撞上组织归属校验。

> [!IMPORTANT] **[卡点 11：数据库迁移与权限分配]** 本次涉及十张新表（件杂货 2 张、飞驼件杂货货物跟踪 8 张）和两张表的结构变化（见 7.4），迁移文件由开发自行生成；五个权限点要给角色分配；客户账期规则的业务类型要能选件杂货；地面代理单位要在客户资料里带上行业类别 `w`（Excel 导入不会带）。

**2026-10-03 联系人存量数据迁移**：同次海运出口、空运出口也各新建了自己的订舱代理联系人子表（`App_SeaExportBookingAgentContacts`、`App_AirExportBookingAgentContacts`）并删掉扩展表的 `BookingAgentContactId`。生成的迁移里必须先建四张新表，再执行下面的 SQL，最后才删四个旧列（EF 默认把删列排在建表前，要手动调整顺序，否则旧数据丢失）：

```sql
INSERT INTO App_OrderClientContacts (Id, TransportOrderId, ClientContactId)
SELECT NEWID(), Id, ClientContactId FROM App_TransportOrders WHERE ClientContactId > 0 AND IsDeleted = 0;
INSERT INTO App_SeaExportBookingAgentContacts (Id, SeaExportId, ClientContactId)
SELECT NEWID(), Id, BookingAgentContactId FROM App_SeaExports WHERE BookingAgentContactId > 0 AND IsDeleted = 0;
INSERT INTO App_AirExportBookingAgentContacts (Id, AirExportId, ClientContactId)
SELECT NEWID(), Id, BookingAgentContactId FROM App_AirExports WHERE BookingAgentContactId > 0 AND IsDeleted = 0;
INSERT INTO App_BreakBulkBookingAgentContacts (Id, BreakBulkId, ClientContactId)
SELECT NEWID(), Id, BookingAgentContactId FROM App_BreakBulks WHERE BookingAgentContactId > 0 AND IsDeleted = 0;
```

集装箱跟踪的表不变。上一版曾给 `App_FeituoPushLogs` 加过可空列 `BizType`，已撤回；如果已经按上一版生成并执行过迁移，重新生成迁移时应删除该列。

编号规则 `BreakBulk.CommissionNum`、权限分配、飞驼回调地址属于配置，不是库结构变更，见第 5 章卡点。
