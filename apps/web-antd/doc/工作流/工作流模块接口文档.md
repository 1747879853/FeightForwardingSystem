> 前端专属。只写工作流**配置**与**实例查询**接口：地址、入参全字段、出参全字段。各业务模块自己的提交/审核/撤回接口写在各自模块的接口文档里，本文不重复。审批路径怎么匹配、卡点口径见《工作流模块总逻辑文档.md》。

# 0. 速查

| 接口 | 方法 | 地址 | 权限 |
| :-- | :-- | :-- | :-- |
| 工作流分页列表 | POST | `/api/services/app/WorkFlowAdmin/GetQueryAsync` | `Admin.WorkFlow.Get` |
| 工作流详情 | GET | `/api/services/app/WorkFlowAdmin/GetAsync` | `Admin.WorkFlow.Get` |
| 新增或修改工作流 | POST | `/api/services/app/WorkFlowAdmin/EditAsync` | `Admin.WorkFlow.Edit` |
| 删除工作流 | DELETE | `/api/services/app/WorkFlowAdmin/DeleteAsync` | `Admin.WorkFlow.Delete` |
| 单个任务的审批路径 | GET | `/api/services/app/WorkFlowInstanceAdmin/GetAsync` | 登录即可 |
| 同一业务主键下多条实例 | GET | `/api/services/app/WorkFlowInstanceAdmin/BatchGetAsync` | 登录即可 |

> 地址里的 `Async` 后缀**不能省**，本项目的动态 API 不会剥掉它。分页参数是 `pageIndex` / `pageSize`，不是 `skipCount`。

## 0.1 本次客户接入（配置页必改）

客户建档审核走通用工作流。配置页要补任务类型和连线条件，否则客户侧提交会报「未配置或未启用…工作流」。

| 要改的地方 | 口径 |
| :-- | :-- |
| 任务类型下拉 | 新增 `90` 新建客户审核、`91` 申请修改客户。**两条都要能配、都要能启用**，缺哪条对应操作就会被拦住 |
| 不要配 `92` | 枚举里有「申请删除客户」，客户模块**没有**删除审核接口，配了也不会被调用 |
| 连线条件下拉 | 任务类型是 `90` 或 `91` 时，只出下面四个客户条件（提交与申请修改**共用同一套**） |
| 节点审核人 | 客户工作流只支持**按用户 / 按角色**。配置页应直接隐藏「用户属性」。配了保存能过，但客户提交审核时会报 `客户工作流不支持用户属性审核` |
| 业务侧审核界面 | 客户审核列表/详情/审核按钮走 `ClientAdmin`，见《客户审核接口文档.md》。**不要**拿 `WorkFlowInstanceAdmin/GetAsync` 去拼客户的审批历史 |

**客户可用的进入条件**（`taskTypeCondition`）：

| 值 | 条件 | 可用比较符 `shouldBe` | `value` 填什么 |
| :-- | :-- | :-- | :-- |
| `90001` | 客户所属人 | `8` 等于、`9` 不等于 | 用户 id（long）。取客户建档时写入的 `userId`，不是实际点提交的人 |
| `90002` | 客户归属公司 | `10` 属于、`11` 不属于 | 组织 id（long）。配大组织时覆盖其下属：配青岛分公司，归属青岛业务部的客户也匹配 |
| `90003` | 客户性质 | `8` 等于、`9` 不等于 | `ClientType`：`0` 同行、`1` 直客。客户性质为空时该条件一律判为不满足 |
| `90004` | 共享类型 | `8` 等于、`9` 不等于 | `ClientSharedType`：`0` 不共享、`1` 共享本公司、`2` 共享所有人 |

这四个条件只能配在 `90` / `91` 上，配到别的任务类型会报 `非客户任务不可输入客户条件`。

## 0.2 任务类型 `taskType`

| 值 | 名称 | 说明 |
| :-- | :-- | :-- |
| `0` | 费用提交 | 费用工作流之一 |
| `1` | 费用修改 | 费用申请修改。**费用申请删除与它共用这一条**，不要单独配 `2` |
| `2` | 费用删除 | **禁止新建**。保存时报 `费用申请删除与费用申请修改共用同一条工作流,请配置在费用申请修改下` |
| `3` | 付费申请 | 不支持按用户属性配审核人（配置时就会拦） |
| `8` | 业务联系单 |  |
| `10` | 提成单 |  |
| `11` | 提单签出 | 不支持按用户属性配审核人（提交时拦） |
| `90` | 新建客户审核 | **2026-09-21 新增**。客户「提交审核」走这条 |
| `91` | 申请修改客户 | **2026-09-21 新增**。客户「申请修改」走这条 |
| `92` | 申请删除客户 | 枚举占位，客户模块未接入，配置页不要当作可用项 |

同一 `taskType` **同一时间只能启用一条**工作流，再启用第二条报 `同类型审核不可同时启用多个审核流`。未启用的可以存多条。

## 0.3 节点通过方式 `passMethod`

| 值 | 名称 | 说明 |
| :-- | :-- | :-- |
| `0` | 直接通过 | 该节点不产生审批层级、不需要审核人。保存时后端会把 `auditors` 清空 |
| `1` | 或签 | 本级任意一人同意即可 |
| `2` | 会签 | 本级全部同意才进入下一级 |

客户工作流所有节点都配成「直接通过」时：提交审核当场变已通过、申请修改当场把修改落到客户上，不生成工作流实例。

## 0.4 比较符 `shouldBe`

| 值   | 名称 | 值   | 名称     |
| :--- | :--- | :--- | :------- |
| `0`  | 是   | `1`  | 不是     |
| `2`  | 包含 | `3`  | 不包含   |
| `4`  | 小于 | `5`  | 小于等于 |
| `6`  | 大于 | `7`  | 大于等于 |
| `8`  | 等于 | `9`  | 不等于   |
| `10` | 属于 | `11` | 不属于   |

每种条件只接受上表 0.1 / 3.4 里列出的那几个，多传会报「…条件比较符输入错误」。

## 0.5 工作流实例状态 `status`（实例查询接口用）

| 值  | 名称               |
| :-- | :----------------- |
| `0` | 活动（审批进行中） |
| `1` | 通过               |
| `2` | 拒绝               |

任务状态 `taskStatus`（某一级某个审核人）：`0` 审核中、`1` 驳回、`2` 通过。`null` 代表还没轮到这一级。

# 1. 工作流分页列表

`POST /api/services/app/WorkFlowAdmin/GetQueryAsync`

## 1.1 入参

| 字段        | 类型   | 必填 | 说明                                          |
| :---------- | :----- | :--- | :-------------------------------------------- |
| `pageIndex` | int    | 否   | 页码，默认 `1`                                |
| `pageSize`  | int    | 否   | 每页条数，默认 `10`                           |
| `sorting`   | string | 否   | 默认 `CreationTime DESC`                      |
| `keyword`   | string | 否   | 模糊匹配工作流名称                            |
| `taskType`  | int?   | 否   | 按任务类型筛。客户配置页筛 `90` / `91` 用这个 |

```json
{ "pageIndex": 1, "pageSize": 10, "taskType": 90 }
```

## 1.2 出参

`PagedList<WorkFlowDto>`：外层 `items` / `totalCount` / `skipCount` / `maxResultCount` / `currentPage` / `totalPages`。

### 1.2.1 `items[]` 行

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | Guid | 工作流 id |
| `name` | string | 流程名称 |
| `taskType` | int | 任务类型，见 0.2 |
| `enable` | bool | 是否启用 |
| `creationTime` | DateTime | 创建时间 |
| `creatorUserId` | long? | 创建人 id。**本接口不返回 nickname** |
| `lastModificationTime` | DateTime? | 最后修改时间 |
| `lastModifierUserId` | long? | 最后修改人 id。**本接口不返回 nickname** |

列表没有节点和连线，要画流程图调详情。

## 1.3 报错

| 提示         | 触发      |
| :----------- | :-------- |
| 输入不能为空 | body 为空 |

# 2. 工作流详情

`GET /api/services/app/WorkFlowAdmin/GetAsync?id={guid}`

编辑回填、画流程图都走这个。节点 id、连线条件都会原样返回，保存时前端会**复用节点 id**。

## 2.1 入参

| 字段 | 类型 | 必填 | 说明                |
| :--- | :--- | :--- | :------------------ |
| `id` | Guid | 是   | 工作流 id，放 query |

## 2.2 出参

`WorkFlowDetailDto`

### 2.2.1 根对象

| 字段          | 类型     | 说明               |
| :------------ | :------- | :----------------- |
| `id`          | Guid     | 工作流 id          |
| `name`        | string   | 流程名称           |
| `taskType`    | int      | 任务类型           |
| `enable`      | bool     | 是否启用           |
| `nodes`       | 对象数组 | 审批节点，见 2.2.2 |
| `transitions` | 对象数组 | 流转线，见 2.2.4   |

详情构造时只赋了上面这些字段，不要依赖 `creationTime` / `creatorUserId`。

### 2.2.2 `nodes[]`

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | Guid | 节点 id。保存时请原样带回，不要重新生成，否则旧图对不上 |
| `nodeName` | string | 节点名 |
| `passMethod` | int | 通过方式，见 0.3 |
| `auditors` | 对象数组 | 审核人。`passMethod = 0` 时为空数组 |

### 2.2.3 `nodes[].auditors[]`

| 字段            | 类型   | 说明                                  |
| :-------------- | :----- | :------------------------------------ |
| `id`            | Guid   | 审核人行 id                           |
| `userId`        | long?  | 按用户审核时有值                      |
| `roleId`        | long?  | 按角色审核时有值                      |
| `userAttribute` | long?  | 按用户属性审核。客户 / 付费申请不要用 |
| `showText`      | string | 前端自己存的展示文本，后端原样读写    |

`userId` / `roleId` / `userAttribute` 三选一。

### 2.2.4 `transitions[]`

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | Guid | 连线 id |
| `srcNodeId` | Guid? | 起始节点。**`null` 代表开始线**（工作流从线进、从节点出） |
| `tgtNodeId` | Guid? | 目标节点。`null` 代表结束线 |
| `priority` | int | 优先级，**越大越先匹配** |
| `isDefault` | bool | 是否默认线。同一源节点有多条出线时必须恰好一条默认 |
| `conditions` | 对象数组 | 非默认线的条件。默认线保存时会被清空 |

### 2.2.5 `transitions[].conditions[]`

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | Guid | 条件行 id |
| `isOr` | bool | `true` 或、`false` 且。同一条线上：所有「或」先联合，再和所有「且」求交 |
| `taskTypeCondition` | int | 条件字段，见 0.1 / 3.4 |
| `shouldBe` | int | 比较符，见 0.4 |
| `value` | string | 被比较的原始值（id、枚举数字等） |
| `valueText` | string | 前端展示用文案，后端原样存 |

## 2.3 报错

| 提示         | 触发      |
| :----------- | :-------- |
| id不能为空   | 入参为空  |
| 工作流不存在 | id 对不上 |

# 3. 新增或修改工作流

`POST /api/services/app/WorkFlowAdmin/EditAsync`

有 `id` 是修改（先全量清掉旧节点/旧连线/旧审批人/旧条件，再按本次提交整批插入），没有 `id` 是新建。

## 3.1 入参根对象 `EditWorkFlowDto`

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `id` | Guid? | 改时必填 | 修改时传已有工作流 id |
| `name` | string | 是 | 工作流名称，不能空白 |
| `taskType` | int | 是 | 任务类型，见 0.2。客户提交配 `90`，客户申请修改配 `91` |
| `enable` | bool | 是 | 是否启用。启用时会检查同类型没有另一条已启用的 |
| `nodes` | 数组 | 是 | 至少一个节点，见 3.2 |
| `transitions` | 数组 | 是 | 至少一条线，且必须有一条 `srcNodeId = null` 的开始线 |

```json
{
  "name": "直客新建客户审核",
  "taskType": 90,
  "enable": true,
  "nodes": [
    {
      "id": "11111111-1111-1111-1111-111111111111",
      "nodeName": "商务审核",
      "passMethod": 1,
      "auditors": [
        {
          "userId": 10001,
          "roleId": null,
          "userAttribute": null,
          "showText": "张三"
        }
      ]
    }
  ],
  "transitions": [
    {
      "srcNodeId": null,
      "tgtNodeId": "11111111-1111-1111-1111-111111111111",
      "priority": 10,
      "isDefault": false,
      "conditions": [
        {
          "isOr": false,
          "taskTypeCondition": 90003,
          "shouldBe": 8,
          "value": "1",
          "valueText": "直客"
        }
      ]
    },
    {
      "srcNodeId": null,
      "tgtNodeId": "11111111-1111-1111-1111-111111111111",
      "priority": 0,
      "isDefault": true,
      "conditions": []
    }
  ]
}
```

## 3.2 `nodes[]` `EditWorkFlowNode`

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `id` | Guid | 是 | **前端生成**。修改时请带回详情里的原 id |
| `nodeName` | string | 否 | 节点名 |
| `passMethod` | int | 是 | 见 0.3 |
| `auditors` | 数组 | 或签/会签时必填 | `passMethod = 0` 时后端会清空，不用传 |

## 3.3 `nodes[].auditors[]` `EditWorkFlowNodeAuditor`

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `userId` | long? | 三选一 | 指定用户 |
| `roleId` | long? | 三选一 | 指定角色 |
| `userAttribute` | long? | 三选一 | 用户属性。付费申请配了直接报错；客户配了能保存，提交审核才报错 |
| `showText` | string | 否 | 展示文本，原样存 |

三个都空报 `审批人不能为空`。

## 3.4 连线条件一览（按任务类型）

`passMethod` / 图结构对所有任务类型一样。**条件下拉必须跟着 `taskType` 变**，不要把费用条件和客户条件混在一个列表里。

### 3.4.1 费用提交 `0` / 费用修改 `1`（共用）

| 值 | 条件 | 可用比较符 | `value` |
| :-- | :-- | :-- | :-- |
| `1` | 业务所属人 | 等于 / 不等于 | 用户 id（long） |
| `2` | 业务所属组织 | 属于 / 不属于 | 组织 id（long），自动展开上级 |
| `4` | 收付类型 | 等于 / 不等于 | `PaySide` 枚举值 |
| `5` | 业务类型 | 等于 / 不等于 | `BizType` 枚举值 |
| `6` | 利润 | 小于 / 小于等于 / 大于 / 大于等于 | decimal |
| `7` | 利润率 % | 同上 | 百分比数值，`15` 代表 15% |
| `8` | 存在某个费用名应收 &lt; 应付 | 是 / 不是 | **不用填** |
| `9` | 存在应付费用名但应收没有 | 是 / 不是 | **不用填** |
| `10` | 存在应收费用名但应付没有 | 是 / 不是 | **不用填** |

> 枚举值 `3` 已废弃，不要用。配到非费用任务报 `非费用任务不可输入费用条件`。

### 3.4.2 付费申请 `3`

| 值     | 条件           | 可用比较符    | `value`         |
| :----- | :------------- | :------------ | :-------------- |
| `3001` | 付费申请人     | 等于 / 不等于 | 用户 id（long） |
| `3002` | 付费申请人组织 | 属于 / 不属于 | 组织 id（long） |

### 3.4.3 业务联系单 `8`

| 值     | 条件       | 可用比较符    | `value`         |
| :----- | :--------- | :------------ | :-------------- |
| `8001` | 申请人     | 等于 / 不等于 | 用户 id（long） |
| `8002` | 申请人组织 | 属于 / 不属于 | 组织 id（long） |

### 3.4.4 提成单 `10`

| 值 | 条件 | 可用比较符 | `value` |
| :-- | :-- | :-- | :-- |
| `10001` | 提成人 | 等于 / 不等于 | 用户 id（long） |
| `10002` | 提成人组织 | 属于 / 不属于 | 组织 id（long） |
| `10003` | 最终应发金额 | 小于 / 小于等于 / 大于 / 大于等于 | decimal，允许为负 |

### 3.4.5 提单签出 `11`

| 值      | 条件       | 可用比较符    | `value`             |
| :------ | :--------- | :------------ | :------------------ |
| `11001` | 委托单位   | 属于 / 不属于 | 委托单位 id（Guid） |
| `11002` | 提交人组织 | 属于 / 不属于 | 组织 id（long）     |
| `11003` | 是否超期   | 是 / 不是     | **不用填**          |

### 3.4.6 新建客户审核 `90` / 申请修改客户 `91`（共用）

见 **0.1**。配置端校验与运行时取值口径一致。

## 3.5 `transitions[]` `EditWorkFlowTransition`

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `srcNodeId` | Guid? | 否 | `null` = 开始线 |
| `tgtNodeId` | Guid? | 否 | `null` = 结束线。两个都空报 `线未关联节点` |
| `priority` | int | 否 | 越大越先匹配 |
| `isDefault` | bool | 是 | `true` 时后端会把 `conditions` 清空 |
| `conditions` | 数组 | 非默认线必填 | 非默认线一条条件都没有报 `非默认分支条件不能为空` |

同一 `srcNodeId`（含开始线的 `null`）下：

- 只有一条出线时，不必是默认；
- **多于一条时必须恰好一条 `isDefault = true`**，否则报 `节点 … 的分支必须有且仅有一个默认路径`。

## 3.6 `transitions[].conditions[]` `EditWorkFlowTransitionCondition`

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `isOr` | bool | 是 | 或 / 且 |
| `taskTypeCondition` | int | 是 | 必须属于当前 `taskType` 那一组，否则按 3.7 报错 |
| `shouldBe` | int | 是 | 必须是该条件允许的比较符 |
| `value` | string | 视条件 | 存在性（是/不是）类条件不用填；其它必须能解析成对应类型 |
| `valueText` | string | 否 | 展示文案 |

## 3.7 出参

`Guid`，本次保存的工作流 id。

## 3.8 报错

| 提示 | 触发 |
| :-- | :-- |
| 输入不能为空 | body 为空 |
| 工作流名称不能为空 | 名称空白 |
| 费用申请删除与费用申请修改共用同一条工作流,请配置在费用申请修改下 | `taskType = 2` |
| 同类型审核不可同时启用多个审核流 | 启用时已有另一条同类型已启用 |
| 输入节点不能为空 | `nodes` 空 |
| 审批人不能为空 | 或签/会签节点没审核人，或审核人三个字段都空 |
| 付费申请工作流不支持用户属性审核 | 付费申请节点配了 `userAttribute` |
| 输入流转线不能为空 | `transitions` 空 |
| 线未关联节点 | 一条线的源、目标都空 |
| 非默认分支条件不能为空 | 非默认线没有条件 |
| 非客户任务不可输入客户条件 | 客户四个条件配在了非 `90`/`91` 上 |
| 客户所属人条件比较符输入错误 | `90001` 没用等于/不等于 |
| 客户归属公司条件比较符输入错误 | `90002` 没用属于/不属于 |
| 客户性质条件比较符输入错误 | `90003` 没用等于/不等于 |
| 共享类型条件比较符输入错误 | `90004` 没用等于/不等于 |
| 被比较值输入错误 | id / 枚举数字解析失败，或枚举值不在定义里 |
| 未知的条件类型 | `taskTypeCondition` 不在后端认识的范围内 |
| 工作流id错误 | 修改时 id 对不上 |
| 节点ID存在重复 | `nodes` 里有重复 id |
| 连线源节点 … 无效 / 连线目标节点 … 无效 | 线连到了不在 `nodes` 里的 id |
| 工作流必须包含至少一个起始入口（源节点为空的线）。 | 没有开始线 |
| 节点 … 的分支必须有且仅有一个默认路径。 | 同一源节点多条出线但默认线不是恰好一条 |
| 检测到无法逃逸的死循环或无法到达终点的路径。 / 检测到路径配置死循环，请检查跳转规则。 | 图画成了出不去的环 |
| 存在无法到达的孤立节点。 | 有节点从开始线走不到 |

比较符、被比较值在费用 / 付费 / 提单上还有各自文案（如 `利润条件比较符输入错误`），规则同 3.4。

# 4. 删除工作流

`DELETE /api/services/app/WorkFlowAdmin/DeleteAsync`

支持批量。会显式删掉节点、审批人、连线、条件，再软删主表。

## 4.1 入参

| 字段  | 类型   | 必填 | 说明                                        |
| :---- | :----- | :--- | :------------------------------------------ |
| `ids` | Guid[] | 是   | 要删的工作流 id。走 body 的 `GuidIdDto.ids` |

```json
{ "ids": ["3f2a..."] }
```

## 4.2 出参

无。

## 4.3 报错

| 提示         | 触发                   |
| :----------- | :--------------------- |
| id不能为空   | body 为空              |
| 工作流不存在 | `ids` 里一个都匹配不到 |

# 5. 工作流实例（运行时查询）

各业务模块的审核列表已经把审批路径嵌在行里了。这两个接口是通用查询，**客户审核不要用它们拼历史**——客户每轮新建任务，`GetAsync` 按 `taskType + entityId` 取第一条、不按时间排序，多轮之后会拿到任意一轮。客户用 `ClientAdmin/GetAuditDetailAsync`。

## 5.1 单个任务的审批路径

`GET /api/services/app/WorkFlowInstanceAdmin/GetAsync?taskType={int}&entityId={guid}`

### 5.1.1 入参

| 字段       | 类型 | 必填 | 说明                                           |
| :--------- | :--- | :--- | :--------------------------------------------- |
| `taskType` | int  | 是   | 任务类型。客户提交传 `90`，客户申请修改传 `91` |
| `entityId` | Guid | 是   | 业务主键。客户传客户 id                        |

### 5.1.2 出参 `WorkFlowInstanceDetailDto`

| 字段         | 类型     | 说明                   |
| :----------- | :------- | :--------------------- |
| `id`         | Guid     | 实例 id                |
| `status`     | int      | 实例状态，见 0.5       |
| `levelGroup` | 对象数组 | 按审批层级分组，见 5.3 |

## 5.2 同一业务主键下多条实例

`GET /api/services/app/WorkFlowInstanceAdmin/BatchGetAsync?taskType={int}&entityId={guid}`

费用一条业务可能同时挂提交 / 修改 / 删除多条实例时用。

### 5.2.1 入参

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `taskType` | int | 是 | 目前只识别费用：传 `0` 时会把费用提交、费用修改、费用删除三条都查出来 |
| `entityId` | Guid | 是 | 业务主键（费用场景是费用 id） |

### 5.2.2 出参

`WorkFlowInstanceDetailDto[]`，元素结构同 5.1.2。

## 5.3 `levelGroup[]`

| 字段         | 类型     | 说明              |
| :----------- | :------- | :---------------- |
| `level`      | int      | 层级，从 `1` 开始 |
| `passMethod` | int      | 本级或签 / 会签   |
| `itemList`   | 对象数组 | 本级每个审核人    |

### 5.3.1 `itemList[]`

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `userId` | long | 审核人 id |
| `userNickName` | string | 审核人 nickname |
| `taskStatus` | int? | `null` 还没轮到；`0` 待他审；`1` 他驳了；`2` 他过了 |
| `comment` | string | 审批意见 |
| `auditTime` | DateTime? | 审批时间 |

## 5.4 报错

| 提示             | 触发         |
| :--------------- | :----------- |
| 输入不能为空     | query 为空   |
| 工作流实例不存在 | 按条件查不到 |

# 6. 前端改造清单（客户接入）

- [ ] 工作流配置页任务类型：补 `90` 新建客户审核、`91` 申请修改客户
- [ ] 不要把 `92` 申请删除客户当成可配项（或标成未接入）
- [ ] 任务类型选 `90` / `91` 时，连线条件下拉只出 `90001`~`90004`，比较符与取值按 0.1
- [ ] 客户性质选项用 `0` 同行 / `1` 直客；共享类型用 `0` 不共享 / `1` 共享本公司 / `2` 共享所有人
- [ ] 客户工作流节点审核人：**隐藏用户属性**，只留用户、角色
- [ ] 客户「提交审核」和「申请修改」要各配一条并启用，缺了客户侧会直接报未配置工作流
- [ ] 客户审核待办、详情、历史走 `ClientAdmin` 六个接口，不要复用 `WorkFlowInstanceAdmin/GetAsync` 当客户审批历史
