# 1. 背景意图 (Background)

船公司(Carrier)属于基础资料，被多个业务模块通过 `CarrierId` 引用。此前 `CarrierAdminAppService.DeleteAsync` 直接物理删除，未校验引用关系，可能造成已被业务单据引用的船公司被误删，导致历史数据外键悬空、相关单据展示异常。

本次为删除增加引用校验：若该船公司已被其他模块引用，则禁止删除，并提示具体被哪些模块引用。

# 2. 核心逻辑变更 (Core Changes)

`src/CsprojBuilder.Application/App/Carrier/CarrierAdminAppService.cs`

- 构造函数新增注入 `IRepository<SeaExport, Guid>`、`IRepository<SeFreiPrice, Guid>` 两个仓储。
- `DeleteAsync` 删除前先校验船公司是否存在；随后逐一检查引用模块：
  - `海运出口`（`App_SeaExports`，字段 `CarrierId`）
  - `海运运价`（`App_SeFreiPrices`，字段 `CarrierId`）
- 若存在任意引用，抛出 `UserFriendlyException`，提示：`该船公司已被【海运出口、海运运价】模块引用,禁止删除`（按实际命中的模块拼接）。
- 仅在无引用时才继续删除 Logo 附件并物理删除船公司记录。

# 3. 避坑指南 (Pitfalls)

- **引用源认定**：仓库实体中直接持有 `CarrierId` 列的只有 `SeaExport` 与 `SeFreiPrice`。`SeServiceTask`、`InvoiceApplication` 等模块虽在查询/DTO 中出现 `CarrierId`，但均是经由 `SeaExport.CarrierId` 关联得到，并无自身的船公司外键列，故无需单独校验。
- **后续扩展**：若以后新增直接持有 `CarrierId` 的实体，需要在 `DeleteAsync` 的引用校验区域同步追加对应模块的判断与中文模块名。
- 校验使用 `AnyAsync` 仅判断是否存在引用，避免全表加载。
