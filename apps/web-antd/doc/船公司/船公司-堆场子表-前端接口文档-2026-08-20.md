# 船公司-堆场子表-前端接口文档-2026-08-20

**变更日期**：2026-08-20 **受众**：前端 **性质**：船公司新增一张堆场子表，增删改查全链路带子表（**向后兼容的增量变更**，不传子表数组即为无堆场）

路由前缀：`/api/services/app/CarrierAdmin`

> **一句话要点**：堆场的 `sortId` **由后端按数组顺序自动生成，前端不要传**；返回时按 `sortId` **升序**，即与提交时的数组顺序完全一致，前端直接按返回顺序渲染即可。
>
> ⚠️ **接口地址必须带 `Async` 后缀**（如 `AddAsync`）。旧版《船公司API前端对接文档》里写的 `/CarrierAdmin/Add`、`/CarrierAdmin/GetPagedList` 是**错的**，照着调会 404，已在该文档中一并修正。

## 1. 接口清单

| 接口 | HTTP | 地址 | 是否带子表 |
| :-- | :-- | :-- | :-- |
| 新建 | POST | `/api/services/app/CarrierAdmin/AddAsync` | 是 |
| 编辑 | PUT | `/api/services/app/CarrierAdmin/EditAsync` | 是 |
| 删除 | DELETE | `/api/services/app/CarrierAdmin/DeleteAsync` | 是（同步删子表） |
| 分页列表 | GET | `/api/services/app/CarrierAdmin/GetPagedListAsync` | 是 |
| 详情 | GET | `/api/services/app/CarrierAdmin/DetailAsync` | 是 |

Logo 附件的上传流程、字段结构与本次变更无关，见《船公司API前端对接文档》。

## 2. 新建 — `AddAsync`

`POST /api/services/app/CarrierAdmin/AddAsync`，请求体 `CarrierAddDto`。

### 2.1 入参 `CarrierAddDto`

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 中文名称 | `cnName` | string | 是 | 最长 128 |
| 中文简称 | `cnShortName` | string | 是 | 最长 128 |
| 英文名称 | `enName` | string | 是 | 最长 128 |
| 英文简称 | `code` | string | 是 | 最长 128 |
| 船公司代码别名 | `otherCode` | string | 否 | 最长 128 |
| EDI代码 | `ediCode` | string | 否 | 最长 128 |
| 备注 | `remark` | string | 否 | 最长 1024 |
| Logo附件 | `logo` | object/null | 否 | 结构见《船公司API前端对接文档》 |
| **堆场** | `carrierYards` | `CarrierYardAddDto[]` | 否 | 不传或传 `[]` 表示该船公司下没有堆场 |

### 2.2 入参 `CarrierYardAddDto`（堆场，数组元素）

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 堆场名称 | `name` | string | 是 | 最长 128，自动去首尾空格；同一船公司下不允许重复（大小写不敏感） |
| 堆场地址 | `address` | string | 否 | 最长 512 |
| 备注 | `remark` | string | 否 | 最长 1024 |

> **注意：堆场没有 `sortId` 入参。** 后端按数组下标自增生成（第 1 条 = 1，第 2 条 = 2……），传了这个字段也会被忽略。要调整顺序请调整数组元素顺序。

### 2.3 出参

| 字段     | 类型 | 说明            |
| :------- | :--- | :-------------- |
| `result` | long | 新增的船公司 id |

### 2.4 请求示例

```json
{
  "cnName": "中远海运",
  "cnShortName": "中远",
  "enName": "COSCO Shipping",
  "code": "COSCO",
  "otherCode": "COS",
  "ediCode": "COSU",
  "remark": "备注信息",
  "logo": { "attachmentId": 12345, "displayOrder": 0 },
  "carrierYards": [
    {
      "name": "外高桥一期堆场",
      "address": "上海市浦东新区外高桥保税区XX路1号",
      "remark": "常用"
    },
    {
      "name": "洋山堆场",
      "address": "上海市浦东新区洋山深水港XX路8号",
      "remark": null
    }
  ]
}
```

落库后两条堆场的 `sortId` 依次为 `1`、`2`。

## 3. 编辑 — `EditAsync`

`PUT /api/services/app/CarrierAdmin/EditAsync`，请求体 `CarrierEditDto`。

> **子表为全量提交**：后端按 `id` 做差异比对——**没传的删除、传了 id 的修改、id 为 null 的新增**。前端必须把该船公司下**保留的全部堆场**都提交上来，只提交增量会导致未提交的堆场被删除。
>
> **`sortId` 按本次提交的数组顺序整体重排**（1、2、3……），无论这一条是新增还是修改。

### 3.1 入参 `CarrierEditDto`

在 `CarrierAddDto` 全部字段基础上增加 `id`（long，必填），子表元素类型换成 Edit 版：

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 船公司id | `id` | long | 是 | 主表 id |
| 堆场 | `carrierYards` | `CarrierYardEditDto[]` | 否 | 全量提交；不传或传 `[]` 表示清空该船公司下所有堆场 |

其余主表字段（`cnName`、`cnShortName`、`enName`、`code`、`otherCode`、`ediCode`、`remark`、`logo`）同新建。

### 3.2 入参 `CarrierYardEditDto`（数组元素）

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 堆场id | `id` | Guid? | 否 | **传 id = 修改这一条；传 null 或不传 = 新增一条**；同一数组内不允许重复 |
| 堆场名称 | `name` | string | 是 | 最长 128；同一船公司下不允许重复（大小写不敏感） |
| 堆场地址 | `address` | string | 否 | 最长 512 |
| 备注 | `remark` | string | 否 | 最长 1024 |

> 同样**没有 `sortId` 入参**。

### 3.3 出参

| 字段     | 类型 | 说明     |
| :------- | :--- | :------- |
| `result` | bool | 是否成功 |

### 3.4 请求示例（一次请求同时完成 删/改/增）

原有 3 条堆场：A(`id=aaa...`, sortId=1)、B(`id=bbb...`, sortId=2)、C(`id=ccc...`, sortId=3)。目标：删除 C、修改 B 的地址、新增一条 D，并把 D 排到 B 前面。

```json
{
  "id": 1,
  "cnName": "中远海运",
  "cnShortName": "中远",
  "enName": "COSCO Shipping",
  "code": "COSCO",
  "otherCode": "COS",
  "ediCode": "COSU",
  "remark": "备注信息",
  "logo": { "attachmentId": 12345, "displayOrder": 0 },
  "carrierYards": [
    {
      "id": "aaaaaaaa-1111-2222-3333-444444444444",
      "name": "外高桥一期堆场",
      "address": "上海市浦东新区外高桥保税区XX路1号",
      "remark": "常用"
    },
    {
      "id": null,
      "name": "宝山堆场",
      "address": "上海市宝山区XX路9号",
      "remark": "新增"
    },
    {
      "id": "bbbbbbbb-1111-2222-3333-444444444444",
      "name": "洋山堆场",
      "address": "上海市浦东新区洋山深水港XX路88号(改)",
      "remark": null
    }
  ]
}
```

执行结果：

- C 未出现在数组里 → 被删除；
- A 保留，`sortId` 重排为 `1`；
- D 是新增，`sortId` = `2`；
- B 被更新，`sortId` 重排为 `3`。

## 4. 删除 — `DeleteAsync`

`DELETE /api/services/app/CarrierAdmin/DeleteAsync`，请求体 `IdDto`。

### 4.1 入参

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 船公司id | `id` | long | 是 | 要删除的船公司 id |
| 批量id | `ids` | long[] | 否 | 本接口当前**未使用**该字段，只按 `id` 删除 |

### 4.2 出参

| 字段     | 类型 | 说明     |
| :------- | :--- | :------- |
| `result` | bool | 是否成功 |

### 4.3 行为说明

删除主表的同时**自动删除该船公司下所有堆场**以及关联的 Logo 附件，前端无需单独调用子表删除接口。船公司被引用时禁止删除，提示 `该船公司已被【海运出口、海运进口、海运运价】模块引用,禁止删除`（实际只列出命中的模块）。

## 5. 分页列表 — `GetPagedListAsync`

`GET /api/services/app/CarrierAdmin/GetPagedListAsync`，查询参数 `CarrierQueryDto`。

### 5.1 入参（query string）

| 字段 | JSON | 类型 | 必填 | 默认值 | 说明 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 关键字 | `keyword` | string | 否 | 空 | 模糊匹配 中文名/中文简称/英文名/英文简称/别名/备注 |
| 当前页码 | `pageIndex` | int | 否 | 1 | 从 1 开始 |
| 每页条数 | `pageSize` | int | 否 | 10 | 1~100000 |
| 排序 | `sorting` | string | 否 | `CreationTime DESC` | 主表字段排序表达式 |

`cnName`、`cnShortName`、`enName`、`code`、`otherCode`、`ediCode`、`remark` 这几个参数 DTO 里有定义，但后端当前**未使用**，筛选一律走 `keyword`。

请求示例：

```
GET /api/services/app/CarrierAdmin/GetPagedListAsync?keyword=中远&pageIndex=1&pageSize=20
```

### 5.2 出参 `PagedList<CarrierDto>`

| 字段     | JSON             | 类型           | 说明                     |
| :------- | :--------------- | :------------- | :----------------------- |
| 数据集合 | `items`          | `CarrierDto[]` | 当前页数据               |
| 总记录数 | `totalCount`     | int            | 满足条件的总条数         |
| 跳过条数 | `skipCount`      | int            | `(pageIndex-1)*pageSize` |
| 最大条数 | `maxResultCount` | int            | 等于 `pageSize`          |

## 8. 错误提示对照表

| 提示文案 | 触发接口 | 触发条件 |
| :-- | :-- | :-- |
| `输入不能为空` | 新建/编辑 | 请求体为 null |
| `船公司中文名不能为空` | 新建/编辑 | `cnName` 为空或纯空格 |
| `船公司中文简称不能为空` | 新建/编辑 | `cnShortName` 为空或纯空格 |
| `船公司英文名称不能为空` | 新建/编辑 | `enName` 为空或纯空格 |
| `船公司英文简称不能为空` | 新建/编辑 | `code` 为空或纯空格 |
| `堆场名称不能为空` | 新建/编辑 | 堆场数组中存在 `name` 为空或纯空格 |
| `堆场名称长度不能超过128个字符` | 新建/编辑 | 堆场名称超长 |
| `堆场地址长度不能超过512个字符` | 新建/编辑 | 堆场地址超长 |
| `堆场名称【xxx】重复` | 新建/编辑 | 同一次提交的堆场数组内名称重复（去空格、大小写不敏感） |

| `输入船公司错误` | 编辑/删除/详情 | 主表 id 不存在 |
| `输入堆场id错误` | 编辑 | 传的堆场 `id` 不属于当前船公司 |
| `该船公司已被【xx】模块引用,禁止删除` | 删除 | 船公司被海运出口/海运进口/海运运价引用 |

## 9. 前端适配清单

- [ ] 检查现有请求地址是否带 `Async` 后缀，不带的全部补上（`AddAsync` / `EditAsync` / `DeleteAsync` / `GetPagedListAsync` / `DetailAsync`）
- [ ] 新建/编辑表单增加「堆场」可增删行的明细表格，列为：名称（必填，上限 128）、地址（上限 512）、备注
- [ ] 明细表格**不要**做排序列输入框，顺序由行顺序决定；如需拖拽排序，拖完直接按新数组顺序提交即可
- [ ] 编辑页进入时用详情接口返回的 `carrierYards` 回填，**原样保留每行的 `id`**
- [ ] 编辑提交时：保留行带 `id`、新增行 `id` 传 `null`、删除行直接从数组移除（**不要**传删除标记）
- [ ] 返回已是**升序**，直接按返回顺序渲染，不需要前端再排一次
- [ ] 提交前做前端同名校验，避免走到后端才报「堆场名称重复」
- [ ] 列表页如需展示堆场，可直接用列表接口返回的 `carrierYards`，无需再逐行调详情
- [ ] 海运运价等页面内嵌的 `carrier` 对象里 `carrierYards` 恒为 `null`，取值时要判空
