# 监装工单-2026-09-04

# 1. 背景意图

师傅端待认领、已认领、已完成三个 tab 共用 `GetMyPagedListAsync`。原先只能按 `carrierYardId` 精确筛堆场，小程序上没法按名称/地址/备注搜。本次给查询入参加上 `carrierYardKeyword`，三个列表一起生效。

# 2. 核心逻辑变更

| 项 | 说明 |
| :-- | :-- |
| 查询入参 | `LoadingOrderMyQueryDto` 新增 `CarrierYardKeyword` |
| 搜索范围 | `CarrierYard`（船公司堆场表），不是工单主表 |
| 匹配字段 | `Name`（堆场名称）、`Address`（地址）、`Remark`（备注） |
| 匹配方式 | `Contains` 模糊匹配，三个字段任一命中即可 |
| 过滤方式 | 先查出匹配的堆场 id，再用 `LoadingOrder.CarrierYardId` 过滤；一个都匹配不到则直接空分页 |
| 影响接口 | `GET /api/services/app/LoadingOrder/GetMyPagedListAsync` |

不传该参数时行为与改动前完全一致。与原有 `carrierYardId` 同时传是 **AND**。

完整入参表见《监装工单模块接口文档》第 10.1 节。

# 3. 避坑指南

> [!IMPORTANT] **搜的是堆场表，不是工单备注。** `carrierYardKeyword` 对 `CarrierYard.Name` / `Address` / `Remark` 做模糊匹配。工单自己的 `Remark` 不在搜索范围内；没选堆场的工单（`CarrierYardId` 为空）也匹配不上。

> [!IMPORTANT] **三个 tab 共用这一个参数。** 待认领 / 已认领 / 已完成都走同一接口、同一入参，只改 `status`。不要给某个 tab 另造查询字段。
