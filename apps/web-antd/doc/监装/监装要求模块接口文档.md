# 监装要求模块接口文档

**受众**：前端 **性质**：新模块

路由前缀：`/api/services/app/LoadingRequirementAdmin`

> **三个要点，先看这里：**
>
> 1. **主表的 `sortId` 前端传，子表的 `sortId` 前端不传。** 子表顺序由数组顺序决定，后端按下标自增（1、2、3……），返回时按其升序，与提交顺序一致。
> 2. **两层名字都不能重复**：要求名在全部监装要求里唯一；明细名称在同一条要求下唯一。两者都是去首尾空格、大小写不敏感。跨要求的明细可以同名。
> 3. **接口地址必须带 `Async` 后缀**，如 `/LoadingRequirementAdmin/AddAsync`。本项目 ABP 动态 API 不会剥掉方法名的 `Async`，写掉了会 404。

---

## 1. 接口清单

| 接口 | HTTP | 地址 | 权限 |
| :-- | :-- | :-- | :-- |
| 新建 | POST | `/api/services/app/LoadingRequirementAdmin/AddAsync` | `Admin.LoadingRequirement.Add` |
| 编辑 | PUT | `/api/services/app/LoadingRequirementAdmin/EditAsync` | `Admin.LoadingRequirement.Edit` |
| 删除 | DELETE | `/api/services/app/LoadingRequirementAdmin/DeleteAsync` | `Admin.LoadingRequirement.Delete` |
| 分页列表 | GET | `/api/services/app/LoadingRequirementAdmin/GetPagedListAsync` | **仅需登录** |
| 详情 | GET | `/api/services/app/LoadingRequirementAdmin/DetailAsync` | **仅需登录** |

五个接口都需要携带登录 Token；列表和详情**暂不校验**任何具体权限。

## 2. 新建 — `AddAsync`

`POST /api/services/app/LoadingRequirementAdmin/AddAsync`，请求体 `LoadingRequirementAddDto`。

### 2.1 入参 `LoadingRequirementAddDto`

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 要求名 | `name` | string | 是 | 最长 128，自动去首尾空格；**不能与已有的监装要求重名**（大小写不敏感，已删除的不算） |
| 排序id | `sortId` | int | 否 | **前端输入**，列表默认按其升序；不传为 `0` |
| 备注 | `remark` | string | 否 | 最长 1024 |
| **明细** | `loadingRequirementItems` | `LoadingRequirementItemAddDto[]` | 否 | 不传或传 `[]` 表示该要求下没有明细 |

### 2.2 入参 `LoadingRequirementItemAddDto`（明细，数组元素）

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 明细名称 | `name` | string | 是 | 最长 128，自动去首尾空格；同一条要求下不允许重复（大小写不敏感） |
| 备注 | `remark` | string | 否 | 最长 1024 |

> **明细没有 `sortId` 入参。** 后端按数组下标自增生成（第 1 条 = 1，第 2 条 = 2……），传了也会被忽略。要调整顺序请调整数组元素顺序。

### 2.3 出参

| 字段     | 类型 | 说明              |
| :------- | :--- | :---------------- |
| `result` | Guid | 新增的监装要求 id |

### 2.4 请求示例

```json
{
  "name": "标准整箱监装要求",
  "sortId": 10,
  "remark": "适用于普货整箱",
  "loadingRequirementItems": [
    { "name": "装箱前拍空箱内壁照", "remark": "四壁各一张" },
    { "name": "货物码放需加护角", "remark": null },
    { "name": "装完贴封条并拍照", "remark": "封条号需清晰可辨" }
  ]
}
```

落库后三条明细的 `sortId` 依次为 `1`、`2`、`3`。

## 3. 编辑 — `EditAsync`

`PUT /api/services/app/LoadingRequirementAdmin/EditAsync`，请求体 `LoadingRequirementEditDto`。

> **子表为全量提交**：后端按 `id` 做差异比对——**没传的删除、传了 id 的修改、id 为 null 的新增**。前端必须把该条要求下**保留的全部明细**都提交上来，只提交增量会导致未提交的明细被删除。
>
> **明细 `sortId` 按本次提交的数组顺序整体重排**（1、2、3……），无论这一条是新增还是修改。主表 `sortId` 则是前端传什么存什么。

### 3.1 入参 `LoadingRequirementEditDto`

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 监装要求id | `id` | Guid | 是 | 主表 id |
| 要求名 | `name` | string | 是 | 最长 128；**不能与其它监装要求重名**（校验时会排除自己，改回原名不会报重复） |
| 排序id | `sortId` | int | 否 | 前端输入 |
| 备注 | `remark` | string | 否 | 最长 1024 |
| 明细 | `loadingRequirementItems` | `LoadingRequirementItemEditDto[]` | 否 | 全量提交；不传或传 `[]` 表示清空该要求下所有明细 |

### 3.2 入参 `LoadingRequirementItemEditDto`（数组元素）

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 明细id | `id` | Guid? | 否 | **传 id = 修改这一条；传 null 或不传 = 新增一条**；同一数组内不允许重复 |
| 明细名称 | `name` | string | 是 | 最长 128；同一条要求下不允许重复（大小写不敏感） |
| 备注 | `remark` | string | 否 | 最长 1024 |

> 同样**没有 `sortId` 入参**。

### 3.3 出参

| 字段     | 类型 | 说明     |
| :------- | :--- | :------- |
| `result` | bool | 是否成功 |

### 3.4 请求示例（一次请求同时完成 删/改/增）

原有 3 条明细：A(`id=aaa...`, sortId=1)、B(`id=bbb...`, sortId=2)、C(`id=ccc...`, sortId=3)。目标：删除 C、修改 B 的备注、新增一条 D，并把 D 排到 B 前面。

```json
{
  "id": "11111111-2222-3333-4444-555555555555",
  "name": "标准整箱监装要求",
  "sortId": 10,
  "remark": "适用于普货整箱",
  "loadingRequirementItems": [
    {
      "id": "aaaaaaaa-1111-2222-3333-444444444444",
      "name": "装箱前拍空箱内壁照",
      "remark": "四壁各一张"
    },
    { "id": null, "name": "核对箱号与封号", "remark": "新增" },
    {
      "id": "bbbbbbbb-1111-2222-3333-444444444444",
      "name": "货物码放需加护角",
      "remark": "四角均需加(改)"
    }
  ]
}
```

执行结果：

- C 未出现在数组里 → 被删除；
- A 保留，`sortId` 重排为 `1`；
- D 是新增，`sortId` = `2`；
- B 被更新，`sortId` 重排为 `3`。

## 4. 删除 — `DeleteAsync`

`DELETE /api/services/app/LoadingRequirementAdmin/DeleteAsync`，请求体 `GuidIdDto`。

### 4.1 入参

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 监装要求id | `id` | Guid | 是 | 要删除的监装要求 id |
| 批量id | `ids` | Guid[] | 否 | 本接口当前**未使用**该字段，只按 `id` 删除 |
| 是否打印 | `isPrint` | bool? | 否 | 通用 DTO 自带，本接口**未使用** |

### 4.2 出参

| 字段     | 类型 | 说明     |
| :------- | :--- | :------- |
| `result` | bool | 是否成功 |

### 4.3 行为说明

删除主表的同时**自动删除该条要求下所有明细**，前端无需单独调用子表删除接口。当前**没有引用校验**（还没有别的模块引用监装要求），任何一条都能删掉。监装单上线后会补上「已被监装单引用禁止删除」的拦截。

## 5. 分页列表 — `GetPagedListAsync`

`GET /api/services/app/LoadingRequirementAdmin/GetPagedListAsync`，查询参数 `LoadingRequirementQueryDto`。

### 5.1 入参（query string）

| 字段 | JSON | 类型 | 必填 | 默认值 | 说明 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 关键字 | `keyword` | string | 否 | 空 | 模糊匹配 要求名/备注 |
| 当前页码 | `pageIndex` | int | 否 | 1 | 从 1 开始 |
| 每页条数 | `pageSize` | int | 否 | 10 | 1~100000 |
| 排序 | `sorting` | string | 否 | **`SortId ASC`** | 主表字段排序表达式 |

> **注意默认排序是 `SortId ASC`，不是别的模块常见的 `CreationTime DESC`**，因为主表排序就是给前端自己排的。需要按创建时间看就显式传 `sorting=CreationTime DESC`。

请求示例：

```
GET /api/services/app/LoadingRequirementAdmin/GetPagedListAsync?keyword=整箱&pageIndex=1&pageSize=20
```

### 5.2 出参 `PagedList<LoadingRequirementDto>`

| 字段 | JSON | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| 数据集合 | `items` | `LoadingRequirementDto[]` | 当前页数据 |
| 总记录数 | `totalCount` | int | 满足条件的总条数 |
| 跳过条数 | `skipCount` | int | `(pageIndex-1)*pageSize` |
| 最大条数 | `maxResultCount` | int | 等于 `pageSize` |

列表**已经带出全部明细**，无需再逐行调详情。

## 8. 错误提示对照表

| 提示文案 | 触发接口 | 触发条件 |
| :-- | :-- | :-- |
| `输入不能为空` | 全部 | 请求体为 null |
| `监装要求名不能为空` | 新建/编辑 | `name` 为空或纯空格 |
| `监装要求名长度不能超过128个字符` | 新建/编辑 | `name` 超长 |
| `监装要求名【xxx】已存在` | 新建/编辑 | 同名的监装要求已存在（去空格、大小写不敏感；已删除的不算；编辑时排除自身） |
| `监装要求备注长度不能超过1024个字符` | 新建/编辑 | `remark` 超长 |
| `监装要求明细名称不能为空` | 新建/编辑 | 明细数组中存在 `name` 为空或纯空格 |
| `监装要求明细名称长度不能超过128个字符` | 新建/编辑 | 明细名称超长 |
| `监装要求明细备注长度不能超过1024个字符` | 新建/编辑 | 明细备注超长 |
| `监装要求明细名称【xxx】重复` | 新建/编辑 | 同一次提交的明细数组内名称重复（去空格、大小写不敏感） |
| `监装要求明细id重复` | 编辑 | 同一次提交的明细数组内出现相同 `id` |
| `输入监装要求错误` | 编辑/删除/详情 | 主表 id 不存在 |
| `输入监装要求明细id错误` | 编辑 | 传的明细 `id` 不属于当前监装要求 |

权限不足时走 ABP 通用的 `unAuthorizedRequest`，不在上表。

## 9. 前端适配清单

- [ ] 所有请求地址带 `Async` 后缀
- [ ] 列表页表格列：要求名、排序、备注、创建人、创建时间；明细可做展开行
- [ ] 新建/编辑表单：要求名（必填，上限 128）、**排序（数字输入框，前端填）**、备注
- [ ] 明细表格：名称（必填，上限 128）、备注；**不要做排序输入框**，顺序由行顺序决定
- [ ] 明细如需拖拽排序，拖完直接按新数组顺序提交即可，不用也不能传 `sortId`
- [ ] 编辑页进入时用详情接口返回的 `loadingRequirementItems` 回填，**原样保留每行的 `id`**
- [ ] 编辑提交时：保留行带 `id`、新增行 `id` 传 `null`、删除行直接从数组移除（**不要**传删除标记）
- [ ] 明细返回已是**升序**，直接按返回顺序渲染，不需要前端再排一次
- [ ] 提交前做前端明细同名校验（同一条要求内，去空格 + 忽略大小写），避免走到后端才报「明细名称重复」
- [ ] 要求名重复由后端拦，报 `监装要求名【xxx】已存在`，前端把这个提示落到要求名输入框上
- [ ] 编辑时改回原来的名字不会报重复（后端排除了自身），不用特殊处理
- [ ] 列表默认排序是 `SortId ASC`，若页面要支持点表头排序，显式传 `sorting`
- [ ] 按钮权限：新增/编辑/删除按 `Admin.LoadingRequirement.Add|Edit|Delete` 控制；列表和详情当前不校验权限
