# WVP 直接接入接口文档

本文只说明当前项目已有的 WVP 接口。业务后端携带 ApiKey 调用 WVP，浏览器使用点播返回的原始流媒体地址播放，不需要 Node demo 或视频代理。

## 1. 接入地址与认证

当前 WVP 地址：`http://43.138.14.122:8080`。

以下控制及查询接口统一携带请求头：

```http
api-key: <有效且已启用的 WVP ApiKey>
```

一个 ApiKey 可以完成设备查询、通道查询、点播、停播和云台控制，实际权限取决于 Key 所属账号。ApiKey 放在业务后端配置中，不下发给播放器。已有 ApiKey 时，不需要先调用登录接口。

调用链路：

```text
业务后端 → WVP API：查询、点播、停播、云台
浏览器 → 点播返回的流媒体地址：直接拉取视频
```

HTTP 成功不一定代表业务成功，还需检查 JSON 的 `code`。通常 `code=0` 表示成功，非 0 时读取 `msg`。下文返回示例只保留相关字段，字段值为说明示例，不是完整的实时响应。

## 2. 查询设备

```http
GET /api/device/query/devices?page=1&count=10
api-key: <WVP_API_KEY>
```

| 参数   | 位置  | 说明                       |
| ------ | ----- | -------------------------- |
| page   | query | 页码，从 1 开始            |
| count  | query | 每页条数                   |
| query  | query | 可选，查询条件             |
| status | query | 可选，在线状态，true/false |

```json
{
  "code": 0,
  "msg": "成功",
  "data": {
    "total": 1,
    "list": [
      { "deviceId": "35020000001320000001", "onLine": true, "channelCount": 1 }
    ]
  }
}
```

后续使用 `data.list[].deviceId`，不是数据库主键 `id`。

## 3. 查询设备通道

```http
GET /api/device/query/devices/35020000001320000001/channels?page=1&count=10
api-key: <WVP_API_KEY>
```

路径中的编号为设备国标编号；`page/count` 为分页参数。

```json
{
  "code": 0,
  "msg": "成功",
  "data": {
    "total": 1,
    "list": [
      {
        "deviceId": "35020000001310000001",
        "parentDeviceId": "35020000001320000001",
        "name": "GV3212682",
        "status": "ON"
      }
    ]
  }
}
```

注意：通道列表中的 `deviceId` 是通道国标编号，作为下面接口的 `channelId`。设备编号使用查询路径里的设备编号。

## 4. 开始点播

```http
GET /api/play/start/{deviceId}/{channelId}
api-key: <WVP_API_KEY>
```

实际调用示例：

```http
GET /api/play/start/35020000001320000001/35020000001310000001
api-key: <WVP_API_KEY>
```

| 参数      | 位置 | 说明         |
| --------- | ---- | ------------ |
| deviceId  | path | 设备国标编号 |
| channelId | path | 通道国标编号 |

成功返回示例：

```json
{
  "code": 0,
  "msg": "成功",
  "data": {
    "app": "rtp",
    "stream": "35020000001320000001_35020000001310000001",
    "mediaServerId": "实际流媒体节点ID",
    "flv": "http://43.138.14.122:8080/rtp/35020000001320000001_35020000001310000001.live.flv",
    "ws_flv": "ws://43.138.14.122:8080/rtp/35020000001320000001_35020000001310000001.live.flv"
  }
}
```

| 返回字段                   | 用途                                  |
| -------------------------- | ------------------------------------- |
| data.flv                   | HTTP-FLV 地址                         |
| data.https_flv             | HTTPS-FLV 地址，需部署可用的 TLS 入口 |
| data.ws_flv / data.wss_flv | WebSocket-FLV 地址                    |
| data.hls / data.https_hls  | HLS 地址                              |
| data.app                   | 查询流信息使用的应用名                |
| data.stream                | 查询流信息使用的流 ID                 |
| data.mediaServerId         | 查询流信息使用的实际流媒体节点 ID     |

将完整播放地址交给支持相应协议的播放器。不要自行拼接或删除查询参数；上例省略了实际返回地址中可能存在的查询参数。返回 HTTPS 地址也不代表部署一定配置了可用的 HTTPS 端口，需实际验证。

点播是异步等待设备出流的请求，超时由 WVP 的点播配置决定，客户端超时应配合服务端设置。保存返回的 app、stream、mediaServerId，后续查询复用这些值，不使用设备配置中的 `auto` 代替实际节点 ID。

## 5. 停止点播

```http
GET /api/play/stop/{deviceId}/{channelId}
api-key: <WVP_API_KEY>
```

```http
GET /api/play/stop/35020000001320000001/35020000001310000001
api-key: <WVP_API_KEY>
```

成功返回中的数据包含设备与通道编号：

```json
{
  "code": 0,
  "msg": "成功",
  "data": {
    "deviceId": "35020000001320000001",
    "channelId": "35020000001310000001"
  }
}
```

这是停止通道点播，可能影响观看同一路流的其他用户。一个用户退出时，先销毁其播放器、断开其播放连接；不要默认对每次页面退出都调用此接口。只有明确需要停止整路视频时调用。

停播不是让某个用户的链接永久失效；再次点播后可能出现相同流路径。

## 6. 云台控制

```http
GET /api/front-end/ptz/{deviceId}/{channelId}?command=left&horizonSpeed=100&verticalSpeed=0&zoomSpeed=0
api-key: <WVP_API_KEY>
```

| 参数          | 位置  | 说明            |
| ------------- | ----- | --------------- |
| deviceId      | path  | 设备国标编号    |
| channelId     | path  | 通道国标编号    |
| command       | query | 见下表          |
| horizonSpeed  | query | 水平速度，0–255 |
| verticalSpeed | query | 垂直速度，0–255 |
| zoomSpeed     | query | 变倍速度，0–15  |

接入时显式传入三个速度参数，不依赖默认值。

| 指令                 | 动作            |
| -------------------- | --------------- |
| left / right         | 左 / 右         |
| up / down            | 上 / 下         |
| upleft / upright     | 左上 / 右上     |
| downleft / downright | 左下 / 右下     |
| zoomin / zoomout     | 变倍放大 / 缩小 |
| stop                 | 停止            |

向左：

```http
GET /api/front-end/ptz/35020000001320000001/35020000001310000001?command=left&horizonSpeed=100&verticalSpeed=0&zoomSpeed=0
api-key: <WVP_API_KEY>
```

停止：

```http
GET /api/front-end/ptz/35020000001320000001/35020000001310000001?command=stop&horizonSpeed=0&verticalSpeed=0&zoomSpeed=0
api-key: <WVP_API_KEY>
```

成功以返回 `code=0` 为准，不依赖 data 内容。按住方向按钮发送移动指令，松开发送 stop；接口没有“移动几秒”的时长参数。设备本身必须支持对应云台能力，接口成功不代表设备一定发生物理转动。

## 7. 查询观看连接数和流信息

这是当前仓库已有的真实 WVP 接口：

```http
GET /api/server/media_server/media_info?app=rtp&stream=35020000001320000001_35020000001310000001&mediaServerId=<实际节点ID>
api-key: <WVP_API_KEY>
```

三个 query 参数均从点播返回结果获取，发送时做 URL 编码。

返回相关字段示例：

```json
{
  "code": 0,
  "msg": "成功",
  "data": {
    "app": "rtp",
    "stream": "35020000001320000001_35020000001310000001",
    "readerCount": 2,
    "online": true,
    "bytesSpeed": 250000,
    "videoCodec": "H264"
  }
}
```

| 字段        | 说明                                                      |
| ----------- | --------------------------------------------------------- |
| readerCount | 流媒体上报的观看连接数量；ZLM 实现映射自 totalReaderCount |
| online      | 流是否在线                                                |
| bytesSpeed  | 流数据产生速度，单位 byte/s；不是服务器总出站速度         |
| videoCodec  | 视频编码                                                  |

`readerCount` 不是按业务账号去重的人数，同一人多开页面、其他客户端观看也可能产生多个连接。流不存在或尚未就绪时，不要把异常或空数据直接解释成观看人数 0。

此接口已核对本仓库源码；本次文档修改没有对线上该接口进行实测。实际字段可用性、统计口径应结合部署版本联调。

## 8. 人数限制与令牌有效期：实际支持范围

| 需求 | 当前核对结果 |
| --- | --- |
| 使用一个 ApiKey 调用点播、云台等接口 | 支持 |
| 查询一路流的观看连接数 | 支持，使用第 7 节接口 |
| 设置“最多 2 人观看” | 本文核对的现有接口没有这一设置参数 |
| 签发单个用户的限时播放令牌 | 本文核对的国标点播接口不提供此能力 |
| 指定某条播放地址 5 分钟过期 | 点播接口没有有效期参数 |
| 单独踢掉一个业务用户 | 本文列出的接口没有此能力；stop 是通道级 |

ApiKey 是 WVP 控制 API 的调用凭证，不是视频地址的短期访问令牌。不能通过在播放 URL 后自行添加 `token` 或 `expires` 获得访问控制，也不能把 ApiKey 失效等同于已建立的视频连接自动断开。

源码中 ZLM 的 on_play 回调会调用 `MediaServiceImpl.authenticatePlay`；当前实现对 `rtp` 应用直接放行。因此本项目国标流不能依赖该逻辑实现单用户播放期限或人数上限。实际入口若另有独立鉴权配置，应以部署配置为准。

业务后端可以在点播前查询 readerCount，达到阈值时暂不提供播放地址，但这只是提示性限制：并发查询可能同时通过，已经持有原始地址的用户也可以重新连接。严格人数上限和到期断流需要媒体服务侧另行实现，本说明不提供虚构的现成接口。

## 9. 浏览器直连播放要求

- 返回的媒体 IP、域名和端口必须能从用户外网访问。
- HTTPS 网页使用已配置可用的 HTTPS/WSS 媒体地址。
- HTTP-FLV 跨域拉流需在媒体入口配置允许业务网页来源的 CORS；用真实浏览器验证。
- 播放器按实际协议选择，普通 video 标签不能直接播放所有 FLV/RTSP 地址。已有 Jessibuca 播放器可继续使用，播放器文件需完整部署。
- 浏览器直连的是流媒体服务，不是摄像头；视频仍消耗流媒体服务器出站带宽。

## 10. 推荐对接顺序

1. 将有效 ApiKey 配置到业务后端。
2. 查询设备及通道，确定两个国标编号。
3. 调用点播，检查 code=0，保存流标识并将原始播放地址交给前端。
4. 前端直接播放，验证实际画面及网络请求。
5. 调用流信息接口获取 readerCount，展示观看连接数。
6. 需要云台时调用方向/变倍指令，松开调用 stop。
7. 用户退出销毁播放器；需要停止整个通道时调用停止点播。

## 11. 未调用停止点播时的自动回收机制

### 11.1 浏览器直连流媒体

不调用停止点播接口，仍可以通过“无人观看”机制回收流，前提是播放连接确实断开，且流媒体回调、WVP 按需配置正常生效。

```text
浏览器关闭或销毁播放器
  → 流媒体检测到播放连接断开
  → 最后一个观看连接消失
  → 持续无人观看达到配置时间
  → ZLMediaKit 向 WVP 发送 on_stream_none_reader
  → WVP 返回 close 决策
  → ZLMediaKit 根据决策处理关闭
```

这不是要求浏览器定时调用业务心跳接口。突然断网时，连接检测可能需要等待网络超时，因此不能承诺从关闭页面开始固定 20 秒就停流。若其他用户或其他消费者仍在使用该流，也不一定进入无人观看状态。

### 11.2 配置与处理证据

ZLMediaKit 官方文档说明，从有人观看转为无人观看时会触发该事件，应用可以决定是否关闭流：

- [on_stream_none_reader 官方说明](https://docs.zlmediakit.com/guide/media_server/web_hook_api.html)
- [streamNoneReaderDelayMS 配置说明](https://docs.zlmediakit.com/guide/media_server/config_file.html)

本仓库 `docker/media/config.ini` 包含：

```ini
[general]
streamNoneReaderDelayMS=20000

[hook]
enable=1
on_stream_none_reader=http://polaris-wvp:18978/index/hook/on_stream_none_reader
```

这是仓库配置示例，不应直接复制其容器主机名和端口到其他部署。`20000` 单位为毫秒，表示持续无人观看的等待时间。线上需要确认流媒体实际生效的配置及回调地址可达性。

WVP 接收回调的实现位于 `src/main/java/com/genersoft/iot/vmp/media/zlm/ZLMHttpHookListener.java` 的 `onStreamNoneReader` 方法，核心处理为：

```java
boolean close = mediaService.closeStreamOnNoneReader(
    param.getMediaServerId(), param.getApp(), param.getStream(), param.getSchema());
ret.put("code", 0);
ret.put("close", close);
```

`MediaServiceImpl.closeStreamOnNoneReader` 在存在录像计划正在录制时返回不关闭；国标流由 `SourceOtherServiceForGbImpl.closeStreamOnNoneReader` 处理，录像下载等情况有例外，通常最终读取 `userSetting.getStreamOnDemand()`。

仓库 `src/main/resources/application-dev.yml` 的相关配置为：

```yaml
user-settings:
  stream-on-demand: true
```

以上说明代码具备该机制，不代表当前线上配置、回调通信和实际停流已通过验证。部署验收应在没有其他消费者的测试通道上播放后断开，观察无人观看回调、WVP 的 close 决策日志及媒体流实际状态。

### 11.3 如果业务后端额外代理视频

本文主接入方案仍是浏览器直连；若接入方另行增加视频代理，需要处理以下差别：

```text
浏览器 → 业务后端代理 → 流媒体
```

流媒体看到的是代理建立的观看连接，不能直接知道代理后面有几个浏览器。

| 代理行为 | 无人观看处理结果 |
| --- | --- |
| 浏览器断开，代理同步取消对应上游拉流 | 最后一个上游观看连接消失后，可触发无人观看回调 |
| 浏览器断开，代理继续读取上游 | 流媒体仍认为有人观看，无法依靠该机制回收 |
| 多个浏览器共享一个上游连接 | 代理需统计下游连接，最后一个退出时再关闭共享上游；媒体计数不是浏览器人数 |

代理应覆盖下游连接关闭、上游异常、主动结束和令牌到期等路径，统一取消上游请求、销毁相关流并回收连接计数。清理必须幂等，不能只依赖页面退出请求或浏览器心跳。

本地 demo 当前 `server.js` 的代理实现存在处理缺口：它监听 `req.close`，但执行 `nodeStream.pipe(res)` 后即在 `finally` 中移除监听。`pipe()` 启动转发不代表传输已结束，因此该实现不能保证浏览器后续关闭时同步取消上游。Node 接入应按下游响应的完整生命周期处理 `res.close` 等事件，并取消上游请求；其他语言后端应使用框架对应的客户端断开通知/请求取消机制。

Node 请求与响应 close 事件的区别见 [Node HTTP 官方文档](https://nodejs.org/api/http.html)。本次仅补充接入说明，未修改 demo 代理代码。

### 11.4 与播放令牌有效期的区别

无人观看回收只处理“已经没有观看连接”的情况。用户持续播放时仍有连接，不会因为经过了 20 秒而自动停播。

因此，“令牌到期立即停止观看”仍须由实际提供视频的入口主动关闭该用户连接；若使用代理，还要同步取消对应的上游连接。随后是否关闭整路流，再由剩余观看者及 WVP 无人观看策略决定。
