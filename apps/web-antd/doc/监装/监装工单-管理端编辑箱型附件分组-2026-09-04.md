# 监装工单-管理端编辑箱型附件分组-2026-09-04

# 1. 背景意图

师傅端 `EditOrderCtnsAsync` 一次提交整票箱子，还能改箱型、箱号、封号、是否完成，并且只有已认领能调。管理端需要在任意状态下单独改某一只箱子的监装照片，不碰箱子本身、也不走工单状态机。

# 2. 核心逻辑变更

| 项 | 说明 |
| :-- | :-- |
| 新接口 | `PUT /api/services/app/LoadingOrderAdmin/EditOrderCtnAttachmentGroupsAsync` |
| 权限 | 复用 `Admin.SeaExport.LoadingOrder.Edit` |
| 入参 | `id` = `OrderCtn.Id`；`attachmentGroups` 分组附件 |
| 只改什么 | 该箱的监装附件（`ModuleTypeIds.Bussiness.OrderCtnLoading`，ItemId=箱型id） |
| 不改什么 | 箱型、箱号、封号、是否完成、工单主表、工单状态 |
| 状态 | **不校验**。未提交 / 待认领 / 已认领 / 已完成都可以调 |
| 替换口径 | 与师傅端相同：先删该箱全部监装附件再按入参重建；`[]` 表示清空 |
| 存在性 | 只确认这只 `OrderCtn` 存在，不查它属不属于某张监装工单 |

完整入参见《监装工单模块接口文档》第 9 节。工单主表的编辑/删除规则不变，仍只允许未提交。

# 3. 避坑指南

> [!IMPORTANT] **这不是工单编辑，也不是师傅端编辑箱型的单条版。** 不要把箱号、封号、是否完成塞进这个接口——后端不会写。真要改箱子字段，仍走师傅端 `EditOrderCtnsAsync`（且仍要求已认领）。

> [!IMPORTANT] **附件是按该箱全量替换。** 漏传某个分组等于删掉该组照片；传 `attachmentGroups: []` 等于清空该箱全部监装附件。详情里 `orderCtns[].attachmentGroups` 原样回传再改，不要只传增量。
