# 监装工单模块接口文档

**受众**：前端（内部管理端）、小程序（监装师傅端）、公开详情页（免登录） **性质**：新模块

两套路由前缀：

| 端 | 路由前缀 | 鉴权 |
| :-- | :-- | :-- |
| 内部管理端 | `/api/services/app/LoadingOrderAdmin` | 登录 + `Admin.SeaExport.LoadingOrder.*` 权限 |
| 监装师傅端（小程序） | `/api/services/app/LoadingOrder` | 登录 + 当前登录人用户属性含**监装** |
| 公开详情 | `/api/services/app/LoadingOrder/DetailByMblAndLoadingOrderNumAsync` | **免登录** |
| 监装视频（公开端） | `/api/services/app/LoadingOrderVideo` | **免登录**，见《监装视频接口文档》 |
| 摄像头（师傅端） | `/api/services/app/LoadingOrder/GetCameraListAsync`、`.../EditCameraNoAsync` | 同师傅端，见《监装视频接口文档》 |

> **先看这五条：**
>
> 1. **接口地址必须带 `Async` 后缀**，写掉了会 404。
> 2. **师傅子表的 `sortId` 前端不传**，按 `userIds` 数组顺序自增（先输入的在前）。最多两个由**前端**限制，后端不卡。
> 3. **工单主表只有「未提交」能编辑和删除**，只有「待认领」能撤回。**箱型附件分组例外**：管理端按箱型id单独改，任意状态都可以，不改工单状态。
> 4. 管理端有两个查询入口：**分页列表** `GetPagedListAsync`（每条带完整的海运出口列表对象，不含运踪），和**按海运出口id查单条** `DetailBySeaExportIdAsync`（海运出口详情页的监装 tab 用这个，没有工单返回 `null`）。
> 5. **摄像头与视频播放全部在《监装视频接口文档》里**。本文只覆盖工单详情出参里的 `cameraNo` / `camera` 两个**只读**字段。摄像头是**师傅**在现场选的（可选列表 + 修改编号两个接口都在师傅端）， **管理端没有摄像头相关接口**，新建/编辑工单也不能带这个字段。

### 1.3 监装状态枚举 `status`

| 值  | 名称   | 说明                                      |
| :-- | :----- | :---------------------------------------- |
| 0   | 未提交 | 新建后的初始状态，只有这个状态能编辑/删除 |
| 1   | 待认领 | 公共池，所有监装师傅可见可认领            |
| 2   | 已认领 | 有师傅了，师傅可编辑箱型                  |
| 3   | 已完成 | 所有箱子都完成后自动进入                  |

## 1.4 管理端 分页列表 — `GetPagedListAsync`

`GET /api/services/app/LoadingOrderAdmin/GetPagedListAsync`，查询参数 `LoadingOrderQueryDto`。

### 入参（query string）

工单自身的条件：

| 字段 | JSON | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| 监装状态 | `status` | int? | 单选。不传查全部（**含未提交**，这点与师傅端不同，师傅端状态必填） |
| 监装状态(多选) | `statuses` | int[] | 多选，Query 重复传参：`statuses=1&statuses=2`。空数组/不传不筛。与 `status` 同时传时两个条件都生效，一般只传其中一个 |
| 监装工单号 | `loadingOrderNum` | string | 模糊匹配 |
| 监装堆场id | `carrierYardId` | Guid? |  |
| 预计到货日期 | `estimatedArrivalDate` | DateTime? | 只按日期部分匹配 |
| 监装师傅id | `userId` | long? | 按师傅子表里有没有这个人筛 |
| 工单创建时间起/止 | `creationTimeStart` / `creationTimeEnd` | DateTime? | 均含当天 |

海运出口维度的条件（后端先筛出海运出口id再过滤工单）：

| 字段       | JSON            | 类型   | 说明             |
| :--------- | :-------------- | :----- | :--------------- |
| 主提单号   | `mblNum`        | string | 模糊匹配         |
| 委托编号   | `commissionNum` | string | 模糊匹配         |
| 品名id     | `codeGoodsId`   | long?  | 按主单品名子表筛 |
| 船公司id   | `carrierId`     | long?  |                  |
| 起运港id   | `polId`         | long?  |                  |
| 船名       | `vessel`        | string | 模糊匹配         |
| 航次       | `innerVoyno`    | string | 模糊匹配         |
| 所属组织id | `orgId`         | long?  | 含其所有下级组织 |

分页与排序：`pageIndex`（默认 1）、`pageSize`（默认 10）、`sorting`（默认 `CreationTime DESC`）。可传工单表字段，以及：

| 路径 | 含义 |
| :-- | :-- |
| `CarrierYard.Name` | 堆场名称，未选堆场视为空 |
| `CodePackageItem.Name` | 明细包装名称，未选包装视为空 |
| `LoadingOrderUsers.UserId` | 师傅用户 id，取子表 `sortId` 最小的那条（先输入的师傅）；没有师傅视为空。最多两个师傅时不按第二个人排 |

多字段用逗号分隔，例如 `CreationTime DESC, CarrierYard.Name ASC`、`LoadingOrderUsers.UserId ASC`。

**数据权限（2026-09-16 接入）：** 列表可见性跟随海运出口，不按工单自己筛。当前用户在海运出口列表里看不到的票，对应监装工单这里也看不到。数据权限类型为「全部」时**连这层过滤都不挂**。详情、新建、编辑、删除不走这层。

### 出参 `PagedList<LoadingOrderListDto>`

`items` 每项：

| 字段 | JSON | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| 工单id | `id` | Guid |  |
| 海运出口id | `seaExportId` | Guid |  |
| 监装工单号 | `loadingOrderNum` | string |  |
| 明细包装对象 | `codePackageItem` | object | 未选为 `null` |
| 明细包装件数 | `pkgs` | int? |  |
| 预计到货时间 | `estimatedArrivalTime` | DateTime? |  |
| 监装堆场对象 | `carrierYard` | object | 未选为 `null` |
| 监装状态 | `status` | int |  |
| 备注 | `remark` | string |  |
| 是否包含水印 | `hasWatermark` | bool | 不可空。`true` 含水印。后端只返回开关，不处理图片 |
| 提交人昵称 / 手机号 / 提交时间 | `submitUserName` / `submitUserPhone` / `submitTime` | string / string / DateTime? | 手机号取用户资料 `PhoneNumber`，未提交或用户无手机号时为 `null` |
| 认领时间 / 完成时间 | `claimTime` / `completeTime` | DateTime? |  |
| 拒接时间 / 原因 | `rejectTime` / `rejectReason` | DateTime? / string | 只保留最后一次 |
| 创建/修改人昵称 | `creatorUserName` / `lastModifierUserName` | string |  |
| 监装师傅列表 | `loadingOrderUsers` | array | 结构同 7.1，按 `sortId` 升序 |
| **海运出口** | `seaExport` | `SeaExportDto` | **与海运出口列表返回的是同一个对象**，字段完全一致 |

> **`seaExport` 不含运踪**：云当订阅、飞驼跟踪那几个字段（`isFeituoSubscribed`、`feituoTracking`、 `yundangShipmentOceanNode` 等）在这里恒为默认值/`null`，需要运踪请走海运出口自己的列表或详情。同样不含服务项任务信息与数据权限的组织串（`orgs`、本位币）。
>
> 海运出口被删掉时 `seaExport` 为 `null`，前端取值要判空。

## 2. 管理端 新建 — `AddAsync`

`POST /api/services/app/LoadingOrderAdmin/AddAsync`，请求体 `LoadingOrderAddDto`。

### 2.1 入参

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 海运出口id | `seaExportId` | Guid | 是 | 与业务委托单id相同；该海运出口**不能已有工单** |
| 明细包装id | `codePackageItemId` | Guid? | 否 | 必须属于业务委托单主单包装下的明细 |
| 明细包装件数 | `pkgs` | int? | 否 |  |
| 预计到货时间 | `estimatedArrivalTime` | DateTime? | 否 |  |
| 监装堆场id | `carrierYardId` | Guid? | 否 | 必须属于该海运出口船公司下的堆场 |
| 备注 | `remark` | string | 否 | 最长 1024；与拒接原因是两个独立字段 |
| 是否包含水印 | `hasWatermark` | bool | 否 | 不可空。不传按 `true`（含水印）。整个监装的图片是否带水印，**后端只存开关，不处理图片** |
| 监装师傅id集合 | `userIds` | long[] | 否 | 用户属性必须含监装；**最多两个由前端限制**；数组顺序即监装顺序 |
| 监装要求明细id集合 | `loadingRequirementItemIds` | Guid[] | 否 | 勾选的监装要求明细 |

工单号由后端按编号规则 `LoadingOrder.LoadingOrderNum` 自动生成，前端不传。新建后状态为**未提交**。

### 2.2 出参

| 字段     | 类型 | 说明              |
| :------- | :--- | :---------------- |
| `result` | Guid | 新增的监装工单 id |

### 2.3 请求示例

```json

  "codePackageItemId": "22222222-2222-2222-2222-222222222222",

  "carrierYardId": "33333333-3333-3333-3333-333333333333",
  "remark": "客户要求装箱前先拍空箱照",
  "hasWatermark": true,
  "userIds": [1001, 1002],
  "loadingRequirementItemIds": [
    "44444444-4444-4444-4444-444444444444",
    "55555555-5555-5555-5555-555555555555"
  ]
}
```

`userIds` 里 1001 的 `sortId` 为 1、1002 为 2。

## 3. 管理端 编辑 — `EditAsync`

`PUT /api/services/app/LoadingOrderAdmin/EditAsync`，请求体 `LoadingOrderEditDto`。

> **只有未提交状态能编辑**，否则报 `只有未提交状态的监装工单可以编辑`。 **不带箱型**。箱型/箱号/封号/是否完成仍由师傅端 `EditOrderCtnsAsync` 改；管理端要改某箱的监装附件走单独接口 `EditOrderCtnAttachmentGroupsAsync`。 `userIds` 和 `loadingRequirementItemIds` 都是**全量提交**，传 `[]` 或不传表示清空。

### 3.1 入参

在新建入参的基础上把 `seaExportId` 换成 `id`（Guid，必填，工单id），其余字段完全相同。 **海运出口不允许改**。

### 3.2 出参

`result`：bool。

---

## 4. 管理端 删除 — `DeleteAsync`

`DELETE /api/services/app/LoadingOrderAdmin/DeleteAsync`，请求体 `GuidIdDto`（`id` 必填）。

> **只有未提交状态能删除**。删除时同步清理师傅子表与监装要求子表。删掉之后该海运出口可以重新新建工单（软删除的不参与「已有工单」判定）。

`result`：bool。

---

## 5. 管理端 提交 — `SubmitAsync`

`POST /api/services/app/LoadingOrderAdmin/SubmitAsync`，请求体 `GuidIdDto`（`id` 必填）。

### 行为

| 条件 | 结果 |
| :-- | :-- |
| 师傅列表非空 | 状态变 **已认领**（2），同时记提交人、提交时间，认领时间=提交时间 |
| 师傅列表为空 | 状态变 **待认领**（1），进公共池 |

**前置校验**：只有未提交状态能提交；该海运出口**必须有箱子**，否则报 `该海运出口没有箱型,不能提交监装工单`。

`result`：bool。

---

## 6. 管理端 撤回 — `WithdrawAsync`

`POST /api/services/app/LoadingOrderAdmin/WithdrawAsync`，请求体 `GuidIdDto`（`id` 必填）。

> **只有待认领状态能撤回**，撤回后状态变未提交，清空提交人与提交时间。已认领的单撤不回来，只能等师傅拒接。

`result`：bool。

---

**该海运出口还没有工单时返回 `result: null`**，前端据此显示「新建监装工单」按钮。

| 字段 | JSON | 类型 | 说明 |
| :-- | :-- | :-- | :-- |

| 箱型id / 对象 | `ctnCodeId` / `ctnCode` | long / object |  |

### 7.4 `loadingRequirements[]`（监装要求 + 勾选状态）

数组元素是**监装要求主表的简易对象**加上一个明细数组，**按主表 `sortId` 升序**：

| 字段   | JSON                      | 类型   | 说明                   |
| :----- | :------------------------ | :----- | :--------------------- |
| 要求id | `id`                      | Guid   | 监装要求主表id         |
| 要求名 | `name`                    | string |                        |
| 排序id | `sortId`                  | int    | 主表排序，数组按它升序 |
| 明细   | `loadingRequirementItems` | array  | 按明细 `sortId` 升序   |

`loadingRequirementItems[]` 每项是监装要求明细，外加一个 `isChecked`：

| 字段 | JSON | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| 明细id | `id` | Guid | 提交时放进 `loadingRequirementItemIds` |

## 11. 师傅端 详情 — `DetailAsync`

`GET /api/services/app/LoadingOrder/DetailAsync?id={工单id}`

## 16. 师傅端 取消完成 — `CancelCompleteAsync`

`POST /api/services/app/LoadingOrder/CancelCompleteAsync`，请求体 `GuidIdDto`（`id`=工单id）。

只有**已完成**状态能取消，取消后状态退回已认领、完成时间清空，之后才能继续编辑箱型。只能由师傅列表里的人操作。

> [!IMPORTANT] **取消完成不会重置各箱的 `isLoadingCompleted`。** 所以如果只是进去改个封号就保存，所有箱子仍然是完成态 → 保存后**会立刻再次自动变已完成**。真要让工单停在已认领，必须把至少一个箱子的 `isLoadingCompleted` 改成 false。前端最好在取消完成后提示一句，避免师傅以为没保存上。

`result`：bool。

| `拒接原因长度不能超过1024个字符` | 拒接 | 超长 |

摄像头相关的报错见《监装视频接口文档》第 6.1 节。
