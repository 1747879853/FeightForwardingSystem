# 监装视频接口文档

**受众**：小程序（监装师傅选摄像头）、公开监装页（免登录看直播） **关联**：《监装工单模块接口文档》《监装工单模块总逻辑文档》第 4.6、5、6.3 节

三个路由前缀：

| 端 | 路由前缀 | 鉴权 |
| :-- | :-- | :-- |
| 监装师傅端（选摄像头） | `/api/services/app/LoadingOrder` | 登录 + 当前登录人用户属性含**监装** + 自己是该工单的师傅 |
| 公开端（点播/云台/看人数） | `/api/services/app/LoadingOrderVideo` | **免登录**，靠「主提单号 + 监装工单号」当口令 |
| 画面转发（播放器直接拉的地址） | `/api/loading-order-video/stream/{监装工单id}.flv` | **免登录**，每次拉流回查工单状态 |

> **先看这七条：**
>
> 1. **接口地址必须带 `Async` 后缀**，写掉了会 404。转发地址（第 3 节）是普通控制器，**没有** `Async`。
> 2. **画面由业务后端转发，播放器只认 `flvUrl` 这一个地址。** 视频平台的原始地址一个字都不下发，也不再返回 `app` / `stream` / `mediaServerId` 这些流标识——前端没有任何场景需要直连视频平台。
> 3. **只有 HTTP-FLV，没有 HLS、没有 WS-FLV。** HLS 延迟十几秒，云台转一下要等二十多秒才看得见，监装场景用不了，后端不转。播放器要选支持 HTTP-FLV 的（如 Jessibuca、mpegts.js）， `<video>` 标签**不能**直接播 FLV。
> 4. **摄像头由师傅在现场选定**：先调 `GetCameraListAsync` 拿可选列表（带占用情况），对着摄像头机身上贴的号牌挑一个，再调 `EditCameraNoAsync` 存回工单。 **管理端不碰这个字段**，只在工单详情里只读看到。
> 5. **一个摄像头同时只能被一张工单绑定**。填写时后端**跨租户**查重。
> 6. **播放地址没有有效期**，只看工单状态：**工单没完成就一直能用，完成的那一刻立刻失效**。完成时后端会停掉这路流、把 `cameraNo` 置空（解绑）。**解绑不可逆**，取消完成不会自动绑回来（但师傅取消完成后可以再填一次编号）。
> 7. **3 路上限是硬限制**，写死 3。第 4 路连接会被转发接口直接拒掉（HTTP 429），不是提示、绕不过去。 **数的是连接不是人**，同一个人开两个页面占两个名额。

## 1. 师傅端 摄像头绑定 — 可选列表与修改编号

**整套摄像头功能只有这两个接口**，都在师傅端：先拉一份可选列表给师傅挑，再把编号写回工单。师傅到了堆场，看自己要用哪个摄像头，选中它，客户那边就能看这一路画面了。 **管理端不碰这个字段**，只在工单详情里只读看到。

### 1.1 查可选摄像头列表 — `GetCameraListAsync`

`GET /api/services/app/LoadingOrder/GetCameraListAsync?id={监装工单id}`。

入参只有一个监装工单id（`GuidIdDto`，`ids` / `isPrint` 两个字段这里用不到，不用传）。 **必须传**，因为「哪些摄像头被占用了」是相对这张单算出来的。

出参 `result`：`LoadingOrderCameraOptionDto[]`，**按编号升序**。

| 字段 | JSON | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| 摄像头编号 | `cameraNo` | int | 保存时回传这个值 |
| 摄像头名称 | `name` | string | 与摄像头机身上贴的号牌一致，师傅照着认 |
| 是否已被占用 | `isOccupied` | bool | 被**其它**工单占着，选不了（保存必被拦），前端置灰 |
| 占用它的工单号 | `occupiedLoadingOrderNum` | string | 仅占用方与本工单**同公司**时才有值；别家公司时为 `null` |
| 是否本工单当前绑的 | `isCurrent` | bool | 用于列表里高亮 |

```json
{
  "result": [
    {
      "cameraNo": 1,
      "name": "摄像头1",
      "isOccupied": false,
      "occupiedLoadingOrderNum": null,
      "isCurrent": true
    },
    {
      "cameraNo": 2,
      "name": "摄像头2",
      "isOccupied": true,
      "occupiedLoadingOrderNum": "JZ2026090001",
      "isCurrent": false
    },
    {
      "cameraNo": 3,
      "name": "摄像头3",
      "isOccupied": true,
      "occupiedLoadingOrderNum": null,
      "isCurrent": false
    }
  ]
}
```

四点说明：

- **已停用的摄像头不在列表里。** 它们不再允许绑定，列出来只会让师傅选了才被拦。历史工单上那个已停用的编号照样能解析出名称（工单详情里的 `camera` 对象），只是重新选不到它。
- **本工单自己绑着的那个不算占用**（`isOccupied` 为 false、`isCurrent` 为 true），否则师傅在自己单上会看到「已被占用」。
- **占用情况是跨公司算的**，因为摄像头是堆场里的物理设备、视频服务全系统共用一套。别家公司占着的只告诉你被占了，不给单号。同公司的给单号，师傅可以去那张单上解绑。
- **鉴权与 `EditCameraNoAsync` 完全一致**：要登录、用户属性含监装、自己在该工单师傅列表里、且工单是**已认领**状态。不限定在自己的单上，这就成了「枚举全系统摄像头正被谁占着」的接口。

`isOccupied` 只是**提前告知**，真正的拦截在保存那一步（见 1.4 第二条）——列表拉完到点保存之间别人可能刚好占了同一台。

### 1.2 修改摄像头编号 — `EditCameraNoAsync`

`PUT /api/services/app/LoadingOrder/EditCameraNoAsync`，请求体 `LoadingOrderCameraEditDto`。

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 监装工单id | `id` | Guid | 是 |  |
| 摄像头编号 | `cameraNo` | int? | 否 | 取 1.1 列表里的 `cameraNo`，也可照着机身号牌直接填；**传 `null` 即解绑** |

### 1.3 出参与请求示例

`result`：bool。

选 1 号摄像头：

```json
{ "id": "11111111-1111-1111-1111-111111111111", "cameraNo": 1 }
```

解绑（不想让客户看了）：

```json
{ "id": "11111111-1111-1111-1111-111111111111", "cameraNo": null }
```

### 1.4 三条限制

**一、只有已认领状态能改，且只能改自己的单。** 口径与 `EditOrderCtnsAsync` 完全一致：不在师傅列表里报 `你不是该工单的监装师傅,不能修改摄像头`，状态不对报 `只有已认领状态的监装工单可以修改摄像头,已完成的请先取消完成`。

已完成改不了是刻意的——那时摄像头已经被自动解绑、释放给别的工单了，绑回去可能抢到别人正在用的设备。确实要继续用就先「取消完成」退回已认领，再填一次编号（此时会重新走一遍占用校验）。

**二、一个摄像头同时只能被一张工单占用。** 填的编号已经被别的工单占着就报错，提示分两种：占用方是**同公司**的单会把工单号说出来（方便去那张单上解绑），占用方是**别家公司**的只说被占用，不透露单号。

**三、换号会把画面切到新摄像头，解绑会让地址立刻失效，两种情况都会把原来那路流停掉。**

播放地址绑的是**工单**不是设备，所以师傅换个摄像头（比如原来那台坏了），客户手里的地址不用换，下次拉流自动切到新的那一路——看到的仍然是自己这票货。解绑（传 `null`）则是彻底关掉，地址立刻报未绑定摄像头。

停流是外部调用，**失败不会让这次修改失败**（只记后端日志）。所以极小概率下会出现「编号已经改了、旧的那路流还在平台上推一会儿」，但客户那边**看不到**——画面必须经我们转发，转发时认的是工单当前绑的那台。等观看的人断开后视频平台会自己回收。

### 1.5 摄像头台账在哪

编号 → 设备的对应关系**写死在代码里**（`App/LoadingOrder/LoadingOrderCamera.cs`），没有表、没有增删改查接口。1.1 的可选列表就是把这份台账里**启用中**的行读出来，再叠上占用情况。

新增/停用摄像头要改代码并发版，步骤见该文件的注释。**重点是编号与名称必须和堆场里实际贴的号牌一致**——师傅是拿着列表去认现场那台设备的，对不上就会调错摄像头。

## 2. 公开端 开始点播 — `StartPlayAsync`

`POST /api/services/app/LoadingOrderVideo/StartPlayAsync`，请求体 `LoadingOrderVideoQueryDto`。

**免登录，不要带登录 token。**

### 2.1 入参

| 字段       | JSON              | 类型   | 必填 | 说明         |
| :--------- | :---------------- | :----- | :--- | :----------- |
| 主提单号   | `mblNum`          | string | 是   | **精确匹配** |
| 监装工单号 | `loadingOrderNum` | string | 是   | **精确匹配** |

两个号码必须匹配到**同一张工单**，与公开详情同一套口令。

### 2.2 出参 `LoadingOrderVideoPlayDto`

| 字段 | JSON | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| 摄像头对象 | `camera` | object | 见 2.3 |
| HTTP-FLV 播放地址 | `flvUrl` | string | 见 2.4 |
| 当前观看连接数 | `viewerCount` | int | **准确值**（由业务后端统计，不是估算），`0` 就是真的没人看 |
| 观看连接数上限 | `maxViewerCount` | int | 固定 3 |

### 2.3 `camera`

| 字段       | JSON       | 类型   | 说明 |
| :--------- | :--------- | :----- | :--- |
| 摄像头编号 | `cameraNo` | int    |      |
| 摄像头名称 | `name`     | string |      |

**刻意不返回设备国标编号与通道国标编号**，前端不需要，也不该拿着编号自己去请求视频平台。

### 2.4 `flvUrl`

**业务后端的转发地址**，形如 `https://你的域名/api/loading-order-video/stream/{监装工单id}.flv`。原样交给播放器即可。

> **没有有效期。** 工单没完成就一直能用，完成的那一刻立刻失效（见第 3 节）。所以长时间装箱不会中途断掉，前端也不用做「快到期了要续」这类逻辑。
>
> 协议（http/https）跟随你请求这个接口时用的协议，所以 HTTPS 页面拿到的就是 HTTPS 地址， **不会有混合内容问题**，也不需要前端判断该用哪个字段。

### 2.5 出参示例

```json
{
  "result": {
    "camera": { "cameraNo": 1, "name": "摄像头1" },
    "flvUrl": "https://api.example.com/api/loading-order-video/stream/11111111-1111-1111-1111-111111111111.flv",
    "viewerCount": 1,
    "maxViewerCount": 3
  }
}
```

### 2.6 行为说明（重点）

点播是一个**异步等设备出流**的请求，慢是正常的，前端要给足等待时间和 loading 态。

后端的执行顺序是「先数人 → 再点播 → 再给地址」：

```text
两个号码定位工单
  → 状态已完成？报「监装已完成,视频已关闭」
  → 没绑摄像头？报「该监装工单未绑定摄像头,暂无视频」
  → 当前连接数 >= 3 ？报「当前已有3人在观看,请稍后再试」
  → 调视频平台点播，把设备的流推起来
  → 返回转发地址
```

人数判断放在点播之前，满了就不必白跑一趟平台。**但这只是提前告知**——真正拦住第 4 个人的是转发接口（第 3 节），手上已经有地址的人可以跳过点播直接连，只有那一道拦得住。

同一路流**重复点播拿回的是同一个流**，不会叠加，所以刷新页面重新点播是安全的。

## 3. 画面转发地址 — `/api/loading-order-video/stream/{监装工单id}.flv`

**这个地址前端不用自己构造**，`StartPlayAsync` 返回的 `flvUrl` 就是它。这一节说明它的行为，便于处理播放器报错。

### 3.1 为什么要转发

视频平台的播放地址**是稳定的**——流 id 就是「设备国标编号\_通道国标编号」，同一个摄像头永远是同一串。而一个摄像头会被一张张工单轮流使用。谁把平台地址存下来，等这个摄像头轮到下一张工单（很可能是**别家客户的货**）时照样能打开。平台侧给不了任何补救手段（没有带过期时间的播放令牌、国标流的播放鉴权回调直接放行、停播是通道级的踢不掉单个人，见 `文档/监装/视频/对接.md` 第 8 节），所以访问控制只能我们自己做。

视频平台因此**只监听本机回环，外网连不上**。能拿到画面的只有转发这一个入口。

### 3.2 每次拉流都要过的四道

播放器**每次连接**（首次播放、断线重连、刷新页面）都会完整走一遍：

```text
地址里的工单 id 是个合法 Guid 吗
  → 这张工单还在吗
  → 是不是已完成
  → 还绑着摄像头吗
  → 占一个观看位（满 3 个就拒）
```

所以「监装完成 / 师傅解绑」是**立即生效**的。地址本身不带任何有效期，也没有签名——能不能看完全由这几道决定，没必要再加一层。

**师傅换摄像头不会让地址失效**：转发时认的是工单**当前**绑的那台，所以原来那台坏了换一台，客户手里的地址自动切到新的一路，不用重开页面。地址绑的是工单不是设备，切过去看到的仍然是自己这票货。

### 3.3 播放器会收到的状态码

| 状态码 | 含义 | 前端该怎么做 |
| :-- | :-- | :-- |
| 200 | 正常推流 |  |
| 403 | 地址失效：工单已完成、已被删除、摄像头已解绑，或地址被改坏了 | 提示重新打开页面；**不要自动重连** |
| 429 | 已有 3 路在看 | 提示稍后再试，给「重试」按钮，**不要自动无限重试** |
| 503 | 设备暂时没画面（掉线、流被回收） | 可以隔几秒重试一次 |

响应体是 `{ "message": "..." }`，**但播放器通常读不到它**——大多数 FLV 播放器只把非 200 当成加载失败，拿不到文案。要给用户准确提示，就在播放器报错时再调一次 `StartPlayAsync`，用它返回的业务错误文案来显示。

### 3.4 其它注意

- **同一个地址可以被多个人同时用**（它绑的是工单，不绑人），但每个连接各占一个名额。
- **地址失效不会掐断正在看的那条连接**，只是重连进不来。要立刻断开所有人只有两个来源：「监装完成」和「师傅换绑/解绑」——它们会停掉平台侧的流。
- 地址里能看到监装工单的 id，这是可以的：**没有任何免登录接口拿工单 id 当入参** （公开详情认的是主提单号 + 监装工单号）。以后加免登录接口时别把工单 id 当口令用。
- 转发是一条长连接，中间有 nginx 的话要确认没有为它设读超时（见第 9 节）。

## 4. 公开端 云台控制 — `PtzAsync`

`POST /api/services/app/LoadingOrderVideo/PtzAsync`，请求体 `LoadingOrderVideoPtzDto`。

### 4.1 入参

| 字段 | JSON | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 主提单号 | `mblNum` | string | 是 | 精确匹配 |
| 监装工单号 | `loadingOrderNum` | string | 是 | 精确匹配 |
| 云台指令 | `command` | int | 是 | 见 4.2 |
| 水平速度 | `horizonSpeed` | int? | 否 | 0–255，不传默认 100，超范围自动裁剪 |
| 垂直速度 | `verticalSpeed` | int? | 否 | 0–255，不传默认 100，超范围自动裁剪 |
| 变倍速度 | `zoomSpeed` | int? | 否 | 0–15，不传默认 10，超范围自动裁剪 |

**指令为「停止」时三个速度会被后端强制归零**，前端传什么都不影响。

### 4.2 云台指令枚举 `command`

| 值  | 名称     | 动作                             |
| :-- | :------- | :------------------------------- |
| 0   | 停止     | 停止转动，**松开方向按钮时发它** |
| 1   | 向左     |                                  |
| 2   | 向右     |                                  |
| 3   | 向上     |                                  |
| 4   | 向下     |                                  |
| 5   | 左上     |                                  |
| 6   | 右上     |                                  |
| 7   | 左下     |                                  |
| 8   | 右下     |                                  |
| 9   | 变倍放大 |                                  |
| 10  | 变倍缩小 |                                  |

### 4.3 出参

`result`：bool。

### 4.4 行为说明

**接口没有「移动几秒」这种时长参数**，只有「开始按某方向转」和「停」。所以交互必须是：

```text
按下方向按钮 → 发对应方向指令
松开方向按钮 → 发「停止」(command=0)
```

漏发「停止」云台就会一直转。变倍同理：按住发 `变倍放大`/`变倍缩小`，松开发 `停止`。

`result: true` 只代表指令下发成功，**不代表摄像头真的转了**——摄像头本身必须支持对应的云台能力。前端不要用返回值去断言画面已经变化，让用户自己看画面。

**云台是所有人共用的**，没有抢占机制。三个人同时按方向键，摄像头听最后一条指令。

## 5. 公开端 查询观看人数 — `GetViewerCountAsync`

`GET /api/services/app/LoadingOrderVideo/GetViewerCountAsync?mblNum=...&loadingOrderNum=...`

### 5.1 入参（query string）

| 字段       | JSON              | 类型   | 必填 | 说明     |
| :--------- | :---------------- | :----- | :--- | :------- |
| 主提单号   | `mblNum`          | string | 是   | 精确匹配 |
| 监装工单号 | `loadingOrderNum` | string | 是   | 精确匹配 |

**不需要传任何流标识。**

### 5.2 出参 `LoadingOrderVideoViewerCountDto`

| 字段 | JSON | 类型 | 说明 |
| :-- | :-- | :-- | :-- |
| 当前观看连接数 | `viewerCount` | int | **是连接数不是人数**，同一人多开页面算多个 |
| 观看连接数上限 | `maxViewerCount` | int | 固定 3 |

### 5.3 行为说明

数的是**正在经业务后端转发的连接**，是准确值，`0` 就是真的没人看，不存在「查不到」的情况。

想在播放页面上实时显示观看人数，轮询这个接口即可（建议 10 秒以上一次，它只是展示用）。

## 6. 为什么没有「停止播放」接口

**这是刻意不给的，不是漏了。**

视频平台的停播是**通道级**操作：一调就把整路画面掐了，正在看的其他人一起黑屏。放在免登录的公开端，等于给了任何人一个「让别人看不了」的按钮。

前端也不需要它：

- **退出页面只销毁播放器就行。** 转发连接一断，观看名额立刻释放；最后一个人走了之后，视频平台会按「无人观看」自动回收这路流（约 20 秒，见 `文档/监装/视频/对接.md` 第 11 节）。
- **真正要停流的三处全在后端**：监装完成、师傅换绑摄像头、师傅解绑摄像头。后端在这三处会主动停流，前端什么都不用做。

## 8. 前端适配清单

### 小程序（监装师傅端，工单详情页）

- [ ] 加一个「摄像头」选择项：点开时调 `GetCameraListAsync` 拉列表，选中后调 `EditCameraNoAsync` 保存
- [ ] 列表里 `isOccupied` 为 true 的**置灰不可选**；有 `occupiedLoadingOrderNum` 时把单号显示出来（「已被 JZ2026090001 占用」），没有时显示「已被其它工单占用」
- [ ] `isCurrent` 为 true 的那一项高亮为当前选中
- [ ] **只在已认领状态可编辑**；未提交/待认领时不显示这一栏（那时还没师傅），已完成时只读（这两个接口在非已认领状态都会报错，不要在这些状态下调）
- [ ] 已完成的工单：显示为空并提示「监装已完成，摄像头已释放」；想继续用要先「取消完成」再重新选
- [ ] 留一个「解绑」动作 = 传 `cameraNo: null`，操作前提示一句「解绑后客户将无法观看视频」
- [ ] 保存时被占用的报错直接展示后端文案，不要自己改写——**列表上的 `isOccupied` 只是提前告知**，拉完列表到点保存之间别人可能刚好占了同一台，真正的拦截在保存那一步

### 内部管理端（海运出口详情页 → 监装工单 tab）

- [ ] 摄像头一栏**只读展示** `camera.name`，**不提供任何编辑入口**——这个字段由师傅在现场维护

### 公开监装页（免登录）

- [ ] 播放器选支持 **HTTP-FLV** 的（Jessibuca、mpegts.js 等），`<video>` 标签不能直接播 FLV。 **不需要**判断 http/https，也**没有** HLS 兜底可选
- [ ] 进页面先调 `StartPlayAsync`，给足 loading（点播要等设备出流），把 `flvUrl` 原样交给播放器
- [ ] 播放器报加载失败时：重调一次 `StartPlayAsync`，用它的业务错误文案提示用户（播放器本身拿不到转发接口的 `message`）
- [ ] 报 `当前已有3人在观看,请稍后再试` 时给一个「重试」按钮，不要自动无限重试
- [ ] 报 `监装已完成,视频已关闭` 时把播放区换成结束态文案，**不要再重试**
- [ ] **不用做「地址快过期了要续」这类逻辑**，地址没有有效期，长时间装箱不会中途断掉
- [ ] 云台：按下发方向指令、**松开必须发 `command: 0`**；离开页面/组件卸载时也补发一次「停止」兜底
- [ ] 退出页面**只销毁播放器**就行，没有也不需要「停止播放」接口（见第 6 节）
- [ ] 观看人数用 `GetViewerCountAsync` 轮询，间隔 ≥ 10 秒
- [ ] **不必传租户**，后端按号码跨租户定位

## 9. 部署联调清单（后端/运维）

这些不是前端的事，但联调时最常卡在这里：

- [ ] **`WvpConfig.ApiKey` 已填**（初始是空串）且在视频平台里**有效且已启用**。只填 Key 本身，**不要带 `WVP_API_KEY=` 前缀**（平台控制台是按环境变量形式给的，整行粘过来会鉴权失败）。这个值和平台地址都**写死在 `App/ExternalApi/Wvp/WvpConfig.cs` 里，不在 `appsettings.json`**，改完要重新发版——不能靠改配置文件重启生效
- [ ] **视频平台 8080 端口不对外网开放。** 这是整套访问控制成立的前提：一旦外网能直连平台，客户就能拿到稳定的原始播放地址跨工单复用，转发就白做了
- [ ] 视频平台与业务服务**部署在同一台机器**（`WvpConfig.BaseUrl` 是 `http://127.0.0.1:8080`）。要拆开部署得先改这个常量，并且 `LoadingOrderVideoViewerCounter` 的进程内计数也要改成共享计数
- [ ] **业务服务不能多实例**：观看人数是进程内统计的，多开一个实例就等于上限翻倍
- [ ] nginx 为转发路径 `/api/loading-order-video/stream/` 关掉缓冲与读超时，否则长连接会被掐断： `proxy_buffering off; proxy_read_timeout 24h;`（后端已下发 `X-Accel-Buffering: no`，但读超时仍要配）
- [ ] 摄像头台账（`App/LoadingOrder/LoadingOrderCamera.cs`）里的设备/通道国标编号与平台一致
- [ ] 「无人观看自动回收」在线上确实生效：拿一路没人用的通道播一下再断开，观察平台的无人观看回调与停流日志（配置见 `文档/监装/视频/对接.md` 第 11.2 节）
