# 0. 先看这里

- **服务名**：`PersonalMailAdmin`，地址前缀 `/api/services/app/PersonalMailAdmin/`，**方法名里的 `Async` 不能省**。
- **鉴权**：要登录（`Authorization: Bearer <token>`），各接口要的权限见 0.1 的「权限」列。 `Admin.PersonalMail`（个人邮箱）既是菜单，也是**邮箱配置的全部权限**：有它就能对自己的邮箱配置增删改查、测试连接，个人设置页里的「邮箱配置」区按它显示。收发与整理邮件每个功能各有一个权限，按钮（回复、转发、删除等）按对应权限显示或隐藏。
- **只能操作自己的邮箱**：所有接口都没有用户 id 入参，后端一律按当前登录人查。
- **出参**：除「下载附件」直接返回文件流外，其余都包在 ABP 统一返回结构的 `result` 里。
- **系统里不存邮件原文**：邮件、草稿都在邮箱服务器上，系统每次实时去邮箱服务器取、只做转手。所以附件**不走系统的附件上传**，而是在发信请求里直接带文件内容（base64），见 6.2。
- **新邮件提醒**：后台每分钟检查一次每个人的收件箱，有新邮件就通过 SignalR 推给本人，见 5.3。

| :-- | :-- | :-- | :-- | :-- |
| 账号（个人设置页） | `GetMyAccountListAsync` | GET | `Admin.PersonalMail` 个人邮箱 | 我的个人邮箱列表（本期至多一条，不含密码） |

|  | `GetMailPagedListAsync` | POST | `Admin.PersonalMail.Get` 查看邮件 | 某个文件夹的邮件分页列表 |

|  | `ReplyAsync` | POST | `Admin.PersonalMail.Reply` 回复 | 回复 / 回复全部 |
|  | `ForwardAsync` | POST | `Admin.PersonalMail.Forward` 转发 | 转发 |

## 0.2 通用约定

- **`mailAccountId`**：所有收发接口都有这个可选字段，**本期不用传**——每人只能配一个邮箱，不传就用那一个。它是给以后「一人多个邮箱」留的口子，到时候传 `GetMyAccountListAsync` 返回的 `id`。
- **`folderName` + `uid` 定位一封邮件**：`uid` 是邮件在**这个文件夹里**的序号，只在 `folderName` 那个文件夹里有效，所以两个必须**成对**从列表里取、成对传回来。`folderName` 不传默认收件箱。
- **文件夹每次都实时取**：用户可能在手机或电脑客户端里新建、改名、删除文件夹，邮件数和未读数也一直在变，前端不要长期缓存文件夹列表，进页面或刷新时重新调 `GetFolderListAsync`。
- **同一个邮箱的请求会排队**：后端为每个邮箱最多保持 2 条到邮箱服务器的连接（复用连接，省掉每次登录），同一个人同时发出的请求超过 2 个就排队依次处理。排队 60 秒还没轮到会报 `邮箱正忙，请稍后重试`，一般是在发大附件邮件，稍后重试即可。前端不要为同一个邮箱并发发很多请求（例如一次性对每个文件夹各调一遍列表）。
- **请求体大小**：附件随请求以 base64 上传，服务器默认请求体上限约 30MB，折算下来**一封邮件的附件合计不要超过约 20MB**，超过会直接被 Web 服务器拒掉（不是业务报错）。各家邮箱自己也有大小限制，通常 20MB 到 50MB。

# 1. 个人邮箱账号（个人设置页）

## 1.1 我的个人邮箱列表 — `GET /api/services/app/PersonalMailAdmin/GetMyAccountListAsync`

无入参。返回数组，本期至多一条；空数组表示还没配置，个人设置页显示「新增」。

### 出参（数组元素 `PersonalMailAccountDto`）

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | Guid | 个人邮箱 id，修改、删除、测试时传它；收发接口的 `mailAccountId` 也是它 |
| `emailAddress` | string | 邮箱地址 |
| `displayName` | string | 发件人显示名称，可能为空 |
| `userName` | string | 登录用户名，可能为空（为空时用邮箱地址登录） |
| `hasPassword` | bool | 是否已经填过密码。**密码本身任何接口都不返回** |
| `imapHost` | string | 收信服务器地址 |
| `imapPort` | int | 收信服务器端口 |
| `imapEnableSsl` | bool | 收信是否启用 SSL |
| `smtpHost` | string | 发信服务器地址 |
| `smtpPort` | int | 发信服务器端口 |
| `smtpEnableSsl` | bool | 发信是否启用 SSL |
| `creationTime` | DateTime | 创建时间 |
| `creatorUserName` | string | 创建人昵称 |
| `lastModificationTime` | DateTime? | 最后修改时间 |
| `lastModifierUserName` | string | 最后修改人昵称 |
| `watchState` | 对象 | 新邮件提醒的状态，刚配好、后台还没检查过时为 `null`，字段见下表 |

`watchState`（`PersonalMailWatchStateDto`）：

| 字段                  | 类型      | 说明                             |
| :-------------------- | :-------- | :------------------------------- |
| `lastCheckTime`       | DateTime? | 上次检查时间                     |
| `consecutiveFailures` | int       | 连续失败次数，`0` 表示正常       |
| `lastFailureReason`   | string    | 最近一次失败的原因，正常时为空   |
| `nextCheckTime`       | DateTime? | 失败后下次检查的时间，正常时为空 |
| `isPaused`            | bool      | 是否已暂停提醒                   |

前端怎么用：`isPaused = true` 时在个人设置里醒目提示「邮箱授权码不正确，新邮件提醒已暂停，请重新填写授权码」； `consecutiveFailures > 0` 时可以把 `lastFailureReason` 作为提示显示。本人保存一次邮箱配置（改授权码或任何一项）后，失败计数清零、暂停恢复。

## 1.2 新增我的个人邮箱 — `POST /api/services/app/PersonalMailAdmin/AddMyAccountAsync`

### 入参（`PersonalMailAccountAddDto`）

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `emailAddress` | string | 是 | 邮箱地址，最长 128。只收纯地址，`张三 <a@b.com>` 这种写法会报格式不正确 |
| `displayName` | string | 否 | 发件人显示名称，最长 64，不填时收件人看到的是邮箱地址 |
| `userName` | string | 否 | 登录用户名，最长 128，不填时用邮箱地址登录（绝大多数邮箱不用填） |
| `password` | string | 是 | 邮箱密码，最长 128。**163、QQ、腾讯企业邮等多数邮箱要填「客户端授权码」而不是网页登录密码** |
| `imapHost` | string | 是 | 收信服务器地址，最长 128，例如 `imap.163.com`、`imap.exmail.qq.com` |
| `imapPort` | int | 否 | 收信端口，1~65535，默认 `993` |
| `imapEnableSsl` | bool | 否 | 收信是否 SSL，默认 `true`。`993` 配 `true`，`143` 配 `false` |
| `smtpHost` | string | 是 | 发信服务器地址，最长 128，例如 `smtp.163.com`、`smtp.exmail.qq.com` |
| `smtpPort` | int | 否 | 发信端口，1~65535，默认 `465` |
| `smtpEnableSsl` | bool | 否 | 发信是否 SSL，默认 `true`。`465` 配 `true`，`587` 配 `false`（走 STARTTLS） |

### 出参

新个人邮箱的 `id`（Guid）。

### 报错

| 情况 | 提示 |
| :-- | :-- |
| 已经配过一个 | `每人最多配置 1 个个人邮箱，请直接修改已有的那个` |
| 地址、服务器、端口、长度不合法 | 对应字段的提示，例如 `邮箱地址格式不正确`、`收信服务器端口必须在 1 到 65535 之间` |
| 服务器没配加密口令 | `系统未配置个人邮箱密码的加密口令，请联系管理员` |

**新增不会去连邮箱服务器**，填错了也能存进去。建议前端在保存前先调 1.5 测试一次。

## 1.3 修改我的个人邮箱 — `PUT /api/services/app/PersonalMailAdmin/EditMyAccountAsync`

### 入参（`PersonalMailAccountEditDto`）

在 1.2 全部字段的基础上多一个：

| 字段 | 类型 | 必填 | 说明                |
| :--- | :--- | :--- | :------------------ |
| `id` | Guid | 是   | 要修改的个人邮箱 id |

`password` **不填（空或只有空格）表示不改**——前端拿不到旧密码，表单里密码框默认留空即可，用户要换授权码时再填。其余字段按传入值整体覆盖（`displayName`、`userName` 传空就是清空）。

### 出参

无。

## 1.4 删除我的个人邮箱 — `DELETE /api/services/app/PersonalMailAdmin/DeleteMyAccountAsync`

### 入参

| 字段 | 类型 | 必填 | 说明                |
| :--- | :--- | :--- | :------------------ |
| `id` | Guid | 是   | 要删除的个人邮箱 id |

只删系统里的这条配置，**邮箱服务器上的邮件不受影响**。

## 1.5 测试我的个人邮箱 — `POST /api/services/app/PersonalMailAdmin/TestMyAccountAsync`

用**页面上当前填的配置**分别去登录收信服务器和发信服务器，不保存任何东西。

### 入参（`PersonalMailAccountEditDto`，同 1.3）

| 情况                   | 怎么传                                       |
| :--------------------- | :------------------------------------------- |
| 新增页（还没保存）     | 不传 `id`，`password` 必填                   |
| 修改页，用户重填了密码 | 传 `id` 和新 `password`                      |
| 修改页，没动密码框     | 传 `id`，`password` 留空，后端用已存的密码测 |

格式校验与 1.2 相同，不通过时直接报错，不会去连服务器。

### 出参（`MailConnectionTestResult`）

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `imapSuccess` | bool | 收信服务器是否连接、登录并能打开收件箱（有的邮箱登录能过、打开文件夹才被拒，所以连收件箱一起测） |
| `imapMessage` | string | 收信结果说明。失败时是原因，例如 `邮箱账号或密码(授权码)不正确，无法登录邮箱收信服务器` |
| `smtpSuccess` | bool | 发信服务器是否连接并登录成功 |
| `smtpMessage` | string | 发信结果说明。失败时是原因 |

连不上、登不进**不会抛错**，而是两边各自给结论，前端分两行展示即可。

# 2. 查看邮件

## 2.1 文件夹列表 — `GET /api/services/app/PersonalMailAdmin/GetFolderListAsync`

### 入参（Query）

| 字段            | 类型 | 必填 | 说明             |
| :-------------- | :--- | :--- | :--------------- |
| `mailAccountId` | Guid | 否   | 见 0.2，本期不传 |

### 出参（数组元素 `MailFolderSummary`）

排序：收件箱、草稿箱、已发送、垃圾邮件、已删除依次在最前，其余按邮箱服务器给的顺序。

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `name` | string | 文件夹显示名 |
| `fullName` | string | 文件夹全名，**查列表、移动邮件时传它**（子文件夹的全名带上级路径） |
| `isInbox` | bool | 是否收件箱 |
| `isDrafts` | bool | 是否草稿箱 |
| `isSent` | bool | 是否已发送 |
| `isTrash` | bool | 是否已删除。在这个文件夹里删除就是彻底删除 |
| `isJunk` | bool | 是否垃圾邮件 |
| `totalCount` | int | 邮件总数，取不到时为 `-1`，前端不显示数字 |
| `unreadCount` | int | 未读数，取不到时为 `-1` |

邮箱没有某个特殊文件夹时，对应标记全部为 `false`（例如找不到草稿箱就存不了草稿，见 3.4）。

## 2.3 邮件详情 — `POST /api/services/app/PersonalMailAdmin/GetMailAsync`

### 入参（`PersonalMailDetailQueryDto`）

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |

### 出参（`MailDetail`）

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `replyTo` | 数组 | 对方指定的回复地址，元素见 6.1 |

| `attachments` | 数组 | 附件清单，元素见 6.3 |

> 渲染 `htmlBody` 时请放进 `<iframe sandbox>` 里，**不要直接 `v-html` 到页面上**：邮件 Html 来自外部发件人，直接插进页面会执行其中的脚本、改写页面样式。

## 2.4 下载附件 — `POST /api/services/app/PersonalMailAdmin/DownloadAttachmentAsync`

### 入参（`PersonalMailAttachmentQueryDto`）

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `mailAccountId` | Guid | 否 | 见 0.2 |
| `folderName` / `uid` / `messageId` |  |  | 同 2.3 |
| `attachmentIndex` | int | 是 | 附件序号，传详情里附件的 `index` |

### 出参

**直接是文件流**（不包 `result`），`Content-Type` 是附件的类型，`Content-Disposition` 带文件名。前端用 `responseType: 'blob'` 接收；文件名直接用详情里的 `fileName`，不必解析响应头。

附件序号跟着邮件结构走，**要先拿详情、再按详情里的 `index` 下载**，不要把 `index` 存下来隔很久再用。

# 3. 发邮件

发信成功后默认往邮箱的「已发送」文件夹存一份副本。**发出去之后**的收尾动作（存已发送、标记已回复、删旧草稿）失败只记日志、不报错——邮件已经发出去了，再报错会让人以为没发成功而重发，同一封邮件重复发给客户。

发送失败时的提示只说类别，不带邮件服务器原文（原文里常带收件人地址，属于邮件信息）：

| 提示 | 常见原因 |
| :-- | :-- |
| `邮件发送失败：有收件人地址被邮件服务器拒收，请检查收件人地址是否正确（状态码 550）` | 收件人地址不存在、拼错 |
| `邮件发送失败：发件人地址被邮件服务器拒绝，请检查个人邮箱配置里的邮箱地址（状态码 …）` | 配置的邮箱地址和登录账号对不上 |
| `邮件发送失败：邮件被邮件服务器拒收，可能是附件过大、发送太频繁或内容被判为垃圾邮件（状态码 …）` | 附件超限、频率超限、反垃圾 |
| `邮件发送失败，请稍后重试` | 网络中断等 |
| `收件人里第 2 个邮箱地址格式不正确` | 地址格式不对，提示只说第几个，不回显地址本身 |

## 3.1 写新邮件 — `POST /api/services/app/PersonalMailAdmin/SendAsync`

### 入参（`PersonalMailSendDto`）

| 字段 | 类型 | 必填 | 说明 |

# 4. 整理邮件

三个接口都是**同一个文件夹里的若干封**批量处理，`uids` 一次最多 500 个。

| 公共字段        | 类型   | 必填 | 说明                                     |
| :-------------- | :----- | :--- | :--------------------------------------- |
| `mailAccountId` | Guid   | 否   | 见 0.2                                   |
| `folderName`    | string | 否   | 这些邮件所在的文件夹全名，不传默认收件箱 |
| `uids`          | uint[] | 是   | 邮件序号，取自这个文件夹的列表           |

出参都为空。邮件已被别处移走或删掉时报 `…失败，邮件可能已被移动或删除，请刷新列表后重试`。文件夹只有只读权限时报 `这个邮箱文件夹只有只读权限，不能修改其中的邮件`。

## 4.1 标记已读 / 未读 — `POST /api/services/app/PersonalMailAdmin/SetReadAsync`

| 字段     | 类型 | 必填 | 说明                              |
| :------- | :--- | :--- | :-------------------------------- |
| `isRead` | bool | 是   | `true` 标记已读，`false` 标记未读 |

## 4.2 移动 — `POST /api/services/app/PersonalMailAdmin/MoveAsync`

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| `targetFolderName` | string | 是 | 移到哪个文件夹，传 2.1 的 `fullName`，不能和 `folderName` 相同 |

移过去之后邮件的 `uid` 会变（新文件夹里重新编号），移动后请刷新列表。

## 4.3 删除 — `POST /api/services/app/PersonalMailAdmin/DeleteAsync`

| 字段        | 类型 | 必填 | 说明                       |
| :---------- | :--- | :--- | :------------------------- |
| `permanent` | bool | 否   | 是否彻底删除，默认 `false` |

| 情况 | 结果 |
| :-- | :-- |
| `permanent = false`，邮件不在「已删除」里 | 移到「已删除」文件夹，可以再移回来 |
| 邮件本来就在「已删除」里（`isTrash = true` 的文件夹） | **彻底删除**，无论 `permanent` 传什么 |
| `permanent = true` | 彻底删除，不可恢复 |
| 邮箱里认不出「已删除」文件夹且没要求彻底删除 | 报 `邮箱里找不到「已删除」文件夹，无法移入；如需直接删除请选择彻底删除` |

彻底删除前端务必二次确认。

# 5. 典型流程

## 5.1 草稿箱

1. 写信页点「存草稿」→ `SaveDraftAsync`（不传 `draftUid`）→ 记下返回的 `uid`。
2. 继续编辑再点「存草稿」→ `SaveDraftAsync`，`draftUid` = 上次的 `uid`，`keepDraftAttachmentIndexes` = 仍保留的旧附件 → 记下新 `uid`。
3. 从草稿箱打开一封草稿：`GetMailAsync`（`folderName` = 草稿箱 `fullName`，`uid`，**`markAsRead: false`**），把 `to`/`cc`/`bcc`/`subject`/`htmlBody` 回填到写信页；`attachments` 里 `isInline = false` 的列成「已有附件」，用户删掉哪个，提交时 `keepDraftAttachmentIndexes` 就不带它的 `index`。
4. 点「发送」→ `SendAsync`，带上 `draftUid` 和 `keepDraftAttachmentIndexes`，发出后草稿自动删除。
5. 不要了 → `DeleteAsync`（`folderName` = 草稿箱）。

## 5.2 回复写到一半存草稿

`ReplyAsync` 是一步发出，不支持中途保存。需要「回复存草稿」时，前端按写新邮件处理：收件人、`Re: 主题`、正文（需要引用原文的话自己拼进正文）都由前端填好，**另外传 `inReplyToMessageId` = 原邮件的 `messageId`**，之后存草稿、发出都走 3.4 / 3.1，对方仍能把它串进原来的会话。

注意这样发出的回复**不会**给原邮件打「已回复」标记（后端不知道原邮件在哪个文件夹）。

## 5.3 实时推送：新邮件提醒

后台每分钟检查一次每个人的收件箱，有新邮件就推给**邮箱本人**登录着的所有页面。不是接口，前端连 SignalR 监听：

- **连接**：系统已有的 `/signalr`（ABP 的 AbpCommonHub），登录后连上即可。SignalR 不能带 `Authorization` 头，身份放在地址的查询串里：`/signalr?enc_auth_token=<登录接口返回的 encryptedAccessToken，用 encodeURIComponent 编码>`，**没带或带错就收不到推送**（连接本身不报错）。
- **事件名**：`personalMail.received`，例如 `connection.on('personalMail.received', payload => { ... })`。
- **只推给本人**，本人不在线就不推，推送内容**不保存**，离线期间到的邮件不会补推（打开邮箱页看未读即可）。
- 第一次配好邮箱时，邮箱里已有的邮件不提醒，只提醒之后新到的。
- 新邮件到了最长约 1 分钟后提醒。

payload（`PersonalMailReceivedPushDto`）：

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `mailAccountId` | Guid | 哪个个人邮箱，同 1.1 的 `id` |
| `folderName` | string | 新邮件所在文件夹全名，本期固定 `INBOX`（收件箱） |
| `newCount` | int | 这一轮新到几封 |
| `mails` | 数组 | 最新几封的摘要，**最多 5 封，最新的在前**，不含正文；元素同 2.2 的 `MailSummary`，提醒里一般显示 `from` 和 `subject` |

建议：弹出提醒「`from.name`（没有就用 `from.address`）：`subject`」，超过 5 封显示「等 N 封新邮件」；点提醒打开邮件时用 `folderName` + `uid` 调 `GetMailAsync`；正停在收件箱列表上时可以顺便刷新列表和文件夹未读数。
