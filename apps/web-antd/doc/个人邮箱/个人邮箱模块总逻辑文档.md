# 1. 业务背景说明 (Background)

**白话解释：** 业务员每天大量的报价、订舱确认、放单催付都在自己的邮箱里来回。个人邮箱让每个人把**自己的**邮箱接进系统：在个人设置里填一次邮箱地址、授权码和收发信服务器，之后就能在系统里看自己邮箱的各个文件夹、翻邮件、看正文和附件，写新邮件、回复、转发、存草稿，以及标记已读未读、移动、删除。

三条硬要求贯穿整个模块：

- **私人的**：每个人只能配置、使用自己的邮箱。邮箱配置只在个人设置里能看能改，**用户管理里看不到**；所有接口都不接受用户 id，一律按当前登录人取数。
- **系统里不保存任何邮件内容**，防止信息泄露：邮件和草稿都在邮箱服务器上，系统每次实时去取、只做转手；发信附件随请求传进来只在内存里用一次，不经过系统附件上传；审计日志、运行日志、报错文案里都不出现邮件内容。
- **权限**：`Admin.PersonalMail`（个人邮箱）既是菜单，也管邮箱配置——有它就能对自己的邮箱配置增删改查、测试连接；查看邮件、下载附件、写邮件、回复、转发、存草稿、标记已读未读、移动、删除各有一个权限，接口只校验自己那个，见 2.1。

底层收发能力复用 `IMailboxService`（见 `文档/邮件/邮件模块总逻辑文档.md`），本模块负责账号存储、密码加解密、按当前登录人取账号、把前端入参转成邮件服务的入参。

# 2. 功能与操作说明 (Features & Operations)

| 功能 | 接口 | 说明 |
| :-- | :-- | :-- |
| 查看我的邮箱配置 | `GetMyAccountListAsync` | 本期至多一条，不返回密码，只返回是否填过 |
| 新增邮箱配置 | `AddMyAccountAsync` | 每人一个，密码加密后入库 |
| 修改邮箱配置 | `EditMyAccountAsync` | 密码不填表示不改 |
| 删除邮箱配置 | `DeleteMyAccountAsync` | 只删系统里的配置，邮箱里的邮件不受影响 |
| 测试连接 | `TestMyAccountAsync` | 用页面上填的配置分别登录收信、发信服务器，不保存 |
| 文件夹列表 | `GetFolderListAsync` | 每次实时取，带邮件数、未读数和草稿箱/已发送/已删除/垃圾邮件标记 |
| 邮件列表 | `GetMailPagedListAsync` | 按文件夹分页，支持关键字、只看未读、时间范围 |
| 邮件详情 | `GetMailAsync` | 正文里的内嵌图片已换成 data URI，前端可直接渲染 |
| 下载附件 | `DownloadAttachmentAsync` | 文件流 |
| 写新邮件 | `SendAsync` | 也用于把草稿发出去 |
| 回复 / 回复全部 | `ReplyAsync` | 串进原会话，标记原邮件已回复 |
| 转发 | `ForwardAsync` | 附言 + 原文引用，默认带原附件 |
| 存草稿 | `SaveDraftAsync` | 存进邮箱服务器的草稿箱，再次保存时替换旧草稿 |
| 标记已读 / 未读 | `SetReadAsync` | 批量 |
| 移动 | `MoveAsync` | 批量 |
| 删除 | `DeleteAsync` | 批量，默认移到「已删除」，在「已删除」里再删或要求彻底删除时直接删掉 |

## 2.1 权限

```
个人邮箱                Admin.PersonalMail                 菜单 + 邮箱配置：GetMyAccountListAsync、AddMyAccountAsync、
│                                                          EditMyAccountAsync、DeleteMyAccountAsync、TestMyAccountAsync
├─ 查看邮件             Admin.PersonalMail.Get             GetFolderListAsync、GetMailPagedListAsync、GetMailAsync
├─ 下载附件             Admin.PersonalMail.Download        DownloadAttachmentAsync
├─ 写邮件               Admin.PersonalMail.Send            SendAsync（含把草稿发出去）
├─ 回复                 Admin.PersonalMail.Reply           ReplyAsync
├─ 转发                 Admin.PersonalMail.Forward         ForwardAsync
├─ 存草稿               Admin.PersonalMail.Draft           SaveDraftAsync
├─ 标记已读未读         Admin.PersonalMail.SetRead         SetReadAsync
├─ 移动邮件             Admin.PersonalMail.Move            MoveAsync
└─ 删除邮件             Admin.PersonalMail.Delete          DeleteAsync（含删草稿）
```

- 邮箱配置不再细分权限：配的是自己的邮箱，能进个人邮箱菜单的人就该能配，拆开只会多出「能进菜单却配不了邮箱」这种没意义的组合。
- 文件夹列表、邮件列表、详情是同一个功能「看邮件」，单独给其中一个没有意义，所以共用 `Get`。
- 权限只决定「能不能用这个功能」，「用的是谁的邮箱」永远是当前登录人自己的，任何权限都不能看别人的邮箱。

## 2.2 其他说明

- **一人多个邮箱的口子**：表结构 `UserId` 不唯一，所有收发接口都带可选的 `MailAccountId`。本期新增时限制每人一个（`PersonalMailAdminAppService.MaxAccountCountPerUser = 1`），`MailAccountId` 不传就用唯一那个。以后放开时改这个常数；同时一人有多个邮箱而前端没传 `MailAccountId` 时会报「请指定要使用哪一个」，届时可再加「默认邮箱」字段。
- **与 User 表上邮箱字段的关系**：`User` 上的 `EmailPwd`、`ReceiveAddrPort`、`SendAddrPort`、`SenderDisplayName` 只是记录展示用，本模块**不读不写**它们，用户管理里照旧显示，两边互不影响。

# 3. 状态流转说明 (Status Transitions)

邮箱配置没有状态。邮件的状态全部在邮箱服务器上：

| 当前状态 | 触发人/动作 | 目标状态 | 状态说明 |
| :-- | :-- | :-- | :-- |
| 未读 | 打开详情（`markAsRead` 默认 true） | 已读 | 只读权限的文件夹会静默跳过 |
| 已读 / 未读 | `SetReadAsync` | 未读 / 已读 | 批量 |
| 收到的邮件 | `ReplyAsync` 成功 | 已回复 | 标记失败只记日志 |
| 任意文件夹的邮件 | `DeleteAsync`（非彻底） | 在「已删除」里 | 可再 `MoveAsync` 移回 |
| 「已删除」里的邮件 | `DeleteAsync` | 彻底删除 | 不可恢复 |
| 草稿 | 再次 `SaveDraftAsync`（带 `DraftUid`） | 新草稿替换旧草稿 | 旧草稿删除失败只记日志，草稿箱里会多留一封 |
| 草稿 | `SendAsync`（带 `DraftUid`） | 已发送里的邮件，草稿删除 | 同上 |

# 4. 核心字段说明 (Field Definitions)

## 4.1 个人邮箱账号 `App_PersonalMailAccounts`（实体 `PersonalMailAccount`）

| 字段名 | 📖 字段含义说明 | 🔌 数据来源 | 🔗 联动规则 | 🛡️ 校验限制 |
| :-- | :-- | :-- | :-- | :-- |
| **Id** | 主键 Guid | 新增时生成 | 收发接口的 `MailAccountId` 就是它 | — |
| **TenantId** | 租户 | 登录态 | — | 自动填 |
| **UserId** | 归属人 | 新增时取当前登录人 | 所有接口都按它过滤 | 不接受前端传入 |
| **EmailAddress** | 邮箱地址，也是发件人地址 | 用户填写 | — | **必填**，最长 128，只收纯地址（`张三 <a@b.com>` 报格式不正确） |
| **DisplayName** | 发件人显示名称 | 用户填写 | 不填时收件人看到的是邮箱地址 | 最长 64 |
| **UserName** | 登录用户名 | 用户填写 | 不填时用邮箱地址登录 | 最长 128 |
| **PasswordCipher** | 密码（授权码）的密文 | 新增/修改时由明文加密 | 任何接口都不返回，只返回 `HasPassword` | **必填**，最长 512 |
| **ImapHost / ImapPort / ImapEnableSsl** | 收信服务器 | 用户填写 | — | 地址**必填**最长 128；端口 1~65535，默认 993；SSL 默认是 |
| **SmtpHost / SmtpPort / SmtpEnableSsl** | 发信服务器 | 用户填写 | — | 地址**必填**最长 128；端口 1~65535，默认 465；SSL 默认是 |

继承 `FullAuditedEntity<Guid>`（软删除），实体上标了 `[DisableAuditing]`，不进实体变更历史。

## 4.2 密码加解密

- 授权码要还原成明文才能去登录邮箱，所以只能**可逆加密**，不能哈希。
- 复用 `CloudSecretCipher`（AES-256-CBC，PBKDF2 十万次，每次随机盐和 IV），口令取配置 **`PersonalMail:PasswordCipherKey`**（`appsettings.json`）。
- 效果：只拿到数据库解不出密码；数据库和配置文件同时泄露才能解。
- **口令上线后不能改**：改了库里已有的密文全部解不开，用户收发时会提示「个人邮箱密码无法解密，请在个人设置里重新填写」。每个客户服务器部署时应换一个自己的随机串。
- 口令没配时新增/修改/收发都报「系统未配置个人邮箱密码的加密口令，请联系管理员」。

## 4.3 收发入参

收发接口的入参都是 `IMailboxService` 入参外面加一个 `MailAccountId`，字段口径见邮件模块文档。差异只有附件：

| 字段名                     | 📖 字段含义说明            | 🛡️ 校验限制    |
| :------------------------- | :------------------------- | :------------- |
| **Attachments[].FileName** | 附件文件名                 | **必填**       |
| **Attachments[].Content**  | 文件内容，JSON 里是 base64 | **必填**，非空 |

前端**不能**传下载地址：邮件服务支持「给地址由后端下载」，但开放给前端就等于让服务器替人访问任意网址，所以应用层的附件 DTO 只有文件名和内容两个字段。

# 5. 核心业务卡点 (Business Blockers)

> [!IMPORTANT] **卡点 1：系统里不保存任何邮件内容** 落到实现上是这几处，改代码时不能破坏：
>
> 1. 不建任何存邮件的表；**文件夹列表也不保存、不缓存，每次实时取**（2026-10-01 已确认）。理由：用户会在手机、Outlook、网页邮箱里增删改自建文件夹，系统感知不到，存下来就会过期（点到已删的文件夹报错、新建的看不到）；文件夹页本来就要实时取邮件数和未读数，多取一次列表只多一条命令，存了也省不下什么；自建文件夹名常带客户名、业务内容，本身就是邮件信息。以后如果发信速度成了问题，可以考虑只在内存里缓存「已发送 / 草稿箱 / 已删除」这三个文件夹的全名（不进库、带过期），其余照旧实时取。
> 2. 发信附件随请求以 base64 传入，只在内存里用，**不走** `UploadController` / `App_Attachments`。
> 3. `PersonalMailAdminAppService` 标了 `[DisableAuditing]`：项目开着 ABP 审计，不关的话每次调用的入参（主题、收件人、正文、附件、新增配置时的明文密码）都会写进 `AbpAuditLogs`。
> 4. 日志不写主题、正文、收件人、搜索关键字、发信服务器回执；**抛给前端的报错也不写**——ABP 会把 `UserFriendlyException` 按 WARN 记进日志文件（log4net 根级别 WARN），报错文案等于日志。所以地址格式错误只提示「抄送里第 2 个邮箱地址格式不正确」，发信失败只给类别和状态码。
> 5. 草稿存在邮箱服务器的草稿箱里。

> [!IMPORTANT] **卡点 2：只能操作自己的邮箱** 所有接口没有用户 id 入参；按 id 取邮箱时条件里一律带 `UserId == 当前登录人`，别人的邮箱 id 传进来提示「个人邮箱不存在」，不区分越权和不存在（区分了就成了探测别人有没有配邮箱的工具）。

> [!IMPORTANT] **卡点 3：新增配置不验证能不能登录** 新增、修改只做格式校验，不连邮箱服务器（邮箱服务器临时连不上时也要能先存）。前端应在保存前调 `TestMyAccountAsync`。测试接口在修改页密码框留空时用已存的密码测，不用为了测一下再去翻授权码。

> [!IMPORTANT] **卡点 4：附件大小受请求体上限约束** 附件随请求 base64 上传，体积膨胀约三分之一。IIS / Kestrel 默认请求体上限约 30MB，折算附件合计约 20MB，超过直接被 Web 服务器拒掉。确实需要更大附件时改服务器的请求体上限，但邮箱服务器自己通常也只收 20MB~50MB。

> [!IMPORTANT] **卡点 5：「回复存草稿」走写新邮件** `ReplyAsync` 一步发出，不能中途保存。要存草稿时前端按写新邮件组装，并传 `InReplyToMessageId`（原邮件 `MessageId`），发出后仍串进原会话；但这样发出的回复不会给原邮件打「已回复」标记。

> [!IMPORTANT] **卡点 6：删除用户时一起删掉他的个人邮箱** `UserAdminAppService.DeleteUsersAsync` 删完用户后按 `UserId` 删掉 `App_PersonalMailAccounts`，加密后的密码不留在库里。本表没有子表，别的模块也不引用它，删除个人邮箱时不需要清其他数据。
