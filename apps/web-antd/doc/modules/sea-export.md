# SeaExport 模块活文档

## 模块定位

- 模块名称：海运出口委托管理。
- 业务作用：承接主流程起点，负责出口委托单的创建、编辑与子业务入口汇聚。
- 主要目录：`apps/web-antd/src/views/sea-export-admin/`。

## 菜单与入口

- 路由定义：`apps/web-antd/src/router/routes/modules/sea-export.ts`
- 入口路由：
  - `/sea-exports`：列表页
  - `/sea-exports/create`：新建页
  - `/sea-exports/:id/edit`：编辑页（`id` 为 GUID）

## 页面结构与核心逻辑

### 1) 列表页（`list.vue`）

- 通过分页查询接口加载海运出口委托列表。
- 支持查询条件筛选、进入编辑、删除等常规操作。
- 双击或操作动作可进入对应委托编辑页。

### 2) 新建页（`form.vue` 非嵌入模式）

- 用户填写基础字段并提交，调用新增接口创建委托。
- 创建成功后以新委托 `id` 跳转到编辑页，进入完整业务态。

### 3) 编辑页（`editor.vue`）

- 编辑页是海运出口模块的核心业务容器。
- 顶部 Tab 当前可用子模块：
  - `basic`：基础信息
  - `party`：更改单
  - `fee`：应收应付费用
  - `dispatch`：派车
  - `billInfo`：分单
- 同时存在 `shipment`、`port`、`issueRecord`、`changeHistory` 标签，但当前未见对应内容挂载实现。

## 核心数据对象（前端可见）

- `SeaExportDto`：海运出口主维度字段（港口、船名航次、船公司、服务项等）。
- `transportOrder`：委托单业务字段（委托编号、主提单号、订舱号、件毛体、账期相关字段、锁定状态等）。
- 编辑态通常将两者展平用于页面显示，再在提交时重组为后端 DTO。

## 关键业务流程

1. 列表检索并选中目标委托。
2. 新建或进入编辑页维护基础信息。
3. 在同一编辑容器内进入费用、更改单、派车、分单模块处理后续业务。
4. 将费用与审核、申请、结算链路向后传递。

## 状态与联动（海运出口视角）

- 费用锁定：通过 `transportOrder.feeLocked` 体现是否允许费用继续改动。
- 业务锁定：`transportOrder.isBusinessLocking` 反映整票业务锁定状态。
- 这两个状态会在列表、只读区和相关子模块中参与可编辑性判断。

## 与主流程上下游关系

- 上游：客户、基础资料（港口/船公司/币别/费目等）提供主数据选择源。
- 下游：应收应付（OrderFee）是付费申请与结算链路的数据基础。
- 并行链路：更改单、派车、分单分别在业务执行层面补充主单信息。

## 产品/测试关注点

- 入口闭环：列表 -> 新建 -> 编辑 的跳转与数据回填必须稳定。
- 子模块可达性：确认当前真正可操作的 Tab 与路由行为一致。
- 状态一致性：锁费/业务锁定在列表与编辑页展示是否一致。
- 字段来源：主单字段与运输单字段是否在详情接口中完整回传。

## 已知边界与注意事项

- 现阶段部分 Tab 仅有标签未挂载内容，测试用例应聚焦已实现模块。
- 文档描述基于前端可见逻辑；税务、结算公式、最终账务处理规则需以后端为准。
- 历史只读展示优化（ellipsis + title）仍有效，属于基础信息展示层的通用能力。
