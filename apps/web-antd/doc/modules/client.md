# Client 模块活文档

## 模块范围

- 页面范围：`apps/web-antd/src/views/client/`（客户列表、客户资料、联系人与账期等客户域页面）。
- 本次聚焦：`list.vue` 与 `base/data.ts` 的列表交互模式改造。

## 核心逻辑（当前现状）

- 客户列表已取消行内“编辑/删除”操作列，改为顶部统一操作按钮。
- 表格首列启用 checkbox 多选，所有编辑/删除动作基于当前勾选集触发。
- 列表支持双击行快速进入编辑页（checkbox 选择列除外），用于高频单条编辑。
- 顶部“修改”按钮仅在勾选 1 条时可点击，点击后进入该客户编辑页。
- 顶部“删除”按钮在勾选至少 1 条时可点击，删除前会弹出二次确认。
- 删除接口按 `ids` 批量提交，删除完成后自动刷新列表。
- 客户新建页 `base/form.vue` 现已固定为单元素根节点，兼容 `RouterView` 外层 `Transition` 动画与运行时指令挂载。

## 当前架构与约束

- 选择状态由 `gridApi.grid.getCheckboxRecords()` 统一读取，通过 `checkboxChange/checkboxAll` 事件保持同步。
- 双击进入编辑通过 `cellDblclick` 事件统一处理，避免维护额外路由分支。
- 查询、刷新、翻页前会清空勾选状态，防止跨页残留导致误操作。
- 行级快捷入口已收敛到顶部统一按钮，便于后续扩展批量业务动作。
- `ClientCreate` 页面不可使用多根节点（fragment）作为模板根；弹窗组件需置于同一主容器内。

## 注意事项

- 若后续新增“批量启用/停用”等动作，优先复用当前顶部按钮与勾选状态机制。
- 删除动作必须保持二次确认，不应绕过确认直接提交。
- 如果表格切换到 `reserve: true`，需重新评估跨页勾选与误删风险控制策略。
- 若再次出现路由切换空白并伴随 Vue `Transition`/directive 警告，优先排查页面模板是否退化为多根节点。
