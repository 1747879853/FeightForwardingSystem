# 船期查询 · 给 UI 的设计说明

2026-09-02 已按桌面设计稿还原 `/schedule` 实现；查询范围已固定 8 周，最近航线记在「最近查询」胶囊里点选再查，进页不回填查询条。下文仍是给设计的原始约束，分组规则不要改。

本地可看：登录后打开船期查询，起运 `CNTAO`、目的 `SGSIN`、离港 `2026-09-01`、范围 8 周。典型结果大约 **62 个方案、613 条班次**。这是设计要扛住的密度，不是演示用的 5 条假数据。

---

## 1. 你要解决什么问题

货代操作 / 航线同事要在几分钟内回答：

1. 这条港到港，有哪些**船公司共舱服务**可以走？
2. 同一服务未来几周有哪些船、哪天开、航程几天、**截关何时**？
3. 两三条服务摊开，比航程、比离港、比截关。

**主角是方案列表。**  
查询条件和筛选是工具，不是看板。不要做「62 个方案 / 613 个班次」这种大数字卡片——同事已经知道自己在查船期，不需要再看一遍统计。

港口名用英文（如 QINGDAO / CNTAO）可以，不要为了中文化硬改。

---

## 2. 用户与场景

| 项 | 说明 |
| :-- | :-- |
| 用户 | 货代操作、航线；每天在本系统里开委托、查船期、对截关 |
| 环境 | 宽屏桌面，嵌在现有后台（左侧菜单 + 顶栏）。不是独立营销站，也不是小程序 |
| 频率 | 同一航线反复查、换周数再查、筛一家船公司再对照 |
| 情绪 | 要快、要准、要能并排看；不需要「探索感」和装饰 |

**主路径**

1. 选起运港、目的港、离港日起、查询周数 → 点查询（可回车）。
2. 扫方案卡：星期、直达/中转、航程、共舱名、最近一班、截关。
3. 展开 1～3 张卡，看班次表，点船名看船位，点详情看全字段。
4. 用直达/中转、船公司、码头、关键词收窄，**不再打接口**。

**次路径：** 交换起运/目的；复制共舱名称去聊天；失败重试。

---

## 3. 两个对象，不要混成一张宽表

以前是几百行扁平船期表，已经否定。现在必须是两层：

| 对象 | 一句话 | 用户怎么用 |
| :-- | :-- | :-- |
| **方案** | 一条共舱服务。例：`CNC(KCS)`、`HMM(NW3)/HPL(TPM)/ONE(AX3)` | 先扫、再决定展开哪几张 |
| **班次** | 这张方案里具体的船名 + 航次 + 日期 | 展开后比较各周船 |

同一方案会把未来 8 周的船收在一张卡里。星期、航程、码头**只展示，不把同一服务拆成几十张卡**。

共舱名称可能很长，例如：

`JINJIANG(NWX)/KMTC(NWX)/MSK(FI3)/ONE(NPI)`

请按长标题设计（折行、截断 + 悬停全称、复制），不要当成短 Tag。

---

## 4. 信息层级（请按这个排视觉权重）

从高到低：

1. **方案卡列表**（查询后第一屏就要看到，至少露出 2～3 张卡）
2. 展开后的 **班次表**（订舱对照：船、航次、离到港、截关、航程）
3. **查询条**（港口、日期、周数、查询按钮）
4. **二次筛选**（直达/中转、船公司、码头、关键词、排序）
5. 详情抽屉、船舶定位弹窗

查询条和筛选可以收成一条工具栏，滚动时可以吸顶，但高度要克制，不能把列表顶出屏幕。

---

## 5. 必须出现的信息

设计可以改位置、字号、是否用图标，**不能删字段含义**。

### 5.1 查询（打接口）

- 起运港、目的港（下拉，值是五字码）
- 交换起运/目的
- 预计离港日期
- 查询范围 1～8 周
- 主按钮：查询  
  未选港口/日期要点明缺什么。

### 5.2 方案卡（折叠态，扫读）

请明确主标题、辅助信息，避免一行塞十个同等权重的格子。

| 信息 | 备注 |
| :-- | :-- |
| 共舱名 `groupName` | 方案身份，最重要的识别 |
| 直达 / 中转 | 中转可带「经 xx」 |
| 班期星期 | 如星期一 |
| 班次数 | 如 9 班 |
| 航程 | 组内最短～最长，如 `6–8` 天；相同则写一个数 |
| 码头 | 有则 `前湾 → PSA`；只有一侧就只写有的；都空则不要占「—」 |
| 最近离港 | 组内最早一班 |
| 最早截关 | 组内最早截关，订舱很看这个 |
| 展开 / 收起 | 可同时开多张，方便对照 |
| 复制共舱名 | 次要操作，不要做成整列高按钮抢视线 |

### 5.3 班次表（展开后）

| 列       | 备注                                                   |
| :------- | :----------------------------------------------------- |
| 船名     | 可点，打开船舶定位                                     |
| 航次     |                                                        |
| 计划离港 | 相对计划日若延误，用克制方式标出；不要行行打大色块 Tag |
| 计划到港 | 同上                                                   |
| 截关     | 班次表里就要能看到，不要只藏在详情                     |
| 航程     | 天                                                     |
| 详情     | 打开抽屉                                               |

组内按离港从早到晚。第一条可以暗示「最近一班」，不要再叠一层装饰。

零点时刻只显示日期即可（`2026-09-04`，不要 `00:00`）。

### 5.4 二次筛选（不打接口）

- 全部 / 直达 / 中转（带方案个数即可，如 62 / 47 / 15）
- 船公司、起运码头、目的码头、关键词（船名/航次/航线/中转港）、排序（按周班 / 最早离港 / 最晚离港 / 航程最短）
- 方案多时先出一批（现在约 80 张），再「显示更多」

数量不要再单独做一块指标区。Tab 上的数字够了；班次总数若要出现，用工具栏上的一句小字，例如 `613 班`。

### 5.5 详情抽屉

分区即可，不必做成营销详情页：船舶与航线、港口码头、中转路径、时间航程、各截点、内部数据标识。  
抽屉里保留「查看船舶定位」。

## 6. 页面状态

| 状态       | 期望                                                |
| :--------- | :-------------------------------------------------- |
| 未查询     | 条件 + 一句「选港口和日期后查询」。不要大空状态插画 |
| 查询中     | 列表区 loading；条件栏可保留                        |
| 有结果     | 工具栏 + 方案列表，立刻能扫                         |
| 无船期     | 短句说明当前航线没有可用班次                        |
| 筛选后为空 | 提示放宽条件，可一键清筛选                          |
| 接口失败   | 说明失败，提供重试                                  |

## 7. 现稿的问题（请针对这些改，不要再加壳）

工程侧已经砍掉「查询大卡 + 航线摘要大卡 + 筛选大卡」三层壳，但方案卡本身仍挤、仍像后台模板。

请重点处理：

1. **方案卡折叠态层级弱**：星期、航程、码头、共舱名、最近离港、截关权重差不多，扫 62 张会累。共舱名应该先被看见。
2. **班次表色彩噪音**：延误几乎每行都有时，橙色 Tag 会盖过日期。请用字重、色或一列状态，而不是行行徽章。
3. **长共舱名**：截断后很难扫，又不能无限撑高卡片。
4. **展开对照**：要能同时开 2～3 张；展开后表格要像对照表，不要再套一层很重的卡片阴影。
5. **工具栏高度**：查询 + 筛选叠起来后，第一张方案仍要进第一屏。
6. **复制**：做成卡上的轻操作，不要右侧通栏。

不要再做：英文装饰标题、港到港插画、KPI 数字墙、每张卡一个大图标。

---

## 8. 技术与品牌约束

- 嵌在现有 **Ant Design Vue + 后台布局** 里实现，设计请按这个组件家族出方案（表格、下拉、日期、抽屉、Tag），可以定制样式，不要换成另一套设计系统。
- 分辨率：优先 **1440～1920 宽**；1280 要能用；900 以下可把次要信息收进展开层，但桌面是主战场。
- 用户可见文案 **不要出现第三方数据供应商名称**。
- 查询一次会等几秒，loading 要诚实。
- 方案如何归组（共舱串、直达/中转）是既定业务规则，设计不能要求「按航程拆卡」「按码头拆卡」。规则说明给开发看：[方案分组规则](./grouping.md)。

---

## 9. 请交付什么

1. **桌面稿（有数据）**
   - 未查询
   - 查询后列表（折叠）
   - 展开 1 张
   - 同时展开 2 张对照
   - 筛了船公司之后
   - 无结果 / 失败
2. **方案卡两种态**的标注：主标题是什么、第二眼看什么、哪些是折叠可藏的。
3. **班次表**列宽、日期和延误怎么表现、截关怎么突出。
4. **标注尺寸与颜色**（字号、行高、间距、主色/警示色），方便按现有后台实现。
5. 若有动效：展开/收起、吸顶，写清楚，不要强动画。

参考数据请用真实量级：62 张方案、单卡最多十几班、共舱名最长约 40～60 字符。

---

## 10. 验收（产品会按这个看稿）

- 打开有结果页，**不滚动就能看到方案卡**，不是先看到三大块统计/说明。
- 3 秒内能指出：这是哪条共舱、直达还是中转、大概几天、最近哪天开。
- 展开后不用进详情就能完成「比船、比天、比截关」。
- 同时展开两张时，仍然能看清表，而不是两坨阴影卡片。
- 62 张列表往下刷不累：间距紧、层级清、没有重复数字块。

实现页与字段说明（给开发对齐用）：[船期查询活文档](./index.md)。
