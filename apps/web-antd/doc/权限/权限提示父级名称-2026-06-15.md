# 权限不足提示带父级名称 - 修改记录 (2026-06-15)

## 一、背景意图

当用户触发无权限的操作时，系统会抛出 `AbpAuthorizationException`，提示文案为：

> 您没有权限进行此操作,您至少需要下列权限的其中一项：查看

问题在于：项目里大量模块的增删改查权限**显示名都叫“查看 / 新增 / 编辑 / 删除”**。当提示里只显示叶子权限的显示名（如“查看”）时，用户根本无法判断到底是哪个模块、哪个功能缺少权限，排查权限配置非常困难。

本次修改让权限提示在返回叶子权限名时，**自动带上其父级（乃至祖先级）的显示名**，形成层级路径，便于用户与管理员快速定位需要授予的具体权限。

## 二、核心逻辑变更

- 文件：`src/Abp/Authorization/PermissionCheckerExtensions.cs`
- 方法：`LocalizePermissionNames(IPermissionChecker, string[])`

原逻辑只本地化叶子权限自身的 `DisplayName`：

```csharp
var permission = permissionManager.Object.GetPermissionOrNull(permissionName);
return permission?.DisplayName == null
    ? permissionName
    : permission.DisplayName.Localize(localizationContext.Object);
```

改为沿 `Permission.Parent` 链向上回溯，收集每一级的本地化显示名，再由根到叶用 `-` 拼接：

```csharp
var names = new List<string>();
var current = permission;
while (current?.DisplayName != null)
{
    names.Add(current.DisplayName.Localize(localizationContext.Object));
    current = current.Parent;
}

names.Reverse();
return string.Join(" - ", names);
```

效果示例（假设权限树为 货运管理 -> 订单 -> 查看）：

| 修改前 | 修改后                 |
| :----- | :--------------------- |
| 查看   | 货运管理 - 订单 - 查看 |

最终提示变为：

> 您没有权限进行此操作,您至少需要下列权限的其中一项：货运管理 - 订单 - 查看

## 三、避坑指南

- **依赖父级显示名存在**：回溯时只要某一级 `DisplayName` 为 `null` 即停止向上拼接。因此父级权限若未设置 `DisplayName`，该级及更上层不会出现在路径中，定义权限树时建议为父级也配置显示名。
- **分隔符约定**：当前使用 `-` 作为层级分隔符，前端若要解析层级可据此切分；如需更换分隔符，仅改此处一行即可。
- **影响范围**：该方法被 `Authorize` / `AuthorizeAsync`（包括 `requireAll` 与“至少其一”两种）共用，所有权限不足提示文案都会随之带上父级名称。
- **本地化无侵入**：仍走原有 `ILocalizationContext`，多语言不受影响。
