# 接口变更说明（前端对接）— 2026-07-22

> 本文只列「前端需要改」的接口和字段。所有 JSON 字段名按后端序列化的 **小驼峰** 书写。关键背景：
>
> 1. 一个用户现在可以隶属 **多个组织机构**；
> 2. 数据权限业务单据把原「归属公司 `companyId`」**统一重命名为「归属组织 `orgId`」**（含义为组织机构 id，可能是公司也可能是部门）；
> 3. 返回体不再返回单个 `company` 对象，改为返回 **组织串 `orgs`**（从最高级组织到该组织的一串）；
> 4. 客户 **下线 `showCompanyId`**，统一用 `orgId`。

> ⚠️ 术语提醒：字段名从 `companyId` → `orgId`、`company` → `orgs`。如果你之前对接过本文的旧版本（用 `companyId`/`company`），请按本版本全量替换。

---

## 0. 通用规则（务必先看）

### 0.1 数据权限单据返回体：单对象 `company` → 组织串 `orgs`

所有「数据权限单据」的列表/详情返回体：

- 废弃（不再返回）：`organizationUnits`、`companys`、`company`
- 新增返回：
  - `orgId`（`number | null`）：该单据录入的归属组织 id。
  - `orgs`（`OrganizationUnitSimpleDto[] | null`）：组织串，**从最高级组织到该组织**，依次排列。

`orgs` 元素结构（`OrganizationUnitSimpleDto`）：

```json
{
  "id": 123, // 组织id
  "name": "上海某某公司", // 组织名
  "localCurrencyId": 1, // 本位币id，可空
  "localCurrencyCode": "CNY" // 本位币编码，可空
}
```

`orgs` 示例（顶 → 底）：

```json
"orgId": 20,
"orgs": [
  { "id": 10, "name": "集团",     "localCurrencyId": 1,    "localCurrencyCode": "CNY" },
  { "id": 20, "name": "业务一部", "localCurrencyId": null, "localCurrencyCode": null }
]
```

> 取「所属公司/本位币」等信息时，可从 `orgs` 中按需取：本位币通常在串首的公司节点上（取第一个有 `localCurrencyId` 的节点即可）。

> 注：发票类三张单据（开票申请 / 发票开出 / 发票备注模板）返回体除了 `orgId` + `orgs` 外，仍附带一个 `companyName`（组织名，便于直接展示），但 **已删除 `companyId`**，见对应章节。

### 0.2 归属组织录入字段 `orgId`

- 类型：`number | null`（可空）。
- 规则：**除「客户」「自动费用模板 OrderFeeTemplate」外**，所有数据权限单据的新增/修改 **必须传** `orgId`，否则后端报「所属组织不能为空」。
- 校验：`orgId` 必须是「数据所属人（本人）」的 **直属组织**（即 UserOrganizationUnit 中本人直接挂的组织，**完全相等，不做父子判断**），否则报「所选组织不在数据所属人(本人)所属组织范围内」。
- 特例：
  - **客户（Client）**：`orgId` 为 **可选**，可不传/传 null；传了才校验。
  - **自动费用模板（OrderFeeTemplate）**：`orgId` 表示「适用组织」，**可空、不做本人校验**（为空代表适用所有组织）。

### 0.3 列表按组织查询（`orgId` 筛选）的语义：含下属组织

所有继承数据权限基类的单据，其列表/查询入参里的 `orgId` 筛选采用「**本组织 + 其所有下属组织**」的口径：

- 后端会先由传入的 `orgId` 解析出「该组织本身 + 所有下级组织」的 id 集合，再匹配单据的 `orgId`。
- 例：传「山东分公司」，会同时查出山东分公司、以及其下属「青岛分公司/业务部…」等所有下级组织的数据。
- 前端 **无需改动入参**（仍传一个 `orgId`），只需知道结果会包含下属组织的数据。

## 1. 用户管理（UserAdmin）

### 1.1 用户分页列表（GetUserPagedList / GetUserPagingList）与用户详情（GetUser）

返回体 `items[]`（详情为对象本身）：

- ❌ 移除：`organizationPath`、以及遗留单值字段 `organization`（原"部门名"字符串，已下线）
- ✅ 新增：`organizations`（该用户所属的全部组织路径）

> 说明：`GetUserPagingList` 与 `GetUser`（详情）此前未返回组织信息，本次已补齐，三个读取接口返回结构一致。

`organizations` 结构（`UserOrganizationPathDto[]`）：

```json
"organizations": [
  {
    "default": true,                 // 是否默认组织
    "oneOrganizationPath": [         // 一条组织路径，从顶到底
      { "id": 10, "name": "集团", "isCompany": true,  "localCurrencyId": 1 },
      { "id": 20, "name": "业务一部", "isCompany": false, "localCurrencyId": null }
    ]
  }
]
```

### 1.2 获取用户详情用于编辑（GetUserForEdit）

返回体：

- ❌ 移除：`companyId`、`companyName`、`departmentId`、`departmentName`
- ✅ 新增：`organizations`（`UserOrganizationPathDto[]`，结构同 1.1）

### 1.3 新增/修改用户（CreateOrUpdateUser / CreateOrUpdateUserInAdmin）

请求体：

- ❌ 移除：`organizationId`、`organizationName`
- ✅ 新增：`organizations`（`UpdateUserOrganizationPathDto[]`）

`organizations` 入参结构：

```json
"organizations": [
  { "id": 10, "default": true },   // 组织id + 是否默认
  { "id": 33, "default": false }
]
```

校验规则：

- `default = true` 的组织必须在 `organizations` 列表内（即用户所属组织中）。
- 有且应仅有一个 `default = true`（默认组织，对应用户 `DefaultOrgId`）。

### 1.4 获取我的信息（GetMy）

返回体：

- ❌ 移除：`companyId`、`companyName`、`departmentId`、`departmentName`、`company`
- ✅ 新增：`organizations`（`MyUserOrganizationPathDto[]`）

`organizations` 结构（每个组织节点为 **完整的** `OrganizationUnitDto`，公司节点含本位币与公司银行账户 `orgBankAccounts`）：

```json
"organizations": [
  {
    "default": true,
    "oneOrganizationPath": [
      {
        "id": 10,
        "displayName": "集团",
        "isCompany": true,
        "localCurrencyId": 1,
        "localCurrencyCode": "CNY",
        "orgBankAccounts": [
          { "id": 1, "currencyId": 1, "currencyCode": "CNY", "...": "..." }
        ]
      },
      { "id": 20, "displayName": "业务一部", "isCompany": false, "orgBankAccounts": null }
    ]
  }
]
```

> 说明：取默认组织请用 `organizations` 中 `default=true` 的那条。公司银行账户从原 `company.orgBankAccounts` 迁移到对应公司节点的 `orgBankAccounts`。

## 2. 客户（Client）

**统一下线 `showCompanyId` / `showCompany`，改用 `orgId` / `orgs`。客户的 `orgId` 为可选。**

### 2.1 客户列表查询入参（ClientQueryDto，用于 Admin 与 App 两个列表接口）

- ❌ 移除：`showCompanyId`（以及旧的 `companyId`）
- ✅ 新增：`orgId`（`number | null`，为空不筛选）

### 2.2 新增/修改客户（Client Add / Edit）

请求体：

- ❌ 移除：`showCompanyId`（以及旧的 `companyId`）
- ✅ 使用：`orgId`（`number | null`，可选；若传则校验属于本人直属组织）

### 2.3 客户列表/详情返回（ClientDto、ClientSimpleDto）

- ❌ 移除：`showCompanyId`、`showCompany`、`company`
- ✅ 新增：`orgId`（`number | null`）、`orgs`（`OrganizationUnitSimpleDto[]`，组织串，见 0.1，可空）

## 3. 数据权限业务单据（录入 `orgId`）

以下模块的 **新增/修改** 接口，把原 `companyId` 入参 **改名为 `orgId`**；列表/详情返回体按 0.1 规则改为 `orgId` + `orgs`（发票三单额外附 `companyName`，见 3.x 备注）。

| 模块 | 说明 | 新增/修改入参 | 返回体 |
| --- | --- | --- | --- |
| TransportOrder | 运输订单 | `orgId`（必填） | `orgId` + `orgs` |
| SeaExport | 海运出口 | `orgId`（必填；本人=**当票销售**，销售有且只能有一个） | `orgId` + `orgs` |
| PreOrder | 业务联系单/预录单 | `orgId`（必填） | `orgId` + `orgs` |
| Agreement | 协议 | `orgId`（必填） | `orgId` + `orgs` |
| Statement | 对账单 | `orgId`（必填） | `orgId` + `orgs` |
| PaymentApplication | 付款申请 | `orgId`（必填） | `orgId` + `orgs` |
| PaymentSettlement | 付款结算 | `orgId`（必填） | `orgId` + `orgs` |
| ReceiveSettlement | 收款结算 | `orgId`（必填） | `orgId` + `orgs` |
| BankStatement | 银行流水 | `orgId`（必填） | `orgId` + `orgs` |
| InvoiceApplication | 开票申请 | `orgId`（必填） | `orgId` + `orgs` + `companyName`（见备注） |
| InvoiceIssue | 发票开出 | `orgId`（必填） | `orgId` + `orgs` + `companyName`（见备注） |
| InvoiceRemarkTem | 发票备注模板 | `orgId`（必填） | `orgId` + `orgs`（见备注） |
| OrderFeeTemplate | 自动费用模板 | `orgId`（**可选，适用组织，不校验**） | `orgId` + `orgs`（另附自有 `company` 展示对象） |
| Client | 客户 | `orgId`（可选，见第 2 章） | `orgId` + `orgs` |
| OrderFee | 订单费用 | **不传**（费用实体不存组织） | `orgId` + `orgs`（**取主单 TransportOrder**，批量填充） |

### 3.x 备注

- **发票三单（InvoiceApplication / InvoiceIssue / InvoiceRemarkTem）**：
  - 入参：原 `companyId` → 改为 `orgId`（必填）。
  - 返回体：**删除了 `companyId`**；统一用基类的 `orgId` + `orgs`。其中 InvoiceApplication / InvoiceIssue 额外保留 `companyName`（=该组织名，便于直接展示）；InvoiceRemarkTem 直接用 `orgs`。
  - 查询入参：发票三单原有的「按公司过滤」入参已下线，列表按数据权限（`orgId` 通过 UserId 过滤，即原有的组织权限过滤字段）返回。
- **自动费用模板（OrderFeeTemplate）**：`orgId` 语义为「适用组织」，**可空、不做本人校验**（为空代表适用所有组织）。列表/详情除 `orgId` + `orgs` 外，仍返回其自有的 `company` 展示对象（不受本次影响）。
- **OrderFee（订单费用）**：实体已改为继承 `FullAuditedEntity`（**不再有自身 `UserId`/`OrgId` 列**，不参与数据权限）。列表/详情仍返回展示用 `orgId`/`orgs`，由主单 `TransportOrder` **批量赋值**（`SetOrderFeeOrgsFromOrderAsync`）。费用可见性跟随主单数据权限。前端 **不需要** 在费用上单独录入组织。
- **SeaExport（海运出口）**：新建/编辑 `orgId` 校验的本人 = **当票销售**（`orderUsers` 中 Sale 必填且唯一）；列表/分组数据权限仍按原规则（所属人/创建人/多类业务关联人员等），**不因本校验改变**。
- **Statement / Agreement / ReceiveSettlement / BankStatement**：列表与详情均返回 `orgId` + `orgs`（通用数据权限组织串）。
- **收款结算按发票新增（ReceiveSettlement AddByInvoice）**：入参同样是 `orgId`（必填）。

## 4. 前端改造清单（Checklist）

- [ ] 用户列表/详情：`organizationPath`、`companyId/departmentId` 等 → 改读 `organizations`。
- [ ] 用户新增/修改：`organizationId` → 改为提交 `organizations`（数组，含 `default`）。
- [ ] 我的信息：`company` 单对象 → 改读 `organizations`；公司银行账户从对应公司节点的 `orgBankAccounts` 取。
- [ ] 客户：全局搜索替换 `showCompanyId`/`companyId` → `orgId`、`showCompany`/`company` → `orgs`（查询/新增/编辑/列表/详情）。
- [ ] 所有数据权限单据的新增/修改：入参 `companyId` → **改名 `orgId`**（客户、自动费用模板可选，OrderFee 不需要）。
- [ ] 单据列表/详情展示：`company` 单对象 → **改读 `orgs` 组织串**（发票三单可继续用 `companyName` 直接展示名；对账单/收费结算/银行流水/协议详情也已返回 `orgs`）。
- [ ] 费用 `OrderFeeDto`：可读 `orgId`/`orgs`（主单组织），**不要**再当费用自身数据权限字段；录入时勿传组织。
- [ ] 归属组织必填校验与后端错误提示（"所属组织不能为空" / "所选组织不在数据所属人(本人)所属组织范围内"）前端做好交互。
