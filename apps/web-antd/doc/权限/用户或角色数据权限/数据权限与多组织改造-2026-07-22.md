# 一、背景意图 (Background)

原系统假设「一个用户只归属一个组织（一条组织链）」，数据权限、用户回显、公司归属等逻辑都基于该假设，并依赖多套旧缓存（用户单组织缓存、组织树缓存、组织下所有用户缓存）。

业务已升级为「一个用户可归属多个组织」，本次改造统一按多组织重写，核心目标：

1. 用户可属于多个组织，新增 `User.DefaultOrgId`（默认组织），用户回显返回全部组织路径。
2. 数据权限（可见用户范围）按用户的**全部**组织链计算，不再只取第一条。
3. 业务单据的「归属组织」为**录入字段** `OrgId`（可空，存表；原一度命名为 `CompanyId`，最终统一改名为 `OrgId`），返回时展示 `orgs` 组织串（从最高级组织到该组织，顶→底）；新增/修改须校验 `orgId` 是数据所属人（本人）**直属组织**（完全相等，不判父子）。客户、自动费用模板为特例（见各模块文档）。
4. 删除三套旧缓存与相关旧方法，统一收敛到两个新方法（带缓存）：`GetAllOrganizationTreesAsync`、`GetUserOrganizationPathsAsync`。

> 本文为**汇总性变更文档**，覆盖今日全部接口与字段改动；各模块活文档（用户 / 组织机构 / 数据权限）已同步追加变更记录并互相引用本文。

# 四、核心逻辑变更 (Core Logic)

## 4.1 新增两个统一方法（带缓存）

`CsprojBuilderAppServiceBase` 中新增并收敛：

- `GetAllOrganizationTreesAsync()` → `List<OrganizationTreeNodeDto>`：**扁平**返回所有组织节点，每个节点含 `Users`（本级直属用户）与 `AllUsers`（本级及所有下属组织去重后的用户）、`IsCompany`、`LocalCurrencyId` 等。**在当前租户内**查询（不禁用多租户过滤）。
- `GetUserOrganizationPathsAsync(userId)` → `List<UserOrganizationPathDto>`：返回某用户的全部组织链（从顶到底）。

两个方法均改为缓存包装：

- `OrganizationTreeCache`：缓存全部组织树节点。
- `UserOrganizationPathsCache`：缓存「用户id → 组织路径列表」字典，可按 userId 取。
- 新增 `OrganizationCacheInvalidator`（事件处理器）：在 `OrganizationUnit`、`UserOrganizationUnit`、`User` 增/删/改时清除上述缓存。

## 4.2 删除的旧缓存与旧方法

- 删除 region「获取组织下的所有用户」「组织树和成员缓存」「用户的组织信息缓存」及其全部缓存代码。
- 删除常量 `OrganizationTreeCacheName`(旧)、`AllUsersOrganizationInfoCacheName`。
- 删除 `GetUserOrganizationHierarchy`（只取单组织）。
- 删除旧失效器 `UserOrganizationCacheInvalidator`、`OrganizationTreeCacheInvalidator`。
- 所有旧调用点迁移到 4.1 的两个新方法。

## 4.3 数据权限可见用户范围

`GetDataPermissionUserIdsAsync` 改为返回三元组 `(AllowAll, UserIds, OrgIds)`：

- 用户类权限（`ManyUser`）→ 收集指定用户ids；并总是并入当前登录人自己。
- 组织类权限（`ManyPart`/`MyPart`/`MyCompany`）→ 收集目标组织**及其所有下属组织**的 ids。

`DataPermissionFilterAsync` 据此对继承基类的实体施加过滤：`x.UserId ∈ UserIds` **或** `x.OrgId ∈ OrgIds`（`AllowAll` 时不过滤）。实现多组织下「按人 + 按组织(含下属)」的数据可见范围。

## 4.4 SetDataPermissionPropsAsync 重写

- 由「按用户id反推组织/公司列表」改为**按 DTO 的 `OrgId` 直接解析 `Orgs` 组织串**（从组织树缓存取整条从最高级组织到该组织的链，含名称与本位币，本位币码再查 `Currency` 补全）。
- 不再填充 `OrganizationUnits`/`Companys`。

## 4.5 归属组织校验 `EnsureUserOwnsOrgAsync`

新增校验方法（原名 `EnsureUserOwnsCompanyAsync`，随字段改名为 `EnsureUserOwnsOrgAsync`），供业务单据新增/修改时调用。校验语义为「`orgId` 必须是数据所属人（本人）的**直属组织**（`UserOrganizationUnit` 中本人直接挂的组织，**完全相等，不判父子**）」：

- `orgId` 为空 → 「所属组织不能为空。」
- 所选组织不存在 → 「所选组织不存在。」
- 组织不在数据所属人(本人)所属组织范围内 → 「所选组织不在数据所属人(本人)所属组织范围内。」

支持 `params long[] ownerUserIds`：模块可传入自定义「本人」集合（如海运出口的录入人+销售/操作等角色用户）；未传时默认取当前登录人。已接入所有继承基类的业务单据新增/修改（客户可选校验；自动费用模板不校验）。

## 4.6 用户多组织写入 `SetUserOrganizationsAsync`

新增/修改用户时：

1. 清空用户原有 `UserOrganizationUnit`。
2. 校验每个组织 id 存在且启用（禁用报错）。
3. 写入新的 `UserOrganizationUnit`。
4. 设置 `User.DefaultOrgId`：`organizations` 中 `default=true` 最多一条；若未指定则回退取第一条。

# 五、避坑指南 (Pitfalls)

- **前端字段替换**：用户列表由 `organizationPath` → `organizations`（且遗留单值 `organization` 已下线）；用户编辑回显与提交由 `organizationId/organizationName` → `organizations`。旧字段已删除，需同步调整。
- **OrderFee（订单费用）**：实体改为 `FullAuditedEntity`（无自身 `UserId`/`OrgId`）；返回体仍有展示用 `orgId`/`orgs`，取自主单并批量填充；费用可见性跟随主单数据权限。
- **业务返回体**：由 `organizationUnits`/`companys` 数组、单对象 `company` → `orgId` + `orgs` 组织串；付费申请任务项 `companys` → `orgs`；发票开出/开票申请额外保留 `companyName`。
- **`orgId` 是录入字段**：业务单据的归属组织由前端在新增/修改时提交 `orgId`（一般必填；客户可空、自动费用模板可空且不校验），且必须是数据所属人本人直属组织（完全相等，不判父子），否则报错；返回体读 `orgs` 组织串。
- **列表按 `orgId` 筛选含下属组织**：查询入参 `orgId` 会解析为「本组织 + 所有下属组织」的 id 集合再匹配单据 `orgId`。
- **组织查询按当前租户**：`GetAllOrganizationTreesAsync`、`GetUserOrganizationPathsAsync` 在当前租户内查询（此前一度禁用多租户过滤，已回退）。
- **缓存一致性**：组织、用户组织关系、用户变化会触发 `OrganizationCacheInvalidator` 清缓存；如新增涉及组织的写入路径，注意其经过实体事件以保证缓存失效。
- **本位币展示**：`orgs` 中公司节点的 `localCurrencyCode` 由 `localCurrencyId` 查 `Currency` 补全，费用币别展示应优先取组织串中第一个有本位币的（公司）节点。
