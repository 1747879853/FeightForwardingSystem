# 1. 接口一览

所有接口都需要登录并带有效 Token。

## 1.1 规则 `/api/services/app/UserDataPermissionAdmin`

| 接口 | 方法 | 路径 | 权限 |
| :-- | :-- | :-- | :-- |
| 新增 | POST | `/api/services/app/UserDataPermissionAdmin/AddAsync` | `Admin.UserDataPermission.Add` |
| 编辑 | PUT | `/api/services/app/UserDataPermissionAdmin/EditAsync` | `Admin.UserDataPermission.Edit` |
| 删除 | DELETE | `/api/services/app/UserDataPermissionAdmin/DeleteAsync` | `Admin.UserDataPermission.Delete` |
| 列表(分页) | GET | `/api/services/app/UserDataPermissionAdmin/GetPagedListAsync` | `Admin.UserDataPermission.Get` |
| 详情 | GET | `/api/services/app/UserDataPermissionAdmin/DetailAsync` | `Admin.UserDataPermission.Get` |

子表没有单独的接口，只通过规则的新增、编辑接口里的 `entityIds` 一次性维护。**2026-09-29 删除了从未可用的子表接口 `UserDataPermissionItemAdmin`**（其权限点从未注册，任何人都调不通）。

## 1.2 相关接口

按数据权限返回公司下拉 `GET /api/services/app/OrganizationUnit/GetMyPermissionCompaniesAsync`（可带 `module`），见《组织机构文档》2.5。

# 2. 枚举

## 2.1 dataPermissionType（数据范围类型）

| 值  | 名称        | 显示名                           | `entityIds` 存什么    |
| :-- | :---------- | :------------------------------- | :-------------------- |
| 0   | My          | 自己（自动拥有，无需配置）       | 不使用                |
| 1   | MyPart      | 自己部门                         | 不使用                |
| 2   | MyCompany   | 自己公司                         | 不使用                |
| 3   | ManyUser    | 多人                             | 用户 id               |
| 4   | ManyPart    | 部分（多部门、多公司）           | 组织 id               |
| 5   | All         | 全部                             | 不使用                |
| 6   | ExcludeUser | 排除人员 **（2026-09-29 新增）** | 用户 id，**不能为空** |

## 2.2 manageType（操作类型）

| 值  | 名称 | 显示名 |
| :-- | :--- | :----- |
| 0   | Get  | 查询   |
| 1   | Edit | 编辑   |

## 2.3 module（数据权限模块，2026-09-29 新增）

不传或传 `null` 表示**通用规则**，所有没有单独配置的模块都用它。

| 值  | 名称               | 显示名     |
| :-- | :----------------- | :--------- |
| 0   | SeaExport          | 海运出口   |
| 3   | PaymentApplication | 付费申请   |
| 4   | SeaImport          | 海运进口   |
| 5   | AirExport          | 空运出口   |
| 8   | PreOrder           | 业务联系单 |
| 9   | Client             | 客户       |
| 12  | BreakBulk          | 件杂货     |
| 13  | ReceiveSettlement  | 收费结算   |
| 14  | PaymentSettlement  | 付款结算   |
| 15  | InvoiceIssue       | 发票开出   |
| 16  | InvoiceApplication | 开票申请   |
| 17  | BankStatement      | 银行流水   |
| 18  | CommissionOrder    | 提成单     |
| 19  | InputInvoice       | 进项发票   |
| 20  | ClientContact      | 客户联系人 |

数值不连续是有意的：和系统里另一个模块枚举同名的模块必须同值。业务费用、提单、监装工单、件杂货分单跟随所属业务单，不在这里配置。

# 3. 规则接口详情

## 3.1 新增 `POST /api/services/app/UserDataPermissionAdmin/AddAsync`

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| userId | long? | 二选一 | 规则所属用户。与 `roleId` 不能同时传，也不能都不传 |
| roleId | int? | 二选一 | 规则所属角色 |
| dataPermissionType | int | 是 | 数据范围类型，见 2.1 |
| manageType | int | 是 | 操作类型，见 2.2 |
| module | int? | 否 | 数据权限模块，见 2.3；不传是通用规则 **（2026-09-29 新增）** |
| entityIds | long[] | 视类型 | 子表：多人、排除人员传用户 id，部分传组织 id；自动去重。排除人员不能为空，且用户规则不能包含 `userId` 自己 |

```json
{
  "userId": 1,
  "roleId": null,
  "dataPermissionType": 6,
  "manageType": 0,
  "module": 0,
  "entityIds": [10, 11]
}
```

上例表示：用户 1 在海运出口的查询里，看不到用户 10、11 的数据。

**返回：** `long`，新增规则的 id。

**唯一性：** 同一用户或角色、同一 `manageType`、同一 `dataPermissionType`、同一 `module`（`null` 也算一个值）只能配一条。同一个人可以同时有「通用：全部」「通用：排除人员」「海运出口：自己部门」等多条。**2026-09-29 由「每个用户或角色每种操作类型只能一条」放宽。**

## 3.2 编辑 `PUT /api/services/app/UserDataPermissionAdmin/EditAsync`

**请求体：** 新增的全部字段，加上：

| 字段 | 类型 | 必填 | 说明    |
| :--- | :--- | :--- | :------ |
| id   | long | 是   | 规则 id |

校验与新增相同，唯一性判断会排除自身。子表按 `entityId` 增量维护：库里有、这次没传的删掉；这次传了、库里没有的新增；两边都有的不动。

**返回：** `bool`。

## 3.3 删除 `DELETE /api/services/app/UserDataPermissionAdmin/DeleteAsync`

**请求体：**

```json
{ "id": 1 }
```

**返回：** `bool`。同时删除该规则的子表。

## 3.4 列表 `GET /api/services/app/UserDataPermissionAdmin/GetPagedListAsync`

**查询参数：**

| 参数 | 类型 | 必填 | 说明 |
| :-- | :-- | :-- | :-- |
| userId | long? | 否 | 按用户筛选 |
| roleId | int? | 否 | 按角色筛选 |
| module | int? | 否 | 只查该模块的规则 **（2026-09-29 新增）** |
| moduleEmpty | bool? | 否 | 传 `true` 只查通用规则（模块为空）；与 `module` 不能同时传 **（2026-09-29 新增）** |
| keyword | string | 否 | 预留，暂不生效 |
| sorting | string | 否 | 排序，默认 `CreationTime DESC` |
| pageIndex | int | 否 | 页码，默认 1 |
| pageSize | int | 否 | 每页条数，默认 10 |

**返回：** 分页对象

| 字段           | 类型   | 说明                     |
| :------------- | :----- | :----------------------- |
| items          | 规则[] | 当前页的规则，字段见下表 |
| totalCount     | int    | 总条数                   |
| skipCount      | int    | 跳过条数                 |
| maxResultCount | int    | 本页最大条数             |
| currentPage    | int    | 当前页                   |
| totalPages     | int    | 总页数                   |

**`items[]` 规则：**

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| id | long | 规则 id |
| userId | long? | 规则所属用户，角色规则时为空 |
| roleId | int? | 规则所属角色，用户规则时为空 |
| dataPermissionType | int | 数据范围类型 |
| manageType | int | 操作类型 |
| module | int? | 数据权限模块，为空是通用规则 **（2026-09-29 新增）** |
| userNickName | string | 规则所属用户的昵称，`userId` 为空时为 null |
| roleName | string | 规则所属角色的显示名，`roleId` 为空时为 null |
| items | 子表[] | 该规则的子表，字段见下表 |
| creationTime | datetime | 创建时间 |
| creatorUserId | long? | 创建人 id |
| lastModificationTime | datetime? | 最后修改时间 |
| lastModifierUserId | long? | 最后修改人 id |

**`items[].items[]` 子表：**

| 字段                 | 类型 | 说明                                       |
| :------------------- | :--- | :----------------------------------------- |
| id                   | long | 子表 id                                    |
| userDataPermissionId | long | 所属规则 id                                |
| entityId             | long | 多人、排除人员时是用户 id；部分时是组织 id |

```json
{
  "items": [
    {
      "id": 1,
      "userId": 1,
      "roleId": null,
      "dataPermissionType": 6,
      "manageType": 0,
      "module": 0,
      "userNickName": "张三",
      "roleName": null,
      "items": [
        { "id": 100, "userDataPermissionId": 1, "entityId": 10 },
        { "id": 101, "userDataPermissionId": 1, "entityId": 11 }
      ],
      "creationTime": "2026-09-29T10:00:00",
      "creatorUserId": 1,
      "lastModificationTime": null,
      "lastModifierUserId": null
    }
  ],
  "totalCount": 1,
  "skipCount": 0,
  "maxResultCount": 10,
  "currentPage": 1,
  "totalPages": 1
}
```

## 3.5 详情 `GET /api/services/app/UserDataPermissionAdmin/DetailAsync`

**查询参数：**

| 参数 | 类型 | 必填 | 说明    |
| :--- | :--- | :--- | :------ |
| id   | long | 是   | 规则 id |

**返回：** 一条规则，结构同 3.4 的 `items[]`。

# 4. 报错文案

| 场景 | 报错 |
| :-- | :-- |
| 用户和角色都传了 | 用户Id和角色Id不能同时传 |
| 用户和角色都没传 | 用户Id和角色Id必须传一个 |
| 模块值不存在 | 模块不存在 **（2026-09-29 新增）** |
| 排除人员没传子项 | 排除人员不能为空 **（2026-09-29 新增）** |
| 用户规则排除了自己 | 排除人员不能包含规则所属用户自己 **（2026-09-29 新增）** |
| 用户不存在 | 输入用户错误 |
| 角色不存在 | 输入角色错误 |
| 用户规则重复 | 该用户在[通用/海运出口…]已配置[查询/编辑][全部/排除人员…]数据权限, 同一模块、同一操作类型的同一种权限只能配置一条 **（2026-09-29 由「每个用户的每种操作类型只能配置一个」改文案）** |
| 角色规则重复 | 该角色在[…]已配置[…][…]数据权限, 同一模块、同一操作类型的同一种权限只能配置一条 **（2026-09-29 改文案）** |
| 列表同时传 `module` 和 `moduleEmpty=true` | 模块筛选：未填写与指定模块不可同时传入 **（2026-09-29 新增）** |
| 编辑、详情的规则不存在 | 输入用户或角色数据权限错误 |
