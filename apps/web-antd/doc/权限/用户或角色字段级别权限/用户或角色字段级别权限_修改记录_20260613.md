# 用户或角色字段级别权限 - 修改记录 (2026-06-13)

## 一、背景意图

字段级别屏蔽此前**只做了输出侧**：`PropMaskContractResolver` 在 JSON 序列化时把当前用户无查看权限的字段从响应中剔除（字段直接消失，不是 null）。

由此引出一个**编辑覆盖问题**：

1. 用户对某字段（如 `Vessel`、`Amount`）无查看权限 → 查询时该字段不在返回的 JSON 中。
2. 前端编辑表单里也就拿不到该字段的值，提交编辑时输入 DTO 对应属性是 `null` / 默认值。
3. 后端编辑方法直接 `entity.X = input.X` 赋值 → **把数据库中的原值覆盖成了空**。

本次修复补齐**输入侧保护**：编辑时，对当前用户无查看权限（被屏蔽）的字段，用数据库中的原值回填输入 DTO，从而“跳过”对这些字段的编辑（赋值后值保持不变）。

## 二、核心逻辑变更

### 1. 新增 `PropMaskInputGuard`（输入侧保护）

- 文件：`src/CsprojBuilder.Application/Shared/PropMaskInputGuard.cs`
- 屏蔽规则优先复用 `PropMaskActionFilter` 预加载在 `HttpContext.Items["PropMaskedFields"]` 的结果，避免重复查 DB；无 HttpContext（后台任务）时回退到 `PropMaskProvider` 查询。
- 提供两个方法，分别对应两类编辑写法：

| 方法 | 适用场景 | 行为 |
| --- | --- | --- |
| `RestoreMaskedFieldsAsync(input, dbEntity, module)` | 单条 / 逐条编辑，存在“一一对应”的数据库实体，且赋值是无条件的 `entity.X = input.X` | 按属性名（不区分大小写）用 `dbEntity` 原值回填 `input` 的被屏蔽字段 |
| `ClearMaskedFieldsAsync(input, module)` | 共享一份输入作用到多条记录、按“字段是否有值决定是否更新”（`if (input.X.HasValue)`）的批量编辑 | 把 `input` 的被屏蔽字段清空为默认值（null/0/false），使其不进入更新，保持各记录原值 |

> 为什么批量编辑不能用 `RestoreMaskedFieldsAsync`：一份输入对应多条实体，回填单条实体的值会被错误地写到其他所有记录上；改用 `ClearMaskedFieldsAsync` 直接让被屏蔽字段不参与更新。

### 2. 基类注入

- 文件：`src/CsprojBuilder.Application/CsprojBuilderAppServiceBase.cs`
- 通过 ABP 属性注入新增 `public PropMaskInputGuard PropMaskInputGuard { get; set; }`，所有 AppService 可直接使用，无需改动各自庞大的构造函数。

### 3. 在编辑方法中回填（赋值之前）

| AppService | 方法 | 回填模块 |
| --- | --- | --- |
| SeaExportAdminAppService | `EditAsync` | `SeaExport`（回填 input）+ `TransportOrder`（回填 input.TransportOrder） |
| TransportOrderAdminAppService | `EditAsync` | `TransportOrder` |
| SeFreiPriceAdminAppService | `EditAsync` | `SeFreiPrice`，`RestoreMaskedFieldsAsync` |
| SeFreiPriceAdminAppService | `BatchEditSimpleAsync`（逐条编辑） | `SeFreiPrice`，`RestoreMaskedFieldsAsync` |
| SeFreiPriceAdminAppService | `BatchEditAsync`（共享输入批量更新多条） | `SeFreiPrice`，`ClearMaskedFieldsAsync` |
| OrderFeeAdminAppService | `EditAsync`（已标注“不用了”，一并加固） | `OrderFee` |
| OrderFeeAdminAppService | `BatchEditAsync`（实际使用路径） | `OrderFee`，回填后重算 `Amount = 单价 × 数量` |

## 三、避坑指南

1. **回填必须在字段赋值之前执行**：本质是把 `input` 的被屏蔽字段提前改回数据库原值，使后续 `entity.X = input.X` 写回原值。放在赋值之后无效。
2. **金额等派生字段**：OrderFee 的 `Amount` 由 `单价 × 数量` 计算。若单价/数量被屏蔽，回填后必须**重新计算** `Amount`，否则金额与回填后的单价数量不一致。已在两个编辑方法中处理。
3. **按属性名匹配**：屏蔽规则的 `PropName` 是 DTO 属性名（PascalCase）。回填要求 `输入 DTO` 与 `数据库实体` 同名属性都存在。若 OutDto 上有而 EditDto/实体上没有的字段（如纯展示字段），回填自动跳过，无副作用。
4. **新增记录无原值可回填**：批量编辑中新增的费用（无 Id）没有数据库原值，被屏蔽字段保持输入值（通常为空）。这是预期行为——新记录本就没有“原值”需要保护。
5. **依赖 `PropMaskActionFilter` 已运行**：编辑请求是普通 HTTP 请求，过滤器会预加载屏蔽规则。`HttpContext.Items` 无该键即视为“当前用户无屏蔽字段”，回填为 no-op，不会产生额外 DB 查询。
6. **新增可屏蔽模块时**：除了在 DTO 上加 `[PropMaskModule]`（输出侧），还需在对应编辑方法中调用 `PropMaskInputGuard.RestoreMaskedFieldsAsync`（输入侧），两侧都要覆盖。
