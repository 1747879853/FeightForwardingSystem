# 用户或角色字段级别权限 - 接口文档

## 概述

本模块用于控制用户或角色在各业务模块中**不可见**的字段。管理员可以为指定用户或角色配置字段屏蔽规则，被屏蔽的字段将**不出现在 API 的 JSON 响应中**（字段完全省略，而非返回 null，也不会返回 `***` 之类的占位文案）。

规则支持**条件屏蔽**：可以配置成「只有当同一行数据的另一个字段满足某个条件时才屏蔽」。例如业务费用的结算对象，只在行业类别为船公司或航空公司时才屏蔽。

前端需根据 `PropName`（PascalCase，与 C# 属性名一致）自行维护字段名与界面显示名称的映射。

---

## 基础路径

```
/api/services/app/UserPropPermissionAdmin
```

所有接口均需登录（携带有效 Token）。

> **接口地址必须带 `Async` 后缀。** 本项目 `Startup.cs` 里设置了 `SuppressAsyncSuffixInActionNames = false`，ABP 动态 API **不会**剥掉方法名的 `Async`。方法叫 `AddAsync`，地址就是 `.../AddAsync`，写成 `.../Add` 会 404。

## 重要：各页面涉及的模块

> 一个页面/列表可能包含多个模块的 DTO 嵌套，需要配置多个模块的屏蔽规则才能完整屏蔽。

| 业务页面 | 涉及的 FrightModule | 说明 |
| --- | --- | --- |
| 海运出口列表/详情 | `SeaExport` + `TransportOrder` | SeaExportDto 内嵌套了 TransportOrderDto |
| 业务费用列表 | `OrderFee` + `TransportOrder` | OrderFeeDto 内嵌套了 TransportOrderSimpleDto |
| 运价列表/详情 | `SeFreiPrice` | 独立模块，无嵌套 |
| 业务表列表/详情 | `TransportOrder` + `OrderFee` | TransportOrderDto 内嵌套了 OrderFeeDto 列表 |
| 利润报表 / 欠费报表 | `TransportOrder` + `SeaExport` / `SeaImport` / `AirExport` | 报表里的业务信息复用业务模块的规则，见下 |

> **报表不需要单独配规则。** 报表里的业务主单信息（委托单位、主提单号、委托编号、销售/操作/客服等）归 `TransportOrder`，船名/航次/港口/船公司等归 `SeaExport` / `SeaImport` / `AirExport`。你给这些模块配的规则**同时管住业务列表和报表**，不用也不能单独针对报表配置。
>
> 报表**自身**的字段（合计应收/应付/利润、币别明细、超期天数、发票号等）目前**不支持屏蔽**。
>
> 一个例外要注意：报表的业务日期字段叫 `BizDate`（按业务类型取开船/到港/起飞日期），业务表那边叫 `ETD`。要屏蔽报表的业务日期，需要在 `TransportOrder` 模块下单独加一条 `PropName = "BizDate"` 的规则。

**举例**：如果要在海运出口页面屏蔽"委托编号"字段，需要为 `TransportOrder` 模块配置 `PropName = "CommissionNum"` 的规则，因为委托编号属于 TransportOrderDto 而非 SeaExportDto。

## 条件表达式（ConditionJson）

`ConditionJson` 为空 = 无条件屏蔽（该字段对该用户永远不返回）。填了值 = 只有满足条件的那些行才屏蔽这个字段。

### 结构

递归的条件树，只有两种节点：

**分组节点**（带 `logic` 和 `items`）：

```json
{
  "logic": "and",
  "items": [
    { "prop": "IndustryCategory", "op": "In", "value": [1, 4] },
    { "prop": "PaySide", "op": "Equals", "value": 1 }
  ]
}
```

**叶子节点**（带 `prop`、`op`、`value`）：

```json
{ "prop": "IndustryCategory", "op": "In", "value": [1, 4] }
```

顶层可以直接是叶子节点（单条件的常见情况），也可以是分组节点。分组可以嵌套，最多 5 层。

| 字段 | 说明 |
| --- | --- |
| logic | `and` 或 `or`，不填按 `and`。组内按此逻辑连接，只在分组节点上有意义 |
| items | 子节点数组，有值即视为分组节点 |
| prop | 判据属性名。该模块 DTO 上任何标量属性都可以（枚举/数字/布尔/日期/Guid/字符串），集合与嵌套对象不行。可用 `GetConditionSourcesAsync` 拉取候选列表 |
| op | 比较操作符，见下表。**提交时**枚举名（`"In"`）或数字（`2`）都认，**读取时**统一是枚举名 |
| value | 比较值。`In`/`NotIn` 必须是数组，其它操作符不能是数组，`IsNull`/`IsNotNull` 不需要 |
| showName | 判据的展示名，纯回显。不传后端会用属性上的中文名兜底填好 |
| showValue | 比较值的展示文本，纯回显。与 `value` **按下标一一对应**，`value` 是数组时它也必须是数组 |

### 关于 showName / showValue（回显）

`value` 里存的是原始值——枚举存数字、外键存 id。前端下次打开这条规则做编辑时，光有 `5` 没法显示成「马士基」，所以条件里额外存两个展示字段。

**它们纯粹用于回显，不参与任何求值。** 后端判断是否屏蔽只看 `prop` / `op` / `value`，改了 showValue 不会影响屏蔽行为。

谁负责填：

| 判据类型 | showValue 谁填 | 说明 |
| --- | --- | --- |
| 枚举（如行业类别） | **后端自动填** | 后端知道枚举有哪些成员，前端不传也会补上「船公司」这类文本 |
| 外键 id（客户、港口、费用代码等） | **前端提交时一并传** | 后端不知道该去查哪张表，不传就只能显示原始 id |
| 数字 / 字符串 / 日期 / 布尔 | 一般不用传 | 值本身就是可读的 |

`showName` 后端一律会兜底（取属性上的中文名），前端可以不传。

保存后端会把补全过的条件**回写**到 `ConditionJson`，所以下次读出来的就是完整的。这个口径与表级别权限的 `UserTablePermissionCondition.ShowName` / `ShowValue` 一致。

> **展示文本是保存那一刻的快照。** 客户改了名字，旧规则里的 `showValue` 不会跟着变（和表级别权限一样）。前端在编辑界面重新选一次即可刷新。屏蔽行为不受影响，因为求值只认 `value` 里的 id。

带回显的完整叶子节点长这样：

```json
{
  "prop": "SettlementId",
  "showName": "结算对象",
  "op": "In",
  "value": [
    "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "8c1e2d33-9a41-4b77-badc-11f0a2e5c901"
  ],
  "showValue": ["马士基", "中远海运"]
}
```

### 操作符

| 枚举名             | 数值 | 说明                                     |
| ------------------ | ---- | ---------------------------------------- |
| Equals             | 0    | 等于                                     |
| NotEquals          | 1    | 不等于                                   |
| In                 | 2    | 属于，`value` 为数组                     |
| NotIn              | 3    | 不属于，`value` 为数组                   |
| IsNull             | 4    | 为空，不需要 `value`。字符串的空白也算空 |
| IsNotNull          | 5    | 不为空，不需要 `value`                   |
| GreaterThan        | 6    | 大于                                     |
| GreaterThanOrEqual | 7    | 大于等于                                 |
| LessThan           | 8    | 小于                                     |
| LessThanOrEqual    | 9    | 小于等于                                 |
| Contains           | 10   | 字符串包含，不区分大小写                 |

### 值的写法

- **枚举**：写数值（`1`）或枚举成员名（`"船公司"`）都可以，推荐写数值
- **数字 / 布尔**：直接写字面量
- **字符串 / Guid**：写字符串，比较时**不区分大小写**
- **日期**：写 ISO 8601 字符串

### 完整示例

行业类别是船公司或航空公司时，屏蔽结算对象：

```json
{
  "userId": 1,
  "frightModule": 1,
  "propName": "SettlementId",
  "conditionJson": "{\"prop\":\"IndustryCategory\",\"op\":\"In\",\"value\":[1,4]}",
  "description": "船公司/航空公司的结算对象不可见"
}
```

> `conditionJson` 是**字符串字段**，里面的 JSON 需要转义。

## 接口列表

### 1. 新增屏蔽规则

**POST** `/api/services/app/UserPropPermissionAdmin/AddAsync`

**权限**：`Admin.UserPropPermission.Add`

**请求体**：

```json
{
  "userId": 1,
  "roleId": null,
  "frightModule": 1,
  "propName": "SettlementId",
  "conditionJson": "{\"prop\":\"IndustryCategory\",\"op\":\"In\",\"value\":[1,4]}",
  "description": "船公司/航空公司的结算对象不可见"
}
```

| 字段          | 类型         | 必填   | 说明                           |
| ------------- | ------------ | ------ | ------------------------------ |
| userId        | long?        | 二选一 | 对指定用户生效                 |
| roleId        | int?         | 二选一 | 对指定角色下所有用户生效       |
| frightModule  | FrightModule | 是     | 模块枚举值                     |
| propName      | string       | 是     | 要屏蔽的属性名（PascalCase）   |
| conditionJson | string       | 否     | 条件表达式，为空表示无条件屏蔽 |
| description   | string       | 否     | 规则描述                       |

**保存时的校验**（不通过会返回 `UserFriendlyException`）：

- `propName` 必须是该模块 DTO 上真实存在的属性
- `conditionJson` 必须是合法 JSON，嵌套不超过 5 层
- 每个 `prop` 必须是该模块 DTO 上真实存在的属性，且类型可做值比较（集合、嵌套对象会被拒绝）
- `op` 必须提供且合法；`In`/`NotIn` 的 `value` 必须是数组，其它操作符的 `value` 不能是数组
- `value` 必须能转换成该判据属性的类型（枚举名写错、给数字字段填字母都会被拦下）

> 该模块下还没有任何 DTO 标注屏蔽支持时（目前是 `PaymentApplication`、`AirImport`、`PreOrder`、`Client`），属性与判据校验会跳过，因为这些模块本身还不会发生屏蔽，报错只会挡住正常配置。

**返回**：`long` - 新增记录的 Id

### 6. 获取当前用户不可见字段列表

**GET** `/api/services/app/UserPropPermissionAdmin/GetCurrentUserMaskedFieldsAsync`

**权限**：仅需登录

**查询参数**：无

**返回**：`List<PropPermissionModuleFieldsDto>` - 按模块分组

```json
[
  {
    "frightModule": 1,
    "frightModuleName": "OrderFee",
    "fields": [
      {
        "propName": "SettlementId",
        "alwaysMasked": false,
        "rules": [
          {
            "description": "船公司/航空公司的结算对象不可见",
            "conditionJson": "{\"prop\":\"IndustryCategory\",\"op\":\"In\",\"value\":[1,4]}",
            "isConditional": true
          }
        ]
      },
      {
        "propName": "Amount",
        "alwaysMasked": true,
        "rules": [
          {
            "description": "金额不可见",
            "conditionJson": null,
            "isConditional": false
          }
        ]
      }
    ]
  }
]
```

**说明**：

- 返回当前登录用户的所有屏蔽字段，**包含通过角色继承的规则**
- 没有任何规则时返回空数组
- 一个 `propName` 下可能有**多条规则**（一条无条件的加几条带条件的），所以 `rules` 是数组，任一命中该字段就不返回
- `alwaysMasked = true` 表示该字段存在无条件规则，一定看不到，前端可以直接**整列隐藏**
- `alwaysMasked = false` 表示全是条件规则，前端**不能整列隐藏**，只能按行判断（详见下面的前端使用建议）
- `description` 是规则的描述信息，不是字段含义，前端自行维护字段名映射

> **接口结构变更提醒**：`fields` 数组的元素由原来的 `{ propName, description }` 改为 `{ propName, alwaysMasked, rules[] }`，`description` 下移到了 `rules` 里。

### 8. 获取可选判据字段列表

**GET** `/api/services/app/UserPropPermissionAdmin/GetConditionSourcesAsync`

**权限**：`Admin.UserPropPermission.Get`

给管理端的条件构造器用：告诉你这个模块下有哪些字段可以当判据、是什么类型、枚举有哪些可选值。

**该模块 DTO 上的任何标量属性都可以当判据**，不需要后端事先声明。这个接口只是帮你把候选列表、类型和枚举可选值一次性拿全，省得手填属性名和枚举数字。

**查询参数**：

| 参数         | 类型         | 必填 | 说明       |
| ------------ | ------------ | ---- | ---------- |
| frightModule | FrightModule | 是   | 模块枚举值 |

**返回**：`List<PropMaskConditionSourceDto>`

```json
[
  {
    "propName": "IndustryCategory",
    "showName": "行业类别",
    "dataType": "enum",
    "enumOptions": [
      { "value": 1, "name": "船公司", "showName": "船公司" },
      { "value": 2, "name": "发货人", "showName": "发货人" }
    ]
  }
]
```

| 字段 | 说明 |
| --- | --- |
| propName | 填到条件表达式的 `prop` 里 |
| showName | 展示名，取属性上的 `Display` 或 `Description` 特性，都没有则等于 `propName` |
| dataType | `enum` / `number` / `bool` / `datetime` / `guid` / `string` |
| enumOptions | 仅 `dataType` 为 `enum` 时有值，`value` 填到条件的 `value` 里 |

返回的是该模块所有 DTO 的标量属性（含从基类继承来的），已排除集合和嵌套对象——它们没法做值比较。 **返回空数组**表示该模块还没有任何 DTO 支持屏蔽（`PaymentApplication`、`AirImport`、`PreOrder`、`Client`）。

## 前端使用建议

1. **登录后获取屏蔽规则**：调用 `GetCurrentUserMaskedFieldsAsync` 获取当前用户的所有屏蔽字段，缓存在前端

2. **区分「一定看不到」和「可能看不到」**：
   - `alwaysMasked = true` → 直接隐藏整列/整个表单项
   - `alwaysMasked = false` → **不要隐藏整列**。该字段在部分行上有值、部分行上不返回，隐藏整列会让本来能看的数据也看不见。正确做法是渲染时按「该行响应里有没有这个 key」决定单元格显示内容

3. **判断字段是否被屏蔽，一律看响应里有没有这个 key**，不要看值是不是 null。被屏蔽是「字段不存在」，值为 null 是「业务上就是空」，两者含义完全不同。JS 里用 `'settlementId' in row` 而不是 `row.settlementId == null`

4. **前端不需要自己解析 `conditionJson`**。它返回给你只是为了展示规则和调试，屏蔽已经由后端在序列化时做完了。想靠前端解析条件来预判某行会不会被屏蔽，会和后端的求值细节（大小写、类型转换、fail-closed）产生偏差

5. **注意嵌套关系**：一个列表页可能涉及多个模块，需要合并多个模块的屏蔽规则。例如海运出口页需要同时检查 `SeaExport` 和 `TransportOrder` 两个模块

6. **字段名映射**：后端返回的 `propName` 是 PascalCase（如 `CommissionNum`），API 响应 JSON 中的字段名是 camelCase（如 `commissionNum`），前端注意统一处理。屏蔽匹配不区分大小写，数据库存 `vessel` 或 `Vessel` 效果一样

7. **id 字段和对象字段要一起配**：像 `SettlementId` 和 `Settlement`（嵌套对象）这种，只屏蔽 id 前端仍能从对象里读到名称，等于没屏蔽。配置时必须成对配

8. **实时生效**：后端无缓存，管理员修改规则后下次请求即生效。前端可在管理员修改规则后提示刷新或重新拉取

9. **编辑提交不用特殊处理**：被屏蔽的字段前端拿不到，提交时是 null，后端有输入侧保护（`PropMaskInputGuard`）会用数据库原值回填，不会把原值覆盖成空
