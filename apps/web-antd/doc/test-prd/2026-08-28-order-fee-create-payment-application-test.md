# 测试说明：应收应付勾选费用创建付费申请

> **适用版本**：2026-08-28 起  
> **覆盖模块**：海运出口、海运进口、空运出口 — 编辑工作台「应收应付」Tab  
> **前置权限**：`Admin.PaymentApplication.Add`（无此权限不显示按钮）

---

## 1. 功能概述

业务人员在应收应付页勾选已审核通过的应付费用后，点击「创建付费申请」，系统校验并回捞可申请明细，跳转付费申请新增页并预填费用，无需在添加费用抽屉中重新搜索。

---

## 2. 测试入口

| 业务     | 路径                               |
| :------- | :--------------------------------- |
| 海运出口 | 海出列表 → 编辑 → **应收应付** Tab |
| 海运进口 | 海进列表 → 编辑 → **应收应付** Tab |
| 空运出口 | 空出列表 → 编辑 → **应收应付** Tab |

---

## 3. 前置数据

准备一票业务，应付费用满足：

- 已保存（有费用 id）；
- 组合费用状态为 **审核通过** 或 **部分结算**；
- 同一结算对象；
- **未申请修改/删除在审**；
- **剩余可申请额度 > 0**（未占满付费申请/收费结算/开票申请）。

另备对照数据：录入中、提交审核、申请修改在审、结算完毕、额度为 0 等各至少一条。

---

## 4. 用例清单

### TC-01 按钮权限

| 步骤 | 操作 | 预期 |
| :-- | :-- | :-- |
| 1 | 使用**无** `Admin.PaymentApplication.Add` 的账号进入应收应付 | 不显示「创建付费申请」按钮 |
| 2 | 使用**有** Add 权限的账号进入 | 显示按钮 |

### TC-02 正常创建（仅勾应付）

| 步骤 | 操作 | 预期 |
| :-- | :-- | :-- |
| 1 | 勾选 1 条及以上应付，状态审核通过，同结算对象，有额度 | — |
| 2 | 点击「创建付费申请」 | 按钮 loading；成功后跳转 `/fee-management/payment-application/add?orderFeeIds=...` |
| 3 | 查看新增页费用明细 | 已预填勾选费用；本次申请金额默认=可申请金额；**不**自动弹出添加费用抽屉 |

### TC-03 混选应收（应失败或需重选）

| 步骤 | 操作 | 预期 |
| :-- | :-- | :-- |
| 1 | 同时勾选应付（已通过）+ 应收（未审核） | — |
| 2 | 点击「创建付费申请」 | 提示未审核通过或状态不可申请，**不跳转** |

### TC-04 申请修改在审

| 步骤 | 操作 | 预期 |
| :-- | :-- | :-- |
| 1 | 对某应付费用提交「申请修改」且仍在审 | 列表组合状态显示「申请修改」 |
| 2 | 勾选该费用并点击创建 | 提示「正在申请修改…」，**不跳转** |

### TC-05 无应付仅应收

| 步骤 | 操作           | 预期                           |
| :--- | :------------- | :----------------------------- |
| 1    | 只勾选应收费用 | —                              |
| 2    | 点击创建       | 提示「请至少选择一条应付费用」 |

### TC-06 多结算对象

| 步骤 | 操作                       | 预期               |
| :--- | :------------------------- | :----------------- |
| 1    | 勾选两条应付但结算对象不同 | —                  |
| 2    | 点击创建                   | 提示结算对象不一致 |

### TC-07 额度已用尽

| 步骤 | 操作 | 预期 |
| :-- | :-- | :-- |
| 1 | 勾选已通过但无可申请额度的应付 | — |
| 2 | 点击创建 | 提示无可申请额度或回捞 0 条（以实际数据为准） |

### TC-08 部分可申请

| 步骤 | 操作 | 预期 |
| :-- | :-- | :-- |
| 1 | 勾选 2 条：1 条可申请 + 1 条不可申请 | — |
| 2 | 点击创建 | 若前端全量校验失败则提示重选；若仅后端过滤则 warning「共选 N 条，M 条可申请」后带 M 条跳转（以当前实现：前端先拦全部须通过，后端回捞可能更少） |

> **说明**：当前实现为前端要求**全部勾选行**状态合格；跳转前 `GetOrderFeeGroupAsync` 再过滤，返回少于请求数时 warning 但仍跳转。

### TC-09 保存与发票方式

| 步骤 | 操作                             | 预期                         |
| :--- | :------------------------------- | :--------------------------- |
| 1    | 预填成功后选择发票方式、绑定银行 | —                            |
| 2    | 保存                             | 正常 `AddAsync` 创建付费申请 |

---

## 5. 状态对照（测试必读）

| 页面「组合费用状态」 | 能否创建付费申请           |
| :------------------- | :------------------------- |
| 审核通过 (2)         | ✅（且有额度、无待审任务） |
| 部分结算 (3)         | ✅（且有额度）             |
| 录入中 / 提交审核    | ❌                         |
| 结算完毕 (4)         | ❌                         |
| 申请修改 (6)         | ❌                         |
| 申请删除 (7)         | ❌                         |

**注意**：申请修改在审时，库里 `FeeStatus` 可能仍为 2，但页面显示「申请修改」，不可申请付费。

---

## 6. 回归点

- 付费申请新增页原有「添加费用」抽屉流程不受影响（无 `orderFeeIds` 时仍自动打开抽屉）。
- 海出/海进/空出费用录入、提交审核、申请修改/删除流程不受影响。
