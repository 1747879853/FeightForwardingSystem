# 测试说明：毛重 / 体积 / 费用数量 4 位小数且不展示末尾 0

> **适用版本**：2026-08-31 起  
> **关联缺陷**：[TAPD #1000905](https://www.tapd.cn/61580498/bugtrace/bugs/view/1161580498001000905)  
> **变更记录**：
>
> - [毛重体积皮重 4 位小数](../changelogs/change-log-2026-08-31-weight-volume-4-decimal.md)
> - [派车、联系单与费用数量对齐](../changelogs/change-log-2026-08-31-dispatch-preorder-fee-qty-4-decimal.md)

---

## 1. 功能概述

毛重、皮重、体积、正式费用「数量」改为最多 **4 位小数**；位数不够时 **不展示末尾 0**（`1.2000` 显示 `1.2`）。金额仍是 2 位。空运长宽高 / 体积重 / 计费重 / 泡比仍是 6 位。

开发已在浏览器测过录入与展示（未点保存），测试需覆盖保存、回显、费用联动。

## 3. 统一预期（所有 4 位字段）

| 输入      | 失焦 / 展示                 | 保存后再打开  |
| :-------- | :-------------------------- | :------------ |
| `1.2`     | `1.2`（不要变成 `1.2000`）  | 仍是 `1.2`    |
| `1.23456` | `1.2346`（四舍五入到 4 位） | 仍是 `1.2346` |
| `1.2000`  | `1.2`                       | 仍是 `1.2`    |
| 空        | 空                          | 空            |
| 负数      | 不允许（`min=0`）           | —             |

输入过程中应能打出小数点（例如先打 `1.` 再打数字），不要被格式化打断。

## 4. 用例清单

### TC-01 海出主单 + 集装箱（P0）

| 步骤 | 操作 | 预期 |
| :-- | :-- | :-- |
| 1 | 海出新建，货物区毛重填 `1.2`、体积填 `1.23456` | 毛重显示 `1.2`，体积显示 `1.2346` |
| 2 | 集装箱行毛重 / 皮重 / 体积同样测 `1.2` 与超过 4 位 | 同上 |
| 3 | 保存后再打开 | 回显与保存前一致，无末尾 0 |

### TC-02 海出派车 + 分单（P0）

| 步骤 | 操作 | 预期 |
| :-- | :-- | :-- |
| 1 | 已有海出票（可用 `JHTSE260825009`）→ 派车 → 箱行毛重 / 皮重 / 体积 | 4 位、去尾 0 |
| 2 | 分单 Tab：分单 kgs / cbm 与分单装箱重量体积 | 同上 |
| 3 | 保存后再打开 | 不削成 2 位 |

### TC-03 海出 / 海进 / 空出费用数量（P0）

| 步骤 | 操作 | 预期 |
| :-- | :-- | :-- |
| 1 | 应收应付 Handsontable 数量填 `1.4443` | 显示 `1.4443`，不要变成整数 `1` |
| 2 | 打开费用编辑弹窗看数量 | 同样 4 位、去尾 0 |
| 3 | 单位为毛重 / 尺码时，改主单 KGS / CBM 后看数量是否跟着走 | 数量等于对应毛重或体积（4 位） |
| 4 | 含税单价、金额 | **仍是 2 位**，不要跟着变成 4 位 |
| 5 | 保存后再打开 | 数量仍是 4 位 |

### TC-04 海进主单 + 集装箱（P0）

| 步骤 | 操作                                      | 预期         |
| :--- | :---------------------------------------- | :----------- |
| 1    | 海进新建 / 编辑：主单毛重、体积、净重合计 | 4 位、去尾 0 |
| 2    | 集装箱毛重 / 皮重 / 净重 / 体积           | 同上         |
| 3    | 保存回显                                  | 与录入一致   |

### TC-05 空出主单 + 货物明细（P0）

| 步骤 | 操作 | 预期 |
| :-- | :-- | :-- |
| 1 | 主单毛重 / 体积填 4 位小数 | 4 位、去尾 0 |
| 2 | 货物明细单件重量、单件体积 | 4 位、去尾 0 |
| 3 | 填长宽高，看单件体积 | 长×宽×高÷1000000 后按 **4 位** 四舍五入 |
| 4 | 长宽高、体积重、计费重、泡比 | **仍是 6 位**，不要改成 4 位 |

### TC-06 业务联系单（P0）

| 步骤 | 操作 | 预期 |
| :-- | :-- | :-- |
| 1 | 主单毛重 / 尺码填 `1.23456` | 显示 `1.2346` |
| 2 | 箱型货重同样 | 4 位、去尾 0 |
| 3 | 费用单位选重量 / 体积 | 数量只读，等于毛重 / 尺码，展示 4 位 |
| 4 | 保存、提交审核 | 主单与货重按 4 位落库；费用数量库列仍可能 2 位，**审核通过后会按 Kgs/Cbm 重算**，以重算后为准 |

### TC-07 回归：不要误改的字段（P1）

以下保持原精度，不要变成 4 位：

- 费用金额、含税单价（2 位）
- 空运长宽高 / 体积重 / 计费重 / 泡比（6 位）
- 超长 / 超宽 / 超高
- 运价金额
- 发票货物明细数量
- 箱型基础资料皮重 / 限重

## 5. 已知说明（不是缺陷）

- 业务联系单费用数量列 `PreOrderFee.Quantity` 库仍是 `decimal(10,2)`。界面按 4 位展示是为了和正式费用对齐；转换海出时会丢弃该列再按毛重 / 体积重算。
- 开发自测未点保存；测试必须走保存 + 再打开。
- 原缺陷只写了海出，前端按同一精度把海进、空出、派车、联系单、正式费用数量一起改了，都要测。
