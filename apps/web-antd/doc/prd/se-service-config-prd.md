## 1. 产品概述

### 1.1 业务背景

按**起运港**维护海运出口**服务项模板**。每个模板定义：

- 该港口下有哪些服务项（订舱、拖车、报关等）
- 每项服务的责任角色（销售/商务/操作等）
- 是否允许自动完成、手动完成、完成提醒
- 服务完成前展示哪些字段、完成后锁定/必填哪些字段

配置完成后，供海运出口业务单据的服务任务执行环节复用。

### 1.2 核心价值

| 维度     | 说明                                        |
| -------- | ------------------------------------------- |
| 配置粒度 | 一个起运港 = 一条主配置，内含多条服务项明细 |
| 使用场景 | 基础数据管理员在系统上线或业务变更时维护    |
| 下游影响 | 海运出口订单/任务执行时的服务项规则来源     |

### 1.3 不在本模块范围内

- 不直接操作海运出口订单
- 不包含服务任务的实际执行/完成操作
- 用户属性选项不含「财务」「人事」（与海运出口订单角色口径一致，共 6 项）

## 4. 页面结构

### 4.1 列表页

**路由：** `/basic-data/se-service-config`  
**页面标题：** 港口服务项配置列表  
**KeepAlive：** 是（从其他页返回时保留筛选/分页状态）

#### 4.1.1 筛选条件

| 字段       | 组件                       | 行为                   |
| ---------- | -------------------------- | ---------------------- |
| 起运港     | PortSelect                 | 可清空；变更后自动查询 |
| 服务项类型 | Select（ServiceType 枚举） | 可清空；变更后自动查询 |

#### 4.1.2 列表列

| 列名 | 数据来源 | 展示规则 |
| --- | --- | --- |
| 起运港 | `pol.portName` / `pol.cnName` | 优先 `portName`，兼容 `cnName` |
| 服务项类型 | `seServiceConfigItems` | 按 `sortId` 排序后，以「、」连接枚举文案；子项不存在时回退 `serviceTypes` 汇总 |
| 服务项数量 | `serviceItemCount` | 数字，居中 |
| 排序 | `sortId` | 主配置排序值 |
| 创建时间 | `creationTime` | 格式化为日期时间 |
| 操作 | — | 编辑、删除 |

#### 4.1.3 列表数据模型（重要）

- **每行 = 一条主配置**（`SeServiceConfig`），不是一条服务项明细
- `totalCount` = 主配置总数，不是服务项总数
- 同一港口只应出现 **1 行**（后端同租户 `polId` 唯一）

> **历史缺陷参考：** 若一次新增 2 个服务项后列表出现 2 行同港口记录，属后端列表分页口径错误，应报缺陷。

### 4.2 新增/编辑弹窗

**宽度：** 约 1000px  
**模式：** 弹窗（Modal），关闭后销毁（`destroyOnClose`）

#### 4.2.1 主配置区（上半部分）

| 字段   | 必填 | 组件        | 默认值 | 说明                 |
| ------ | ---- | ----------- | ------ | -------------------- |

| 排序   | 否   | InputNumber | 0      | 整数 ≥ 0             |
| 备注   | 否   | TextArea    | 空     | 2 行                 |

#### 4.2.2 服务项配置明细区（下半部分）

每条明细为一个独立卡片，标题格式：**「服务项 #序号 · 服务项类型名称」**（左侧蓝色竖线样式）。

| 字段 | 必填 | 组件 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 服务项类型 | 是 | Select | — | 同配置内不可重复 |
| 自动完成 | 否 | Switch | 关 | 与「允许手动完成」「完成提醒」同一行 |
| 允许手动完成 | 否 | Switch | **开** |  |
| 完成提醒 | 否 | Switch | 关 |  |
| 用户属性 | 否 | Checkbox 多选 | 空 | 6 项：销售、商务、操作、客服、单证、海外客服 |
| 展示字段 | 否 | Select（tags 多选） | 空 | SeaExportPropEnum，候选集见 §5.3 |
| 完成后锁定字段 | 否 | Select（tags 多选） | 空 | 仅基础字段 ≤1000 |
| 完成时必填字段 | 否 | Select（tags 多选） | 空 | 仅基础字段 ≤1000 |
| 备注 | 否 | TextArea | 空 |  |

**明细操作按钮：**

| 按钮       | 条件              | 行为                     |
| ---------- | ----------------- | ------------------------ |
| 上移       | 非第一条          | 与上一条交换位置，带动画 |
| 下移       | 非最后一条        | 与下一条交换位置，带动画 |
| 删除       | 明细 > 1 条时可删 | 移除该明细               |
| 新增服务项 | 始终可用          | 追加空白明细             |

**底部提示：**  
「可通过"上移/下移"手动调整服务项顺序，保存时按当前列表顺序自动写入排序值（从 0 开始）。」

#### 4.2.3 用户属性服务概览（P1）

- 位置：「服务项配置明细」标题下方
- 触发：明细中勾选用户属性并选择服务项类型后**实时更新**
- 展示：按角色分组，显示该角色当前负责的服务项类型名称
- 无配置时不显示概览区

## 5. 业务规则

### 5.1 主配置规则

| 规则 ID | 规则描述                                                       |
| ------- | -------------------------------------------------------------- |
| R-01    | 起运港必填                                                     |
| R-02    | 同租户下同一起运港只能存在一条主配置                           |
| R-03    | 新增时至少包含 1 条服务项明细（打开弹窗自动添加 1 条空白明细） |
| R-04    | 编辑时若后端返回 0 条明细，前端自动补 1 条空白明细             |

### 5.2 服务项明细规则

| 规则 ID | 规则描述 |
| --- | --- |
| R-05 | 每条明细的服务项类型必填 |
| R-06 | 同一配置下服务项类型不可重复（前端校验，报错：「同一配置下服务项类型不能重复」） |
| R-07 | 保存时 `sortId` 按当前 UI 顺序从 0 递增写入 |
| R-08 | 编辑回显时按 `sortId` 升序排列明细 |
| R-09 | 删除明细后保存，后端应级联删除对应子项 |
| R-10 | 子表（展示/锁定/必填字段）采用差异更新：有 id 更新、无 id 新增、提交缺失的 id 删除 |

### 5.3 SeaExportPropEnum 千位分流规则（重点）

后端枚举分两段：

- **基础字段（1~17）：** CarrierId、POLId、PODId、Vessel、ETD、ClientId 等
- **额外字段（1001+）：** CarrierName、ClientName 等，设计为 `1000 + 基础 value`

| 下拉 | 可选范围 | 示例 |
| --- | --- | --- |
| 展示字段 | `>1000` 始终可选；`≤1000` 且不存在对应 `value+1000` 时可选 | 有 1017 则不可选 17，但 4(Vessel) 仍可选 |
| 锁定字段 | 仅 `≤1000` | 不可选 ClientName(1017) |
| 必填字段 | 仅 `≤1000` | 同锁定字段 |

**编辑回显：** 锁定/必填中若存在历史 `>1000` 的值，前端会过滤不显示。  
**非法输入：** tags 模式下手工输入不在白名单的枚举值会被过滤，不会提交。

### 5.4 服务项类型枚举

| 值  | 默认文案 |
| --- | -------- |
| 0   | 订舱     |
| 1   | 拖车     |
| 2   | 报关     |
| 3   | 仓库     |
| 4   | 保险     |
| 5   | 代收支   |

> 实际文案以系统枚举 `ServiceType` 为准；列表与弹窗共用同一套加载逻辑。

### 5.5 用户属性（位标志）

| 角色     | 说明       |
| -------- | ---------- |
| 销售     | 可多选组合 |
| 商务     |            |
| 操作     |            |
| 客服     |            |
| 单证     |            |
| 海外客服 |            |

一个服务项可绑定多个角色；提交时合并为整型位掩码 `userAttribute`。

## 7. 接口清单

**API 前缀：** `/services/app/SeServiceConfigAdmin`

| 接口                | 方法   | 用途                    |
| ------------------- | ------ | ----------------------- |
| `GetPagedListAsync` | GET    | 分页列表（主配置维度）  |

| `DeleteAsync`       | DELETE | 删除（支持 `ids` 数组） |

### 7.1 列表请求参数

```
polId       可选，起运港 ID
serviceType 可选，服务项类型
pageIndex   页码
pageSize    每页条数
```

### 7.2 新增/编辑请求体结构（关键字段）

```json
{
  "polId": "10001",
  "sortId": 0,
  "remark": "备注",
  "seServiceConfigItems": [
    {
      "id": "xxx",
      "serviceType": 1,
      "userAttribute": 3,
      "autoComplete": false,
      "manualAllowed": true,
      "reminder": false,
      "sortId": 0,
      "remark": "",
      "seServiceShows": [{ "id": "...", "seaExportPropEnum": 1017 }],
      "seServiceLocks": [{ "seaExportPropEnum": 17 }],
      "seServiceRequires": [{ "seaExportPropEnum": 16 }]
    }
  ]
}
```

> 注：`id` 字段仅在编辑时存在；新增时子项不含 `id`。

## 9. 验收标准（Must Have）

1. **列表口径正确：** 1 个港口 + N 个服务项 = 列表 1 行，`serviceItemCount = N`
2. **CRUD 闭环：** 新增、编辑、删除均可完成且数据一致
3. **校验生效：** 起运港必填、服务项类型必填、类型不可重复
4. **排序持久化：** 上移/下移后保存，再次编辑顺序不变
5. **枚举回显：** 列表与弹窗服务项类型文案一致，不出现裸数字
6. **港口回显：** 编辑态起运港稳定显示
7. **字段分流：** 展示/锁定/必填三套下拉候选集符合千位规则
8. **子表差异更新：** 编辑字段规则后不产生脏数据
9. **权限控制：** 无权限用户不可操作
10. **删除级联：** 删主配置后子项不可单独查询

## 10. 已知风险与测试关注点

| 风险点 | 说明 | 测试建议 |
| --- | --- | --- |
| 列表重复行 | 后端曾按子项分页导致同港口多行 | 重点验证 TC-107、TC-108 |
| sortId 不一致 | 数组顺序与 sortId 不同步可能导致回显乱序 | 多次调整顺序后反复编辑验证 |
| 枚举异步加载 | 列表初次加载可能短暂显示数字 | 刷新后应变为文案 |
| tags 手工输入 | 展示/锁定/必填支持 tags 模式 | 尝试输入非法值验证过滤 |
| 软删除子项 | 已软删子项不应出现在列表/详情 | 编辑后删除子项再查详情 |
