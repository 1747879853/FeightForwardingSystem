> **模块名称：** 海运出口 **页面路径：** 新建 `/sea-exports/create`、编辑 `/sea-exports/:id/edit`（基础信息 Tab 内服务项目流水线）、工作台服务任务（完成/取消完成/转交） **菜单入口：** 海运出口列表 → 新建 / 双击行进入编辑；仪表盘工作台 → 服务任务 **权限标识：** 新增 `Admin.SeaExport.Add`；编辑 `Admin.SeaExport.Edit`（服务项目与执行方字段共用海出编辑权限，无独立权限点） **文档版本：** v1.0 **更新日期：** 2026-07-11 **参考文档：** `doc/modules/sea-exports/id-edit.md`

## 1. 产品概述

### 1.1 业务背景

一票海运出口从下单到出运，需要按固定优先级完成一串「服务项目」（如订舱、报关、拖车、保险等）。系统把「本票要做哪些服务」和「当前该谁去做的待办任务」分成两层管理，并按港口配置的优先级（`SortId`）逐档推进：同一优先级的服务可并行，全部完成后才解锁下一档。测试要重点验证「勾了什么」「什么时候生成任务」「什么时候重建任务」「谁能完成」「完成后锁哪些字段」这几条主线。

### 1.2 核心概念（务必先分清两张表）

| 概念 | 实体 | 含义 |
| :-- | :-- | :-- |
| **服务项目** | `SeaExportService` | 本票勾选的全部服务项清单，带 `serviceType` + `sortId`（优先级） |
| **服务任务** | `SeServiceTask` | 按优先级逐档生成的待办；**不是**勾选后一次性全生成 |
| **优先级** | `SortId` | 来自港口服务项配置，**相同 SortId = 同优先级**，可并行多任务；前端传的 sortId 后端忽略 |
| **处理人** | `SeServiceTaskUser` | 由服务项配置的 `UserAttribute` 与本票干系人（OrderUser）按位匹配生成 |

### 1.3 核心价值

| 维度 | 说明 |
| --- | --- |
| 配置/操作粒度 | 委托客户 × 起运港 × 服务项 |
| 使用场景 | 业务/单证/操作/客服在同一票据上按优先级协作推进服务 |
| 下游影响 | 服务任务完成可触发费用生成；服务锁定字段影响基础信息可编辑范围 |

### 1.4 不在本功能范围内（不能测成缺陷）

- 前端传的 `sortId` 不会改变优先级，也不会触发重建 / 同步（后端一律以港口配置为准）。
- 勾选服务项后**不会**立刻生成全部任务，只生成最小 `SortId` 那一档。
- 客户排除的服务项**仍可手动勾选**，`checked` 只影响默认勾选。
- 复制（`CopyAsync`）走后端既有生成逻辑，本轮前端不特判。
- 工作台完成/取消完成/转交的交互链路本轮未改动。

## 4. 页面结构

### 4.1 入口与状态

- 服务项目流水线位于**基础信息 Tab 顶栏**（与 AI 识别同一行），左侧「服务项目」标题 + `...` 配置入口 + Chevron 三态流水线。
- 流水线按 `sortId` 视觉分组：同组紧密排列为一块，不同优先级组之间留间距。
- 三态图标：`已完成`（对勾）/`处理中`（当前活跃组）/`还未到`（后续组）。
- 新建页：未选起运港时不展示服务项内容；选港后按配置渲染。
- 编辑页：首屏按详情渲染；改港/改委托单位后进入「新建态预览」（见 R-05）。

### 4.2 字段与展示规则（服务相关）

| 字段/列 | 数据来源 | 展示/编辑规则 |
| --- | --- | --- |
| 服务项勾选 | `GetServiceTypesByPOLAsync` / 详情 `seaExportServices` | 新建按 `checked` 默认；编辑首屏按详情；改港/改客户按新 `checked` 重写 |
| `sortId` 分组 | 港口配置 | 展示与分组用；提交可不传，后端忽略前端值 |
| 任务态 | 详情 `seServiceTask.serviceTaskStatus` | `0` 待处理 / `1` 已处理；无任务为 `null`（未到该优先级） |
| 处理人 | `seServiceTaskUsers` | 仅待处理返回；已转交时仅被转交人 |
| 锁定字段 | 配置 `seServiceLocks` | 已完成任务对应字段在编辑页置只读（disabled） |

## 5. 业务规则（测试重点）

| 规则 ID | 规则描述 |
| --- | --- |
| R-01 | 拉配置查找顺序：先找该 `polId` 专属配置 → 无则用默认港（`POLId=null`）→ 都无则报错「该起运港未配置服务项目」。 |
| R-02 | 新建/复制保存：只生成**最小 SortId** 且本票已勾选的服务项任务；处理人按 `(config.UserAttribute & orderUser.UserAttribute) != 0` 匹配，匹配不到报错。 |
| R-03 | 完成任务：需当前用户为处理人（或被转交人）；校验当前+历史已完成任务的必填字段（`SeServiceRequires`）与必填费用（`RequireFee`）。 |
| R-04 | 完成推进：**仅当当前 SortId 档已勾选服务项任务全部完成**，才生成下一档任务；否则只完成本条。 |
| R-05 | 编辑改起运港（`polId` 变）**或**服务项集合（`serviceType` 排序后不一致）变 → 后端**重建**：删全部服务项+任务→按新配置重插→生成首档。仅前端 `sortId` 变不重建、不同步。 |
| R-06 | 编辑改 `polId` 或 `clientId`：前端按新港+客户 `checked` **重写勾选**（客户排除项默认不勾、可手动勾回），丢弃任务进度，流水线回到「新建态」仅展示服务项、不显示任务；保存成功后恢复真实任务态。 |
| R-07 | 编辑保存重建二次确认：当 `polId` 或勾选集合相对详情变化，**且本票已有任意任务**，弹「将清空全部服务任务进度并重新生成」，取消则中止保存；无任务时不弹、直接保存。 |
| R-08 | 配置服务弹窗：选项为**当前起运港配置全量**服务项（可增可删）；编辑态点「确定」直接应用勾选并保存，重建确认由保存流程统一处理。 |
| R-09 | 已完成任务锁定字段：编辑页把所有**已完成**任务对应服务项 `seServiceLocks` 的字段置为只读（disabled）；取消完成或改港重写后自动解除。字段值仍随 DTO 提交，由后端用库值覆盖。 |
| R-10 | 服务责任角色预校验：保存前按当前勾选服务项的 `userAttribute` 校验干系人（每个服务至少有一个绑定角色已选人），不通过禁止保存并提示缺哪类角色；销售必须且只能有一人，销售/操作不可删除。 |
| R-11 | 不重建时（港与集合都没变）：后端对**待处理且未转交**任务按新 OrderUser 重算处理人；**已转交/已完成**不动；匹配不到报错「未找到对应用户属性的处理人，无法同步任务处理人」。 |
| R-12 | 取消完成：当前任务改回待处理、清空完成人/时间，并**删除本票 SortId 大于当前任务的所有后续任务**（进度回退）。 |

## 6. 接口清单

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `SeaExportAdmin/GetServiceTypesByPOLAsync` | GET | 按起运港（可带委托单位）拉可选服务项、默认勾选、优先级、责任角色、锁定/必填字段 |
| `SeaExportAdmin/AddAsync` | POST | 新建，提交 `serviceTypes` |
| `SeaExportAdmin/EditAsync` | PUT | 编辑，全量回传 `serviceTypes` |
| `SeaExportAdmin/CopyAsync` | POST | 复制 |
| `SeaExportAdmin/DetailAsync` | GET | 详情带回 `seaExportServices[].seServiceTask` |
| `SeServiceTaskAdmin/Complete`、`CancelComplete`、转交 | POST | 任务推进 |

### 6.1 请求参数要点

- `GetServiceTypesByPOLAsync`：`polId` 决定可见范围；`polId+clientId` 决定默认勾选（`checked`）。
- 提交 `serviceTypes`：编辑为**全量替换**语义，即使未改也要回传当前勾选结果；`sortId` 可不传。

```json
{
  "serviceTypes": [{ "serviceType": 0 }, { "serviceType": 2 }]
}
```

## 7. 测试用例（建议）

### 7.1 入口与权限

| 用例 ID | 步骤 | 期望结果 |
| --- | --- | --- |
| TC-001 | 无 `Admin.SeaExport.Edit` 用户打开编辑页 | 服务项目只读，不能勾选/完成 |
| TC-002 | 新建页未选起运港 | 不展示服务项目内容 |

### 7.2 主流程

| 用例 ID | 步骤 | 期望结果 |
| --- | --- | --- |
| TC-101 | 新建选起运港（有专属配置） | 按 `checked` 默认勾选，客户排除项默认不勾但可手动勾 |
| TC-102 | 新建勾选服务项并配好干系人后保存 | 保存成功，仅最小 SortId 档生成任务 |
| TC-103 | 新建缺少某服务项绑定角色的干系人后保存 | 拦截并提示缺哪类角色（R-10） |
| TC-104 | 编辑页首屏 | 勾选/任务态/处理人按详情回显；未到优先级的服务无任务 |
| TC-105 | 编辑完成当前活跃组的最后一个任务 | 生成下一 SortId 档任务；组内未全完成时只完成本条 |
| TC-106 | 编辑改起运港为另一有配置的港 | 勾选按新港+客户 `checked` 重写；流水线转为新建态、不显示旧任务 |
| TC-107 | 承 TC-106 且本票原有任务，点保存 | 弹重建二次确认；确认后进度清空、按新配置重建首档 |
| TC-108 | 编辑仅改委托单位（起运港不变） | 按新客户 `checked` 重写勾选；集合若变→保存重建；集合不变→保存后待处理未转交任务处理人按新 OrderUser 同步 |
| TC-109 | 编辑 `...` 配置弹窗新增当前港的一个服务项后确定 | 弹窗展示当前港全量服务项；确定后应用并触发保存（有任务则重建确认） |
| TC-110 | 完成某服务后，编辑页对应 `seServiceLocks` 字段 | 该字段置灰只读；取消完成后恢复可编辑（R-09） |

### 7.3 边界与回归

| 用例 ID | 步骤 | 期望结果 |
| --- | --- | --- |
| TC-901 | 编辑不改任何服务项与起运港直接保存 | 不弹重建确认，任务进度保留 |
| TC-902 | 仅调整（假设）前端 sortId、不改集合与港 | 不重建、不同步；优先级仍按配置 |
| TC-903 | 改委托单位后待处理任务角色匹配失败并保存 | 报错「未找到对应用户属性的处理人，无法同步任务处理人」 |
| TC-904 | 取消完成一个已完成任务 | 该任务回待处理，SortId 更大的后续任务被删除（R-12） |
| TC-905 | 起运港无配置且传了服务项 | 报错「该起运港未配置服务项目，不允许输入服务项」 |
| TC-906 | 完成任务但必填字段/必填费用缺失 | 拦截并提示「请先填写…」/「完成任务需要以下费用…」 |
| TC-907 | 已转交任务，改委托单位并保存（未重建） | 已转交任务处理人不被覆盖 |
| TC-908 | 已完成任务锁定了起运港字段，尝试改起运港 | 起运港只读不可改（需先取消完成） |

## 8. 验收标准（Must Have）

1. 新建/编辑保存后，服务项目集合与后端一致；任务仅按最小 SortId 档生成。
2. 编辑改起运港/委托单位后勾选按新配置重写，且未保存前不显示旧任务、不可操作旧任务。
3. 起运港或集合变化且已有任务时，保存前必有重建二次确认；取消不落库。
4. 已完成任务锁定字段在编辑页只读；取消完成后恢复。
5. 保存前服务责任角色预校验生效，缺角色明确提示且不提交。
6. 完成/取消完成推进与回退符合 R-04 / R-12。

## 9. 已知风险与测试关注点

| 风险点 | 说明 | 测试建议 |
| --- | --- | --- |
| 重建清空已完成进度 | 改港/改集合保存后已完成任务也归零 | 重点验证二次确认文案与取消不落库；确认后进度确实重置 |
| 新建态预览与库不一致 | 改港后未保存时流水线是预览态 | 验证此时不能点完成/取消完成；刷新/离开不误保存 |
| 锁定字段仍提交 | disabled 字段值仍进 DTO，由后端覆盖 | 确认后端以库值为准，前端只读仅防误操作 |
| 历史脏数据 | 详情服务项不在当前港配置中 | 验证首屏仍保留该历史服务项、不丢节点 |
| 接口路径命名 | 文档写 `GetServiceTypesByPOL`，实际调 `GetServiceTypesByPOLAsync` | 抓包核对接口名一致 |
| 默认港兜底 | 专属港无配置时用 `POLId=null` 默认港 | 覆盖「专属港无配置但默认港有」的场景 |
