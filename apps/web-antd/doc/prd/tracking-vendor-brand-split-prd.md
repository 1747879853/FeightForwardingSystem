# 运踪按品牌分流（新服务商运踪）PRD（测试版）

> **模块名称：** 共享能力 / 运踪（影响海运进口、海运出口、空运出口） **页面路径：** `/sea-imports`、`/sea-exports`、`/air-exports`、`/air-exports/:id/edit` **菜单入口：** 操作管理 → 海运进口 / 海运出口 / 空运出口 **权限标识：** 列表本身用各模块 `Admin.SeaImport.* / Admin.SeaExport.* / Admin.AirExport.*`；运踪订阅用 `Admin.ExternalApi.Use`，运踪查看用 `Admin.ExternalApi.Get` **文档版本：** v1.0 **更新日期：** 2026-08-16 **参考文档：** `doc/modules/shared/feituo-tracking-brand-split.md`

## 1. 产品概述

### 1.1 业务背景

运踪就是「这票货现在到哪了」。系统原来只有一家服务商的运踪（海运出口、空运出口已上线）。本次按**打包品牌 × 业务线**分流到新服务商：世纪通达（`sjtd`）的**海运出口**继续用原来那套，其余场景（全品牌海运进口、全品牌空运出口、非 `sjtd` 品牌的海运出口）改用新服务商。

同时新增两件事：列表「主提单号 / 主运单号」前加**异常预警黄色叹号**（悬停看原因）；以及**用户界面不允许出现服务商名称**，所有对外话术统一叫「运踪」。

### 1.2 核心价值

| 维度     | 说明                                                              |
| -------- | ----------------------------------------------------------------- |
| 分流粒度 | 打包品牌（构建期 `VITE_APP_BRAND`）× 业务线（海出 / 海进 / 空出） |
| 使用场景 | 操作、客服跟单：批量订阅运踪、看当前节点、看异常预警、看轨迹地图  |
| 下游影响 | 列表跟单效率；异常预警是催单依据；对外分享页要求白标              |

### 1.3 不在本功能范围内

- **空运进口**运踪（模块尚未建设，不做，也不预留入口）。
- **其他品牌海运出口的对外分享页白标改造**（本期未做，分享入口仍是原品牌那套）。
- 服务商推送回调地址配置、IP 白名单等**后端/运维事项**。
- 云当（原服务商）空运前端代码的删除（本期只摘入口，代码保留）。

## 4. 页面结构

### 4.1 入口与状态

**列表工具栏**：「运踪订阅」按钮在最左侧，右侧带一个问号图标，悬停显示订阅规则（各业务线文案不同）。按钮 loading 期间不可重复点击。

**运踪状态列**：列标题「运踪状态」。Tag 文案与颜色由四态决定：

| 状态 | 触发条件 | Tag 文案 | 颜色 |
| --- | --- | --- | --- |
| 未订阅 | 无订阅记录 | 未订阅 | 灰（default） |
| 订阅失败 | 有订阅记录但订阅未成功 | 订阅失败 | 红（error） |
| 数据获取中 | 订阅成功但服务商还没返回当前节点 | 数据获取中 | 橙（warning） |
| 有轨迹 | 有当前节点 | 当前节点中文描述（预计节点加「（预计）」） | 蓝（processing） |

**运踪详情弹窗**（海运）：顶部数据状态标签 + 数据更新时间 + 「查看轨迹地图」；下方依次是甩柜提示（如有）、最近一条异常预警（如有）、关键信息表（订阅号 / 数据状态 / 当前节点 / 发生时间 / 发生地 / 头程船名航次 / 起运预计-实际离开 / 目的预计-实际到达 / 订舱状态 / 箱量汇总）、集装箱清单（箱号 / 箱型 / 当前状态 / 发生地 / 甩柜）。

**运踪详情弹窗**（空运）：字段换成航司单号 / 航空公司 / 当前节点 / 当前航班 / 起飞-目的机场 / 航班 / 目的预计-实际到达 / 货物 / 中转方式。

**空运编辑页「运踪信息」Tab**：摘要表 + **全量异常预警明细表**（发生时间 / 预警类型 / 发生地 / 预警说明）+ 「查看轨迹地图」+ 「重新订阅」。

**空状态**：未订阅显示「尚未订阅运踪，请先使用「运踪订阅」」；订阅失败显示红色 Alert + 失败原因；数据获取中显示蓝色 Alert + 「轨迹数据尚未返回，到达后会自动更新，无需重复订阅」。

### 4.2 字段与展示规则

| 字段/列 | 数据来源 | 展示/编辑规则 |
| --- | --- | --- |
| 运踪状态 | 列表返回的 `feituoTracking` 摘要 + `isFeituoSubscribed` / `isFeituoSubscribeSuccess` | 只读；无 `Admin.ExternalApi.Get` 时为不可点的纯文本 |
| 预警叹号 | `feituoTracking.hasWarning` / `warningCount` / `latestWarningDescription` / `latestWarningTime` | `hasWarning=false` 时**完全不渲染**，不占位、不影响单号展示 |
| 预警 Tooltip | 同上 | 第一行原因（可能多行，需按换行显示）；有时间则第二行「发生时间：…」；条数 > 1 时第三行「共 N 条预警，全部明细见运踪详情」 |
| 全量预警明细 | 详情接口 `feituoTrackingWarnings` | **只有空运编辑页运踪 Tab 有**；列表接口恒为空 |
| 轨迹地图 | 海运取摘要 `iframeUrl`；空运前端按 env 拼装 | 无链接 / env 缺配置时**不显示**入口 |
| 所有时间字段 | 服务商原样字符串 | 原样展示，不做时区换算、不重新格式化 |

## 5. 业务规则（测试重点）

| 规则 ID | 规则描述 |
| --- | --- |
| R-01 | 分流：仅「`sjtd` 品牌 + 海运出口」用原运踪；其余（含 `sjtd` 的海进/空出）用新服务商。品牌是**构建期**决定的，界面上无切换开关 |
| R-02 | 海运出口订阅号：装运方式=整箱 → 主提单号；拼箱主票/分票 → 第一个箱号 |
| R-03 | 海运进口订阅号：优先主提单号，无主提单号则取第一个箱号 |
| R-04 | 海运两者：船公司必须维护 EDI 代码，否则该票订阅失败并给出原因 |
| R-05 | 空运订阅号：主运单号自动剥离连字符与空格，剥离后必须**恰好 11 位数字**，否则本地拦截不发请求 |
| R-06 | 批量订阅**单条互不影响**：一条失败不影响其它条，结果弹窗逐条列出 |
| R-07 | 空运「已订阅成功且单号未变」的票再次订阅会**复用旧订阅**，结果显示「已订阅」并说明未消耗配额，仍计入成功 |
| R-08 | 「订阅成功但暂无数据」不是失败：海运表现为无 `data`、空运表现为 `trackingLoaded=false`，统一提示「订阅成功，数据获取中」 |
| R-09 | 异常预警**只来自服务商的增量推送**，订阅/查询接口不返回。刚订阅必然是 0 条；回调未配置时会一直是 0 条 |
| R-10 | 列表只给预警**条数 + 最近一条**，全量明细在详情；不允许为了悬停而逐行请求详情 |
| R-11 | 用户可见处**禁止出现服务商名称**。后端返回文案（订阅失败原因、暂无数据说明、预警描述）展示前必须清洗为「运踪服务商」 |
| R-12 | 未勾选任何行点订阅 → 提示「请先勾选需要订阅运踪的数据」，不发请求 |
| R-13 | 勾选超过 30 条 → 提示「单次订阅建议不超过 30 条…」，**只提示不拦截**，仍会全部提交 |
| R-14 | 空运「重新订阅」**会消耗一次订阅配额**，必须二次确认；仅在单号改过或数据异常时使用 |
| R-15 | 空运编辑页基础信息的单票订阅按钮：已订阅成功时置灰，悬停提示去「运踪信息」中重新订阅 |
| R-16 | 空运当前节点可能是**预计**事件（`EST`），此时文案带「（预计）」后缀，与实际节点区分 |
| R-17 | 空运地图 iframe 参数：`key`（可视化密钥，非 token secret）、`clientId`、`businessNumber`（与订阅单号一致）、`showInfo`（系统默认 `2` 收起）、`lang`（跟随界面语言） |
| R-18 | 订阅成功后列表会**自动刷新**，运踪状态列随之更新；数据后续由推送自动更新，前端不轮询 |

## 6. 接口清单

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/api/services/app/FeituoAdmin/SubscribeContainerAsync` | POST | 海运集装箱运踪订阅（海出/海进，批量） |
| `/api/services/app/FeituoAdmin/GetContainerTrackingAsync` | POST | 查询海运运踪本地快照（运踪弹窗补箱清单与轨迹链接） |
| `/api/services/app/FeituoAdmin/SubscribeAirWaybillAsync` | POST | 空运航空货运运踪订阅（批量） |
| `/api/services/app/FeituoAdmin/ResubscribeAirWaybillAsync` | POST | 空运单条强制重新订阅（消耗配额） |
| `/api/services/app/SeaImportAdmin/GetPagedListAsync` | GET | 海运进口列表，已带运踪摘要 |
| `/api/services/app/SeaExportAdmin/GetPagedListAsync` | GET | 海运出口列表，已带运踪摘要 |
| `/api/services/app/AirExportAdmin/GetPagedListAsync` | GET | 空运出口列表，已带运踪摘要 |
| `/api/services/app/AirExportAdmin/DetailAsync` | GET | 空运出口详情，带完整轨迹与**全量预警明细** |

> 权限：订阅类 `Admin.ExternalApi.Use`，查询类 `Admin.ExternalApi.Get`。响应统一 ABP 信封，业务失败是 **HTTP 500 + `success=false`**，按 `success` 判定成败。

### 6.1 请求/响应示例

海运订阅请求（`bizType`：0=海运出口，1=海运进口）：

```json
{
  "bizType": 1,
  "orderIds": ["3f2504e0-4f89-11d3-9a0c-0305e82c3301"]
}
```

```json
{
  "airExportIds": ["3fa85f64-5717-4562-b3fc-2c963f66afa6"],
  "forceResubscribe": false
```

## 8. 验收标准（Must Have）

1. 三个列表都能完成「勾选 → 订阅 → 结果弹窗 → 列表自动刷新 → 状态列更新」闭环，单条失败不影响其它条。
2. `sjtd` 包的海运出口运踪与分享行为**零变化**；非 `sjtd` 包的海运出口只出现新服务商一套入口。
3. 有预警的票在单号前显示黄色叹号，悬停能看到原因、时间与条数；无预警的票不显示任何图标。
4. 用户可见的任何位置（含后端返回的失败原因与提示）**都不出现服务商名称**。
5. 「订阅成功但暂无数据」「已订阅复用」两类结果都归为成功，不得表现为报错。
6. 权限缺失时按「不渲染 / 不可点」降级，无 JS 报错、无空白页。
7. 中英文两种语言下文案完整，无 i18n key 裸露。
8. 时间字段原样展示，无时区偏移。

## 9. 已知风险与测试关注点

| 风险点 | 说明 | 测试建议 |
| --- | --- | --- |
| 预警数据依赖服务商推送 | 异常预警只来自增量推送，回调地址未配置时永远 0 条，**不是前端缺陷** | 先向后端确认回调是否已配置；无真实数据时用 DevTools 覆盖响应验证 UI |
| 轨迹地图需商务开通 | 未开通时 iframe 可能空白或提示无权限 | 先确认开通状态；未开通只验「入口是否按规则显示/隐藏」 |
| 品牌是构建期决定 | 界面上没有切换开关，测 sjtd 必须换构建 | 至少覆盖「一个非 sjtd 包 + sjtd 包」两次回归 |
| env 变更需重启 | 空运地图三个变量在 dev 下改完必须重启才生效 | 发现地图入口不出现时先确认服务已重启 |
| 空运地图参数为新契约 | `businessNumber` / `showInfo` / `lang` 首次接入，`key` 与取 token 的 `secret` 不同 | 用 DevTools 检查 iframe src 参数是否完整、`showInfo=2` |
| 云当空运旧代码仍在仓库 | 已无入口引用，但文件保留 | 若发现界面上还能进入旧空运运踪面板，属缺陷 |
| 海运地图语言参数未确认 | 海运轨迹链接由服务商下发，`lang` 是前端按同名参数追加的 | 实测切换是否生效；不生效记为已知限制并反馈商务，不按缺陷处理 |
| 海运分享令牌是编码非加密 | 令牌可被解码、iframe 请求域名在网络层可见；链接与界面已白标 | 只验「地址栏与页面看不到服务商名称」；更严格的隐藏需后端匿名接口 |
| 列配置自愈 | 新增列会让旧的列配置数据不完整 | 重点验老账号首次进入是否丢配置或报错 |
