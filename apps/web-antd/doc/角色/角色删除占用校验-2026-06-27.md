# 1. 背景意图 (Background)

**TAPD**：#0314 角色删除占用校验

角色实体为软删除（`FullAuditedEntity`），`DeleteRoleAsync` 调用 `_roleManager.DeleteAsync` 仅将 `Sys_Roles` 标记为已删除，**不会自动级联清理** `Sys_UserRoles`。

旧逻辑在删除前会通过 `GetUsersInRoleAsync` 查出关联用户并逐个 `RemoveFromRoleAsync` 后再软删除，存在两个问题：

1. **不符合业务规则**：产品要求「仍有用户占用则禁止删除」，而非静默解除全部关联后删除。
2. **关联清理不可靠**：若解除关联未完整落库，角色软删除后 `Sys_UserRoles` 会残留指向已删角色的孤儿记录，进而影响用户角色相关操作。

# 2. 核心逻辑变更 (Core Logic)

涉及接口：`DELETE /api/services/app/Role/DeleteRoleAsync`

文件：`src/CsprojBuilder.Application/Authorization/Roles/RoleAppService.cs`

- **移除**「先批量解除用户关联再删除」的逻辑。
- 删除前新增占用校验：统计仍关联该 `RoleId` 的用户数量，若 **> 0** 抛出 `UserFriendlyException("该角色已分配给用户，无法删除")`。
- 系统内置角色（`IsStatic`）保持现有不可删校验不变。

变更后核心代码：

```csharp
if (entity.IsStatic)
    throw new UserFriendlyException("该角色属于系统角色，不可删除");

var assignedUserCount = await UserManager.Users
    .CountAsync(u => u.Roles.Any(r => r.RoleId == entity.Id));
if (assignedUserCount > 0)
    throw new UserFriendlyException("该角色已分配给用户，无法删除");

CheckErrors(await _roleManager.DeleteAsync(entity));
```

# 3. 避坑指南 (Pitfalls)

- 占用判定基于 `Sys_UserRoles`（`AbpUser.Roles` 导航的 `RoleId`），与基础资料删除引用校验模式保持一致：占用即拒绝，绝不静默解除。
- 软删除实体不会级联清理关联表，删除前必须显式做引用/占用校验，避免产生孤儿关联记录。
- 管理员需先在用户管理中解除全部用户分配，才能删除该角色。
