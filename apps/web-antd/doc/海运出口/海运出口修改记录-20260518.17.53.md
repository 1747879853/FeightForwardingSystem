# 海运出口修改记录 - 2026-05-19

## 变更概述

本次修改实现了海运出口服务项任务集成功能，包括新增API、新增/编辑接口的服务项校验与任务生成、详情/列表接口的任务信息填充。

---

## 1. 新增接口：GetServiceTypesByPOLAsync

**用途**：根据起运港ID和委托单位ID获取可选服务项目列表（前端新建/编辑时调用获取服务项配置）。

**路径**：`GET /api/services/app/SeaExportAdmin/GetServiceTypesByPOL`

**逻辑**：

- 查询 `SeServiceConfig`（起运港服务项配置）及其子项
- 根据 `ClientExceptService`（客户排除服务）标记每个服务项的 `checked` 状态
- 返回服务项列表含展示字段、锁定字段、必填字段信息

**新增DTO**：

- `GetServiceTypesByPOLInput`：入参（polId, clientId）
- `SeServiceTypeItemDto`：出参（serviceType, sortId, checked, shows, locks, requires）

---

## 2. 修改 AddAsync（新增海运出口）

**变更点**：

- `polId` 改为必填（原为可选）
- 新增服务项校验逻辑：
  - 输入的 `serviceTypes` 必须在起运港配置的允许列表中（排除客户排除项后）
  - `serviceTypes` 的顺序必须与配置顺序一致
- 新增首个服务项任务生成：
  - 根据第一个输入服务项对应的配置项的 `UserAttribute`，匹配订单用户
  - 生成 `SeServiceTask`（状态=待处理）和 `SeServiceTaskUsers`

---

## 3. 修改 EditAsync（编辑海运出口）

**变更点**：

- `polId` 改为必填
- 新增起运港变更检测逻辑：
  - **Case A（起运港变更）**：删除所有现有 `SeaExportService` 和 `SeServiceTask`（含用户），按新起运港重新执行 AddAsync 逻辑
  - **Case B（起运港未变更）**：
    - 执行同 AddAsync 的服务项值和顺序校验
    - 校验被删除的服务项是否有已完成的任务（有则不允许删除）
    - 校验新增的服务项后面是否有已生成的任务（有则不允许新增）
    - 校验通过后更新 `SeaExportService` 记录

---

## 4. 修改 DetailAsync + GetPagedListAsync

**变更点**：

- `SeaExportServiceDto` 新增 `seServiceTask` 属性（嵌套对象）
- 新增DTO：
  - `SeaExportServiceTaskDto`：任务简要信息（id, 状态, 完成人, 完成时间, 处理人列表）
  - `SeaExportServiceTaskUserDto`：处理人信息（userId, userNickName）
- 详情接口和列表接口均会填充每个服务项对应的当前任务信息
- 待处理状态下返回处理人列表，已处理状态下返回完成人名称

---

## 5. 新增依赖注入

`SeaExportAdminAppService` 构造函数新增以下仓储注入：

- `IRepository<SeServiceConfig, Guid>`
- `IRepository<SeServiceConfigItem, Guid>`
- `IRepository<ClientExceptService, long>`
- `IRepository<SeServiceTask, Guid>`
- `IRepository<SeServiceTaskUser, Guid>`

---

## 6. 新增错误提示

| 错误信息 | 触发条件 |
| --- | --- |
| 起运港不能为空 | 新增/编辑时 polId 为空 |
| 服务项目包含未配置的项 | serviceTypes 中包含未配置或客户排除的服务项 |
| 服务项目顺序不正确 | serviceTypes 顺序与配置顺序不一致 |
| 未找到对应用户属性的处理人，不允许新建 | 首个服务项的 UserAttribute 与订单用户无匹配 |
| 已完成的服务项不允许删除 | 编辑时删除有已完成任务的服务项 |
| 新增的服务项后面已有生成的任务，不允许新增 | 编辑时新增排在已有任务之前的服务项 |
