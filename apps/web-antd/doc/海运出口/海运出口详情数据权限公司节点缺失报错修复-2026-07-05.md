# 海运出口详情数据权限公司节点缺失报错修复 修改记录 2026-07-05

**修改时间：** 2026-07-05

**修改人：** 后端

**关联需求：** 修复 `DetailAsync`（`api/services/app/SeaExportAdmin/DetailAsync`）在设置数据权限所属组织机构时抛出 `Sequence contains no matching element` 的报错。

---

## 一、问题背景

调用海运出口详情接口时报错：

```
接口：api/services/app/SeaExportAdmin/DetailAsync?Id=2dd8823b-62db-4d6b-b519-85bd34285906
报错位置：await SetDataPermissionPropsAsync<SeaExportDto, Guid>(result);
报错信息：Sequence contains no matching element
```

根因：`SetDataPermissionPropsAsync` 在给 `dto.Companys` 赋值时，使用 `x.Last(x => x.IsCompany)` 从组织层级链中取“最底层公司节点”。当某条组织层级链中**不存在** `IsCompany == true` 的节点时，`Enumerable.Last(predicate)` 会抛出 `Sequence contains no matching element`。

该数据创建人所属的组织层级链中恰好没有公司节点，因此触发异常。

> 说明：基类中存在两个重载：
>
> - `List<T>` 版本（列表接口）用 `try/catch` 兜底，异常时把 `Companys` 整体置空，故列表接口不报错但会丢失全部公司信息。
> - 单个 `T` 版本（详情接口）**没有兜底**，因此详情接口直接抛异常。

## 三、核心逻辑变更

1. 取公司节点前先过滤出“确实包含公司节点”的层级链，再用 `Last`，从根本上避免抛异常：

```csharp
// 链路中可能不存在公司节点(IsCompany==true)，需先过滤再取，避免 Last 抛出 "Sequence contains no matching element"
dto.Companys = hierarchy.Where(x => x != null && x.Count > 0 && x.Any(n => n.IsCompany)).Select(x =>
{
    var company = x.Last(n => n.IsCompany);
    return new OrganizationUnitSimpleDto
    {
        Id = company.Id,
        Name = company.DisplayName,
        LocalCurrencyId = company.LocalCurrencyId,
        LocalCurrencyCode = company.LocalCurrencyId.HasValue && currencyMap.TryGetValue(company.LocalCurrencyId.Value, out var compCode) ? compCode : null,
    };
}).ToList();
```

2. 列表接口重载去掉了原来的 `try/catch` 兜底，改为同样的“先过滤再取”写法。好处：**不再因为个别链缺公司节点而丢失全部公司信息**，只跳过缺失的那条链，保留其余有效公司数据。

3. `OrganizationUnits` 赋值同步改为局部变量缓存 `x.Last()`，避免多次枚举，逻辑不变。

---

## 四、避坑指南

1. **`Last(predicate)` vs `LastOrDefault(predicate)`**：在组织层级链中取公司节点必须考虑“无公司节点”的情况。本次采用先 `Any(n => n.IsCompany)` 过滤的方式，语义清晰且避免了 `null` 判断。项目其他位置（如 `OrganizationUnitAppService` 第 171 行）使用 `chain?.LastOrDefault(x => x.IsCompany)` 同样是安全写法。
2. **数据前提**：出现该问题的本质是用户所属组织链未挂到任何“公司(IsCompany=true)”节点下。若业务要求每个用户必须归属公司，需在组织架构维护侧另行约束，本次仅从代码健壮性层面兜底。
3. **影响面**：该基类方法被多个模块（海运出口、账单、开票申请、收付款结算等）复用，本次修复对所有调用该方法的详情/列表接口均生效。
