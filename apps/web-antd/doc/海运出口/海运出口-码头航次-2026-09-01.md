# 1. 背景意图 (Background)

海运出口原来只有一个航次字段 `InnerVoyno`，界面标签就叫「航次」，存的是**船公司给的航次**。

但港区（码头）自己另有一套航次编号，和船公司航次经常不一样。外部「码头船舶计划」接口认的是**港区航次**，之前一直拿船公司航次去查，本质上查不准——表现就是「明明有这条船，却查不到计划」。

因此新增一个 `TerminalVoyno`「码头航次」字段，与船公司航次并存，两者都由用户维护。

# 2. 核心逻辑变更

## 2.1 新增字段

| 项          | 值                                                     |
| :---------- | :----------------------------------------------------- |
| 实体        | `SeaExport.TerminalVoyno`                              |
| 类型 / 长度 | `string`，`[StringLength(64)]`（与 `InnerVoyno` 对齐） |
| 界面标签    | 码头航次                                               |
| 是否必填    | 否                                                     |

`InnerVoyno` 的注释同步改为「航次(船公司航次)」，值和长度都没动。

## 2.2 接入范围

按 `InnerVoyno` 的既有做法全套接入，没有特殊处理：

| 场景 | 处理 |
| :-- | :-- |
| 新增 `AddAsync` | `SeaExportAddDto.TerminalVoyno`，走 `ObjectMapper.Map` 自动映射 |
| 编辑 `EditAsync` | `SeaExportEditDto.TerminalVoyno`，手写赋值 `seaExport.TerminalVoyno = input.TerminalVoyno` |
| 长度校验 | 新增与编辑各一处，超 64 报「码头航次长度不能超过64个字符」 |
| 列表 / 详情 | `SeaExportDto.TerminalVoyno`，走 `ObjectMapper.Map` 自动映射 |
| 简易输出 | `SeaExportSimpleDto.TerminalVoyno` |
| 列表查询 | `SeaExportQueryDto.TerminalVoyno`，模糊匹配 |
| 批量修改 | `SeaExportPropEnum.TerminalVoyno = 19` |
| 复制 `CopyAsync` | 自动带过去（走 `ObjectMapper.Map`，未列入「一票一号不复制」名单） |

**关键字 `keyword` 的模糊范围没有加码头航次**，仍是船名、船公司航次、备注、主提单号、订舱编号、合同号、委托编号。想按码头航次搜，用 `terminalVoyno` 这个专用筛选条件。

## 2.3 码头船舶计划改用码头航次

`FeituoAdmin/QueryTerminalScheduleAsync`（按业务单查码头船舶计划）的航次取值改为：

1. 业务单的**码头航次**有值 → 直接用它。
2. 码头航次为空、**船公司航次**有值 → 先调外部「船司航次转码头航次」换算一次，用换算结果查。
3. 两者都为空 → 不带航次，按船名 + 起运港查全部挂靠计划。

返回结构里 `innerVoyno` / `terminalVoyno` 两个航次都会带上，另有 `terminalVoynoConverted` 标识本次的码头航次是否为换算所得。**换算结果不落库**，需要固化得由用户自己补录到单据上。

外部接口返回条目里的 `evoyage` 也是**码头航次**，前端填表时要填到「码头航次」而不是「航次」。

# 3. 避坑指南 (Blockers)

> [!IMPORTANT] **1. 两个航次不能混用。** `innerVoyno` 是船公司航次，`terminalVoyno` 是港区航次。查码头船舶计划、以及外部返回的 `evoyage` 都属于码头航次这一侧。界面上两个字段要分开摆、标签写清楚，不要共用一个输入框。

> [!IMPORTANT] **2. 迁移要自己生成。** `App_SeaExports` 新增 `TerminalVoyno` 列（`nvarchar(64)`，可空），需自行生成 EF Core 迁移。存量数据该列为 `NULL`，此时查码头船舶计划会走「拿船公司航次换算」的分支，不影响可用性。

> [!NOTE] **3. `GetDatesAsync`（按船名航次取日期）没有改。** 那个接口是按「船名 + 船公司航次」去匹配其它单子来推荐日期的，仍然只用 `InnerVoyno`，没有把码头航次纳入匹配条件。

> [!NOTE] **4. 批量修改枚举是追加的。** `SeaExportPropEnum.TerminalVoyno = 19` 接在 `ContractNum = 18` 之后，没有动任何已有取值，前端已在用的枚举值不受影响。
