# 1. 背景意图 (Background)

`SeaExportAdminAppService` 的列表与详情原先把港口以扁平字段返回（`polName`/`podName`/`countryName`/`laneName`/`*EdiCode` 等），与项目「关联外键以对象返回、禁止平铺」及海运进口 `PortCodeSimpleDtoForOrder` 口径不一致。现改为港口对象字段，便于前端统一展示与扩展。

# 2. 核心逻辑变更 (Core Changes)

| 字段 | 变更前 | 变更后 |
| :-- | :-- | :-- |
| 付费地点 | `prepareAtId` + `prepareAtName`/`prepareAtEdiCode` | `prepareAtId` + `prepareAt`：`PortCodeSimpleDtoForOrder` |
| 签单地点 | `signingPortId` + `signingPortName`/`signingPortEdiCode` | `signingPortId` + `signingPort` |
| 目的港 | `podId` + `podName`/`podEdiCode` + 顶层 `countryName`/`countryEnName`/`laneName` | `podId` + `pod`（航线/国家挂在 `pod.lane` / `pod.country`） |
| 起运港 | `polId` + `polName`/`polEdiCode` | `polId` + `pol` |
| 中转港1/2 | `pot1Id`/`pot2Id` + Name/EdiCode | `pot1`/`pot2` |
| 收货地/交货地 | `receivePortId`/`deliverPortId` + Name/EdiCode | `receivePort`/`deliverPort` |

未改：各港口 `*Id`、`*Remark`；输入 DTO 仍只传 Id。

**受影响组装点**（均改为 `QueryPortSimpleDtosAsync` 批量挂载）：

- `SeaExportAdminAppService.GetPagedListAsync`
- `SeaExportAdminAppService.DetailAsync`
- `SeServiceTaskAdminAppService.MapSeaExportsAsync`（任务内 `seaExport` 与列表结构一致）

# 3. 避坑指南 (Pitfalls)

- 前端勿再读 `polName`/`podName`/`countryName`/`laneName`/`*EdiCode`，改为 `pol?.cnName`、`pod?.portName`、`pod?.ediCode` 等。
- **海运出口界面航线/国家取自目的港**：`pod.lane.laneName`、`pod.country.countryName` / `pod.country.countryEnName`（与海运进口取自起运港不同）。
- 无港口时对应对象为 `null`。
- `SeaExportSimpleDto`（开票/打印等简易结构）此前已对象化，本次未改。
