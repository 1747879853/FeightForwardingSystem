# 海运出口/业务表新增危险品与冻柜字段 修改记录 2026-07-06

**修改时间：** 2026-07-06

**修改人：** 后端

**关联需求：** `TransportOrder`（业务表）根据货物类型 `CargoId` 需要补充「危险品」与「冻柜」两组扩展字段，并同步 `TransportOrder`、`SeaExport` 全部接口。

---

## 一、需求背景

业务表 `TransportOrder` 的货物类型 `CargoId`（枚举 `CargoType`：`S=普通货`、`R=冻柜`、`D=危险品`、`O=超限箱`）为 `D`（危险品）时需要录入危险品申报信息，为 `R`（冻柜）时需要录入冷藏控制信息。

由于 `SeaExport` 与 `TransportOrder` 为 1:1 共享主键，海运出口的新建/编辑/详情/列表接口均嵌套复用 `TransportOrder` 的 DTO，因此字段统一新增在 `TransportOrder` 业务表上，海运出口接口自动复用。

---

## 五、避坑指南

1. **字段统一放在业务表 `TransportOrder`**：勿放在 `SeaExport`，否则空运/陆运等其他业务无法复用；海运出口接口通过嵌套 DTO 自动复用。
2. **新增/详情/列表走 AutoMapper**：`[AutoMap]`/`[AutoMapFrom]` 依赖属性同名，本次属性名与实体保持一致，无需改映射 Profile。
3. **两处 `EditAsync` 均为手动赋值**：`TransportOrderAdminAppService` 与 `SeaExportAdminAppService` 的 `EditAsync` 都是逐字段赋值，新增字段必须两处同步补充，否则编辑不生效。
4. **温度单位为前端枚举**：`ReeferTemperatureUnit` 后端仅存 `int?`，枚举含义由前端维护。
5. **迁移文件未生成**：按项目约定（`不需要生成migration文件 我会自己生成`），本次仅完成实体与接口改动，数据库迁移由维护人自行生成。新增列均为可空，向后兼容。
