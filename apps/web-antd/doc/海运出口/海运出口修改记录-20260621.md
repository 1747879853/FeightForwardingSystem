# 海运出口 修改记录 2026-06-21

**修改时间：** 2026-06-21

**修改人：** 后端

**关联需求：** 海运出口列表新增「应收费用状态」「应付费用状态」两列（组合费用状态）

---

## 一、需求背景

海运出口分页列表此前只返回 `FeeStatusReceive` / `FeeStatusPay`（应收/应付费用的最小费用状态，`int?`），无法直观表达一票业务整体的费用流转状态（含驳回、申请修改、申请删除、结算等异常/进度）。

本次新增两列组合费用状态：

- **应收费用状态**：综合「应收 + 更改单应收费用」判断。
- **应付费用状态**：综合「应付 + 更改单应付费用」判断，规则与应收完全一致。

> 说明：更改单费用与主业务费用共用同一个 `TransportOrderId`（仅 `ChangeOrderId` 不为空），列表费用查询按 `TransportOrderId` 聚合，已天然包含更改单费用，无需额外查询。

---

## 二、判断规则（应收/应付一致，优先级从上到下）

| 优先级 | 状态 | 触发条件 |
| --- | --- | --- |
| 1 | **驳回** `Rejected` | 只要费用含任意驳回记录（`FeeStatus.Rejected`），直接显示驳回，忽略其他所有状态 |
| 2 | **申请修改** `Modification` | 无驳回情况下，存在待审核（`TaskStatus.Auditing`）的费用申请修改 |
| 3 | **申请删除** `Deletion` | 无驳回、无申请修改情况下，存在待审核的费用申请删除 |
| 4 | **录入状态** `Entering` | 无以上三类异常，有费用停留在录入环节（`FeeStatus.Entering`） |
| 5 | **提交审核** `Submitted` | 费用已提交、审核未全部完成（`FeeStatus.Submitted`） |
| 6 | **审核通过** `Passed` | 费用全部审核通过，暂无任何结算 |
| 7 | **部分结算** `PartialSettlement` | 审核已通过，已有部分金额结算 |
| 8 | **结算完毕** `Settlemented` | 费用全额结算完成（全部 `SettlementStatus.Settlemented`） |

> 该方向无任何费用时，返回 `null`。

## 四、详细修改内容

### 4.1 SeaExportFeeStatus 枚举（CsprojBuilderEnum.cs）

```csharp
public enum SeaExportFeeStatus
{
    Entering = 0,           // 录入状态
    Submitted = 1,          // 提交审核
    Passed = 2,             // 审核通过
    PartialSettlement = 3,  // 部分结算
    Settlemented = 4,       // 结算完毕

```

### 4.3 GetPagedListAsync（SeaExportAdminAppService.cs）

**接口：** `GET /api/services/app/SeaExportAdmin/GetPagedListAsync`

批量查询待审核的费用申请修改/删除任务（按费用 id）：

```csharp
var pendingModifyFeeIds = (await _taskItemRepository.GetAll()
    .Where(x => x.TaskType == TaskType.ModifyOrderFee && x.TaskStatus == TaskStatus.Auditing && allOrderFeeIds.Contains(x.EntityId))
    .Select(x => x.EntityId).Distinct().ToListAsync()).ToHashSet();
var pendingDeleteFeeIds = (await _taskItemRepository.GetAll()
    .Where(x => x.TaskType == TaskType.DeleteOrderFee && x.TaskStatus == TaskStatus.Auditing && allOrderFeeIds.Contains(x.EntityId))
    .Select(x => x.EntityId).Distinct().ToListAsync()).ToHashSet();
```

结果映射补充组合状态：

```csharp
data.ReceiveFeeStatus = ComputeSeaExportFeeStatus(thisOrderFees.FindAll(x => x.PaySide == PaySide.收), pendingModifyFeeIds, pendingDeleteFeeIds);
data.PayFeeStatus = ComputeSeaExportFeeStatus(thisOrderFees.FindAll(x => x.PaySide == PaySide.付), pendingModifyFeeIds, pendingDeleteFeeIds);
```

新增私有计算方法 `ComputeSeaExportFeeStatus`（按上述优先级判断）。

---

## 六、避坑指南

1. **更改单费用无需单独查询**：更改单费用与主单费用共用 `TransportOrderId`，按收付方向（`PaySide`）过滤即已包含更改单费用。
2. **驳回判断基于 `FeeStatus.Rejected`**，优先级最高，命中后直接返回，忽略后续所有判断。
3. **申请修改/申请删除判断基于 `TaskItem`**：`TaskType` 为 `ModifyOrderFee` / `DeleteOrderFee` 且 `TaskStatus == Auditing`（待审核）的费用才算异常。
4. **结算三态判断顺序**：先判全额结算（全部 `Settlemented`）→ 再判部分结算（任意非 `UnSettled`）→ 否则审核通过。

---

## 七、验收标准

| 序号 | 验收项 | 期望结果 |
| --- | --- | --- |
| 1 | 应收费用含任意驳回记录 | `ReceiveFeeStatus` = 驳回 |
| 2 | 无驳回，应收存在待审核申请修改 | `ReceiveFeeStatus` = 申请修改 |
| 3 | 无驳回/修改，应收存在待审核申请删除 | `ReceiveFeeStatus` = 申请删除 |
| 4 | 无异常，存在录入态费用 | `ReceiveFeeStatus` = 录入状态 |
| 5 | 存在已提交未审完费用 | `ReceiveFeeStatus` = 提交审核 |
| 6 | 全部审核通过且无结算 | `ReceiveFeeStatus` = 审核通过 |
| 7 | 审核通过且部分金额已结算 | `ReceiveFeeStatus` = 部分结算 |
| 8 | 全额结算完成 | `ReceiveFeeStatus` = 结算完毕 |
| 9 | 该方向无任何费用 | 对应状态返回 `null` |
| 10 | 应付费用状态（`PayFeeStatus`）规则同上 | 与应收一致 |

# 海运出口附件功能 修改记录 2026-06-21

**修改时间：** 2026-06-21

**关联需求：** 海运出口新增/详情支持按附件详细类型分组的附件功能

---

## 一、需求背景

海运出口需要支持附件上传，附件按**附件详细类型**（`AttachmentDtlTypeId`，如提单、托书）分组管理。前端以分组形式传入和展示，而非平铺列表。

## 二、改动范围

| 接口 | 是否改动 | 说明 |
| :-- | :-- | :-- |
| `AddAsync` | 是 | 新增入参 `attachmentGroup`，保存分组附件 |
| `DetailAsync` | 是 | 返回 `attachmentGroup`，按 `attachmentDtlTypeId` 分组 |
| `EditAsync` | **否** | 本次不改动 |

## 三、DTO 说明

### 入参 `AttachmentGroupInputDto`（`SeaExportAddDto.attachmentGroup`）

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| attachmentDtlTypeId | long? | 分组依据的附件详细类型 Id |
| items | List\<AttachmentItemForItemInputDto\> | 该类型下的附件 |

### 出参 `AttachmentGroupDto`（`SeaExportDto.attachmentGroup`）

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| attachmentDtlTypeId | long? | 分组依据 |
| attachmentDtlType | AttachmentDtlTypeSimpleDto | 类型信息（id、name、sortId） |
| items | List\<AttachmentItemDto\> | 该类型下的附件 |

## 四、业务逻辑

- 模块类型 Id：`ModuleTypeIds.Bussiness.SeaExport`（`160040`）
- 新增时：遍历 `attachmentGroup`，将每组 `items` 保存为 `AttachmentItem`，`attachmentDtlTypeId` 优先取分组级，其次取 item 级
- 详情时：查询全部附件后按 `attachmentDtlTypeId` 分组；组间按 `attachmentDtlType.sortId` 升序，组内按 `displayOrder` 升序

- API 文档：`文档\海运出口\海运出口api.md`（AddAsync、DetailAsync 章节已更新）
- 附件通用说明：`文档\附件\附件接口文档.md`
