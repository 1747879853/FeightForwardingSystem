# 海运出口分组统计接口 修改记录 2026-06-27

**修改时间：** 2026-06-27

**修改人：** 后端

**关联需求：** 海运出口新增分组统计接口，查询条件与海运出口列表一致，额外通过「分组字段」对筛选结果进行分组统计

---

## 一、需求背景

海运出口需要一个分组统计接口：

- 输入参数与海运出口列表（`GetPagedListAsync`）类似，但额外多一个**分组字段**（枚举）。
- 通过查询参数筛出所有符合条件的数据，再按分组字段对这些数据进行分组。
- 例如分组字段传 `1`（装运方式），则按装运方式分组；每个分组返回对应装运方式的 **id、名称**，以及该分组的**数据总条数**。

分组字段枚举：`1`装运方式、`2`订单类型、`3`委托单位、`4`船公司、`5`起运港、`6`目的港、`7`船名、`8`付费方式、`9`签单方式。

## 三、接口说明

**接口：** `GET /api/services/app/SeaExportAdmin/GetGroupedListAsync`

**权限：** `Admin.SeaExport.Get`（与列表接口一致）

### 入参 `SeaExportGroupQueryDto`

继承 `SeaExportQueryDto`（列表全部查询参数），新增：

| 字段       | 类型                | 说明                          |
| ---------- | ------------------- | ----------------------------- |
| GroupField | SeaExportGroupField | 分组字段，1装运方式~9签单方式 |

### 出参 `List<SeaExportGroupDto>`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| Id | string | 分组值 id（枚举为枚举值、委托单位为 Guid、船名为名称本身、其余为 long 类型 id；无值为 null） |
| Name | string | 分组名称（无值为 null） |
| Count | int | 该分组数据总条数 |

> 结果按 `Count` 倒序排列。

### 分组字段对应来源

| GroupField | 含义 | 分组依据 | id / name 来源 |
| --- | --- | --- | --- |
| 1 | 装运方式 | `SeaExport.BLType` | 枚举值 / 枚举描述（`GetDescription`） |
| 2 | 订单类型 | `SeaExport.BillType` | 枚举值 / 枚举描述 |
| 3 | 委托单位 | `TransportOrder.ClientId` | `Client.Id` / `Client.Name` |
| 4 | 船公司 | `SeaExport.CarrierId` | `Carrier.Id` / `Carrier.CnName` |
| 5 | 起运港 | `SeaExport.POLId` | `PortCode.Id` / `PortCode.PortName` |
| 6 | 目的港 | `SeaExport.PODId` | `PortCode.Id` / `PortCode.PortName` |
| 7 | 船名 | `SeaExport.Vessel` | 船名字符串 / 船名字符串 |
| 8 | 付费方式 | `TransportOrder.CodeFrtId` | `CodeFrt.Id` / `CodeFrt.CnName` |
| 9 | 签单方式 | `SeaExport.CodeIssueTypeId` | `CodeIssueType.Id` / `CodeIssueType.BillType` |

## 四、核心逻辑变更

### 4.1 抽取共用筛选方法 `BuildSeaExportFilterQuery`

将原 `GetPagedListAsync` 内联的近百条 `WhereIf` 筛选条件抽取为私有方法 `BuildSeaExportFilterQuery(SeaExportQueryDto input, List<long> permissionUserIds)`，列表与分组统计接口共用，保证两者筛选逻辑完全一致。

`GetPagedListAsync` 改为调用该方法，行为不变。

### 4.2 `GetGroupedListAsync` 实现

```csharp
var query = BuildSeaExportFilterQuery(input, permissionUserIds);
query = await DataPermissionFilterAsync(query);
query = await TablePermissionsAsync(query, FrightModule.SeaExport);
// 按 input.GroupField switch，EF GroupBy + Count，再批量查询名称
```

- 枚举字段（装运方式、订单类型）：直接 `GroupBy` 枚举，`Id` 取枚举值、`Name` 取 `GetDescription()`。
- 关联字段（委托单位/船公司/起运港/目的港/付费方式/签单方式）：先 `GroupBy` id 拿到分组与条数，再用对应仓储批量查询名称回填。
- 船名：直接 `GroupBy` 字符串，`Id`/`Name` 均为船名本身。

---

## 五、对前端的影响

- 纯新增接口，列表接口 `GetPagedListAsync` 行为不变（仅内部抽取方法，无破坏性变更）。
- 分页参数（PageIndex/PageSize/Sorting）对分组接口无效，返回全部分组。

---

## 六、避坑指南

1. **筛选逻辑唯一来源**：列表与分组统计共用 `BuildSeaExportFilterQuery`，新增筛选条件只需改一处。
2. **数据权限不可省**：分组前同样要执行 `DataPermissionFilterAsync` 与 `TablePermissionsAsync`，否则会统计到越权数据。
3. **可空字段的分组**：船公司/起运港/目的港/付费方式/签单方式为可空字段，存在 id 为 null 的分组，此时 `Id`/`Name` 返回 null，但仍统计条数。
4. **签单方式名称取 `CodeIssueType.BillType`**（该表用 `BillType` 字段存放签单方式名称），而非 `CnName`。
5. **枚举名称取 `GetDescription()`**（`CsprojBuilder.Tools.EnumExtensions`），无 `Description` 特性时回退为枚举名。
