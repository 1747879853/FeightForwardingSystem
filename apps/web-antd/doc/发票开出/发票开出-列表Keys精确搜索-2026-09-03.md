# 1. 背景意图 (Background)

列表关键字 `keyword` 同时模糊匹配开出编号、委托编号、主提单号。本次新增 `keys`，一次传入多个值做精确匹配。

# 2. 核心逻辑变更

`InvoiceIssueQueryDto` 新增 `List<string> Keys`。覆盖字段与 `keyword` 相同：开出编号 `ApplicationNo`、委托编号、主提单号。

生效接口：`GET /api/services/app/InvoiceIssueAdmin/GetPagedListAsync`

`GetSubmittedApplicationListAsync` 没有 `keyword`，本次不加 `keys`。

匹配规则：精确相等、列表内 OR、与 `keyword` 同时传时为 AND。GET 用 `keys=A&keys=B`。

# 3. 避坑指南 (Blockers)

> [!IMPORTANT] **`keys` 会命中开出编号。** 批量贴提单号时，若某张发票开出编号恰好等于其中某个提单号，也会被搜出来。这是跟 `keyword` 对齐后的预期行为。
