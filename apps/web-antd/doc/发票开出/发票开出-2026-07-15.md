# 1. 背景意图 (Background)

`InvoiceIssueAdminAppService.DetailAsync`（发票开出详情）此前在 `invoiceIssueItems` 中仅返回关联开票申请的简易信息（`InvoiceApplicationSimpleDto`），**不包含该开票申请下的费用明细**。前端在详情页展示"每条开票申请对应哪些费用、申请了多少金额"时，需要额外再查开票申请详情，体验不佳。

本次在详情接口的 `invoiceIssueItems.invoiceApplication` 中**直接返回费用明细**（`invoiceApplicationItems`），每条明细携带费用简易信息（`OrderFeeSimpleDto`），并额外显示费用的**币别代码**（`currencyCode`）。

| 字段           | 类型     | 说明                                             |
| :------------- | :------- | :----------------------------------------------- |
| `CurrencyCode` | `string` | 币别代码（由 `CurrencyId` 关联 `Currency.Code`） |

## 2.4 查询与填充逻辑

1. **Include 链**：`InvoiceIssueItems → InvoiceApplication → InvoiceApplicationItems → OrderFee`。
2. **批量币别**：汇总全部费用 `CurrencyId`，一次查询 `Currency` 表得到 `Id → Code` 字典。
3. **映射**：`ObjectMapper.Map<InvoiceApplicationItemSimpleDto>` + `ObjectMapper.Map<OrderFeeSimpleDto>`，再赋值 `CurrencyCode`。

> 本接口使用 **简易 DTO**（非 `InvoiceApplicationItemDetailDto` / `OrderFeeDto`），不返回运输订单、海运出口、已开票金额等扩展字段，与 `GetSubmittedApplicationListAsync` 的完整费用详情区分。

# 3. 避坑指南 (Pitfalls)

- **仅 `DetailAsync` 变更**：列表 `GetPagedListAsync` 不返回费用明细，前端详情页需调详情接口。
- **`currencyCode` 为扩展字段**：`OrderFeeSimpleDto` 通过 `[AutoMapFrom]` 映射实体后手动赋值，不在 `OrderFee` 实体上。
- **与已提交列表区分**：`GetSubmittedApplicationListAsync` 返回 `InvoiceApplicationItemDetailDto` + 完整 `OrderFeeDto`（含 `transportOrder.seaExport` 等）；详情接口返回轻量 `SimpleDto`，避免详情过重。
- **空集合**：开票申请无费用明细时 `invoiceApplicationItems` 为空数组（非 `null`）。
