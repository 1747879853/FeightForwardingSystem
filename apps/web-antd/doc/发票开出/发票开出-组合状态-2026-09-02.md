# 一、背景意图

列表和详情原先同时返回 `issueStatus` 与 `redStatus`。两个枚举的数值有重叠（两边都有 `2`：一边是开票完成，一边是待购方确认），前端没法用一个下拉同时表达「开票中 / 开票完成 / 冲红中 / 已冲红」。

本次把两个状态合成一个出参字段 `combinedStatus`，列表筛选也认这个值。

完整取值与筛选口径见《发票开出接口文档》第五节、《诺诺开票模块总逻辑文档》3.6。

# 二、核心逻辑变更

公式：

- `redStatus == 0`（未冲红）→ 返回 `issueStatus`
- 已发起冲红（含失败终态）→ 返回 `redStatus + 100`

因此 `2` 只表示「开票完成且从未冲红」；冲红完成是 `199`，不是 `2`。没有 `100`（未冲红不会作为组合值返回）。

列表查询新增 `combinedStatus`（单值）与 `combinedStatuses`（多选），一组内部多个值是 OR。筛小于 100 的值时额外要求 `redStatus=未冲红`，否则已经冲红的票仍会被「开票完成」命中。原有的 `issueStatus` / `redStatus` 条件保留，与组合状态同时传是 AND。

`issueStatus` / `redStatus` 出参仍在，按钮禁用继续看 `editLocked`，不要用组合状态去推按钮。

# 三、避坑指南

> [!IMPORTANT] **不要把「开票完成」理解成「当前这张票的最终命运」。** 筛 `combinedStatus=2` 拿不到已经冲红的票。界面上「已开票」如果要包含已冲红，需要把 `199` 一起传。

> [!IMPORTANT] **冲红接口出参没有 `combinedStatus`。** `IssueByInterfaceAsync` / `QueryRedResultAsync` 仍只回各自那一组状态。组合字段只在发票开出列表和详情上。
