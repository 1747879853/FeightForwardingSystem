# 1. 背景意图 (Background)

原 `EditAsync` 一次全量替换主表+开票申请明细+商品明细，前端局部加减开票申请不便。现拆成三个独立接口，并**保留**原 `EditAsync` 兼容。

# 2. 核心逻辑变更 (Core Changes)

| 接口 | 作用 |
| :-- | :-- |
| `EditMainAsync` | 仅改主表字段；发票号变更时同步回填已关联开票申请的 `InvoiceNo` |
| `AddApplicationsAsync` | 向某张发票开出追加多条开票申请；入参带完整 `InvoiceIssueGoodsDtls`，与**合并后全部申请**做金额校验并全量替换商品明细 |
| `RemoveApplicationsAsync` | 移除多条开票申请；入参带完整 `InvoiceIssueGoodsDtls`，与**剩余申请**做金额校验并全量替换商品明细；移除后至少保留 1 条 |
| `EditAsync` | **保留**，仍为全量替换 |

抽取 `ValidateApplicationsAsync(items, goodsDtls, currentIssueId)` 与 `ReplaceGoodsDtlsAsync` 供新增/编辑/增删申请复用。主表与开票申请状态更新改为局部赋值（不调 `UpdateAsync`）。

# 3. 避坑指南 (Pitfalls)

- 增删开票申请时 `invoiceIssueGoodsDtls` 是**最终完整商品明细**，不是增量；金额须与目标申请集合合计一致。
- 移除时若已被收费结算引用，仍走 `EnsureNotSettledByInvoiceAsync`，禁止反开票。
- 权限均为 `Admin.InvoiceIssue.Edit`。
