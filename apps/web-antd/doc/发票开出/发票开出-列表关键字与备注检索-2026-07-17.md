# 1. 背景意图 (Background)

`InvoiceIssueAdminAppService.GetPagedListAsync`（发票开出分页列表）原有检索条件仅能按开出单号、发票号等固定字段过滤。业务上常需要凭借业务单据编号快速定位发票开出记录，但发票开出本身不直接持有委托编号与主提单号（这些字段位于关联的运输订单上），且缺少针对备注的检索。

本次新增：

- **关键字 `keyword`**：一个输入框同时模糊匹配 **开出编号（`applicationNo`）**、**委托编号（`commissionNum`）**、**主提单号（`mblNum`）**。
- **备注 `remark`**：对发票开出主表备注做模糊检索。

## 2.4 查询逻辑

关键字通过导航链遍历到运输订单编号：

```
InvoiceIssue.ApplicationNo
InvoiceIssue.InvoiceIssueItems
  └── InvoiceApplication.InvoiceApplicationItems
        └── OrderFee.TransportOrder.CommissionNum / MblNum
```

对应 `WhereIf` 条件：

```csharp
.WhereIf(!string.IsNullOrEmpty(input.Keyword), m =>
    m.ApplicationNo.Contains(input.Keyword) ||
    m.InvoiceIssueItems.Any(item =>
        item.InvoiceApplication.InvoiceApplicationItems.Any(appItem =>
            appItem.OrderFee.TransportOrder.CommissionNum.Contains(input.Keyword) ||
            appItem.OrderFee.TransportOrder.MblNum.Contains(input.Keyword))))
.WhereIf(!string.IsNullOrEmpty(input.Remark), m => m.Remark.Contains(input.Remark))
```

# 3. 避坑指南 (Pitfalls)

- **关键字为跨表模糊匹配**：委托编号、主提单号来源于运输订单（`OrderFee.TransportOrder`），通过 `发票开出明细 → 开票申请 → 开票申请明细 → 费用 → 运输订单` 的导航链 `Any` 子查询实现，EF Core 会翻译为 `EXISTS` 子查询，命中任一关联运输订单即返回该发票开出。
- **`keyword` 与 `applicationNo` 可共存**：`keyword` 覆盖开出编号，仍保留独立的 `applicationNo` 精确入口，两者是 `AND` 关系。
- **`remark` 仅匹配主表**：不检索子表（明细/商品明细）的备注。
