# 一、背景意图

`GET /api/services/app/InvoiceIssueAdmin/GetPagedListAsync` 原来只有 12 个查询条件，接口开票那一组只能按**开票方式**筛，红冲那一组**一个条件都没有**。

这就意味着几件天天要干的事在列表上做不到：

- 「哪些票正在冲红」「哪些票已经冲红」——红冲状态压根不能筛。
- 「哪些票开票失败了要重开」——接口开票状态不能筛。
- 拿着服务商工作台上的**开票流水号**或税局的**红字确认单编号**反查是本地哪一张票——只能去数据库查。

本次把主表上所有有检索价值的字段都补成查询条件，共 12 → 37 个。

# 二、加了什么

字段清单与类型见《发票开出接口文档》**第五节**，这里不重复。分三组：

| 组 | 加了哪些 |
| :-- | :-- |
| 主表遗漏 | `require` 开票要求(模糊)、`applyUserId` 申请人、`applyTimeStart/End` 申请时间 |
| 接口开票 | `issueStatus` / `issueStatuses`、`issueOrderNo`、`issueSerialNum`、`invoiceCode`、`issueRequestTimeStart/End` |
| 红冲 | `redStatus` / `redStatuses`、`redReason`、`redBillId`、`redBillNo`、`redOrderNo`、`redSerialNum`、`redInvoiceNo`、`redInvoiceCode`、`redInvoiceTimeStart/End`、`redApplyTimeStart/End`、`redApplyUserId` |

**申请人不等于创建人**：原来只有 `creatorUserId`，而申请人是可以代他人填的，两者是不同的人，所以 `applyUserId` 是单独一个条件，不能拿创建人凑。

接口地址与方法签名没变，不传新参数时行为与改动前完全一致。

# 三、避坑指南

> [!IMPORTANT] **「冲红中」「开票中」必须用多选参数，单值枚举筛不出来。**
>
> `redStatus` / `issueStatus` 是**精确匹配单个枚举值**，而界面上用户想筛的「冲红中」「开票中」都不是一个状态、而是**一段流程**，各自跨好几个状态值：
>
> | 界面上想筛            | 传什么                                     |
> | --------------------- | ------------------------------------------ |
> | 冲红中                | `redStatuses` = `15`,`1`,`2`,`3`,`4`       |
> | 冲红失败/确认单已作废 | `redStatuses` = `5`~`9`,`16`               |
> | 开票中                | `issueStatuses` = `1`,`20`,`21`            |
> | 已冲红 / 开票完成     | 单值就够：`redStatus=99` / `issueStatus=2` |
>
> 所以这两组各给了「单值 + 多选」两个参数。数组用重复参数名传（`redStatuses=15&redStatuses=1`）。两个同时传时是 **AND**，正常只传一个。
>
> 之所以不在后端造一个「冲红中」的聚合枚举：状态值的分组归属会随服务商的确认单流程变，交给前端按需组合，后端就不用跟着改。

> [!IMPORTANT] **禁止用这些查询条件去算按钮禁用。** 列表出参里已经有 `editLocked` / `redLocked`，那是后端用与写操作同一份规则（`InvoiceIssueLockRule`）算出来的。自己拿 `issueStatus` + `redStatus` 拼条件，迟早跟后端的拦截规则漂开——界面上按钮亮着、点下去被拒。详见《诺诺发票对接-开票方式不再校验与出参附件补齐-前端对接文档-2026-08-16.md》。

# 四、没加的与原因

| 没加 | 原因 |
| :-- | :-- |
| `clientInvoiceBankId` / `orgBankAccountId` 按银行筛 | 实际业务不会这么查发票开出，加了只是让参数表更长 |
| `issueFailCause` / `redFailCause` 模糊查 | 服务商回的自由文本，按它检索意义不大，列表里直接显示就够 |

要的话再补，后端加一行 `WhereIf` 的事。
