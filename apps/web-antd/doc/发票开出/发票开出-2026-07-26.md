# 1. 背景意图 (Background)

前端列表需要勾选多条发票开出一次性删除。原 `DeleteAsync` 入参仅为单个 `id`，改为 `ids` 批量删除。

# 2. 核心逻辑变更 (Core Changes)

| 项 | 变更 |
| :-- | :-- |
| `InvoiceIssueDeleteDto` | `id: Guid` → `ids: List<Guid>` |
| `DeleteAsync` | 按 `ids` 批量删除；汇总关联开票申请做反开票校验与状态回退；回写费用开票状态 |

子表删除改为：`DeleteAsync(x => ids.Contains(x.InvoiceIssueId))`。开票申请回退仅局部赋值 `Status`/`InvoiceNo`，不再调用 `UpdateAsync`。

# 3. 避坑指南 (Pitfalls)

- 请求体字段名是 `ids`（数组），不再接受单个 `id`。
- 任一关联开票申请已被收费结算引用时，整批禁止删除（`EnsureNotSettledByInvoiceAsync`）。
- 删除后关联申请回退为 `Auditing`，并触发 `RecalcInvoiceStatusByApplicationsAsync` 费用状态降级。
