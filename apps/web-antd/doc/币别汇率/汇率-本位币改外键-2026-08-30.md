# 1. 背景意图 (Background)

汇率表原来用一个字符串列 `LocalCurrency` 记本位币，全库实际只写过 `'RMB'`，取数的地方也一律硬编码 `LocalCurrency == "RMB"`。

这套做法在「只有一个公司、本位币只有人民币」时能跑，但本位币其实是**配在组织机构的公司节点上的**（`OrganizationUnit.LocalCurrencyId`），不同公司可以配不同本位币。一旦真的有第二个公司配了非人民币本位币，就会同时出现两个问题：

1. 字符串对不上——按 `'RMB'` 筛根本查不到那个公司的汇率；
2. **更隐蔽的是取数方法压根没带本位币条件**。基类的 `ResolveExchangeRateAsync` 只按「币别 + 会计期间」取 `FirstOrDefault`，连 `OrderBy` 都没有。同一币别一旦并存两条不同本位币的有效汇率，取到哪条完全看数据库返回顺序。

本次把本位币改成指向币别表的**不可空外键**，并把所有取汇率的地方统一成「币别 + 本位币 + 会计期间」三条件。

# 2. 核心逻辑变更 (Core Logic)

## 2.1 表结构

| 表 | 变更 |
| :-- | :-- |
| `App_ExchangeRates` | 删 `LocalCurrency`(`nvarchar`)，加 `LocalCurrencyId`(`bigint`，**不可空**)，新增索引 `(CurrencyId, LocalCurrencyId)` |

一条汇率的含义从此明确为「`CurrencyId` 折算成 `LocalCurrencyId` 的比率」。

> [!IMPORTANT] **迁移脚本必须手写回填，不能直接用 EF 生成的默认迁移。**
>
> 新列不可空，EF 默认会生成 `AddColumn<long>(nullable: false, defaultValue: 0L)`，结果是整表 `LocalCurrencyId = 0`，指向一个不存在的币别，所有取汇率的逻辑当场全部失效。
>
> Up 里必须先按旧的字符串反查币别 id 回填，再删旧列。另外要先确认现网有没有 `LocalCurrency` 为 `NULL` 或空串的历史行——这些行反查不出 id，需要单独定一个兜底值或先清理。

## 2.2 取汇率的统一口径

**取汇率必须带本位币，本位币必须由业务所属公司解析出来。** 为此在 `CsprojBuilderAppServiceBase` 加了三个公共方法：

| 方法 | 用途 |
| :-- | :-- |
| `GetCompanyLocalCurrencyIdAsync(long? orgId)` | 由组织(可为部门)向上找到所属公司，取该公司的本位币；取不到返回 `null` |
| `EnsureCompanyLocalCurrencyIdAsync(long? orgId)` | 同上，取不到直接报「当前公司未配置本位币」 |
| `GetCompanyLocalCurrencyIdMapAsync(orgIds)` | 批量版，校验一批费用时用，避免把组织树查询重复跑很多遍 |

> [!IMPORTANT] **不要用「组织串上第一个配了本位币的节点」来取本位币。**
>
> 改造前全项目 8 处都是 `Orgs.FirstOrDefault(o => o.LocalCurrencyId.HasValue)`。组织串是**从顶到底**排的，这个写法取的是**最顶层**那个有本位币的节点。本位币按规定只配在公司上，但集团等上级节点历史上也可能配过，一旦配了，取出来的就是集团的而不是公司的。
>
> 正确做法是取组织串里**最后一个** `IsCompany = true` 的节点（= 最接近本组织的所属公司），与 `GetCompanyOrgIdAsync` 口径一致。为此给 `OrganizationUnitSimpleDto` 补了 `IsCompany` 字段（组织树节点上本来就有，只是以前没往外传）。

### `ResolveExchangeRateAsync` 签名变更

```csharp
// 旧
ResolveExchangeRateAsync(repo, currencyId, paySide, accountDate)
// 新 多了本位币
ResolveExchangeRateAsync(repo, currencyId, localCurrencyId, paySide, accountDate)
```

同时修了两个原有缺陷：

- 加了 `OrderByDescending(r => r.StartDate)`，区间重叠时取最新生效的一条，不再是无序 `FirstOrDefault`；
- 币别本身就是本位币时**直接返回 1**，不查表（库里已禁止存在币别与本位币相同的汇率）。

调用方：`OrderFeeAdminAppService`(复制引入费用)、`SeServiceTaskAdminAppService`(服务项自动生成费用)，两处都改为按目标业务 `TransportOrder.OrgId` 解析公司本位币。

## 2.3 发票汇率是例外：本位币固定人民币

开票申请与发票开出取的是 `InvoiceValue`，本位币**不跟公司走，固定人民币**——开具增值税发票的外币金额按税务口径必须折人民币申报，这是税务规定不是公司口径。

新增 `GetRmbCurrencyIdAsync()`（走基础资料缓存按 `Code == "RMB"` 反查 id）供这 6 处使用：

| 文件 | 方法 |
| :-- | :-- |
| `InvoiceApplicationAdminAppService` | `GetInvoiceRateValueAsync`、详情填 `InvoiceExchangeRate`、列表批量取汇率 |
| `InvoiceIssueAdminAppService` | `GetInvoiceExchangeRateAsync`、列表、已提交列表 |

币别表没维护 RMB 时统一用 `-1` 让查询自然落空（不返回汇率好过返回一条本位币不明的汇率），有报错分支的走报错分支。

## 2.4 提成汇率改按公司本位币

`CommissionOrderAdminAppService` 里写死的 `private const string LocalCurrencyCode = "RMB"` 已删除。`BuildRateMapAsync` 增加 `localCurrencyId` 入参，本位币由提成单所属组织解析。详见 [提成单-新建加OrgId-2026-08-30.md](../提成单/提成单-新建加OrgId-2026-08-30.md)。

## 2.5 汇率模块自身的接口变更

### 新增/编辑入参

`ExchangeRateAddDto` / `ExchangeRateEditDto`：删 `localCurrency`(string)，加 **`localCurrencyId`(long，必填)**。

新增外键校验（`ValidateCurrencyPairAsync`，新增与编辑共用）：

| 校验                  | 报错文案             |
| :-------------------- | :------------------- |
| `currencyId > 0`      | 币别不能为空         |
| `localCurrencyId > 0` | 本位币不能为空       |
| 两者不相等            | 币别与本位币不可相同 |
| 币别存在              | 输入币别错误         |
| 本位币存在            | 输入本位币错误       |

> 禁止币别与本位币相同：折算自身恒为 1，落这样一条没有意义，反而给按「币别+本位币」取数的逻辑增加一条噪声。取汇率的方法已内置「币别即本位币返回 1」。

### 列表入参

`ExchangeRateQueryDto` 新增 `localCurrencyId`(long?) 筛选。加了本位币之后汇率的业务唯一键实际是「币别 + 本位币 + 起止日期」，列表不能按本位币过滤会很难用。

`keyword` 的匹配范围变了：原来匹配 `LocalCurrency` 字符串与备注，现在匹配**币别代码、本位币代码、备注**（前两个是子查询，EF 翻成 `EXISTS`，不会把整表拉回内存）。

### 列表/详情出参

删 `localCurrency`(string)，改为两个字段：

| 字段名            | 类型                | 含义       |
| :---------------- | :------------------ | :--------- |
| `localCurrencyId` | `long`              | 本位币id   |
| `localCurrency`   | `CurrencySimpleDto` | 本位币对象 |

> [!NOTE] `localCurrency` 这个字段名沿用了，但**类型从字符串变成了对象**，前端原来直接当字符串用的地方全都要改。
>
> 另外注意出参里现在有两个币别对象，别搞混：`currency` 是**被折算的币别**，`localCurrency` 是**折算的对家(本位币)**。

## 2.6 同步费用汇率增加本位币过滤

「同步费用汇率」原来只按币别筛费用。加了本位币之后，一条「USD → RMB」的汇率如果刷到本位币是 USD 的公司的费用上就是错的。

`BuildSyncPreviewAsync` 增加一道过滤：候选费用捞回来后，按主单 `OrgId` 解析所属公司本位币，只保留与该汇率 `LocalCurrencyId` 相等的。**主单没有所属组织、或所属公司未配本位币的一律不纳入同步范围**——判断不出归属就不能刷。

> 组织树在缓存里没法在 SQL 里 join，所以这道过滤放在捞回内存之后做。

## 2.7 币别删除引用校验补两处

`CurrencyAdminAppService.DeleteAsync` 原来只判了 `ExchangeRate.CurrencyId`，漏了两个方向：

| 补的校验                                 | 提示                              |
| :--------------------------------------- | :-------------------------------- |
| `ExchangeRate.LocalCurrencyId == id`     | 已被【汇率】模块引用,禁止删除     |
| `OrganizationUnit.LocalCurrencyId == id` | 已被【组织机构】模块引用,禁止删除 |

漏掉任一个都会留下悬空外键。组织机构那个尤其严重——删掉一个被当公司本位币用的币别，该公司下所有取汇率的逻辑会直接报「当前公司未配置本位币」。

## 2.8 费用代码列表的汇率预填

`FeeCodeAppService.GetListAsync` 每条费用代码会带一个「默认币别当前有效汇率」给前端预填。这个汇率同样必须按本位币取。

`FeeCodeListQueryDto` 新增可空的 `orgId`（公司或部门均可），不传则取当前登录人的默认组织。

> [!IMPORTANT] **解析不出本位币时返回空汇率，而不是随便给一条。** 这个值前端会直接预填到费用行上，给错的汇率比不给更糟。

# 3. 避坑指南 (Pitfalls)

- **迁移必须手写回填**，见 2.1 的警告框。这是本次改动最容易造成线上事故的一步。
- **不要再写 `LocalCurrency == "RMB"` 这种硬编码。** 除发票汇率（税务口径，见 2.3）外，本位币一律用 `GetCompanyLocalCurrencyIdAsync` 从业务所属公司解析。发票那 6 处也不要自己拼字符串，调 `GetRmbCurrencyIdAsync`。
- **取本位币不要用「组织串上第一个有值的节点」**，要取最后一个 `IsCompany` 的节点。见 2.2 的警告框。这是本次统一口径时改动面最大的一处，全项目 8 个地方都是老写法。
- **汇率表现在允许同一币别配多条不同本位币的记录，这是有意的。** 「USD→RMB」和「USD→HKD」可以并存且同时有效。所以任何取汇率的查询都必须带本位币条件，缺了就是随机取。
- **同步费用汇率的范围变小了。** 加了本位币过滤之后，主单没组织、或公司没配本位币的票不再返回。如果用户反馈「以前能刷的票现在查不出来了」，先查这两个条件而不是怀疑筛选逻辑。
- **`ExchangeRateSimpleDto` 没有本位币字段。** 它只在费用代码列表里当预填值用，调用方已经确定了本位币口径。以后要在别的地方复用它，先确认取它的那段查询带没带本位币条件。
