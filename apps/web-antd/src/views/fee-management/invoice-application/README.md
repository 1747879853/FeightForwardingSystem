# 发票申请模块

## 功能说明

发票申请模块用于管理开票申请的完整流程，包括新建、编辑、提交审核、撤回、驳回等操作。

## 页面结构

```
fee-management/invoice-application/
├── data.ts          # 表格和表单配置
├── list.vue         # 列表页面（增删改查）
├── form.vue         # 表单页面（新增/编辑）
└── README.md        # 说明文档
```

## 状态流转

```
Entering(录入) ──SubmitAsync──→ Auditing(待审核) ──后续开票操作──→ Invoiced(已开票) [终态]
    ↑    ↑                          │
    │    └──────WithdrawAsync───────┤ (撤回到录入)
    │                               │
    └──────AuditAsync(仅驳回)────────┘ Rejected(驳回) → 可修改后重新提交
```

### 各状态操作权限

| 操作     | Entering | Auditing | Rejected | Invoiced |
| -------- | -------- | -------- | -------- | -------- |
| 编辑     | ✅       | ❌       | ✅       | ❌       |
| 删除     | ✅       | ✅       | ✅       | ❌       |
| 提交审核 | ✅       | ❌       | ✅       | ❌       |
| 撤回     | ❌       | ✅       | ❌       | ❌       |
| 驳回     | ❌       | ✅       | ❌       | ❌       |

## 主要功能

### 1. 列表页面 (list.vue)

#### 查询条件

- 申请单号（模糊搜索）
- 发票号（模糊搜索）
- 状态（下拉选择）
- 结算对象
- 币别
- 申请时间范围
- 创建人

#### 操作按钮

- **新建**：跳转到新增页面
- **批量提交**：批量提交选中的申请进行审核
- **删除**：批量删除选中的申请（已开票状态不可删除）

#### 行操作

- **编辑**：只有录入或驳回状态可编辑
- **提交**：提交申请到待审核状态
- **撤回**：撤回待审核的申请回到录入状态
- **驳回**：驳回待审核的申请（需填写驳回原因）

## API 接口

所有接口定义在 `#/api/Invoice/invoiceRequest.ts`：

- `getOrderFeeGroupAsync` - 拉取剩余未开票金额>0的费用
- `addAsync` - 新增开票申请（批量）
- `editAsync` - 修改开票申请
- `deleteAsync` - 删除开票申请
- `detailAsync` - 获取开票申请详情
- `getPagedListAsync` - 获取开票申请列表
- `auditAsync` - 审核（驳回）开票申请
- `submitAsync` - 提交审核
- `withdrawAsync` - 撤回审核

## 业务规则

### 1. 金额计算

```
已开票金额(InvoicedAmount) = Sum(AppliedAmount) WHERE Status = Invoiced
发票申请金额(OrderInvoiceAmount) = Sum(AppliedAmount)  // 包含所有状态
剩余可开票金额 = Amount - OrderInvoiceAmount
```

### 2. 并发控制

新增和修改时使用行级悲观锁（UPDLOCK, ROWLOCK）防止并发超额申请。

### 3. 数据校验

- 每条费用的申请金额不能超过剩余可开票金额
- 同一币别下，商品明细金额合计必须等于费用明细金额合计
- 新建时需验证发票汇率是否存在

### 4. 多币别处理

前端选择费用时，如果包含多个币别，将按币别生成多个独立的 InvoiceApplication，每个申请有：

- 独立的申请单号
- 独立的银行信息
- 独立的发票类型

## 开发注意事项

### 前端开发

1. **状态判断**：操作前务必检查当前状态是否允许该操作
2. **金额格式化**：金额字段统一使用 `.toFixed(2)` 格式化
3. **日期处理**：使用 dayjs 进行日期转换，API 传参使用 ISO 格式
4. **错误处理**：所有异步操作都需要 try-catch 并给出友好提示

### 后端对接

1. **分页参数**：pageIndex 从 1 开始，不是 skipCount
2. **日期格式**：前后端统一使用 ISO 8601 格式
3. **枚举值**：使用数字枚举，不要使用字符串
4. **行锁机制**：理解后端的并发控制逻辑，避免前端重复提交
