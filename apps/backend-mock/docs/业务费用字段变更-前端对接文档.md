# 业务费用（OrderFee）字段变更 — 前端对接文档

**变更日期**：2026-06-02

**变更概述**：本次对 `OrderFee`（业务费用）进行了三项字段变更：

| # | 变更类型 | 字段 | JSON Key | 说明 |
| --- | --- | --- | --- | --- |
| 1 | **新增** | 不含税单价 | `noTaxUnitPrice` | 前端传入，后端直接存储，不再后端计算 |
| 2 | **新增** | 不含税金额 | `noTaxAmount` | 前端传入，后端直接存储，不再后端计算 |
| 3 | **删除** | 是否含税 | `taxIncluded` | 从实体和所有DTO中彻底移除 |

---

## 一、新增字段定义

| 字段名 | JSON Key | 类型 | 精度 | 说明 |
| --- | --- | --- | --- | --- |
| 不含税单价 | `noTaxUnitPrice` | `decimal` | 4位小数 | 前端计算后传入，后端直接保存并原样返回 |
| 不含税金额 | `noTaxAmount` | `decimal` | 2位小数 | 前端计算后传入，后端直接保存并原样返回 |

**重要变化**：这两个字段之前都是后端根据含税单价/金额和税率实时计算返回的，现在改为前端传入什么就存什么、返回什么。

## 二、删除字段定义

| 字段名   | JSON Key      | 原类型    | 说明                           |
| -------- | ------------- | --------- | ------------------------------ |
| 是否含税 | `taxIncluded` | `decimal` | **已删除**，不再传入、不再返回 |

---

## 四、入参DTO变更详情

### 4.1 `OrderFeeAddDto`（新增费用）

**变更前**：

```json
{
  "unitPrice": 100.0,
  "amount": 1000.0,
  "unitEmum": 0,
  "quantity": 10.0,
  "taxIncluded": 1.0,
  "taxRate": 13.0
}
```

**变更后**：

```json
{
  "unitPrice": 100.0,
  "noTaxUnitPrice": 88.4956,
  "amount": 1000.0,
  "noTaxAmount": 884.96,
  "unitEmum": 0,
  "quantity": 10.0,
  "taxRate": 13.0
}
```

**字段变更明细**：

| 变更     | 字段             | 类型      | 精度    | 位置                 |

| **新增** | `noTaxAmount`    | `decimal` | 2位小数 | `amount` 之后        |
| **删除** | `taxIncluded`    | -         | -       | 原在 `quantity` 之后 |

## 七、前端需要做的改动

### 7.1 费用表单（新增/编辑/提交/更改单）

**新增**：

- 添加 `noTaxUnitPrice`（不含税单价）输入/显示控件
- 添加 `noTaxAmount`（不含税金额）输入/显示控件
- 前端自行计算后传给后端，或允许用户手动输入

**删除**：

- 移除 `taxIncluded`（是否含税）输入控件
- 移除提交数据中的 `taxIncluded` 字段

**涉及页面**：

- 业务费用新增（`AddAsync`）
- 业务费用编辑（`EditAsync`）
- 业务费用批量新增（`BatchAddAsync`）
- 业务费用批量编辑（`BatchEditAsync`）
- 费用提交审核（`SubmitOrderFeeAsync`）
- 更改单编辑（`ChangeOrderAdmin/EditAsync`）

### 7.2 费用列表/详情展示

- `noTaxUnitPrice` 和 `noTaxAmount` 字段名不变，前端**无需修改取值逻辑**，但值的来源从"后端计算"变为"数据库存储值"
- **移除** 所有展示 `taxIncluded` 的列/字段

**涉及页面**：费用列表、费用详情、各类审核详情页、海运出口详情、更改单详情、付费申请、付费结算、对账单等

### 7.3 审核/驳回/撤回流程

`noTaxUnitPrice` 和 `noTaxAmount` 会随其他字段一起在审核通过时更新、驳回时恢复。前端无需额外处理。

### 7.4 注意事项

- 后端传入已删除的 `taxIncluded` 不会报错（ABP 框架忽略多余字段），但建议尽快清理
- `noTaxUnitPrice` 和 `noTaxAmount` 如果不传，默认值为 `0`
- 所有字段均为全量更新，传入什么值就更新为什么值
