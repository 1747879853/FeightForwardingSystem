# Windows 本地打包发布

支持环境：`jht`、`jiayue`、`sjtd`、`demo`。

## 首次配置

1. 本机安装项目要求的 Node.js、pnpm，以及 Microsoft Web Deploy 3.6。
2. 复制配置模板：

   ```powershell
   Copy-Item .\scripts\publish-config.example.json .\scripts\publish-config.local.json
   ```

3. 编辑 `scripts\publish-config.local.json`，为每家公司填写：
   - `serverIp`：IIS 服务器 IP 或域名。
   - `endpoint`：完整的 Web Deploy 地址。留空时根据 `serverIp`、`siteName` 自动生成。
   - `siteName`：IIS 管理器中显示的站点名（不是服务器物理目录，也不是本地 `dist` 目录），与原 GitHub Secret `IIS_SITE_NAME` 含义相同。只有 IIS 中确实创建了子应用时才填写 `站点名/应用名`。
   - `userName`：IIS Web Deploy 用户名。
   - `password`：可留空，发布时会隐藏输入。也可填写在本地配置中，该文件已被 Git 忽略。
   - `msDeployPath`：本机 `msdeploy.exe` 路径。

如果不希望密码写入文件，也可以设置当前用户的环境变量，例如：

```powershell
[Environment]::SetEnvironmentVariable('IIS_JHT_PWD', '你的密码', 'User')
```

其他环境对应 `IIS_JIAYUE_PWD`、`IIS_SJTD_PWD`、`IIS_DEMO_PWD`。重新打开终端后生效，环境变量优先于配置文件中的密码。

## 使用

直接双击 `scripts\publish-web.cmd`，然后选择公司环境。

也可以在项目根目录执行：

```powershell
# 交互选择公司
pnpm run deploy:antd

# 指定公司
pnpm run deploy:antd:jht
pnpm run deploy:antd:jiayue
pnpm run deploy:antd:sjtd
pnpm run deploy:antd:demo
```

一键按 `jht → jiayue → sjtd → demo` 发布全部环境：

```powershell
pnpm run deploy:antd:all
```

也可以直接双击 `scripts\publish-all-web.cmd`。全部环境固定使用 `-Force`，不会要求输入公司代码确认；任一环境失败时立即停止，剩余环境不会继续发布。

脚本按以下顺序执行：

1. 使用对应 `.env.<公司>` 构建前端。
2. 校验构建产物中的 API 地址，防止发错环境。
3. 在 `output\releases\<公司>` 生成带时间戳的 MSDeploy ZIP 包。
4. 检查 IIS Web Deploy 端口。
5. 要求再次输入公司代码确认，再覆盖 IIS 站点（默认跳过 `WhatIf`）。

## 常用参数

```powershell
# 只打包，不发布
.\scripts\publish-web.ps1 -Environment jht -PackageOnly

# 只执行发布预演，不真正发布
.\scripts\publish-web.ps1 -Environment jht -WhatIfOnly

# 使用已有 dist，不重新构建
.\scripts\publish-web.ps1 -Environment jht -SkipBuild

# 跳过 @vben-core 包的 prebuild
.\scripts\publish-web.ps1 -Environment jht -SkipPrebuild

# 忽略 Turbo 缓存，强制重建 @vben-core 包
.\scripts\publish-web.ps1 -Environment jht -ForcePrebuild

# 首次发布前安装依赖
.\scripts\publish-web.ps1 -Environment jht -InstallDeps

# 自动确认，适合已经核对配置后的重复发布
.\scripts\publish-web.ps1 -Environment jht -Force
```

四个环境均关闭 `VITE_ARCHIVER`，构建时不再额外生成归档文件。默认 prebuild 使用 Turbo 内容缓存：源码和依赖未变化时直接命中缓存；`-SkipPrebuild` 可明确跳过，`-ForcePrebuild` 可强制刷新。

正式发布默认跳过 `WhatIf`。需要排查 IIS 目标或权限时，仍可显式运行 `-WhatIfOnly`。
